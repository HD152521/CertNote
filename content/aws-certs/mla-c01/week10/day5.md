# Day 5 - D-Day 마무리: 시험 구성·시간 배분·시나리오 분해 전략

## 📌 핵심 정리

- MLA-C01은 **65문항(채점 50 + 비채점 15) / 130분 / 합격 720점(1000점 만점)** 이다. 어느 문항이 비채점인지는 알 수 없다.
- 문항당 평균 **2분**. 1차 통과 90~100분 → 2차 검토 25~30분 → 3차 마무리 5분의 페이스를 지킨다.
- 막히면 임시 답 + 표시(flag) 후 이동. 모든 문항의 배점은 같고, **오답 감점이 없으므로 빈칸은 순손해**다.
- 긴 사례형은 마지막 질문 → 조건 키워드 → 보기 전에 정답 떠올리기 → 함정 소거 순으로 해체한다.
- 최상급 한정어(MOST/LEAST)를 반드시 읽는다. 여러 보기가 작동하더라도 그 기준의 최선 하나만 정답이다.

## 시험 구성 — 무엇을 마주하는가

10주의 마지막 날이다. 오늘은 새 지식이 아니라 **시험을 치르는 기술**을 다룬다. 같은 실력이라도 시간 배분과 문제 분해 전략에 따라 합불이 갈린다.

| 항목 | 내용 |
|------|------|
| 문항 수 | 65문항 (채점 50 + 비채점 15) |
| 시간 | 130분 |
| 문항 유형 | 객관식 단답/다답, 사례형, 순서배열 등 |
| 합격 점수 | 720 / 1000 (스케일 점수) |
| 결과 | 채점 대상 50문항으로 산정(비채점 15는 점수에 미반영) |

도메인 비중은 다음과 같다.

```text
 도메인 1  데이터 준비          ████████████████████████████  28%
 도메인 2  모델 개발            ██████████████████████████    26%
 도메인 4  모니터링·보안        ████████████████████████      24%
 도메인 3  배포·오케스트레이션  ██████████████████████        22%
                               └ 1+2 = 54%  ·  3+4 = 46% ┘
```

어느 한 도메인도 버릴 수 없지만, 1·2가 절반을 넘으므로 데이터·모델 영역의 안정성이 합격의 토대다.

> 💡 **관련 이론**: 15개 비채점(unscored) 문항은 미래 출제를 위한 시험용 문항으로, 어느 것이 비채점인지 알 수 없다. 따라서 "이건 비채점일 것"이라 짐작해 버리지 말고 모든 문항을 동등하게 대해야 한다. 합격선 720은 채점 50문항 기준 약 70% 안팎의 정답을 의미하니, 완벽이 아니라 "확실한 다수 + 함정 회피"가 목표다.

## 시간 배분 — 130분을 어떻게 쓰나

65문항/130분이면 **문항당 평균 2분**이다. 다음 페이스를 권한다.

- **1차 통과(약 90~100분)**: 모든 문항을 한 번씩 푼다. 2분 넘게 막히면 임시 답을 찍고 **표시(flag)** 후 넘어간다. 절대 한 문항에 5분 이상 쓰지 않는다.
- **2차 검토(약 25~30분)**: 표시한 문항으로 돌아와 차분히 푼다. 1차 때 본 다른 문항이 힌트를 주는 경우도 많다.
- **3차 마무리(약 5분)**: 빈 답이 없는지, 다답형에서 개수를 맞췄는지 확인한다.

중간 점검용 기준표다. 실제 시험 화면의 남은 시간과 대조해 페이스가 밀렸는지 바로 알 수 있다.

| 경과 시간 | 여기까지 풀었으면 정상 | 밀렸을 때 조치 |
|-----------|------------------------|----------------|
| 30분 | 약 15문항 | 표시 후 넘기는 기준을 2분 → 90초로 당긴다 |
| 60분 | 약 30문항 | 긴 사례형은 질문·한정어만 읽고 소거로 승부 |
| 90분 | 약 45문항 | 검토 시간을 15분으로 줄이는 것을 각오 |
| 100분 | 65문항 1차 완료 | 표시 문항 순으로 검토 시작 |
| 125분 | 검토 종료 | 빈칸·다답형 개수 최종 확인 |

```text
[130분 배분]
├──────────── 1차 통과 90~100분 ────────────┤── 2차 검토 25~30분 ──┤─ 3차 5분 ─┤
   전 문항 1회 · 막히면 찍고 flag              flag 문항 재검토        빈칸·개수
```

> ⚠️ **함정**: 가장 흔한 실패는 "어려운 한 문항에 10분을 쏟다가 쉬운 뒤쪽 문항을 못 푸는 것"이다. 모든 문항의 배점은 같다. 막히면 즉시 찍고 표시하고 넘어가는 규율이 점수를 지킨다. 또 답이 없는 문항은 무조건 찍는다 — 오답 감점은 없으므로 빈칸은 순손해다.

## 시나리오 분해 전략 — 긴 문제를 해체하기

긴 사례형 문항은 다음 순서로 해체한다.

1. **마지막 질문 문장부터 읽는다.** "가장 비용 효율적인 것은?", "가장 적절한 추론 옵션은?" — 무엇을 묻는지 먼저 알면 본문에서 무엇을 찾을지 분명해진다.
2. **결정 키워드를 표시한다.** 실시간/간헐, 불균형, 시계열, 드리프트, 인터넷 차단, 암호화 등.
3. **보기를 보기 전에 정답을 떠올린다.** Day4의 번역표를 적용한다.
4. **보기에서 함정을 소거한다.** 요구 하나라도 위반하는 보기를 지운다.

```text
[4단계 해체]
  ① 마지막 질문 ─▶ "무엇을 고르라는 것인가" + 한정어(MOST/LEAST)
        ▼
  ② 본문 스캔  ─▶ 조건 키워드에 번호를 매긴다  (조건①②③)
        ▼
  ③ 보기 전 정답 ─▶ 번역표로 기능 이름을 머릿속에 적는다
        ▼
  ④ 보기 소거   ─▶ 조건을 하나라도 깨는 보기 제거 → 남는 하나
```

## 문항 유형별 대응

| 유형 | 특징 | 대응 |
|------|------|------|
| 단답 객관식 | 보기 4개 중 1개 | 번역표로 정답을 먼저 떠올린 뒤 보기에서 찾는다 |
| 다답형(TWO 등) | 정확한 개수를 골라야 하고 부분점수 없음 | 개수를 먼저 확인하고, 확실한 것부터 확정 후 나머지를 비교 |
| 긴 사례형 | 조건 키워드가 2~3개 흩어져 있음 | 질문·한정어 먼저 → 조건에 번호 → 조건을 다 만족하는 보기 |
| 매칭/순서 | 항목을 짝짓거나 순서를 배열 | 확신 있는 짝부터 고정하고 남은 것을 소거로 채운다 |
| "잘못된 것은?" | 부정형 질문 | 질문에 부정어가 있는지 반드시 확인. 맞는 것 3개를 찾아 소거 |

> ⚠️ **함정**: 부정형("NOT", "잘못된 것은")을 놓치면 정답을 알고도 반대를 고른다. 급하게 읽을수록 자주 나오는 실수다. 질문 문장을 읽을 때 부정어와 한정어(MOST·LEAST·TWO)에 눈을 한 번 더 두는 습관이 이 손실을 막는다.

> 🔍 **더 깊이**: 다답형(2개 이상 고르기)은 따로 전략이 필요하다. 문항이 "TWO" 또는 "TWO actions"라고 명시하면 정확히 그 개수를 골라야 하고, 한 개만 맞아도 부분점수가 없다. 또 "MOST cost-effective", "LEAST operational overhead", "MOST secure"처럼 **최상급 한정어**가 핵심이다. 여러 보기가 기술적으로 작동하더라도, 한정어 기준(비용·운영부담·보안)에서 최선인 하나만 정답이다. 한정어를 놓치면 "작동은 하지만 최선이 아닌" 함정 보기를 고른다.

## 막판 점검 — 시험 직전 빠르게 훑을 것

전날·당일 아침에 다음을 빠르게 복습하자.

| 영역 | 한 줄 점검 |
|------|-----------|
| 추론 옵션 | 즉시성·트래픽·페이로드로 실시간/서버리스/비동기/배치 가르기 |
| 고급 배포 | 동종 다수=MME, 다른 프레임워크 소수=MCE, 전처리 체인=추론 파이프라인 |
| 알고리즘 | 시계열=DeepAR, 이상=RCF, 표=XGBoost, 추천=FM, 텍스트=BlazingText |
| 평가 지표 | 불균형=F1/AUC, 놓침=Recall, 오탐=Precision, 회귀=RMSE |
| 학습 인프라 | 큰 데이터=Pipe/FastFile, 반복 읽기=FSx, 비용=Spot+체크포인트 |
| 튜닝 | 적은 시도=Bayesian, 조기 종료=Hyperband |
| 데이터 준비 | 비주얼=Data Wrangler, 스크립트=Processing Job, ETL=Glue, 조회=Athena |
| 특성 | 학습-추론 일관성=Feature Store(온라인 단건/오프라인 대량) |
| 모니터링 | 입력 드리프트=Data Quality, 성능 저하=Model Quality(+라벨) |
| 편향·설명 | Clarify(사전/사후 편향, SHAP), 운영 중 지속 감시는 Model Monitor |
| 보안 | IAM 최소권한 · VPC 엔드포인트(S3=Gateway, 나머지=Interface) · 격리 · KMS |
| 거버넌스 | 누가=CloudTrail, 지표=CloudWatch, 계보=Lineage, 문서=Model Cards |
| MLOps | EventBridge → Pipelines(ConditionStep) → Model Registry |
| 비용 | MME · Inferentia · 서버리스/비동기 · Spot · 배치 변환 |

> 💡 **관련 이론**: 시험 직전엔 새 개념을 욱여넣기보다 **이미 아는 것의 인출 경로를 다지는 것**이 효과적이다. 위 표를 소리 내어 키워드→기능으로 매핑해보는 인출 연습이 정보를 새로 읽는 것보다 시험장 회상에 훨씬 도움이 된다. 충분히 자고, 시험장에 일찍 도착하고, 첫 몇 문항에서 막혀도 흔들리지 말자 — 어려운 문항이 앞쪽에 몰리는 것은 흔한 배치일 뿐이다.

## 시험 당일 체크리스트

지식 밖의 이유로 점수를 잃지 않기 위한 준비물·환경 점검이다. 세부 규정은 응시 방식(시험장 / 온라인 감독)에 따라 다르니 예약 확인 메일의 안내를 최종 기준으로 삼자.

| 구분 | 점검 항목 |
|------|-----------|
| 전날 | 충분한 수면. 새 강의·새 문제집을 새로 시작하지 않는다 |
| 전날 | 예약 시간·응시 방식·장소(또는 온라인 감독 절차)를 다시 확인 |
| 당일 준비물 | 예약 확인서에 명시된 신분증. 이름 표기가 예약과 일치하는지 확인 |
| 시험장 응시 | 여유 있게 도착. 소지품 보관 규정 확인 |
| 온라인 응시 | 사전 시스템 점검, 책상 위 정리, 조용하고 방해받지 않는 공간 확보 |
| 시작 직후 | 남은 시간 표시 위치와 표시(flag) 버튼 위치를 먼저 확인 |
| 진행 중 | 30/60/90분 지점에서 진도 대조. 밀리면 즉시 페이스 조정 |
| 종료 전 | 빈칸 0개, 다답형 개수 일치 확인 후 제출 |

## 마지막 인출 카드 — 소리 내어 대답해보기

읽지 말고 **답을 먼저 말한 뒤** 오른쪽을 확인하자. 막히는 칸이 있으면 그 주차 내용만 다시 본다.

| 물음 | 답 |
|------|-----|
| 0까지 스케일되지 않는 추론 옵션은? | 실시간(최소 1대 유지) |
| 개별 요청인데 크고 오래 걸리면? | 비동기 추론 |
| 전체 데이터셋을 한 번에 점수화하면? | 배치 변환 |
| 같은 프레임워크 모델이 수천 개면? | 멀티모델 엔드포인트(MME) |
| 학습 때 전처리를 추론에도 그대로 쓰려면? | 추론 파이프라인 또는 Feature Store |
| 라벨 없이 이상치를 찾으면? | Random Cut Forest |
| 여러 관련 시계열의 미래를 예측하면? | DeepAR |
| 99% 정상 데이터의 성능 지표는? | F1·AUC·Recall (Accuracy 아님) |
| 놓치면 안 되는 문제의 지표는? | Recall |
| 정답 라벨이 있어야 도는 모니터는? | Model Quality |
| 입력 분포 변화를 보는 모니터는? | Data Quality |
| 배포 전 일회성 편향 점검은? | Clarify |
| 인터넷 없이 S3에 붙으려면? | Gateway VPC 엔드포인트 |
| 인터넷 없이 ECR에 붙으려면? | Interface 엔드포인트(PrivateLink) |
| 컨테이너의 외부 통신을 끊으려면? | EnableNetworkIsolation |
| "누가 지웠나"를 확인하려면? | CloudTrail |
| 새 데이터 도착 시 재학습을 걸려면? | EventBridge → Pipelines |
| 기준 미달 모델의 등록을 막으려면? | ConditionStep |
| 학습 비용을 줄이되 재개돼야 하면? | Managed Spot + 체크포인트 |
| 적은 시도로 하이퍼파라미터를 찾으면? | Bayesian |

> 💡 **관련 이론**: 위 카드가 효과적인 이유는 형식이 시험과 같기 때문이다. 시험장에서 필요한 것은 "설명할 수 있는 지식"이 아니라 **짧은 단서로 이름 하나를 꺼내는 속도**다. 자료를 다시 읽으면 아는 것처럼 느껴지지만(친숙함 착각), 실제로 꺼내보면 막히는 칸이 드러난다. 마지막 복습은 반드시 꺼내보는 방식이어야 한다.

## 마지막 규율 다섯 가지

- 한 문항에 5분 이상 쓰지 않는다. 배점은 모두 같다.
- 빈칸으로 두지 않는다. 오답 감점이 없으므로 찍는 것이 항상 이득이다.
- 한정어(MOST·LEAST·TWO)를 소리 내듯 읽는다. 여기서 갈리는 문항이 가장 많다.
- 조건 개수를 세고, 보기가 그 조건을 몇 개 만족하는지 표시한다.
- 첫 직관을 근거 없이 뒤집지 않는다. 뒤집으려면 "어떤 조건 때문에"를 말할 수 있어야 한다.

## 10주를 마치며

MLA-C01은 결국 **요구사항을 SageMaker 기능으로 번역하는 시험**이다. 10주 동안 수집·특성공학·Feature Store·Clarify부터 학습·튜닝·평가, 추론 옵션·고급 배포, Pipelines·MLOps, Model Monitor·IAM·VPC·KMS까지 한 바퀴를 돌았다. 데이터 준비(도메인 1)와 모델 개발(도메인 2)의 안정성을 토대로, 배포(도메인 3)와 모니터링·보안(도메인 4)의 키워드 매핑을 반사적으로 떠올리면 된다. 이제 남은 것은 자신을 믿고 차분히 푸는 일이다. 행운을 빈다.

## 📖 용어

- **스케일 점수(scaled score)** : 문항 난이도를 보정해 100~1000 범위로 환산한 점수. MLA-C01 합격선은 720이다.
- **비채점 문항(unscored)** : 향후 출제를 위해 섞어 놓은 15문항. 어느 것인지 알 수 없으므로 전부 똑같이 대해야 한다.
- **표시(flag)** : 나중에 다시 볼 문항을 시험 화면에서 북마크해 두는 기능. 1차 통과의 핵심 도구다.
- **1차 통과 / 2차 검토** : 전 문항을 한 번 훑는 단계 / 표시해 둔 문항만 다시 푸는 단계. 시간 배분의 뼈대다.
- **다답형** : "TWO"처럼 정확한 개수를 고르라는 문항. 개수가 틀리면 부분점수 없이 오답 처리된다.
- **최상급 한정어** : MOST cost-effective, LEAST operational overhead 등 비교 기준을 지정하는 표현.
- **인출 연습(retrieval practice)** : 자료를 다시 읽는 대신 기억에서 꺼내보는 복습법. 시험 직전 복습으로 가장 효과가 크다.
- **결정 키워드** : 시나리오에서 정답을 가르는 단어(간헐·일괄·불균형·시계열·드리프트·인터넷 차단 등).

**문제 4.** "다음 중 가장 비용 효율적인(MOST cost-effective) 옵션은?" 같은 최상급 한정어가 포함된 문항을 풀 때 핵심 주의점은?

A) 기술적으로 작동하는 보기 아무거나 고른다
