# Day 3 - 전체 모의고사 페이스: 4개 도메인 종합 시나리오

## 📌 핵심 정리

- 실제 시험은 문항이 어느 도메인인지 알려주지 않는다. 한 문장에 **여러 도메인의 조건 키워드가 2~3개** 박혀 있다.
- 65문항/130분 = **문항당 평균 2분**. 오늘의 8문항은 16분 안에 푸는 것을 목표로 한다.
- 푸는 순서는 고정이다: 질문 문장 → 조건 키워드 추출 → 보기 보기 전에 정답 떠올리기 → 요구 위반 보기 소거.
- 조건이 여러 개면 **모든 조건을 동시에 만족하는 보기**만 정답이다. 하나라도 깨면 아무리 그럴듯해도 오답이다.
- 틀린 문항은 정답을 외우는 게 아니라 **다른 보기가 왜 함정이었는지**까지 말할 수 있어야 복습이 끝난다.

## 모의고사 사용법

오늘은 개념 설명을 줄이고 시험과 같은 페이스로 4개 도메인이 섞인 종합 시나리오를 푼다. 아래 8문항을 가능하면 16분 내에 풀고, 답을 보기 전에 "이 문항의 도메인은 무엇이고, 정답을 가르는 키워드는 무엇인가"를 먼저 말로 정리해보자.

| 단계 | 할 일 | 시간 |
|------|-------|------|
| 1차 풀이 | 8문항을 멈추지 않고 끝까지 | 16분 |
| 자가 채점 전 | 각 문항의 도메인·결정 키워드를 적어보기 | 4분 |
| 채점·복습 | 오답은 "다른 보기가 왜 틀렸는지"까지 설명 | 제한 없음 |

> 💡 **관련 이론**: 종합 문제는 보통 한 문장에 "조건 키워드"가 2~3개 박혀 있다. 예: "수백 개 동종 모델(→MME 후보)"+"가끔 호출(→비용 절감 강화)"+"같은 프레임워크(→MME 확정)". 키워드를 분리해 각각을 기능에 매핑한 뒤, 모든 키워드를 동시에 만족하는 보기를 고르면 함정 보기를 걸러낼 수 있다.

## 최상급 한정어 읽기

한 문장에 조건이 여러 개일 때, 마지막을 가르는 것은 대개 **한정어**다.

| 한정어 | 비교 축 | 자주 나오는 정답 방향 |
|--------|---------|-----------------------|
| MOST cost-effective | 비용 | MME · 서버리스 · 배치 · Spot · Inferentia |
| LEAST operational overhead | 운영 부담 | 관리형·서버리스 서비스(Glue, Pipelines, 서버리스 추론) |
| MOST secure | 보안 | VPC 엔드포인트 + 네트워크 격리 + KMS + 최소 권한 |
| LEAST latency | 지연 | 실시간 엔드포인트, Feature Store 온라인, 캐싱 |
| FASTEST to implement | 구현 속도 | 빌트인 알고리즘·Data Wrangler·관리형 기능 |
| MINIMUM code changes | 코드 변경 | 기존 구성 유지 + 설정 변경으로 해결 |

> ⚠️ **함정**: 여러 보기가 **기술적으로는 모두 작동한다.** 최상급 한정어가 정답을 하나로 좁히는 유일한 기준이다. "비용을 줄여라"인데 성능·가용성 요구를 깨는 보기(실시간을 0으로, 데이터를 버려서, XGBoost에 GPU)는 비용이 줄어도 오답이다. 반대로 "운영 부담을 줄여라"인데 EC2에 직접 구축하는 보기는 작동해도 오답이다.

## 복합 조건 해체 연습

문항 형식이 아니라, **조건을 분해하는 습관**을 보는 예시다. 각 조건이 어느 칸으로 가는지 눈으로 따라가보자.

케이스 A — "전국 매장별 XGBoost 모델 2,000개가 있고 각각 하루 몇 번만 호출된다. 비용을 최소화하라."

| 조건 조각 | 번역 |
|-----------|------|
| 모델 2,000개 | 다수 모델 → MME 후보 |
| 전부 XGBoost | 같은 프레임워크 → MME 확정(MCE 탈락) |
| 하루 몇 번만 호출 | 저빈도 → 인스턴스 공유가 유리 |
| 비용 최소화 | 한정어 = 비용 |

케이스 B — "규제 데이터로 학습한다. 인터넷을 거치면 안 되고, 컨테이너가 외부로 데이터를 보내서도 안 되며, 저장 데이터는 암호화해야 한다."

| 조건 조각 | 번역 |
|-----------|------|
| 인터넷 비경유 | VPC 엔드포인트(S3는 Gateway, ECR은 Interface) |
| 외부 통신 차단 | EnableNetworkIsolation |
| 저장 암호화 | KMS |
| 조건 3개 동시 | 셋 다 포함한 보기만 정답 |

케이스 C — "실시간 사기 탐지 모델이 배포됐다. 시간이 지나며 정확도가 떨어지는지 감시하고, 떨어지면 자동 재학습하라."

| 조건 조각 | 번역 |
|-----------|------|
| 정확도가 떨어지는지 | Model Quality 모니터 |
| 정확도 계산 전제 | ground truth 라벨 수집 필요 |
| 자동 재학습 | CloudWatch 알람 → EventBridge → Pipeline |
| 실시간 사기 | 불균형이므로 지표는 Accuracy가 아님 |

> 🔍 **더 깊이**: 케이스 C처럼 조건이 **감시 + 자동화**로 두 도메인에 걸치면, 보기 중 하나는 대개 "감시만" 하고 하나는 "자동화만" 한다. 둘 다 담은 보기가 정답이다. 반대로 조건이 하나뿐인데 여러 기능을 잔뜩 붙인 보기는 과잉 구성이라 "LEAST operational overhead" 기준에서 밀린다. 조건 개수와 보기의 구성 요소 개수를 맞춰보는 것도 빠른 소거법이다.

## 오답 패턴: 증상 → 원인 → 조치

| 증상(자주 틀리는 방식) | 원인 | 조치 |
|------------------------|------|------|
| 불균형 데이터인데 Accuracy를 골랐다 | "정확도"라는 단어에 반사적으로 반응 | 데이터 비율 문장을 먼저 찾는 습관 |
| 실시간 엔드포인트를 0으로 스케일하는 보기를 골랐다 | 실시간의 최소 1대 제약을 잊음 | 0 스케일은 서버리스·비동기·배치뿐 |
| 개별 요청인데 배치 변환을 골랐다 | 페이로드 크기만 보고 판단 | "개별 요청"이면 비동기, "전체 데이터셋"이면 배치 |
| 네트워크 요구인데 KMS를 골랐다 | 보안 = 암호화라는 단순 연상 | 네트워크는 VPC 엔드포인트·격리, 저장은 KMS |
| 감사 질문인데 CloudWatch를 골랐다 | 둘 다 "로그"라 혼동 | "누가"는 CloudTrail, "얼마나·언제 느린가"는 CloudWatch |
| 시계열인데 회귀 알고리즘을 골랐다 | 예측=회귀라는 연상 | 시간 축이 핵심이면 DeepAR |
| 기술적으로 되는 보기를 골랐는데 오답 | 최상급 한정어를 안 읽음 | 문항 마지막 줄의 한정어에 밑줄 긋기 |
| 조건 3개 중 2개만 만족하는 보기를 골랐다 | 조건을 끝까지 세지 않음 | 조건 개수를 세고 보기마다 체크 |

이제 실전이다. 8문제를 풀어보자. 내일은 이 오답 패턴들을 함정 유형별로 다시 정리한다.

## 📖 용어

- **종합 시나리오 문항** : 한 문항에 여러 도메인의 조건이 섞인 사례형 문제. 실제 시험의 주류 형태다.
- **조건 키워드** : 정답을 가르는 결정적 단어(간헐·일괄·불균형·시계열·드리프트·인터넷 차단 등). 문항에서 이것부터 뽑는다.
- **최상급 한정어** : MOST cost-effective, LEAST operational overhead처럼 비교 기준을 지정하는 표현. 여러 보기가 다 작동할 때 정답을 하나로 좁힌다.
- **소거법** : 요구를 하나라도 위반하는 보기를 지워 후보를 줄이는 풀이 방식. 조건이 여러 개일수록 강력하다.
- **과잉 구성 보기** : 요구보다 훨씬 복잡한 구성을 제시하는 보기. 운영 부담 기준 문항에서 오답이 되기 쉽다.
- **0 스케일** : 요청이 없을 때 인스턴스를 0까지 내려 비용을 없애는 것. 서버리스·비동기·배치만 가능하고 실시간은 안 된다.
- **ground truth** : 예측이 맞았는지 판정할 실제 결과 라벨. 이것이 없으면 Model Quality 감시가 성립하지 않는다.
- **페이스(pace)** : 문항당 평균 2분이라는 시간 예산. 막히면 찍고 표시하고 넘어가는 규율이 페이스를 지킨다.

## 📝 연습 문제

**문제 1.** 핀테크 회사가 신용카드 사기를 실시간으로 탐지하려 한다. 거래의 99.7%가 정상이며, 사기를 놓치는 비용이 매우 크다. 어떤 평가 지표를 우선해야 하는가?

A) Accuracy  
B) Recall(과 보조로 F1·AUC-ROC)  
C) RMSE  
D) R² 결정계수  

**정답: B**  
해설: 극심한 불균형(99.7% 정상)에서 사기를 놓치는 비용이 크면 거짓음성을 최소화하는 Recall을 우선하고 전반 균형은 F1·AUC로 본다. A는 "전부 정상" 예측만으로 99.7%가 나와 사기 탐지력을 못 보여주고, C·D는 회귀 지표라 분류 평가에 부적합하다.

**문제 2.** 전국 2,000개 매장에 매장별 수요 예측 XGBoost 모델이 있다. 각 모델은 하루 몇 번만 호출되며, 2,000개 엔드포인트 비용이 부담이다. 가장 비용 효율적인 배포는?

A) 매장마다 별도 실시간 엔드포인트  
B) 멀티모델 엔드포인트(MME)  
C) 멀티컨테이너 엔드포인트(MCE)  
D) 2,000개를 묶은 추론 파이프라인  

**정답: B**  
해설: "같은 프레임워크(XGBoost) 모델이 매우 많고 개별 호출 빈도가 낮다"는 MME의 정확한 조건으로, 소수 인스턴스에 모델을 동적 로드·공유해 비용을 크게 낮춘다. A는 2,000개 엔드포인트로 비용이 폭발하고, C는 서로 다른 프레임워크 소수 모델용이며, D는 전처리→추론 순차 체인이라 다수 모델 서빙과 무관하다.

**문제 3.** 의료 영상 모델이 개별 요청당 250MB 이미지를 받아 약 8분간 추론하며, 결과는 완료 후 S3에서 수령한다. 가장 적절한 추론 옵션은?

A) 실시간 엔드포인트  
B) 서버리스 추론  
C) 비동기 추론  
D) 배치 변환  

**정답: C**  
해설: 페이로드 250MB와 처리 8분은 실시간/서버리스 한계(6MB·4MB / 60초)를 초과하고, 개별 요청을 큐로 받아 결과를 S3에 저장하는 패턴은 비동기 추론(최대 1GB·60분)과 정확히 일치한다. A·B는 페이로드·시간 제약으로 탈락하고, D는 전체 데이터셋 일괄 방식이라 "개별 요청" 패턴과 다르다.

**문제 4.** 규제 대상 데이터로 학습하는데, 학습 컨테이너가 인터넷을 거치지 않고 S3·ECR에 접근하고 외부로의 데이터 유출을 차단해야 한다. 가장 적절한 구성은?

A) IAM 정책만 강화  
B) VPC 내 학습 + S3·ECR VPC 엔드포인트 + 네트워크 격리(EnableNetworkIsolation)  
C) KMS 암호화만 적용  
D) 퍼블릭 서브넷 + 보안그룹  

**정답: B**  
해설: VPC 내부 학습 + VPC 엔드포인트로 인터넷 비경유 접근 + 네트워크 격리로 외부 통신 차단의 조합이 요구를 정확히 충족한다. A는 권한만으로 네트워크 격리가 안 되고, C는 저장 암호화일 뿐 네트워크와 무관하며, D는 퍼블릭 노출이 남아 유출 차단 요구에 어긋난다.

**문제 5.** 데이터 사이언티스트가 코드를 거의 작성하지 않고 S3 데이터셋을 시각적으로 탐색·정제하고 결측 대치·인코딩을 적용한 뒤 그 흐름을 학습 파이프라인으로 내보내려 한다. 가장 적절한 도구는?

B) SageMaker Data Wrangler  
C) Amazon Athena  
D) AWS Lambda  

**정답: B**  
해설: Data Wrangler는 비주얼 인터페이스로 데이터 탐색·정제·특성 변환을 코드 없이 수행하고 그 흐름을 처리 작업·파이프라인으로 내보낼 수 있어 요구와 일치한다. A는 직접 Spark 코딩이 필요하고, C는 SQL 분석 쿼리 도구이며, D는 범용 함수 실행으로 비주얼 데이터 준비 기능이 없다.

**문제 6.** 운영 중인 모델의 예측 정확도가 시간이 지나며 떨어지는지(실제 정답 대비) 감시하려 한다. 어떤 구성이 필요한가?

A) Model Monitor — Data Quality 모니터만

C) Clarify 편향 분석 일회 실행  
D) CloudTrail 로그 분석

해설: 예측 성능 저하(정답 대비)를 감시하려면 Model Quality 모니터가 필요하며, 이를 계산하려면 실제 정답 라벨을 수집해 예측과 대조해야 한다. A의 Data Quality는 입력 분포 변화만 보고 정답 대비 성능을 평가하지 못하고, C는 일회성 편향 분석이며, D는 API 감사 로그라 모델 성능과 무관하다.

**문제 8.** 새 학습 데이터가 S3에 들어올 때마다 자동으로 재학습→평가→(기준 통과 시)등록을 수행하고, 모델 버전과 승인 상태를 관리하려 한다. 가장 적절한 조합은?

A) cron으로 단일 학습 작업만 반복  
B) EventBridge 트리거 → SageMaker Pipeline(ConditionStep) → Model Registry 등록/승인  
C) 사람이 수동으로 노트북 실행  
D) Model Monitor가 재학습을 직접 수행  

**정답: B**  
해설: EventBridge가 S3 이벤트로 Pipeline을 시작하고, ConditionStep이 평가 기준 통과 시에만 Model Registry에 등록·승인 관리하게 하는 것이 자동 재학습 MLOps의 표준 패턴이다. A는 평가·조건·버전관리가 없고, C는 자동화가 아니며, D는 Model Monitor가 재학습 실행 주체가 아니라 부적절하다.
