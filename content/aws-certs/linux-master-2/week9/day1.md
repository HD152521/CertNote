# Day 1 - OSI 7계층과 TCP/IP

## 📌 핵심 정리

- OSI 7계층은 아래부터 **물리 · 데이터링크 · 네트워크 · 전송 · 세션 · 표현 · 응용**이다.
- 앞 글자만 따서 **"물데네전세표응"** 으로 외운다.
- 계층별 장비 — **1계층 리피터·허브, 2계층 브리지·스위치, 3계층 라우터, 4계층 이상 게이트웨이**.
- 데이터 단위 — **1 비트, 2 프레임, 3 패킷, 4 세그먼트**.
- **TCP/IP는 4계층**이며 OSI 7계층을 묶은 실제 구현 모델이다.

## OSI 7계층

```text
   7  응용 (Application)      사용자와 만나는 서비스      HTTP · FTP · SMTP · DNS
   6  표현 (Presentation)     암호화 · 압축 · 인코딩      JPEG · ASCII · SSL
   5  세션 (Session)          연결의 시작과 끝 관리
   ─────────────────────────────────────────────────────────────
   4  전송 (Transport)        종단 간 전달, 신뢰성        TCP · UDP     세그먼트
   3  네트워크 (Network)      경로 선택, 주소 지정        IP · ICMP     패킷
   2  데이터링크 (Data Link)  같은 망 안의 전달, 오류검출  MAC · 이더넷   프레임
   1  물리 (Physical)         전기 신호로 바꿔 전송        케이블 · 허브   비트
```

| 계층 | 이름 | 하는 일 | 대표 장비 | 데이터 단위 |
|-----|------|--------|----------|-----------|
| **7** | **응용** | 사용자 서비스 | 게이트웨이 | 데이터 |
| **6** | **표현** | **암호화·압축·형식 변환** | | 데이터 |
| **5** | **세션** | 연결 유지·동기화 | | 데이터 |
| **4** | **전송** | **종단 간 신뢰성**, 포트 | 게이트웨이 | **세그먼트** |
| **3** | **네트워크** | **경로 선택(라우팅)**, IP 주소 | **라우터** | **패킷** |
| **2** | **데이터링크** | 같은 망 전달, **MAC 주소** | **브리지·스위치** | **프레임** |
| **1** | **물리** | 전기 신호 전송 | **리피터·허브** | **비트** |

> **계층 번호와 이름을 바로 대응**시킬 수 있어야 한다. "3계층은?" → 네트워크, "라우터는 몇 계층?" → 3계층 식으로 나온다.

### 주소는 계층마다 다르다

| 계층 | 주소 |
|-----|------|
| **2계층** | **MAC 주소** (물리 주소, 48비트) |
| **3계층** | **IP 주소** (논리 주소) |
| **4계층** | **포트 번호** |

- **MAC은 하드웨어에 새겨진 주소**라 바뀌지 않고, **IP는 설정으로 바뀐다.**
- MAC 주소는 `00:1a:2b:3c:4d:5e` 처럼 **16진수 12자리**로 쓴다. 16진수 한 자리가 4비트이므로 12 × 4 = **48비트**다. 앞쪽 절반(24비트)은 **제조사 번호**, 뒤쪽 절반은 제조사가 붙인 일련번호다.
- OSI 모델을 만든 곳은 **ISO**(국제표준화기구)다. 철자가 뒤집힌 꼴이라 **"ISO가 OSI를 만들었다"** 로 묶어 둔다.

### 설명 문장에서 계층 찾기

계층 이름을 직접 묻기보다 **설명을 주고 몇 계층인지** 고르게 하는 문항이 많다. 문장 속 단서 낱말로 가른다.

| 문장에 이런 말이 나오면 | 계층 |
|---------------------|------|
| 전기적·기계적 특성, 케이블, 신호, 비트 전송 | **1 물리** |
| 인접한 두 장치 사이, 프레임, MAC 주소, 오류 검출 | **2 데이터링크** |
| 경로 설정(라우팅), 논리 주소(IP), 패킷 | **3 네트워크** |
| 종단 간(end-to-end), 포트, 흐름 제어, 재전송 | **4 전송** |
| 대화 제어, 연결의 설정·유지·해제, 동기점 | **5 세션** |
| 암호화, 압축, 코드·형식 변환 | **6 표현** |
| 사용자에게 서비스를 제공, 메일·웹·파일 전송 | **7 응용** |

- **2계층과 4계층이 가장 잘 섞인다.** 둘 다 "오류"와 "흐름"을 다루지만 **2계층은 바로 옆 장치까지**, **4계층은 출발지에서 목적지까지 전체**를 책임진다. "인접"이면 2, "종단 간"이면 4다.
- **5·6계층은 한 낱말로 정한다.** "암호화·압축"이 보이면 표현, "대화·동기"가 보이면 세션이다.

### 장비는 "무엇을 보고 전달하나"로 가른다

| 장비 | 계층 | 보는 것 | 하는 일 |
|------|-----|--------|--------|
| **리피터** | 1 | 아무것도 안 본다 | 약해진 **신호를 증폭**해 더 멀리 보낸다 |
| **허브** | 1 | 아무것도 안 본다 | 들어온 신호를 **모든 포트로** 내보낸다 |
| **브리지** | 2 | **MAC 주소** | 두 구간을 잇고, 필요한 프레임만 넘긴다 |
| **스위치** | 2 | **MAC 주소** | 목적지 MAC이 연결된 **그 포트로만** 보낸다 |
| **라우터** | 3 | **IP 주소** | **서로 다른 네트워크**를 잇고 경로를 고른다 |
| **게이트웨이** | 4~7 | 상위 계층 내용 | **프로토콜이 다른 망**을 변환해 잇는다 |

- **허브와 스위치는 생김새가 같지만 계층이 다르다.** 허브는 주소를 볼 줄 몰라 전부에게 뿌리고, 스위치는 MAC 주소를 기억해 두었다가 해당 포트로만 보낸다.
- **허브는 "포트가 여러 개인 리피터", 스위치는 "포트가 여러 개인 브리지"** 로 짝지으면 1계층 둘, 2계층 둘이 한 번에 정리된다.
- 여기서 **게이트웨이**는 계층 모델에서의 장비 이름이다. 4일 차에 나오는 **기본 게이트웨이**(밖으로 나가는 출구 주소)는 실제로는 라우터가 맡는다. 같은 낱말이 두 뜻으로 쓰인다.

## 캡슐화 — 내려가며 머리말이 붙는다

보내는 쪽에서는 데이터가 **위 계층에서 아래 계층으로** 내려가며 계층마다 **헤더**(머리말)가 하나씩 붙는다. 받는 쪽은 반대로 올라가며 하나씩 벗긴다.

```text
   7~5 응용 데이터                                   [ 데이터 ]
   4   전송       + TCP 헤더(포트 번호)        [ TCP | 데이터 ]          세그먼트
   3   네트워크   + IP 헤더(IP 주소)      [ IP | TCP | 데이터 ]          패킷
   2   데이터링크 + 이더넷 헤더(MAC 주소) [ MAC | IP | TCP | 데이터 | FCS ]  프레임
   1   물리       0과 1의 신호로 바꿔 전송                                비트
```

- **붙이는 것이 캡슐화(encapsulation), 벗기는 것이 역캡슐화**다.
- 데이터 단위 이름이 계층마다 다른 이유가 이것이다. **헤더가 하나 붙을 때마다 이름이 바뀐다** — 세그먼트에 IP 헤더를 붙이면 패킷, 패킷에 이더넷 헤더를 붙이면 프레임이다.
- 헤더에 담기는 주소도 계층과 짝이 맞는다 — **4계층 헤더에 포트, 3계층 헤더에 IP, 2계층 헤더에 MAC**.
- **프레임만 꼬리(FCS)가 붙는다.** 받은 쪽이 전송 중에 깨졌는지 검사하는 값이다. 2계층의 역할에 "오류 검출"이 들어 있는 근거다.

## TCP/IP 4계층

실제 인터넷은 OSI가 아니라 **TCP/IP 모델**로 동작한다.

```text
   OSI 7계층                    TCP/IP 4계층
   ──────────────────────────────────────────────
   7 응용  ┐
   6 표현  ├──────────────►   4  응용 (Application)
   5 세션  ┘
   4 전송  ───────────────►   3  전송 (Transport)
   3 네트워크 ─────────────►   2  인터넷 (Internet)
   2 데이터링크 ┐
   1 물리      ┘──────────►   1  네트워크 액세스
```

| TCP/IP 계층 | 묶인 OSI 계층 | 대표 프로토콜 |
|------------|-------------|-------------|
| **응용** | 7·6·5 | HTTP, FTP, SMTP, DNS |
| **전송** | 4 | **TCP, UDP** |
| **인터넷** | 3 | **IP, ICMP, ARP** |
| **네트워크 액세스** | 2·1 | 이더넷 |

- **OSI는 이론 모델, TCP/IP는 실제 구현**이다. 이 대비를 묻는 문제가 나온다.
- 계층 이름은 책마다 조금씩 다르게 적는다. **인터넷 계층 = 네트워크 계층**, **네트워크 액세스 계층 = 네트워크 인터페이스 계층 = 링크 계층**은 같은 것을 가리킨다.

### 인터넷 계층의 네 프로토콜

| 프로토콜 | 하는 일 | 떠올릴 것 |
|---------|--------|----------|
| **IP** | 주소를 붙여 **목적지까지 전달**한다. 도착을 보장하지는 않는다 | 비연결형 |
| **ICMP** | **오류와 상태를 알려 주는** 메시지 | **`ping`** 이 쓰는 프로토콜 |
| **ARP** | **IP 주소 → MAC 주소**를 알아낸다 | `arp` 명령 |
| **RARP** | **MAC 주소 → IP 주소**를 알아낸다 | ARP의 반대(Reverse) |

- **ARP와 RARP는 방향만 다르다.** "IP는 아는데 MAC을 모를 때"가 ARP, 그 반대가 RARP다. 방향을 바꿔 놓은 보기가 오답으로 쓰이기 쉽다.
- **IP 자체는 신뢰성이 없다.** 순서를 맞추고 빠진 것을 다시 보내는 일은 한 층 위의 TCP가 맡는다. "TCP/IP"라는 이름이 두 프로토콜의 분업을 그대로 보여 준다.

## TCP와 UDP

| 구분 | **TCP** | **UDP** |
|------|--------|--------|
| 연결 | **연결형** (3-way handshake) | **비연결형** |
| 신뢰성 | **보장한다** (재전송·순서) | 보장하지 않는다 |
| 속도 | 느리다 | **빠르다** |
| 용도 | 웹, 메일, 파일 전송 | **스트리밍, DNS, VoIP** |

- **TCP는 정확하게, UDP는 빠르게**가 핵심 대비다.
- TCP의 연결 수립은 **3-way handshake** — SYN → SYN/ACK → ACK 세 단계다.

```text
   클라이언트                         서버
       │ ──────── SYN ──────────►  │   1  "연결해도 될까요"
       │ ◄────── SYN/ACK ───────── │   2  "좋습니다, 저도 연결할게요"
       │ ──────── ACK ──────────►  │   3  "확인했습니다"
       │ ◄═════ 데이터 전송 ═════► │
```

- 세 번 주고받는 이유는 **양쪽이 모두 "보낼 수 있고 받을 수 있다"는 것을 확인**해야 하기 때문이다. 데이터는 3단계가 끝난 뒤에야 흐른다.
- 연결을 끊을 때는 **FIN**을 주고받으며 네 단계(4-way handshake)를 거친다. **맺을 때 3번, 끊을 때 4번**이다.
- UDP에는 이 절차가 없다. 그래서 빠르지만, 중간에 사라져도 보낸 쪽이 알지 못한다.

| 전송 프로토콜 | 그 위에서 도는 서비스 |
|-------------|------------------|
| **TCP** | HTTP · HTTPS · FTP · SSH · TELNET · SMTP · POP3 · IMAP |
| **UDP** | DHCP · SNMP · NTP · TFTP |
| 둘 다 | **DNS** — 보통 UDP, 응답이 크면 TCP |

- 가르는 기준은 **"한 글자라도 빠지면 안 되는가"** 다. 파일·메일·로그인은 빠지면 안 되니 TCP, 짧은 질의응답이나 실시간 전송은 UDP다.

## 주요 포트 번호

| 포트 | 서비스 |
|-----|-------|
| **20 / 21** | **FTP** (데이터 / 제어) |
| **22** | **SSH** |
| **23** | **TELNET** |
| **25** | **SMTP** (메일 보내기) |
| **53** | **DNS** |
| **80** | **HTTP** |
| **110** | **POP3** (메일 받기) |
| **143** | **IMAP** |
| **443** | **HTTPS** |
| 631 | CUPS(IPP) |

- **포트 번호를 그대로 묻는다.** 특히 **22(SSH) · 23(TELNET) · 25(SMTP) · 53(DNS) · 80(HTTP) · 110(POP3)** 은 반드시 외운다.
- **0~1023은 잘 알려진 포트(well-known port)** 로 root 권한이 있어야 열 수 있다.
- 포트와 서비스의 대응은 **`/etc/services`** 파일에 정리되어 있다.

| 범위 | 이름 | 쓰임 |
|------|------|------|
| **0 ~ 1023** | **잘 알려진 포트** | 주요 서비스에 고정 배정 |
| 1024 ~ 49151 | 등록된 포트 | 특정 프로그램이 등록해 쓰는 번호 |
| 49152 ~ 65535 | 동적 포트 | 클라이언트가 접속할 때 **잠깐 빌려 쓰는** 번호 |

- 포트 번호는 **16비트**라 전체 범위가 **0 ~ 65535**다.
- 서버는 정해진 번호에서 **기다리고**, 클라이언트는 높은 번호 하나를 임시로 받아 **찾아간다.** 22번을 쓰는 것은 SSH 서버 쪽이지 접속하는 쪽이 아니다.

```text
   # /etc/services  —  서비스이름   포트/프로토콜
   ftp             21/tcp
   ssh             22/tcp
   telnet          23/tcp
   smtp            25/tcp
   domain          53/udp
   http            80/tcp
```

- 한 줄이 **서비스 이름 + `포트/프로토콜`** 꼴이다. 뒤의 `tcp`·`udp`가 그 서비스가 쓰는 전송 프로토콜이다.
- **DNS는 이 파일에 `domain`이라는 이름**으로 올라 있다. `dns`로 찾으면 나오지 않는다.
- 이 파일은 **이름과 번호를 짝지어 둔 표**일 뿐이다. 여기 적혀 있다고 그 포트가 열려 있는 것은 아니다. 실제로 열린 포트는 4일 차의 `netstat`·`ss`로 본다.

> 내일은 데이터가 실제로 오가는 방식 — 회선 교환과 패킷 교환, 그리고 여러 통신 기술을 다룬다.

## 📖 용어

- **OSI 7계층** : 네트워크 통신을 일곱 단계로 나눈 국제 표준 참조 모델.
- **TCP/IP 4계층** : 실제 인터넷에서 사용하는 통신 모델. OSI를 네 층으로 묶은 형태다.
- **MAC 주소** : 2계층에서 사용하는 하드웨어 고유 주소.
- **라우터** : 서로 다른 네트워크를 연결하고 경로를 정하는 3계층 장비.
- **스위치** : 같은 네트워크 안에서 MAC 주소로 전달하는 2계층 장비.
- **TCP** : 연결을 맺고 신뢰성을 보장하는 전송 계층 프로토콜.
- **UDP** : 연결 없이 빠르게 전달하는 전송 계층 프로토콜.
- **잘 알려진 포트** : 0번부터 1023번까지의 포트. 주요 서비스에 미리 배정되어 있다.

C) 전송 계층  
D) 세션 계층  

**정답: B**  
해설: OSI 7계층은 아래에서부터 물리, 데이터링크, 네트워크, 전송, 세션, 표현, 응용 순서이다. 3계층인 네트워크 계층은 IP 주소를 사용해 경로를 선택하는 라우팅을 담당하며 대표 장비는 라우터이다.

**문제 2.** 다음 중 OSI 7계층에서 라우터가 동작하는 계층으로 알맞은 것은?

A) 물리 계층  
B) 데이터링크 계층  
C) 전송 계층  
D) 네트워크 계층  

**정답: D**  
해설: 라우터는 IP 주소를 보고 서로 다른 네트워크 사이의 경로를 결정하므로 3계층인 네트워크 계층 장비이다. 리피터와 허브는 1계층, 브리지와 스위치는 2계층에서 동작한다.

**문제 3.** 다음 중 연결을 맺지 않고 데이터를 전송해 속도가 빠른 대신 신뢰성을 보장하지 않는 프로토콜로 알맞은 것은?

A) TCP  
B) IP  
C) UDP  
D) ICMP  

**정답: C**  
해설: UDP는 연결 설정 과정 없이 데이터를 보내므로 지연이 적어 스트리밍이나 DNS 조회처럼 속도가 중요한 곳에 쓰인다. TCP는 3-way handshake로 연결을 맺고 재전송과 순서 보장을 제공하는 연결형 프로토콜이다.

**문제 4.** 다음 중 SSH 서비스가 기본으로 사용하는 포트 번호로 알맞은 것은?

A) 22  
B) 23  
C) 25  
D) 21  

**정답: A**  
해설: SSH는 22번 포트를 사용하며 통신 내용을 암호화한다. 23번은 암호화하지 않는 TELNET, 25번은 메일 전송에 쓰이는 SMTP, 21번은 FTP의 제어 포트이다.

**문제 5.** 다음 중 OSI 7계층에서 데이터링크 계층의 데이터 전송 단위로 알맞은 것은?

A) 패킷  
B) 프레임  
C) 세그먼트  
D) 비트  

**정답: B**  
해설: 계층별 데이터 단위는 물리 계층이 비트, 데이터링크 계층이 프레임, 네트워크 계층이 패킷, 전송 계층이 세그먼트이다. 프레임에는 출발지와 목적지의 MAC 주소가 담긴다.
