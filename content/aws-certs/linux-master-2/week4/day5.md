# Day 5 - Week 4 종합 복습: 권한 한 장 정리

## 📌 핵심 정리

- 권한은 **[특수][소유자][그룹][기타]** 네 자리다. 앞자리가 0이면 생략한다.
- **r=4 w=2 x=1**, **SetUID=4 SetGID=2 Sticky=1** — **두 줄이 같은 4·2·1** 이다.
- **umask는 빼기**다. **파일은 666, 디렉터리는 777** 에서 뺀다. 기본값 022 → 644 / 755.
- **`chown`은 root만**, `chmod`는 소유자도 할 수 있다.
- **`df`는 파일 시스템, `du`는 경로.** `umount`는 n이 없다.

## 권한 한 장

```text
   chmod  4  7  5  5   file
          │  │  │  │
          │  │  │  └── other   r-x
          │  │  └───── group   r-x
          │  └──────── user    rwx
          └─────────── 특수     SetUID
                       4 SetUID · 2 SetGID · 1 Sticky

   -rws r-x r-x
    │└┬┘ └┬┘ └┬┘
    │ │   │   └── 기타
    │ │   └────── 그룹
    │ └────────── 소유자 (x 자리가 s = SetUID)
    └──────────── 파일 종류
```

```text
   umask 계산

     파일      666  -  umask
     디렉터리   777  -  umask

     022  →  파일 644 · 디렉터리 755   (기본)
     077  →  파일 600 · 디렉터리 700   (엄격)
     000  →  파일 666 · 디렉터리 777   (파일은 777이 아니다!)
```

## 8진수 변환표 — 외워 둘 것

| 숫자 | 표기 | 숫자 | 표기 |
|-----|------|-----|------|
| **7** | `rwx` | 3 | `-wx` |
| **6** | `rw-` | **2** | `-w-` |
| **5** | `r-x` | 1 | `--x` |
| **4** | `r--` | 0 | `---` |

| 권한값 | 표기 | 쓰이는 곳 |
|-------|------|----------|
| **644** | `rw-r--r--` | 일반 파일 |
| **755** | `rwxr-xr-x` | 디렉터리·실행 파일 |
| **600** | `rw-------` | 비밀 키 |
| **1777** | `rwxrwxrwt` | **`/tmp`** |
| **4755** | `rwsr-xr-x` | **`/usr/bin/passwd`** |

## 헷갈리는 짝 대조

| 구분 | A | B | 가르는 기준 |
|------|---|---|-----------|
| 파일의 `x` vs 디렉터리의 `x` | 실행 | **진입(`cd`)** | 대상이 무엇인가 |
| 파일의 `r` vs 디렉터리의 `r` | 내용 읽기 | **목록 보기** | 〃 |
| `chmod 755` vs `chmod u+x` | **전체를 덮어씀** | 지금 상태에 더함 | 기존 권한 보존 |
| `chown` vs `chgrp` | 소유자 | 그룹 | 무엇을 바꾸나 |
| `chown` vs `chmod` | **root만** | 소유자도 가능 | 누가 할 수 있나 |
| SetUID vs SetGID | 소유자 권한 | 그룹 권한 / **그룹 상속** | 어느 자리의 s |
| SetGID(파일) vs SetGID(디렉터리) | 그룹 권한 실행 | **그룹 물려주기** | 대상이 무엇인가 |
| Sticky vs 일반 `w` | **자기 것만 삭제** | 남의 것도 삭제 | 삭제 제한 여부 |
| `s` vs `S` | x 권한 **있음** | x 권한 없음 | 대소문자 |
| `df` vs `du` | **파일 시스템** 용량 | **경로별** 사용량 | 무엇을 세나 |
| `/bin` vs `/sbin` | 일반 명령 | **관리자 명령** | 누가 쓰나 |
| `/` vs `/root` | 최상위 | **root의 홈** | 위치 |
| `/mnt` vs `/media` | 수동 마운트 | 이동식 매체 | 자동 여부 |

## 자주 틀리는 지점

1. **umask 000이면 파일이 777** → 아니다. 파일 기준값이 **666**이라 **666**이다. 777이 되는 건 디렉터리다.
2. **umask는 더하기** → **빼기**다. 값이 클수록 권한이 좁아진다.
3. **디렉터리의 x는 실행** → **진입**이다. `x`가 없으면 `cd` 가 안 된다.
4. **읽기 전용 파일은 못 지운다** → 지울 수 있다. 삭제는 **파일이 아니라 그 디렉터리의 `w`** 가 결정한다. 이걸 막는 게 Sticky bit다.
5. **소유자면 무조건 다 된다** → 아니다. 권한은 **user 칸 하나만** 적용된다. 소유자 칸이 좁으면 소유자가 못 읽는다.
6. **자기 파일을 남에게 넘길 수 있다** → `chown`은 **root만** 가능하다.
7. **`unmount`** → **`umount`** 다. n이 없다.
8. **`fsck`를 마운트한 채 실행** → 손상 위험이 있다. **반드시 언마운트** 후에 한다.
9. **특수 권한 순서를 1·2·4로** → **4(SetUID)·2(SetGID)·1(Sticky)** 다. rwx와 같은 순서로 외운다.
10. **umask 033이면 파일이 633** → **644**다. umask는 켜진 권한을 꺼 줄 뿐이라, 파일에 원래 없던 `x`는 뺄 것이 없다.
11. **SetUID는 root 권한으로 실행** → 정확히는 **파일 소유자**의 권한이다. 소유자가 root일 때 root 권한이 된다.
12. **Sticky bit가 걸리면 남의 파일을 못 읽는다** → 막는 것은 **삭제와 이름 변경**뿐이다. 읽기·쓰기는 파일 자신의 권한이 정한다.
13. **`df /var/log`는 그 디렉터리의 크기** → 그 디렉터리가 속한 **파일 시스템 전체**의 용량이다. 디렉터리 크기는 `du -sh`다.
14. **`chmod -r`로 하위까지** → 재귀는 **대문자 `-R`** 이다. `chown`·`chgrp`도 같다.

## 손으로 풀어 보는 계산

시험장에서는 계산기 없이 바로 바꿔야 한다. 유형별로 한 번씩 따라가 본다.

### 유형 ① 기호 ↔ 숫자

```text
   rwxr-x--x   →  (4+2+1)(4+0+1)(0+0+1)  →  751
   rw-rw----   →  (4+2+0)(4+2+0)(0+0+0)  →  660
   640         →  6=rw-  4=r--  0=---    →  rw-r-----
   711         →  7=rwx  1=--x  1=--x    →  rwx--x--x
```

- 빠른 확인법: **홀수 자리에는 `x`가 있다.** 6·4·2·0은 실행 불가, 7·5·3·1은 실행 가능이다.

### 유형 ② 기호 방식의 결과

`rw-r--r--`(644)에서 시작해 차례로 적용한다.

| 명령 | 결과 | 값 |
|------|------|-----|
| `chmod u+x` | `rwxr--r--` | 744 |
| `chmod go-r` | `rwx------` | 700 |
| `chmod a+r` | `rwxr--r--` | 744 |
| `chmod g=rw` | `rwxrw-r--` | 764 |
| `chmod o=` | `rwxrw----` | 760 |

- **`+`·`-`는 적은 것만 바꾸고, `=`는 그 대상의 세 칸을 통째로 바꾼다.** `g=rw`는 그룹에 있던 권한을 지우고 `rw-`로 다시 쓴다.

### 유형 ③ umask

| umask | 디렉터리 (777에서) | 파일 (666에서) |
|-------|-----------------|--------------|
| 022 | 755 | 644 |
| 002 | 775 | 664 |
| 027 | 750 | 640 |
| 077 | 700 | 600 |
| 033 | 744 | **644** |
| 000 | 777 | **666** |

- 순서를 정해 두면 틀리지 않는다 — **디렉터리 값을 먼저 구하고(777 − umask), 거기서 `x`를 지우면 파일 값**이다.
- 거꾸로 묻는 문항도 있다. "새 디렉터리가 750으로 만들어진다. umask는?" → 777 − 750 = **027**.

### 유형 ④ 특수 권한 읽기

| 표기 | 값 | 무엇이 걸렸나 |
|------|-----|-------------|
| `-rwsr-xr-x` | 4755 | SetUID |
| `-rwxr-sr-x` | 2755 | SetGID |
| `drwxrwxrwt` | 1777 | Sticky bit |
| `drwxrws---` | 2770 | SetGID (협업 디렉터리) |
| `-rwsr-sr-x` | 6755 | SetUID + SetGID |
| `-rwSr--r--` | 4644 | SetUID인데 실행 권한 없음 |

- **`s`가 앞 세 칸에 있으면 SetUID, 가운데 세 칸에 있으면 SetGID, 맨 끝 `t`는 Sticky** 다.

## 이 사람은 무엇을 할 수 있나

권한 문항은 "누가 어느 칸을 적용받는가"를 가려내는 것이 관건이다. `alice`와 `bob`은 `dev` 그룹, `carol`은 아니다.

```text
   drwxrwx--T  2 root  dev   /project
   -rw-r-----  1 alice dev   /project/plan.txt
```

| 질문 | 답 | 근거 |
|------|-----|------|
| bob이 `plan.txt`를 읽을 수 있나 | O | dev 그룹 → 파일의 group 칸 `r--` |
| bob이 `plan.txt`를 고칠 수 있나 | X | group 칸에 `w`가 없다 |
| bob이 `plan.txt`를 지울 수 있나 | **X** | 디렉터리에 `w`는 있지만 **Sticky bit** 가 걸려 소유자만 지운다 |
| bob이 `/project`에 새 파일을 만들 수 있나 | O | 디렉터리의 group 칸 `rwx` |
| carol이 `/project`에 들어갈 수 있나 | X | 디렉터리의 other 칸에 `x`가 없다 (`T`는 대문자) |
| alice가 `plan.txt`의 소유자를 bob으로 바꿀 수 있나 | **X** | `chown`은 root만 |
| alice가 `plan.txt`의 권한을 바꿀 수 있나 | O | `chmod`는 소유자도 가능 |

- 따지는 순서는 늘 같다 — **① 어느 칸인가(소유자 → 그룹 → 기타, 하나만) ② 대상이 파일인가 디렉터리인가 ③ 삭제라면 파일이 아니라 디렉터리 권한과 Sticky bit.**

## 명령과 옵션 모으기

| 명령 | 하는 일 | 꼭 기억할 옵션 |
|------|--------|--------------|
| `chmod` | 권한 변경 | `-R` 재귀 |
| `chown` | 소유자(와 그룹) 변경 | `-R`, `소유자:그룹` 형식 |
| `chgrp` | 그룹 변경 | `-R` |
| `umask` | 기본 권한 마스크 확인·설정 | `-S` 기호로 보기 |
| `mount` | 파일 시스템 연결 | `-t` 종류, `-o` 옵션, `-a` fstab 전부 |
| `umount` | 연결 해제 | 장치 이름 또는 마운트 지점 |
| `df` | 파일 시스템별 용량 | `-h`, `-T` 종류, `-i` inode |
| `du` | 경로별 사용량 | `-h`, `-s` 합계 |
| `fsck` | 파일 시스템 검사·복구 | `-y` 전부 yes, **언마운트 후** 실행 |
| `find -perm` | 권한으로 찾기 | `-perm -4000` SetUID 포함 |
| `stat` | 8진수·기호 권한을 함께 표시 | |
| `ls -ld` | 디렉터리 **자체**의 권한 | |

| 파일 | 무엇 |
|------|------|
| `/etc/fstab` | **부팅 때 마운트할** 목록 (6필드) |
| `/etc/mtab`, `/proc/mounts` | **지금 마운트된** 목록 |
| `/etc/profile`, `/etc/bashrc` | 시스템 전체의 umask 설정 |
| `~/.bashrc` | 사용자 개인의 umask 설정 |

## 디렉터리 한 줄 요약

| 디렉터리 | 한 줄 | 디렉터리 | 한 줄 |
|---------|-------|---------|-------|
| `/bin` | 기본 명령 | `/sbin` | 관리자 명령 |
| `/etc` | 설정 파일 | `/var` | 로그·스풀 등 변하는 것 |
| `/home` | 사용자 홈 | `/root` | root의 홈 |
| `/dev` | 장치 파일 | `/proc` | 커널·프로세스 정보(가상) |
| `/boot` | 커널·부트로더 | `/lib` | 공유 라이브러리 |
| `/usr` | 응용 프로그램 | `/opt` | 추가 패키지 |
| `/tmp` | 임시 파일 (1777) | `/mnt`, `/media` | 마운트 지점 |

## 시험에 그대로 나오는 값

| 값 | 무엇 |
|-----|------|
| **4 / 2 / 1** | r / w / x, 그리고 SetUID / SetGID / Sticky |
| **022** | 일반적인 기본 umask |
| **666 / 777** | umask 계산의 기준값 (파일 / 디렉터리) |
| **644 / 755** | umask 022 의 결과 |
| **1777** | `/tmp` 의 권한 |
| **4755** | `/usr/bin/passwd` 의 권한 |
| **`s` / `t`** | SetUID·SetGID / Sticky bit 의 표시 문자 |

> 다음 주는 명령을 받아 해석하는 프로그램 자체 — **셸**을 다룬다. 환경 변수, 리다이렉션, 별칭이 나온다.

## 📖 용어

- **특수 권한 자리** : 권한 네 자리 중 맨 앞자리. 0이면 생략해 세 자리로 쓴다.
- **umask** : 새 파일·디렉터리의 권한에서 깎아낼 값. 파일 666, 디렉터리 777이 기준이다.
- **SetUID / SetGID / Sticky bit** : 각각 4·2·1 값을 갖는 특수 권한.
- **마운트 포인트** : 파일 시스템이 붙는 디렉터리.
- **FHS** : 디렉터리의 이름과 역할을 정한 파일 시스템 계층 표준.
- **inode 고갈** : 용량은 남았지만 파일을 더 만들 수 없는 상태. `df -i`로 확인한다.

## 📝 연습 문제

**문제 1.** 다음 중 `chmod 1777 /shared` 명령으로 설정되는 특수 권한으로 알맞은 것은?

A) SetUID  
B) Sticky bit  
C) SetGID  
D) 특수 권한 없음  

**정답: B**  
해설: 네 자리 권한에서 맨 앞자리가 특수 권한이며 1은 Sticky bit이다. Sticky bit가 걸린 디렉터리에서는 파일의 소유자와 root만 그 파일을 삭제할 수 있다. `/tmp`가 바로 이 1777 권한을 사용한다.

---

**문제 2.** umask 값이 000일 때 새로 생성되는 일반 파일의 권한으로 알맞은 것은?

A) 777  
B) 755  
C) 644  
D) 666  

**정답: D**  
해설: 파일의 기준값은 666이므로 umask가 0이어도 666을 넘지 못한다. 새로 만드는 파일에 실행 권한을 자동으로 주지 않기 위한 설계이다. 디렉터리는 기준값이 777이므로 같은 조건에서 777이 된다.

---

**문제 3.** 다음 중 파일 자체에는 쓰기 권한이 없어도 그 파일을 삭제할 수 있게 하는 조건으로 알맞은 것은?

A) 해당 파일이 있는 디렉터리에 쓰기 권한이 있을 때  
B) 해당 파일에 읽기 권한이 있을 때  
C) 해당 파일에 실행 권한이 있을 때  
D) 해당 파일의 그룹에 속해 있을 때  

**정답: A**  
해설: 파일 삭제는 파일 자체의 권한이 아니라 그 파일이 들어 있는 디렉터리의 쓰기 권한으로 결정된다. 디렉터리에서 항목을 지우는 동작이기 때문이다. 이 때문에 공유 디렉터리에서 남의 파일이 지워지는 것을 막으려면 Sticky bit를 설정한다.

---

**문제 4.** 다음 중 관리자용 명령어가 주로 저장되는 디렉터리로 알맞은 것은?

A) /bin  
B) /lib  
C) /sbin  
D) /opt  

**정답: C**  
해설: `/sbin`에는 `fdisk`, `shutdown`처럼 시스템 관리에 사용하는 명령이 들어 있다. `/bin`은 `ls`, `cp`처럼 일반 사용자도 쓰는 기본 명령을, `/lib`은 공유 라이브러리를, `/opt`는 추가로 설치한 패키지를 담는다.

---

**문제 5.** 다음 중 `-rwxr-sr-x` 권한 표기가 나타내는 상태로 알맞은 것은?

A) SetUID가 설정되어 있다  
B) Sticky bit가 설정되어 있다  
C) 그룹에 실행 권한이 없다  
D) SetGID가 설정되어 있다  

**정답: D**  
해설: 그룹 자리의 실행 권한이 `s`로 표시된 것은 SetGID가 설정되었다는 뜻이다. 소문자 `s`이므로 실행 권한도 함께 있는 상태이다. 소유자 자리의 `s`는 SetUID, 기타 자리의 `t`는 Sticky bit를 나타낸다.

**문제 6.** 다음 중 특정 디렉터리가 차지하는 전체 용량을 합계로 확인하는 명령으로 알맞은 것은?

A) du -sh /var/log  
B) df -h /var/log  
C) ls -lh /var/log
