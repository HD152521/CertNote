# Day 2 - 파티션: 디스크를 어떻게 나눌 것인가

## 📌 핵심 정리

- **MBR** 방식은 주 파티션을 **최대 4개**까지만 만들 수 있고, 더 필요하면 **확장 파티션 안에 논리 파티션**을 만든다.
- **GPT**는 MBR의 한계(2TB, 4개)를 없앤 방식으로, **UEFI**와 짝을 이룬다.
- 장치명은 **`/dev/sda`가 첫 번째 디스크**, `/dev/sda1`이 그 첫 번째 파티션이다.
- 최소 구성은 **`/`(루트)와 swap** 둘이다. 여기에 `/boot`, `/home`을 분리하는 것이 흔한 선택이다.
- 파티션 도구는 **`fdisk`(MBR), `gdisk`(GPT), `parted`(둘 다)** 를 쓴다.

## 왜 나누는가

디스크 하나를 통째로 쓰지 않고 굳이 나누는 이유가 있다.

- **격리**: `/home`을 따로 두면 로그가 폭주해 `/var`가 꽉 차도 사용자 데이터는 무사하다.
- **재설치 편의**: `/home`이 분리돼 있으면 배포판을 갈아엎어도 개인 파일이 남는다.
- **성능·목적별 설정**: 파티션마다 다른 파일 시스템과 마운트 옵션을 줄 수 있다.
- **swap 확보**: 스왑은 별도의 파티션(또는 파일)이 필요하다.

## MBR과 GPT

| 구분 | MBR | GPT |
|------|-----|-----|
| 정식 이름 | 마스터 부트 레코드 | GUID 파티션 테이블 |
| 최대 디스크 크기 | **2TB** | 사실상 무제한 |
| 주 파티션 개수 | **최대 4개** | 128개 이상 |
| 짝이 되는 펌웨어 | BIOS | **UEFI** |
| 파티션 정보 백업 | 없음(첫 섹터 하나) | 디스크 끝에 사본 보관 |

- **2TB와 4개** — MBR의 두 한계를 숫자로 외워두면 대부분의 문항이 풀린다.
- 요즘 새로 설치하는 시스템은 대부분 **UEFI + GPT** 조합이다.

### 왜 하필 4개, 왜 하필 2TB인가

두 숫자는 임의로 정한 규칙이 아니라 **MBR이 차지하는 공간이 512바이트뿐**이라는 데서 나온다.

```text
   디스크의 첫 섹터 (512바이트) = MBR
  ┌──────────────────────────┬─────────────────────┬──────────┐
  │  부트로더 코드  446바이트   │ 파티션 테이블 64바이트 │ 서명 2바이트│
  └──────────────────────────┴─────────────────────┴──────────┘
                                16바이트짜리 칸 × 4
```

- 파티션 하나를 적는 데 16바이트가 들고 자리가 64바이트뿐이니 **4칸**이 전부다. 주 파티션이 4개인 이유다.
- 각 칸은 파티션의 시작 위치와 크기를 **32비트 숫자**(섹터 단위)로 적는다. 섹터 하나가 512바이트이므로 2³² × 512바이트 = **2TB**가 표현할 수 있는 끝이다.
- 앞쪽 446바이트는 **부트로더**의 자리다. "BIOS는 MBR에서 부트로더를 읽는다"는 말이 바로 이 영역을 가리킨다.

GPT는 이 구조를 버리고 디스크 앞쪽에 넉넉한 표를 따로 둔다.

- 파티션 위치를 64비트로 적어 용량 한계가 사실상 사라졌고, 기본으로 **128개**의 칸을 둔다. 확장·논리 파티션이라는 구분도 **필요 없어졌다.**
- 표의 **사본을 디스크 맨 끝**에 하나 더 둔다. 앞쪽이 망가져도 복구할 수 있다.
- 맨 첫 섹터에는 **보호용 MBR(protective MBR)** 을 남겨 둔다. GPT를 모르는 옛 도구가 "빈 디스크"로 착각해 덮어쓰는 것을 막기 위한 장치다.
- 파티션마다 고유 식별자(**GUID**)가 붙는다. 이름의 G가 이것이다.

### MBR의 파티션 3종

```text
  ┌──────────────────────────────────────────────┐
  │  주 파티션(Primary)   최대 4개                  │
  │  ┌────┬────┬────┬──────────────────────────┐ │
  │  │sda1│sda2│sda3│  확장 파티션(Extended)     │ │
  │  │    │    │    │  ┌──────┬──────┬───────┐  │ │
  │  │    │    │    │  │ sda5 │ sda6 │ sda7  │  │ │
  │  │    │    │    │  │ 논리(Logical)         │  │ │
  │  │    │    │    │  └──────┴──────┴───────┘  │ │
  │  └────┴────┴────┴──────────────────────────┘ │
  └──────────────────────────────────────────────┘
```

| 종류 | 설명 |
|------|------|
| **주(Primary)** | 실제로 쓰는 파티션. 최대 4개 |
| **확장(Extended)** | 논리 파티션을 담는 **껍데기**. 여기에 직접 데이터를 넣지 못한다. 디스크당 **1개**만 |
| **논리(Logical)** | 확장 파티션 안에 만드는 파티션. 번호가 **5번부터** 시작한다 |

> 함정 둘. ① 확장 파티션은 **그 자체로 저장 공간이 아니다.** ② 논리 파티션 번호는 `sda5`부터 붙는다 — 주 파티션이 2개뿐이어도 논리는 5번부터다.

## 장치 이름 읽기

```text
   /dev/sda1
        │││
        ││└── 파티션 번호 (1부터)
        │└─── 디스크 순서 (a=첫 번째, b=두 번째 …)
        └──── 장치 종류
```

| 표기 | 뜻 |
|------|-----|
| `/dev/hda` | **IDE** 방식 첫 번째 디스크 (옛 표기) |
| `/dev/sda` | **SATA·SCSI·USB** 첫 번째 디스크 |
| `/dev/sdb2` | 두 번째 디스크의 두 번째 파티션 |
| `/dev/nvme0n1p1` | NVMe SSD의 첫 번째 파티션 |
| `/dev/sr0` | 광학 드라이브(CD/DVD) |
| `/dev/vda` | 가상 머신(KVM)의 가상 디스크 |
| `/dev/fd0` | 플로피 디스크 드라이브 |

옛 IDE 방식은 메인보드에 케이블이 둘(primary·secondary), 케이블마다 장치가 둘(master·slave) 달렸다. 그래서 `hd` 뒤의 글자는 **연결된 자리**로 정해졌다.

| 장치명 | 연결 위치 |
|--------|----------|
| `/dev/hda` | primary master |
| `/dev/hdb` | primary slave |
| `/dev/hdc` | secondary master |
| `/dev/hdd` | secondary slave |

- `sd` 계열은 다르다. 자리가 아니라 **커널이 발견한 순서**대로 a, b, c가 붙는다. USB 메모리를 꽂으면 그때 남아 있는 다음 글자를 받는다.
- NVMe는 `nvme0`(컨트롤러) · `n1`(저장 공간) · `p1`(파티션) 세 조각이다. 파티션 번호 앞에 **`p`가 붙는다**는 점이 `sda1`과 다르다.

> ⚠️ **함정**: `/dev/sda`는 **디스크 전체**, `/dev/sda1`은 **그 안의 파티션**이다. 파티션을 나누는 `fdisk`에는 디스크(`/dev/sda`)를, 파일 시스템을 만드는 `mkfs`에는 파티션(`/dev/sda1`)을 넘긴다. 숫자 하나 차이로 대상이 완전히 달라진다.

## 어떤 마운트 포인트로 나눌까

| 마운트 포인트 | 담는 것 | 분리하면 좋은 이유 |
|--------------|--------|------------------|
| **`/`** (루트) | 나머지 전부 | **반드시 있어야 한다** |
| **swap** | 메모리가 모자랄 때 쓰는 예비 공간 | 별도 영역이 필요 |
| `/boot` | 커널과 부트로더 파일 | 부팅에 꼭 필요, 작게(1GB 내외) |
| `/home` | 사용자 개인 파일 | 재설치해도 데이터 보존 |
| `/var` | 로그·메일·DB 등 **자주 변하는** 데이터 | 로그 폭주로 시스템이 멈추는 것 방지 |
| `/tmp` | 임시 파일 | 누구나 쓸 수 있어 폭주 위험 |

- **최소 구성은 `/`와 swap 둘**이다. 시험에서 "반드시 필요한 것"을 물으면 답은 `/`다.
- UEFI 시스템은 여기에 **EFI 시스템 파티션(ESP, `/boot/efi`)** 이 추가로 필요하다.

### swap 크기

- 옛 기준: **메모리의 1~2배**.
- 요즘은 메모리가 커서 그대로 적용하지 않는다. 8GB 이상이면 메모리와 같거나 그 이하로 잡는 경우가 많다.
- **최대 절전(하이버네이션)** 을 쓰려면 메모리 크기 이상이 필요하다.
- 시험에서는 여전히 **"1~2배"** 라는 고전적 기준을 묻는 경우가 있다.

swap은 파일을 담는 곳이 아니라서 **만드는 명령도, 켜는 명령도 따로** 있다.

| 명령 | 하는 일 |
|------|--------|
| `mkswap /dev/sda2` | 파티션을 swap 영역으로 초기화한다 (`mkfs`가 아니다) |
| `swapon /dev/sda2` | swap을 켠다 (`mount`가 아니다) |
| `swapoff /dev/sda2` | swap을 끈다 |
| `swapon -s` | 켜져 있는 swap 목록. `cat /proc/swaps`와 같은 내용이다 |
| `free -h` | 메모리와 swap 사용량을 함께 본다 |

- swap은 디렉터리 트리에 붙지 않으므로 **마운트 포인트가 없다.** `df`에도 나오지 않는다.
- 부팅할 때마다 자동으로 켜지게 하려면 `/etc/fstab`에 `/dev/sda2  swap  swap  defaults  0  0` 처럼 한 줄을 적는다(내일 다룬다).

## 파티션 도구

| 명령 | 다루는 방식 | 특징 |
|------|-----------|------|
| `fdisk` | MBR (최근 버전은 GPT도) | 가장 전통적인 대화형 도구 |
| `gdisk` | GPT 전용 | `fdisk`와 조작법이 비슷하다 |
| `parted` | MBR·GPT 모두 | 크기 조절까지 가능, 스크립트로 쓰기 좋다 |
| `df` | — | 마운트된 파티션의 **사용량** 확인 |
| `lsblk` | — | 디스크와 파티션 **구조**를 트리로 표시 |

```bash
sudo fdisk -l          # 디스크와 파티션 목록
lsblk                  # 트리 형태로 보기
df -h                  # 마운트된 파티션 사용량
```

### 출력 읽기

```text
$ sudo fdisk -l /dev/sda
Disk /dev/sda: 20 GiB, 21474836480 bytes, 41943040 sectors
Units: sectors of 1 * 512 = 512 bytes
Disklabel type: dos

Device     Boot   Start      End  Sectors Size Id Type
/dev/sda1  *       2048  2099199  2097152   1G 83 Linux
/dev/sda2       2099200  6293503  4194304   2G 82 Linux swap / Solaris
/dev/sda3       6293504 41943039 35649536  17G 83 Linux
```

- **`Disklabel type`** 이 파티션 방식이다. **`dos`면 MBR, `gpt`면 GPT**다. "MBR"이라는 글자가 나오지 않으니 주의한다.
- `Boot` 열의 `*`는 부팅 가능 표시가 붙은 파티션이다.
- **`Id`** 는 파티션의 용도를 나타내는 16진수 코드다.

| Id | 종류 |
|----|------|
| **83** | Linux — 일반 리눅스 파티션 |
| **82** | Linux swap — 스왑 |
| **5** | Extended — 확장 파티션 |
| 7 | HPFS/NTFS/exFAT — 윈도우 파티션 |
| b | W95 FAT32 |

```text
$ lsblk
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda      8:0    0   20G  0 disk
├─sda1   8:1    0    1G  0 part /boot
├─sda2   8:2    0    2G  0 part [SWAP]
└─sda3   8:3    0   17G  0 part /
sr0     11:0    1 1024M  0 rom
```

- `TYPE`이 `disk`인 줄이 디스크, 그 아래 `part`가 파티션이다. swap은 마운트 포인트 대신 `[SWAP]`이라고 표시된다.
- `fdisk -l`은 **나뉜 모양**을, `df -h`는 **마운트된 것의 사용량**을 보여준다. 만들기만 하고 마운트하지 않은 파티션은 `df`에 **나오지 않는다.**

### fdisk 안에서 쓰는 명령

`fdisk /dev/sdb`처럼 디스크를 지정해 들어가면 한 글자 명령을 받는 대화형 화면이 된다.

| 키 | 뜻 | 기억법 |
|----|-----|-------|
| `m` | 도움말 | menu |
| `p` | 현재 파티션 표 출력 | print |
| `n` | 새 파티션 만들기 | new |
| `d` | 파티션 삭제 | delete |
| `t` | 파티션 종류(Id) 바꾸기 | type |
| `l` | 종류 코드 목록 보기 | list |
| `w` | **저장하고 나가기** | write |
| `q` | **저장하지 않고 나가기** | quit |

```text
$ sudo fdisk /dev/sdb
Command (m for help): n
Partition type
   p   primary (0 primary, 0 extended, 4 free)
   e   extended (container for logical partitions)
Select (default p): p
Partition number (1-4, default 1): 1
First sector (2048-41943039, default 2048):
Last sector, +/-sectors or +/-size{K,M,G,T,P} (2048-41943039, default 41943039): +5G

Created a new partition 1 of type 'Linux' and of size 5 GiB.

Command (m for help): w
The partition table has been altered.
```

- 화면이 묻는 `p`(primary)와 `e`(extended)가 앞에서 본 주·확장 파티션이다. `4 free`는 남은 주 파티션 칸 수다.
- 크기는 끝 섹터 번호 대신 **`+5G`** 처럼 적는 것이 보통이다.
- 스왑으로 쓸 파티션은 `t`로 종류를 **82**로 바꿔 둔다.

> ⚠️ **함정**: `fdisk` 안에서 한 작업은 **`w`를 누르기 전까지 디스크에 기록되지 않는다.** 실수했으면 `q`로 나가면 아무 일도 없었던 것이 된다. 반대로 `w` 없이 나가면 열심히 나눈 것이 전부 사라진다. "저장 후 종료"와 "저장 없이 종료"의 키를 맞바꾼 보기가 오답으로 쓰이기 쉽다.

## 자주 틀리는 지점

1. **"MBR은 파티션을 4개까지만 만들 수 있다"** → **주 파티션**이 4개까지다. 확장 파티션 안에 논리 파티션을 만들면 더 늘어난다.
2. **"주 3개 + 확장 1개면 논리는 4번부터"** → 1~4번은 주·확장 몫으로 **비워 두는 번호**다. 논리는 언제나 5번부터다.
3. **"GPT에도 확장 파티션이 있다"** → 없다. 칸이 넉넉해 필요가 없다.
4. **"swap도 `mkfs`로 만들고 `mount`로 붙인다"** → `mkswap`과 `swapon`이다.
5. **"`fdisk -l`에 `dos`라고 나오면 윈도우 디스크다"** → 운영체제와 무관하게 **MBR 방식**이라는 뜻이다.
6. **"`/dev/sdb`는 두 번째 파티션이다"** → 두 번째 **디스크**다. 파티션은 뒤에 숫자가 붙는다.

> 내일은 나눈 파티션에 무엇을 씌울지 — 파일 시스템의 종류와 차이를 본다.

## 📖 용어

- **파티션(Partition)** : 하나의 디스크를 논리적으로 나눈 영역.
- **MBR** : 마스터 부트 레코드. 2TB·주 파티션 4개의 한계가 있는 전통적 파티션 방식.
- **GPT** : GUID 파티션 테이블. MBR의 한계를 없앤 방식으로 UEFI와 함께 쓰인다.
- **주 파티션(Primary)** : 실제 데이터를 담는 파티션. MBR에서 최대 4개.
- **확장 파티션(Extended)** : 논리 파티션을 담기 위한 껍데기. 디스크당 1개, 직접 저장 불가.
- **논리 파티션(Logical)** : 확장 파티션 안에 만드는 파티션. 번호가 5번부터 시작한다.
- **스왑(Swap)** : 메모리가 부족할 때 디스크를 임시 메모리처럼 쓰는 영역.
- **마운트 포인트** : 파티션을 디렉터리 트리의 어느 위치에 연결할지 정한 지점.
- **ESP** : EFI 시스템 파티션. UEFI 부팅에 필요하며 보통 `/boot/efi`에 마운트된다.

## 📝 연습 문제

**문제 1.** 다음 중 MBR 방식에서 만들 수 있는 주 파티션의 최대 개수로 알맞은 것은?

A) 1개  
B) 2개  
C) 8개  
D) 4개  

**정답: D**  
해설: MBR 파티션 테이블은 주 파티션 정보를 4개까지만 담을 수 있습니다. 그보다 많은 파티션이 필요하면 주 파티션 자리 하나를 확장 파티션으로 만들고, 그 안에 논리 파티션을 여러 개 생성합니다. GPT는 이 제한이 없어 128개 이상을 지원합니다.

---

**문제 2.** 다음 중 확장 파티션에 대한 설명으로 알맞은 것은?

A) 디스크당 여러 개를 만들 수 있다  
B) 논리 파티션을 담기 위한 공간이며 직접 데이터를 저장하지 않는다  
C) GPT 방식에서만 사용할 수 있다  
D) 주 파티션보다 접근 속도가 빠르다  

**정답: B**  
해설: 확장 파티션은 논리 파티션을 담는 껍데기 역할만 하며 그 자체에 파일을 저장하지 않습니다. 디스크당 하나만 만들 수 있고, MBR 방식에서 주 파티션 4개 제한을 넘기 위해 사용합니다. 확장 파티션 안의 논리 파티션은 번호가 5번부터 붙습니다.

---

**문제 3.** 다음 중 두 번째 SATA 디스크의 첫 번째 파티션을 나타내는 장치명으로 알맞은 것은?

A) /dev/sdb1  
B) /dev/sda2  
C) /dev/hdb1  
D) /dev/sdb5  

**정답: A**  
해설: SATA·SCSI·USB 디스크는 `sd`로 시작하며 뒤의 알파벳이 디스크 순서(a=첫 번째, b=두 번째), 숫자가 파티션 번호입니다. 따라서 두 번째 디스크의 첫 파티션은 `/dev/sdb1`입니다. `hd`는 옛 IDE 방식 표기이고, 5번은 논리 파티션에 붙는 번호입니다.

---

**문제 4.** 다음 중 리눅스 설치 시 반드시 지정해야 하는 마운트 포인트로 알맞은 것은?

A) /home  
B) /var  
C) / (루트)  
D) /tmp  

**정답: C**  
해설: 루트(`/`)는 파일 시스템 전체의 시작점이므로 반드시 있어야 합니다. `/home`, `/var`, `/tmp`는 분리하면 관리상 이점이 있지만 필수는 아니며, 분리하지 않으면 루트 파티션 안에 포함됩니다. swap은 별도 영역이지만 마운트 포인트를 갖지 않습니다.

---

**문제 5.** 다음 중 MBR 방식의 한계로 알맞게 짝지어진 것은?

A) 최대 512GB, 주 파티션 2개  
B) 최대 1TB, 주 파티션 8개  
C) 최대 4TB, 주 파티션 16개  
D) 최대 2TB, 주 파티션 4개  

**정답: D**  
해설: MBR은 디스크 최대 크기 2TB, 주 파티션 최대 4개라는 두 가지 제약이 있습니다. 이 한계를 넘기 위해 등장한 것이 GPT이며, GPT는 사실상 무제한에 가까운 용량과 128개 이상의 파티션을 지원하고 UEFI 펌웨어와 함께 사용됩니다.
