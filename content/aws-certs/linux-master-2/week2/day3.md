# Day 3 - 파일 시스템: 나눈 공간에 무엇을 씌울 것인가

## 📌 핵심 정리

- 파티션은 **빈 땅**이고, 파일 시스템은 그 위에 세우는 **주소 체계**다. `mkfs`로 만든다.
- 리눅스 표준 계보는 **ext2 → ext3 → ext4**이며, **ext3부터 저널링**이 들어갔다.
- **저널링**은 쓰기 작업을 미리 기록해 두어, 갑자기 전원이 나가도 빠르게 복구하게 해준다.
- **inode**는 파일의 메타데이터(권한·소유자·크기·위치)를 담는 구조다. **파일 이름은 inode에 없다.**
- 마운트 정보를 영구히 기록하는 파일은 **`/etc/fstab`** 이다.

## 파일 시스템이란

- 파티션만 만들면 **아직 파일을 저장할 수 없다.** 어디에 무엇을 어떻게 적을지 규칙이 없기 때문이다.
- 그 규칙이 **파일 시스템**이다. 디렉터리 구조, 파일 이름 길이, 최대 파일 크기, 권한 기록 방식이 전부 여기서 정해진다.

```text
   디스크  →  파티션  →  파일 시스템  →  마운트  →  사용
            (나누기)     (mkfs)        (mount)
```

## 리눅스 파일 시스템 계보

| 이름 | 저널링 | 특징 |
|------|-------|------|
| **ext2** | ✗ | 리눅스 표준이었던 초기 파일 시스템 |
| **ext3** | **✓** | ext2에 **저널링을 추가**. 호환성이 좋다 |
| **ext4** | ✓ | 대용량·성능 개선. **현재 가장 널리 쓰인다** |
| **XFS** | ✓ | 대용량 파일에 강하다. RHEL 7부터 **기본** |
| **Btrfs** | ✓ | 스냅샷·압축 등 기능이 풍부. SUSE가 기본으로 채택 |

> 시험 포인트는 **"저널링이 언제부터인가"** 다. 답은 **ext3**이다. ext2에는 없다.

### 저널링이 무엇을 해결하나

- 파일을 쓰는 도중 전원이 나가면 **어디까지 썼는지 알 수 없는 상태**가 된다.
- 저널링은 **"이제 이걸 쓸 것이다"를 먼저 기록**하고 실제 작업을 한다.
- 복구할 때 그 기록만 확인하면 되므로, 디스크 전체를 검사하지 않아도 된다.
- 결과: **부팅 후 복구 시간이 극적으로 짧아진다.**

## 다른 운영체제·용도의 파일 시스템

| 이름 | 쓰이는 곳 |
|------|----------|
| **FAT32** | USB 등 범용. 호환성 최고, **한 파일 4GB 제한** |
| **exFAT** | FAT32의 4GB 제한을 없앤 것. 대용량 USB |
| **NTFS** | 윈도우 표준 |
| **ISO 9660** | CD/DVD 광학 매체 |
| **swap** | 스왑 영역 전용 |
| **HFS+ / APFS** | macOS |

> "USB에 4GB 넘는 파일이 안 들어간다"는 흔한 증상의 원인이 **FAT32**다.

## inode: 파일의 신분증

- **inode**는 파일 하나마다 붙는 정보 묶음이다.

| inode에 있는 것 | inode에 **없는** 것 |
|----------------|-------------------|
| 파일 종류, 권한 | **파일 이름** |
| 소유자·그룹 | |
| 크기 | |
| 시간 정보(수정·접근) | |
| 데이터가 있는 블록 위치 | |

- **파일 이름은 디렉터리가 가지고 있다.** 디렉터리는 "이름 ↔ inode 번호" 짝을 적어둔 목록이다.
- 그래서 이름이 다른 파일 둘이 같은 inode를 가리킬 수 있다 — 이것이 **하드 링크**다.
- inode 개수는 파일 시스템을 만들 때 정해진다. **용량이 남아도 inode가 바닥나면 파일을 못 만든다.**

```bash
ls -i 파일       # inode 번호 보기
df -i            # inode 사용량 확인
```

## 만들고, 붙이고, 기록하기

| 단계 | 명령 | 설명 |
|------|------|------|
| 만들기 | `mkfs.ext4 /dev/sdb1` | 파티션에 파일 시스템 생성(= 포맷) |
| 붙이기 | `mount /dev/sdb1 /data` | 디렉터리에 연결 |
| 떼기 | `umount /data` | 연결 해제 |
| 확인 | `df -h`, `mount`, `lsblk -f` | 상태 보기 |
| 검사 | `fsck /dev/sdb1` | 파일 시스템 오류 점검·복구 |
| 영구 등록 | `/etc/fstab` 편집 | **재부팅 후에도 자동 마운트** |

- `mount` 명령만 쓰면 **재부팅하면 사라진다.** 계속 쓰려면 `/etc/fstab`에 적어야 한다.
- `fsck`는 **마운트를 푼 상태**에서 돌리는 것이 원칙이다. 마운트된 채 검사하면 손상될 수 있다.

### /etc/fstab 한 줄 읽기

```text
/dev/sdb1   /data   ext4   defaults   0   2
    │         │       │        │      │   │
    │         │       │        │      │   └── fsck 검사 순서 (0=안 함, 1=루트, 2=나머지)
    │         │       │        │      └────── dump 백업 여부 (보통 0)
    │         │       │        └───────────── 마운트 옵션
    │         │       └────────────────────── 파일 시스템 종류
    │         └────────────────────────────── 마운트 포인트
    └──────────────────────────────────────── 장치
```

> 내일은 전원을 켠 순간부터 로그인 화면이 뜨기까지 — 부팅 과정과 부트 매니저를 따라간다.

## 📖 용어

- **파일 시스템** : 디스크에 파일과 디렉터리를 저장·관리하는 규칙 체계.
- **저널링(Journaling)** : 작업 내용을 미리 기록해 장애 시 빠르게 복구하는 기법. ext3부터 도입됐다.
- **inode** : 파일의 권한·소유자·크기·위치를 담은 구조. 파일 이름은 포함하지 않는다.
- **하드 링크** : 같은 inode를 가리키는 다른 이름. 원본을 지워도 데이터가 남는다.
- **마운트(Mount)** : 파일 시스템을 디렉터리 트리의 한 지점에 연결하는 것.
- **`/etc/fstab`** : 부팅 시 자동으로 마운트할 항목을 기록하는 설정 파일.
- **mkfs** : 파티션에 파일 시스템을 만드는 명령. 흔히 말하는 '포맷'이다.
- **fsck** : 파일 시스템의 오류를 검사하고 복구하는 명령.

## 📝 연습 문제

**문제 1.** 다음 중 저널링 기능이 처음 도입된 리눅스 파일 시스템으로 알맞은 것은?

A) ext2  
B) ext3  
C) ext4  
D) XFS  

**정답: B**  
해설: ext3은 기존 ext2에 저널링을 추가한 파일 시스템입니다. 저널링은 변경 작업을 미리 기록해 두어 갑작스러운 전원 차단 후에도 전체 검사 없이 빠르게 복구할 수 있게 합니다. ext2에는 저널링이 없고, ext4와 XFS는 그 이후에 나온 것들입니다.

---

**문제 2.** 다음 중 inode에 저장되지 않는 정보로 알맞은 것은?

A) 파일의 접근 권한  
B) 파일의 소유자와 그룹  
C) 파일의 크기  
D) 파일의 이름  

**정답: D**  
해설: inode는 파일의 권한, 소유자, 크기, 시간 정보, 데이터 블록 위치 등 메타데이터를 담지만 파일 이름은 포함하지 않습니다. 파일 이름은 디렉터리가 "이름과 inode 번호의 짝" 형태로 관리합니다. 이 구조 덕분에 여러 이름이 하나의 inode를 가리키는 하드 링크가 가능합니다.

---

**문제 3.** 다음 중 부팅할 때 자동으로 마운트할 파일 시스템을 기록하는 설정 파일로 알맞은 것은?

A) /etc/mtab  
B) /etc/inittab  
C) /etc/fstab  
D) /etc/passwd  

**정답: C**  
해설: `/etc/fstab`에는 장치, 마운트 포인트, 파일 시스템 종류, 마운트 옵션, dump 여부, fsck 검사 순서가 기록되어 부팅 시 자동으로 마운트됩니다. `mount` 명령만 사용하면 재부팅 후 사라집니다. `/etc/mtab`은 현재 마운트 상태를 담고, `/etc/passwd`는 사용자 계정 정보를 담습니다.

---

**문제 4.** 다음 중 한 개의 파일 크기가 4GB를 넘을 수 없어 대용량 파일 저장에 제약이 있는 파일 시스템으로 알맞은 것은?

A) FAT32  
B) NTFS  
C) ext4  
D) XFS  

**정답: A**  
해설: FAT32는 호환성이 매우 좋아 USB 메모리에 널리 쓰이지만 단일 파일 크기가 4GB로 제한됩니다. 이 제한을 없앤 것이 exFAT입니다. NTFS, ext4, XFS는 훨씬 큰 파일을 다룰 수 있습니다.

---

**문제 5.** 다음 중 파티션에 파일 시스템을 생성하는 명령으로 알맞은 것은?

A) fsck  
B) mkfs  
C) mount  
D) fdisk  

**정답: B**  
해설: `mkfs`(make filesystem)는 파티션에 파일 시스템을 만드는 명령으로 흔히 말하는 포맷에 해당합니다. `mkfs.ext4`처럼 종류를 지정해 사용합니다. `fdisk`는 파티션을 나누는 단계, `mount`는 만들어진 파일 시스템을 디렉터리에 연결하는 단계, `fsck`는 오류를 검사하는 명령입니다.
