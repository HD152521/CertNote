# Day 1 - 설치 유형과 준비: 리눅스를 처음 올리기 전에

## 📌 핵심 정리

- 설치 전에 **아키텍처(x86_64/ARM)와 하드웨어 호환성**을 먼저 확인한다.
- 설치 매체는 **DVD·USB·네트워크(PXE)·Live 이미지** 네 갈래다. Live 이미지는 **설치 없이 먼저 써보는** 용도다.
- 설치 유형은 **서버 / 데스크톱 / 최소(Minimal)** 로 나뉘고, 서버는 보통 **GUI를 빼는 것**이 원칙이다.
- 입문 학습에는 **가상 머신 설치**가 가장 안전하다. 스냅샷으로 되돌릴 수 있다.
- 설치 마지막에 **root 비밀번호**와 **일반 사용자 계정**을 만든다. 평소 작업은 일반 사용자로 한다.

## 설치 전에 확인할 것

| 항목 | 왜 보나 |
|------|--------|
| **아키텍처** | x86_64(대부분의 PC), ARM(라즈베리 파이, 애플 실리콘) — 이미지가 다르다 |
| CPU 가상화 지원 | 가상 머신을 쓸 거면 VT-x/AMD-V가 켜져 있어야 한다 |
| 메모리·디스크 | 최소 요구 사양은 배포판마다 다르다. GUI를 쓰면 크게 늘어난다 |
| 하드웨어 호환성 | 무선 랜·그래픽 카드가 흔한 문제 지점이다 |
| 기존 데이터 | **파티션 작업은 되돌릴 수 없다.** 백업이 먼저다 |

> 아키텍처가 안 맞으면 설치 자체가 시작되지 않는다. 32비트는 `i386`/`i686`, 64비트는 `x86_64`(또는 `amd64`)로 표기된다.

## 설치 매체 네 갈래

| 매체 | 설명 | 쓰는 상황 |
|------|------|----------|
| **DVD/ISO** | 설치에 필요한 패키지를 담은 이미지 | 표준적인 설치 |
| **USB** | ISO를 USB에 구워 부팅 | 광학 드라이브 없는 요즘 PC |
| **네트워크(PXE)** | 랜을 통해 부팅하고 설치 | 여러 대를 한 번에 설치 |
| **Live 이미지** | **설치하지 않고** 메모리에서 바로 실행 | 먼저 써보기, 복구 작업 |

- **Live 이미지의 핵심**은 "디스크에 쓰지 않는다"는 점이다. 전원을 끄면 작업 내용이 사라진다.
- 그래서 **하드디스크가 망가진 시스템을 복구**할 때도 쓴다.
- 대부분의 Live 이미지는 "지금 설치하기" 버튼을 함께 제공한다.

## 설치 유형 세 갈래

```text
   최소(Minimal)          서버(Server)           데스크톱(Desktop)
   ─────────────         ────────────           ────────────────
   커널 + 필수 도구만      최소 + 서버 데몬        서버 + X 윈도 + 응용
   GUI 없음               GUI 없음(권장)          GUI 있음
   가장 가벼움             웹·DB 서버용            개인 PC용
   직접 골라 설치          원격 접속으로 관리       화면 앞에서 사용
```

- **서버에 GUI를 넣지 않는 이유**는 두 가지다.
  - 자원을 쓴다 — 메모리와 CPU를 화면 그리는 데 쓸 이유가 없다.
  - **공격 면이 넓어진다** — 설치된 프로그램이 많을수록 취약점도 늘어난다.
- 이 원칙을 **최소 설치(minimal installation)** 라고 부른다.

## 어디에 설치할까

| 방법 | 장점 | 단점 |
|------|------|------|
| **가상 머신** | 스냅샷으로 되돌리기 쉬움, 기존 OS 유지 | 성능이 조금 손해 |
| **듀얼 부팅** | 성능 손실 없음 | 파티션 조정이 위험, 재부팅해야 전환 |
| **단독 설치** | 가장 깔끔함 | 기존 OS를 지워야 함 |
| **WSL** | 윈도우 안에서 리눅스 명령 사용 | 커널이 완전한 리눅스가 아님 |

> 학습 목적이라면 **가상 머신을 강력히 권한다.** 파티션을 잘못 잡아도 스냅샷으로 되돌리면 그만이고, 설치 과정을 몇 번이든 반복해볼 수 있다. VirtualBox·VMware·KVM 중 아무거나 좋다.

## 설치 과정의 순서

대부분의 배포판이 이 흐름을 따른다.

```text
1. 부팅 매체로 시동
        ▼
2. 언어 · 키보드 · 시간대 선택
        ▼
3. 디스크 파티션 설정          ◄── 가장 중요하고 되돌리기 어려운 단계
        ▼
4. 네트워크 · 호스트명 설정
        ▼
5. 설치할 패키지(소프트웨어) 선택
        ▼
6. root 비밀번호 · 일반 사용자 계정 생성
        ▼
7. 설치 진행 → 재부팅
```

- 3단계가 이번 주의 핵심이라 **내일 하루를 통째로 쓴다.**
- 6단계에서 만든 **일반 사용자로 평소 작업**을 하고, 관리 작업이 필요할 때만 권한을 올린다. root로 상시 로그인하는 것은 사고의 지름길이다.

## 설치 후 첫 확인

```bash
uname -r                 # 커널 버전
cat /etc/*-release       # 배포판 이름과 버전
df -h                    # 파티션이 의도대로 잡혔는지
free -h                  # 메모리와 swap
ip addr                  # 네트워크가 붙었는지
```

> 내일은 설치 과정에서 가장 어려운 단계 — 파티션을 어떻게 나눌지 다룬다.

## 📖 용어

- **아키텍처(Architecture)** : CPU의 종류와 명령어 체계. x86_64, ARM 등. 이미지가 이에 맞아야 한다.
- **ISO 이미지** : 광학 디스크의 내용을 파일 하나로 담은 것. 설치 매체의 표준 형태다.
- **Live 이미지** : 디스크에 설치하지 않고 메모리에서 바로 실행되는 배포판. 체험·복구용이다.
- **PXE** : 네트워크로 부팅해 설치하는 방식. 여러 대를 한꺼번에 설치할 때 쓴다.
- **최소 설치(Minimal)** : 꼭 필요한 것만 설치하는 방식. 자원 절약과 보안 강화가 목적이다.
- **듀얼 부팅** : 한 컴퓨터에 운영체제 둘을 설치하고 부팅할 때 골라 쓰는 것.
- **스냅샷(Snapshot)** : 가상 머신의 특정 시점 상태를 저장해 두었다가 되돌리는 기능.
- **호스트명(Hostname)** : 네트워크에서 그 컴퓨터를 부르는 이름.

## 📝 연습 문제

**문제 1.** 다음 중 디스크에 설치하지 않고 메모리에서 바로 실행되어, 체험이나 시스템 복구에 사용하는 배포판 형태로 알맞은 것은?

A) Live 이미지  
B) 최소 설치본  
C) 네트워크 설치 이미지  
D) 소스 코드 배포본  

**정답: A**  
해설: Live 이미지는 하드디스크에 쓰지 않고 메모리에서 동작하므로 기존 시스템을 건드리지 않습니다. 설치 전에 먼저 사용해 보거나, 부팅이 되지 않는 시스템을 복구할 때 유용합니다. 전원을 끄면 작업 내용은 사라집니다.

---

**문제 2.** 다음 중 서버 용도로 리눅스를 설치할 때 일반적으로 권장되는 방식으로 알맞은 것은?

A) 가능한 모든 패키지를 설치해 기능을 최대화한다  
B) 데스크톱 환경을 반드시 포함해 관리 편의를 높인다  
C) 필요한 것만 설치하고 GUI는 제외한다  
D) 반드시 Live 이미지 상태로 운영한다  

**정답: C**  
해설: 서버는 최소 설치가 원칙입니다. GUI는 메모리와 CPU를 소모할 뿐 아니라 설치된 프로그램이 많아질수록 취약점, 즉 공격 면이 넓어집니다. 서버 관리는 보통 SSH 같은 원격 접속으로 하므로 화면 출력이 필요하지 않습니다.

---

**문제 3.** 다음 중 64비트 PC용 리눅스 배포판 이미지를 나타내는 표기로 알맞은 것은?

A) i386  
B) i686  
C) armhf  
D) x86_64  

**정답: D**  
해설: `x86_64`(배포판에 따라 `amd64`로도 표기)가 64비트 PC 아키텍처입니다. `i386`과 `i686`은 32비트 x86 계열이고, `armhf`는 ARM 계열 표기입니다. 아키텍처가 맞지 않으면 설치가 시작되지 않습니다.

---

**문제 4.** 다음 중 리눅스 설치 과정에서 되돌리기 가장 어려워 사전 백업이 특히 중요한 단계로 알맞은 것은?

A) 언어와 키보드 배열 선택  
B) 디스크 파티션 설정  
C) 호스트명 지정  
D) 설치할 패키지 선택  

**정답: B**  
해설: 파티션 설정은 디스크의 구조를 바꾸고 기존 데이터를 지울 수 있어 되돌리기 어렵습니다. 언어·호스트명·패키지는 설치 후에도 얼마든지 변경할 수 있습니다. 파티션 작업 전에는 반드시 중요한 데이터를 백업해야 합니다.

---

**문제 5.** 다음 중 여러 대의 컴퓨터에 네트워크를 통해 리눅스를 설치할 때 사용하는 방식으로 알맞은 것은?

A) Live USB 부팅  
B) 듀얼 부팅  
C) PXE 부팅  
D) 스냅샷 복원  

**정답: C**  
해설: PXE(Preboot eXecution Environment)는 네트워크 카드를 통해 부팅해 설치 이미지를 내려받는 방식입니다. 설치 매체를 컴퓨터마다 꽂을 필요가 없어 다수의 시스템을 한꺼번에 설치할 때 사용합니다. 듀얼 부팅은 한 대에 운영체제 둘을 설치하는 것이고, 스냅샷은 가상 머신의 상태를 되돌리는 기능입니다.
