# Day 5 - Week 5 종합 복습: 셸 한 장 정리

## 📌 핵심 정리

- 셸은 **Bourne 계열(sh·ksh·bash·zsh·dash)** 과 **C 계열(csh·tcsh)** 둘뿐이다. **c가 들어간 둘만 C 계열**이다.
- **셸 변수는 현재 셸까지, 환경 변수는 자식까지.** 승격 명령이 **`export`** 다.
- **로그인 셸은 `.bash_profile`, 비로그인 셸은 `.bashrc`** 를 읽는다.
- **`>`는 덮어쓰기 `>>`는 이어쓰기**, **에러는 2번** 통로다.
- 설정 즉시 반영은 **`source`**, 별칭 해제는 **`unalias`**.

## 셸 한 장

```text
   셸의 갈래
     Bourne 계열   sh(Bourne) · ksh(Korn) · bash(Fox) · zsh · dash
     C 계열        csh(Joy) · tcsh                    ← 이 둘만!

   변수
     NAME=값          셸 변수    → set   으로 확인   (현재 셸까지)
     export NAME=값   환경 변수  → env   으로 확인   (자식까지)

   설정 파일
     로그인    /etc/profile  →  ~/.bash_profile  →  (~/.bashrc 호출)
     비로그인                    ~/.bashrc
     로그아웃                    ~/.bash_logout
     즉시적용  source 파일   또는   . 파일

   입출력
     0 stdin      <
     1 stdout     >   >>          &>  둘 다
     2 stderr     2>  2>>         2> /dev/null  버리기
     파이프       명령 | 명령

   편의
     alias / unalias      별칭
     history · !! · !번호  이력
```

## 헷갈리는 짝 대조

| 구분 | A | B | 가르는 기준 |
|------|---|---|-----------|
| Bourne vs C 계열 | sh·ksh·bash·zsh·dash | **csh·tcsh** | 이름에 c가 있나 |
| 셸 변수 vs 환경 변수 | 현재 셸까지 | **자식까지** | export 했나 |
| `set` vs `env` | **전부** | 환경 변수만 | 범위 |
| `.bash_profile` vs `.bashrc` | **로그인** 셸 | 비로그인 셸 | 로그인 과정 여부 |
| `.bash_profile` vs `.profile` | bash 전용 | **없을 때 대신** | 우선순위 |
| `su` vs `su -` | 비로그인 | **로그인 셸** | 하이픈 유무 |
| `>` vs `>>` | **덮어씀** | 이어 붙임 | 기존 내용 보존 |
| `>` vs `2>` | 표준 출력 | **표준 에러** | 통로 번호 |
| `>` vs `\|` | **파일**로 | 다음 **명령**으로 | 넘기는 대상 |
| `*` vs `?` | 글자 수 제한 없음 | **한 글자** | 개수 |
| `source` vs `bash` | **현재 셸**에 반영 | 새 셸에서 끝남 | 어디서 실행되나 |
| `alias` vs `unalias` | 만들기 | 지우기 | — |
| `$SHELL` vs `$0` | **로그인 셸** | 지금 실행 중인 셸 | 시점 |

## 자주 틀리는 지점

1. **zsh는 C 계열** → 아니다. **Bourne 계열**이다. C 계열은 **csh와 tcsh 둘뿐**이다.
2. **`NAME = linux`** → 등호 양옆에 **공백을 넣으면 안 된다.** `NAME=linux`.
3. **변수 만들 때도 `$`를 붙인다** → 아니다. **꺼낼 때만** 붙인다.
4. **`env`가 전부 보여 준다** → 아니다. **`set`이 전부**, `env`는 환경 변수만이다.
5. **PATH 구분자가 세미콜론** → **콜론(`:`)** 이다. 세미콜론은 윈도다.
6. **`export PATH=/opt/bin`** → 기존 경로가 날아간다. **`$PATH:`** 를 반드시 포함한다.
7. **`$?`가 1이면 성공** → **0이 성공**이다.
8. **터미널 새 창이 `/etc/profile`을 읽는다** → 읽지 않는다. **비로그인 셸은 `.bashrc`만** 읽는다.
9. **설정을 고치면 바로 적용된다** → 아니다. **`source`** 로 다시 읽거나 재로그인해야 한다.
10. **`>`로 에러도 저장된다** → 아니다. 에러는 **`2>`** 로 따로 돌린다.
11. **별칭을 `unset`으로 지운다** → **`unalias`** 다. `unset`은 변수용이다.

## 📖 용어

- **Bourne 계열 / C 계열** : 셸을 나누는 두 갈래. C 계열은 csh와 tcsh 둘뿐이다.
- **`export`** : 셸 변수를 환경 변수로 승격시키는 명령.
- **로그인 셸 / 비로그인 셸** : 로그인 과정을 거쳤는지에 따라 읽는 설정 파일이 달라진다.
- **`source`** : 설정 파일을 현재 셸에서 다시 읽는 명령. 점(`.`)과 같다.
- **파일 디스크립터** : 입출력 통로에 붙은 번호. 0·1·2가 표준 입력·출력·에러다.
- **`/dev/null`** : 보낸 데이터를 버리는 특수 파일.

## 📝 연습 문제

**문제 1.** 다음 중 Bourne 셸 계열에 속하지 **않는** 셸로 알맞은 것은?

A) bash  
B) tcsh  
C) ksh  
D) dash  

**정답: B**  
해설: 셸은 Bourne 계열과 C 계열로 나뉘며 C 계열은 csh와 그 개선판인 tcsh 둘뿐입니다. bash, ksh, dash, zsh는 모두 Bourne shell에서 갈라져 나온 Bourne 계열입니다.

---

**문제 2.** 다음 중 셸 변수와 환경 변수를 모두 출력하는 명령으로 알맞은 것은?

A) set  
B) env  
C) printenv  
D) export  

**정답: A**  
해설: `set`은 현재 셸이 가진 셸 변수와 환경 변수를 모두 출력하므로 결과가 가장 깁니다. `env`와 `printenv`는 환경 변수만 보여 주며, `export`는 변수를 환경 변수로 승격시키거나 그 목록을 보여 주는 명령입니다.

---

**문제 3.** 다음 중 명령의 표준 출력과 표준 에러를 모두 하나의 파일로 저장하는 표기로 알맞은 것은?

A) > file  
B) 2> file  
C) < file  
D) &> file  

**정답: D**  
해설: `&>`는 표준 출력과 표준 에러를 함께 지정한 파일로 보냅니다. `> file 2>&1`도 같은 결과를 냅니다. `>`는 표준 출력만, `2>`는 표준 에러만 보내며 `<`는 입력 방향을 바꾸는 기호입니다.

---

**문제 4.** 다음 중 SSH로 원격 접속했을 때 읽히는 개인 설정 파일로 알맞은 것은?

A) ~/.bashrc  
B) ~/.bash_logout  
C) ~/.bash_profile  
D) ~/.bash_history  

**정답: C**  
해설: SSH 접속은 로그인 과정을 거치므로 로그인 셸로 시작하며 `/etc/profile`에 이어 `~/.bash_profile`을 읽습니다. `~/.bashrc`는 비로그인 셸이 읽는 파일이지만, 대부분의 배포판은 `.bash_profile` 안에서 `.bashrc`를 불러오도록 설정해 둡니다.

---

**문제 5.** 다음 중 `PATH` 환경 변수에 기존 값을 유지하면서 `/opt/bin`을 추가하는 명령으로 알맞은 것은?

A) export PATH=$PATH:/opt/bin  
B) export PATH=/opt/bin  
C) export /opt/bin=$PATH  
D) PATH=/opt/bin export  

**정답: A**  
해설: 기존 경로를 유지하려면 `$PATH`를 포함해 새 경로를 이어 붙여야 합니다. `$PATH`를 빼고 지정하면 기존 검색 경로가 모두 사라져 `ls` 같은 기본 명령조차 실행되지 않는 상태가 됩니다.

---

**문제 6.** 다음 중 직전에 실행한 명령의 성공 여부를 확인할 수 있는 특수 변수와 성공을 뜻하는 값으로 알맞은 것은?

A) `$!`, 값 1  
B) `$?`, 값 0  
C) `$$`, 값 0  
D) `$?`, 값 1  

**정답: B**  
해설: `$?`에는 직전 명령의 종료 상태가 들어가며 0이면 정상 종료, 0이 아니면 오류를 뜻합니다. 참을 1로 표현하는 일반적인 관습과 반대여서 혼동하기 쉽습니다. `$$`는 현재 셸의 PID, `$!`는 마지막 백그라운드 작업의 PID입니다.
