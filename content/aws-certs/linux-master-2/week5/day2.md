# Day 2 - 셸 변수와 환경 변수

## 📌 핵심 정리

- 변수는 **`이름=값`** 으로 만든다. **등호 양옆에 공백이 있으면 안 된다.**
- **셸 변수는 지금 셸에서만**, **환경 변수는 자식 프로세스까지** 전달된다. 이 차이가 전부다.
- 셸 변수를 환경 변수로 승격시키는 명령이 **`export`** 다.
- 값을 꺼낼 때는 **`$이름`** 을 쓴다. `echo $PATH` 처럼.
- **`PATH`는 명령을 찾는 경로 목록**이고, 구분자는 **콜론(`:`)** 이다.

## 변수 만들기

```bash
NAME=linux           # 만들기 — 등호 양옆에 공백 없이!
echo $NAME           # linux
echo ${NAME}         # 중괄호로 감싸도 된다
NAME="hello world"   # 공백이 들어가면 따옴표로
unset NAME           # 지우기
```

> **공백이 실수의 원인이 되기 쉽다.** `NAME = linux` 라고 쓰면 셸은 `NAME` 을 명령으로 보고 실행하려 한다. **`=` 양옆을 붙여 쓴다.**

- 변수 이름은 관례상 **대문자**를 쓴다. 필수는 아니지만 시스템 변수와 구분하기 좋다.
- **값을 꺼낼 때만 `$`를 붙인다.** 만들 때는 붙이지 않는다.

### 이름 짓는 규칙과 중괄호

| 규칙 | 되는 예 | 안 되는 예 |
|------|--------|-----------|
| 영문자·숫자·밑줄(`_`)만 쓴다 | `MY_NAME`, `dir2` | `MY-NAME`, `my.name` |
| **숫자로 시작할 수 없다** | `v1` | `1v` |
| **대소문자를 구분한다** | `Name`과 `NAME`은 서로 다른 변수 | — |

```bash
FILE=report
echo $FILE_backup      # (빈 줄)        ← FILE_backup 이라는 변수를 찾는다
echo ${FILE}_backup    # report_backup
```

- 중괄호는 **변수 이름이 어디서 끝나는지** 알려 주는 표시다. 뒤에 글자가 바로 붙을 때 필요하다.
- **없는 변수를 꺼내면 오류가 아니라 빈 값**이 나온다. 이름을 잘못 쳐도 조용히 넘어가므로 오타를 알아채기 어렵다.

### 따옴표에 따라 달라지는 값

```bash
NAME=linux
echo "I use $NAME"            # I use linux           큰따옴표 — 변수가 값으로 바뀐다
echo 'I use $NAME'            # I use $NAME           작은따옴표 — 글자 그대로
echo "Today is `date +%F`"    # Today is 2026-10-14   백틱 — 명령을 실행한 결과
echo "Today is $(date +%F)"   # 위와 같다
```

| 기호 | 이름 | 안에 든 `$변수`는 |
|------|------|-----------------|
| **`" "`** | 큰따옴표 | **값으로 바뀐다** |
| **`' '`** | 작은따옴표 | **바뀌지 않는다** (문자 그대로) |
| `` ` ` `` | 백틱(역따옴표) | 안의 **명령을 실행한 결과**로 바뀐다. `$( )` 와 같다 |
| `\` | 역슬래시 | 바로 뒤 **한 글자**의 특수한 뜻을 없앤다 — `echo \$NAME` 은 `$NAME` |

> **큰따옴표는 풀고 작은따옴표는 막는다.** 둘 다 공백을 하나의 값으로 묶어 주는 것은 같지만, `$`를 해석하느냐가 다르다. 백틱은 따옴표처럼 생겼어도 **명령 실행**이라는 전혀 다른 일을 한다.

## 셸 변수 vs 환경 변수

```text
   현재 셸
   ├── NAME=linux        (셸 변수)   ─┐
   └── export AGE=30     (환경 변수) ─┼─ 자식에게 전달되는 건?
        │                             │
        ▼ 자식 프로세스 실행           │
      자식 셸                          │
        NAME → 비어 있음  ◄────────────┘  전달 안 됨
        AGE  → 30                         전달 됨
```

| 구분 | **셸 변수** | **환경 변수** |
|------|-----------|-------------|
| 범위 | **현재 셸에서만** | **자식 프로세스까지** |
| 만들기 | `NAME=값` | **`export NAME=값`** |
| 보기 | **`set`** | **`env`** 또는 `printenv` |
| 예 | 사용자가 임시로 만든 변수 | `PATH`, `HOME`, `SHELL` |

```bash
NAME=linux              # 셸 변수
export NAME             # 환경 변수로 승격
export AGE=30           # 만들면서 바로 환경 변수로
```

| 명령 | 보여 주는 것 |
|------|------------|
| **`set`** | **셸 변수 + 환경 변수 전부** |
| **`env`** | **환경 변수만** |
| `printenv` | 환경 변수만 (`env`와 비슷) |
| `export` | 환경 변수 목록 |
| `unset 이름` | 변수 삭제 |

> **`set`은 전부, `env`는 환경 변수만.** 이 짝이 시험 범위에 든다. 출력 범위로 기억하면 `set`이 더 넓다.

### 직접 확인: 자식 셸에서 보이는가

```bash
NAME=linux             # 셸 변수
export AGE=30          # 환경 변수
bash                   # 자식 셸로 들어간다
echo "[$NAME] [$AGE]"
# [] [30]              ← NAME 은 비어 있고 AGE 만 넘어왔다
AGE=99                 # 자식에서 값을 바꿔 본다
exit                   # 부모 셸로 돌아온다
echo $AGE
# 30                   ← 부모의 값은 그대로다
```

- 전달은 **부모 → 자식 한 방향**이다. 자식은 부모 환경의 **복사본**을 받으므로, 자식이 무엇을 바꾸든 부모에게는 닿지 않는다.
- `bash script.sh` 로 실행한 스크립트도 자식 셸이다. **스크립트 안에서 `export` 한 변수는 스크립트가 끝나면 사라진다.**
- 한번 `export` 한 변수는 **값을 다시 바꿔도 계속 환경 변수**다. 바꿀 때마다 `export`를 다시 할 필요가 없다.

### 변수를 다루는 명령 더 보기

```bash
export -p | head -3
# declare -x HOME="/home/user"
# declare -x LANG="ko_KR.UTF-8"
# declare -x LOGNAME="user"
printenv HOME          # /home/user        ← 이름을 주면 그 값만 나온다
env | grep LANG        # LANG=ko_KR.UTF-8
export -n AGE          # 환경 변수를 다시 셸 변수로 (값은 남는다)
unset AGE              # 변수 자체를 삭제
env LANG=C date        # 이 명령 한 번에만 LANG 을 바꿔 실행한다
# Wed Oct 14 09:30:00 KST 2026
```

| 헷갈리는 짝 | 차이 |
|-----------|------|
| `unset` vs `export -n` | **변수를 삭제** / 값은 두고 **환경 변수 자격만** 뺀다 |
| `env` vs `printenv` | 둘 다 환경 변수를 출력한다. `printenv`는 **이름을 지정**할 수 있고, `env`는 **임시 환경으로 명령을 실행**할 수 있다 |
| `set` vs `env` | `set`의 출력에는 셸 변수뿐 아니라 **셸 함수**까지 들어 있다 |

- `export -p` 출력의 **`declare -x`** 에서 `x`가 export 속성이다. 그래서 `declare -x NAME`은 `export NAME`과 같지만, 옵션 없는 `declare NAME`은 환경 변수를 만들지 않는다.
- 지울 때는 **`unset NAME`** 이다. `unset $NAME` 이라고 쓰면 NAME에 **들어 있는 값**을 이름으로 가진 변수를 지우려 한다.

## 주요 환경 변수

| 변수 | 담는 것 |
|------|--------|
| **`PATH`** | **명령을 찾을 디렉터리 목록** |
| **`HOME`** | 홈 디렉터리 |
| **`SHELL`** | 로그인 셸 |
| **`USER`** | 현재 사용자 이름 |
| **`PWD`** | 현재 작업 디렉터리 |
| **`LANG`** | 언어와 문자 인코딩 |
| **`TERM`** | 터미널 종류 |
| **`PS1`** | **프롬프트 모양** |
| `HISTSIZE` | 히스토리에 담을 명령 개수 |
| `EDITOR` | 기본 편집기 |
| `HOSTNAME` | 호스트 이름 |
| `LOGNAME` | 로그인 이름 |

```bash
echo $HOME       # /home/user
echo $USER       # user
echo $PWD        # 현재 디렉터리 — pwd 명령과 같은 값
echo $LANG       # ko_KR.UTF-8
```

### 함께 묻는 변수들

| 변수 | 담는 것 |
|------|--------|
| `PS2` | 명령이 끝나지 않았을 때 나오는 **2차 프롬프트** (기본값 `>`) |
| `HISTFILE` | 히스토리가 저장되는 파일 (기본값 `~/.bash_history`) |
| `HISTFILESIZE` | 히스토리 **파일**에 남길 줄 수 |
| `TMOUT` | 입력 없이 이 **초**가 지나면 자동으로 로그아웃 |
| `MAIL` | 메일함 경로 |
| `DISPLAY` | X 윈도 화면이 표시될 곳 |
| `OLDPWD` | 직전 작업 디렉터리 — `cd -` 가 돌아가는 곳 |

- **`HISTSIZE`는 메모리에 기억할 개수, `HISTFILESIZE`는 파일에 남길 개수**다. 이름이 비슷해 바꿔 묻는다.
- `USER`와 `LOGNAME`은 보통 같은 값이다.

### PS1 — 프롬프트 모양

```bash
echo $PS1
# [\u@\h \W]\$
# 화면에는 이렇게 보인다 →  [user@server1 ~]$
```

| 기호 | 바뀌는 값 |
|------|----------|
| **`\u`** | 사용자 이름 (user) |
| **`\h`** | 호스트 이름 (host) |
| **`\w`** | 현재 디렉터리의 **전체 경로** |
| **`\W`** | 현재 디렉터리의 **마지막 이름만** |
| **`\$`** | root면 `#`, 일반 사용자면 `$` |
| `\d` / `\t` | 날짜 / 시각(24시간) |
| `\!` | 히스토리 번호 |

- **`\w`와 `\W`는 대소문자로 갈린다.** `/usr/local/bin` 에 있을 때 `\w`는 `/usr/local/bin`, `\W`는 `bin` 을 보여 준다.
- 프롬프트 끝이 `#`이면 root로 작업 중이라는 뜻이다. `\$` 가 이 구분을 만든다.

## PATH — 명령을 어디서 찾나

```bash
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin
#                └ 콜론(:) 으로 구분한다
```

- `ls`라고 치면 셸은 **PATH에 적힌 디렉터리를 앞에서부터 차례로 뒤져** 실행 파일을 찾는다.
- **구분자는 콜론(`:`)** 이다. 윈도가 세미콜론을 쓰는 것과 다르다.
- 앞에 있는 경로가 **먼저** 검색된다. 같은 이름의 명령이 여러 곳에 있으면 앞쪽이 이긴다.

```bash
export PATH=$PATH:/opt/myapp/bin      # 뒤에 추가 (권장)
export PATH=/opt/myapp/bin:$PATH      # 앞에 추가 (우선하게)
which ls                              # /usr/bin/ls — 실제로 찾은 위치
```

> ⚠️ **`export PATH=/opt/bin` 처럼 `$PATH`를 빼먹으면** 기존 경로가 전부 날아가 `ls` 조차 실행되지 않는다. 반드시 **`$PATH:`** 를 포함해서 쓴다.

- **현재 디렉터리(`.`)는 PATH에 넣지 않는 것이 원칙**이다. 악성 파일을 같은 이름으로 심어 두면 그것이 실행되기 때문이다. 그래서 현재 위치의 스크립트는 **`./script.sh`** 처럼 경로를 붙여 실행한다.

### PATH에 없으면 벌어지는 일

```bash
ls -l backup.sh
# -rwxr-xr-x 1 user user 120 Oct 14 09:00 backup.sh
backup.sh
# bash: backup.sh: command not found
./backup.sh
# backup start...
```

- 파일이 눈앞에 있고 실행 권한도 있는데 못 찾는다. **셸은 현재 디렉터리가 아니라 PATH에 적힌 곳만** 뒤지기 때문이다.

| 메시지 | 원인 |
|-------|------|
| **`command not found`** | **PATH 어디에도 그 이름이 없다** |
| `Permission denied` | 찾기는 했는데 **실행 권한(x)이 없다** |

- **`which`는 PATH에서 찾은 실행 파일의 위치**를, `type`은 그 이름이 별칭인지 내부 명령인지까지 알려 준다.
- `cd`·`echo`·`export` 같은 **내부 명령은 PATH와 상관없이 실행된다.** 그래서 PATH를 망가뜨렸어도 `export PATH=/usr/bin:/bin` 을 쳐서 되살릴 수 있다.

## 특수 변수

| 변수 | 뜻 |
|------|-----|
| **`$?`** | **직전 명령의 종료 상태** (0이면 성공) |
| **`$$`** | 현재 셸의 **PID** |
| `$0` | 실행 중인 셸이나 스크립트 이름 |
| `$!` | 마지막 백그라운드 작업의 PID |

```bash
ls /없는경로
echo $?          # 2  ← 0이 아니면 실패
ls /etc
echo $?          # 0  ← 성공
```

- **`$?`가 0이면 성공**이다. 0이 아닌 값은 오류를 뜻한다. 일반적인 참/거짓과 반대라 헷갈리기 쉽다.

| `$?` 값 | 뜻 |
|--------|-----|
| **0** | **성공** |
| 1 | 일반적인 실패 — 예: `grep`이 맞는 줄을 하나도 못 찾음 |
| 2 | 사용법 오류 등 — 예: `ls`가 지정한 파일에 접근하지 못함 |
| 126 | 찾았지만 실행할 수 없음 (권한 없음) |
| 127 | 명령을 찾지 못함 (`command not found`) |
| 130 | `Ctrl+C` 로 중단됨 |

```bash
grep root /etc/passwd > /dev/null
echo $?        # 0
echo $?        # 0     ← 방금 실행한 echo 의 결과다. grep 의 값은 이미 덮였다
echo $$        # 2314  ← 지금 셸의 PID
sleep 100 &
echo $!        # 2377  ← 방금 백그라운드로 보낸 sleep 의 PID
```

- 외울 것은 하나다 — **0만 성공이고 나머지는 전부 실패**다. 값의 범위는 0~255이며 0이 아닌 값의 세부 뜻은 명령마다 다르다.
- **`$?`는 직전 명령 하나만** 기억한다. 확인하려면 다른 명령을 끼우지 말고 바로 꺼내야 한다.

## 변수는 셸을 벗어나면 사라진다

```bash
export PATH=$PATH:/opt/bin     # 지금 이 셸에서만 유효
```

| 만드는 방법 | 살아 있는 범위 |
|-----------|--------------|
| `NAME=값 명령` 또는 `env NAME=값 명령` | **그 명령 한 번**에만 |
| `NAME=값` | 현재 셸 |
| `export NAME=값` | 현재 셸과 거기서 띄운 자식들 |
| 설정 파일(`~/.bashrc` 등)에 적기 | **로그인할 때마다 다시** 만들어진다 |

- 명령으로 만든 변수는 **터미널을 닫으면 사라진다.**
- 계속 쓰려면 **설정 파일에 적어야 한다** — `~/.bashrc`나 `~/.bash_profile`. 이것이 내일 주제다.

> 내일은 이 변수들이 언제 어떤 순서로 읽히는지 — 셸 환경 설정 파일을 다룬다.

## 📖 용어

- **셸 변수** : 현재 셸 안에서만 유효한 변수. 자식 프로세스에는 전달되지 않는다.
- **환경 변수** : 자식 프로세스까지 전달되는 변수. `export`로 만든다.
- **`export`** : 셸 변수를 환경 변수로 승격시키는 명령.
- **`set`** : 셸 변수와 환경 변수를 모두 보여 주는 명령.
- **`env`** : 환경 변수만 보여 주는 명령.
- **`PATH`** : 실행 파일을 찾을 디렉터리 목록. 콜론으로 구분한다.
- **`PS1`** : 프롬프트의 모양을 정하는 환경 변수.
- **`$?`** : 직전 명령의 종료 상태를 담은 특수 변수. 0이면 성공이다.

## 📝 연습 문제

**문제 1.** 다음 중 셸 변수를 환경 변수로 만들어 자식 프로세스에도 전달되게 하는 명령으로 알맞은 것은?

A) set  
B) export  
C) unset  
D) declare  

**정답: B**  
해설: `export`는 셸 변수를 환경 변수로 승격시켜 그 셸에서 실행되는 자식 프로세스에도 값이 전달되게 한다. `set`은 변수 목록을 보여 주는 명령이고 `unset`은 변수를 삭제하는 명령이다.

A) PATH  
B) HOME  
C) SHELL  
D) TERM  

**정답: A**  
해설: `PATH`에는 명령을 입력했을 때 셸이 실행 파일을 찾아볼 디렉터리들이 콜론으로 구분되어 나열된다. 앞쪽에 적힌 경로부터 순서대로 검색한다. `HOME`은 홈 디렉터리, `SHELL`은 로그인 셸, `TERM`은 터미널 종류를 담는다.

**문제 3.** 다음 중 `PATH` 환경 변수에서 각 디렉터리를 구분하는 문자로 알맞은 것은?

A) 세미콜론(;)  
B) 쉼표(,)  
C) 공백  
D) 콜론(:)  

**정답: D**  
해설: 리눅스에서 `PATH`의 경로 구분자는 콜론이다. 윈도가 세미콜론을 사용하는 것과 다르므로 혼동하지 않아야 한다. 기존 값을 유지하며 경로를 추가할 때는 `export PATH=$PATH:/new/path` 형식으로 작성한다.

**문제 4.** 다음 중 환경 변수만 출력하는 명령으로 알맞은 것은?

A) set  
B) unset  
C) env  
D) export -n  

**정답: C**  
해설: `env`와 `printenv`는 환경 변수만 출력한다. 반면 `set`은 셸 변수까지 포함해 현재 셸이 가진 모든 변수를 보여 주므로 출력이 훨씬 길다. `unset`은 변수를 삭제하는 명령이다.

**문제 5.** 다음 중 변수를 올바르게 선언한 것으로 알맞은 것은?

A) NAME = linux  
B) NAME=linux  
C) $NAME=linux  
D) set NAME linux  

**정답: B**  
해설: 셸에서 변수를 선언할 때는 등호 양옆에 공백을 두지 않는다. 공백을 넣으면 셸이 `NAME`을 명령어로 해석해 오류가 난다. 또한 `$`는 값을 꺼내 쓸 때만 붙이므로 선언할 때는 사용하지 않는다.
