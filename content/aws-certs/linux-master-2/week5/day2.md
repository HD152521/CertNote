# Day 2 - 셸 변수와 환경 변수

## 📌 핵심 정리

- 변수는 **`이름=값`** 으로 만든다. **등호 양옆에 공백이 있으면 안 된다.**
- **셸 변수는 지금 셸에서만**, **환경 변수는 자식 프로세스까지** 전달된다. 이 차이가 전부다.
- 셸 변수를 환경 변수로 승격시키는 명령이 **`export`** 다.
- 값을 꺼낼 때는 **`$이름`** 을 쓴다. `echo $PATH` 처럼.
- **`PATH`는 명령을 찾는 경로 목록**이고, 구분자는 **콜론(`:`)** 이다.

## 변수 만들기

```bash
NAME=linux           # 만들기 — 등호 양옆에 공백 없이!
echo $NAME           # linux
echo ${NAME}         # 중괄호로 감싸도 된다
NAME="hello world"   # 공백이 들어가면 따옴표로
unset NAME           # 지우기
```

> **가장 흔한 실수가 공백이다.** `NAME = linux` 라고 쓰면 셸은 `NAME` 을 명령으로 보고 실행하려 한다. **`=` 양옆을 붙여 쓴다.**

- 변수 이름은 관례상 **대문자**를 쓴다. 필수는 아니지만 시스템 변수와 구분하기 좋다.
- **값을 꺼낼 때만 `$`를 붙인다.** 만들 때는 붙이지 않는다.

## 셸 변수 vs 환경 변수

```text
   현재 셸
   ├── NAME=linux        (셸 변수)   ─┐
   └── export AGE=30     (환경 변수) ─┼─ 자식에게 전달되는 건?
        │                             │
        ▼ 자식 프로세스 실행           │
      자식 셸                          │
        NAME → 비어 있음  ◄────────────┘  전달 안 됨
        AGE  → 30                         전달 됨
```

| 구분 | **셸 변수** | **환경 변수** |
|------|-----------|-------------|
| 범위 | **현재 셸에서만** | **자식 프로세스까지** |
| 만들기 | `NAME=값` | **`export NAME=값`** |
| 보기 | **`set`** | **`env`** 또는 `printenv` |
| 예 | 사용자가 임시로 만든 변수 | `PATH`, `HOME`, `SHELL` |

```bash
NAME=linux              # 셸 변수
export NAME             # 환경 변수로 승격
export AGE=30           # 만들면서 바로 환경 변수로
```

| 명령 | 보여 주는 것 |
|------|------------|
| **`set`** | **셸 변수 + 환경 변수 전부** |
| **`env`** | **환경 변수만** |
| `printenv` | 환경 변수만 (`env`와 비슷) |
| `export` | 환경 변수 목록 |
| `unset 이름` | 변수 삭제 |

> **`set`은 전부, `env`는 환경 변수만.** 이 짝이 시험에 나온다. 어느 쪽이 더 많이 나오는지로 기억하면 `set`이 더 많다.

## 주요 환경 변수

| 변수 | 담는 것 |
|------|--------|
| **`PATH`** | **명령을 찾을 디렉터리 목록** |
| **`HOME`** | 홈 디렉터리 |
| **`SHELL`** | 로그인 셸 |
| **`USER`** | 현재 사용자 이름 |
| **`PWD`** | 현재 작업 디렉터리 |
| **`LANG`** | 언어와 문자 인코딩 |
| **`TERM`** | 터미널 종류 |
| **`PS1`** | **프롬프트 모양** |
| `HISTSIZE` | 히스토리에 담을 명령 개수 |
| `EDITOR` | 기본 편집기 |
| `HOSTNAME` | 호스트 이름 |
| `LOGNAME` | 로그인 이름 |

```bash
echo $HOME       # /home/user
echo $USER       # user
echo $PWD        # 현재 디렉터리 — pwd 명령과 같은 값
echo $LANG       # ko_KR.UTF-8
```

## PATH — 명령을 어디서 찾나

```bash
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin
#                └ 콜론(:) 으로 구분한다
```

- `ls`라고 치면 셸은 **PATH에 적힌 디렉터리를 앞에서부터 차례로 뒤져** 실행 파일을 찾는다.
- **구분자는 콜론(`:`)** 이다. 윈도가 세미콜론을 쓰는 것과 다르다.
- 앞에 있는 경로가 **먼저** 검색된다. 같은 이름의 명령이 여러 곳에 있으면 앞쪽이 이긴다.

```bash
export PATH=$PATH:/opt/myapp/bin      # 뒤에 추가 (권장)
export PATH=/opt/myapp/bin:$PATH      # 앞에 추가 (우선하게)
which ls                              # /usr/bin/ls — 실제로 찾은 위치
```

> ⚠️ **`export PATH=/opt/bin` 처럼 `$PATH`를 빼먹으면** 기존 경로가 전부 날아가 `ls` 조차 실행되지 않는다. 반드시 **`$PATH:`** 를 포함해서 쓴다.

- **현재 디렉터리(`.`)는 PATH에 넣지 않는 것이 원칙**이다. 악성 파일을 같은 이름으로 심어 두면 그것이 실행되기 때문이다. 그래서 현재 위치의 스크립트는 **`./script.sh`** 처럼 경로를 붙여 실행한다.

## 특수 변수

| 변수 | 뜻 |
|------|-----|
| **`$?`** | **직전 명령의 종료 상태** (0이면 성공) |
| **`$$`** | 현재 셸의 **PID** |
| `$0` | 실행 중인 셸이나 스크립트 이름 |
| `$!` | 마지막 백그라운드 작업의 PID |

```bash
ls /없는경로
echo $?          # 2  ← 0이 아니면 실패
ls /etc
echo $?          # 0  ← 성공
```

- **`$?`가 0이면 성공**이다. 0이 아닌 값은 오류를 뜻한다. 일반적인 참/거짓과 반대라 헷갈리기 쉽다.

## 변수는 셸을 벗어나면 사라진다

```bash
export PATH=$PATH:/opt/bin     # 지금 이 셸에서만 유효
```

- 명령으로 만든 변수는 **터미널을 닫으면 사라진다.**
- 계속 쓰려면 **설정 파일에 적어야 한다** — `~/.bashrc`나 `~/.bash_profile`. 이것이 내일 주제다.

> 내일은 이 변수들이 언제 어떤 순서로 읽히는지 — 셸 환경 설정 파일을 다룬다.

## 📖 용어

- **셸 변수** : 현재 셸 안에서만 유효한 변수. 자식 프로세스에는 전달되지 않는다.
- **환경 변수** : 자식 프로세스까지 전달되는 변수. `export`로 만든다.
- **`export`** : 셸 변수를 환경 변수로 승격시키는 명령.
- **`set`** : 셸 변수와 환경 변수를 모두 보여 주는 명령.
- **`env`** : 환경 변수만 보여 주는 명령.
- **`PATH`** : 실행 파일을 찾을 디렉터리 목록. 콜론으로 구분한다.
- **`PS1`** : 프롬프트의 모양을 정하는 환경 변수.
- **`$?`** : 직전 명령의 종료 상태를 담은 특수 변수. 0이면 성공이다.

## 📝 연습 문제

**문제 1.** 다음 중 셸 변수를 환경 변수로 만들어 자식 프로세스에도 전달되게 하는 명령으로 알맞은 것은?

A) set  
B) export  
C) unset  
D) declare  

**정답: B**  
해설: `export`는 셸 변수를 환경 변수로 승격시켜 그 셸에서 실행되는 자식 프로세스에도 값이 전달되게 합니다. `set`은 변수 목록을 보여 주는 명령이고 `unset`은 변수를 삭제하는 명령입니다.

---

**문제 2.** 다음 중 실행 파일을 찾을 디렉터리 목록을 담고 있는 환경 변수로 알맞은 것은?

A) PATH  
B) HOME  
C) SHELL  
D) TERM  

**정답: A**  
해설: `PATH`에는 명령을 입력했을 때 셸이 실행 파일을 찾아볼 디렉터리들이 콜론으로 구분되어 나열됩니다. 앞쪽에 적힌 경로부터 순서대로 검색합니다. `HOME`은 홈 디렉터리, `SHELL`은 로그인 셸, `TERM`은 터미널 종류를 담습니다.

---

**문제 3.** 다음 중 `PATH` 환경 변수에서 각 디렉터리를 구분하는 문자로 알맞은 것은?

A) 세미콜론(;)  
B) 쉼표(,)  
C) 공백  
D) 콜론(:)  

**정답: D**  
해설: 리눅스에서 `PATH`의 경로 구분자는 콜론입니다. 윈도가 세미콜론을 사용하는 것과 다르므로 혼동하지 않아야 합니다. 기존 값을 유지하며 경로를 추가할 때는 `export PATH=$PATH:/new/path` 형식으로 작성합니다.

---

**문제 4.** 다음 중 환경 변수만 출력하는 명령으로 알맞은 것은?

A) set  
B) unset  
C) env  
D) export -n  

**정답: C**  
해설: `env`와 `printenv`는 환경 변수만 출력합니다. 반면 `set`은 셸 변수까지 포함해 현재 셸이 가진 모든 변수를 보여 주므로 출력이 훨씬 깁니다. `unset`은 변수를 삭제하는 명령입니다.

---

**문제 5.** 다음 중 변수를 올바르게 선언한 것으로 알맞은 것은?

A) NAME = linux  
B) NAME=linux  
C) $NAME=linux  
D) set NAME linux  

**정답: B**  
해설: 셸에서 변수를 선언할 때는 등호 양옆에 공백을 두지 않습니다. 공백을 넣으면 셸이 `NAME`을 명령어로 해석해 오류가 납니다. 또한 `$`는 값을 꺼내 쓸 때만 붙이므로 선언할 때는 사용하지 않습니다.
