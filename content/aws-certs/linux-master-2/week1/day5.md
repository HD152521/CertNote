# Day 5 - Week 1 종합 복습: 리눅스라는 이름의 정체

## 📌 핵심 정리

- **커널 / 셸 / 응용 프로그램**의 세 층과 그 사이의 **시스템 콜**이 이번 주의 뼈대다.
- 계보는 **유닉스(1969) → GNU(1983) → MINIX(1987) → 리눅스 커널(1991)** 순으로 외운다.
- 라이선스는 **카피레프트(GPL)** 냐 **퍼미시브(BSD·MIT)** 냐 두 갈래로 먼저 가른다.
- 배포판 계열은 **고수준 도구**로 구분한다 — `dnf`=레드햇, `apt`=데비안, `zypper`=수세.
- 1차 '리눅스의 이해'는 **인물·연도·이름을 짝짓는 문항**이 많다. 표를 통째로 외우는 게 빠르다.

## 한 장 정리

```text
     1969  유닉스        켄 톰슨 · 데니스 리치 (벨 연구소)
       │                 1973년 C 언어로 재작성 → 이식성 확보
       ├──────────────┬──────────────┐
       ▼              ▼              ▼
     BSD 계열      System V 계열   (영향만 받음)
   FreeBSD          AIX               │
   OpenBSD          HP-UX             │
   macOS            Solaris           │
                                      │
     1983  GNU 프로젝트   리처드 스톨먼 │  도구는 완성, 커널(HURD)이 미완성
       │                              │
     1987  MINIX        타넨바움       │  교육용 — 리누스를 자극
       │                              │
     1991  리눅스 커널   리누스 토르발스 ◄┘
       │
       └──► GNU + 리눅스 커널 = GNU/Linux → 배포판들
```

## 인물·연도 짝짓기

| 인물 | 한 일 | 연도 |
|------|------|------|
| 켄 톰슨 | 유닉스 개발 | 1969 |
| 데니스 리치 | C 언어 개발, 유닉스 재작성 | 1972~1973 |
| 리처드 스톨먼 | GNU 프로젝트 시작, FSF 설립, GPL 작성 | 1983 / 1985 / 1989 |
| 앤드루 타넨바움 | MINIX 개발 | 1987 |
| 리누스 토르발스 | 리눅스 커널 개발 | 1991 |

## 헷갈리는 짝 대조

| 구분 | A | B | 가르는 기준 |
|------|---|---|-----------|
| 커널 vs 셸 | 커널 — 하드웨어 제어 | 셸 — 명령 해석 | **하드웨어를 직접 만지는가** |
| 모놀리식 vs 마이크로커널 | 리눅스, 유닉스 | MINIX, Mach | **기능이 커널 안에 다 있는가** |
| BSD vs System V | FreeBSD, macOS | AIX, HP-UX, Solaris | **버클리인가 AT&T인가** |
| 자유 소프트웨어 vs 오픈소스 | FSF, 윤리 강조 | OSI, 실용 강조 | **강조점**(코드 목록은 거의 같다) |
| 카피레프트 vs 퍼미시브 | GPL, LGPL, AGPL | BSD, MIT, Apache | **파생물도 공개해야 하는가** |
| GPL vs LGPL | 링크해도 공개 | 링크만 하면 면제 | **라이브러리 예외가 있는가** |
| RPM vs DEB | 레드햇·**수세** | 데비안·우분투 | 형식만으로는 부족 → **고수준 도구로** |
| Fedora vs RHEL | 실험장, 짧은 주기 | 상용, 장기 지원 | **검증 전인가 후인가** |

## 자주 틀리는 지점

1. **"자유 소프트웨어 = 무료"** → 아니다. 유료 판매도 가능하다. 자유는 가격이 아니라 권리다.
2. **"RPM이면 레드햇"** → 수세도 RPM을 쓴다. `zypper`를 보고 가려야 한다.
3. **"리눅스는 유닉스의 한 종류"** → 코드를 물려받지 않았다. 동작 방식만 본뜬 **유닉스 계열(Unix-like)** 이다.
4. **"GNU가 리눅스를 만들었다"** → GNU는 도구를, 리누스는 커널을 만들었다. 둘이 합쳐진 것이다.
5. **"커널 버전 짝수=안정"** → 2.6 이전의 옛 규칙이다. 지금은 무관하지만 시험엔 나온다.
6. **"안드로이드는 리눅스 배포판"** → 커널만 공유하고 GNU 도구를 쓰지 않는다.

## 명령어 정리

| 명령 | 하는 일 |
|------|--------|
| `uname -a` | 커널 이름·버전·아키텍처 전부 |
| `uname -r` | 커널 버전만 |
| `cat /proc/version` | 커널이 보고하는 상세 정보 |
| `echo $SHELL` | 현재 로그인 셸 |
| `cat /etc/*-release` | 배포판 이름과 버전 |

> 다음 주는 이 운영체제를 실제로 설치하는 이야기다 — 설치 유형, 파티션, 파일 시스템, 부트 매니저를 다룬다.

## 📖 용어

- **유닉스 계열(Unix-like)** : 유닉스의 코드를 물려받진 않았지만 동작 방식과 명령 체계가 유닉스를 닮은 운영체제.
- **이식성** : 다른 기종에서도 큰 수정 없이 동작하게 만드는 성질. 유닉스가 C로 재작성된 이유다.
- **적재 가능 커널 모듈(LKM)** : 실행 중에 커널에 붙였다 뗄 수 있는 기능 조각.
- **전염성(Viral)** : GPL 코드를 쓴 결과물도 GPL로 공개해야 하는 성질.
- **고정 릴리스** : 정해진 주기로 새 버전을 내는 배포 방식.
- **롤링 릴리스** : 버전 구분 없이 계속 갱신하는 배포 방식.

## 📝 연습 문제

**문제 1.** 다음 중 리눅스 커널을 처음 개발한 인물과 연도의 연결로 알맞은 것은?

A) 켄 톰슨 — 1969년  
B) 리처드 스톨먼 — 1983년  
C) 리누스 토르발스 — 1991년  
D) 앤드루 타넨바움 — 1987년  

**정답: C**  
해설: 리눅스 커널은 1991년 핀란드 헬싱키 대학의 리누스 토르발스가 개발했습니다. 켄 톰슨은 1969년 유닉스를, 리처드 스톨먼은 1983년 GNU 프로젝트를, 앤드루 타넨바움은 1987년 MINIX를 만들었습니다.

**문제 2.** 다음 중 리눅스와 유닉스의 관계에 대한 설명으로 가장 알맞은 것은?

A) 리눅스는 유닉스의 소스 코드를 그대로 물려받은 파생 버전이다  
B) 리눅스는 유닉스와 무관하게 만들어진 완전히 다른 체계다  
C) 리눅스는 유닉스의 코드가 아니라 동작 방식을 본뜬 유닉스 계열이다  
D) 리눅스는 유닉스를 개발한 벨 연구소가 직접 만든 후속작이다  

**정답: C**  
해설: 리눅스 커널은 유닉스의 소스 코드를 물려받지 않고 처음부터 새로 작성되었습니다. 다만 명령 체계와 동작 방식이 유닉스를 본떴기 때문에 "유닉스 계열(Unix-like)"이라고 부릅니다. BSD 계열이나 System V 계열의 직접적인 후손은 아닙니다.

**문제 3.** 다음 중 GNU 프로젝트와 리눅스 커널의 관계를 가장 정확히 설명한 것은?

A) GNU가 커널을 만들고 리누스가 도구를 만들었다  
B) GNU는 도구를 완성했으나 커널이 없었고, 그 자리를 리눅스 커널이 채웠다  
C) 리눅스 커널은 GNU 프로젝트의 공식 커널인 HURD를 개량한 것이다  
D) 두 프로젝트는 서로 경쟁 관계라 결합된 적이 없다  

**정답: B**  
해설: GNU 프로젝트는 GCC, bash, coreutils 등 운영체제에 필요한 도구를 대부분 완성했지만 커널인 HURD는 완성되지 못했습니다. 1991년 등장한 리눅스 커널이 그 빈자리를 채우면서 완성된 운영체제가 되었고, 이 때문에 GNU/Linux라고 부릅니다. 리눅스 커널은 HURD와 무관하게 독립적으로 개발되었습니다.

**문제 4.** 다음 중 카피레프트(copyleft) 성격의 라이선스로만 묶인 것은?

A) BSD, MIT  
B) MIT, Apache  
C) GPL, LGPL  
D) BSD, Apache  

**정답: C**  
해설: 카피레프트는 파생 저작물에도 동일한 자유를 강제하는 방식으로 GPL 계열(GPL, LGPL, AGPL)과 MPL이 여기 속합니다. LGPL은 라이브러리 링크에 예외를 둔 약한 카피레프트입니다. BSD, MIT, Apache는 저작권 표시 정도만 요구하는 퍼미시브 라이선스입니다.

**문제 5.** 다음 중 배포판과 계열의 연결로 알맞지 않은 것은?

A) openSUSE — 데비안 계열  
B) Rocky Linux — 레드햇 계열  
C) Ubuntu — 데비안 계열  
D) AlmaLinux — 레드햇 계열  

**정답: A**  
해설: openSUSE는 수세 계열입니다. 수세 계열은 레드햇 계열과 같은 RPM 패키지 형식을 사용하지만 고수준 관리 도구로 `zypper`를 쓴다는 점에서 구분됩니다. Ubuntu는 데비안 기반이고, Rocky Linux와 AlmaLinux는 RHEL 호환을 목표로 하는 레드햇 계열입니다.

**문제 6.** 다음 중 현재 시스템에 설치된 배포판의 이름과 버전을 확인하는 방법으로 가장 알맞은 것은?

A) `uname -r`  
B) `cat /proc/cpuinfo`  
C) `echo $SHELL`  
D) `cat /etc/*-release`  

**정답: D**  
해설: `/etc` 아래의 `os-release`, `redhat-release` 같은 파일에 배포판 이름과 버전이 기록되어 있습니다. `uname -r`은 커널 버전만 보여주므로 배포판을 알 수 없고, `echo $SHELL`은 로그인 셸을, `/proc/cpuinfo`는 CPU 정보를 보여줍니다.
