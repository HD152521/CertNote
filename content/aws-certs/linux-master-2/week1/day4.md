# Day 4 - 배포판: 커널과 도구를 하나로 묶어 파는 단위

## 📌 핵심 정리

- **배포판(distribution)** = 리눅스 커널 + GNU 도구 + 패키지 관리자 + 설치 프로그램 + 응용 소프트웨어.
- 3대 계열: **레드햇 계열(RPM)**, **데비안 계열(DEB)**, **수세 계열(RPM)**.
- 패키지 형식으로 계열을 구분한다 — **RPM은 레드햇·수세**, **DEB는 데비안·우분투**.
- **페도라 → RHEL → CentOS/Rocky/Alma** 순으로 안정성이 흐른다. 페도라가 실험장이다.
- **안드로이드도 리눅스 커널 기반**이지만 GNU 도구를 쓰지 않아 일반 배포판과 다르다.

## 배포판이란 무엇인가

커널만 있으면 컴퓨터를 쓸 수 없다. 실제로 쓰려면 이만큼이 더 필요하다.

![리눅스 커널 위에 GNU 도구, 패키지 관리자, 데스크톱 환경, 응용 소프트웨어를 얹어 묶은 배포판 계층도](/diagrams/linux-distro-layers.svg)

- 커널은 모든 배포판이 **똑같은 것**을 쓴다(버전만 다르다).
- 배포판을 가르는 것은 **패키지 형식·관리 도구·기본 설정·지원 정책**이다.

## 3대 계열

| 계열 | 패키지 형식 | 저수준 도구 | 고수준 도구 | 대표 배포판 |
|------|-----------|-----------|-----------|-----------|
| **레드햇** | `.rpm` | `rpm` | `yum` → `dnf` | RHEL, CentOS, Rocky, Alma, Fedora |
| **데비안** | `.deb` | `dpkg` | `apt`, `apt-get` | Debian, Ubuntu, Mint |
| **수세** | `.rpm` | `rpm` | `zypper` | SLES, openSUSE |

> 함정: **수세도 RPM을 쓴다.** "RPM = 레드햇"이라고만 외우면 틀린다. 구분은 **고수준 도구**로 하는 게 안전하다 — `dnf`면 레드햇, `zypper`면 수세.

### 저수준 도구와 고수준 도구는 무엇이 다른가

표에 도구가 두 칸으로 나뉜 이유는 **의존성** 때문이다. 프로그램 하나는 보통 다른 라이브러리 여러 개가 깔려 있어야 돈다.

| 구분 | 저수준 도구 (`rpm`, `dpkg`) | 고수준 도구 (`dnf`, `apt`, `zypper`) |
|------|--------------------------|-----------------------------------|
| 다루는 대상 | 내 손에 있는 **패키지 파일 하나** | 인터넷 **저장소(repository)** 의 패키지 |
| 의존성 | 알려만 준다. **직접 구해 와야** 한다 | 필요한 패키지를 **자동으로 찾아 함께** 설치 |
| 쓰는 때 | 파일을 받아 직접 설치, 설치 정보 조회 | 평소의 설치·삭제·업데이트 |

같은 일을 계열별로 어떻게 치는지 나란히 놓으면 이렇다(자세한 옵션은 7주차에서 다룬다).

| 작업 | 레드햇 계열 | 데비안 계열 | 수세 계열 |
|------|-----------|-----------|----------|
| 저장소에서 설치 | `dnf install 패키지` | `apt install 패키지` | `zypper install 패키지` |
| 삭제 | `dnf remove 패키지` | `apt remove 패키지` | `zypper remove 패키지` |
| 파일로 설치 | `rpm -ivh 파일.rpm` | `dpkg -i 파일.deb` | `rpm -ivh 파일.rpm` |
| 설치된 목록 | `rpm -qa` | `dpkg -l` | `rpm -qa` |

- **`yum`과 `dnf`의 관계**: `dnf`는 `yum`의 후속이다. RHEL 8부터 `dnf`가 기본이고, `yum` 명령은 호환을 위해 남아 `dnf`로 연결된다.
- **`apt`와 `apt-get`의 관계**: `apt`가 더 나중에 나온, 사람이 쓰기 편하게 다듬은 명령이다. 하는 일은 같다.

> ⚠️ **함정**: 데비안 계열에서 `apt update`는 **저장소 목록만 새로 받는다.** 실제로 패키지를 올리는 것은 `apt upgrade`다. 레드햇 계열의 `dnf update`는 패키지를 실제로 올린다. 이름이 같아도 하는 일이 다르다.

### 레드햇 계열

```text
   Fedora  ──────►  RHEL  ──────►  CentOS Stream / Rocky / Alma
  (실험장)         (상용 안정판)      (RHEL 호환 무료판)
   최신 기술         유료 지원         무료 재빌드
   빠른 주기         장기 지원
```

- **페도라**: 새 기술을 먼저 넣어보는 실험장. 주기가 짧고 변화가 크다.
- **RHEL**(Red Hat Enterprise Linux): 페도라에서 검증된 것을 담은 상용 배포판. **유료 기술 지원**이 상품이다.
- **CentOS**: RHEL 소스를 그대로 재빌드한 무료판이었다. 2021년 정책이 바뀌어 **CentOS Stream**(RHEL의 앞단)이 되었고, 그 빈자리를 **Rocky Linux**와 **AlmaLinux**가 채웠다.

위 그림은 "안정성이 흐르는 방향"을 단순화한 것이고, 실제 **코드가 흐르는 순서**는 조금 더 세밀하다.

```text
   Fedora  ──►  CentOS Stream  ──►  RHEL  ──►  Rocky Linux · AlmaLinux
   (실험)        (RHEL의 다음 버전     (상용)       (RHEL과 호환되게 다시 만든 무료판)
                  을 미리 공개)
```

| 시기 | 사건 |
|------|------|
| 2003년 | 무료였던 '레드햇 리눅스'가 끝나고, 커뮤니티판은 **Fedora**로, 기업용은 **RHEL**로 나뉘었다 |
| 2020년 말 | 레드햇이 CentOS의 방향을 **CentOS Stream**으로 바꾼다고 발표 |
| 2021년 | CentOS Linux 8 지원 종료(연말). **AlmaLinux**·**Rocky Linux** 첫 버전 등장 |
| 2024년 6월 | CentOS Linux 7 지원 종료 — 옛 방식의 CentOS가 완전히 끝났다 |

- **옛 CentOS**는 RHEL **뒤**에 있었다(RHEL을 그대로 다시 빌드). **CentOS Stream**은 RHEL **앞**에 있다(다음 RHEL에 들어갈 내용을 먼저 받는다). 이름은 이어졌지만 자리가 정반대다.
- 그래서 "RHEL과 똑같은 무료판"이라는 옛 CentOS의 역할은 이제 Rocky와 Alma가 맡는다.

### 데비안 계열

- **데비안**: 비영리 커뮤니티가 만든다. 안정성을 최우선으로 해 **패키지가 보수적**이다.
- **우분투**: 데비안 기반으로 캐노니컬(Canonical)이 만든다. 데스크톱 사용성이 좋고 **LTS(장기 지원) 버전**이 5년 지원된다.
- **리눅스 민트**: 우분투 기반. 더 친숙한 데스크톱을 제공한다.

데비안은 한 시점에 세 갈래를 동시에 굴린다.

| 갈래 | 성격 |
|------|------|
| **stable**(안정) | 정식 릴리스. 서버에 쓰는 것은 이것이다 |
| **testing**(시험) | 다음 stable이 될 후보 |
| **unstable**(불안정, 별명 `sid`) | 새 패키지가 처음 들어오는 곳 |

우분투의 버전 번호는 **출시 연도와 달**이다.

```text
   22.04 LTS        23.10          24.04 LTS
   │  │             │  │           │  │
   │  └ 4월          │  └ 10월      │  └ 4월
   └─── 2022년       └─── 2023년    └─── 2024년
```

- **6개월마다**(4월·10월) 새 버전이 나오고, **2년마다 짝수 해 4월 버전이 LTS**가 된다.
- LTS가 아닌 일반 버전은 지원 기간이 9개월뿐이라 서버에는 LTS를 쓴다.

### 수세 계열

- **SLES**(SUSE Linux Enterprise Server): 상용 배포판. 유럽에서 강세.
- **openSUSE**: 무료 커뮤니티판. `YaST`라는 통합 설정 도구가 특징이다.

## 그 밖에 알아둘 것

| 배포판 | 특징 |
|--------|------|
| **슬랙웨어(Slackware)** | 가장 오래된 배포판 중 하나. 단순하고 유닉스에 가깝다 |
| **젠투(Gentoo)** | 소스를 직접 컴파일해 설치. 최적화 자유도가 높다 |
| **아치(Arch)** | 롤링 릴리스. 항상 최신 상태를 유지한다 |
| **안드로이드** | **리눅스 커널 기반**이지만 GNU 도구 대신 자체 라이브러리를 쓴다 |
| **라즈베리 파이 OS** | 데비안 기반. 소형 보드용 |

> 기출에서 "리눅스 커널을 기반으로 한 운영체제"를 묻고 보기에 **안드로이드**를 넣는 문항이 나온다. 안드로이드는 리눅스 커널 위에 구글이 만든 별도의 계층을 올린 것이라, 커널만 공유하고 일반 배포판과는 구성이 다르다.

### 누가 누구에게서 나왔나

배포판 대부분은 맨바닥에서 만든 것이 아니라 **앞선 배포판을 바탕으로** 만들어졌다. "기반이 다른 하나"를 고르는 문항이 이 족보에서 나온다.

| 배포판 | 처음 나온 해 | 바탕 | 기억할 점 |
|--------|------------|------|----------|
| **슬랙웨어** | 1993 | (SLS라는 초기 배포판) | 패트릭 볼커딩이 만들었다. **지금까지 이어지는 가장 오래된 배포판** |
| **데비안** | 1993 | 독자 | 이안 머독이 시작. 이름은 아내 **Deb**ra와 자신 **Ian**을 합친 것 |
| **수세** | 1990년대 초 | 처음엔 슬랙웨어 | 독일에서 출발 |
| **우분투** | 2004 | 데비안 | 캐노니컬이 후원 |
| **리눅스 민트** | — | 우분투 | 데비안 → 우분투 → 민트로 이어진다 |
| **칼리 리눅스** | — | 데비안 | 보안 점검·모의 해킹 도구를 모아 둔 배포판 |

레드햇·데비안·수세 밖의 배포판은 패키지 도구도 제각각이다.

| 배포판 | 패키지 도구 | 특징 |
|--------|-----------|------|
| 아치 | `pacman` | 미리 빌드된 패키지를 롤링 릴리스로 받는다 |
| 젠투 | `emerge`(Portage) | 소스를 받아 **내 컴퓨터에서 컴파일**한다 |
| 슬랙웨어 | `pkgtool` | 압축 파일(`.tgz`·`.txz`) 형태의 패키지. 의존성을 자동으로 풀어 주지 않는다 |

## 지금 쓰는 배포판 확인하기

`uname`은 커널만 알려준다. 배포판은 `/etc` 아래의 파일이 말해 준다.

```text
$ cat /etc/os-release
NAME="Rocky Linux"
VERSION="9.3 (Blue Onyx)"
ID="rocky"
ID_LIKE="rhel centos fedora"
VERSION_ID="9.3"
PRETTY_NAME="Rocky Linux 9.3 (Blue Onyx)"

$ cat /etc/redhat-release
Rocky Linux release 9.3 (Blue Onyx)
```

| 파일·명령 | 있는 곳 | 내용 |
|----------|--------|------|
| `/etc/os-release` | 요즘 배포판 **공통** | 이름·버전·계열(`ID_LIKE`) |
| `/etc/redhat-release` | 레드햇 계열 | 한 줄짜리 배포판 이름과 버전 |
| `/etc/debian_version` | 데비안 계열 | 데비안 버전 |
| `lsb_release -a` | 해당 패키지가 깔려 있을 때 | 배포판 ID·설명·릴리스·코드명 |

- **`ID_LIKE`** 줄이 계열을 알려준다. Rocky는 `rhel centos fedora`, 우분투는 `debian`이라고 나온다. 처음 보는 배포판을 만나면 이 줄부터 보면 된다.
- `cat /etc/*-release`처럼 와일드카드를 쓰면 배포판이 무엇이든 해당하는 파일이 한꺼번에 나온다.

## 자주 틀리는 지점

1. **"RPM을 쓰면 레드햇 계열"** → 수세도 RPM이다. `zypper`·`YaST`가 보이면 수세다.
2. **"우분투는 레드햇 계열"** → 데비안 계열이다. 민트도 우분투를 거쳐 데비안에 닿는다.
3. **"페도라는 RHEL을 재빌드한 무료판"** → 반대다. 페도라가 **앞**에 있고 RHEL이 그것을 받아 만든다. 재빌드판은 Rocky·Alma다.
4. **"배포판마다 커널이 다르다"** → 커널은 같은 리눅스 커널이고 **버전과 설정**이 다를 뿐이다.
5. **"롤링 릴리스가 가장 안정적이다"** → 항상 최신이라는 뜻이지 안정적이라는 뜻이 아니다. 안정성은 고정 릴리스·LTS 쪽이다.

## 릴리스 방식

| 방식 | 설명 | 예 |
|------|------|-----|
| **고정 릴리스** | 정해진 주기로 버전을 낸다 | 데비안, 우분투, RHEL |
| **롤링 릴리스** | 버전 구분 없이 계속 갱신한다 | 아치, 젠투 |
| **LTS** | 특정 버전을 오래 지원한다 | 우분투 LTS(5년), RHEL(10년) |

## 어떤 배포판을 고를까

- **서버·기업 환경** → RHEL, Rocky, AlmaLinux, SLES (장기 지원과 안정성)
- **개인 데스크톱·입문** → 우분투, 리눅스 민트 (설치와 사용이 쉽다)
- **최신 기술 실험** → 페도라, 아치
- **학습·자격증 준비** → 우분투 또는 Rocky. 두 계열을 다 만져보는 게 좋다

## 📖 용어

- **배포판(Distribution)** : 커널·GNU 도구·패키지 관리자·응용 프로그램을 하나로 묶어 설치 가능하게 만든 것.
- **패키지 관리자** : 소프트웨어의 설치·삭제·의존성을 관리하는 도구. `dnf`, `apt`, `zypper` 등.
- **RPM** : 레드햇·수세 계열이 쓰는 패키지 형식이자 그 관리 명령.
- **DEB** : 데비안·우분투 계열이 쓰는 패키지 형식.
- **RHEL** : 레드햇의 상용 기업용 배포판. 유료 기술 지원이 핵심 상품이다.
- **페도라(Fedora)** : RHEL에 들어갈 기술을 먼저 시험하는 커뮤니티 배포판.
- **LTS** : 장기 지원(Long Term Support). 특정 버전을 오랫동안 유지·보수하는 정책.
- **롤링 릴리스** : 버전 구분 없이 계속 최신 상태로 갱신하는 배포 방식. 아치가 대표적이다.

## 📝 연습 문제

**문제 1.** 다음 중 데비안 계열 배포판에서 사용하는 패키지 형식으로 알맞은 것은?

A) RPM  
B) MSI  
C) TGZ  
D) DEB  

**정답: D**  
해설: 데비안과 우분투를 비롯한 데비안 계열은 `.deb` 패키지 형식을 사용하며 `dpkg`(저수준)와 `apt`(고수준) 도구로 관리한다. RPM은 레드햇 계열과 수세 계열이 사용하는 형식이다.

---

**문제 2.** 다음 중 배포판과 고수준 패키지 관리 도구의 연결로 알맞지 않은 것은?

A) 우분투 — apt  
B) Rocky Linux — dnf  
C) openSUSE — zypper  
D) 데비안 — yum  

**정답: D**  
해설: 데비안은 `apt`를 사용한다. `yum`(및 후속인 `dnf`)은 레드햇 계열의 고수준 패키지 관리 도구이다. 수세 계열은 RPM 패키지를 쓰지만 고수준 도구로는 `zypper`를 사용하므로, 계열 구분은 패키지 형식보다 고수준 도구로 하는 것이 정확하다.

**문제 4.** 다음 중 리눅스 배포판의 구성 요소로 거리가 먼 것은?

A) 리눅스 커널  
B) GNU 도구 모음  
C) 패키지 관리자  
D) 하드웨어 펌웨어를 대체하는 BIOS  

**정답: D**

**문제 5.** 다음 중 리눅스 커널을 기반으로 하지만 GNU 도구 대신 자체 라이브러리와 실행 환경을 사용하는 운영체제로 알맞은 것은?

A) 안드로이드  
B) FreeBSD  
C) Solaris  
D) macOS  

**정답: A**  
해설: 안드로이드는 리눅스 커널을 기반으로 하지만 GNU 도구 모음 대신 구글이 만든 자체 라이브러리와 런타임을 사용한다. FreeBSD는 BSD 계열, Solaris는 System V 계열 유닉스이며, macOS는 BSD에 뿌리를 둔 별도의 운영체제로 리눅스 커널을 쓰지 않는다.
