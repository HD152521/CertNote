# Day 1 - 운영체제와 커널: 리눅스가 하는 일

## 📌 핵심 정리

- **커널**은 하드웨어를 직접 다루는 핵심이고, **셸**은 사용자의 명령을 커널에 전달하는 통역사다.
- **"리눅스"는 원래 커널의 이름**이다. 우리가 쓰는 완성된 운영체제는 커널 + GNU 도구 모음이다.
- 커널의 5대 임무: **프로세스·메모리·파일 시스템·장치·네트워크** 관리.
- 리눅스 커널은 **모놀리식(monolithic)** 구조이며, 필요한 기능을 **모듈**로 붙였다 뗐다 할 수 있다.
- 커널 버전은 `uname -r`로 확인하고, **두 번째 숫자가 짝수면 안정(stable) 버전**이라는 옛 규칙이 있었다.

## 컴퓨터는 네 겹으로 되어 있다

리눅스를 이해하는 가장 빠른 길은 **층 구조**를 그려보는 것이다.

```text
┌─────────────────────────────────┐
│  응용 프로그램                    │  vi, 웹 브라우저, 컴파일러
├─────────────────────────────────┤
│  셸(Shell)                       │  bash, sh, csh — 명령 해석기
├─────────────────────────────────┤
│  커널(Kernel)                    │  리눅스 그 자체
├─────────────────────────────────┤
│  하드웨어                         │  CPU, 메모리, 디스크, 네트워크 카드
└─────────────────────────────────┘
```

- 위층은 아래층에 **직접 손대지 못한다.** 응용 프로그램이 디스크에 쓰고 싶으면 커널에 부탁해야 한다.
- 이 부탁을 **시스템 콜(system call)** 이라고 부른다.
- 이렇게 막아두는 이유는 **안정성**이다. 프로그램 하나가 잘못돼도 시스템 전체가 무너지지 않는다.

> 시험에서 "커널과 셸의 차이"를 묻는 문항이 반복된다. **셸은 명령을 해석해 전달할 뿐, 하드웨어를 직접 다루지 않는다**는 점만 확실히 잡아두면 된다.

## 커널이 실제로 하는 다섯 가지

| 임무 | 하는 일 | 예 |
|------|---------|-----|
| 프로세스 관리 | 어떤 프로그램을 언제 CPU에 올릴지 결정 | 스케줄링, 프로세스 생성·종료 |
| 메모리 관리 | 프로그램마다 쓸 메모리를 나눠주고 회수 | 가상 메모리, 스왑 |
| 파일 시스템 | 디스크의 0과 1을 "파일과 디렉터리"로 보여줌 | ext4, xfs 마운트 |
| 장치 관리 | 하드웨어를 다루는 드라이버 제공 | 키보드, 프린터, 그래픽 카드 |
| 네트워크 | 패킷을 주고받는 규칙 처리 | TCP/IP 스택 |

- 다섯 가지 모두 **"자원을 나눠 쓰게 만드는 일"** 이라는 공통점이 있다.
- 운영체제를 한 문장으로 정의하면 **"하드웨어 자원을 관리하고 사용자에게 인터페이스를 제공하는 소프트웨어"** 다.

## 리눅스라는 이름의 범위

여기서 초보자가 가장 많이 헷갈린다.

- **좁은 의미의 리눅스** = 리누스 토르발스가 만든 **커널**.
- **넓은 의미의 리눅스** = 커널 + GNU 도구 + 각종 소프트웨어를 묶은 **운영체제**(= 배포판).

그래서 자유 소프트웨어 진영에서는 **"GNU/Linux"** 라고 부르자고 주장한다. `ls` `cp` `bash` 같은 우리가 매일 쓰는 명령은 전부 **GNU 프로젝트**가 만든 것이고, 리눅스 커널이 만든 게 아니기 때문이다.

## 커널의 구조: 모놀리식과 마이크로커널

| 구분 | 모놀리식 커널 | 마이크로커널 |
|------|--------------|-------------|
| 구조 | 대부분의 기능이 커널 안에 들어있음 | 최소 기능만 커널에, 나머지는 바깥 |
| 속도 | 빠름 (호출이 커널 내부에서 끝남) | 상대적으로 느림 (통신 비용) |
| 안정성 | 한 부분의 오류가 전체에 영향 | 문제 부분만 격리 가능 |
| 크기 | 큼 | 작음 |
| 예 | **리눅스**, 유닉스 | MINIX, Mach |

- **리눅스는 모놀리식이다.** 이 한 줄이 시험 포인트다.
- 다만 순수한 모놀리식은 아니다. **적재 가능 커널 모듈(LKM)** 로 기능을 필요할 때 붙이고 뗄 수 있어, 마이크로커널의 장점을 일부 가져왔다.
- 그래서 "모듈화된 모놀리식 커널"이라고 부르기도 한다.

## 커널 버전 읽기

```text
$ uname -r
5.15.0-88-generic
│ │  │
│ │  └── 패치 레벨
│ └───── 주 버전(major) 안의 부 버전(minor)
└─────── 주 버전(major)
```

- 예전(2.6 이전)에는 **부 버전이 짝수면 안정판, 홀수면 개발판**이라는 규칙이 있었다.
  - `2.4` → 안정판 / `2.5` → 개발판
- 이 규칙은 **2.6 이후 사라졌다.** 지금은 짝·홀수와 안정성이 무관하다.
- 시험은 여전히 **옛 규칙**을 묻는 경우가 있으니 "짝수=안정" 이라는 문장 자체를 기억해 두자.

## 직접 쳐보기

```bash
uname -a          # 커널 이름·버전·아키텍처 전부
uname -r          # 커널 버전만
cat /proc/version # 커널이 스스로 보고하는 정보
echo $SHELL       # 지금 쓰는 셸
```

> 내일은 이 커널이 어디서 왔는지 — 유닉스에서 리눅스까지의 계보를 따라간다.

## 📖 용어

- **커널(Kernel)** : 하드웨어를 직접 제어하는 운영체제의 핵심부. "리눅스"의 원래 뜻.
- **셸(Shell)** : 사용자가 친 명령을 해석해 커널에 전달하는 프로그램. bash가 대표적이다.
- **시스템 콜(System Call)** : 응용 프로그램이 커널에 일을 부탁하는 공식 창구.
- **모놀리식 커널** : 대부분의 기능이 커널 안에 들어있는 구조. 리눅스가 여기 속한다.
- **마이크로커널** : 최소 기능만 커널에 두고 나머지를 바깥으로 뺀 구조. MINIX가 대표적이다.
- **커널 모듈(LKM)** : 실행 중에 붙였다 뗄 수 있는 커널 기능 조각. 장치 드라이버가 주로 이 형태다.
- **GNU/Linux** : 리눅스 커널과 GNU 도구를 합친 운영체제를 정확히 부르는 이름.
- **가상 메모리** : 실제 메모리보다 큰 공간을 쓰는 것처럼 보이게 하는 커널의 메모리 관리 기법.

## 📝 연습 문제

**문제 1.** 다음 중 리눅스 커널의 구조에 대한 설명으로 알맞은 것은?

A) 최소한의 기능만 커널에 두는 마이크로커널 구조다  
B) 대부분의 기능을 커널에 포함하는 모놀리식 구조다  
C) 커널이 존재하지 않고 셸이 하드웨어를 직접 제어한다  
D) 응용 프로그램마다 별도의 커널이 하나씩 배정된다  

**정답: B**  
해설: 리눅스는 모놀리식 커널입니다. 대부분의 운영체제 기능이 커널 내부에 포함되어 있어 호출이 빠르지만 크기가 큽니다. 다만 적재 가능 커널 모듈(LKM)을 지원해 필요한 기능을 실행 중에 붙였다 뗄 수 있으므로 "모듈화된 모놀리식"이라고도 부릅니다. 마이크로커널의 대표는 MINIX입니다.

---

**문제 2.** 다음 중 셸(Shell)에 대한 설명으로 가장 알맞은 것은?

A) 하드웨어를 직접 제어하는 운영체제의 핵심부다  
B) 사용자의 명령을 해석해 커널에 전달하는 명령 해석기다  
C) 디스크에 파일을 저장하는 파일 시스템의 이름이다  
D) 네트워크 패킷을 처리하는 커널의 하위 모듈이다  

**정답: B**  
해설: 셸은 사용자와 커널 사이에서 명령을 해석해 전달하는 명령 해석기입니다. 하드웨어를 직접 제어하는 것은 커널의 역할이며(A), 셸은 커널에 시스템 콜로 요청할 뿐입니다. bash, sh, csh, ksh, zsh 등이 셸에 해당합니다.

---

**문제 3.** 다음 중 커널의 주요 기능으로 거리가 먼 것은?

A) 프로세스 스케줄링  
B) 메모리 할당과 회수  
C) 워드프로세서 문서 편집  
D) 장치 드라이버를 통한 하드웨어 제어  

**정답: C**  
해설: 문서 편집은 응용 프로그램의 몫입니다. 커널은 프로세스 관리, 메모리 관리, 파일 시스템, 장치 관리, 네트워크라는 다섯 축의 자원 관리를 담당합니다. 응용 프로그램은 커널 위에서 동작하며 필요한 자원을 시스템 콜로 요청합니다.

---

**문제 4.** 응용 프로그램이 하드웨어에 직접 접근하지 못하도록 막고, 커널에 작업을 요청할 때 사용하는 공식적인 통로를 무엇이라 하는가?

A) 셸 스크립트  
B) 시스템 콜  
C) 커널 모듈  
D) 데몬  

**정답: B**  
해설: 시스템 콜은 응용 프로그램이 커널의 기능을 요청하는 인터페이스입니다. 이 구조 덕분에 프로그램 하나가 잘못되어도 하드웨어나 시스템 전체가 손상되지 않습니다. 커널 모듈은 실행 중 적재 가능한 커널 기능 조각이고, 데몬은 백그라운드에서 상시 동작하는 프로세스입니다.

**문제 5.** 다음 중 "리눅스"라는 이름에 대한 설명으로 알맞은 것은?

A) 리누스 토르발스가 만든 커널의 이름에서 유래했다  
B) GNU 프로젝트가 만든 셸의 이름에서 유래했다  
C) 유닉스를 만든 벨 연구소의 상표명이다  
D) 배포판을 관리하는 회사의 이름이다  

**정답: A**  
해설: 리눅스는 1991년 리누스 토르발스가 발표한 커널의 이름입니다. 우리가 사용하는 완성된 운영체제는 이 커널에 GNU 프로젝트의 도구(`ls`, `cp`, `bash` 등)와 여러 소프트웨어를 더한 것이며, 이 때문에 "GNU/Linux"라고 부르자는 주장이 있습니다.
