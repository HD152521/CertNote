# Day 4 - 프로세스 명령과 작업 예약

## 📌 핵심 정리

- **`ps`는 그 순간의 목록, `top`은 실시간**이다. `ps -ef`와 `ps aux`가 대표 조합이다.
- **`kill`은 죽이는 게 아니라 시그널을 보내는** 명령이다. 기본 시그널은 **15(TERM)**.
- **강제 종료는 9(KILL)** 다. `kill -9 PID` 형태로 쓴다.
- **우선순위는 `nice` 값**으로 정한다. **-20이 가장 높고 19가 가장 낮다.**
- **`cron`은 주기적으로, `at`은 한 번만** 실행한다. crontab은 **5개 필드**다.

## 프로세스 보기

```bash
ps                 # 현재 터미널의 프로세스만
ps -ef             # 전체 (System V 방식)
ps aux             # 전체 (BSD 방식) — 하이픈 없음
ps -ef | grep httpd
pstree             # 부모-자식 관계를 트리로
pgrep httpd        # 이름으로 PID 찾기
```

| 형식 | 계열 | 특징 |
|------|------|------|
| **`ps -ef`** | **System V** | UID·PID·PPID·시작시각 |
| **`ps aux`** | **BSD** | **CPU·메모리 사용률**까지 |

- **`aux`에는 하이픈이 없다.** BSD 방식이라 그렇다. 이 표기 차이가 문제로 나온다.
- `-e`는 전체(every), `-f`는 자세히(full)라는 뜻이다.

### top — 실시간

```bash
top            # 실시간 모니터링, q 로 종료
top -d 2       # 2초마다 갱신
```

| 키 | 하는 일 |
|----|--------|
| `q` | 종료 |
| `k` | 프로세스 종료(kill) |
| `M` | **메모리** 사용률순 정렬 |
| `P` | **CPU** 사용률순 정렬 |

- **`ps`는 한 번 찍는 사진, `top`은 계속 움직이는 화면**이다. 이 대비를 기억한다.

### 프로세스 상태 문자

| 문자 | 상태 |
|------|------|
| **`R`** | 실행 중(Running) |
| **`S`** | 대기(Sleeping) |
| **`Z`** | **좀비** |
| `T` | 정지(Stopped) |
| `D` | 중단 불가 대기 |

## 프로세스 종료 — kill

**`kill`은 시그널을 보내는 명령**이다. 이름 때문에 오해하기 쉽다.

| 번호 | 이름 | 하는 일 |
|-----|------|--------|
| **1** | **SIGHUP** | 터미널 끊김. 데몬은 **설정 다시 읽기**로 쓴다 |
| **2** | **SIGINT** | 인터럽트 — **`Ctrl+C`** 와 같다 |
| **9** | **SIGKILL** | **강제 종료. 무시할 수 없다** |
| **15** | **SIGTERM** | **정상 종료 요청. `kill`의 기본값** |
| 18/19 | SIGCONT / SIGSTOP | 재개 / 정지 |

```bash
kill 1234              # 15번(TERM) 을 보낸다 — 기본값
kill -9 1234           # 강제 종료
kill -15 1234          # 정상 종료 (kill 1234 와 같다)
kill -l                # 시그널 목록
killall httpd          # 이름으로 전부 종료
pkill -u alice         # 사용자 단위로 종료
```

> **9와 15의 차이**가 핵심이다. **15는 "정리하고 끝내라"는 요청**이라 프로그램이 저장 등 마무리를 할 수 있다. **9는 커널이 즉시 없애 버려** 무시할 수 없지만 데이터가 손상될 수 있다. **먼저 15, 안 되면 9** 가 순서다.

## 우선순위 — nice

```bash
nice -n 10 명령        # 우선순위를 낮춰 실행
renice 5 -p 1234       # 실행 중인 프로세스의 값 변경
```

```text
   -20  ◄──────────────────────►  19
   높음         우선순위          낮음
                 0
              (기본값)
```

- **값이 작을수록 우선순위가 높다.** 직관과 반대라 헷갈린다. **nice는 "양보"** 라고 생각하면 된다 — 많이 양보할수록(값이 클수록) 뒤로 밀린다.
- 범위는 **-20 ~ 19**, 기본값은 **0** 이다.
- **우선순위를 높이는 것(음수)은 root만** 할 수 있다. 일반 사용자는 낮추기만 가능하다.

## 작업 예약

| 구분 | **cron** | **at** |
|------|---------|-------|
| 실행 횟수 | **주기적으로 반복** | **한 번만** |
| 데몬 | `crond` | `atd` |
| 설정 | `crontab -e` | `at 시각` |
| 예 | 매일 새벽 백업 | 오늘 밤 10시에 한 번 |

### crontab — 5개 필드

```text
   *  *  *  *  *   실행할 명령
   │  │  │  │  │
   │  │  │  │  └── 요일  (0-7, 0과 7이 일요일)
   │  │  │  └───── 월    (1-12)
   │  │  └──────── 일    (1-31)
   │  └─────────── 시    (0-23)
   └────────────── 분    (0-59)
```

| 예 | 뜻 |
|----|-----|
| `0 3 * * *` | **매일 새벽 3시** |
| `30 2 * * 0` | 매주 **일요일** 2시 30분 |
| `*/10 * * * *` | **10분마다** |
| `0 0 1 * *` | 매월 **1일** 자정 |

- **필드는 5개**이고 **순서는 분·시·일·월·요일**이다. 이 순서를 그대로 묻는다.
- **요일은 0과 7이 모두 일요일**이다.
- `*`는 "매번", `*/n`은 "n마다", 쉼표는 나열(`1,15`), 하이픈은 범위(`1-5`)다.

```bash
crontab -e         # 편집
crontab -l         # 목록 보기
crontab -r         # 전부 삭제
```

> ⚠️ **`-r`은 확인 없이 전부 지운다.** `-e`와 키가 붙어 있어 실수하기 쉽다.

### at

```bash
at 22:00           # 오늘 밤 10시
at now + 1 hour    # 1시간 뒤
atq                # 예약 목록
atrm 3             # 3번 예약 취소
```

- 명령을 입력한 뒤 **`Ctrl+D`** 로 마친다.
- 사용 허가는 **`/etc/at.allow`·`/etc/at.deny`**, cron은 **`/etc/cron.allow`·`/etc/cron.deny`** 로 관리한다.

> 내일은 이번 주의 에디터와 프로세스를 한 장으로 묶어 정리한다.

## 📖 용어

- **`ps`** : 실행 중인 프로세스 목록을 한 번 출력하는 명령.
- **`top`** : 프로세스 상태를 실시간으로 갱신하며 보여 주는 명령.
- **시그널** : 프로세스에 보내는 신호. `kill`이 전달한다.
- **SIGKILL(9)** : 무시할 수 없는 강제 종료 시그널.
- **SIGTERM(15)** : 정상 종료를 요청하는 시그널. `kill`의 기본값이다.
- **nice 값** : 프로세스 우선순위. -20이 가장 높고 19가 가장 낮으며 기본은 0이다.
- **cron** : 지정한 주기로 명령을 반복 실행하는 예약 도구. 필드가 5개다.
- **at** : 지정한 시각에 명령을 한 번만 실행하는 예약 도구.

## 📝 연습 문제

**문제 1.** 다음 중 프로세스를 강제로 종료할 때 사용하는 시그널 번호로 알맞은 것은?

A) 1  
B) 2  
C) 15  
D) 9  

**정답: D**  
해설: 9번 SIGKILL은 프로세스가 무시할 수 없는 강제 종료 시그널로 커널이 즉시 프로세스를 제거합니다. 15번 SIGTERM은 정상 종료를 요청하는 기본 시그널이며, 1번 SIGHUP은 설정 재적용, 2번 SIGINT는 `Ctrl+C`에 해당합니다.

---

**문제 2.** 다음 중 `crontab` 설정의 다섯 개 필드를 순서대로 바르게 나열한 것은?

A) 시 분 일 월 요일  
B) 분 시 일 월 요일  
C) 분 시 월 일 요일  
D) 요일 분 시 일 월  

**정답: B**  
해설: crontab의 필드는 왼쪽부터 분, 시, 일, 월, 요일 순서입니다. 요일은 0부터 7까지 쓰며 0과 7이 모두 일요일을 뜻합니다. 예를 들어 `0 3 * * *`는 매일 새벽 3시에 실행하라는 설정입니다.

---

**문제 3.** 다음 중 프로세스의 우선순위를 나타내는 nice 값의 범위와 가장 높은 우선순위에 해당하는 값으로 알맞은 것은?

A) 0에서 19까지이며 0이 가장 높다  
B) -19에서 20까지이며 20이 가장 높다  
C) -20에서 19까지이며 -20이 가장 높다  
D) -20에서 19까지이며 19가 가장 높다  

**정답: C**  
해설: nice 값은 -20부터 19까지이며 값이 작을수록 우선순위가 높습니다. 기본값은 0이고, 우선순위를 높이는 음수 지정은 root만 가능하며 일반 사용자는 값을 올려 우선순위를 낮추는 것만 할 수 있습니다.

---

**문제 4.** 다음 중 프로세스의 상태를 실시간으로 갱신하며 보여 주는 명령으로 알맞은 것은?

A) top  
B) ps  
C) pstree  
D) jobs  

**정답: A**  
해설: `top`은 화면을 주기적으로 갱신하며 CPU와 메모리 사용률을 실시간으로 보여 줍니다. `ps`는 실행 시점의 목록을 한 번 출력하고 끝나며, `pstree`는 부모 자식 관계를 트리로, `jobs`는 현재 셸의 백그라운드 작업만 보여 줍니다.

---

**문제 5.** 다음 중 지정한 시각에 명령을 한 번만 실행하도록 예약하는 명령으로 알맞은 것은?

A) cron  
B) at  
C) nice  
D) nohup  

**정답: B**  
해설: `at`은 지정한 시각에 작업을 한 번만 수행하며 `atq`로 목록을 보고 `atrm`으로 취소합니다. 반복 실행이 필요하면 `cron`을 사용합니다. `nice`는 우선순위 조정, `nohup`은 터미널 종료 후에도 실행을 유지하는 명령입니다.
