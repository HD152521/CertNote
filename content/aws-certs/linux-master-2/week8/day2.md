# Day 2 - 라이브러리와 툴킷 계층

## 📌 핵심 정리

- X 클라이언트는 **두 층**을 거쳐 X 서버와 대화한다 — **저수준 라이브러리**와 그 위의 **툴킷**.
- 저수준 라이브러리는 **Xlib**과 **XCB** 둘이다. **XCB가 X 서버에 더 가까운 저수준**이다.
- 툴킷은 **GTK+ · Qt · FLTK · Motif · Tk** 가 대표다.
- **GTK+는 C 언어로 만들어져 GNOME이**, **Qt는 C++로 만들어져 KDE가** 쓴다.
- 짝을 이룬다 — **Xlib ↔ XCB(저수준 라이브러리)**, **GTK+ ↔ Qt(툴킷)**.

## 네 개의 층

![응용 프로그램·툴킷·저수준 라이브러리·X 서버로 이어지는 X 윈도 계층 구조](/diagrams/x-window-layers.svg)

- **아래로 갈수록 X 서버에 가깝고 저수준**이다. 이 위아래 관계를 그대로 묻는다.
- 툴킷 없이 Xlib만으로도 프로그램을 만들 수 있지만, 버튼 하나를 그리는 데도 선을 일일이 그려야 한다.

### "확인" 버튼 하나가 화면에 나오기까지

| 층 | 이 층에서 하는 말 | 맡은 일 |
|----|----------------|--------|
| **응용 프로그램** | "여기에 '확인' 버튼을 둔다" | 무엇을 보여 줄지 정한다 |
| **툴킷** (GTK+ · Qt) | "버튼은 둥근 사각형에 글자, 누르면 색이 바뀐다" | **위젯의 모양과 동작**을 만든다 |
| **저수준 라이브러리** (Xlib · XCB) | "좌표 (10,20)에 사각형, 그 안에 글자" | 그리기 지시를 **X 프로토콜 메시지로 바꿔** 보낸다 |
| **X 서버** | (받은 대로 화면에 그린다) | 실제 **화면 출력과 입력 장치**를 맡는다 |

- 위 세 층(응용 프로그램·툴킷·저수준 라이브러리)은 **모두 X 클라이언트 쪽**이다. Xlib과 XCB를 **"X 클라이언트 라이브러리"** 라고 부르는 이유이며, X 서버의 일부로 오해하면 안 된다.
- 마우스로 버튼을 누르면 반대 방향으로 올라온다 — X 서버가 **이벤트**를 보내고, 저수준 라이브러리가 받아, 툴킷이 "버튼이 눌렸다"로 해석해 프로그램에 알린다.
- 층을 나눈 덕에 **아래가 바뀌어도 위는 그대로** 쓸 수 있다. GTK+와 Qt는 Wayland에서도 동작하므로, 툴킷으로 만든 프로그램은 X에서도 Wayland에서도 돈다. Xlib을 직접 부르는 옛 프로그램은 어제 본 XWayland가 필요하다.

## 저수준 라이브러리 — Xlib과 XCB

| 구분 | **Xlib** | **XCB** |
|------|---------|--------|
| 풀네임 | X Library | **X protocol C-language Binding** |
| 등장 | **전통적**, 오래됐다 | **나중에 나온 대체품** |
| 계층 | X 프로토콜을 감싼 라이브러리 | **더 얇다 — X 서버에 더 가깝다** |
| 통신 | **동기(synchronous)** 중심 | **비동기(asynchronous)** |
| 크기 | 무겁다 | **가볍다** |

> **"X 서버에 가장 가까운 저수준 X 클라이언트 라이브러리는?"** 이라는 문제의 답은 **XCB** 다. Qt·GTK+·FLTK는 그보다 위층의 **툴킷**이므로 답이 될 수 없다.

- **XCB는 Xlib을 대체하려고 만든 것**이다. 프로토콜에 더 가깝고 지연이 적다.
- 지금은 Xlib 내부도 XCB 위에서 동작하도록 재구현되어 있다.

### 동기와 비동기가 무슨 차이인가

```text
   Xlib (동기)                          XCB (비동기)
   요청 1 보냄                           요청 1 보냄
     … 응답 올 때까지 기다림              요청 2 보냄
   응답 1 받음                           요청 3 보냄
   요청 2 보냄                             … 다른 일을 한다
     … 기다림                            응답 1 · 2 · 3 을 필요할 때 받음
   응답 2 받음
```

- 위 그림은 창의 크기를 묻는 것처럼 **응답이 필요한 요청**을 보낼 때의 차이다.
- X 서버가 네트워크 건너편에 있으면 응답 하나에 시간이 걸린다. **하나씩 기다리는 방식은 요청이 많을수록 느려지고**, 한꺼번에 보내 두는 방식은 기다리는 시간을 겹쳐 쓴다. XCB가 "지연이 적다"는 말의 속뜻이다.
- **"더 저수준"은 "더 불편하지만 X 프로토콜에 더 가깝다"** 는 뜻이다. XCB는 프로토콜의 메시지를 거의 그대로 함수로 옮겨 놓았고, Xlib은 그 위에 편의 기능을 더 얹었다. 성능이 낮다는 뜻이 아니다.

| 헷갈리는 표현 | 맞는 답 |
|-------------|--------|
| "X 서버에 **가장 가까운**", "**가장 저수준**의" 라이브러리 | **XCB** |
| "**전통적인**", "가장 오래된" 저수준 라이브러리 | **Xlib** |
| "Xlib을 **대체**하려고 만든" | **XCB** |
| "**비동기**" 방식 | **XCB** |
| "**위젯**을 제공하는" | 툴킷 (GTK+ · Qt …) — 둘 다 아니다 |

- 옛 X 프로그램 가운데에는 Xlib과 툴킷 사이에 **Xt(X Toolkit Intrinsics)** 라는 층을 두는 것이 있다. 위젯을 만들 뼈대만 주는 층으로, **Motif**와 X 기본 프로그램(`xterm`·`xclock`)이 쓰는 **Athena 위젯(Xaw)** 이 이 위에 만들어졌다.

## 툴킷

버튼·메뉴·체크박스 같은 **위젯(widget)** 을 만들어 주는 라이브러리다.

| 툴킷 | 풀네임 · 유래 | 언어 | 쓰는 곳 |
|------|-------------|------|--------|
| **GTK+** | **GIMP Toolkit** | **C** | **GNOME**, GIMP, Xfce |
| **Qt** | (큐트라고 읽는다) | **C++** | **KDE**, VLC |
| **FLTK** | **Fast Light Toolkit** | C++ | **가벼운** 프로그램 |
| **Motif** | — | C | **CDE**, 전통적인 상용 유닉스 |
| **Tk** | Tcl/Tk의 그래픽 부분 | Tcl | 스크립트용 |
| **XForms** | — | C | 예전 툴킷 |

### 외워야 할 짝

| 짝 | 무엇이 같은가 |
|----|-------------|
| **Xlib ↔ XCB** | 둘 다 **저수준 라이브러리** |
| **GTK+ ↔ Qt** | 둘 다 **대표 툴킷** |
| **GNOME ↔ Xfce** | 둘 다 **GTK+** 를 쓰는 데스크톱 환경 |
| **KDE ↔ Qt** | KDE는 Qt로 만들어졌다 |

> **"나머지와 종류가 다른 것"** 형태로 묻는다. 예를 들어 `Xlib · XCB · GTK+` 중에서는 **GTK+가 툴킷**이라 다르고, `GTK+ · Qt · FLTK · XCB` 중에서는 **XCB가 저수준 라이브러리**라 다르다.

### GTK+와 Qt

| 구분 | **GTK+** | **Qt** |
|------|---------|-------|
| 언어 | **C** | **C++** |
| 유래 | **GIMP**를 만들려고 개발 | 노르웨이 Trolltech |
| 대표 데스크톱 | **GNOME**, Xfce, LXDE | **KDE**, LXQt |
| 대표 프로그램 | GIMP, Firefox | VLC, Krita |

- **GTK+ = GIMP Toolkit** 이라는 유래를 묻는 문제가 있다. 이미지 편집기 GIMP를 만들려고 개발한 것이 독립 툴킷이 되었다.
- **언어가 C인지 C++인지**도 묻는다. **GTK+는 C, Qt는 C++** 다.

### 왜 진영이 둘로 갈렸나

```text
   1996  KDE 시작      Qt 를 골랐다 — 그런데 당시 Qt 는 자유 소프트웨어 라이선스가 아니었다
     │
   1997  GNOME 시작    "완전히 자유로운 데스크톱"을 내걸고 GTK+ 를 골랐다
     │
   이후   Qt 도 GPL · LGPL 로 공개 — 라이선스 문제는 해소됐지만 두 진영은 그대로 남았다
```

- **GNOME이 생긴 직접적인 계기가 Qt의 라이선스**였다. 그래서 "GNOME ↔ GTK+", "KDE ↔ Qt"는 우연한 조합이 아니라 **출발부터 묶인 짝**이다.
- 이 사정이 **GTK+는 GNU 프로젝트의 일부**라는 점, 라이선스가 **LGPL**이라는 점과 이어진다.

| 구분 | **GTK+** | **Qt** |
|------|---------|-------|
| 라이선스 | LGPL | GPL · LGPL과 상용 라이선스를 함께 제공 |
| 만든 곳의 변천 | GIMP 개발자들 → GNOME 프로젝트 | Trolltech → 노키아 → 지금의 The Qt Company |
| 동작하는 곳 | 리눅스 중심, 윈도·macOS도 지원 | **리눅스·윈도·macOS·모바일**까지 폭넓게 |
| 이름 표기 | 최근 버전부터 `+`를 떼고 **GTK** 로 쓴다 | — |

- 시험 보기에는 여전히 **`GTK+`** 로 나온다. `GTK`와 같은 것이다.
- **"C로 만든 툴킷"이지 "C로만 쓸 수 있는 툴킷"이 아니다.** GTK+도 Qt도 파이썬 등 다른 언어에서 불러 쓸 수 있다. 문제가 묻는 것은 **툴킷 자체를 작성한 언어**다.

### 프로그램을 보고 툴킷 맞히기

| 프로그램 | 종류 | 툴킷 |
|---------|------|------|
| **GIMP** | 이미지 편집기 | **GTK+** (이 툴킷의 출발점) |
| gedit · Nautilus | GNOME의 편집기 · 파일 관리자 | **GTK+** |
| Firefox (리눅스판) | 웹 브라우저 | GTK+ |
| **Dolphin** · Konsole · Kate | KDE의 파일 관리자 · 터미널 · 편집기 | **Qt** |
| VLC · Krita | 동영상 재생기 · 그림 도구 | Qt |
| `xterm` · `xclock` · `xeyes` | X 기본 프로그램 | 툴킷 없이 Xlib·Xt·Athena 위젯 |

- **GNOME에 딸린 프로그램은 GTK+, KDE에 딸린 프로그램은 Qt** 로 묶어 기억한다. KDE 프로그램은 이름에 **K**가 들어간 것이 많다.
- 툴킷이 달라도 **같은 화면에 함께 뜬다.** GNOME에서 Qt 프로그램인 VLC를 실행해도 된다. 결국 둘 다 같은 X 서버에 그려 달라고 요청하기 때문이다. 다만 버튼·메뉴의 생김새가 서로 달라 보인다.

### Motif

- **1980년대 후반의 상용 툴킷**으로 전통적인 유닉스 워크스테이션의 표준이었다.
- **CDE(Common Desktop Environment)** 가 Motif로 만들어졌다.
- 이후 오픈소스로 공개되어 **OpenMotif** 가 되었고, 호환 구현으로 **LessTif** 가 있었다.
- 지금은 거의 쓰이지 않지만 **이름은 시험에 나온다.**

## 계층 정리

```text
   응용 프로그램
        │
   ┌────┴──────────────────────────┐
   │  툴킷                          │   GTK+(C) · Qt(C++) · FLTK · Motif · Tk
   └────┬──────────────────────────┘
        │
   ┌────┴──────────────────────────┐
   │  저수준 라이브러리              │   Xlib · XCB   ← XCB 가 더 아래
   └────┬──────────────────────────┘
        │  X 프로토콜
        ▼
     X 서버
```

### 나머지 툴킷을 한 줄씩

| 툴킷 | 기억할 한 가지 | 함께 나오는 이름 |
|------|-------------|---------------|
| **FLTK** | **작고 빠른 것**이 목표. "풀틱"이라 읽는다 | Fast Light Toolkit |
| **Motif** | 상용 유닉스 시절의 표준. **Xt 위에** 만들어졌다 | CDE, OpenMotif, LessTif |
| **Tk** | 스크립트 언어 **Tcl**과 짝. 파이썬의 `tkinter`도 이것을 쓴다 | Tcl/Tk |
| **XForms** | 예전의 가벼운 툴킷. Xfce가 처음에 이것으로 만들어졌다 | — |

### 이름을 층에 꽂아 넣기

| 이름 | 층 | 틀리기 쉬운 이유 |
|------|-----|---------------|
| **XCB** | 저수준 라이브러리 | 낯선 이름이라 툴킷으로 착각 |
| **Xlib** | 저수준 라이브러리 | X 서버의 일부로 착각 — **클라이언트 쪽**이다 |
| **GTK+** | 툴킷 | GNOME(데스크톱 환경)과 혼동 |
| **Qt** | 툴킷 | KDE(데스크톱 환경)와 혼동 |
| **FLTK** · **Motif** · **Tk** | 툴킷 | 이름이 생소함 |
| **GIMP** | **응용 프로그램** | "GIMP Toolkit" 때문에 툴킷으로 착각 |
| **GNOME** · **KDE** | **데스크톱 환경** | 툴킷과 한 묶음으로 외우다 층을 섞음 |
| **X11** | **프로토콜 버전** | 라이브러리 이름으로 착각 |
| **X.org Server** | **X 서버** | — |

- 한 보기 안에 **층이 다른 이름을 일부러 섞는다.** "툴킷이 아닌 것"을 물으면 Xlib·XCB(아래층)나 GNOME·KDE(위층)가 답이 되고, "저수준 라이브러리가 아닌 것"을 물으면 툴킷 가운데 하나가 답이 된다.
- 순서를 묻기도 한다. **X 서버에서 가까운 순으로 `XCB → Xlib → 툴킷(GTK+·Qt) → 응용 프로그램`** 이다.

| 외우는 실마리 | 내용 |
|-------------|------|
| **이름이 X로 시작하면 아래층** | **X**lib, **X**CB는 저수준 라이브러리 (단, XForms는 툴킷) |
| **끝이 tk·TK면 툴킷** | G**TK**+, FL**TK**, **Tk** — toolkit의 줄임이다 |
| **C는 G, C++은 Q** | GTK+ = C = GNOME, Qt = C++ = KDE |
| **CB는 C Binding** | X**CB** = X protocol **C**-language **B**inding |

> 내일은 이 위에 얹히는 **윈도 매니저 · 디스플레이 매니저 · 데스크톱 환경**의 구분을 다룬다.

## 📖 용어

- **Xlib** : X 프로토콜을 함수로 감싼 전통적인 저수준 라이브러리.
- **XCB** : X protocol C-language Binding. Xlib보다 얇고 X 서버에 더 가까운 저수준 라이브러리.
- **툴킷(toolkit)** : 버튼·메뉴 같은 위젯을 제공하는 상위 라이브러리.
- **GTK+** : GIMP Toolkit. C 언어로 만들어졌으며 GNOME이 사용한다.
- **Qt** : C++로 만들어진 툴킷. KDE가 사용한다.
- **FLTK** : Fast Light Toolkit. 가볍고 빠른 것을 목표로 한 C++ 툴킷.
- **Motif** : 전통적인 상용 유닉스에서 쓰이던 툴킷. CDE가 이것으로 만들어졌다.
- **위젯(widget)** : 버튼, 메뉴, 스크롤바처럼 화면을 구성하는 개별 요소.

## 📝 연습 문제

**문제 1.** 다음 중 X 서버에 가장 가까운 저수준 X 클라이언트 라이브러리로 알맞은 것은?

A) Qt  
B) XCB  
C) GTK+  
D) FLTK  

**정답: B**  
해설: XCB는 X protocol C-language Binding의 줄임말로 X 프로토콜을 얇게 감싼 저수준 라이브러리이며 Xlib보다 X 서버에 더 가깝습니다. Qt, GTK+, FLTK는 그보다 상위 계층에서 버튼과 메뉴 같은 위젯을 제공하는 툴킷입니다.

---

**문제 2.** 다음 중 GTK+ 툴킷을 작성하는 데 사용된 프로그래밍 언어로 알맞은 것은?

A) C++  
B) Java  
C) C  
D) Python  

**정답: C**  
해설: GTK+는 C 언어로 작성되었으며 이름은 GIMP Toolkit에서 유래했습니다. 반면 Qt는 C++로 작성되었고 KDE 데스크톱 환경의 기반이 됩니다. 두 툴킷의 개발 언어를 구분하는 문제가 자주 출제됩니다.

**문제 3.** 다음 중 KDE 데스크톱 환경의 기반이 되는 툴킷으로 알맞은 것은?

A) Qt  
B) GTK+  
C) Motif  
D) Tk  

**정답: A**  
해설: KDE는 C++로 작성된 Qt 툴킷을 기반으로 만들어졌습니다. GTK+는 GNOME과 Xfce가 사용하며, Motif는 전통적인 상용 유닉스의 CDE에서 쓰이던 툴킷이고 Tk는 Tcl 언어와 함께 쓰이는 툴킷입니다.

**문제 4.** 다음 중 나머지 셋과 계층이 다른 것으로 알맞은 것은?

A) GTK+  
B) Qt  
C) FLTK  
D) Xlib  

**정답: D**  
해설: GTK+, Qt, FLTK는 모두 위젯을 제공하는 툴킷 계층에 속하지만 Xlib은 X 프로토콜을 직접 감싼 저수준 라이브러리로 툴킷보다 아래 계층에 있습니다. 같은 계층의 라이브러리로는 XCB가 있습니다.

**문제 5.** 다음 중 GTK+ 툴킷 이름의 유래가 된 프로그램으로 알맞은 것은?

A) GIMP  
B) GNOME  
C) GNU  
D) Gedit  

**정답: A**  
해설: GTK+는 GIMP Toolkit의 줄임말로, 이미지 편집 프로그램 GIMP를 개발하는 과정에서 만들어진 툴킷이 독립적인 라이브러리로 발전한 것입니다. 이후 GNOME 데스크톱 환경의 기반 툴킷으로 널리 쓰이게 되었습니다.
