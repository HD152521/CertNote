# Day 1 - X 윈도의 구조와 발전

## 📌 핵심 정리

- **X 윈도는 유닉스·리눅스의 그래픽 환경을 담당하는 시스템**이다. 1984년 **MIT**에서 시작됐다.
- **서버와 클라이언트가 뒤바뀌어 있다.** **화면·키보드·마우스를 가진 쪽이 X 서버**, **프로그램이 X 클라이언트**다.
- **네트워크 기반**이라 다른 컴퓨터에서 실행한 프로그램의 화면을 내 컴퓨터에 띄울 수 있다.
- X 서버 구현의 발전 순서는 **XFree86 → X.org Server → Wayland** 다.
- X 윈도는 **모양과 조작 방식을 강제하지 않는다.** 그래서 **윈도 매니저**가 따로 필요하다.

## X 윈도란

| 항목 | 내용 |
|------|------|
| 시작 | **1984년 MIT** (Athena 프로젝트) |
| 성격 | 그래픽 환경을 제공하는 **시스템이자 프로토콜** |
| 특징 | **네트워크 기반 · 플랫폼 독립적 · 정책을 강제하지 않음** |

- 정식 이름은 **X Window System** 이다. "X Windows"라고 복수로 쓰지 않는다.
- **운영체제의 일부가 아니다.** 리눅스 커널과 분리된 **응용 프로그램**이라 없어도 시스템은 동작한다. 서버는 흔히 X 없이 운영한다.

## 서버와 클라이언트가 뒤바뀌어 있다

여기가 X 윈도에서 가장 헷갈리는 부분이자 가장 자주 나오는 문제다.

```text
   [ 내 앞의 컴퓨터 ]                    [ 멀리 있는 서버 ]

     X 서버                                X 클라이언트
     화면 · 키보드 · 마우스                  실제 프로그램
     (하드웨어를 가진 쪽)                    (xterm, gedit ...)
        │                                        │
        │◄──── 화면에 그려 달라는 요청 ───────────┤
        ├───── 키보드·마우스 입력 전달 ─────────►│
```

| 구분 | **X 서버** | **X 클라이언트** |
|------|----------|----------------|
| 정체 | **디스플레이·입력장치를 가진 쪽** | **응용 프로그램** |
| 하는 일 | 화면에 그려 주고 입력을 전달 | 무엇을 그릴지 요청 |
| 있는 곳 | **사용자 앞** | 어디든 (원격도 가능) |
| 예 | 내 노트북의 화면 | `xterm`, `xclock`, 브라우저 |

> **"자원(화면)을 제공하는 쪽이 서버"** 라고 생각하면 이해된다. 웹은 자료를 가진 쪽이 서버지만, X는 **화면을 가진 쪽**이 서버다. 그래서 **내 앞의 컴퓨터가 X 서버**가 된다.

- 이 구조 덕분에 **원격 컴퓨터에서 실행한 프로그램의 창이 내 화면에 뜨는** 일이 가능하다. 이를 **네트워크 투명성(network transparency)** 이라 한다.
- 프로그램과 화면이 같은 컴퓨터에 있을 때도 **똑같은 방식**으로 동작한다.

## 발전 과정

```text
   1984  X Window System        MIT 에서 시작
     │
   1987  X11                    지금까지 쓰이는 버전 번호
     │
   1992  XFree86                PC 유닉스용 무료 구현. 오랫동안 표준
     │                          2004년 라이선스 변경으로 갈라짐
     ▼
   2004  X.org Server           XFree86 에서 갈라져 나옴. 현재 표준
     │
     ▼
   2008~ Wayland                X 를 대체하려는 차세대 방식
```

| 이름 | 성격 |
|------|------|
| **XFree86** | PC용 X 구현으로 오랫동안 표준이었다. **라이선스 문제**로 주도권을 잃었다 |
| **X.org Server** | XFree86에서 **갈라져 나온** 구현. **현재의 표준** |
| **Wayland** | X의 복잡한 구조를 걷어낸 **차세대 디스플레이 서버 프로토콜** |

> **발전 순서 `XFree86 → X.org Server → Wayland`** 를 그대로 묻는 문제가 나온다. 세 이름의 순서를 외운다.

- **X11** 은 1987년에 나온 **11번째 버전**이며, 지금 쓰는 것도 여전히 X11이다. 그래서 `X11`이라는 표기가 곳곳에 남아 있다.
- **Wayland는 X의 새 버전이 아니라 대체품**이다. 구조 자체가 다르며, 기존 X 프로그램은 `XWayland`라는 호환 계층으로 돌린다.

## 정책을 강제하지 않는다

X 윈도는 **"어떻게 그릴 것인가"만 제공하고 "어떻게 보일 것인가"는 정하지 않는다.**

```text
   X 윈도       창을 그리는 기본 기능만 제공
      │
      ├── 창의 테두리 · 최소화 버튼 · 이동?   →  윈도 매니저가 담당
      ├── 로그인 화면?                       →  디스플레이 매니저가 담당
      └── 패널 · 파일관리자 · 통합 환경?      →  데스크톱 환경이 담당
```

- 그래서 리눅스에는 **창 모양이 서로 다른 환경이 여러 개** 존재한다. 윈도나 macOS와 크게 다른 점이다.
- 이 세 가지(윈도 매니저 · 디스플레이 매니저 · 데스크톱 환경)의 구분은 **3일 뒤에 자세히** 다룬다.

## 관련 용어

| 용어 | 뜻 |
|------|-----|
| **X11** | X 윈도의 11번째 버전. 현재까지 쓰인다 |
| **네트워크 투명성** | 프로그램이 로컬에 있든 원격에 있든 같은 방식으로 화면에 표시되는 성질 |
| **XWayland** | Wayland 환경에서 기존 X 프로그램을 실행하기 위한 호환 계층 |
| **디스플레이 서버** | 화면 출력과 입력을 관리하는 프로그램. X 서버·Wayland 컴포지터가 여기 해당 |

> 내일은 X 클라이언트를 만드는 데 쓰는 라이브러리와 툴킷의 계층을 다룬다.

## 📖 용어

- **X 윈도(X Window System)** : 유닉스·리눅스의 그래픽 환경을 제공하는 시스템. 1984년 MIT에서 시작됐다.
- **X 서버** : 화면·키보드·마우스를 가진 쪽. 사용자가 앉아 있는 컴퓨터가 여기 해당한다.
- **X 클라이언트** : 화면에 무언가를 그려 달라고 요청하는 응용 프로그램.
- **네트워크 투명성** : 원격에서 실행한 프로그램의 화면을 로컬과 똑같이 표시할 수 있는 성질.
- **XFree86** : PC용 X 구현으로 오랫동안 표준이었던 프로젝트.
- **X.org Server** : XFree86에서 갈라져 나온 현재의 표준 X 서버 구현.
- **Wayland** : X를 대체하려는 차세대 디스플레이 서버 프로토콜.
- **X11** : 1987년에 나온 X 윈도의 11번째 버전. 현재까지 쓰이는 버전이다.

## 📝 연습 문제

**문제 1.** 다음 중 X 윈도 시스템에서 X 서버에 해당하는 것으로 알맞은 것은?

A) 원격에서 실행 중인 응용 프로그램  
B) 화면에 창을 띄우려는 프로그램  
C) 디스플레이와 입력장치를 가진 사용자 측 컴퓨터  
D) 창의 테두리와 버튼을 그리는 윈도 매니저  

**정답: C**  
해설: X 윈도에서는 화면과 키보드, 마우스 같은 자원을 제공하는 쪽이 서버입니다. 따라서 사용자가 앉아 있는 컴퓨터가 X 서버가 되고, 무언가를 그려 달라고 요청하는 응용 프로그램이 X 클라이언트가 됩니다. 일반적인 웹 서버 개념과 반대라 혼동하기 쉽습니다.

---

**문제 2.** 다음 중 X 서버 구현의 발전 순서를 바르게 나열한 것은?

A) XFree86 → X.org Server → Wayland  
B) X.org Server → XFree86 → Wayland  
C) Wayland → XFree86 → X.org Server  
D) XFree86 → Wayland → X.org Server  

**정답: A**  
해설: PC용 X 구현으로 널리 쓰이던 XFree86이 라이선스 변경 문제로 주도권을 잃으면서 X.org Server가 갈라져 나와 현재의 표준이 되었고, 이후 구조를 새로 설계한 Wayland가 차세대 방식으로 등장했습니다.

---

**문제 3.** 다음 중 X 윈도 시스템에 대한 설명으로 알맞지 **않은** 것은?

A) 네트워크를 통해 원격 프로그램의 화면을 표시할 수 있다  
B) 1984년 MIT에서 개발이 시작되었다  
C) 창의 모양이나 조작 방식을 강제하지 않는다  
D) 리눅스 커널에 포함되어 있어 제거할 수 없다  

**정답: D**  
해설: X 윈도는 커널의 일부가 아니라 별도의 응용 프로그램이므로 설치하지 않거나 제거할 수 있으며, 서버 용도의 시스템은 흔히 X 없이 운영합니다. 네트워크 기반 동작과 정책을 강제하지 않는 설계는 X 윈도의 대표적인 특징입니다.

---

**문제 4.** 다음 중 X를 대체하기 위해 설계된 차세대 디스플레이 서버 프로토콜로 알맞은 것은?

A) XFree86  
B) Wayland  
C) X11  
D) XCB  

**정답: B**  
해설: Wayland는 기존 X의 복잡한 구조를 걷어내고 새로 설계한 디스플레이 서버 프로토콜입니다. X의 새 버전이 아니라 대체품이며 기존 X 응용 프로그램은 XWayland라는 호환 계층을 통해 실행합니다. X11은 현재까지 쓰이는 X 윈도의 버전 번호입니다.

---

**문제 5.** 다음 중 원격 컴퓨터에서 실행한 프로그램의 화면을 로컬 컴퓨터와 동일한 방식으로 표시할 수 있는 X 윈도의 특성으로 알맞은 것은?

A) 플랫폼 독립성  
B) 모듈 독립성  
C) 네트워크 투명성  
D) 하드웨어 가속  

**정답: C**  
해설: 네트워크 투명성은 프로그램이 로컬에 있든 원격에 있든 동일한 프로토콜로 화면에 표시되는 X 윈도의 특성입니다. 이 덕분에 서버에서 실행한 그래픽 프로그램의 창을 사용자의 컴퓨터 화면에 띄울 수 있습니다.
