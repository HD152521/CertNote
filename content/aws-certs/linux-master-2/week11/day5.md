# Day 5 - 종합 모의 2: 리눅스 활용과 최종 정리

## 📌 핵심 정리

- 2차 시험은 **운영 및 관리 + 리눅스 활용** 두 과목이다. 오늘은 그중 **리눅스 활용** — **X 윈도 · 인터넷 활용 · 응용분야** 세 항목을 점검한다.
- 비중이 크게 다르다 — **인터넷 활용이 절반을 훌쩍 넘고**, X 윈도가 그다음, 응용분야는 몇 문항이다.
- 2차는 **원리보다 이름과 값**을 묻는다. **제품명·프로토콜·포트·레코드**가 핵심이다.
- 마지막까지 남겨야 할 것은 **포트 번호 · 서브넷 계산 · 계층 분류표** 셋이다.
- 아래 10문항으로 리눅스 활용 전 범위를 마무리한다.

## 2차 시험에서 오늘 범위의 자리

| 과목 | 이 트랙의 주차 | 점검한 날 |
|------|-------------|---------|
| 리눅스 운영 및 관리 | W4~W7 | 어제 (Day 4) |
| **리눅스 활용** | **W8~W11** | **오늘** |

- 2차는 **80문항 · 100분**, 합격선은 60점이고 **과목당 40% 미만이면 과락**이다. 활용만 잘해도, 운영 및 관리만 잘해도 합격하지 못한다.
- 한 기출 회차를 세어 보면 80문항 가운데 **리눅스 활용이 32문항**이고, 그 안에서 **X 윈도 8 · 인터넷 활용 20 · 응용분야 4** 로 나뉘었다. 회차마다 조금씩 다르겠지만 **인터넷 활용(W9·W10)에 가장 많은 시간을 써야 한다**는 방향은 분명하다.
- 응용분야는 문항 수가 적은 대신 **범위가 좁다.** 클러스터 3종, 가상화 제품, 리눅스 커널 기반 OS 세 덩어리만 확실히 하면 된다.

## 한 번의 접속에 세 주차가 겹친다

**원격 서버의 그래픽 프로그램을 내 화면에 띄우는** 장면 하나에 X 윈도(W8)·네트워크(W9)·인터넷 서비스(W10)가 모두 들어 있다.

```bash
ssh -X alice@www.example.com         # 내 PC 에서 실행
echo $DISPLAY                        # 여기부터는 원격 서버의 셸
# localhost:10.0
gedit &                              # 서버의 프로그램인데 창은 내 화면에 뜬다
```

```text
   내 PC (화면 앞에 앉은 쪽)                       원격 서버 www.example.com

   ① 이름을 IP 로        /etc/hosts → DNS(53)
   ② SSH 클라이언트  ──── TCP 22번, 암호화 ────►   SSH 서버 (sshd)
   ③ X 서버          ◄─── 터널 안으로 그리기 요청 ──  gedit (X 클라이언트)
      화면·키보드·마우스
```

| 단계 | 일어나는 일 | 단원 |
|------|----------|------|
| ① | 이름을 `/etc/hosts`에서 찾고, 없으면 `/etc/resolv.conf`의 DNS 서버에 묻는다 | W9·W10 |
| ② | **22번 포트**로 TCP 연결을 맺고 그 위에서 암호화된 SSH 세션이 열린다 | W9·W10 |
| ③ | 서버에서 실행한 프로그램이 **내 PC의 X 서버**에 "창을 그려 달라"고 요청한다 | W8 |

- **한 접속 안에서 서버·클라이언트가 엇갈린다.** SSH로 보면 원격이 서버지만, X로 보면 **화면을 가진 내 PC가 서버**다. 8주차의 "웹과 반대"가 바로 이 장면이다.
- `DISPLAY`가 `localhost:10.0` 인 것은 SSH가 **자동으로 설정**해 준 값이다. 형식은 그대로 **호스트:디스플레이.스크린**이고, 서버 안에 SSH가 만들어 둔 중계용 화면 번호를 가리킨다(보통 10번부터 쓴다). 여기로 보낸 그리기 요청이 암호화된 터널을 타고 내 PC의 진짜 화면 `:0` 에 도착한다.
- 같은 일을 `xhost +` 와 `export DISPLAY=내PC주소:0.0` 으로도 할 수 있지만, **암호화되지 않고 누구에게나 화면을 여는** 방법이다. 시험은 이 대비를 묻는다.
- ②가 TELNET(23번)이었다면 비밀번호까지 평문으로 흐른다. **원격 접속은 SSH, 원격 GUI는 `ssh -X`** 로 짝지어 둔다.

## 누가 서버이고 누가 클라이언트인가

주차마다 한 번씩 나온 "방향" 문제를 한 표로 모으면 같은 유형임이 보인다.

| 장면 | 서버 쪽 (내주는 쪽) | 클라이언트 쪽 (쓰는 쪽) | 걸리는 지점 |
|------|-----------------|-------------------|-----------|
| X 윈도 | **화면·입력장치를 가진 컴퓨터** | 창을 띄우려는 프로그램 | 원격 서버가 X 서버라고 착각한다 |
| SSH 설정 파일 | `/etc/ssh/sshd_config` | `/etc/ssh/ssh_config` | `d`(데몬)가 있는 쪽이 서버 |
| DNS | `/etc/named.conf` — **답하는** 쪽 | `/etc/resolv.conf` — **묻는** 쪽 | DNS 서버 주소를 `hosts`에 적는다고 착각한다 |
| FTP 데이터 연결 | **능동** 모드: 서버가 건다 | **수동** 모드: 클라이언트가 건다 | 이름은 서버 입장에서 붙였다 |
| 메일 | MTA끼리 **SMTP** | MUA가 **POP3·IMAP**으로 받아 온다 | 보낼 때는 사용자도 SMTP다 |
| NFS | `/etc/exports`, `exportfs` | `mount -t nfs`, `showmount -e` | 설정 파일은 내주는 쪽에만 있다 |
| 가상화 | 호스트 | 게스트 | 전가상화의 게스트는 자신이 게스트인 줄 모른다 |

## 머리글자가 같은 이름 갈라 놓기

리눅스 활용은 **이름을 칸에 넣는 시험**이다. 주차별로는 구분되던 이름이 한 시험지에서는 머리글자끼리 뭉쳐 보인다.

| 머리 | 이름 → 들어갈 칸 |
|------|---------------|
| **X** | X11(X 윈도 버전) · X.org(X 서버 구현) · Xlib·XCB(저수준 라이브러리) · XDM(디스플레이 매니저) · Xfce(데스크톱 환경) · Xfwm(윈도 매니저) / **X.25**(패킷 교환 WAN 규격) / **Xen**(하이퍼바이저) |
| **K** | KDE(데스크톱 환경) · KWin(윈도 매니저) · KDM(옛 디스플레이 매니저) / **KVM**(하이퍼바이저) |
| **G** | GNOME(데스크톱 환경) · GTK+(툴킷) · GDM(디스플레이 매니저) / **Gopher**(메뉴 방식 정보 검색) |
| **L** | LXDE(데스크톱 환경) · LightDM·LXDM(디스플레이 매니저) / LDAP(계정 정보) / **LVS**(부하분산) |
| **M** | Mutter·Metacity(윈도 매니저) · Motif(툴킷) / MUA·MTA·MDA(메일 구성) · MX(DNS 레코드) · MIME(메일 규격) / MapReduce(하둡 처리) |
| **N** | NFS(파일 공유) · NNTP(뉴스그룹) · NTP(시간 맞추기) · NetBIOS(삼바 구성) · NS(DNS 레코드) |
| **S** | SMTP(메일 보내기) · SMB(삼바 프로토콜) · SNMP(망 관리) · SSH(원격 접속) · SOA(DNS 레코드) / SDDM(디스플레이 매니저) / SaaS(클라우드 모델) |
| **F** | FTP(파일 전송) / FDDI(광케이블 이중 링) · Frame Relay(WAN) / FLTK(툴킷) |
| **C** | CSMA/CD(유선 매체 접근) / CIFS(삼바) · CNAME(DNS 별칭) / CDE(데스크톱 환경) |
| **H** | HTTP(웹) / HPC(고계산용) · HA(고가용성) · HDFS(하둡 저장) |
| **V** | VDI·VMDK·VHD(가상 디스크 형식) — 차례로 VirtualBox·VMware·마이크로소프트 |

- 특히 **X로 시작한다고 모두 X 윈도 것이 아니다.** X.25는 통신 규격, Xen은 가상화다.
- **K 세 개(KDE·KWin·KDM)와 KVM**, **G 세 개(GNOME·GTK+·GDM)와 Gopher**처럼 "세 개는 한 집안, 하나는 남"인 묶음이 보기 넷으로 그대로 나온다.

이 과목에서 가장 흔한 문항 꼴이다. **셋의 공통점을 먼저 말할 수 있어야** 남는 하나가 보인다. 가운데 칸을 가리고 풀어 본다.

| 보기 넷 | 다른 하나 | 나머지 셋의 공통점 |
|--------|---------|---------------|
| KWin · Xfce · Windowmaker · Afterstep | **Xfce** | 윈도 매니저 (Xfce는 데스크톱 환경) |
| GDM · SDDM · LightDM · KWin | **KWin** | 디스플레이 매니저 |
| GTK+ · Qt · FLTK · XCB | **XCB** | 툴킷 (XCB는 저수준 라이브러리) |
| HTTP · FTP · SMTP · TCP | **TCP** | 응용 계층 프로토콜 (TCP는 전송 계층) |
| X.25 · Frame Relay · ATM · CSMA/CD | **CSMA/CD** | WAN 전송 기술 (CSMA/CD는 매체 접근 방식) |
| 10.1.1.1 · 172.20.1.1 · 192.168.1.1 · 172.32.1.1 | **172.32.1.1** | 사설 IP (172는 16~31만) |

| SMB · CIFS · NetBIOS · RPC | **RPC** | 삼바의 구성 요소 (RPC는 NFS 쪽) |
| A · AAAA · MX · IMAP | **IMAP** | DNS 레코드 |
| Xen · KVM · ESXi · VirtualBox | **VirtualBox** | Type 1 하이퍼바이저 |
| 안드로이드 · Tizen · webOS · iOS | **iOS** | 리눅스 커널 기반 운영체제 |
| 고계산용 · 고가용성 · 부하분산 · 임베디드 | **임베디드** | 클러스터의 종류 |

## 서브넷 — 거꾸로 묻는 꼴

"마스크를 주고 호스트 수"를 묻는 것이 기본형이라면, **"호스트 수를 주고 마스크"** 를 묻는 것이 뒤집은 꼴이다. 외워 둔 **254 · 126 · 62 · 30 · 14 · 6 · 2** 줄에서 **필요한 수 이상인 것 중 가장 작은 칸**을 고른다.

| 필요한 호스트 | 고르는 마스크 | 블록 | 그 칸의 호스트 수 | 판단 |
|------------|------------|------|---------------|------|
| 100대 | 255.255.255.128 (/25) | 128 | 126 | 다음 칸 62로는 모자란다 |
| 50대 | 255.255.255.192 (/26) | 64 | 62 | 다음 칸 30으로는 모자란다 |
| 30대 | 255.255.255.224 (/27) | 32 | 30 | 딱 맞는다 |
| **31대** | 255.255.255.192 (/26) | 64 | 62 | 30으로는 **한 대** 모자라 한 칸 위로 |
| 10대 | 255.255.255.240 (/28) | 16 | 14 | 다음 칸 6으로는 모자란다 |
| 2대 | 255.255.255.252 (/30) | 4 | 2 | 장비 둘을 잇는 구간 |

- 함정은 넷째 줄이다. **블록 크기 32를 보고 "32대까지"라고 읽으면 틀린다.** 네트워크·브로드캐스트 주소 2개를 뺀 30이 한계다.
- 서브넷 **개수**를 물으면 `256 ÷ 블록`이다. /26이면 256 ÷ 64 = 4개, /27이면 8개다. 호스트 수와 서브넷 개수는 **한쪽이 늘면 다른 쪽이 준다.**

## 옳고 그름 가리기

| 문장 | 판정 | 이유 |
|------|------|------|
| `ssh -X`로 접속했을 때 X 서버는 원격 서버에서 동작한다 | ✗ | 화면을 가진 **내 PC**가 X 서버 |
| KDE의 툴킷은 Qt이고 지금의 디스플레이 매니저는 SDDM이다 | ○ | KDM은 예전 것 |
| Wayland는 X11의 다음 버전이다 | ✗ | 버전이 아니라 **대체 프로토콜** |
| 스위치는 IP 주소를 보고 경로를 정한다 | ✗ | 스위치는 2계층, **MAC**. IP는 라우터 |
| 172.20.1.1은 사설 IP다 | ○ | 172.16~172.31 범위 안 |
| 255.255.255.224인 서브넷 하나에 호스트 32대를 둘 수 있다 | ✗ | 32 − 2 = **30대** |
| 사용자가 메일을 보낼 때도, 서버끼리 넘길 때도 SMTP를 쓴다 | ○ | POP3·IMAP은 받아 올 때만 |
| IMAP은 메일을 서버에 남겨 여러 기기에서 볼 수 있다 | ○ | 내려받고 지우는 쪽은 POP3 |
| PTR 레코드는 IP 주소에서 이름을 찾는 데 쓴다 | ○ | 역방향 조회 |
| DNS 서버의 주소는 `/etc/hosts`에 적는다 | ✗ | `/etc/resolv.conf` |
| FTP의 제어 연결은 20번 포트를 쓴다 | ✗ | **21이 제어**, 20은 능동 모드의 데이터 |
| 삼바는 RPC를 바탕으로 유닉스끼리 파일을 공유한다 | ✗ | 그건 NFS. 삼바는 SMB/CIFS로 윈도와 |
| 하트비트는 부하분산 클러스터가 요청을 나누는 방식이다 | ✗ | **고가용성**에서 생존을 확인하는 신호 |
| KVM은 운영체제 위에 설치하는 Type 2 하이퍼바이저다 | ✗ | 커널이 하이퍼바이저가 되는 **Type 1** |
| VirtualBox는 마이크로소프트의 VHD 이미지를 읽을 수 있다 | ○ | VMDK도 지원한다 |
| 안드로이드와 iOS는 모두 리눅스 커널 기반이다 | ✗ | iOS는 Darwin |

## 📝 연습 문제

**문제 1.** 다음 중 X 윈도에서 GTK+ 툴킷을 사용하는 데스크톱 환경으로 알맞은 것은?

A) KDE  
B) GNOME  
C) LXQt  
D) CDE  

**정답: B**  
해설: GNOME은 C 언어로 작성된 GTK+ 툴킷을 기반으로 하며 Xfce와 MATE도 같은 툴킷을 사용합니다. KDE와 LXQt는 C++로 작성된 Qt를, CDE는 전통적인 Motif 툴킷을 사용합니다.

---

**문제 2.** 다음 중 성격이 나머지 셋과 다른 것으로 알맞은 것은?

A) GDM  
B) SDDM  
C) LightDM  
D) Mutter  

**정답: D**  
해설: GDM, SDDM, LightDM은 모두 그래픽 로그인 화면을 제공하는 디스플레이 매니저이며 이름이 DM으로 끝납니다. Mutter는 GNOME에서 창의 테두리와 이동을 담당하는 윈도 매니저이므로 역할이 다릅니다.

---

**문제 3.** 다음 중 OSI 7계층에서 포트 번호를 사용해 종단 간 통신을 담당하는 계층으로 알맞은 것은?

A) 전송 계층  
B) 네트워크 계층  
C) 세션 계층  
D) 표현 계층  

**정답: A**  
해설: 4계층인 전송 계층은 포트 번호로 애플리케이션을 구분하며 TCP와 UDP가 여기에 속합니다. 3계층인 네트워크 계층은 IP 주소로 경로를 정하고, 2계층은 MAC 주소를 사용합니다.

---

**문제 4.** C 클래스 네트워크에서 서브넷마스크가 255.255.255.240일 때 하나의 서브넷에서 사용할 수 있는 호스트 개수로 알맞은 것은?

A) 16  
B) 30  
C) 14  
D) 62  

**정답: C**  
해설: 256에서 240을 빼면 블록 크기가 16이고, 여기서 네트워크 주소와 브로드캐스트 주소 두 개를 제외하면 14개가 남습니다. 마스크가 224일 때는 30개, 192일 때는 62개가 됩니다.

---

**문제 5.** 다음 중 사용자가 작성한 메일을 자신의 메일 서버로 보내고 그 서버가 상대 서버로 전달할 때 공통으로 사용하는 프로토콜로 알맞은 것은?

A) IMAP  
B) POP3  
C) NNTP  
D) SMTP  

**정답: D**  
해설: SMTP는 사용자가 메일을 발송할 때와 메일 서버끼리 메일을 전달할 때 모두 사용됩니다. POP3와 IMAP은 도착한 메일을 사용자가 가져오거나 열람할 때만 쓰이며, NNTP는 뉴스그룹용 프로토콜입니다.

---

**문제 6.** 다음 중 도메인 이름을 IPv6 주소와 연결하는 DNS 레코드로 알맞은 것은?

A) AAAA  
B) A  
C) MX  
D) SOA  

**정답: A**  
해설: 128비트인 IPv6 주소는 AAAA 레코드로 연결하며 32비트인 IPv4 주소는 A 레코드를 사용합니다. MX는 메일 서버를, SOA는 영역의 관리자와 갱신 주기 같은 기본 정보를 담습니다.

---

**문제 7.** 다음 중 FTP에서 클라이언트가 데이터 연결을 직접 여는 방식으로 방화벽 환경에서 주로 사용되는 모드로 알맞은 것은?

A) 능동 모드  
B) 수동 모드  
C) 바이너리 모드  
D) 익명 모드  

**정답: B**  
해설: 수동 모드는 클라이언트가 데이터 연결까지 직접 열기 때문에 클라이언트 쪽 방화벽에 막히지 않습니다. 능동 모드는 서버가 20번 포트에서 클라이언트로 연결을 시도하므로 방화벽 뒤에 있는 환경에서는 실패하기 쉽습니다.

**문제 8.** 다음 중 삼바 서버의 동작을 설정하는 파일로 알맞은 것은?

A) /etc/exports  
B) /etc/resolv.conf  
C) /etc/samba/smb.conf  
D) /etc/cups/cupsd.conf  

**정답: C**  
해설: 삼바는 `/etc/samba/smb.conf`에 공유할 디렉터리와 접근 권한을 설정하며 `smbd`와 `nmbd` 두 데몬이 동작합니다. `/etc/exports`는 NFS, `/etc/resolv.conf`는 DNS 서버 주소, `cupsd.conf`는 인쇄 시스템의 설정 파일입니다.

**문제 9.** 다음 중 하나의 큰 연산을 여러 노드가 나누어 처리하도록 구성한 클러스터로 알맞은 것은?

A) 부하분산 클러스터  
B) 고계산용 클러스터  
C) 고가용성 클러스터  
D) 하이브리드 클러스터  

**정답: B**  
해설: 고계산용 클러스터는 기상 예측이나 유전자 분석처럼 큰 연산을 여러 노드가 병렬로 나누어 처리합니다. 부하분산은 요청을 나누어 받는 것이고 고가용성은 장애가 나도 서비스가 끊기지 않게 하는 구성이라 목적이 다릅니다.

**문제 10.** 다음 중 게스트 운영체제를 수정하지 않고도 가상 머신에서 실행할 수 있게 하는 가상화 방식으로 알맞은 것은?

A) 반가상화  
B) 컨테이너 방식  
C) 에뮬레이션  
D) 전가상화  

**정답: D**  
해설: 전가상화는 하이퍼바이저가 하드웨어를 그대로 흉내 내므로 게스트 운영체제를 고칠 필요가 없으며 Intel VT-x와 AMD-V 같은 하드웨어 지원으로 성능도 확보합니다. 반가상화는 게스트 커널을 수정해야 하는 대신 성능이 좋습니다.
