# Day 4 - 종합 모의 1: 리눅스 일반 + 운영 및 관리

## 📌 핵심 정리

- 실제 시험은 **1차가 리눅스 일반(50문항)**, **2차가 리눅스 운영 및 관리 + 리눅스 활용(80문항)** 이다.
- 오늘은 그중 **W1~W7** — 리눅스 일반(W1~W3)과 운영 및 관리(W4~W7)를 한 묶음으로 점검한다. 리눅스 활용은 내일이다.
- 가장 많이 나오는 축은 넷이다 — **권한(8진수·umask·특수권한) · 명령어 옵션 · 프로세스 · 패키지 계열**.
- **값을 그대로 묻는 문제**가 절반이다. 숫자와 파일 경로를 외우면 점수가 붙는다.
- 아래 10문항으로 이 범위를 한 번 훑는다.

## 시험 구조와 오늘의 범위

| 구분 | 1차 | 2차 |
|------|-----|-----|
| 과목 | **리눅스 일반** | **리눅스 운영 및 관리 + 리눅스 활용** |
| 이 트랙의 주차 | W1~W3 | W4~W7 + W8~W11 |
| 문항 · 시간 | 50문항 · 60분 | 80문항 · 100분 |
| 형식 | 온라인 시험, 사지선다 | 필기, 사지선다 |
| 합격 기준 | 60점 이상 | 60점 이상, **과목당 40% 미만이면 과락** |

- 오늘 범위의 뒤쪽 절반(W4~W7)은 실제 시험에서 **2차의 첫 과목**이다.
- 2차는 과목이 둘이라 **한쪽만 잘해서는 합격하지 못한다.** 운영 및 관리(오늘)와 활용(내일) 중 어느 한 과목이 40%에 못 미치면 평균이 60점을 넘어도 불합격이다.
- 시간은 두 시험 모두 **문항당 1분 남짓**이다. 계산이 필요한 권한·umask 문제에 시간을 쓰려면 값을 묻는 문제를 빨리 넘겨야 한다.

## 같은 숫자, 다른 뜻

주차별로 외울 때는 헷갈리지 않던 숫자가 **한 시험지에 모이면** 섞인다. 숫자 쪽에서 거꾸로 정리해 둔다.

| 숫자 | 권한 (W4) | 에디터·프로세스 (W6) | 설치·부팅 (W2) | 계정·셸 (W3·W5) |
|-----|---------|-----------------|---------------|---------------|
| **0** | 권한 없음 `---` | nice 기본값 | 종료 | root의 UID · 표준 입력 · `$?` 성공 |
| **1** | `x` · Sticky | **PID 1**(systemd) · SIGHUP | 단일 사용자(복구) | 표준 출력 |
| **2** | `w` · SetGID | SIGINT(`Ctrl+C`) | — | 표준 에러 |
| **3** | `-wx` | vi의 모드 수 | **텍스트** | — |
| **4** | `r` · SetUID | — | MBR 주 파티션 최대 개수 | `/etc/group` 필드 수 |
| **5** | `r-x` | **crontab 시각 필드 수** | **그래픽** · 논리 파티션 시작 번호 | — |
| **6** | `rw-` | — | 재시작 · `/etc/fstab` 필드 수 | — |
| **7** | `rwx` | crontab 요일의 일요일(0과 같다) | — | **`/etc/passwd` 필드 수** |
| **9** | — | **SIGKILL** | — | `/etc/shadow` 필드 수 |
| **15** | — | **SIGTERM**(`kill` 기본) | — | — |

- 가장 자주 엇갈리는 짝은 **5(crontab)와 7(passwd)**, **6(fstab·재시작)과 0(종료)**, **9(강제)와 15(기본)** 다.
- **1이 붙은 것**을 한 번에 떠올려 본다 — PID 1, 시그널 1(HUP), 런레벨 1(복구), FD 1(표준 출력), 권한 1(`x`), 특수 권한 1(Sticky). 문제는 이 가운데 하나만 묻지만 보기에는 나머지가 오답으로 깔린다.

## 같은 옵션 글자, 다른 뜻

3주차에 한 번 모았던 표를 **W4~W7 명령까지 넓힌** 것이다. 글자만 외우면 틀리고 **명령과 함께** 외워야 한다.

| 글자 | 명령마다의 뜻 |
|------|------------|
| **`-r`** | `cp -r`·`rm -r` 하위까지 / `ls -r` 역순 / `userdel -r` 홈까지 삭제 / `dpkg -r` 패키지 삭제 / **`crontab -r` 전부 삭제** / `uname -r` 커널 버전 |
| **`-l`** | `ls -l` 자세히 / `wc -l` 줄 수 / `fdisk -l`·`crontab -l`·`kill -l`·`dpkg -l` **목록** / `usermod -l` 이름 변경 |
| **`-i`** | `cp -i` 덮어쓰기 전 확인 / `grep -i` 대소문자 무시 / `rpm -i`·`dpkg -i` **설치** / `df -i`·`ls -i` inode |
| **`-e`** | `ps -e` 전체 프로세스 / `rpm -e` **삭제** / `crontab -e` **편집** |
| **`-f`** | `rm -f` 강제 / `tail -f` 따라가기 / `ps -f` 자세히 / `tar -f` 파일 이름 지정 |
| **`-a`** | `ls -a` 숨김 포함 / `uname -a` 전부 / `mount -a` fstab 전부 / `usermod -aG` 추가 |
| **`-u`** | `useradd -u` UID 지정 / `crontab -u`·`top -u` 사용자 지정 |
| **`-U`** | `rpm -U` 업그레이드 (대문자) |
| **`-p`** | `mkdir -p` 중간 경로까지 / `cp -p` 속성 보존 / `renice -p`·`top -p` PID 지정 |
| **`-h`** | `df -h`·`du -h` 읽기 쉬운 단위 / `rpm -ivh`의 `h`는 진행 표시(`#`) |

- **지우는 옵션이 명령마다 다르다** — `rpm -e`, `dpkg -r`(설정까지는 `-P`), `crontab -r`, `userdel`, `atrm`. "삭제"라는 한 단어에 다섯 가지 표기가 대응한다.
- **목록은 대체로 `-l`** 이다. 예외가 `rpm -qa`(설치된 패키지 전부)와 `atq` 다.

## 지금만인가, 다음에도인가

"명령을 쳤는데 재부팅하니(또는 다시 로그인하니) 사라졌다"는 지문은 주차를 가리지 않고 같은 구조다. **명령은 지금만, 파일에 적어야 다음에도** 유지된다.

| 지금만 (명령) | 다음에도 (파일) | 주차 |
|-------------|--------------|------|
| `mount /dev/sdb1 /data` | `/etc/fstab` 에 한 줄 | W2·W4 |
| `systemctl isolate multi-user.target` | `systemctl set-default multi-user.target` | W2 |
| `init 3` | `/etc/inittab` | W2 |
| `umask 027` | `~/.bashrc` (전체 사용자는 `/etc/profile`) | W4 |
| `export EDITOR=vi` | `~/.bash_profile` | W5 |
| `alias ll='ls -l'` | `~/.bashrc` | W5 |
| vi 안에서 `:set nu` | `~/.vimrc` | W6 |
| `at 22:00` (한 번 실행하고 사라진다) | `crontab -e` (반복) | W6 |

- 반대 방향의 함정도 있다. **파일을 고쳤는데 지금 반영이 안 된다** — 설정 파일은 읽히는 시점이 정해져 있기 때문이다. 셸 설정은 `source` 로, `/etc/fstab`은 `mount -a` 로 다시 읽히고, `/etc/default/grub`은 `grub2-mkconfig` 로 `grub.cfg` 를 다시 만들어야 한다. `crontab -e` 로 고친 예약만은 저장하는 즉시 반영된다.

## 누가 할 수 있나

| 하려는 일 | 일반 사용자 | root |
|---------|----------|------|
| 자기 파일의 권한 변경 (`chmod`) | O | O |
| 파일의 소유자 변경 (`chown`) | **X** | O |
| 자기 비밀번호 변경 (`passwd`) | O | 남의 것도 가능 |
| 계정 생성·삭제 (`useradd`·`userdel`) | X | O |
| `/etc/passwd` 읽기 | O | O |
| `/etc/shadow` 읽기 | **X** | O |
| 자기 프로세스에 시그널 (`kill`) | O | 모든 프로세스 |
| nice 값 올리기 (양보) | O | O |
| nice 값 내리기 (음수 지정) | **X** | O |
| 남의 crontab 보기 (`crontab -u`) | X | O |

- 일반 사용자가 root만 쓸 수 있는 `/etc/shadow`를 고치며 자기 비밀번호를 바꿀 수 있는 이유가 4주차의 **SetUID** 다. `/usr/bin/passwd` 가 `4755` 라서 실행하는 동안만 소유자(root)의 권한을 빌린다. 권한·계정·특수 권한 세 단원이 한 문제에 겹치는 대표 사례다.

## 한 장면에 여러 주차 엮기

시험 문항은 주차별로 나오지만 실제 작업은 주차를 넘나든다. 협업 디렉터리를 하나 만드는 과정을 따라가며 **각 줄이 어느 단원인지** 짚어 본다.

```bash
groupadd -g 1500 dev                 # W3  그룹 생성 → /etc/group 에 한 줄
useradd -m -u 1001 -G dev alice      # W3  계정 생성 → /etc/passwd, 홈 디렉터리
passwd alice                         # W3  비밀번호 → /etc/shadow
id alice
# uid=1001(alice) gid=1001(alice) groups=1001(alice),1500(dev)

mkdir /project                       # W3
chgrp dev /project                   # W4  소유 그룹을 dev 로
chmod 2770 /project                  # W4  SetGID(2) + rwxrwx---
ls -ld /project
# drwxrws--- 2 root dev 4096 Oct 14 10:00 /project

su - alice                           # W3·W5  로그인 셸로 전환
umask 027                            # W4
touch /project/plan.txt
ls -l /project/plan.txt
# -rw-r----- 1 alice dev 0 Oct 14 10:05 /project/plan.txt
```

| 출력에서 읽을 것 | 이유 | 단원 |
|--------------|------|------|
| `groups=...,1500(dev)` | `-G`는 **보조** 그룹이다. 기본 그룹(`gid=`)은 계정과 같은 이름으로 따로 만들어진 alice (레드햇·데비안 계열의 기본 동작) | W3 |
| `drwxrws---` 의 `s` | 그룹 칸의 `x` 자리가 `s` → **SetGID** | W4 |
| `plan.txt`의 그룹이 `dev` | alice의 기본 그룹(alice)이 아니라 **디렉터리의 그룹을 물려받았다** | W4 |
| `plan.txt`의 권한 `640` | 파일 기준 666에서 umask 027을 뺐다 | W4 |
| `su -` 의 하이픈 | 하이픈이 있어야 alice의 `.bash_profile`까지 읽는 **로그인 셸**이 된다 | W5 |

여기에 프로세스와 패키지 단원이 이어 붙는다.

```bash
crontab -l                           # W6  root 의 예약 목록
# 0 3 * * 0 tar -czf /backup/project.tar.gz /project
```

- 시각 다섯 칸은 **분 0 · 시 3 · 일 `*` · 월 `*` · 요일 0** 이므로 "매주 일요일 3시 정각"이다 (W6).
- `tar -czf` 는 **`c` 묶기 · `z` gzip 압축 · `f` 파일 이름** 이다. `z`가 없으면 묶기만 하고 압축은 하지 않는다 (W7).
- cron이 돌리는 작업에는 화면이 없다. 결과와 에러를 파일로 남기려면 줄 끝에 `>> /var/log/backup.log 2>&1` 을 붙인다 (W5).

## 옳고 그름 가리기

여러 주차를 섞은 문장이다. 먼저 스스로 판정하고 오른쪽을 본다.

| 문장 | 판정 | 이유 |
|------|------|------|
| `/etc/passwd`의 일곱째 필드와 `chsh -s`가 바꾸는 값은 같은 것이다 | ○ | 둘 다 로그인 셸 |
| `ps -ef`에서 PPID가 1인 프로세스는 모두 좀비다 | ✗ | 부모가 systemd라는 뜻일 뿐이다. 좀비는 상태 `Z`로 본다 |
| `rpm -e`와 `crontab -e`의 `-e`는 같은 뜻이다 | ✗ | 삭제(erase)와 편집(edit) |
| `apt update`를 마치면 새 버전 패키지가 설치되어 있다 | ✗ | 목록만 갱신한다. 설치는 `apt upgrade` |
| 런레벨 5와 `graphical.target`은 같은 상태를 가리킨다 | ○ | 3은 `multi-user.target` |
| `kill 1234`와 `kill -15 1234`는 같은 명령이다 | ○ | 기본 시그널이 15 |
| `tar -cvf a.tar dir`로 만든 파일은 압축되어 있다 | ✗ | 묶기만 했다. 압축은 `-z`·`-j`·`-J` |
| `~/.bashrc`에 적은 별칭은 저장하자마자 지금 셸에서 쓸 수 있다 | ✗ | `source ~/.bashrc` 를 해야 한다 |
| MBR 디스크의 `/dev/sda5`는 논리 파티션이다 | ○ | 논리 파티션은 항상 5번부터 |
| `find / -name core 2> /dev/null`은 에러 메시지를 화면에서 없앤다 | ○ | 2번 통로를 버리는 곳으로 보냈다 |
| SUSE는 `.rpm`을 쓰므로 `yum`으로 관리한다 | ✗ | 형식은 RPM이지만 도구는 `zypper` |
| `chmod 4755`가 걸린 실행 파일은 실행한 사람의 권한으로 동작한다 | ✗ | **파일 소유자**의 권한으로 동작한다 |
| `df -i`와 `ls -i`의 `-i`는 둘 다 inode와 관련된다 | ○ | inode 사용량 / inode 번호 |
| umask 000에서 만든 파일의 권한은 777이다 | ✗ | 파일 기준값이 666이라 666 |

## 문항 유형별로 읽는 법

| 유형 | 지문의 표지 | 실수하는 지점 |
|------|----------|------------|
| 옳은 것 고르기 | "알맞은 것은" | 첫 보기가 그럴듯하면 끝까지 안 읽는다 |
| **틀린 것 고르기** | "알맞지 **않은**", "틀린", "거리가 먼" | 옳은 보기를 보자마자 답으로 찍는다 |
| 성격이 다른 것 | "나머지 셋과 다른" | 셋의 공통점을 먼저 찾아야 한다 (셸 계열, 패키지 계열, 에디터 종류) |
| 순서 | "순서로 알맞은" | 부팅 순서, `./configure → make → make install`, 새 디스크 `fdisk → mkfs → mount` |
| 계산 | 숫자 보기 넷 | 권한 8진수, umask (**파일 666·디렉터리 777**), crontab 읽기 |
| 짝짓기 | "바르게 짝지은" | `df - du`, 저수준 - 고수준 도구처럼 **순서가 뒤집힌 보기**가 섞인다 |

- "틀린 것"을 묻는 문항은 보기마다 **○·✗를 시험지에 적어 가며** 푼다. 넷 중 ✗가 하나만 남아야 한다.
- 모르는 이름이 나오면 **아는 셋을 지워서** 남기는 편이 빠르다. 명칭 분류 문제는 대부분 이 방법으로 풀린다.

## 시험 직전 점검

- [ ] `rwxr-x--x` 같은 표기를 보자마자 8진수로 바꿀 수 있다
- [ ] umask가 주어지면 **디렉터리 값부터** 구하고 파일 값으로 내려간다
- [ ] `/etc/passwd` 7필드의 **순서**(이름·x·UID·GID·설명·홈·셸)를 말할 수 있다
- [ ] 시그널 1·2·9·15를 **번호와 이름 양쪽**으로 안다
- [ ] crontab 한 줄을 보고 "언제 실행되는지" 풀어 읽을 수 있다
- [ ] RPM 계열과 DEB 계열의 **배포판 · 저수준 도구 · 고수준 도구**를 세 칸씩 채울 수 있다
- [ ] 로그인 셸과 비로그인 셸이 읽는 파일을 구분한다
- [ ] vi에서 저장하고 나가기, 저장 없이 나가기, 전체 치환을 입력할 수 있다
- [ ] 부팅 순서와 런레벨 0·1·3·5·6의 뜻을 말할 수 있다
- [ ] CUPS·ALSA·SANE이 각각 무엇을 맡는지 안다

## 📖 용어

- **umask** : 새 파일·디렉터리의 권한에서 깎아낼 값. 파일은 666, 디렉터리는 777이 기준이다.
- **특수 권한** : SetUID(4)·SetGID(2)·Sticky bit(1). 권한 네 자리 중 맨 앞자리다.
- **좀비 프로세스** : 종료되었으나 부모가 상태를 회수하지 않아 목록에 남은 프로세스.
- **환경 변수** : `export`로 승격되어 자식 프로세스까지 전달되는 변수.
- **저수준 패키지 도구** : `rpm`, `dpkg`처럼 의존성을 해결하지 않는 도구.
- **파일 디스크립터** : 입출력 통로에 붙은 번호. 0·1·2가 표준 입력·출력·에러다.

**문제 1.** 다음 중 리눅스 커널이 배포될 때 적용되는 라이선스로 알맞은 것은?

A) GPL  
B) MIT  
C) 아파치 라이선스

해설: 리눅스 커널은 GNU General Public License를 따르며, 소스를 수정해 배포할 때 같은 조건으로 소스를 공개해야 합니다. MIT와 BSD는 공개 의무가 약한 허용적 라이선스이고 아파치 라이선스는 특허 조항이 포함된 별도의 라이선스입니다.

**문제 2.** 다음 중 리눅스 부팅 과정에서 커널을 메모리에 올리는 역할을 하는 것으로 알맞은 것은?

A) BIOS  
B) init  
C) 부트로더  
D) 셸  

**정답: C**  
해설: 전원이 들어오면 BIOS 또는 UEFI가 하드웨어를 점검한 뒤 부트로더를 실행하고, GRUB 같은 부트로더가 커널을 메모리에 적재합니다. 이후 커널이 첫 프로세스인 init 또는 systemd를 실행해 나머지 서비스를 올립니다.

**문제 3.** 다음 중 `chmod 640 report.txt` 명령을 실행한 뒤의 권한 상태로 알맞은 것은?

A) 소유자는 읽기만, 그룹은 읽기와 쓰기가 가능하다  
B) 소유자는 읽기와 쓰기, 그룹은 읽기만 가능하며 기타 사용자는 접근할 수 없다  
C) 모든 사용자가 읽고 쓸 수 있다  
D) 소유자만 읽고 쓰고 실행할 수 있다  

**정답: B**  
해설: 640은 세 자리를 각각 읽으면 6(rw-), 4(r--), 0(---)입니다. 따라서 소유자는 읽기와 쓰기, 그룹은 읽기만 가능하고 기타 사용자에게는 아무 권한도 없습니다.

**문제 4.** umask 값이 002로 설정된 상태에서 새로 만들어지는 디렉터리의 권한으로 알맞은 것은?

A) 664  
B) 755  
C) 777  
D) 775  

**정답: D**  
해설: 디렉터리의 기준값 777에서 umask 002를 빼면 775가 됩니다. 그룹까지 쓰기를 허용하는 설정이라 여러 사용자가 함께 작업하는 환경에서 사용합니다. 같은 umask에서 파일은 666에서 002를 뺀 664가 됩니다.

**문제 5.** 다음 중 `find` 명령으로 `/home` 아래에서 크기가 100MB보다 큰 파일을 찾는 명령으로 알맞은 것은?

A) find /home -size +100M  
B) find -size +100M /home  
C) grep /home -size +100M  
D) find /home +100M  

**정답: A**  
해설: `find`는 검색을 시작할 경로를 먼저 쓰고 그 뒤에 조건을 지정합니다. 크기 조건은 `-size` 옵션으로 주며 `+`는 그보다 큰 것을 의미합니다. `grep`은 파일 내용을 찾는 명령이라 이 용도에 맞지 않습니다.

**문제 6.** 다음 중 디렉터리에 설정했을 때 그 안에 생성되는 파일이 디렉터리의 그룹을 물려받게 하는 특수 권한과 그 값으로 알맞은 것은?

A) SetUID, 4  
B) Sticky bit, 1  
C) SetGID, 2  
D) SetUID, 2  

**정답: C**  
해설: SetGID의 값은 2이며 디렉터리에 설정하면 그 안에서 새로 만들어지는 파일의 그룹이 생성자의 기본 그룹이 아니라 디렉터리의 그룹으로 지정됩니다. 여러 사용자가 함께 쓰는 협업 디렉터리에서 그룹을 일관되게 유지할 때 사용합니다.

**문제 7.** 다음 중 실행 중인 프로세스에 정상 종료를 요청했으나 응답이 없을 때 마지막으로 사용하는 명령으로 알맞은 것은?

A) kill -1 PID  
B) kill -2 PID  
C) kill -15 PID  
D) kill -9 PID  

**정답: D**  
해설: 9번 SIGKILL은 프로세스가 무시할 수 없어 커널이 즉시 제거합니다. 다만 마무리 작업을 할 기회가 없어 데이터가 손상될 수 있으므로 먼저 기본값인 15번 SIGTERM으로 정상 종료를 요청하고 응답이 없을 때만 사용합니다.

**문제 8.** 다음 중 vi 편집기에서 파일 전체를 대상으로 문자열을 치환하기 위해 지정하는 범위 기호로 알맞은 것은?

A) g  
B) %  
C) $  
D) &  

**정답: B**  
해설: `%`는 파일 전체를 대상 범위로 지정하는 기호이고 끝에 붙이는 `g`는 각 줄 안의 모든 일치를 바꾸도록 하는 옵션입니다. 둘을 함께 쓴 `:%s/A/B/g`가 문서 전체의 모든 문자열을 치환하는 형태입니다.

**문제 9.** 다음 중 데비안 계열에서 의존성까지 자동으로 처리하며 패키지를 설치하는 명령으로 알맞은 것은?

A) apt install  
B) dpkg -i  
C) rpm -ivh  
D) tar -zxvf  

**정답: A**  
해설: `apt`는 저장소를 이용하는 고수준 도구여서 필요한 의존 패키지까지 함께 내려받아 설치합니다. `dpkg -i`는 같은 데비안 계열이지만 저수준 도구라 의존성을 해결하지 못하고, `rpm`은 레드햇 계열, `tar`는 압축 해제 명령입니다.

**문제 10.** 다음 중 파일 시스템별 전체 용량과 사용률을 확인하는 명령과 특정 디렉터리의 사용량 합계를 확인하는 명령을 바르게 짝지은 것은?

A) du - df  
B) df - fsck  
C) df - du  
D) fsck - du  

**정답: C**  
해설: `df`는 마운트된 파일 시스템 단위로 전체·사용·잔여 용량을 보여 주고, `du`는 지정한 경로가 실제로 차지하는 용량을 계산하며 `-sh` 옵션으로 합계만 낼 수 있습니다. `fsck`는 파일 시스템의 무결성을 검사하는 명령입니다.
