# Day 2 - 가상화

## 📌 핵심 정리

- 가상화는 **한 대의 물리 컴퓨터에서 여러 운영체제를 동시에** 돌리는 기술이다.
- **전가상화는 게스트 OS를 고치지 않아도 되고**, **반가상화는 게스트 OS를 수정해야** 한다.
- 하이퍼바이저는 둘로 나뉜다 — **Type 1(하드웨어 위에 바로)** 과 **Type 2(운영체제 위에)**.
- **VirtualBox는 오라클의 Type 2 제품**이며 **GPL** 로 공개되어 있고 **전가상화**를 쓴다.
- **VirtualBox는 VMware의 VMDK와 마이크로소프트의 VHD 이미지를 지원**한다.

## 가상화란

```text
   [ 가상화 없이 ]              [ 가상화 ]

   ┌──────────┐               ┌────┐┌────┐┌────┐
   │  운영체제  │               │리눅스││윈도 ││리눅스│  게스트 OS
   ├──────────┤               ├────┴┴────┴┴────┤
   │  하드웨어  │               │   하이퍼바이저   │
   └──────────┘               ├────────────────┤
                              │    하드웨어      │
                              └────────────────┘
```

- **하이퍼바이저(hypervisor)** 가 하드웨어를 나눠 각 가상 머신에 배분한다.
- 물리 컴퓨터를 **호스트**, 그 위의 가상 컴퓨터를 **게스트**라 한다.

## 하이퍼바이저의 두 종류

| 구분 | **Type 1 (네이티브·베어메탈)** | **Type 2 (호스트형)** |
|------|---------------------------|---------------------|
| 위치 | **하드웨어 위에 바로** | **운영체제 위에** |
| 성능 | **좋다** | 상대적으로 낮다 |
| 용도 | **서버·데이터센터** | **개인 PC·테스트** |
| 예 | **Xen, KVM, VMware ESXi, Hyper-V** | **VirtualBox, VMware Workstation** |

- **Type 1은 그 자체가 운영체제 역할**을 한다. 그래서 빠르다.
- **Type 2는 이미 깔린 운영체제 위에 프로그램처럼 설치**한다. 설치가 간단해 개인용으로 쓴다.

## 전가상화와 반가상화

| 구분 | **전가상화 (Full)** | **반가상화 (Para)** |
|------|------------------|------------------|
| 게스트 OS 수정 | **필요 없다** | **필요하다** |
| 방식 | 하드웨어를 **그대로 흉내** | 게스트가 하이퍼바이저에 **직접 요청** |
| 성능 | 보통 (하드웨어 지원 시 개선) | **좋다** |
| 하드웨어 지원 | **Intel VT-x / AMD-V** 활용 | — |
| 대표 | **VirtualBox, VMware, KVM** | **Xen**(초기) |

> **가르는 기준은 "게스트 OS를 고쳐야 하는가"** 다. **전가상화는 수정 없이 그대로**, **반가상화는 수정이 필요**하다. 대신 반가상화가 더 빠르다.

- **Intel VT-x와 AMD-V**는 CPU가 가상화를 도와주는 기능이다. 이 덕분에 전가상화도 성능이 크게 좋아졌고, 지금은 전가상화가 주류다.
- Xen은 반가상화로 시작했지만 지금은 전가상화도 지원한다.

## 제품별 특징

| 제품 | 만든 곳 | 종류 | 특징 |
|------|--------|------|------|
| **VirtualBox** | **오라클** | **Type 2** | **GPL 공개**. 무료. **전가상화** |
| **VMware Workstation** | VMware | Type 2 | 상용. 개인용 |
| **VMware ESXi** | VMware | **Type 1** | 서버용 |
| **KVM** | 오픈소스 | **Type 1** | **리눅스 커널에 내장**됨 |
| **Xen** | 오픈소스 | **Type 1** | **반가상화의 대표** |
| **Hyper-V** | 마이크로소프트 | Type 1 | 윈도 서버용 |
| QEMU | 오픈소스 | 에뮬레이터 | 다른 CPU도 흉내 낸다. KVM과 함께 쓴다 |

### VirtualBox

시험에 **제품 스펙 그대로** 나오는 항목이다.

| 항목 | 내용 |
|------|------|
| 개발 | **오라클**(원래 이노테크 → 썬 → 오라클) |
| 라이선스 | **GPL** (기본 패키지) |
| 종류 | **Type 2 호스트형** |
| 가상화 방식 | **전가상화** (Intel VT-x / AMD-V 활용) |
| 기본 이미지 | **VDI** |
| **지원 이미지** | **VMDK(VMware)**, **VHD(마이크로소프트)**, HDD(Parallels) |

> ⚠️ **"VirtualBox는 반가상화를 지원한다"는 설명은 틀린 것**으로 출제된다. VirtualBox는 Intel VT-x·AMD-V를 이용한 **전가상화** 제품이다. 반면 **VMDK와 VHD 이미지를 지원한다는 설명은 맞다.**

### KVM

| 항목 | 내용 |
|------|------|
| 풀네임 | **Kernel-based Virtual Machine** |
| 특징 | **리눅스 커널 자체가 하이퍼바이저**가 된다 |
| 종류 | **Type 1** |
| 함께 쓰는 것 | **QEMU**(장치 흉내), libvirt·`virsh`(관리) |

- 별도 하이퍼바이저를 설치하는 것이 아니라 **커널 모듈을 올리면 리눅스가 곧 하이퍼바이저**가 된다. 이 점이 KVM의 정의다.

## 컨테이너 — 가상화와 다르다

| 구분 | **가상 머신** | **컨테이너** |
|------|------------|------------|
| 게스트 OS | **각각 따로** 있다 | **호스트 커널을 공유**한다 |
| 크기 | 무겁다(GB) | **가볍다(MB)** |
| 시작 속도 | 느리다 | **빠르다** |
| 격리 수준 | **강하다** | 상대적으로 약하다 |
| 예 | VirtualBox, KVM | **Docker**, LXC |

- **컨테이너는 운영체제를 따로 올리지 않는다.** 커널을 공유하고 프로세스만 격리한다. 그래서 가볍고 빠르다.
- **Docker는 가상 머신이 아니다.** 이 구분을 묻는 문제가 나온다.

> 내일은 임베디드 시스템과 기술 동향을 다룬다.

## 📖 용어

- **가상화** : 한 대의 물리 컴퓨터에서 여러 운영체제를 동시에 실행하는 기술.
- **하이퍼바이저** : 가상 머신에 하드웨어 자원을 나누어 주는 소프트웨어.
- **Type 1 / Type 2** : 하드웨어 위에서 바로 동작하는 방식 / 운영체제 위에 설치하는 방식.
- **전가상화** : 게스트 OS를 수정하지 않고 하드웨어를 흉내 내는 방식.
- **반가상화** : 게스트 OS를 수정해 하이퍼바이저에 직접 요청하는 방식.
- **VirtualBox** : 오라클의 Type 2 가상화 제품. GPL로 공개되어 있고 전가상화를 사용한다.
- **KVM** : 리눅스 커널 자체를 하이퍼바이저로 만드는 가상화 기술.
- **컨테이너** : 호스트 커널을 공유하며 프로세스만 격리하는 경량 방식. Docker가 대표적이다.

## 📝 연습 문제

**문제 1.** 다음 중 게스트 운영체제의 커널을 수정해야 하는 가상화 방식으로 알맞은 것은?

A) 전가상화  
B) 컨테이너  
C) 반가상화  
D) 에뮬레이션  

**정답: C**  
해설: 반가상화는 게스트 운영체제가 하이퍼바이저에 직접 요청을 보내도록 커널을 수정해야 하며 그 대신 성능이 좋습니다. 전가상화는 하드웨어를 그대로 흉내 내므로 게스트 운영체제를 수정할 필요가 없습니다.

---

**문제 2.** 다음 중 VirtualBox에 대한 설명으로 알맞지 **않은** 것은?

A) 인텔과 AMD 기반의 반가상화를 지원한다  
B) 기본 패키지가 GPL 라이선스로 공개되어 있다  
C) VMware의 VMDK 이미지 형식을 지원한다  
D) 마이크로소프트의 VHD 이미지 형식을 지원한다  

**정답: A**  
해설: VirtualBox는 Intel VT-x와 AMD-V 같은 하드웨어 지원 기능을 활용한 전가상화 제품이며 반가상화 방식을 사용하지 않습니다. 기본 패키지가 GPL로 공개되어 있고 자체 형식인 VDI 외에 VMDK와 VHD 이미지도 지원한다는 설명은 모두 맞습니다.

---

**문제 3.** 다음 중 하드웨어 위에서 직접 동작하는 Type 1 하이퍼바이저에 해당하는 것으로 알맞은 것은?

A) VirtualBox  
B) VMware Workstation  
C) Docker  
D) KVM  

**정답: D**  
해설: KVM은 리눅스 커널 자체가 하이퍼바이저 역할을 하므로 하드웨어 위에서 직접 동작하는 Type 1에 해당하며 Xen과 VMware ESXi도 같은 유형입니다. VirtualBox와 VMware Workstation은 운영체제 위에 설치하는 Type 2이고, Docker는 가상화가 아닌 컨테이너 기술입니다.

---

**문제 4.** 다음 중 KVM에 대한 설명으로 알맞은 것은?

A) 게스트 운영체제 없이 애플리케이션만 격리한다  
B) 리눅스 커널 자체가 하이퍼바이저 역할을 한다  
C) 마이크로소프트가 개발한 윈도 전용 가상화 기술이다  
D) 반가상화만 지원하며 게스트 커널 수정이 필수다  

**정답: B**  
해설: KVM은 Kernel-based Virtual Machine의 줄임말로 커널 모듈을 적재하면 리눅스 자체가 하이퍼바이저가 됩니다. 장치 흉내는 QEMU가 맡고 관리에는 libvirt와 `virsh`를 사용합니다. 애플리케이션만 격리하는 것은 컨테이너 방식입니다.

---

**문제 5.** 다음 중 컨테이너 기술의 특징으로 알맞은 것은?

A) 게스트 운영체제를 각각 따로 설치한다  
B) 가상 머신보다 이미지 크기가 크고 무겁다  
C) 호스트의 커널을 공유하므로 가볍고 시작이 빠르다  
D) 서로 다른 CPU 구조를 흉내 낼 수 있다  

**정답: C**  
해설: 컨테이너는 별도의 게스트 운영체제를 올리지 않고 호스트 커널을 공유하면서 프로세스만 격리하므로 크기가 작고 실행이 빠릅니다. 다른 CPU 구조를 흉내 내는 것은 QEMU 같은 에뮬레이터의 기능입니다.
