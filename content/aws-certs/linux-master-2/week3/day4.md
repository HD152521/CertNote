# Day 4 - 사용자와 계정 관리

## 📌 핵심 정리

- 계정 정보는 **`/etc/passwd`** 에, **비밀번호는 `/etc/shadow`** 에 따로 있다. 분리한 이유는 **보안**이다.
- `/etc/passwd`는 **콜론(`:`)으로 나뉜 7개 필드**다. UID·GID·홈 디렉터리·로그인 셸이 여기 들어간다.
- **UID 0은 root**다. 이름이 root가 아니어도 UID가 0이면 관리자 권한을 갖는다.
- 계정 명령 3종: **`useradd`(생성) · `usermod`(수정) · `userdel`(삭제)**.
- **`su`는 사용자 전환**, **`sudo`는 한 명령만 관리자로** 실행한다. `sudo` 설정은 `/etc/sudoers`에 있다.

## 계정 정보는 어디에 있나

| 파일 | 담는 것 | 권한 |
|------|--------|------|
| **`/etc/passwd`** | 계정 기본 정보 | 누구나 읽을 수 있다 |
| **`/etc/shadow`** | **암호화된 비밀번호**와 만료 정책 | **root만** 읽을 수 있다 |
| **`/etc/group`** | 그룹 정보 | 누구나 읽을 수 있다 |

> 왜 나눴나: `/etc/passwd`는 여러 프로그램이 사용자 이름·UID를 조회해야 해서 **누구나 읽을 수 있어야 한다.** 그런데 비밀번호까지 거기 있으면 누구나 해시를 가져가 크래킹할 수 있다. 그래서 비밀번호만 `/etc/shadow`로 떼어내 **root 전용**으로 막았다.

### /etc/passwd 한 줄 읽기

```text
   user:x:1000:1000:Test User:/home/user:/bin/bash
     │  │  │    │       │          │          │
     │  │  │    │       │          │          └── ⑦ 로그인 셸
     │  │  │    │       │          └───────────── ⑥ 홈 디렉터리
     │  │  │    │       └──────────────────────── ⑤ 설명(코멘트)
     │  │  │    └──────────────────────────────── ④ GID (기본 그룹)
     │  │  └───────────────────────────────────── ③ UID
     │  └──────────────────────────────────────── ② 비밀번호 자리 (x = shadow 에 있음)
     └─────────────────────────────────────────── ① 사용자 이름
```

- **필드는 7개, 구분자는 콜론(`:`)** — 이 두 가지가 자주 출제된다.
- 두 번째 필드의 **`x`** 는 "실제 비밀번호는 `/etc/shadow`에 있다"는 표시다.

### UID 규칙

| UID | 뜻 |
|-----|-----|
| **0** | **root** — 이름과 무관하게 관리자 권한 |
| 1~999 | 시스템 계정(데몬용) |
| **1000 이상** | 일반 사용자 (배포판에 따라 500부터인 경우도 있다) |

- **UID 0이 root**라는 점이 핵심이다. 계정 이름을 바꿔도 UID가 0이면 root다.
- 로그인시키지 않을 계정은 셸을 **`/sbin/nologin`** 이나 `/bin/false`로 지정한다.

## 계정 다루기

| 명령 | 하는 일 |
|------|--------|
| `useradd 이름` | 계정 생성 |
| `useradd -m 이름` | **홈 디렉터리까지** 생성 |
| `useradd -u 1500 -g dev 이름` | UID·기본 그룹 지정 |
| `passwd 이름` | 비밀번호 설정·변경 |
| `usermod -aG 그룹 이름` | **보조 그룹 추가** |
| `usermod -L` / `-U` | 계정 잠금 / 해제 |
| `userdel 이름` | 계정 삭제 (홈은 남는다) |
| `userdel -r 이름` | **홈 디렉터리까지** 삭제 |
| `id 이름` | UID·GID·소속 그룹 확인 |
| `who` / `w` | 현재 접속한 사용자 |

```bash
sudo useradd -m alice        # 홈 디렉터리와 함께 생성
sudo passwd alice            # 비밀번호 설정
id alice                     # uid=1001(alice) gid=1001(alice) ...
sudo usermod -aG wheel alice # wheel 그룹에 추가
sudo userdel -r alice        # 홈까지 삭제
```

> 함정 둘. ① **`useradd`는 홈 디렉터리를 자동으로 만들지 않는 경우가 있다** — `-m`이 그 역할이다(배포판 기본 설정에 따라 다르다). ② **`usermod -G`만 쓰면 기존 보조 그룹이 날아간다.** 추가하려면 반드시 **`-aG`** 를 쓴다.

## 그룹

| 구분 | 설명 |
|------|------|
| **기본 그룹(primary)** | `/etc/passwd`의 GID 필드. 파일을 만들면 이 그룹이 붙는다 |
| **보조 그룹(secondary)** | `/etc/group`에 이름이 올라간 그룹. 여러 개 가능 |

| 명령 | 하는 일 |
|------|--------|
| `groupadd 이름` | 그룹 생성 |
| `groupdel 이름` | 그룹 삭제 |
| `groups 사용자` | 소속 그룹 확인 |

## 권한을 잠깐 올리기 — su와 sudo

| 구분 | `su` | `sudo` |
|------|------|--------|
| 하는 일 | **사용자 자체를 전환** | **한 명령만** 다른 권한으로 실행 |
| 필요한 비밀번호 | **대상 계정의** 비밀번호 | **자기 자신의** 비밀번호 |
| 로그 | 남기 어렵다 | 누가 무엇을 했는지 **기록된다** |
| 설정 파일 | — | **`/etc/sudoers`** |

```bash
su          # root 로 전환 (환경변수는 그대로)
su -        # root 로 전환 + root 의 환경까지 로드
sudo 명령    # 그 명령 하나만 root 권한으로
```

- **`su -`의 하이픈**이 중요하다. 붙이면 대상 사용자로 **로그인한 것처럼** 환경 변수·작업 디렉터리까지 바뀐다.
- `sudo`가 권장되는 이유는 **최소 권한 원칙과 감사 추적** 때문이다. root 비밀번호를 여러 사람이 공유할 필요도 없다.
- `/etc/sudoers`는 **`visudo`로 편집**한다. 문법 오류를 검사해 주기 때문에, 직접 편집하다 망가뜨리면 sudo 자체를 못 쓰게 된다.

> 내일은 이번 주에 익힌 명령들을 한 장으로 묶어 정리한다.

## 📖 용어

- **`/etc/passwd`** : 사용자 계정의 기본 정보를 담은 파일. 콜론으로 구분된 7개 필드.
- **`/etc/shadow`** : 암호화된 비밀번호와 만료 정책을 담은 파일. root만 읽을 수 있다.
- **UID** : 사용자 식별 번호. 0은 root, 1000 이상이 일반 사용자다.
- **GID** : 그룹 식별 번호.
- **기본 그룹** : `/etc/passwd`에 기록된 그룹. 새로 만든 파일의 그룹이 된다.
- **보조 그룹** : 추가로 속한 그룹. `usermod -aG`로 더한다.
- **`su`** : 다른 사용자로 전환하는 명령. 대상 계정의 비밀번호가 필요하다.
- **`sudo`** : 지정한 명령 하나만 관리자 권한으로 실행하는 명령. 자기 비밀번호를 쓴다.
- **`visudo`** : `/etc/sudoers`를 문법 검사와 함께 안전하게 편집하는 명령.

## 📝 연습 문제

**문제 1.** 다음 중 `/etc/passwd` 파일의 필드 구분자와 필드 개수로 알맞은 것은?

A) 콜론(:), 7개  
B) 쉼표(,), 5개  
C) 탭, 6개  
D) 공백, 7개  

**정답: A**  
해설: `/etc/passwd`는 각 줄이 콜론으로 구분된 7개 필드로 이루어집니다. 순서대로 사용자 이름, 비밀번호 자리, UID, GID, 설명, 홈 디렉터리, 로그인 셸입니다. 두 번째 필드의 `x`는 실제 비밀번호가 `/etc/shadow`에 있음을 뜻합니다.

---

**문제 2.** 다음 중 root 계정을 나타내는 UID 값으로 알맞은 것은?

A) 1  
B) 100  
C) 1000  
D) 0  

**정답: D**  
해설: UID 0은 root, 즉 시스템의 모든 권한을 가진 관리자를 뜻합니다. 계정 이름이 root가 아니더라도 UID가 0이면 관리자 권한을 갖습니다. 1~999는 시스템 계정, 1000 이상(배포판에 따라 500 이상)은 일반 사용자에게 할당됩니다.

---

**문제 3.** 다음 중 사용자의 암호화된 비밀번호가 저장되는 파일로 알맞은 것은?

A) /etc/group  
B) /etc/shadow  
C) /etc/passwd  
D) /etc/sudoers  

**정답: B**  
해설: `/etc/passwd`는 여러 프로그램이 사용자 정보를 조회해야 해서 누구나 읽을 수 있습니다. 그래서 비밀번호 해시는 root만 읽을 수 있는 `/etc/shadow`로 분리했습니다. `/etc/group`은 그룹 정보를, `/etc/sudoers`는 sudo 권한 설정을 담습니다.

---

**문제 4.** 다음 중 기존 보조 그룹을 유지하면서 사용자를 새 그룹에 추가하는 명령으로 알맞은 것은?

A) usermod -G dev alice  
B) useradd -G dev alice  
C) usermod -aG dev alice  
D) groupadd -a dev alice  

**정답: C**  
해설: `usermod -G`만 사용하면 지정한 그룹 목록으로 **교체**되어 기존 보조 그룹이 사라집니다. 기존 소속을 유지하면서 추가하려면 `-a`(append)를 함께 써서 `-aG` 형태로 지정해야 합니다. `useradd`는 새 계정을 만드는 명령입니다.

---

**문제 5.** 다음 중 `su`와 `sudo`의 차이에 대한 설명으로 알맞은 것은?

A) 둘 다 대상 계정의 비밀번호를 입력해야 한다  
B) `su`는 자기 비밀번호를, `sudo`는 root 비밀번호를 쓴다  
C) `sudo`는 사용자 자체를 전환하고 `su`는 명령 하나만 실행한다  
D) `su`는 사용자를 전환하고 `sudo`는 명령 하나만 권한을 올려 실행한다  

**정답: D**  
해설: `su`는 지정한 사용자로 전환하며 그 계정의 비밀번호가 필요합니다. `sudo`는 명령 하나만 관리자 권한으로 실행하며 자기 자신의 비밀번호를 입력합니다. `sudo`는 누가 어떤 명령을 실행했는지 기록이 남아 감사 추적에 유리하며, 권한 설정은 `visudo`로 `/etc/sudoers`를 편집해 관리합니다.
