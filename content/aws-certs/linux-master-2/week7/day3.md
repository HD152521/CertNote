# Day 3 - 장치 파일과 /dev

## 📌 핵심 정리

- 리눅스는 **"모든 것은 파일이다"** — 키보드도 디스크도 프린터도 **`/dev` 아래의 파일**로 다룬다.
- 장치는 **블록 장치(`b`)와 문자 장치(`c`)** 로 나뉜다. **디스크는 블록, 키보드·프린터는 문자**다.
- 장치 파일은 **주 번호(major)와 부 번호(minor)** 로 구별된다. 크기 대신 이 두 숫자가 보인다.
- **`udev`** 가 장치를 감지해 `/dev` 아래 파일을 **자동으로 만들고 지운다**.
- 하드웨어 조회는 **`lsblk`(블록) · `lsusb`(USB) · `lspci`(PCI) · `dmesg`(커널 메시지)** 로 한다.

## 장치도 파일이다

```bash
ls -l /dev/sda /dev/tty0
# brw-rw---- 1 root disk 8, 0 Sep  3 09:00 /dev/sda
# crw--w---- 1 root tty  4, 0 Sep  3 09:00 /dev/tty0
#  │                      │  │
#  │                      │  └── 부 번호 (minor)
#  │                      └───── 주 번호 (major)
#  └──────────────────────────── b = 블록, c = 문자
```

- 일반 파일에서 **크기가 표시되던 자리에 두 개의 숫자**가 나온다. 이것이 주 번호와 부 번호다.

| 번호 | 뜻 |
|------|-----|
| **주 번호(major)** | 어떤 **드라이버**가 담당하는가 (장치의 종류) |
| **부 번호(minor)** | 그 드라이버가 다루는 **몇 번째 장치**인가 |

## 블록 장치와 문자 장치

| 구분 | **블록 장치** | **문자 장치** |
|------|-------------|-------------|
| 표시 | **`b`** | **`c`** |
| 다루는 단위 | **정해진 크기의 블록** | **한 글자씩(스트림)** |
| 버퍼 | 사용한다 | 거의 쓰지 않는다 |
| 임의 접근 | **가능** | 순차적 |
| 예 | **하드디스크, USB, CD-ROM** | **키보드, 마우스, 프린터, 터미널** |

> **디스크 계열은 블록, 입출력 계열은 문자**로 기억한다. "임의의 위치를 바로 읽을 수 있는가"가 가르는 기준이다. 디스크는 아무 데나 바로 읽지만 키보드는 눌린 순서대로 흘러온다.

## 주요 장치 파일

| 장치 파일 | 무엇 |
|----------|------|
| **`/dev/sda`** | 첫 번째 **SATA·SCSI·USB 디스크** |
| `/dev/sda1` | sda의 **첫 번째 파티션** |
| `/dev/sdb` | 두 번째 디스크 |
| `/dev/hda` | 예전 **IDE** 방식 디스크 |
| `/dev/nvme0n1` | **NVMe** SSD |
| **`/dev/sr0`** (`/dev/cdrom`) | **CD/DVD** 드라이브 |
| **`/dev/null`** | **버리는 곳**. 읽으면 아무것도 없다 |
| **`/dev/zero`** | 읽으면 **0이 무한히** 나온다 |
| `/dev/random`, `/dev/urandom` | **난수** 생성 |
| **`/dev/tty`** | 현재 **터미널** |
| `/dev/lp0` | 첫 번째 **프린터** 포트 |
| `/dev/fd0` | 플로피 디스크 |

### 디스크 이름 규칙

```text
   /dev/sd a 1
        │  │ │
        │  │ └── 파티션 번호 (1부터)
        │  └──── 몇 번째 디스크 (a, b, c...)
        └─────── sd = SATA/SCSI/USB,  hd = IDE
```

| 예 | 뜻 |
|----|-----|
| `/dev/sda` | 첫 번째 디스크 **전체** |
| `/dev/sda1` | 첫 번째 디스크의 **1번 파티션** |
| `/dev/sdb2` | 두 번째 디스크의 **2번 파티션** |

- **디스크는 알파벳, 파티션은 숫자**다. 이 조합을 그대로 묻는다.
- 요즘은 IDE 디스크도 `sd`로 인식하는 경우가 많다.

## udev — 장치 파일을 자동으로

예전에는 `/dev` 아래에 **쓰지도 않을 장치 파일이 수천 개** 미리 만들어져 있었다.

```text
   장치 연결(USB 꽂기)
        │
        ▼
   커널이 감지 ──► udev ──► /dev/sdb 파일 생성
        │                    권한·소유자 지정
        ▼                    이름 규칙 적용
   장치 제거 ──► udev ──► 파일 삭제
```

- **`udev`는 장치가 연결·제거될 때 `/dev` 아래 파일을 실시간으로 만들고 지운다.**
- 규칙 파일은 **`/etc/udev/rules.d/`** 에 둔다. 특정 USB에 항상 같은 이름을 붙이는 식의 설정이 가능하다.
- 덕분에 실제로 있는 장치만 `/dev`에 존재한다.

## 하드웨어 조회 명령

| 명령 | 보여 주는 것 |
|------|------------|
| **`lsblk`** | **블록 장치**를 트리로 |
| **`lsusb`** | 연결된 **USB** 장치 |
| **`lspci`** | **PCI** 장치 (그래픽·랜카드) |
| `lscpu` | CPU 정보 |
| `lsmod` | 적재된 **커널 모듈** |
| **`dmesg`** | **커널 메시지** — 장치 인식 기록 |
| `blkid` | 장치의 UUID와 파일 시스템 종류 |

```bash
lsblk                  # 디스크와 파티션 구조
lsusb                  # USB 목록
dmesg | tail -20       # 방금 꽂은 장치가 무엇으로 인식됐나
```

- **`ls`로 시작하는 명령들이 한 묶음**이다 — `lsblk`, `lsusb`, `lspci`, `lscpu`, `lsmod`.
- **USB를 꽂았는데 안 보이면 `dmesg`** 로 커널이 무엇으로 인식했는지 확인하는 것이 표준 절차다.

## 이동식 매체 다루기

```bash
lsblk                        # /dev/sdb1 로 잡혔는지 확인
sudo mount /dev/sdb1 /mnt    # 붙이기
ls /mnt                      # 내용 확인
sudo umount /mnt             # 떼기 — 뽑기 전에 반드시
```

- 요즘 데스크톱 환경은 **`/media/사용자명/` 아래에 자동으로 마운트**해 준다.
- **뽑기 전에 반드시 `umount`** 한다. 쓰기 캐시가 남아 있으면 데이터가 손상된다.

> 내일은 프린터·사운드·스캐너 같은 주변장치를 실제로 다루는 방법을 배운다.

## 📖 용어

- **장치 파일** : 하드웨어를 파일처럼 다루도록 `/dev` 아래에 만들어진 특수 파일.
- **블록 장치** : 정해진 크기의 블록 단위로 임의 접근하는 장치. 표시는 `b`이며 디스크가 해당한다.
- **문자 장치** : 데이터를 한 글자씩 순차적으로 주고받는 장치. 표시는 `c`이며 키보드·프린터가 해당한다.
- **주 번호(major)** : 장치를 담당하는 드라이버를 구분하는 번호.
- **부 번호(minor)** : 같은 드라이버가 다루는 개별 장치를 구분하는 번호.
- **udev** : 장치의 연결과 제거를 감지해 `/dev` 아래 파일을 자동 생성·삭제하는 관리자.
- **`/dev/null`** : 보낸 데이터를 버리는 장치 파일.
- **`dmesg`** : 커널이 남긴 메시지를 출력하는 명령. 장치 인식 결과를 확인할 때 쓴다.

## 📝 연습 문제

**문제 1.** 다음 중 하드디스크와 같이 블록 단위로 데이터를 주고받는 장치의 `ls -l` 표시 문자로 알맞은 것은?

A) b  
B) c  
C) d  
D) l  

**정답: A**  
해설: 블록 장치는 맨 앞에 `b`로 표시되며 하드디스크, USB 메모리, CD-ROM이 여기 해당합니다. 문자 장치는 `c`로 표시되고 키보드나 프린터처럼 한 글자씩 순차적으로 주고받는 장치입니다. `d`는 디렉터리, `l`은 심볼릭 링크입니다.

---

**문제 2.** 다음 중 문자 장치에 해당하는 것으로 알맞은 것은?

A) 하드디스크  
B) USB 메모리  
C) 키보드  
D) CD-ROM  

**정답: C**  
해설: 키보드는 눌린 순서대로 데이터가 흘러오는 문자 장치입니다. 하드디스크, USB 메모리, CD-ROM은 정해진 크기의 블록 단위로 임의의 위치를 바로 읽을 수 있는 블록 장치입니다.

---

**문제 3.** 다음 중 첫 번째 SATA 디스크의 두 번째 파티션을 나타내는 장치 파일로 알맞은 것은?

A) /dev/sdb1  
B) /dev/sda2  
C) /dev/sda1  
D) /dev/hdb2  

**정답: B**  
해설: `sd` 다음의 알파벳이 몇 번째 디스크인지를, 그 뒤의 숫자가 파티션 번호를 나타냅니다. 따라서 첫 번째 디스크는 `sda`, 그 두 번째 파티션은 `sda2`가 됩니다. `hd`로 시작하는 이름은 예전 IDE 방식 디스크를 가리킵니다.

---

**문제 4.** 다음 중 장치의 연결과 제거를 감지해 `/dev` 아래의 장치 파일을 자동으로 생성하고 삭제하는 것으로 알맞은 것은?

A) systemd  
B) fstab  
C) mount  
D) udev  

**정답: D**  
해설: udev는 커널이 감지한 장치 정보를 받아 `/dev` 아래에 해당 장치 파일을 만들고 제거될 때 지웁니다. 규칙은 `/etc/udev/rules.d/`에 두어 특정 장치에 고정된 이름을 부여할 수도 있습니다. `mount`는 파일 시스템을 연결하는 명령입니다.

---

**문제 5.** 다음 중 커널이 남긴 메시지를 출력해 새로 연결한 장치가 어떻게 인식되었는지 확인하는 명령으로 알맞은 것은?

A) dmesg  
B) lsmod  
C) lscpu  
D) blkid  

**정답: A**  
해설: `dmesg`는 커널 링 버퍼에 쌓인 메시지를 출력하므로 방금 연결한 USB가 어떤 장치 이름으로 인식되었는지 확인할 수 있습니다. `lsmod`는 적재된 커널 모듈, `lscpu`는 CPU 정보, `blkid`는 장치의 UUID와 파일 시스템 종류를 보여 줍니다.
