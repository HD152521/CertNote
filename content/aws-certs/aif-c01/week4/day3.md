# Day 3 - AWS AI 서비스 (1): 이미지·문서·텍스트·음성을 다루는 관리형 API

## 📌 핵심 정리

- AWS AI 서비스는 미리 학습된 모델을 뒤에 숨기고 **완성된 기능만 API 로** 내놓는다. 모델을 만들거나 고를 필요가 없다.
- 용도 매핑: 이미지·영상은 **Rekognition**, 문서의 표·양식 추출은 **Textract**, 텍스트 의미 분석은 **Comprehend**, 음성→텍스트는 **Transcribe**, 텍스트→음성은 **Polly**, 번역은 **Translate**.
- 헷갈리는 쌍은 입력과 목적으로 가른다. 사진 속 사물·얼굴이면 Rekognition, 서류에서 필드를 뽑으면 Textract. 이미 있는 글을 분석하면 Comprehend.
- 서비스는 **파이프라인으로 연결**해 쓴다. 통화→텍스트→감정(Transcribe→Comprehend), 음성→번역→음성(Transcribe→Translate→Polly).
- 일반 모델이 약한 고유 용어·분류는 서비스별 커스텀 기능으로 보완하고, 그래도 부족하면 SageMaker 로 넘어간다.

## 한눈에 보는 6개 서비스

지금까지 본 Bedrock 과 SageMaker 는 "모델 자체"를 다루는 서비스였다. 오늘 보는 서비스들은 결이 다르다. **모델을 만들거나 고를 필요조차 없이, API 한 번 호출로 특정 작업을 끝내주는** 관리형 AI 서비스들이다. AWS 는 이를 "AI Services"라고 부른다.

- 이들은 AWS 가 미리 학습시켜 둔 모델을 뒤에 숨겨두고, "이미지에서 글자 찾기", "음성을 텍스트로" 같은 **완성된 기능**만 노출한다.
- AIF-C01 시험은 "이 작업에는 어떤 서비스?"를 집요하게 묻는다. 6개 핵심 서비스의 **용도**를 정확히 짝짓는 것이 목표다.

| 서비스 | 입력 → 출력 | 한 줄 용도 |
|--------|-------------|------------|
| Rekognition | 이미지/영상 → 분석 결과 | 객체·얼굴·텍스트·부적절 콘텐츠 탐지 |
| Textract | 문서 이미지 → 구조화 텍스트 | 문서에서 글자·표·양식 추출(OCR+) |
| Comprehend | 텍스트 → 의미 분석 | 감정·개체·핵심구·언어 분석(NLP) |
| Transcribe | 음성 → 텍스트 | 음성 인식(STT) |
| Polly | 텍스트 → 음성 | 음성 합성(TTS) |
| Translate | 텍스트 → 번역 텍스트 | 언어 간 번역 |

이 표가 오늘의 핵심이다. 외우는 요령은 **입력이 무엇인가**부터 보는 것이다. 사진·영상이면 Rekognition, 서류면 Textract, 글이면 Comprehend 나 Translate, 소리면 Transcribe, 글을 소리로 바꾸면 Polly 다.

## Rekognition: 이미지와 영상을 보는 눈

**Amazon Rekognition** 은 이미지·영상을 분석하는 컴퓨터 비전 서비스다.

- **객체·장면 탐지**: 사진에 무엇이 있는지(자동차, 강아지, 해변).
- **얼굴 분석·비교**: 얼굴 감지, 두 얼굴이 같은 사람인지 비교, 표정·연령대 추정.
- **텍스트 추출**: 이미지 속 글자 읽기(간판, 번호판).
- **부적절 콘텐츠 탐지(content moderation)**: 폭력·선정적 이미지 필터링.
- **유명인 인식, 라벨링** 등.

조금 더 들어가면 시험에 나올 만한 기능이 셋 더 있다.

- **Custom Labels**: 자사 로고·제품·부품처럼 일반 모델이 모르는 대상을 내 이미지로 학습시켜 찾게 한다. "ML 전문성 없이 우리 회사 제품을 이미지에서 찾고 싶다"의 답이다.
- **보호 장비(PPE) 탐지**: 작업자가 안전모·마스크 등을 착용했는지 확인한다.
- **Face Liveness**: 얼굴 인증 때 카메라 앞에 실제 사람이 있는지, 사진·영상으로 속이는지 가려낸다.

가상의 사례로, 한 SNS 플랫폼은 사용자가 올리는 수백만 장의 이미지에서 부적절 콘텐츠를 사람이 일일이 검수했다. Rekognition 의 content moderation API 로 1차 자동 필터링을 도입하자, 사람은 애매한 경우만 검토하면 되어 검수 인력이 크게 줄었다. "이미지/영상을 이해해야 한다"는 단서가 나오면 Rekognition 이다.

- 탐지 결과에는 **신뢰도 점수**가 붙는다. 사례처럼 점수가 높은 것은 자동 처리하고 애매한 구간만 사람이 보는 구성이 Human-in-the-loop 의 전형이다.
- 얼굴 분석은 사람의 권리에 닿는 기능이다. 책임 있는 AI 관점에서 용도와 한계를 확인하고 써야 한다는 점이 Week 5 와 이어진다.

## Textract: 문서를 진짜로 읽기

**Amazon Textract** 는 단순 OCR 을 넘어선다. 일반 OCR 이 "글자만" 뽑는다면, Textract 는 **표(table)와 양식(form)의 구조까지** 이해한다. 청구서에서 "총액: $1,200" 같은 키-값 쌍을 인식하고, 표를 행·열로 정확히 추출한다.

| 기능 | 뽑아 주는 것 | 예 |
|------|------|------|
| 텍스트 감지 | 인쇄체와 손글씨 글자 | 스캔한 계약서 본문 |
| 양식·표 분석 | 키-값 쌍, 행·열 구조 | 신청서의 "이름: 홍길동", 견적표 |
| 쿼리(Queries) | 자연어로 물은 항목의 값 | "납부 기한은 언제인가?" |
| 비용 문서 분석 | 청구서·영수증의 공급자, 합계, 품목 | 경비 정산 자동화 |
| 신분증 분석 | 운전면허증·여권의 항목(미국 정부 발급 신분증 대상) | 본인 확인 서류 처리 |

> 💡 **관련 이론**: Rekognition 도 이미지 속 텍스트를 읽지만, Textract 는 **문서 처리**에 특화되어 있다. 영수증, 세금 양식, 보험 청구서, 신분증처럼 "구조가 있는 문서"에서 데이터를 뽑아 자동 처리하는 게 목적이다. 시험에서 "스캔한 청구서/양식에서 필드를 추출해 자동 입력"이면 Textract, "사진 속 객체나 얼굴 분석"이면 Rekognition 으로 가른다.

같은 "글자 읽기"라도 대상이 다르다. 거리 사진 속 **간판 한 줄**은 Rekognition, 서류 한 장의 **어느 칸에 무슨 값이 있는지**는 Textract 다.

## Comprehend: 텍스트의 의미를 파악

**Amazon Comprehend** 는 자연어 처리(NLP) 서비스로, 텍스트의 의미를 분석한다.

- **감정 분석(sentiment)**: 긍정/부정/중립, 그리고 둘이 섞인 혼합.
- **개체 인식(entity)**: 사람·장소·날짜·조직 추출.
- **핵심 구(key phrase)**, **언어 감지**, **주제 모델링**.
- **PII 탐지**: 텍스트 속 개인정보 식별.

의료 텍스트에 특화된 **Comprehend Medical** 도 있다.

- **대상 감정(targeted sentiment)**: 문서 전체가 아니라 개체별 감정을 본다. "음식은 훌륭했지만 배송이 늦었다"에서 음식은 긍정, 배송은 부정으로 나뉜다.
- **Comprehend Custom**: 내 분류 체계로 문서를 나누는 **커스텀 분류**와, 내 업계 고유 용어를 찾는 **커스텀 개체 인식**을 내 데이터로 만든다. 모델 설계는 서비스가 대신한다.

> 🔍 **더 깊이**: Comprehend 는 "텍스트가 이미 있을 때" 그 의미를 분석한다. 고객 리뷰 수천 건의 감정을 자동 집계하거나, 문서에서 사람·날짜를 뽑아 색인하는 식이다. "텍스트의 감정/개체/언어를 분석"이라는 단서가 핵심 신호다.

Comprehend 는 글을 **새로 쓰지 않는다.** 분류하고 뽑아낼 뿐이다. 요약문이나 답장을 만들어야 하면 생성형 AI(Bedrock)의 일이다.

## Transcribe & Polly: 음성과 텍스트를 오가다

이 둘은 서로 반대 방향이다.

- **Amazon Transcribe (STT, Speech-to-Text)**: 음성 → 텍스트. 회의 녹음 받아쓰기, 콜센터 통화 기록, 자막 생성. 화자 분리(누가 말했는지)도 지원.
- **Amazon Polly (TTS, Text-to-Speech)**: 텍스트 → 음성. 자연스러운 사람 목소리로 글을 읽어준다. 오디오북, 음성 안내, 접근성.

| 구분 | Transcribe | Polly |
|------|-----------|-------|
| 방향 | 음성 → 텍스트 | 텍스트 → 음성 |
| 약어 | STT | TTS |
| 활용 | 자막, 통화 기록 | 음성 안내, 오디오북 |

- Transcribe 는 S3 에 올린 파일을 처리하는 **배치**와 실시간 **스트리밍**을 모두 지원한다. 녹음 파일 정리는 배치, 생방송 자막은 스트리밍이다.
- 전문 용어·고유명사를 잘못 받아쓰면 **사용자 지정 어휘**나 커스텀 언어 모델로 보완한다. 받아쓴 글에서 개인정보를 가리거나 부적절한 단어를 거르는 기능도 있다.
- 콜센터 통화 분석과 의료 받아쓰기에 맞춘 변형(Call Analytics, Transcribe Medical)이 있다.
- Polly 는 표준·뉴럴·장문·생성형 등 여러 종류의 음성을 제공하고, SSML 태그로 발음·쉼·속도를 조절한다.

가상의 사례로, 한 콜센터는 Transcribe 로 통화를 텍스트로 변환하고, 그 텍스트를 Comprehend 에 넣어 고객 감정을 분석했다. 불만 신호가 강한 통화를 자동 플래그해 관리자에게 알렸다. 여러 AI 서비스를 **파이프라인으로 연결**한 전형적 예다(음성→텍스트→감정).

## Translate: 언어의 장벽 넘기

**Amazon Translate** 는 신경망 기반 기계 번역 서비스다. 텍스트를 한 언어에서 다른 언어로 실시간 번역한다. 다국어 웹사이트, 고객 지원 메시지 번역, 실시간 채팅 통역 등에 쓴다.

Translate 역시 다른 서비스와 자주 결합한다. 예를 들어 외국어 음성을 Transcribe 로 받아쓰고 → Translate 로 번역하고 → Polly 로 다시 음성으로 내보내면 간단한 통역 파이프라인이 된다.

- 브랜드명·제품명처럼 번역하면 안 되거나 정해진 표현으로 옮겨야 하는 말은 **사용자 지정 용어집**으로 고정한다.
- 여러 언어로 들어온 리뷰를 한 언어로 번역한 뒤 Comprehend 로 분석하는 조합도 흔하다(Translate→Comprehend).

이 6개 서비스의 공통점은 **"사전학습된 모델을 API 로 노출"** 한다는 것이다. 사용자는 ML 지식 없이 즉시 쓸 수 있다. 단, 매우 특수한 도메인(예: 전문 의료 용어, 자사 고유 제품명)은 일반 모델이 약할 수 있어, 일부 서비스는 **커스텀 모델/사용자 사전** 기능을 제공한다. 그래도 "직접 학습"이 필요한 수준이면 SageMaker 로 넘어가야 한다.

## 닮은 기능 가려내기

| 헷갈리는 쌍 | 가르는 질문 | 답 |
|------|------|------|
| Rekognition 텍스트 감지 vs Textract | 사진 속 글자인가, 서류의 구조인가 | 간판·번호판 = Rekognition, 양식·표 = Textract |
| Comprehend vs Translate | 글의 뜻을 분석하나, 다른 언어로 옮기나 | 감정·개체 = Comprehend, 번역 = Translate |
| Comprehend vs Bedrock(FM) | 정해진 항목을 뽑나, 새 글을 쓰나 | 분류·추출 = Comprehend, 요약·답장 작성 = FM |
| Transcribe vs Polly | 소리가 입력인가 출력인가 | 입력 = Transcribe, 출력 = Polly |
| Comprehend PII vs Macie | 텍스트 한 건을 분석하나, S3 저장소를 훑나 | 텍스트 속 PII = Comprehend, S3 의 민감 데이터 발견 = Macie |
| Comprehend PII vs Bedrock Guardrails | 일반 텍스트 분석인가, 생성형 AI 입출력 통제인가 | 문서·로그 분석 = Comprehend, 챗봇 대화 마스킹 = Guardrails |

**완성형 AI 서비스냐, 파운데이션 모델이냐.** 요즘 FM 은 이미지도 읽고 번역도 한다. 그래도 시험은 다음 기준으로 완성형 서비스를 고르게 한다.

| 기준 | 완성형 AI 서비스 | FM(Bedrock) |
|------|------|------|
| 작업 | 범위가 정해진 한 가지(감정, OCR, STT…) | 열려 있고 여러 가지 |
| 출력 | 정해진 구조와 신뢰도 점수, 매번 같은 형태 | 자유 형식, 프롬프트에 따라 달라짐 |
| 준비 | API 호출만 | 프롬프트 설계와 검증 |
| 맞는 단서 | "ML 전문성 없음", "가장 적은 노력", "특정 작업" | "요약·생성", "대화", "유연한 지시" |

## 커스터마이징과 비용

| 서비스 | 일반 모델이 약할 때의 보완 | 과금의 기준 |
|------|------|------|
| Rekognition | Custom Labels(내 이미지로 학습) | 분석한 이미지 수·영상 분량 |
| Textract | 쿼리, 커스텀 쿼리 | 분석한 문서 분량(기능에 따라 요율이 다름) |
| Comprehend | 커스텀 분류·커스텀 개체 인식 | 분석한 텍스트 양, 커스텀 모델 학습과 실시간 엔드포인트 유지 시간 |
| Transcribe | 사용자 지정 어휘, 커스텀 언어 모델 | 받아쓴 오디오 길이(초 단위), 일부 기능은 추가 요금 |
| Polly | SSML, 음성 종류 선택 | 음성으로 합성한 텍스트 양 |
| Translate | 사용자 지정 용어집 | 번역한 텍스트 양 |

- 여섯 서비스 모두 **쓴 만큼 내는** 구조이고 미리 띄워 둘 서버가 없다. 예외에 가까운 것이 커스텀 모델의 실시간 엔드포인트로, 띄워 둔 시간만큼 과금된다.
- 파이프라인은 단계마다 요금이 붙는다. 통화 1분을 Transcribe→Translate→Comprehend 로 돌리면 세 서비스의 요금이 모두 든다.

**흔한 오해.**

- "AI 서비스도 쓰려면 학습 데이터를 준비해야 한다" → 기본 기능은 데이터 없이 바로 호출한다. 데이터가 필요한 것은 커스텀 기능뿐이다.
- "Rekognition 이 글자를 읽으니 문서 처리도 된다" → 글자는 읽지만 표·키-값 구조는 Textract 의 일이다.
- "감정 분석에는 생성형 AI 가 필요하다" → 긍정/부정 분류는 Comprehend 로 충분하고 결과 형태도 일정하다.
- "Polly 가 통화를 받아쓴다" → 방향이 반대다. 받아쓰기는 Transcribe 다.

## 시나리오 → 정답 판별표

| 지문 단서 | 정답 | 탈락하는 보기와 이유 |
|------|------|------|
| "업로드된 사진에서 폭력·선정적 이미지를 걸러낸다" | Rekognition | Comprehend — 텍스트용 |
| "공장 사진에서 안전모 미착용자를 찾는다" | Rekognition(PPE 탐지) | Textract — 문서용 |
| "우리 회사 로고가 찍힌 사진만 골라낸다" | Rekognition Custom Labels | SageMaker 로 처음부터 학습 — 노력이 과하다 |
| "스캔한 보험 청구서에서 청구액과 표를 추출" | Textract | Rekognition — 구조를 모른다 |
| "영수증 사진에서 상호와 합계만 뽑아 경비 처리" | Textract(비용 문서 분석) | Comprehend — 이미지를 직접 읽지 못한다 |
| "고객 리뷰가 긍정인지 부정인지 집계" | Comprehend | Translate — 번역만 한다 |
| "상담 기록에서 주민번호·전화번호를 찾아낸다" | Comprehend(PII 탐지) | Rekognition — 이미지용 |
| "회의 녹음을 화자별로 받아쓴다" | Transcribe | Polly — 반대 방향 |
| "기사 본문을 읽어 주는 오디오 버전 제공" | Polly | Transcribe — 반대 방향 |
| "외국어 통화를 받아써 한국어로 옮기고 감정까지 분석" | Transcribe → Translate → Comprehend | 단일 서비스 — 한 서비스로는 끝나지 않는다 |

내일은 나머지 AI 서비스(Lex, Kendra, Personalize, Forecast)와 Amazon Q 를 보고, 전체 서비스를 "어떤 작업에 무엇을" 고르는 기준으로 묶는다.

## 📖 용어

- **컴퓨터 비전** : 이미지·영상에서 사물, 얼굴, 글자 등을 알아보는 AI 분야.
- **OCR** : 이미지 속 글자를 텍스트로 읽어 내는 기술. Textract 는 여기에 표·양식 구조 이해를 더한다.
- **키-값 쌍** : "총액: 1,200"처럼 항목 이름과 그 값이 짝지어진 것. 양식 문서의 기본 구조다.
- **NLP(자연어 처리)** : 사람의 글을 컴퓨터가 분석하고 이해하게 하는 기술.
- **개체 인식** : 글에서 사람, 장소, 날짜, 조직 같은 이름을 찾아내는 것.
- **PII** : 이름, 주소, 계좌번호처럼 개인을 식별할 수 있는 정보.
- **STT / TTS** : 음성을 글로 바꾸는 것(Speech-to-Text)과 글을 음성으로 바꾸는 것(Text-to-Speech).
- **화자 분리** : 녹음에서 누가 어느 부분을 말했는지 나누는 것.
- **콘텐츠 모더레이션** : 부적절한 이미지·영상·글을 찾아 걸러내는 일.
- **신뢰도 점수** : 서비스가 자기 판단을 얼마나 확신하는지 나타내는 값. 낮으면 사람 검토로 넘긴다.

## 📝 연습 문제

**문제 1.** 사용자가 업로드한 사진에서 객체와 얼굴을 감지하고 부적절한 콘텐츠를 자동으로 걸러내려 한다. 가장 적합한 서비스는?

A) Amazon Comprehend  
B) Amazon Rekognition  
C) Amazon Polly  
D) Amazon Translate  

**정답: B**  
해설: Rekognition은 이미지·영상에서 객체·얼굴 탐지와 부적절 콘텐츠 검열을 제공하는 컴퓨터 비전 서비스다. A는 텍스트 NLP, C는 음성 합성, D는 번역으로 이미지 분석과 무관하다.

---

**문제 2.** 스캔한 청구서 이미지에서 "총액", "날짜" 같은 키-값 쌍과 표 데이터를 구조화해 추출하려 한다. 가장 적합한 서비스는?

A) Amazon Textract  
B) Amazon Transcribe  
C) Amazon Rekognition  
D) Amazon Polly  

**정답: A**  
해설: Textract는 문서에서 글자뿐 아니라 표와 양식의 키-값 구조까지 추출하는 문서 처리 서비스다. C(Rekognition)도 이미지 속 텍스트를 읽지만 문서의 구조화 추출에는 Textract가 특화되어 있다. B는 음성 인식, D는 음성 합성으로 무관하다.

---

**문제 3.** 고객 리뷰 수천 건이 긍정인지 부정인지 자동으로 분류하고, 텍스트에서 사람·장소 같은 개체를 추출하려 한다. 적합한 서비스는?

A) Amazon Translate  
B) Amazon Comprehend  
C) Amazon Textract  
D) Amazon Lex  

**정답: B**  
해설: Comprehend는 감정 분석, 개체 인식, 핵심 구 추출 등 텍스트 의미 분석(NLP)을 제공한다. A는 번역, C는 문서 추출이며, D(Lex)는 챗봇 구축 서비스로 대량 텍스트 의미 분석이 본업이 아니다.

---

**문제 4.** 콜센터 통화 녹음을 텍스트로 변환한 뒤, 그 텍스트의 고객 감정을 분석하려 한다. 어떤 서비스 조합이 적절한가?

A) Polly → Translate  
B) Transcribe → Comprehend  
C) Rekognition → Textract  
D) Translate → Polly  

**정답: B**  
해설: Transcribe로 음성을 텍스트(STT)로 바꾸고, 그 텍스트를 Comprehend로 감정 분석하는 파이프라인이 적절하다. A는 텍스트를 음성으로 만든 뒤 번역하는 비논리적 순서다. C는 이미지·문서용, D는 번역 후 음성 합성으로 통화 감정 분석과 맞지 않는다.

---

**문제 5.** 웹사이트의 안내 텍스트를 자연스러운 사람 목소리의 음성으로 변환해 들려주려 한다. 가장 적합한 서비스는?

A) Amazon Transcribe  
B) Amazon Polly  
C) Amazon Comprehend  
D) Amazon Rekognition  

**정답: B**  
해설: Polly는 텍스트를 자연스러운 음성으로 합성하는 TTS 서비스다. A(Transcribe)는 반대로 음성을 텍스트로 바꾸는 STT다. C는 텍스트 의미 분석, D는 이미지 분석으로 음성 합성과 무관하다.
