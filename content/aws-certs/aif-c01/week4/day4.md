# Day 4 - AWS AI 서비스 (2) + Amazon Q: 챗봇·검색·추천·예측과 생성형 비서

어제는 이미지·문서·텍스트·음성을 다루는 6개 AI 서비스를 봤다. 오늘은 나머지 핵심 서비스 — **Lex(챗봇), Kendra(검색), Personalize(추천), Forecast(예측)** — 와, AWS의 생성형 AI 비서인 **Amazon Q**를 본다. 마지막으로 지금까지 본 모든 서비스를 "무엇을 고를까" 기준으로 묶는다.

이 영역은 AIF-C01에서 가장 출제 비중이 높다. 핵심은 여전히 **용도 매핑**: "이 시나리오엔 어떤 서비스인가?"

## Lex: 대화형 챗봇·음성봇 만들기

**Amazon Lex**는 챗봇과 음성봇을 만드는 서비스다. Amazon Alexa를 떠받치는 기술과 같은 엔진을 쓴다. Lex의 두 핵심 개념:

- **인텐트(Intent)**: 사용자가 하려는 의도(예: "항공편 예약하기").
- **슬롯(Slot)**: 그 의도를 채우는 데 필요한 정보(예: 출발지, 도착지, 날짜).

Lex는 사용자의 말에서 인텐트를 파악하고 부족한 슬롯을 되물으며 대화를 이끈다. 실제 처리(예약 실행)는 Lambda로 연결한다.

> 💡 **관련 이론**: Lex는 음성/텍스트 입력을 이해하는 **NLU(자연어 이해)**와 대화 관리를 제공한다. "고객 문의를 처리하는 대화형 봇을 만들고 싶다"는 단서가 Lex 신호다. Bedrock Agents와 헷갈릴 수 있는데, Lex는 인텐트/슬롯 기반의 정형화된 대화 봇 구축에, Bedrock Agents는 FM의 추론으로 더 유연하게 다단계 작업을 수행하는 데 강하다.

## Kendra: 똑똑한 기업 내부 검색

**Amazon Kendra**는 머신러닝 기반의 **기업 내부 검색(enterprise search)** 서비스다. 사내 위키, PDF, SharePoint, S3 등에 흩어진 문서를 색인해, 직원이 자연어로 질문하면 정확한 답이 있는 위치를 찾아준다.

단순 키워드 검색이 아니라 "질문의 의미"를 이해해 답을 찾는다. "휴가는 며칠인가요?"라고 물으면 관련 규정 문서의 정확한 문단을 짚어준다.

> 🔍 **더 깊이**: Kendra는 RAG의 "검색(retrieval)" 부분을 강력하게 담당할 수 있어, Bedrock과 결합해 생성형 Q&A의 백엔드로 자주 쓰인다. "사내 여러 문서를 가로질러 자연어로 검색"이면 Kendra다. Comprehend(텍스트 의미 분석)와 구분하자 — Kendra는 "찾기", Comprehend는 "분석하기"다.

## Personalize & Forecast: 추천과 예측

이 둘은 전통 ML 작업을 관리형으로 제공한다.

- **Amazon Personalize**: 실시간 **추천 시스템**. Amazon닷컴의 추천 기술을 서비스화한 것으로, "이 상품을 본 사람이 좋아할 만한 것"을 추천한다.
- **Amazon Forecast**: **시계열 예측**. 과거 데이터를 바탕으로 미래 수요·판매·재고를 예측한다.

| 서비스 | 작업 | 활용 사례 |
|--------|------|-----------|
| Personalize | 개인화 추천 | 상품·콘텐츠 추천, 맞춤 검색 |
| Forecast | 시계열 예측 | 수요 예측, 재고 계획, 매출 전망 |

> 📚 **사례**: 한 이커머스 기업은 Forecast로 매장별·상품별 수요를 예측해 재고를 최적화하고, Personalize로 사용자별 추천을 제공했다. 둘 다 데이터 과학팀 없이 관리형 API로 구현했다. "미래 수치를 예측"이면 Forecast, "사용자에게 맞춤 추천"이면 Personalize다.

## Amazon Q: AWS의 생성형 AI 비서

**Amazon Q**는 생성형 AI 기반의 비서(어시스턴트)다. 용도에 따라 두 갈래로 나뉜다.

| 구분 | Amazon Q Business | Amazon Q Developer |
|------|-------------------|--------------------|
| 대상 | 일반 직원·업무 | 개발자 |
| 하는 일 | 사내 데이터 기반 질문 답변·요약 | 코드 생성·설명·디버깅, AWS 작업 지원 |
| 연결 | 위키·문서·앱 등 사내 시스템 | IDE, AWS 콘솔/CLI |

- **Amazon Q Business**: 사내 데이터에 연결해 직원이 자연어로 질문하면 근거와 함께 답해주는 업무용 비서. (사내 RAG 챗봇을 완제품으로 제공하는 느낌.)
- **Amazon Q Developer**: 코드 작성·설명·디버깅을 돕고 AWS 인프라 관련 질문에 답하는 개발자 비서. (과거 CodeWhisperer의 후속/확장.)

> 💡 **관련 이론**: Bedrock과의 차이를 잡자. Bedrock은 "내가 직접 생성형 앱을 만드는 빌딩 블록(API)"이고, Amazon Q는 "이미 완성된 생성형 비서 제품"이다. 직접 챗봇을 설계·개발할 거면 Bedrock, 곧바로 쓸 수 있는 업무/개발 비서가 필요하면 Amazon Q다.

## 서비스 선택 기준: 한 장으로 정리

시험에서 가장 중요한 건 "단서 → 서비스" 연결이다.

| 시나리오 단서 | 정답 서비스 |
|---------------|-------------|
| 여러 FM을 관리 없이 API로 | Bedrock |
| 자체 데이터로 커스텀 모델 학습·배포 | SageMaker |
| 이미지/영상 분석 | Rekognition |
| 문서(양식·표)에서 데이터 추출 | Textract |
| 텍스트 감정·개체 분석(NLP) | Comprehend |
| 음성 → 텍스트 / 텍스트 → 음성 | Transcribe / Polly |
| 언어 번역 | Translate |
| 대화형 챗봇·음성봇 | Lex |
| 사내 문서 자연어 검색 | Kendra |
| 개인화 추천 | Personalize |
| 시계열 수요·매출 예측 | Forecast |
| 업무용 생성형 비서(사내 데이터) | Amazon Q Business |
| 개발자용 코딩 비서 | Amazon Q Developer |

이 표가 Week 4의 결론이자, 시험 점수를 좌우하는 핵심 자산이다.

## 정리하며

오늘 추가한 서비스: **Lex**(챗봇/음성봇, 인텐트·슬롯), **Kendra**(사내 자연어 검색), **Personalize**(추천), **Forecast**(시계열 예측). 그리고 **Amazon Q**는 완성형 생성형 비서로, 업무용 **Q Business**와 개발자용 **Q Developer**로 나뉜다. Bedrock이 "빌딩 블록"이라면 Q는 "완제품 비서"다.

다음 글에서는 Week 4 전체를 종합 복습한다. 모든 AI/ML 서비스를 용도 매핑표로 한 번에 정리하고, 시험에서 헷갈리기 쉬운 서비스 쌍들을 비교한다.

## 📝 연습 문제

**문제 1.** 인텐트와 슬롯 개념을 사용해 고객 문의를 처리하는 대화형 챗봇/음성봇을 만들려 한다. 가장 적합한 서비스는?

A) Amazon Kendra  
B) Amazon Lex  
C) Amazon Forecast  
D) Amazon Polly  

**정답: B**  
해설: Lex는 인텐트(의도)와 슬롯(필요 정보) 기반으로 챗봇·음성봇을 구축하는 서비스다. A는 문서 검색, C는 시계열 예측, D는 음성 합성으로 대화형 봇 구축과는 다르다.

---

**문제 2.** 직원이 사내 위키·PDF·SharePoint에 흩어진 문서를 자연어 질문으로 검색해 정확한 답의 위치를 찾게 하려 한다. 가장 적합한 서비스는?

A) Amazon Comprehend  
B) Amazon Translate  
C) Amazon Kendra  
D) Amazon Personalize  

**정답: C**  
해설: Kendra는 ML 기반 기업 내부 검색으로, 여러 소스에 흩어진 문서를 색인해 자연어 질문에 정확한 답 위치를 제공한다. A는 텍스트 의미 분석, B는 번역, D는 추천으로 검색이 본업이 아니다.

---

**문제 3.** 사용자의 과거 행동을 바탕으로 "좋아할 만한 상품"을 실시간으로 추천하려 한다. 적합한 서비스는?

A) Amazon Forecast  
B) Amazon Personalize  
C) Amazon Lex  
D) Amazon Textract  

**정답: B**  
해설: Personalize는 Amazon닷컴의 추천 기술을 서비스화한 실시간 개인화 추천 시스템이다. A(Forecast)는 시계열 수치 예측이고, C는 챗봇, D는 문서 추출로 추천과 무관하다.

---

**문제 4.** 개발자가 IDE 안에서 코드 생성·설명·디버깅과 AWS 관련 질문에 대한 도움을 즉시 받고 싶다. 가장 적합한 것은?

A) Amazon Q Developer  
B) Amazon Q Business  
C) Amazon Forecast  
D) Amazon Comprehend  

**정답: A**  
해설: Q Developer는 개발자용 생성형 비서로 코드 작성·설명·디버깅과 AWS 작업을 지원한다. B(Q Business)는 사내 데이터 기반 업무용 비서로 대상이 다르다. C는 예측, D는 NLP로 코딩 지원과 무관하다.

---

**문제 5.** 직접 챗봇을 설계·개발하지 않고, 사내 데이터에 연결해 직원 질문에 근거와 함께 답하는 "완성형 업무용 생성형 비서"를 바로 도입하려 한다. 가장 적합한 것은?

A) Amazon Bedrock  
B) Amazon Q Business  
C) Amazon SageMaker  
D) Amazon Lex  

**정답: B**  
해설: Q Business는 사내 데이터에 연결되는 완제품형 생성형 업무 비서로, 직접 개발 없이 바로 쓸 수 있다. A(Bedrock)는 직접 앱을 만드는 빌딩 블록이고, C는 모델 학습 플랫폼, D는 직접 구축하는 챗봇 서비스로 "즉시 도입"과는 거리가 있다.
