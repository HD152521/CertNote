# Day 2 - AWS의 책임 있는 AI 도구: SageMaker Clarify, Model Monitor, Bedrock Guardrails, AI Service Cards

어제는 책임 있는 AI의 원칙들 — 공정성, 편향, 투명성, 설명가능성, 견고성, 프라이버시 — 을 배웠다. 원칙은 알았으니 이제 질문은 하나다. "그래서 AWS로 이걸 **어떻게** 실천하나?" 다행히 AWS는 각 원칙에 대응하는 구체적인 관리형 도구를 제공한다. 오늘은 그 핵심 네 가지를 본다.

이 도구들은 AIF-C01에서 "이 문제 상황에 맞는 AWS 도구는?"으로 자주 출제된다. 그래서 각 도구가 "어느 원칙을 어떻게 해결하는지"의 짝을 정확히 잡는 것이 목표다.

## 한눈에 보는 도구 매핑

| 도구 | 해결하는 원칙 | 한 줄 역할 |
|------|--------------|-----------|
| SageMaker Clarify | 공정성·편향, 설명가능성 | 편향 측정 + 특성 중요도 설명 |
| SageMaker Model Monitor | 견고성·신뢰성(운영) | 배포된 모델의 품질·드리프트 감시 |
| Bedrock Guardrails | 안전성·프라이버시 | 유해 콘텐츠 필터·PII 마스킹·주제 제한 |
| AI Service Cards | 투명성 | AWS AI 서비스의 용도·한계·공정성 공개 문서 |

> 💡 **관련 이론**: 이 표가 오늘의 핵심이다. 시험에서 "모델이 특정 집단에 편향됐는지 확인하고 싶다"면 → Clarify, "배포 후 시간이 지나며 성능이 떨어지는지 보고 싶다"면 → Model Monitor, "챗봇 출력에서 욕설·개인정보를 막고 싶다"면 → Guardrails, "이 AWS AI 서비스의 한계와 권장 용도를 알고 싶다"면 → AI Service Cards다.

## SageMaker Clarify: 편향 측정 + 설명가능성

**Amazon SageMaker Clarify**는 책임 있는 AI 도구의 핵심이다. 두 가지 일을 한다.

1. **편향 탐지(Bias Detection)**: 데이터와 모델 양쪽에서 편향을 측정한다.
   - **학습 전 편향**: 학습 데이터 자체에 특정 집단(예: 성별, 나이)이 불균형하게 분포하는지.
   - **학습 후 편향**: 학습된 모델의 예측 결과가 집단 간에 차별적인지.
   - 여러 통계 지표(클래스 불균형, 예측 격차 등)를 자동 계산한다.

2. **설명가능성(Explainability)**: 어떤 입력 특성이 예측에 얼마나 기여했는지를 **SHAP 값** 기반으로 계산해 보여준다. "이 대출이 거절된 이유는 신용점수 특성이 가장 크게 작용했다" 같은 설명을 만든다.

> 🔍 **더 깊이**: Clarify는 학습 전(데이터), 학습 후(모델), 배포 후(추론) 어느 단계에서도 쓸 수 있다. 특히 Model Monitor와 결합하면 배포된 모델의 편향이 시간이 지나며 커지는지(bias drift)도 감시할 수 있다. 즉 Clarify는 "편향과 설명"이라는 두 원칙을 한 도구로 묶어 다룬다고 기억하면 된다.

## SageMaker Model Monitor: 배포 후 품질 감시

모델은 배포하면 끝이 아니다. 시간이 지나면서 현실 데이터가 학습 데이터와 달라지면(데이터 드리프트), 모델 성능이 조용히 나빠진다. **SageMaker Model Monitor**는 배포된 모델 엔드포인트를 자동으로 감시한다.

감시하는 항목:

- **데이터 품질**: 입력 데이터의 분포가 학습 때와 달라졌는지(통계적 드리프트).
- **모델 품질**: 예측 정확도 같은 성능 지표가 기준선 아래로 떨어졌는지.
- **편향 드리프트**: (Clarify와 연동) 편향이 시간이 지나며 심해지는지.
- **특성 기여 드리프트**: 설명가능성 패턴이 바뀌었는지.

기준선(baseline)을 정해두고, 실제 트래픽이 그 기준에서 벗어나면 CloudWatch로 경보를 보낸다.

> ⚠️ **함정**: Model Monitor는 "모델을 자동으로 고쳐주는" 도구가 아니다. **이상을 감지해 알려주는** 모니터링 도구다. 문제를 발견하면 재학습·재배포는 사람이 결정해야 한다. "모델이 알아서 자가 치유한다"는 식의 보기는 함정이다.

## Bedrock Guardrails: 생성형 AI의 안전장치

**Amazon Bedrock Guardrails**는 생성형 AI(LLM) 애플리케이션에 안전·프라이버시 장벽을 두는 기능이다. 입력(사용자 프롬프트)과 출력(모델 응답) 양쪽에 적용된다.

주요 기능:

| 기능 | 역할 |
|------|------|
| 콘텐츠 필터 | 증오·폭력·성적·욕설 등 유해 콘텐츠 차단 |
| 거부 주제(Denied Topics) | 특정 주제(예: 의료 조언, 투자 권유)를 다루지 않도록 제한 |
| 민감정보(PII) 필터 | 이름·주민번호·카드번호 등 개인정보를 마스킹·차단 |
| 단어 필터 | 금지어·경쟁사명 등 특정 단어 차단 |
| 컨텍스트 그라운딩 검사 | 응답이 제공된 근거에서 벗어났는지(환각) 점검 |

이렇게 Guardrails는 **안전성**(유해 출력 차단)과 **프라이버시**(PII 보호)를 한꺼번에 책임진다. 모델 자체와 분리된 정책이라, 어떤 FM을 쓰든 동일하게 적용할 수 있다는 점이 강점이다.

> 📚 **사례**: 한 은행이 Bedrock 기반 고객 상담 챗봇을 만들었다. Guardrails로 ① 고객이 입력한 계좌번호·주민번호를 자동 마스킹(PII 필터)하고, ② "투자 종목을 추천해줘" 같은 요청은 규제 위험이 있어 거부 주제로 막고, ③ 욕설·차별 발언을 콘텐츠 필터로 차단했다. 모델을 바꿔 끼워도 이 정책은 그대로 유지돼, 안전 기준을 일관되게 적용할 수 있었다.

## AI Service Cards: 투명성을 위한 공개 문서

**AWS AI Service Cards**는 AWS가 자사 AI 서비스(예: Amazon Rekognition, Textract 등)에 대해 공개하는 문서다. 각 카드는 그 서비스의 **권장 사용 사례, 설계상의 선택, 공정성·정확성에 대한 고려, 한계와 책임 있는 사용 가이드**를 담는다.

이는 **투명성** 원칙의 구현이다. 사용자가 "이 AI 서비스가 어떤 용도에 적합하고, 어디서 조심해야 하는지"를 사전에 알 수 있게 한다.

> 🔍 **더 깊이**: AI Service Cards는 일종의 "영양 성분표"다. 모델을 직접 들여다볼 수는 없어도, AWS가 "이 서비스는 이런 데이터로 평가했고, 이런 한계가 있으며, 이런 용도엔 쓰지 말라"고 공개함으로써 책임 있는 사용을 돕는다. 시험에서 "AWS AI 서비스의 의도된 용도와 한계를 알려주는 투명성 자료는?"이라는 질문이 나오면 AI Service Cards다.

## 원칙 → 도구 빠른 복습

- 편향을 측정하고 결정을 설명하고 싶다 → **SageMaker Clarify**
- 배포된 모델이 시간이 지나며 나빠지는지 감시한다 → **SageMaker Model Monitor**
- 생성형 AI 출력에서 유해·민감 내용을 막는다 → **Bedrock Guardrails**
- AWS AI 서비스의 용도·한계를 공개 문서로 본다 → **AI Service Cards**

## 정리하며

오늘은 어제의 원칙들을 AWS의 구체적 도구로 연결했다. 핵심은 도구와 원칙의 짝을 외우는 것이다. Clarify(편향+설명), Model Monitor(운영 감시), Guardrails(안전+프라이버시), AI Service Cards(투명성). 이 네 짝만 정확히 잡으면 책임 있는 AI 영역의 시나리오 문제 대부분이 풀린다.

내일은 시야를 넓혀 **AI 보안** — IAM 최소권한, 데이터 암호화, PII 보호, PrivateLink, 책임 공유 모델 — 로 넘어간다. 책임 있는 AI가 "윤리·신뢰"라면, 보안은 "기술적 방어"다.

## 📝 연습 문제

**문제 1.** 한 데이터 과학자가 학습 데이터에 특정 연령대가 과도하게 많은지 측정하고, 모델 예측 결과가 집단 간 차별적인지 확인하려 한다. 또 각 예측의 근거(특성 기여도)도 설명하고 싶다. 가장 적절한 AWS 도구는?

A) Amazon Bedrock Guardrails  
B) Amazon SageMaker Clarify  
C) AWS AI Service Cards  
D) Amazon SageMaker Model Monitor  

**정답: B**  
해설: SageMaker Clarify는 학습 전·후 편향 측정과 SHAP 기반 특성 기여도(설명가능성)를 모두 제공한다. A의 Guardrails는 생성형 AI 출력 안전 장치, C의 AI Service Cards는 투명성 문서, D의 Model Monitor는 배포 후 드리프트 감시 도구로 편향 측정·설명이 주 기능이 아니다.

---

**문제 2.** 생성형 AI 챗봇이 사용자 입력에 포함된 주민번호·카드번호를 마스킹하고, 욕설을 차단하며, "투자 종목 추천" 같은 특정 주제를 다루지 않게 하려 한다. 적절한 기능은?

A) Amazon SageMaker Model Monitor  
B) AWS CloudTrail  
C) Amazon Bedrock Guardrails  
D) Amazon SageMaker Clarify  

**정답: C**  
해설: Bedrock Guardrails는 PII 필터(마스킹), 콘텐츠 필터(욕설 차단), 거부 주제(특정 주제 제한)를 한 정책으로 제공한다. A는 모델 품질 감시, B는 API 호출 감사 로깅, D는 편향·설명 도구로 이 요구사항과 맞지 않는다.

---

**문제 3.** Amazon SageMaker Model Monitor에 대한 설명으로 옳은 것은?

A) 배포된 모델의 데이터 드리프트와 품질 저하를 감지해 경보를 보낸다  
B) 문제를 감지하면 모델을 자동으로 재학습·재배포한다  
C) 생성형 AI 출력의 유해 콘텐츠를 차단하는 도구다  
D) AWS AI 서비스의 한계를 공개하는 문서다  

**정답: A**  
해설: Model Monitor는 배포된 엔드포인트의 데이터 품질·모델 품질·편향 드리프트를 감시하고 CloudWatch로 경보를 보낸다. B는 자동 재학습까지 하지 않으며(사람이 결정), C는 Guardrails, D는 AI Service Cards의 역할이라 틀렸다.

**문제 4.** AWS AI Service Cards의 주된 목적은?

A) 모델 학습 속도를 높이는 것  
B) AWS AI 서비스의 권장 용도·한계·공정성 고려사항을 공개해 투명성을 제공하는 것  
C) 개인정보를 암호화하는 것  
D) 모델의 편향을 자동으로 제거하는 것  

**정답: B**  
해설: AI Service Cards는 서비스의 의도된 용도, 설계상의 선택, 한계, 책임 있는 사용 가이드를 공개하는 투명성 문서다. A는 성능과 무관하고, C는 암호화 기능이 아니며, D처럼 편향을 자동 제거하지도 않는다(투명성 정보 제공이 목적).

**문제 5.** 책임 있는 AI 원칙과 이를 지원하는 AWS 도구의 연결이 올바른 것은?

A) 투명성 - Amazon Bedrock Guardrails  
B) 편향·설명가능성 - Amazon SageMaker Clarify  
C) 안전성 - AWS AI Service Cards  
D) 운영 감시 - Amazon Bedrock Guardrails  

**정답: B**  
해설: SageMaker Clarify는 편향 측정과 설명가능성을 함께 지원한다. A는 투명성에 AI Service Cards가 맞고, C는 안전성에 Guardrails가 맞으며, D는 운영 감시에 Model Monitor가 맞으므로 모두 짝이 어긋났다.
