# Day 5 - Week 2 종합: ML 수명주기와 데이터 한눈에 복습

## 📌 핵심 정리

- ML은 **수집 → 준비 → 학습 → 평가 → 배포 → 모니터링**을 도는 순환이고, 그 원을 사람과 데이터가 함께 돌린다.
- 데이터의 **품질과 분리**가 토대다. 대표성이 부족하면 편향이, 테스트 데이터가 새면(누수) 부풀려진 점수가 나온다.
- 지표는 **어떤 실수가 더 비싼가**로 고른다. 헛잡음이 비싸면 정밀도, 놓침이 비싸면 재현율, 균형은 F1. 불균형 데이터의 정확도는 믿지 않는다.
- **과적합**은 학습·테스트 점수의 격차로, **드리프트**는 배포 뒤 시간에 따른 저하로, **누수**는 비현실적으로 높은 평가 점수로 알아챈다.
- 사람은 **라벨링(학습 전) · 피드백(다듬는 중) · HITL 검토(운영 중)** 로 끼어든다. 고위험 결정일수록 사람의 최종 승인을 둔다.

## 한 장으로 보는 Week 2

이번 주는 모델을 직접 코딩하지 않아도 알아야 하는 것, 곧 모델이 태어나 운영되기까지의 흐름과 그 흐름을 떠받치는 데이터의 원리를 훑었다. 오늘은 나흘치를 하나로 엮는다.

```
[ ML 수명주기 — 순환하는 원 (Day 1) ]

 데이터 수집 → 데이터 준비 → 학습 → 평가 → 배포 → 모니터링
      ▲                                              │
      └──────── 성능 저하 시 다시 처음으로 ◄──────────┘

   ├─ 데이터(Day 2): 정형/비정형, 학습·검증·테스트 분리, 품질
   ├─ 평가(Day 3): 정확도·정밀도·재현율, 과적합/과소적합
   └─ 사람(Day 4): 라벨링, 피드백(RLHF), Human-in-the-loop, 반복 개선
```

핵심 메시지 하나만 가져간다면 이것이다 — **ML은 직선이 아니라 원이고, 그 원을 사람과 데이터가 함께 돌린다.**

## 헷갈리기 쉬운 짝 비교

### 정밀도 vs 재현율 — 다시 한 번

이 둘은 시험에서 헷갈리기 쉬운 짝이다. 상황 키워드로 구분한다.

| 상황 키워드 | 우선 지표 | 이유 |
|------------|----------|------|
| "잘못된 경보가 비싸다", "헛잡으면 곤란" | 정밀도 | 거짓 양성(FP)을 줄여야 |
| "절대 놓치면 안 된다", "놓치면 치명적" | 재현율 | 거짓 음성(FN)을 줄여야 |
| "둘 다 균형 있게" | F1 점수 | 정밀도·재현율의 조화 평균 |

> 💡 **관련 이론**: 정밀도와 재현율 중 무엇이 옳다는 정답은 없다. 항상 **"어떤 실수가 더 치명적인가"**라는 비즈니스·윤리적 판단이 선택을 결정한다. 스팸 필터는 정밀도, 암 진단·사기 탐지는 재현율을 우선하는 것이 전형적이다.

### 과적합 vs 과소적합 — 점수로 진단

| 진단 | 학습 점수 | 테스트 점수 | 처방 |
|------|----------|------------|------|
| 과소적합 | 낮음 | 낮음 | 더 복잡한 모델, 더 많은 학습 |
| 적절(좋은 일반화) | 높음 | 높음 | 그대로 좋음 |
| 과적합 | 매우 높음 | 낮음(큰 격차) | 더 많고 다양한 데이터, 모델 단순화 |

> ⚠️ **함정**: 학습 점수만 보고 "99%! 훌륭한 모델"이라 판단하는 것이 대표적인 실수다. 반드시 **테스트 점수와의 격차**를 함께 봐야 한다. 큰 격차는 과적합 경고등이다.

### 데이터 드리프트 vs 데이터 누수

| 개념 | 언제 일어나나 | 결과 |
|------|--------------|------|
| 데이터 드리프트 | 배포 후, 시간이 지나며 분포 변화 | 운영 중 성능 저하 → 재학습 필요 |
| 데이터 누수 | 학습 전, 테스트가 학습에 섞임 | 평가 점수가 비현실적으로 부풀려짐 |

이 둘은 이름이 비슷하지만 시점도 결과도 정반대다. 드리프트는 "운영 중 모델이 낡는 문제", 누수는 "평가가 거짓말하는 문제"다.

## 시험 대비 마지막 점검

> 🎯 **시나리오 1**: "데이터를 모았으니 바로 모델을 학습시키면 되는가?" → 아니다. **데이터 준비(정제·변환·분리)**가 빠졌다. 가장 시간이 많이 드는 단계다.

> 🎯 **시나리오 2**: "사기 거래가 0.1%인 데이터에서 정확도 99.9% 모델을 만들었다. 좋은가?" → 단정할 수 없다. **불균형 데이터에서 정확도는 속기 쉽다.** 재현율 등 다른 지표를 봐야 한다.

> 🎯 **시나리오 3**: "고위험 자동 결정을 AI에게 전부 맡기려 한다." → 위험하다. **Human-in-the-loop**로 사람이 중대한 결정을 검토·승인하게 해야 한다.

## 거꾸로 읽는 수명주기: 증상에서 단계로

지금까지는 단계를 앞에서부터 따라갔다. 시험과 실무는 반대로 온다 — **증상이 먼저 주어지고, 어느 단계의 문제인지 짚어야 한다.**

| 증상 | 의심할 단계 | 진짜 원인 | 조치 |
|------|------------|----------|------|
| 평가 점수는 아주 높았는데 출시 **직후부터** 엉망이다 | 데이터 준비 | 데이터 누수 — 평가가 처음부터 거짓이었다 | 분리를 다시 하고, 예측 시점에 알 수 없는 특성을 뺀다 |
| 출시 때는 좋았는데 **몇 달에 걸쳐 서서히** 나빠진다 | 모니터링 | 데이터 드리프트 — 세상이 변했다 | 최신 데이터를 수집해 재학습한다 |
| 학습 점수만 높고 테스트 점수가 뚝 떨어진다 | 학습 | 과적합 | 더 많고 다양한 데이터, 모델 단순화 |
| 학습 점수부터 낮다 | 학습 | 과소적합(또는 쓸 만한 특성이 없음) | 더 표현력 있는 모델, 더 나은 데이터 |
| 전체 점수는 좋은데 특정 집단에서만 자주 틀린다 | 데이터 수집 | 대표성 부족 → 편향 | 그 집단의 데이터를 보강하고 집단별로 지표를 따로 잰다 |
| 정확도는 높은데 정작 찾으려던 것을 못 잡는다 | 평가 | 불균형 데이터에 지표를 잘못 골랐다 | 재현율·정밀도·F1로 다시 평가한다 |
| 같은 종류의 입력에 정답이 뒤죽박죽으로 학습됐다 | 데이터 준비(라벨링) | 레이블 오류 | 검수하고 여러 사람의 답을 합쳐 확정한다 |
| 모델은 정확한데 잘못된 자동 결정으로 사고가 났다 | 배포 설계 | 고위험 결정에 사람 검토가 없다 | Human-in-the-loop를 넣는다 |

- 첫 두 줄을 가르는 단서는 **시간**이다. "처음부터 안 맞았다"면 누수, "점점 안 맞게 됐다"면 드리프트다.
- 셋째·넷째 줄을 가르는 단서는 **학습 점수**다. 학습 점수가 높으면 과적합, 학습 점수부터 낮으면 과소적합이다.

## 한 사례로 한 바퀴 돌기

보험사가 "허위 청구를 가려내는 모델"을 만드는 경우를 따라가 본다. 여섯 단계마다 이번 주의 개념이 하나씩 걸린다.

| 단계 | 이 사례에서 하는 일 | 걸리는 개념 |
|------|-------------------|------------|
| 수집 | 과거 청구 20,000건을 모은다. 청구서 항목(정형)과 사고 현장 사진·상담 녹취(비정형)가 섞여 있다 | 정형/비정형, 대표성 |
| 준비 | 조사팀이 각 청구에 "허위/정상"을 표시한다. 중복을 지우고 학습·검증·테스트로 나눈다. "조사 완료일"처럼 결과가 난 뒤에 생기는 항목은 뺀다 | 라벨링, 분리, 누수 |
| 학습 | 준비한 데이터로 모델을 학습한다 | 과적합/과소적합 |
| 평가 | 떼어 둔 테스트 데이터로 지표를 계산한다(아래) | 정확도·정밀도·재현율 |
| 배포 | 모델이 허위로 의심한 건은 자동 거절하지 않고 조사 담당자에게 넘긴다 | Human-in-the-loop |
| 모니터링 | 새로운 수법이 등장하면 성능이 떨어진다. 담당자가 교정한 사례를 모아 재학습한다 | 드리프트, 반복 개선 |

**평가 단계의 숫자.** 20,000건 중 실제 허위는 200건(1%)이다. 모델은 250건을 허위로 잡았고 그중 150건이 진짜였다.

| 실제 \ 예측 | 허위라 예측 | 정상이라 예측 | 합계 |
|------------|------------|--------------|------|
| **실제 허위** | TP 150 | FN 50 | 200 |
| **실제 정상** | FP 100 | TN 19,700 | 19,800 |

| 지표 | 이 모델 | "전부 정상"이라고만 답하는 모델 |
|------|--------|-------------------------------|
| 정확도 | (150 + 19,700) ÷ 20,000 = 99.25% | 19,800 ÷ 20,000 = 99.0% |
| 재현율 | 150 ÷ 200 = 75% | 0 ÷ 200 = 0% |
| 정밀도 | 150 ÷ 250 = 60% | 계산 불가(잡은 것이 없음) |

- 정확도로는 두 모델이 0.25%p 차이밖에 나지 않는다. 재현율로 보면 0%와 75%다. **불균형 데이터에서 정확도가 왜 쓸모없는지**가 이 한 줄에 있다.
- 정밀도 60%는 잡은 250건 중 100건이 멀쩡한 청구라는 뜻이다. 그래서 자동 거절이 아니라 **사람 검토**로 넘긴다. 정밀도가 낮은 모델의 헛잡음을 사람이 걸러 주는 구조다.
- 허위 청구를 놓치는 비용이 크다고 판단해 기준선을 느슨하게 잡으면 재현율은 오르고 정밀도는 내려간다. 그만큼 조사 담당자의 검토량이 늘어난다. 지표 선택이 곧 **인력 계획**이 된다.

## 단계마다 어떤 AWS 도구가 붙는가

이번 주에 이름이 나온 서비스를 수명주기 위에 올려 둔다. 자세한 내용은 Week 4·5에서 다룬다.

| 단계 | 서비스·기능 | 하는 일 |
|------|------------|--------|
| 준비(라벨링) | Amazon SageMaker Ground Truth | 사람 작업 인력과 자동 라벨링으로 레이블된 데이터셋을 만든다 |
| 준비·평가(편향 점검) | Amazon SageMaker Clarify | 학습 전 데이터와 학습 후 모델의 편향을 측정하고, 예측에 어떤 특성이 기여했는지 설명한다 |
| 학습·배포 | Amazon SageMaker AI(옛 이름 Amazon SageMaker) | 모델을 학습하고 추론 엔드포인트로 내보낸다 |
| 운영 중 사람 검토 | Amazon Augmented AI(Amazon A2I) | 신뢰도 낮은 예측을 사람 검토로 넘긴다 |
| 모니터링 | Amazon SageMaker Model Monitor | 운영 중인 모델의 데이터 품질·모델 품질·편향 드리프트·특성 기여도 드리프트를 감시하고 벗어나면 알린다 |

- AWS 문서는 현재 Ground Truth·Clarify·A2I·Model Monitor를 신규 고객에게는 열지 않고 기존 고객만 계속 쓸 수 있는 서비스로 안내한다. 시험 대비로는 "**어느 단계의 무슨 일을 맡는 도구인가**"를 기억한다.
- 이 순환을 사람이 매번 손으로 돌리지 않고 **반복 가능한 절차로 자동화해 운영하는 방식**이 MLOps다. 시험 가이드는 MLOps의 개념으로 실험, 반복 가능한 프로세스, 확장 가능한 시스템, 모델 모니터링, 모델 재학습 등을 든다.

## 헷갈리는 짝을 한 질문으로 가르기

| 짝 | 가르는 질문 | 답이 이러면 |
|-----|-----------|------------|
| 드리프트 vs 누수 | 문제가 언제부터 보였나? | 서서히 → 드리프트 / 처음부터 → 누수 |
| 과적합 vs 과소적합 | 학습 점수는 높은가? | 높다 → 과적합 / 낮다 → 과소적합 |
| 정밀도 vs 재현율 | 분모가 무엇인가? | 모델이 잡은 것 → 정밀도 / 실제로 있던 것 → 재현율 |
| 검증 vs 테스트 | 그 점수를 보고 모델을 고치는가? | 고친다 → 검증 / 마지막에 재기만 한다 → 테스트 |
| 대표성 vs 균형 | 무엇이 부족한가? | 현실의 어떤 집단이 빠졌다 → 대표성 / 맞히려는 범주 한쪽이 너무 적다 → 균형 |
| 라벨링 vs HITL 검토 | 사람이 다루는 것이 무엇인가? | 학습할 데이터 → 라벨링 / 모델이 낸 예측 → HITL 검토 |
| 모델 지표 vs 비즈니스 지표 | 누구의 질문에 답하는가? | "잘 맞히나" → 모델 지표 / "이익이 되나" → 비즈니스 지표 |

다음 주에는 생성형 AI 기초로 들어간다. 파운데이션 모델이 무엇인지, LLM이 어떻게 작동하는지, 프롬프트는 어떻게 쓰는지를 다룬다.

## 📖 용어

- **ML 수명주기** : 수집 → 준비 → 학습 → 평가 → 배포 → 모니터링을 계속 되풀이하는 한 바퀴.
- **데이터 드리프트** : 배포한 뒤 시간이 지나며 실제 데이터의 성격이 변해 모델이 서서히 안 맞게 되는 현상.
- **데이터 누수** : 실전에서는 알 수 없는 정보(테스트 데이터, 결과 뒤에 생기는 값)가 학습에 흘러들어 평가 점수가 부풀려지는 사고.
- **대표성** : 데이터가 현실의 여러 집단과 경우를 골고루 담은 정도. 부족하면 편향이 생긴다.
- **정밀도 / 재현율** : 모델이 잡은 것 중 진짜의 비율 / 실제로 있던 것 중 잡아낸 비율.
- **기준선(임계값)** : 모델의 점수가 몇 이상일 때 "맞다"고 판정할지 사람이 정하는 선. 옮기면 정밀도와 재현율이 맞바뀐다.
- **Human-in-the-loop(HITL)** : 중요한 결정이나 모델이 확신하지 못하는 건에 사람의 검토를 끼워 넣는 설계.
- **능동 학습** : 모델이 확신하는 것은 자동으로 처리하고 헷갈리는 것만 사람에게 물어 라벨링 비용을 줄이는 방식.
- **MLOps** : ML 수명주기를 반복 가능하고 자동화된 절차로 운영하는 방식. 모니터링과 재학습을 포함한다.
- **비즈니스 지표** : 사용자당 비용·ROI·고객 피드백처럼 모델이 사업에 이익이 되는지를 재는 잣대.

## 📝 연습 문제

**문제 1.** ML 수명주기에 대한 설명으로 가장 정확한 것은?

A) 수집 → 학습 → 배포로 끝나는 한 방향 직선이다  
B) 수집 → 준비 → 학습 → 평가 → 배포 → 모니터링을 거치며, 성능 저하 시 다시 도는 순환 구조다  
C) 배포가 마지막 단계이며 그 이후로는 아무 작업이 없다  
D) 데이터 준비 단계는 생략해도 무방하다  

**정답: B**  
해설: ML 수명주기는 수집·준비·학습·평가·배포·모니터링의 여섯 단계를 거치며, 데이터 드리프트로 성능이 떨어지면 다시 처음으로 돌아가는 순환 구조다. 한 방향 직선이 아니고(A), 배포가 끝이 아니며(C), 데이터 준비는 가장 중요한 단계 중 하나라 생략할 수 없다(D).

**문제 2.** 다음 중 정밀도(Precision)를 우선해야 하는 상황으로 가장 적절한 것은?

A) 암 환자를 한 명도 놓치면 안 되는 진단 모델  
B) 정상 메일을 스팸으로 잘못 분류하면 곤란한 스팸 필터  
C) 사기 거래를 최대한 많이 잡아야 하는 탐지 시스템  
D) 실종자를 한 명도 놓치면 안 되는 수색 시스템  

**정답: B**  
해설: 정상 메일을 스팸으로 잘못 잡는 것은 거짓 양성(FP)이며, 정밀도는 FP를 줄이는 데 초점을 둔 지표다. 따라서 헛잡음이 비싼 스팸 필터에서 우선한다. 나머지(암 진단·사기 탐지·실종자 수색)는 모두 "놓치면 치명적"인 상황으로 거짓 음성을 줄이는 재현율을 우선한다.

**문제 3.** 학습 데이터 정확도는 98%로 매우 높지만 테스트 데이터 정확도는 64%로 크게 낮다. 이 현상과 그 진단으로 옳은 것은?

A) 과소적합 — 모델이 너무 단순하다  
B) 과적합 — 모델이 학습 데이터를 외워 일반화에 실패했다  
C) 데이터 누수가 전혀 없다는 증거다  
D) 클래스 균형이 완벽하다는 의미다  

**정답: B**  
해설: 학습 점수는 매우 높은데 테스트 점수가 크게 낮은 큰 격차는 과적합의 전형적 신호로, 모델이 학습 데이터를 외웠을 뿐 처음 보는 데이터에 일반화하지 못한 것이다. 과소적합이라면 학습 점수도 낮아야 하며(A 오답), C·D는 이 증상과 무관한 진술이다.

**문제 4.** 데이터 드리프트(Data Drift)와 데이터 누수(Data Leakage)를 구분한 설명으로 옳은 것은?

A) 둘 다 학습 전에 발생하며 동일한 문제다  
B) 드리프트는 배포 후 시간이 지나며 분포가 변하는 문제, 누수는 테스트 데이터가 학습에 섞여 평가가 부풀려지는 문제다  
C) 누수는 운영 중 성능 저하, 드리프트는 평가 점수 부풀림이다  
D) 둘 다 모델 배포 단계에서만 발생한다  

**정답: B**  
해설: 데이터 드리프트는 배포 후 시간이 지나며 데이터 분포가 변해 모델이 낡는 운영상의 문제이고, 데이터 누수는 학습 전 테스트 데이터가 학습에 섞여 평가 점수가 비현실적으로 높아지는 평가상의 문제다. 둘은 시점도 결과도 정반대이므로 A·C·D는 모두 틀렸다.

**문제 5.** 고위험 자동 의사결정 시스템에서 책임 있는 AI를 위해 권장되는 설계는?

A) 모든 결정을 AI가 단독으로 자동 처리하게 한다  
B) 중대한 결정은 Human-in-the-loop로 사람이 검토·승인하게 한다  
C) 데이터 라벨링을 생략해 속도를 높인다  
D) 모니터링을 중단해 비용을 절감한다  

**정답: B**  
해설: 고위험 결정에서는 AI 단독 자동화의 위험(편향·오류를 거를 수 없음)이 크므로, 사람을 고리 안에 두어(Human-in-the-loop) 중대한 결정을 검토·승인하게 하는 것이 책임 있는 AI의 핵심 안전장치다. 라벨링 생략이나 모니터링 중단은 오히려 모델 품질과 안전성을 해치므로 부적절하다.
