# Day 1 - ML 수명주기 개요: 데이터에서 운영까지의 한 바퀴

## 📌 핵심 정리

- ML 수명주기는 **데이터 수집 → 데이터 준비 → 모델 학습 → 모델 평가 → 배포 → 모니터링**의 여섯 단계다.
- 직선이 아니라 **순환하는 원**이다. 배포가 끝이 아니라 모니터링 → 재학습으로 다시 돈다.
- 가장 흔히 빠뜨리는 단계는 **데이터 준비**. 수집 직후 바로 학습하면 안 된다.
- 평가는 반드시 **학습에 쓰지 않은, 본 적 없는 데이터**로 해야 의미가 있다.
- 순환이 필요한 이유는 **데이터 드리프트** — 시간이 지나면 데이터 분포가 변해 모델이 낡는다.

## 왜 "수명주기"라고 부르는가

- AIF-C01은 모델을 직접 코딩하길 기대하지 않는다. **"어떤 단계를 거치며 각 단계가 무엇을 책임지는가"**를 묻는다.
- 일반 소프트웨어 개발: `요구사항 → 설계 → 구현 → 배포`의 비교적 **직선적** 흐름.
- ML: 결과물(모델)이 **데이터로부터 패턴을 학습**하므로, 데이터가 변하면 모델도 낡는다 → 계속 다시 도는 **원(loop)**.

> 💡 **관련 이론**: ML 수명주기가 순환 구조인 핵심 이유는 "데이터 드리프트(Data Drift)" 때문이다. 세상의 데이터 분포는 시간이 지나며 바뀐다(예: 작년의 쇼핑 패턴 ≠ 올해의 쇼핑 패턴). 학습 당시 데이터로 만든 모델은 시간이 지나면 현실과 어긋나기 시작하고, 그래서 다시 데이터를 모으고 재학습하는 순환이 필요하다.

## 여섯 단계 한눈에 보기

| 단계 | 한 줄 정의 | 핵심 질문 |
|------|-----------|----------|
| 데이터 수집(Collection) | 문제에 맞는 원시 데이터를 모은다 | "어떤 데이터가 필요한가?" |
| 데이터 준비(Preparation) | 데이터를 깨끗하게 다듬고 학습 가능한 형태로 만든다 | "데이터가 깨끗하고 쓸 만한가?" |
| 모델 학습(Training) | 알고리즘이 데이터에서 패턴을 배운다 | "모델이 패턴을 잘 익혔는가?" |
| 모델 평가(Evaluation) | 모델이 정말 잘 맞히는지 측정한다 | "처음 보는 데이터에도 잘 맞히는가?" |
| 배포(Deployment) | 모델을 실제 서비스에서 쓸 수 있게 내보낸다 | "사용자가 실제로 쓸 수 있는가?" |
| 모니터링(Monitoring) | 운영 중 모델 성능이 떨어지는지 감시한다 | "여전히 잘 작동하는가?" |

- 이 **순서는 외워 둘 가치**가 있다. "데이터를 모은 다음 바로 학습하면 되는가?" 같은 질문이 나오면 **중간에 '준비'가 빠졌다**는 것을 알아채야 한다.

## 단계별로 풀어 보기

### 1. 데이터 수집 — 모든 것의 출발점

- 모델은 본 적 없는 것을 만들어 내지 못한다. 고양이 사진을 한 장도 못 본 모델은 고양이를 알아볼 수 없다.
- 첫 단계는 **문제에 맞는 데이터를 모으는 것**.
- 출처: 데이터베이스, 로그, 센서, 외부 API, 사용자 입력 등.

> 📚 **사례**: 스팸 메일을 걸러 내는 모델을 만들려면, 먼저 "스팸으로 분류된 메일"과 "정상 메일"을 잔뜩 모아야 한다. 이 두 종류를 충분히 모으지 못하면 그 뒤의 어떤 단계도 의미가 없다.

### 2. 데이터 준비 — 가장 시간이 많이 드는 단계

- 현실 데이터는 지저분하다: 값이 비어 있음, 중복, 형식 제각각, 오타.
- 하는 일: **정제(cleaning)** → 빠진 값 채우기 → 형식 통일 → 모델이 이해할 **숫자 형태로 변환**.
- 이 단계에서 데이터를 **학습용·검증용·테스트용으로 나눈다**(Day 2에서 자세히).

> 💡 **관련 이론**: 실무에서 ML 프로젝트 시간의 70~80%가 이 데이터 준비에 쓰인다는 말이 있다. "Garbage In, Garbage Out(쓰레기를 넣으면 쓰레기가 나온다)"이라는 격언이 ML의 핵심을 찌른다 — 아무리 좋은 알고리즘도 나쁜 데이터로는 좋은 모델을 만들 수 없다.

### 3. 모델 학습 — 패턴을 배우는 단계

- 준비된 데이터를 알고리즘에 넣으면 알고리즘이 **패턴(규칙)을 스스로 찾아낸다**. 이것이 학습(training).
- 예: 집값 예측 모델은 "면적이 넓을수록, 역과 가까울수록 비싸다"는 패턴을 데이터에서 배운다.
- 결과물: **학습된 모델(trained model)**.

### 4. 모델 평가 — 진짜 실력 측정

- 학습 데이터에서 잘 맞히는 건 당연하다(이미 본 데이터니까).
- 중요한 것은 **처음 보는 데이터에서도 잘 맞히는가** → 학습에 쓰지 않은 **테스트 데이터**로 측정한다.
- 이 단계에서 정확도 같은 지표가 등장한다(Day 3 주제).

> ⚠️ **함정**: "학습 데이터에서 99% 정확하니 좋은 모델"이라는 판단은 위험하다. 학습 데이터만 달달 외운 모델은 새 데이터에서 형편없을 수 있다(과적합). 평가는 반드시 **본 적 없는 데이터**로 해야 의미가 있다.

### 5. 배포 — 모델을 세상에 내보내기

- 평가를 통과한 모델을 실제 서비스에 연결한다.
- 예: 앱에서 사진을 올리면 모델이 분류, 쇼핑몰에서 상품을 보면 모델이 추천.
- 정의: **모델을 호출 가능한 형태로 만들어 운영 환경에 올리는** 단계.

### 6. 모니터링 — 끝이 아니라 새로운 시작

- 운영 중인 모델은 시간이 지나며 성능이 떨어질 수 있다(데이터 드리프트).
- 하는 일: **모델이 여전히 잘 작동하는지 감시**하고, 성능이 떨어지면 경보를 울린다.
- 그러면 다시 1단계(데이터 수집)로 돌아가 새 데이터로 재학습한다 → 원이 닫힌다.

## 하나의 순환 그림으로 보기

```
   ┌──────────────────────────────────────────────┐
   │                                                │
   ▼                                                │
[데이터 수집] → [데이터 준비] → [모델 학습] → [모델 평가]
                                                     │
                                                     ▼
                              [모니터링] ◄──────── [배포]
                                  │
                                  └─ 성능 저하 감지 시 다시 데이터 수집으로
```

- 핵심은 **이 흐름이 한 방향으로만 흐르지 않는다**는 것.
- 평가에서 성능이 나쁘면 → 데이터 준비나 학습으로 되돌아간다.
- 모니터링에서 문제를 발견하면 → 처음으로 되돌아간다.
- ML은 본질적으로 **반복적이고 순환적**이다.

> 🎯 **시나리오**: "6개월 전에 배포한 추천 모델의 클릭률이 점점 떨어지고 있다. 무엇을 해야 하는가?" → 모니터링이 성능 저하를 감지한 상황이다. 최신 데이터를 다시 수집하고 모델을 재학습하는, 즉 수명주기를 다시 한 바퀴 도는 것이 정답이다.

내일은 이 수명주기의 연료인 "데이터" 자체를 깊이 들여다본다. 정형/비정형의 차이, 데이터를 셋으로 나누는 이유, 그리고 데이터 품질이 왜 모든 것을 좌우하는지를 다룬다.

## 📖 용어

- **ML 수명주기** : 데이터를 모아 모델을 만들고 배포한 뒤 감시하다 다시 데이터로 돌아오는, 계속 반복되는 한 바퀴.
- **데이터 드리프트** : 시간이 지나면서 실제 데이터의 성격이 변해, 예전 데이터로 배운 모델이 점점 안 맞게 되는 현상.
- **데이터 정제(cleaning)** : 빠진 값·중복·오타·제각각인 형식을 손봐서 데이터를 쓸 만하게 다듬는 일.
- **학습(training)** : 데이터를 알고리즘에 넣어 그 안의 규칙을 스스로 찾아내게 하는 과정.
- **학습된 모델** : 학습이 끝나서 이제 예측에 쓸 수 있게 된 결과물.
- **테스트 데이터** : 학습에 한 번도 쓰지 않고 남겨 둔 데이터. 모델의 진짜 실력을 재는 데 쓴다.
- **과적합** : 학습 데이터를 달달 외워서 그 데이터에는 잘 맞지만 새 데이터에는 형편없어지는 상태.
- **배포(deployment)** : 만든 모델을 실제 서비스에서 불러 쓸 수 있는 형태로 올려놓는 일.
- **모니터링** : 운영 중인 모델이 여전히 잘 맞히는지 계속 지켜보고, 나빠지면 알려 주는 일.
- **Garbage In, Garbage Out** : 나쁜 데이터를 넣으면 나쁜 결과가 나온다는 뜻. 데이터 품질의 중요성을 강조하는 격언.

## 📝 연습 문제

**문제 1.** ML 수명주기에서 데이터를 모은 직후, 모델 학습 전에 반드시 거쳐야 하는 단계는?

A) 모델 배포  
B) 데이터 준비(정제·변환)  
C) 모니터링  
D) 모델 평가  

**정답: B**  
해설: 현실의 원시 데이터는 빠진 값, 중복, 형식 불일치 등으로 지저분하기 때문에, 학습 전에 반드시 데이터를 정제하고 학습 가능한 형태로 다듬는 데이터 준비 단계를 거쳐야 한다. 배포·모니터링은 학습과 평가 이후의 단계이고, 평가는 학습 이후에 수행하므로 학습 직전 단계로는 맞지 않는다.

---

**문제 2.** ML 수명주기를 한 방향으로 끝나는 직선이 아니라 순환하는 원으로 보는 가장 큰 이유는?

A) 모델을 한 번 배포하면 영원히 정확하기 때문  
B) 시간이 지나며 데이터 분포가 변해(드리프트) 모델이 낡으므로 재학습이 필요하기 때문  
C) 알고리즘이 매번 새로 발명되기 때문  
D) 배포 단계가 가장 오래 걸리기 때문  

**정답: B**  
해설: 세상의 데이터 분포는 시간이 지나며 변하고(데이터 드리프트), 학습 당시 데이터로 만든 모델은 점점 현실과 어긋난다. 그래서 모니터링으로 성능 저하를 감지하면 다시 데이터를 모아 재학습하는 순환이 필요하다. 모델은 영원히 정확하지 않으므로 A는 틀렸고, C·D는 순환의 근본 이유와 무관하다.

**문제 3.** 모델 평가 단계에서 성능을 측정할 때 사용해야 하는 데이터로 가장 적절한 것은?

A) 학습에 사용한 데이터  
B) 학습에 사용하지 않은, 처음 보는 데이터  
C) 아직 정제하지 않은 원시 데이터  
D) 배포 후 수집된 데이터만  

**정답: B**  
해설: 모델이 학습 데이터를 잘 맞히는 것은 당연하므로(이미 본 데이터), 진짜 실력은 학습에 쓰지 않은 처음 보는 데이터로 측정해야 한다. 학습 데이터로만 평가하면 외워서 푼 것인지 진짜 일반화한 것인지 구분할 수 없다. 정제하지 않은 원시 데이터는 평가에 부적합하고, 평가는 배포 전에 수행한다.

**문제 4.** "Garbage In, Garbage Out"이라는 격언이 ML 수명주기에서 강조하는 단계는?

A) 배포  
B) 모니터링  
C) 데이터 수집과 준비(데이터 품질)  
D) 모델 평가  

**정답: C**  
해설: 이 격언은 입력 데이터의 품질이 나쁘면 아무리 좋은 알고리즘을 써도 결과(모델)가 나쁘다는 뜻으로, 데이터를 모으고 정제하는 단계의 중요성을 강조한다. 배포·모니터링·평가는 데이터 품질이 확보된 이후의 단계로, 이 격언의 직접적 대상이 아니다.

**문제 5.** 6개월 전 배포한 모델의 정확도가 운영 중 점점 떨어지고 있다. ML 수명주기 관점에서 가장 올바른 대응은?

A) 모델을 즉시 폐기하고 ML 사용을 중단한다  
B) 아무 조치도 하지 않는다, 모델은 시간이 지나면 저절로 회복된다  
C) 모니터링이 감지한 성능 저하이므로 최신 데이터를 수집해 재학습한다  
D) 학습 데이터에서의 정확도만 다시 확인한다  

**정답: C**  
해설: 운영 중 성능 저하는 모니터링 단계가 잡아내야 할 신호이며, 데이터 드리프트가 원인일 가능성이 높다. 따라서 수명주기를 한 바퀴 다시 돌려 최신 데이터를 수집하고 재학습하는 것이 정석이다. 모델이 저절로 회복되지 않으므로 B는 틀렸고, 학습 데이터 정확도는 현재의 운영 문제와 무관하므로 D도 부적절하다.
