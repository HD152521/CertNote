# Day 4 - ML 개발에서 사람의 역할: 라벨링, 피드백, 반복 개선

## 📌 핵심 정리

- ML은 **사람과 기계의 협업**이다. "기계가 알아서 다 한다"는 인상은 현실과 정반대에 가깝다.
- **라벨링**: 사람이 데이터에 정답을 붙이는 작업. **지도 학습의 토대**이고, 라벨이 틀리면 모델도 틀리게 배운다.
- **피드백**: 사람이 모델의 답을 평가·교정한다. 생성형 AI에서는 **RLHF**가 대표 기법이다.
- **Human-in-the-loop(HITL)**: 중요하거나 위험한 결정일수록 사람이 최종 검토·승인한다. 책임 있는 AI의 핵심 안전장치.
- ML은 "완성"되는 게 아니라 **"계속 개선"**된다. 사람 손을 떼면 드리프트로 모델이 낡는다.

## 왜 사람이 필요한가

- AIF-C01은 이 주제를 **"Human-in-the-loop(사람이 개입하는 고리)"** 개념과 책임 있는 AI의 맥락에서 자주 묻는다.
- **"이 사진은 고양이"라는 정답은 누가 알려 주는가?** 기계가 처음부터 아는 것이 아니라 사람이 알려 줘야 한다.
- 모델이 내놓은 답이 맞는지 틀린지, 무엇이 부적절한지를 **최종 판단하는 것도 사람**이다.

> 💡 **관련 이론**: ML 학습 방식은 크게 **지도 학습(Supervised Learning)**과 **비지도 학습(Unsupervised Learning)**으로 나뉜다. 지도 학습은 "입력 + 정답(라벨)" 쌍으로 배우고, 비지도 학습은 정답 없이 데이터 구조만으로 배운다. 사람의 라벨링이 특히 중요한 것은 지도 학습이다. 시험 입문 수준에서는 "라벨이 있으면 지도, 없으면 비지도"라는 구분을 기억하면 된다.

## 1. 데이터 라벨링 — 정답을 붙이는 작업

- 원시 데이터에 **"이건 무엇이다"라는 정답표(label)를 붙이는** 작업.
- 지도 학습 모델은 이 라벨을 보고 패턴을 배운다.

| 데이터 유형 | 라벨링 예시 |
|------------|-----------|
| 이미지 | "이 사진은 고양이/강아지" 표시, 사진 속 물체에 상자 치기 |
| 텍스트 | "이 리뷰는 긍정/부정", 문장 속 사람 이름 표시 |
| 음성 | 녹음을 듣고 텍스트로 받아쓰기 |

- 라벨링은 **느리고 비싸고 사람의 노동이 많이 드는** 작업이다(수만 장 사진에 일일이 라벨을 붙이는 일을 상상해 보라).
- 그래서 **라벨링 품질 관리**가 ML 프로젝트의 큰 과제다.

> ⚠️ **함정**: 라벨이 틀리면 모델도 틀리게 배운다. 만약 라벨러가 강아지 사진에 "고양이"라고 잘못 붙이면, 모델은 그 잘못된 정답을 그대로 학습한다. 그래서 여러 사람이 같은 데이터를 라벨링해 일치도를 확인하거나, 검수 단계를 두어 라벨 품질을 관리한다.

> 📚 **사례**: AWS에는 **Amazon SageMaker Ground Truth**라는 라벨링 도구가 있다. 사람 라벨러를 관리하고, 자동 라벨링으로 사람의 일을 덜어 주는 기능을 제공한다. 시험에서는 "라벨링을 돕는 AWS 서비스가 있다" 정도만 알면 충분하다.

## 2. 피드백 — 모델의 답을 평가하고 교정하기

- 모델이 답을 내놓으면 사람은 그 답을 **평가하고 교정**한다. 이 피드백이 모델 개선의 핵심 연료다.
- 특히 **생성형 AI에서 사람의 피드백은 결정적**이다.
- 피드백은 한 번으로 끝나지 않는다: 모델이 답함 → 사람이 평가 → 모델 개선 → 다시 답함의 **고리(loop)**가 계속 돈다.

> 💡 **관련 이론**: 생성형 AI(대규모 언어 모델)를 다듬는 대표 기법이 **RLHF(Reinforcement Learning from Human Feedback, 사람 피드백 기반 강화학습)**다. 사람이 모델의 여러 답변 중 어느 것이 더 좋은지 평가하면, 그 평가를 바탕으로 모델이 "사람이 선호하는 방향"으로 조정된다. 챗봇이 더 도움이 되고 덜 위험하게 답하도록 만드는 데 이 사람 피드백이 핵심이다.

## 3. Human-in-the-loop — 사람이 고리 안에 있다

- **HITL**은 ML 시스템의 작동 과정에 **사람의 판단을 의도적으로 끼워 넣는 설계**다.
- 모델이 확신이 없거나, 결정이 중요하거나, 위험이 큰 경우 → **자동으로 결정하지 않고 사람에게 넘긴다**.

| 상황 | HITL이 하는 일 |
|------|---------------|
| 모델이 확신 없는 판단 | 사람에게 검토 요청 |
| 고위험 결정(대출 거절, 의료) | 사람이 최종 승인 |
| 모델이 틀린 답 | 사람이 교정 → 다음 학습에 반영 |
| 부적절·위험한 출력 | 사람이 걸러 냄 |

> 💡 **관련 이론**: HITL은 책임 있는 AI(Responsible AI)의 핵심 안전장치다. AI가 모든 것을 자동으로 결정하게 두면, 편향된 판단이나 위험한 실수를 걸러 낼 방법이 없다. 사람을 고리 안에 두면 모델의 한계를 보완하고, 잘못된 결정에 대한 책임 소재도 분명해진다. "중요하거나 위험한 결정일수록 사람의 개입을 강화한다"가 원칙이다.

> 🎯 **시나리오**: "AI가 대출 신청을 자동 심사하는데, 거절 결정이 사람의 삶에 큰 영향을 준다. 어떻게 설계해야 하는가?" → 고위험 결정이므로 Human-in-the-loop를 적용해, 최소한 거절 같은 중대한 결정은 사람이 최종 검토·승인하도록 해야 한다.

## 4. 반복 개선 — ML은 한 번에 완성되지 않는다

- Day 1의 순환하는 수명주기를 돌리는 힘의 큰 부분이 **사람의 반복 개선**이다.
- 배포 후 사람이 실제 사용 결과를 보고 → 틀린 사례를 모으고 → 새 데이터에 라벨을 붙이고 → 재학습한다.

```
[ 사람이 돌리는 개선 고리 ]

  라벨링 → 학습 → 모델이 답함 → 사람이 평가/교정
    ▲                                    │
    │                                    ▼
    └──── 새 라벨·피드백 반영해 재학습 ◄───┘
```

- 핵심: **ML은 "완성"되는 것이 아니라 "계속 개선"되는 것**. 사람의 라벨·피드백·검토가 이 고리를 살아 있게 한다.

> ⚠️ **함정**: "모델을 한 번 잘 만들면 사람 손이 더 안 가도 된다"는 생각은 위험하다. 데이터가 변하고(드리프트), 새로운 상황이 등장하며, 모델은 낡는다. 사람의 지속적인 모니터링과 피드백 없이는 좋은 모델도 시간이 지나면 무너진다.

내일은 이번 주의 모든 내용 — ML 수명주기와 데이터 — 을 한데 모아 복습하고, 시험에서 자주 나오는 포인트를 정리한다.

## 📖 용어

- **데이터 라벨링** : 원시 데이터에 "이건 무엇이다"라는 정답을 사람이 붙여 주는 작업.
- **라벨(label)** : 데이터에 붙인 정답표. 모델이 학습할 때 기준으로 삼는 값이다.
- **지도 학습** : 입력과 정답이 짝을 이룬 데이터로 배우는 방식. 라벨이 반드시 필요하다.
- **비지도 학습** : 정답 없이 데이터 자체의 구조나 묶임만 보고 배우는 방식.
- **RLHF** : 사람이 모델 답변의 좋고 나쁨을 평가해, 그 평가로 모델을 사람이 원하는 방향으로 조정하는 기법.
- **Human-in-the-loop(HITL)** : AI가 혼자 결정하게 두지 않고, 중요한 대목에 사람의 판단을 끼워 넣는 설계.
- **책임 있는 AI** : AI를 공정하고 안전하고 설명 가능하게 만들려는 원칙과 실천을 묶어 부르는 말.
- **Amazon SageMaker Ground Truth** : 사람 라벨러를 관리하고 자동 라벨링도 돕는 AWS의 라벨링 서비스.
- **반복 개선** : 배포 → 사용 결과 관찰 → 라벨·피드백 반영 → 재학습을 계속 돌려 모델을 조금씩 낫게 만드는 일.
- **라벨 일치도** : 같은 데이터를 여러 사람이 라벨링했을 때 얼마나 같은 답을 붙였는지. 라벨 품질을 재는 방법.

## 📝 연습 문제

**문제 1.** 지도 학습(Supervised Learning)에서 사람이 데이터에 "이것은 고양이/강아지"라는 정답을 붙이는 작업을 무엇이라 하는가?

A) 데이터 드리프트(Data Drift)  
B) 데이터 라벨링(Data Labeling)  
C) 과적합(Overfitting)  
D) 모델 배포(Deployment)  

**정답: B**  
해설: 원시 데이터에 "무엇인지"를 나타내는 정답(label)을 붙이는 작업이 데이터 라벨링이며, 지도 학습 모델은 이 라벨을 보고 패턴을 학습한다. 데이터 드리프트는 분포 변화, 과적합은 학습 데이터를 외운 상태, 배포는 모델을 서비스에 올리는 단계로 모두 다른 개념이다.

---

**문제 2.** 대규모 언어 모델(생성형 AI)을 사람이 선호하는 방향으로 다듬기 위해, 사람이 모델의 답변을 평가하고 그 평가를 학습에 반영하는 대표 기법은?

A) 데이터 누수(Data Leakage)  
B) RLHF(사람 피드백 기반 강화학습)  
C) 비지도 학습(Unsupervised Learning)  
D) 클래스 불균형 처리  

**정답: B**  
해설: RLHF는 사람이 모델의 여러 답변 중 더 나은 것을 평가하고, 그 피드백을 바탕으로 모델을 사람이 선호하는 방향으로 조정하는 기법으로, 생성형 AI를 더 유용하고 안전하게 만드는 데 핵심이다. 데이터 누수는 평가 오염 문제, 비지도 학습은 정답 없는 학습, 클래스 불균형 처리는 별개의 데이터 문제다.

---

**문제 3.** 대출 거절처럼 사람의 삶에 큰 영향을 주는 고위험 결정에 대해, AI가 단독으로 자동 결정하지 않고 사람이 최종 검토·승인하도록 설계하는 접근을 무엇이라 하는가?

A) 데이터 라벨링  
B) Human-in-the-loop(사람 개입 고리)  
C) 과소적합  
D) 데이터 드리프트  

**정답: B**  
해설: Human-in-the-loop는 ML 시스템의 작동 과정에 사람의 판단을 의도적으로 끼워 넣는 설계로, 특히 위험하거나 중대한 결정에서 사람이 최종 검토·승인하게 하여 모델의 한계를 보완하고 책임 소재를 분명히 한다. 나머지 선택지는 라벨링·학습 상태·분포 변화로 이 설계 개념과 다르다.

---

**문제 4.** 데이터 라벨링 품질이 모델에 미치는 영향으로 가장 정확한 것은?

A) 라벨이 틀려도 모델은 스스로 올바르게 학습한다  
B) 잘못된 라벨은 모델이 잘못된 정답을 그대로 학습하게 만든다  
C) 라벨 품질은 모델 성능과 무관하다  
D) 라벨링은 비지도 학습에서만 필요하다  

**정답: B**  
해설: 지도 학습 모델은 사람이 붙인 라벨을 정답으로 받아들여 학습하므로, 라벨이 틀리면 그 잘못된 정답을 그대로 배운다. 따라서 라벨 품질은 모델 성능에 직접적인 영향을 준다. 라벨링은 정답이 필요한 지도 학습에서 핵심이며 비지도 학습은 정답 없이 학습하므로 D도 틀렸다.

**문제 5.** "모델을 한 번 잘 만들면 더 이상 사람의 개입이 필요 없다"는 주장에 대한 가장 적절한 반박은?

A) 옳다, 잘 만든 모델은 영원히 정확하다  
B) 데이터가 변하고 모델이 낡으므로, 지속적인 모니터링·피드백·재학습이 필요하다  
C) 사람의 개입은 학습 속도만 늦출 뿐 도움이 안 된다  
D) 비지도 학습은 사람이 전혀 필요 없으므로 옳다  

**정답: B**  
해설: 시간이 지나며 데이터 분포가 변하고(드리프트) 새로운 상황이 등장해 모델은 낡는다. 따라서 사람의 지속적인 모니터링, 피드백, 재학습이 있어야 모델이 계속 잘 작동한다. 영원히 정확한 모델은 없으므로 A는 틀렸고, 사람의 개입은 모델 품질에 필수적이므로 C도 틀렸다.
