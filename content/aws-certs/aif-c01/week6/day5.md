# Day 5 - D-Day 마무리: 시험 구성, 키워드→서비스 번역표, 자주 틀리는 함정

6주의 여정이 끝났다. 마지막 글은 "더 배우는" 시간이 아니라, 시험장에 들고 들어갈 **한 장짜리 요약**을 만드는 시간이다. 시험이 어떻게 생겼는지, 문제 속 키워드를 어떻게 서비스로 번역하는지, 그리고 똑똑한 사람도 자주 빠지는 함정이 무엇인지를 정리한다.

시험 전날에는 새 내용을 욱여넣기보다, 지금까지 다진 개념의 **경계선과 매핑**을 다시 훑는 것이 점수에 훨씬 유리하다. 오늘 글을 그 마지막 점검표로 쓰자.

## 시험 구성: 무엇을 마주하게 되나

AWS Certified AI Practitioner(AIF-C01)의 기본 형태는 다음과 같다.

| 항목 | 내용 |
|------|------|
| **문항 수** | 65문항 (이 중 약 15문항은 채점되지 않는 평가용) |
| **시간** | 90분 |
| **합격 점수** | 1000점 만점에 **700점** |
| **문제 형식** | 객관식(단일 정답), 복수 응답, 기타 보조 유형 |
| **수준** | Foundational(기초) |

핵심은 "채점용 50문항만 잘 맞히면 된다"는 점이다. 모르는 문제 한두 개에 시간을 다 쓰지 말고, 아는 문제부터 빠르게 확보하는 전략이 합격을 가른다.

> 💡 **관련 이론**: 65문항 중 약 15문항이 채점되지 않는 이유는, AWS가 향후 시험에 쓸 새 문항을 미리 테스트하기 때문이다. 어떤 문항이 평가용인지는 표시되지 않으므로, 모든 문제를 똑같이 진지하게 풀되 한 문제에 과하게 매달리지 않는 것이 맞다. 90분/65문항이면 한 문항당 약 1분 20초이니, 막히면 표시해 두고 넘어간 뒤 마지막에 돌아오는 페이스 관리가 중요하다.

## 도메인별 출제 비중

시험은 4개 도메인으로 구성되며 비중이 다르다. 비중이 큰 곳에 복습 시간을 더 쓰는 것이 합리적이다.

| 도메인 | 대략적 비중 |
|--------|-------------|
| AI/ML 기초 개념 | 약 20% |
| 생성형 AI 기초 | 약 24% |
| 파운데이션 모델 응용 | 약 28% |
| 책임 있는 AI + 보안·규정·거버넌스 | 약 28% |

생성형 AI와 그 응용(Bedrock·서비스 매핑), 책임 있는 AI/보안이 합쳐서 절반을 훌쩍 넘는다. 이 글의 번역표와 함정 정리가 바로 그 핵심을 겨눈다.

## "키워드 → 서비스" 번역표

시험 문제는 늘 "상황"을 묘사한다. 그 상황 속 키워드를 서비스로 번역하는 표를 머리에 새겨라. 이것이 가장 강력한 무기다.

| 문제 속 키워드 | 정답 서비스 |
|----------------|-------------|
| 문서/스캔본에서 텍스트·표 **추출**, OCR | **Amazon Textract** |
| 이미지·영상 속 객체/얼굴/부적절 콘텐츠 **인식** | **Amazon Rekognition** |
| 텍스트 **감정 분석**, 엔터티/언어 추출 | **Amazon Comprehend** |
| **음성 → 텍스트**(STT), 통화 녹취 | **Amazon Transcribe** |
| **텍스트 → 음성**(TTS), 음성 안내 | **Amazon Polly** |
| 언어 **번역** | **Amazon Translate** |
| **챗봇**/음성봇, 인텐트 인식 | **Amazon Lex** (또는 Amazon Q Business) |
| 상품/콘텐츠 **개인화 추천** | **Amazon Personalize** |
| 시계열 **수요·매출 예측** | **Amazon Forecast** |
| 사내 문서 **지능형 검색** | **Amazon Kendra** |
| 여러 **FM 호스팅**·단일 API로 호출 | **Amazon Bedrock** |
| **커스텀 모델 직접 학습**·배포·MLOps | **Amazon SageMaker** |
| 사내 데이터 기반 **업무 AI 비서** | **Amazon Q Business** |
| **코딩 보조**, 코드 생성·설명 | **Amazon Q Developer** |
| 모델/데이터 **편향 탐지·설명가능성** | **SageMaker Clarify** |
| 생성형 AI 출력 **안전 정책**(유해/PII/환각) | **Guardrails for Amazon Bedrock** |
| 모델 용도·한계·공정성 **투명성 문서** | **AWS AI Service Cards** |

> 💡 **관련 이론**: 같은 데이터 타입이라도 "동사"가 서비스를 가른다. 텍스트를 **꺼내면** Textract, **분석하면** Comprehend, **생성하면** Bedrock/LLM이다. 그래서 문제를 읽을 때 명사("문서", "음성")보다 동사("추출", "분석", "변환", "생성", "추천", "예측")에 먼저 밑줄을 긋는 습관이 정답률을 가장 크게 끌어올린다.

## 자주 틀리는 함정 정리

마지막으로, 기초 수준임에도 사람들이 반복해서 틀리는 함정들을 모았다.

- **Textract vs Comprehend**: 글자를 "추출"하면 Textract, 글자의 "의미·감정 분석"이면 Comprehend. 헷갈리면 동사를 보라.
- **SageMaker vs Bedrock**: 모델을 "직접 만들면" SageMaker, FM을 "빌려 쓰면" Bedrock. "커스텀 학습"이 보이면 SageMaker.
- **Few-shot vs 파인튜닝**: Few-shot은 프롬프트 안 예시(가중치 변경 없음), 파인튜닝은 가중치 변경. "예시를 보여준다"면 Few-shot.
- **temperature 방향**: 낮을수록 일관·결정적, 높을수록 창의·다양. 정확성 필요 → 낮춤.
- **책임 공유 모델**: 데이터·권한·암호화 설정은 거의 항상 "고객" 책임.
- **환각 완화**: 더 큰 모델이 아니라 **RAG**(근거 제공)가 정석.
- **RAG vs 파인튜닝**: 모르는 "정보"가 필요하면 RAG, 깊은 "말투·도메인 행동" 내재화면 파인튜닝.
- **Lex vs Polly vs Transcribe**: 대화(챗봇)=Lex, 음성 만들기=Polly, 음성 받아쓰기=Transcribe.
- **AI 서비스 vs SageMaker**: "ML 전문가 없이 빠르게"면 관리형 AI 서비스, "직접 통제·커스텀"이면 SageMaker.

> 💡 **관련 이론**: 함정 문제는 대부분 "비슷하지만 다른 두 선택지"를 나란히 둔다. 출제자는 키워드 하나(예: "추출" vs "분석")로 정답을 가른다. 그래서 시험장에서 두 서비스가 다 그럴듯해 보이면, 문제 문장으로 돌아가 "정확히 어떤 작업을 요구하는가"의 동사를 다시 확인하는 것이 가장 안전한 검증법이다.

## 정리하며 — 그리고 시험장으로

6주를 정리하면 이렇다. **기초 개념(포함 관계·학습 방식·토큰/임베딩)**으로 토대를 잡고, **AWS AI 서비스 매핑**으로 표면 문제를 잡고, **책임 있는 AI·보안·거버넌스**로 가치 판단 문제를 잡는다. 시험은 65문항 90분, 700점이면 합격이다. 모르는 문제에 매달리지 말고, **동사를 잡아 서비스로 번역하고**, 함정 두 선택지에선 문제 문장으로 돌아가 동사를 재확인하라.

여기까지 왔다면 준비는 충분하다. 마지막으로 이 번역표와 함정 목록을 한 번 더 훑고, 가벼운 마음으로 시험장에 들어가자. 합격을 응원한다.

## 📝 연습 문제

**문제 1.** AIF-C01 시험의 구성으로 옳은 것은?

A) 100문항, 60분, 합격 800점  
B) 65문항, 90분, 합격 700점(1000점 만점)  
C) 50문항, 120분, 합격 600점  
D) 30문항, 45분, 합격 900점  

**정답: B**  
해설: AIF-C01은 65문항을 90분 동안 풀며, 1000점 만점에 700점 이상이면 합격한다. 65문항 중 약 15문항은 채점되지 않는 평가용이다. 나머지 보기는 문항 수·시간·합격 점수가 실제와 다르다.

---

**문제 2.** "스캔한 송장(invoice)에서 금액과 항목 표를 자동으로 추출"하라는 문제가 나왔다. 어떤 서비스를 떠올려야 하는가?

A) Amazon Comprehend  
B) Amazon Textract  
C) Amazon Lex  
D) Amazon Polly  

**정답: B**  
해설: 핵심 동사가 "추출"이고 대상이 스캔 문서이므로 Textract다. Comprehend는 텍스트의 의미·감정 분석, Lex는 챗봇, Polly는 음성 합성으로 문서에서 텍스트·표를 꺼내는 작업과 맞지 않는다.

---

**문제 3.** 두 선택지 Amazon SageMaker와 Amazon Bedrock이 모두 그럴듯해 보인다. 문제에 "자사 데이터로 모델을 처음부터 직접 학습시킨다"는 표현이 있다면 정답은?

A) Bedrock — 기성 FM을 빌려 쓰므로  
B) SageMaker — 커스텀 모델을 직접 학습·배포하므로  
C) 둘 다 정답이다  
D) 둘 다 학습 기능이 없다  

**정답: B**  
해설: "처음부터 직접 학습"은 커스텀 모델 구축을 뜻하므로 SageMaker다. Bedrock은 사전학습된 FM을 활용하는 서비스라 직접 학습 요구와 맞지 않고, 두 서비스는 목적이 분명히 달라 "둘 다"는 틀리며 SageMaker는 학습이 핵심 기능이다.

---

**문제 4.** 생성형 AI 챗봇의 환각을 줄이라는 문제에서, 정답으로 가장 적절한 접근은?

A) 모델 파라미터 수를 무조건 늘린다  
B) 신뢰할 수 있는 문서를 검색해 답의 근거로 제공하는 RAG를 적용한다  
C) temperature를 최대로 높인다  
D) 프롬프트를 무조건 길게 만든다  

**정답: B**  
해설: 환각 완화의 정석은 더 큰 모델이 아니라, 실제 근거 문서를 제공해 모델이 그 안에서 답하게 하는 RAG다. 모델 크기 확대는 환각을 보장 없이 줄이고, temperature 상승은 오히려 자유로운 생성을 늘리며, 프롬프트 길이는 환각 자체를 줄이지 못한다.

**문제 5.** 시험에서 비슷해 보이는 두 서비스(예: Textract와 Comprehend) 중 정답을 고를 때 가장 안전한 검증 방법은?

A) 알파벳 순서로 앞선 것을 고른다  
B) 문제 문장의 핵심 동사(추출/분석/생성 등)를 다시 확인해 작업 종류를 판별한다  
C) 더 비싼 서비스를 고른다  
D) 항상 가장 최신 서비스를 고른다  

**정답: B**  
해설: 함정 문제는 키워드 하나로 정답이 갈리므로, 문제 속 동사를 다시 확인해 "어떤 작업을 요구하는가"를 판별하는 것이 가장 안전하다. 알파벳 순서·가격·출시 시점은 작업 적합성과 무관한 기준이라 정답 근거가 될 수 없다.
