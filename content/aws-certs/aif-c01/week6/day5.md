# Day 5 - D-Day 마무리: 시험 구성, 키워드→서비스 번역표, 자주 틀리는 함정

## 📌 핵심 정리

- AIF-C01 은 65문항(채점 50 + 비채점 15), 90분, 100~1,000점 척도에서 **700점**이 합격선이다. 도메인은 다섯 개, 비중은 20/24/28/14/14% 다.
- 문항당 약 1분 20초다. 막히면 잠정 답을 고르고 표시한 뒤 넘어간다. 무응답은 오답이고 틀려도 감점은 없다.
- 문제는 늘 "상황"을 묘사한다. 명사보다 **동사**(추출·분석·변환·생성·추천·예측)에 밑줄을 긋고 서비스로 번역한다.
- 함정은 대부분 "비슷하지만 다른 두 보기"다. 둘 다 그럴듯하면 문제 문장으로 돌아가 요구하는 작업을 다시 확인한다.
- 시험 전날은 새 내용 대신 번역표와 함정 목록, 오답 노트를 본다. 불합격하면 14일 뒤 다시 응시할 수 있다.

## 시험 구성: 무엇을 마주하게 되나

6주의 여정이 끝났다. 마지막 글은 "더 배우는" 시간이 아니라 시험장에 들고 들어갈 **한 장짜리 요약**을 만드는 시간이다. 시험 전날에는 새 내용을 욱여넣기보다 지금까지 다진 개념의 **경계선과 매핑**을 다시 훑는 것이 점수에 유리하다.

AWS Certified AI Practitioner(AIF-C01)의 기본 형태는 다음과 같다.

| 항목 | 내용 |
|------|------|
| **문항 수** | 65문항 (이 중 15문항은 채점되지 않는 평가용) |
| **시간** | 90분 |
| **합격 점수** | 1000점 만점에 **700점** (100~1,000 척도) |
| **문제 형식** | 객관식(단일 정답), 복수 응답, 순서 배열, 짝짓기 |
| **수준** | Foundational(기초) |
| **응시료** | 100 USD |
| **응시 방식** | Pearson VUE 시험 센터 또는 온라인 감독 시험 |
| **자격 유효 기간** | 3년 |

핵심은 "채점용 50문항만 잘 맞히면 된다"는 점이다. 모르는 문제 한두 개에 시간을 다 쓰지 말고, 아는 문제부터 빠르게 확보하는 전략이 합격을 가른다.

> 💡 **관련 이론**: 65문항 중 15문항이 채점되지 않는 이유는, AWS 가 향후 시험에 쓸 새 문항을 미리 테스트하기 때문이다. 어떤 문항이 평가용인지는 표시되지 않으므로, 모든 문제를 똑같이 진지하게 풀되 한 문제에 과하게 매달리지 않는 것이 맞다. 90분/65문항이면 한 문항당 약 1분 20초이니, 막히면 표시해 두고 넘어간 뒤 마지막에 돌아오는 페이스 관리가 중요하다.

- 응시 가능 언어 목록은 바뀔 수 있다. 한국어 응시가 제공되며, 정확한 목록은 시험을 예약할 때 공식 페이지에서 확인한다.
- 시험 가이드가 그리는 응시 대상은 AWS 에서 AI/ML 기술을 최대 6개월 정도 접해 본 사람, 그리고 AI/ML 솔루션을 **만들기보다 쓰는** 사람이다. 모델 코딩, 하이퍼파라미터 튜닝, 파이프라인 구축, 수학적 분석은 범위 밖이라고 밝힌다. 계산이나 코드를 요구하는 것처럼 보이는 문제도 실제로는 개념 구분을 묻는다.

## 점수는 어떻게 매겨지나

| 규칙 | 내용 | 시험장에서의 의미 |
|------|------|------|
| 척도 점수 | 결과는 100~1,000 의 척도 점수로 나온다. 시험 폼마다 조금씩 다른 난이도를 보정하려는 것이다 | 700점이 "정답률 70%"를 뜻하지는 않는다. 맞힌 개수로 합격을 역산하지 않는다 |
| 보상 채점 | 도메인별 합격선이 없고 전체 점수만 본다 | 약한 도메인을 강한 도메인으로 메울 수 있다 |
| 비채점 문항 | 15문항은 통계 수집용이며 표시되지 않는다 | 낯설고 어려운 문항에 흔들리지 않는다 |
| 무응답 | 답하지 않은 문항은 오답이다 | 빈 답을 남기지 않는다 |
| 추측 | 틀려도 감점이 없다 | 모르면 소거한 뒤 고른다 |
| 복수 응답·순서 배열·짝짓기 | 전부 맞혀야 점수가 된다 | 요구한 개수와 순서를 끝까지 확인한다 |

- 성적표에는 도메인별 성취 수준이 표로 나올 수 있다. 도메인마다 문항 수가 달라 문항이 적은 도메인의 평가는 흔들리기 쉬우므로, 시험 가이드도 도메인별 피드백은 신중하게 해석하라고 적는다.

## "키워드 → 서비스" 번역표

시험 문제는 늘 "상황"을 묘사한다. 그 상황 속 키워드를 서비스로 번역하는 표를 머리에 새긴다. 이것이 가장 강력한 무기다.

| 문제 속 키워드 | 정답 서비스 |
|----------------|-------------|
| 문서/스캔본에서 텍스트·표 **추출**, OCR | **Amazon Textract** |
| 이미지·영상 속 객체/얼굴/부적절 콘텐츠 **인식** | **Amazon Rekognition** |
| 텍스트 **감정 분석**, 엔터티/언어 추출 | **Amazon Comprehend** |
| **음성 → 텍스트**(STT), 통화 녹취 | **Amazon Transcribe** |
| **텍스트 → 음성**(TTS), 음성 안내 | **Amazon Polly** |
| 언어 **번역** | **Amazon Translate** |
| **챗봇**/음성봇, 인텐트 인식 | **Amazon Lex** (또는 Amazon Q Business) |
| 상품/콘텐츠 **개인화 추천** | **Amazon Personalize** |
| 시계열 **수요·매출 예측** | **Amazon Forecast** |
| 사내 문서 **지능형 검색** | **Amazon Kendra** |
| 여러 **FM 호스팅**·단일 API로 호출 | **Amazon Bedrock** |
| **커스텀 모델 직접 학습**·배포·MLOps | **Amazon SageMaker** |
| 사내 데이터 기반 **업무 AI 비서** | **Amazon Q Business** |
| **코딩 보조**, 코드 생성·설명 | **Amazon Q Developer** |
| 모델/데이터 **편향 탐지·설명가능성** | **SageMaker Clarify** |
| 생성형 AI 출력 **안전 정책**(유해/PII/환각) | **Guardrails for Amazon Bedrock** |
| 모델 용도·한계·공정성 **투명성 문서** | **AWS AI Service Cards** |

> 💡 **관련 이론**: 같은 데이터 타입이라도 "동사"가 서비스를 가른다. 텍스트를 **꺼내면** Textract, **분석하면** Comprehend, **생성하면** Bedrock/LLM 이다. 그래서 문제를 읽을 때 명사("문서", "음성")보다 동사("추출", "분석", "변환", "생성", "추천", "예측")에 먼저 밑줄을 긋는 습관이 정답률을 가장 크게 끌어올린다.

- 이름이 두 가지로 돌아다니는 것이 있다. **Guardrails for Amazon Bedrock = Amazon Bedrock Guardrails**, **Amazon SageMaker = Amazon SageMaker AI** 다. 어느 쪽으로 나와도 같은 것이다.

번역표의 나머지 절반은 생성형 AI 의 **방법**과 보안·거버넌스다.

| 문제 속 키워드 | 정답 |
|------|------|
| 최신·사내 문서로 답하게, 재학습 없이, 출처 표시 | **RAG** (Amazon Bedrock Knowledge Bases) |
| 여러 단계로 API 를 호출해 실제 작업을 수행 | **Amazon Bedrock Agents**(에이전트) |
| 특정 도메인의 말투·형식을 모델에 내재화 | **파인튜닝** |
| 프롬프트에 예시 몇 개를 넣어 패턴을 따르게 | **few-shot 프롬프팅** |
| 단계별로 추론을 풀어 쓰게 | **chain-of-thought** |
| 요약 품질 / 번역 품질 / 의미 유사도 지표 | **ROUGE / BLEU / BERTScore** |
| 사전학습 모델을 SageMaker 에서 빠르게 시작 | **SageMaker JumpStart** |
| 배포된 모델의 드리프트·품질 저하 감시 | **SageMaker Model Monitor** |
| 우리 모델의 용도·위험·평가 결과 문서화 | **SageMaker Model Cards** |
| 누가 무엇을 할 수 있는지, 최소 권한 | **IAM** |
| 저장 데이터 암호화 키 관리 | **AWS KMS** |
| S3 에 저장된 민감 데이터 탐지 | **Amazon Macie** |
| 트래픽이 공용 인터넷을 거치지 않게 | **AWS PrivateLink** |
| 누가 언제 무엇을 했는지 API 감사 기록 | **AWS CloudTrail** |
| 지표·로그·경보로 운영 상태 확인 | **Amazon CloudWatch** |
| 리소스 구성이 규칙에 맞는지 평가 | **AWS Config** |
| AWS 의 SOC·ISO 보고서 내려받기 | **AWS Artifact** |

표에 나오는 Kendra·Forecast·Q Business·Bedrock Agents는 현재 신규 고객에게 닫혀 있고, 최신 시험 가이드는 AgentCore·Amazon Quick·Kiro를 든다(Week 4 Day 4·5). 보기에는 옛 이름과 새 이름이 모두 나올 수 있다.

## 자주 틀리는 함정 정리

기초 수준임에도 사람들이 반복해서 틀리는 함정들을 모았다.

- **Textract vs Comprehend**: 글자를 "추출"하면 Textract, 글자의 "의미·감정 분석"이면 Comprehend. 헷갈리면 동사를 본다.
- **SageMaker vs Bedrock**: 모델을 "직접 만들면" SageMaker, FM 을 "빌려 쓰면" Bedrock. "커스텀 학습"이 보이면 SageMaker.
- **Few-shot vs 파인튜닝**: Few-shot 은 프롬프트 안 예시(가중치 변경 없음), 파인튜닝은 가중치 변경. "예시를 보여준다"면 Few-shot.
- **temperature 방향**: 낮을수록 일관·결정적, 높을수록 창의·다양. 정확성 필요 → 낮춤.
- **책임 공유 모델**: 데이터·권한·암호화 설정은 거의 항상 "고객" 책임.
- **환각 완화**: 더 큰 모델이 아니라 **RAG**(근거 제공)가 정석.
- **RAG vs 파인튜닝**: 모르는 "정보"가 필요하면 RAG, 깊은 "말투·도메인 행동" 내재화면 파인튜닝.
- **Lex vs Polly vs Transcribe**: 대화(챗봇)=Lex, 음성 만들기=Polly, 음성 받아쓰기=Transcribe.
- **AI 서비스 vs SageMaker**: "ML 전문가 없이 빠르게"면 관리형 AI 서비스, "직접 통제·커스텀"이면 SageMaker.

> 💡 **관련 이론**: 함정 문제는 대부분 "비슷하지만 다른 두 선택지"를 나란히 둔다. 출제자는 키워드 하나(예: "추출" vs "분석")로 정답을 가른다. 그래서 시험장에서 두 서비스가 다 그럴듯해 보이면, 문제 문장으로 돌아가 "정확히 어떤 작업을 요구하는가"의 동사를 다시 확인하는 것이 가장 안전한 검증법이다.

도메인 4·5 에서 추가로 자주 틀리는 것들이다.

- **Clarify vs Model Monitor**: 편향을 측정하고 예측을 설명하면 Clarify, 배포 후 변화를 계속 지켜보면 Model Monitor. Model Monitor 는 알릴 뿐 고치지 않는다.
- **AI Service Cards vs Model Cards**: AWS 가 자사 서비스에 대해 쓴 문서 / 우리가 우리 모델에 대해 쓴 문서.
- **CloudTrail vs CloudWatch**: 누가 무엇을 했나 / 시스템이 어떻게 동작하나.
- **Macie vs Comprehend vs Guardrails(PII)**: S3 에 저장된 데이터 / 넘겨준 텍스트 / 생성형 AI 의 입력과 출력.
- **암호화 vs PrivateLink**: 내용을 지킨다 / 경로를 지킨다. 서로 대신하지 못한다.
- **투명성 vs 설명가능성**: 시스템이 무엇인지 공개 / 이 결정이 왜 나왔는지 설명.

## 한정어가 정답을 바꾼다

같은 상황이라도 질문 문장의 한정어에 따라 정답이 달라진다. 질문 문장을 먼저 읽어야 하는 이유다.

| 한정어 | 기울어야 할 방향 | 예 |
|------|------|------|
| "최소한의 ML 전문 지식으로" | 관리형 AI 서비스, Bedrock, Amazon Q | 직접 학습시키는 보기는 탈락 |
| "가장 비용 효율적으로" | 싼 방법부터(프롬프트 → RAG → 파인튜닝) | 처음부터 학습은 탈락 |
| "운영 부담을 최소화" | 완전 관리형·서버리스 | 직접 서버를 띄우는 보기는 탈락 |
| "가장 빠르게 출시" | 사전학습 모델·완성형 서비스 | 데이터 수집부터 하는 보기는 탈락 |
| "모델과 데이터를 완전히 통제" | SageMaker 에서 직접 호스팅·학습 | 완성형 비서는 탈락 |
| "규제상 결정 근거를 설명" | 설명하기 쉬운 모델, 설명 도구, 사람 검토 | 성능만 높은 블랙박스는 탈락 |
| "옳지 않은 것은", "가장 적절하지 않은" | 맞는 말 셋을 지우고 남는 하나 | 맞는 말을 고르면 오답 |

| 구분 | 내용 |
|------|------|
| 새로 추가된 목표 | 전통 ML 모델과 FM 중 무엇이 맞는지 판단, 토큰 기반 요금이 비용·성능에 주는 영향, 컨텍스트 엔지니어링의 역할, 에이전트형 AI 기초 개념(멀티 에이전트 패턴, MCP, 메모리 관리, 도구 사용, 워크플로 오케스트레이션), Amazon Bedrock Prompt Management 를 쓰는 프롬프트 버전 관리, 사업 목표 정렬 지표(작업 완료율·사용자 만족도·상호작용당 비용), 환각 탐지와 그라운딩 기법 |
| 예시가 늘어난 목표 | 추론 유형에 비동기·서버리스, 평가 지표에 정밀도·재현율, FM 커스터마이즈에 모델 증류, FM 평가에 LLM-as-a-judge, 보안 고려 사항에 데이터 유출 방지·출력 필터링과 검증·AI 상호작용의 감사 추적과 로깅·독성 |
| 범위에 추가된 서비스 | Amazon Aurora, Amazon Bedrock AgentCore, Kiro, Strands Agents, Amazon Q, Amazon SageMaker JumpStart, AWS Transform |
| 범위에서 빠진 서비스 | Amazon MemoryDB |

- 새 목표는 대부분 "정의한다", "설명한다" 수준이다. 에이전트를 구현하는 법이 아니라 에이전트가 챗봇과 무엇이 다른지, MCP 가 무엇을 연결하는지를 한 문장으로 말할 수 있으면 된다(Day 1·2 의 표 참고).
- 범위 내 서비스 목록은 "전부가 아니며 바뀔 수 있다"고 적혀 있다. 목록에 없는 서비스 이름이 보기에 나와도 당황하지 말고, 아는 보기부터 판정한다.

## 도메인별 마지막 점검표

아래 문장을 소리 내어 완성할 수 있으면 그 줄은 통과다. 막히는 줄만 해당 복습 글로 되돌아간다.

```text
[도메인 1 — AI/ML 기초]
□ AI·ML·딥러닝·생성형 AI 의 포함 관계는? (→ AI ⊃ ML ⊃ 딥러닝 ⊃ 생성형 AI)
□ 분류와 회귀를 가르는 것은? (→ 출력이 범주인가 연속 숫자인가)
□ 레이블 없는 데이터에서 그룹을 찾는 것은? (→ 비지도학습의 군집화)
□ ML 이 맞지 않는 상황은? (→ 규칙이 명확하다, 정해진 한 가지 결과가 필요하다)

[도메인 2 — 생성형 AI 기초]
□ 비용과 컨텍스트 한도의 단위는? (→ 토큰)
□ 환각의 근본 원인은? (→ 다음 토큰 확률 예측이지 사실 검증이 아니다)
□ 일관된 답이 필요하면 temperature 는? (→ 낮춘다)
□ 임베딩은 무엇에 쓰나? (→ 의미 검색, RAG)

[도메인 3 — 파운데이션 모델 응용]
□ 모델 동작을 바꾸는 시도 순서는? (→ 프롬프트 → RAG → 파인튜닝)
□ RAG 와 파인튜닝을 가르는 것은? (→ 지식 공급인가, 말투·행동 내재화인가)
□ few-shot 에서 바뀌지 않는 것은? (→ 모델 가중치)
□ 요약과 번역의 자동 평가 지표는? (→ ROUGE, BLEU)
□ Bedrock 과 SageMaker 를 가르는 것은? (→ 빌려 쓰나, 직접 만드나)

[도메인 4 — 책임 있는 AI]
□ 편향과 공정성의 관계는? (→ 편향은 원인, 불공정은 결과)
□ 투명성과 설명가능성의 차이는? (→ 무엇인지 공개 / 왜 그런지 설명)
□ 편향 측정과 설명을 함께 하는 도구는? (→ SageMaker Clarify)
□ 생성형 AI 의 입출력을 정책으로 거르는 것은? (→ Amazon Bedrock Guardrails)
□ 고위험 결정의 안전장치는? (→ Human-in-the-Loop)

[도메인 5 — 보안·규정 준수·거버넌스]
□ 데이터·권한·암호화 설정은 누구 책임인가? (→ 고객)
□ 저장 중·전송 중 암호화의 수단은? (→ KMS / TLS)
□ 공용 인터넷을 거치지 않게 하는 것은? (→ PrivateLink)
□ 누가 무엇을 했는지 남기는 것은? (→ CloudTrail)
□ AWS 의 규정 준수 보고서를 받는 곳은? (→ AWS Artifact)
```

## 응시 절차와 정책

시험 내용만큼 절차를 몰라 손해 보는 경우가 있다. AWS 자격증 정책 페이지 기준이다.

| 항목 | 내용 |
|------|------|
| 일정 변경·취소 | 예약 시각 24시간 전까지 변경할 수 있고, 한 예약은 두 번까지만 변경할 수 있다. 24시간 이내에 취소하거나 나타나지 않으면 응시료를 돌려받지 못한다 |
| ESL +30 | 영어가 모국어가 아닌 응시자가 **영어로** 응시할 때 30분을 더 받는 편의 제도. 시험 등록 **전에** 한 번 신청해 두면 된다. 한국어로 응시하면 해당하지 않는다 |
| 신분증 | 정부 발급 신분증이 필요하다. 온라인과 시험 센터의 요건이 다르므로 예약 안내에서 확인한다 |
| 결과 통지 | 시험을 마친 뒤 영업일 기준 5일 이내에 확인할 수 있다 |
| 불합격 시 | 14일(달력 기준)을 기다린 뒤 재응시할 수 있다. 횟수 제한은 없지만 매번 응시료 전액을 낸다 |

- 한국어 번역 지문이 어색하게 느껴지면 서비스 이름과 기능 용어는 영어 원문을 떠올려 대조한다. 번역표의 서비스 이름을 영어로 익혀 둔 이유다.
- 온라인 감독 시험은 시작 전에 응시 환경을 확인하는 절차가 있다. 안내된 시각보다 여유 있게 접속하고 책상 위를 미리 비워 둔다.

## 시험 중 흔들릴 때의 규칙

미리 정해 둔 규칙이 있으면 시험 중에 판단에 쓰는 힘을 아낄 수 있다.

| 상황 | 규칙 |
|------|------|
| 처음 보는 서비스 이름이 보기에 있다 | 아는 보기 셋을 먼저 판정한다. 셋이 모두 조건을 어길 때만 모르는 보기를 고른다 |
| 처음 보는 주제의 문항이 연달아 나온다 | 비채점 문항일 수 있다. 잠정 답을 고르고 넘어간다 |
| 두 보기가 모두 맞아 보인다 | 질문 문장의 동사와 한정어를 다시 읽는다 |
| 한 문항에 2분이 지났다 | 지금 가장 그럴듯한 보기를 고르고 표시한 뒤 넘어간다 |
| 종료 5분 전 미응답이 남았다 | 지문을 다 읽지 말고 남은 문항부터 모두 답을 채운다 |
| 검토 중 답을 바꾸고 싶다 | 지문에서 놓친 조건을 새로 찾았을 때만 바꾼다 |

6주를 정리하면 이렇다. **기초 개념(포함 관계·학습 방식·토큰/임베딩)** 으로 토대를 잡고, **AWS AI 서비스 매핑**으로 표면 문제를 잡고, **책임 있는 AI·보안·거버넌스**로 가치 판단 문제를 잡는다. 모르는 문제에 매달리지 말고 동사를 잡아 서비스로 번역한다. 여기까지 왔다면 준비는 충분하다. 번역표와 함정 목록을 한 번 더 훑고 가벼운 마음으로 시험장에 들어간다. 합격을 응원한다.

## 📖 용어

- **척도 점수(scaled score)** : 시험 폼마다 다른 난이도를 보정해 같은 기준으로 환산한 점수. 정답률과 일치하지 않는다.
- **보상 채점** : 영역별 합격선 없이 전체 점수로만 합격을 정하는 방식.
- **비채점 문항** : 점수에 반영되지 않는 통계 수집용 문항. 수험자는 어느 문항인지 알 수 없다.
- **복수 응답** : 보기 다섯 개 이상에서 정답을 둘 이상 고르는 문항 유형.
- **순서 배열 / 짝짓기** : 항목을 올바른 순서로 놓는 유형 / 제시문과 응답을 연결하는 유형.
- **한정어** : "가장 비용 효율적인", "최소한의 운영 부담으로"처럼 정답의 기준을 정하는 표현.
- **온라인 감독 시험** : 감독관이 웹캠과 화면 공유로 지켜보는 가운데 자기 장소에서 치르는 시험.
- **ESL +30** : 비영어권 응시자가 영어로 시험을 볼 때 신청할 수 있는 30분 연장 편의 제도.
- **시험 가이드** : AWS 가 공개하는 공식 출제 범위 문서. 도메인 비중과 목표, 범위 안팎의 서비스가 적혀 있다.

## 📝 연습 문제

**문제 1.** AIF-C01 시험의 구성으로 옳은 것은?

A) 100문항, 60분, 합격 800점  
B) 65문항, 90분, 합격 700점(1000점 만점)  
C) 50문항, 120분, 합격 600점  
D) 30문항, 45분, 합격 900점  

**정답: B**  
해설: AIF-C01은 65문항을 90분 동안 풀며, 1000점 만점에 700점 이상이면 합격한다. 65문항 중 약 15문항은 채점되지 않는 평가용이다. 나머지 보기는 문항 수·시간·합격 점수가 실제와 다르다.

**문제 2.** "스캔한 송장(invoice)에서 금액과 항목 표를 자동으로 추출"하라는 문제가 나왔다. 어떤 서비스를 떠올려야 하는가?

A) Amazon Comprehend  
B) Amazon Textract  
C) Amazon Lex  
D) Amazon Polly  

**정답: B**  
해설: 핵심 동사가 "추출"이고 대상이 스캔 문서이므로 Textract다. Comprehend는 텍스트의 의미·감정 분석, Lex는 챗봇, Polly는 음성 합성으로 문서에서 텍스트·표를 꺼내는 작업과 맞지 않는다.

---

**문제 3.** 두 선택지 Amazon SageMaker와 Amazon Bedrock이 모두 그럴듯해 보인다. 문제에 "자사 데이터로 모델을 처음부터 직접 학습시킨다"는 표현이 있다면 정답은?

A) Bedrock — 기성 FM을 빌려 쓰므로  
B) SageMaker — 커스텀 모델을 직접 학습·배포하므로  
C) 둘 다 정답이다  
D) 둘 다 학습 기능이 없다  

**정답: B**  
해설: "처음부터 직접 학습"은 커스텀 모델 구축을 뜻하므로 SageMaker다. Bedrock은 사전학습된 FM을 활용하는 서비스라 직접 학습 요구와 맞지 않고, 두 서비스는 목적이 분명히 달라 "둘 다"는 틀리며 SageMaker는 학습이 핵심 기능이다.

**문제 4.** 생성형 AI 챗봇의 환각을 줄이라는 문제에서, 정답으로 가장 적절한 접근은?

A) 모델 파라미터 수를 무조건 늘린다  
B) 신뢰할 수 있는 문서를 검색해 답의 근거로 제공하는 RAG를 적용한다  
C) temperature를 최대로 높인다  
D) 프롬프트를 무조건 길게 만든다  

**정답: B**  
해설: 환각 완화의 정석은 더 큰 모델이 아니라, 실제 근거 문서를 제공해 모델이 그 안에서 답하게 하는 RAG다. 모델 크기를 키워도 환각이 줄어든다는 보장이 없고, temperature 상승은 오히려 자유로운 생성을 늘리며, 프롬프트 길이는 환각 자체를 줄이지 못한다.

**문제 5.** 시험에서 비슷해 보이는 두 서비스(예: Textract와 Comprehend) 중 정답을 고를 때 가장 안전한 검증 방법은?

A) 알파벳 순서로 앞선 것을 고른다  
B) 문제 문장의 핵심 동사(추출/분석/생성 등)를 다시 확인해 작업 종류를 판별한다  
C) 더 비싼 서비스를 고른다  
D) 항상 가장 최신 서비스를 고른다  

**정답: B**  
해설: 함정 문제는 키워드 하나로 정답이 갈리므로, 문제 속 동사를 다시 확인해 "어떤 작업을 요구하는가"를 판별하는 것이 가장 안전하다. 알파벳 순서·가격·출시 시점은 작업 적합성과 무관한 기준이라 정답 근거가 될 수 없다.
