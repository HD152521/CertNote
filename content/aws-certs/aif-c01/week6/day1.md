# Day 1 - 도메인 복습 1: AI/ML 기초 + 생성형 AI 기초 핵심 총정리

## 📌 핵심 정리

- **AI ⊃ ML ⊃ 딥러닝 ⊃ 생성형 AI**. 규칙을 사람이 코드로 적으면 ML 이 아니라 규칙 기반 시스템이다.
- 학습 방식은 정답(레이블) 유무로 갈린다. 지도(분류·회귀), 비지도(군집화·차원 축소), 강화(보상).
- 출력이 **범주면 분류, 연속 숫자면 회귀**다. 평가 지표는 "어떤 실수가 더 치명적인가"로 고른다.
- 생성형 AI 는 **토큰** 단위로 다음 토큰의 확률을 예측한다. 비용·한도·비결정성·환각이 모두 여기서 나온다.
- 모델 동작을 바꾸는 시도 순서는 **프롬프트 엔지니어링 → RAG → 파인튜닝**, 싸고 빠른 것부터다.

## AI · ML · 딥러닝 · 생성형 AI: 포함 관계 다시 긋기

마지막 주차다. 복습 주차의 목표는 "새로 배우기"가 아니라 "헷갈리는 경계 다시 긋기"다. 오늘은 시험의 출발점인 도메인 1(AI/ML 기초, 20%)과 도메인 2(생성형 AI 기초, 24%)를 묶는다. 두 도메인을 합치면 채점 문항의 44% 이고, 나머지 도메인의 문제도 여기서 쓰는 용어 위에 세워진다.

기초 단계에서 가장 먼저 짚을 함정은 네 용어의 포함 관계다. 큰 원 안에 작은 원이 들어가는 구조다.

| 용어 | 정의 | 포함 관계 |
|------|------|-----------|
| **AI(인공지능)** | 사람의 지능적 행동을 흉내 내는 모든 기술 | 가장 큰 범주 |
| **ML(머신러닝)** | 데이터로 규칙을 스스로 학습하는 AI의 한 갈래 | AI ⊃ ML |
| **딥러닝(Deep Learning)** | 신경망 층을 깊게 쌓은 ML | ML ⊃ 딥러닝 |
| **생성형 AI(Generative AI)** | 새 콘텐츠를 만들어내는 딥러닝 응용 | 딥러닝 ⊃ 생성형 AI |

- "생성형 AI 는 ML 의 일종이다"는 참이고, "ML 은 모두 딥러닝이다"는 거짓이다.
- 규칙을 사람이 직접 코드로 적으면 그것은 ML 이 아니라 **규칙 기반(rule-based)** 시스템이다.
- 현재 시험 가이드는 여기에 **에이전트형 AI(agentic AI)** 를 더해 비교하게 한다. 생성형 AI 가 "요청받은 콘텐츠를 만든다"면, 에이전트형 AI 는 모델이 목표를 받아 스스로 단계를 계획하고 도구를 호출해 일을 끝낸다. 포함 관계의 새 원이라기보다 생성형 AI 모델을 "행동하는 주체"로 쓰는 방식이다.

> 💡 **관련 이론**: ML 이 전통 프로그래밍과 다른 본질은 "규칙을 사람이 짜느냐, 데이터에서 뽑아내느냐"다. 전통 프로그래밍은 `입력 + 규칙 → 출력`이지만, ML 은 `입력 + 출력(정답) → 규칙(모델)`을 거꾸로 학습한다. 그래서 ML 은 "정답이 붙은 데이터"가 충분해야 잘 작동하고, 데이터가 편향되면 모델도 편향된다. 시험에서 "스팸 규칙이 계속 바뀌어 사람이 일일이 못 따라간다" 같은 상황이 나오면 ML 이 답이 되는 이유가 이것이다.

## 학습 방식 3종: 지도 · 비지도 · 강화

ML 학습 방식은 "정답(레이블)이 있느냐"로 갈린다.

| 방식 | 데이터 | 대표 작업 | 예시 |
|------|--------|-----------|------|
| **지도학습** | 정답 있음 | 분류, 회귀 | 스팸/정상 분류, 집값 예측 |
| **비지도학습** | 정답 없음 | 군집화, 차원 축소 | 고객 세분화, 이상 탐지 |
| **강화학습** | 보상 신호 | 순차적 의사결정 | 게임 AI, 로봇 제어 |

- 지도학습 안에서 또 갈린다. 출력이 **범주**(스팸/정상, 개/고양이)면 **분류(classification)**, 출력이 **연속 숫자**(가격, 온도)면 **회귀(regression)** 다. 이 구분이 시험에서 답을 가른다.
- 숫자가 나온다고 모두 회귀는 아니다. "1~5 등급 중 하나"처럼 정해진 칸에서 고르면 분류다. 반대로 "내일 방문자 수"는 셀 수 있는 값이지만 연속된 크기를 맞히므로 회귀다.

비지도학습이 "정답 없이도 학습한다"는 말은 데이터 안의 구조(거리, 밀도, 분포)를 스스로 찾는다는 뜻이다. 예컨대 군집화는 "가까운 것끼리 묶는다"는 거리 개념만으로 그룹을 만든다. 그래서 비지도학습은 "무엇을 찾을지 미리 모르는" 탐색적 상황(이상 거래 탐지, 고객 그룹 발견)에 강하다. 반대로 "이미 무엇이 정답인지 아는" 상황이면 지도학습이 맞다.

| 지문 단서 | 학습 방식·작업 |
|------|------|
| "과거 거래에 사기/정상 표시가 붙어 있다" | 지도학습, 분류 |
| "면적·위치로 임대료를 예측" | 지도학습, 회귀 |
| "레이블 없이 비슷한 고객끼리 묶는다" | 비지도학습, 군집화 |
| "평소와 다른 패턴을 찾는다. 사기 표시는 없다" | 비지도학습, 이상 탐지 |
| "시행착오로 보상을 최대화하는 행동을 배운다" | 강화학습 |

## 도메인 1 에서 놓치기 쉬운 네 가지

포함 관계와 학습 방식만 보고 넘어가면 빠지는 항목이다. 시험 가이드의 도메인 1 과제에 모두 들어 있다.

**① ML 을 쓰지 말아야 할 때**

| 상황 | 판단 | 이유 |
|------|------|------|
| 규칙이 명확하고 변하지 않는다(세율 계산) | ML 부적합 | 코드로 적는 편이 싸고 정확하다 |
| 매번 정해진 한 가지 결과가 나와야 한다 | ML 부적합 | ML 은 확률적 예측을 낸다 |
| 데이터가 거의 없다 | ML 부적합 | 배울 재료가 없다 |
| 얻는 가치보다 구축·운영 비용이 크다 | ML 부적합 | 비용 대비 효과가 맞지 않는다 |
| 규칙이 너무 많거나 계속 바뀌고 데이터는 풍부하다 | ML 적합 | 사람이 규칙을 따라갈 수 없다 |

**② 전통 ML 모델과 파운데이션 모델 중 무엇을 쓸까**

| 기준 | 전통 ML 모델이 맞는 쪽 | 파운데이션 모델이 맞는 쪽 |
|------|------|------|
| 작업 | 표 형태 데이터의 분류·회귀·예측 | 텍스트·이미지 생성, 요약, 대화 |
| 설명 요구 | 결정 근거를 규제 기관에 제시해야 한다 | 설명보다 유연함이 중요하다 |
| 운영 제약 | 지연·비용이 엄격하고 작업이 좁다 | 여러 작업을 하나의 모델로 처리하고 싶다 |
| 데이터 | 레이블 붙은 자사 데이터가 충분하다 | 학습 데이터 없이 바로 시작해야 한다 |

- "대출 승인 여부를 판정하고 거절 사유를 설명해야 한다"는 지문에서 무조건 최신 대형 모델을 고르면 틀린다. 규제와 설명 요구가 보이면 전통 ML 쪽을 먼저 본다.

**③ 추론 방식 네 가지**

| 방식 | 언제 쓰나 | 예 |
|------|------|------|
| 실시간(real-time) | 요청마다 즉시 응답이 필요하다 | 결제 순간의 사기 판정 |
| 배치(batch) | 대량 데이터를 한꺼번에, 즉시 응답은 필요 없다 | 매일 밤 전체 고객의 이탈 점수 계산 |
| 비동기(asynchronous) | 입력이 크거나 처리가 오래 걸려 요청을 쌓아 두고 처리한다 | 긴 영상·대용량 문서 분석 |
| 서버리스(serverless) | 요청이 드문드문 들어와 상시 서버를 두기 아깝다 | 가끔만 호출되는 사내 도구 |

**④ 평가 지표**

- **정확도**는 전체 중 맞힌 비율이다. 클래스가 심하게 불균형하면(사기 1%) 전부 "정상"이라 답해도 99% 가 나와 믿을 수 없다.
- **정밀도**는 잡은 것 중 진짜의 비율(잘못 잡는 실수를 줄임), **재현율**은 진짜 중 잡아낸 비율(놓치는 실수를 줄임)이다. 스팸 필터는 정밀도, 암 진단은 재현율이 우선이다.
- **F1 점수**는 정밀도와 재현율을 함께 보는 지표다.
- 시험 가이드는 모델 지표와 별개로 **비즈니스 지표**(사용자당 비용, 개발 비용, 고객 피드백, 투자 대비 수익)도 평가 기준으로 든다. 정확도가 높아도 비용이 수익을 넘으면 좋은 모델이 아니다.

## 생성형 AI 기초: 토큰 · 임베딩 · 파운데이션 모델

- 생성형 AI 는 단어가 아니라 **토큰(token)** 단위로 텍스트를 다룬다. 토큰은 단어 조각이며, 모델 비용과 컨텍스트 한도가 모두 토큰 수로 계산된다. 입력 토큰 + 출력 토큰이 곧 요금이다.
- **임베딩(embedding)** 은 텍스트·이미지를 의미를 담은 숫자 벡터로 바꾼 것이다. 의미가 비슷하면 벡터도 가깝다. 검색, 추천, RAG 의 기반이 된다.
- **파운데이션 모델(FM)** 은 방대한 데이터로 사전학습된 대형 범용 모델로, 하나의 모델이 요약·번역·분류 등 여러 작업에 두루 쓰인다. 그중 텍스트 중심의 거대 모델이 **LLM(대규모 언어 모델)** 이다.

| 개념 | 한 줄 정의 | 시험 포인트 |
|------|-----------|-------------|
| 토큰 | 텍스트의 처리 단위(단어 조각) | 비용·컨텍스트 한도의 기준 |
| 임베딩 | 의미를 담은 숫자 벡터 | 의미 검색·RAG의 기반 |
| 파운데이션 모델 | 사전학습된 대형 범용 모델 | 여러 작업에 재사용 |
| LLM | 텍스트 중심 대형 FM | 챗봇·요약·번역 |

LLM 이 글을 쓰는 원리는 "다음 토큰 확률 예측"이다. 지금까지의 토큰을 보고 다음에 올 가장 그럴듯한 토큰을 하나씩 골라 이어 붙인다. 이 확률적 특성 때문에 같은 질문에도 답이 조금씩 달라지고(비결정성), 모르는 것도 그럴듯하게 지어내는 **환각(hallucination)** 이 생긴다. 토큰·확률·환각은 한 뿌리에서 나온 개념이라 함께 이해해야 한다.

시험 가이드의 기초 용어 가운데 위 표에 없는 것을 한 줄씩 더한다.

| 용어 | 한 줄 정의 |
|------|------|
| 청킹(chunking) | 긴 문서를 검색하기 좋은 작은 조각으로 나누는 것. RAG 의 준비 단계다 |
| 벡터(vector) | 임베딩의 결과인 숫자 배열. 벡터 데이터베이스에 저장해 가까운 것을 찾는다 |
| 트랜스포머(transformer) | 오늘날 LLM 의 바탕이 되는 신경망 구조 |
| 멀티모달 모델 | 텍스트·이미지·음성 등 여러 형태를 함께 다루는 모델 |
| 확산 모델(diffusion model) | 잡음에서 시작해 단계적으로 다듬어 이미지를 만들어 내는 생성 모델 |
| 컨텍스트 윈도우 | 모델이 한 번에 볼 수 있는 토큰의 최대 개수. 입력과 출력을 합쳐 센다 |

## 토큰이 비용과 성능을 정한다

- 요금은 **입력 토큰 + 출력 토큰**으로 매겨진다. 프롬프트가 길어지면 입력 비용이, 답이 길어지면 출력 비용이 는다.
- 챗봇은 매 턴마다 이전 대화를 다시 입력으로 넣는다. 대화가 길어질수록 같은 질문 하나의 비용이 커지고, 컨텍스트 윈도우를 넘으면 앞부분이 잘린다.
- 처리할 토큰이 많을수록 응답도 느려진다. 비용과 지연은 대개 함께 움직인다.
- 그래서 **컨텍스트에 무엇을 넣을지 고르는 일**이 중요해진다. 시험 가이드는 이를 컨텍스트 엔지니어링이라 부른다. 지시문, 검색해 온 문서, 대화 기록, 도구 실행 결과 가운데 지금 필요한 것만 골라 넣어 품질을 높이고 토큰을 아낀다.
- 줄이는 수단: 출력 길이 상한(max tokens), 꼭 필요한 문서 조각만 검색해 넣기, 작업에 맞는 작은 모델 고르기.

## 추론 파라미터와 프롬프트 한 줄 정리

생성 결과를 조절하는 핵심 파라미터와 프롬프트 기법도 시험 범위에 든다.

- **Temperature**: 높을수록 다양·창의적, 낮을수록 일관·보수적. 정확성이 중요하면 낮춘다.
- **Top-p / Top-k**: 다음 토큰 후보 범위를 좁히는 샘플링 조절.
- **Max tokens**: 출력 길이 상한(비용 통제).
- **Zero-shot**: 예시 없이 지시만. **Few-shot**: 예시 몇 개로 패턴 제시(가중치 변경 없음, In-Context Learning).
- 모델 동작을 바꾸는 시도 순서는 **프롬프트 엔지니어링 → RAG → 파인튜닝**으로, 싸고 빠른 것부터다.

> 💡 **관련 이론**: temperature 를 0 에 가깝게 하면 모델은 매번 "가장 확률 높은 토큰"만 고르므로 거의 결정적으로 동작한다. 그래서 분류·추출처럼 정답이 하나인 작업엔 낮은 temperature 가, 브레인스토밍·카피라이팅처럼 다양성이 필요한 작업엔 높은 temperature 가 맞다. "창의성 ↔ 일관성"의 손잡이라고 기억하면 된다.

| 하고 싶은 일 | 조절할 것 | 방향 |
|------|------|------|
| 같은 질문에 늘 같은 답 | temperature | 낮춘다 |
| 광고 문구 후보를 다양하게 | temperature | 높인다 |
| 답이 너무 길고 비용이 크다 | max tokens | 줄인다 |
| 모델이 출력 형식을 못 맞춘다 | 프롬프트 | 예시를 넣는다(few-shot) |
| 모델이 최신 사내 정보를 모른다 | 지식 공급 | RAG |
| 전문 분야 말투와 용어를 깊이 익혀야 한다 | 모델 자체 | 파인튜닝 |

- 파라미터는 모델이 **아는 것**을 바꾸지 못한다. temperature 를 아무리 조절해도 모델이 모르는 정보는 생기지 않는다.

## 생성형 AI 의 강점과 약점, 그리고 모델 고르기

| 구분 | 시험 가이드가 드는 항목 | 뜻 |
|------|------|------|
| 강점 | 적응성 | 한 모델이 여러 작업에 맞춰 쓰인다 |
| 강점 | 반응성 | 요청에 빠르게 결과를 낸다 |
| 강점 | 대화 능력 | 자연어로 묻고 답할 수 있다 |
| 강점 | 콘텐츠 생성 능력 | 글·이미지·코드를 새로 만든다 |
| 약점 | 환각 | 사실이 아닌 내용을 그럴듯하게 낸다 |
| 약점 | 해석 가능성 부족 | 왜 그 답인지 들여다보기 어렵다 |
| 약점 | 부정확성 | 틀린 계산·사실이 섞인다 |
| 약점 | 비결정성 | 같은 입력에도 출력이 달라진다 |

- 모델을 고를 때는 모델 유형, 성능 요구, 기능, 제약, 규정 준수, 비용, 지연, 모델 복잡도를 함께 본다. "가장 큰 모델"이 정답인 경우는 드물다. 요구를 채우는 가장 작고 싼 모델이 대개 맞는 답이다.
- 비즈니스 가치는 효율, 전환율, 사용자당 평균 매출, 정확도, 고객 생애 가치, 투자 대비 수익 같은 지표로 본다.

## 에이전트형 AI 기초 용어

현재 시험 가이드는 에이전트형 AI 의 기초 개념을 도메인 2 에 넣었다. 입문 시험이므로 용어를 한 줄로 말할 수 있으면 된다.

| 용어 | 한 줄 정의 |
|------|------|
| 에이전트(agent) | 목표를 받아 스스로 단계를 정하고 도구를 써서 일을 수행하는 AI |
| 도구 사용(tool usage) | 모델이 API·검색·계산기 같은 외부 기능을 호출하는 것 |
| 메모리 관리 | 대화나 작업 중 알게 된 것을 기억해 다음 단계에 쓰는 것 |
| 워크플로 오케스트레이션 | 여러 단계와 도구 호출의 순서를 조율하는 것 |
| 멀티 에이전트 시스템 | 역할이 다른 여러 에이전트가 협력해 복잡한 일을 나눠 하는 구조 |
| MCP(Model Context Protocol) | 에이전트를 외부 시스템·도구에 연결하는 표준 규약 |

- 챗봇과 에이전트를 가르는 것은 **행동**이다. "환불 규정을 알려 준다"는 답변이고, "주문을 조회해 환불을 접수한다"는 에이전트의 일이다.

## 흔한 오해 여섯 가지

| 오해 | 실제 |
|------|------|
| AI 와 ML 은 같은 말이다 | ML 은 AI 의 한 갈래다. 규칙 기반 시스템도 AI 에 들어간다 |
| 딥러닝이 항상 더 좋다 | 데이터가 적거나 설명이 필요하면 단순한 모델이 낫다 |
| 정확도가 높으면 좋은 모델이다 | 불균형 데이터에서는 정밀도·재현율을 봐야 한다 |
| few-shot 은 모델을 학습시키는 것이다 | 프롬프트에 예시를 넣을 뿐 가중치는 그대로다 |
| temperature 를 낮추면 환각이 사라진다 | 일관성은 높아지지만 모르는 것을 알게 되지는 않는다 |
| 컨텍스트 윈도우가 크면 기억력이 좋은 것이다 | 한 번에 볼 수 있는 양일 뿐, 대화가 끝나면 남지 않는다 |

## 도메인 1·2 마지막 점검표

아래 문장을 소리 내어 완성할 수 있으면 그 줄은 통과다.

```text
[도메인 1 — AI/ML 기초]
□ 네 용어의 포함 관계는? (→ AI ⊃ ML ⊃ 딥러닝 ⊃ 생성형 AI)
□ 분류와 회귀를 가르는 것은? (→ 출력이 범주인가 연속 숫자인가)
□ 레이블 없이 그룹을 찾는 작업은? (→ 비지도학습의 군집화)
□ ML 이 맞지 않는 상황 두 가지는? (→ 규칙이 명확하다, 정해진 한 가지 결과가 필요하다)
□ 놓치면 안 될 때 우선하는 지표는? (→ 재현율)
□ 밤새 대량으로 한꺼번에 예측하는 추론 방식은? (→ 배치 추론)
□ 설명이 꼭 필요한 규제 업무에 먼저 고려할 모델은? (→ 전통 ML 모델)

[도메인 2 — 생성형 AI 기초]
□ 비용과 한도의 단위는? (→ 토큰, 입력 + 출력)
□ 의미가 비슷하면 가까워지는 숫자 표현은? (→ 임베딩)
□ 환각이 생기는 근본 이유는? (→ 사실 검증이 아니라 다음 토큰 확률 예측)
□ 일관된 답이 필요할 때 temperature 는? (→ 낮춘다)
□ few-shot 에서 바뀌지 않는 것은? (→ 모델 가중치)
□ 모델 동작을 바꾸는 시도 순서는? (→ 프롬프트 → RAG → 파인튜닝)
□ 답변과 에이전트를 가르는 것은? (→ 도구를 써서 실제로 행동하는가)
```

다음 글에서는 이 기초 위에서 **AWS 의 AI 서비스(파운데이션 모델 응용)** 를 한 번에 정리한다. "어떤 상황엔 어떤 서비스"를 빠르게 떠올리는 연습이 핵심이다.

## 📖 용어

- **규칙 기반 시스템** : 사람이 조건과 규칙을 직접 코드로 적어 동작하게 만든 시스템. 데이터에서 배우지 않는다.
- **레이블(label)** : 학습 데이터에 붙어 있는 정답.
- **분류 / 회귀** : 범주를 맞히는 작업 / 연속된 숫자를 맞히는 작업.
- **군집화(clustering)** : 정답 없이 비슷한 것끼리 묶는 비지도학습 작업.
- **토큰(token)** : 모델이 텍스트를 다루는 단위인 단어 조각. 비용과 한도의 기준이다.
- **임베딩(embedding)** : 의미를 담도록 텍스트나 이미지를 바꾼 숫자 벡터.
- **파운데이션 모델(FM)** : 방대한 데이터로 미리 학습해 여러 작업에 재사용하는 대형 모델.
- **환각(hallucination)** : 사실이 아닌 내용을 그럴듯하게 만들어 내는 현상.
- **In-Context Learning** : 가중치를 바꾸지 않고 프롬프트 안의 예시만으로 패턴을 따르게 하는 것.
- **에이전트형 AI(agentic AI)** : 모델이 목표를 향해 스스로 계획하고 도구를 써서 행동하는 방식의 AI.

**문제 1.** AI, ML, 딥러닝, 생성형 AI의 포함 관계로 옳은 것은?

A) 생성형 AI ⊃ AI ⊃ ML ⊃ 딥러닝  
B) AI ⊃ ML ⊃ 딥러닝 ⊃ 생성형 AI  
C) ML ⊃ AI ⊃ 딥러닝 ⊃ 생성형 AI  
D) 딥러닝 ⊃ AI ⊃ ML ⊃ 생성형 AI  

**정답: B**  
해설: 가장 넓은 범주가 AI이고, 그 안에 데이터로 학습하는 ML, 다시 그 안에 신경망을 깊게 쌓은 딥러닝, 그리고 콘텐츠를 생성하는 생성형 AI가 차례로 포함된다. 나머지 보기는 포함 순서가 뒤섞여 틀렸다.

**문제 2.** 집의 면적·방 개수 등으로 매매 가격(연속 숫자)을 예측하는 작업의 유형은?

A) 분류(classification)  
B) 회귀(regression)  
C) 군집화(clustering)  
D) 강화학습(reinforcement learning)  

**정답: B**  
해설: 출력이 가격이라는 연속적인 숫자값이므로 회귀다. 분류는 범주(스팸/정상 등)를 예측할 때, 군집화는 정답 없이 그룹을 찾을 때, 강화학습은 보상을 통한 순차적 의사결정에 쓰이므로 모두 맞지 않는다.

**문제 3.** 생성형 AI에서 "토큰(token)"에 대한 설명으로 가장 정확한 것은?

A) 모델의 가중치를 저장하는 파일 단위다  
B) 텍스트를 처리하는 단위(단어 조각)로, 비용과 컨텍스트 한도의 기준이 된다  
C) 사용자를 인증하는 보안 자격 증명이다  
D) 이미지의 픽셀 한 개를 가리킨다  

**정답: B**  
해설: 토큰은 LLM이 텍스트를 다루는 기본 단위인 단어 조각이며, 입력·출력 토큰 수가 곧 비용과 컨텍스트 윈도우 한도를 결정한다. A는 모델 파일, C는 인증 토큰, D는 픽셀에 대한 설명으로 모두 다른 개념이다.

**문제 4.** temperature 값을 낮게(0에 가깝게) 설정하면 나타나는 효과는?

A) 출력이 더 창의적이고 매번 크게 달라진다  
B) 출력이 더 일관되고 예측 가능해진다  
C) 모델이 학습하지 않은 정보를 정확히 알게 된다  
D) 토큰 비용이 무료가 된다  

**정답: B**  
해설: temperature가 낮으면 모델이 확률이 높은 토큰을 우선 선택해 일관되고 보수적인 출력을 낸다. 창의성·다양성이 커지는 것은 높은 temperature이며(A 반대), temperature는 지식이나 비용과는 무관하므로 C·D도 틀렸다.

**문제 5.** 모델 동작을 조정할 때 일반적으로 권장되는 시도 순서는?

A) 파인튜닝 → RAG → 프롬프트 엔지니어링  
B) RAG → 프롬프트 엔지니어링 → 파인튜닝  
C) 프롬프트 엔지니어링 → RAG → 파인튜닝  
D) 파인튜닝 → 프롬프트 엔지니어링 → RAG  

**정답: C**  
해설: 비용과 난이도가 가장 낮은 프롬프트 엔지니어링을 먼저 시도하고, 외부·최신 지식이 필요하면 RAG, 깊은 도메인 내재화가 필요하면 마지막으로 파인튜닝을 고려하는 것이 정석이다. 비싼 파인튜닝을 앞세우거나 순서가 뒤섞인 나머지 보기는 권장되지 않는다.
