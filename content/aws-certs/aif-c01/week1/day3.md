# Day 3 - ML이 적합한 문제 vs 아닌 문제

## 📌 핵심 정리

- 전통적 프로그래밍은 `데이터 + 규칙 → 결과`, 머신러닝은 `데이터 + 결과 → 규칙`. **입력과 출력이 뒤바뀐다**.
- ML이 **적합**: 규칙이 복잡해 사람이 적기 어렵고 + 데이터가 충분하고 + 약간의 오차를 허용할 수 있을 때.
- ML이 **부적합**: 규칙이 단순·명확하거나, 데이터가 거의 없거나, 100% 정확성·완전한 설명이 필수일 때.
- **가장 단순하면서 충분한 방법**을 고르는 것이 좋은 설계다. 복잡한 기술이 곧 정답은 아니다.
- 실무에서는 명확한 규칙은 코드로, 복잡한 판단만 ML로 **함께 쓰는** 경우가 많다.

## 전통적 프로그래밍 vs 머신러닝

머신러닝은 강력하지만 만능이 아니다. "굳이 필요 없는데 도입해 비용만 늘고 결과도 나쁜" 사례가 실무에 흔하다.

| 구분 | 전통적 프로그래밍 | 머신러닝 |
|------|------------------|----------|
| 규칙을 만드는 주체 | 사람(개발자) | 데이터로부터 학습 |
| 입력 | 데이터 + 규칙 | 데이터 + 정답(예시) |
| 출력 | 결과(답) | 규칙(모델) |
| 적합한 상황 | 규칙이 명확하고 변하지 않음 | 규칙이 복잡하거나 사람이 정의하기 어려움 |

- 전통적 프로그래밍: 사람이 규칙을 적으면 컴퓨터가 그대로 실행한다.
- 머신러닝: 데이터와 정답 예시를 주면 컴퓨터가 규칙(모델)을 만들어 낸다.

전통적 프로그래밍은 `데이터 + 규칙 → 결과`이고, 머신러닝은 `데이터 + 결과 → 규칙`이다. 입력과 출력이 뒤바뀐 셈이라고 이해하면 기억하기 쉽다.

## 머신러닝이 적합한 문제

다음 조건을 만족할수록 머신러닝이 좋은 선택이다.

1. **규칙이 너무 복잡하거나 사람이 일일이 적기 어렵다** — 사진 속 고양이를 인식하는 규칙을 코드로 적기는 사실상 불가능하다.
2. **패턴은 있지만 명시적으로 표현하기 어렵다** — 스팸 메일의 특징은 계속 변하고 미묘해 규칙으로 고정하기 어렵다.
3. **충분한 양과 품질의 데이터가 있다** — 학습에 쓸 과거 데이터(예시)가 많아야 한다.
4. **약간의 오차를 허용할 수 있다** — 머신러닝은 100% 정확하지 않고 확률적으로 좋은 답을 준다.
5. **상황이 변하면 규칙도 바뀌어야 한다** — 새 데이터로 다시 학습해 변화에 적응할 수 있다.

### 적합한 사례

- 이미지/음성/자연어 인식
- 추천 시스템(상품, 영화)
- 스팸·사기 탐지
- 수요·가격 예측
- 고객 이탈 예측

## 머신러닝이 적합하지 않은 문제

반대로 다음과 같은 경우에는 머신러닝이 과하거나 부적절하다.

1. **규칙이 명확하고 간단하다** — "부가세는 금액의 10%"는 그냥 곱셈이다.
2. **데이터가 거의 없다** — 학습할 예시가 부족하면 제대로 작동하지 않는다.
3. **100% 정확성과 완벽한 설명이 필수다** — 법적·안전상 오차가 허용되지 않고 모든 결정의 근거를 설명해야 한다면, 확률적이고 때로 "블랙박스"인 머신러닝은 위험할 수 있다.
4. **단순 계산·조회로 충분하다** — 데이터베이스 조회, 정해진 수식 계산은 전통적 방식이 더 정확하고 저렴하다.

### 부적합한 사례

| 문제 | 더 나은 방법 | 이유 |
|------|-------------|------|
| 두 숫자의 합 계산 | 전통적 프로그래밍 | 규칙이 명확함 |
| 세금 10% 계산 | 전통적 프로그래밍 | 단순 수식 |
| 사번으로 직원 정보 조회 | 데이터베이스 조회 | 정확한 조회로 충분 |
| 데이터가 단 10건뿐인 예측 | 데이터 확보 우선 | 학습 데이터 부족 |

> 💡 **관련 이론**: "머신러닝이 항상 더 똑똑하다"는 오해를 피해야 한다. 규칙이 명확한 문제에 머신러닝을 쓰면 비용은 늘고 정확도는 오히려 떨어질 수 있다. **가장 단순하면서 충분한 방법을 선택**하는 것이 좋은 설계다.

## 판단 흐름도

머신러닝 도입 여부를 빠르게 점검하는 순서다.

```
규칙을 사람이 쉽고 명확하게 적을 수 있는가?
   └ 예  → 전통적 프로그래밍 사용 (머신러닝 불필요)
   └ 아니오 ↓
학습에 쓸 충분한 데이터가 있는가?
   └ 아니오 → 먼저 데이터 확보 (지금은 머신러닝 어려움)
   └ 예 ↓
약간의 오차를 허용할 수 있는가?
   └ 아니오 → 신중히 검토 (머신러닝 위험할 수 있음)
   └ 예 → 머신러닝이 적합할 가능성이 높음
```

## 시험 가이드가 꼽는 "부적합" 신호 두 가지

AIF-C01 시험 가이드는 AI/ML이 맞지 않는 상황의 예로 **비용 대비 효과 분석**과 **예측이 아니라 정해진 결과가 필요한 경우**를 든다.

### 1) 예측이 아니라 "정해진 결과"가 필요하다

- 머신러닝의 답은 **예측**이다. "아마 이럴 것이다"이며, 같은 종류의 입력에도 가끔 틀린다.
- 반대로 전통적 코드는 **결정적**이다. 같은 입력이면 언제나 같은 결과가 나오고, 왜 그 결과인지 코드 한 줄로 짚을 수 있다.

| 업무 | 필요한 것 | 맞는 방식 |
|------|----------|----------|
| 급여에서 소득세 원천징수액 계산 | 법에 정해진 단 하나의 값 | 전통적 프로그래밍 |
| 계좌 잔액 조회, 이체 금액 차감 | 1원도 틀리면 안 되는 값 | 전통적 프로그래밍 |
| 비밀번호 일치 여부 확인 | 맞다/틀리다의 확정 | 전통적 프로그래밍 |
| 이 거래가 사기일 가능성 | 가능성에 대한 추정 | 머신러닝 |
| 다음 달 예상 방문자 수 | 불확실한 미래의 추정 | 머신러닝 |

- 구분법: 답을 "**계산한다/조회한다**"고 말할 수 있으면 전통적 방식, "**추정한다/가려낸다**"고 말해야 하면 머신러닝 후보다.

### 2) 비용 대비 효과가 맞지 않는다

머신러닝은 모델을 만드는 값만 드는 것이 아니다. 아래를 모두 더해 얻는 이익과 견줘야 한다.

| 드는 것 | 내용 |
|---------|------|
| 데이터 | 수집, 정리, 정답(레이블) 붙이기 |
| 학습 | 연산 자원과 시간, 여러 번의 시행착오 |
| 운영 | 서비스에 올려 두는 비용, 성능 감시, 주기적 재학습 |
| 사람 | 전문 인력, 결과를 검토하는 담당자 |

- 한 달에 20건 들어오는 문의를 자동 분류하려고 모델을 만들면, 사람이 직접 읽는 편이 훨씬 싸다. **처리량이 작으면 자동화의 이익도 작다.**
- 규칙 서너 줄로 95%가 해결되는 문제에 모델을 얹어 97%로 올리는 일도, 그 2%p가 운영비보다 값진지 따져 봐야 한다.

## 반대로, AI/ML이 가치를 주는 세 방향

시험 가이드는 가치를 주는 예로 **사람의 의사결정 보조, 솔루션 확장성, 자동화**를 든다.

| 방향 | 뜻 | 예 |
|------|-----|-----|
| 의사결정 보조 | 사람이 결정하되, 모델이 근거와 후보를 추려 준다 | 영상 판독에서 의심 부위를 표시해 의사에게 보여 줌 |
| 확장성 | 사람 수를 늘리지 않고 처리량을 늘린다 | 하루 수백만 건의 결제를 실시간으로 점검 |
| 자동화 | 반복적인 판단을 사람 손에서 덜어 낸다 | 들어온 문의를 담당 부서로 자동 배정 |

## 시나리오로 판별하기

| 시나리오 | 판단 | 근거 |
|----------|------|------|
| 주문 금액이 5만 원 이상이면 무료 배송 | 전통적 프로그래밍 | 규칙이 한 줄, 정해진 결과 |
| 손글씨로 쓴 주소를 읽어 텍스트로 바꾼다 | 머신러닝 | 글씨체 규칙을 사람이 적을 수 없다 |
| 회원 등급별 할인율을 적용한다 | 전통적 프로그래밍 | 표를 조회하면 끝난다 |
| 수백만 고객 중 다음 달 해지할 사람을 추린다 | 머신러닝 | 패턴이 복잡하고 과거 데이터가 많다 |
| 창업 첫 주, 고객 기록 30건으로 수요를 예측한다 | 지금은 부적합 | 데이터가 부족하다. 먼저 쌓는다 |
| 법으로 근거 제시가 의무인 자격 심사를 전부 자동 결정한다 | 신중히 | 완전한 설명이 필요하다. 규칙 또는 사람 검토를 둔다 |
| 한 달에 몇 건뿐인 서류를 자동 분류한다 | 부적합 | 비용 대비 효과가 없다 |
| 사진에서 불량품을 골라낸다(불량 사진 수만 장 보유) | 머신러닝 | 복잡한 시각 패턴 + 충분한 데이터 |

## 현실적인 균형 잡기

- 실무에서는 두 방식을 **함께 쓰는 경우**가 많다. 명확한 규칙은 전통적 코드로, 복잡한 판단만 머신러닝에 맡긴다.
- "둘 중 하나만 옳다"가 아니라 **"문제에 맞는 도구를 고른다"**는 관점이 중요하다.

> 📚 **사례**: 카드 결제 승인 시스템에서 "한도를 넘으면 거절", "분실 신고된 카드는 거절"은 예외 없이 지켜야 하는 정책이라 **코드**로 넣는다. "평소와 다른 수상한 결제인가"는 규칙으로 적기 어려워 **머신러닝**이 점수를 매긴다. 점수가 애매한 건은 **사람**이 확인한다. 한 시스템 안에 세 가지가 층층이 놓인다.

## 전통적 ML 모델 vs 파운데이션 모델

머신러닝을 쓰기로 했어도 선택이 하나 더 남는다. 시험 가이드는 **규제, 설명 가능성, 운영상 제약**을 기준으로 전통적 ML 모델과 파운데이션 모델(FM) 중 무엇이 맞는지 가려내라고 요구한다.

| 비교 축 | 전통적 ML 모델 | 파운데이션 모델(FM) |
|---------|---------------|--------------------|
| 만들어진 목적 | 한 가지 작업(예: 연체 예측)에 맞춰 학습 | 방대한 데이터로 미리 학습해 여러 작업에 범용으로 사용 |
| 잘하는 일 | 표 데이터로 분류·수치 예측 | 글·이미지 생성, 요약, 질의응답 |
| 결과 설명 | 어떤 특성이 영향을 줬는지 비교적 밝히기 쉽다 | 왜 그 문장이 나왔는지 설명하기 어렵다 |
| 크기와 운영 | 작고 빠르고 싸다 | 크고, 응답 지연과 사용 비용을 따져야 한다 |
| 어울리는 상황 | 규제 산업의 심사·점수처럼 근거를 대야 하는 결정 | 초안 작성·상담 응대처럼 표현의 유연함이 필요한 일 |

- "대출 심사 결과의 근거를 규제 기관에 설명해야 한다" → 설명 가능한 전통적 ML 쪽이다.
- "고객 문의에 자연스러운 문장으로 답해야 한다" → 파운데이션 모델 쪽이다.
- 파운데이션 모델 자체는 Week 3에서 다룬다. 오늘은 **"생성형이 최신이니 무조건 그쪽"이 아니다**라는 점만 기억한다.

## 흔한 오해 바로잡기

- **"데이터만 많으면 머신러닝이 된다"** → 양보다 먼저 **정답이 붙어 있는지, 치우치지 않았는지**를 본다. 쓸 수 없는 데이터 100만 건은 0건과 같다.
- **"모델은 한 번 만들면 끝"** → 세상이 바뀌면 모델도 낡는다. 감시와 재학습 비용이 계속 든다.
- **"머신러닝을 쓰면 규칙은 필요 없다"** → 반드시 지켜야 하는 정책은 여전히 코드로 고정한다. 모델은 그 바깥의 애매한 판단을 맡는다.
- **"오차를 허용할 수 없으면 머신러닝은 절대 못 쓴다"** → 모델은 후보만 추리고 사람이 최종 결정하는 **의사결정 보조** 형태로는 쓸 수 있다.

## 📖 용어

- **전통적 프로그래밍** : 사람이 규칙을 코드로 적어두면 컴퓨터가 그대로 실행하는 방식.
- **모델** : 머신러닝이 데이터에서 찾아낸 규칙 덩어리. 학습의 결과물이다.
- **학습 데이터** : 모델을 가르치는 데 쓰는 과거 데이터와 그 정답.
- **데이터 품질** : 데이터가 정확하고 빠짐없고 치우치지 않은 정도. 데이터의 양만큼 중요하다.
- **확률적** : 항상 같은 정답을 보장하지 않고 "이럴 가능성이 높다"로 답한다는 뜻.
- **블랙박스** : 답은 나오지만 왜 그런 답인지 사람이 설명하기 어려운 상태.
- **설명 가능성** : 모델이 왜 그런 결정을 내렸는지 근거를 댈 수 있는 성질. 금융·의료·법률에서 특히 중요하다.
- **이탈 예측** : 고객이 서비스를 그만둘지 미리 맞히는 작업. 대표적인 ML 활용 사례.
- **사기 탐지** : 카드 결제 등에서 비정상 거래를 골라내는 작업.
- **파운데이션 모델(FM)** : 방대한 데이터로 미리 학습해 두어 여러 작업에 두루 쓸 수 있는 대형 모델. 생성형 AI의 토대다.

## 📝 연습 문제

**문제 1.** 다음 중 머신러닝보다 전통적 프로그래밍이 더 적합한 문제는?

A) 수백만 장의 사진에서 고양이를 인식하기  
B) 변화하는 스팸 메일을 탐지하기  
C) 입력 금액에 고정 세율 10%를 곱해 세금을 계산하기  
D) 고객의 구매 이력으로 상품을 추천하기  

**정답: C**  
해설: 고정 세율을 곱하는 것은 규칙이 명확하고 단순한 계산이므로 전통적 프로그래밍이 더 정확하고 저렴하다. 이미지 인식, 변화하는 스팸 탐지, 추천은 규칙이 복잡하거나 정의하기 어려워 머신러닝이 적합하다.

**문제 2.** 전통적 프로그래밍과 머신러닝의 입력·출력 관계를 가장 정확하게 설명한 것은?

A) 둘 다 데이터와 규칙을 입력받아 결과를 출력한다  
B) 전통적 방식은 데이터+규칙으로 결과를, 머신러닝은 데이터+결과로 규칙을 만든다  
C) 머신러닝은 규칙을 입력받아 데이터를 생성한다  
D) 전통적 방식은 데이터 없이 결과만 만든다  

**정답: B**  
해설: 전통적 프로그래밍은 사람이 만든 규칙과 데이터로 결과를 내고, 머신러닝은 데이터와 정답(결과) 예시로부터 규칙(모델)을 학습한다. 입력과 출력의 관계가 서로 뒤바뀌어 있다는 점이 핵심이다.

**문제 3.** 어떤 업무에서 학습에 사용할 과거 데이터가 단 몇 건밖에 없고, 결과는 법적으로 100% 정확하고 완전히 설명 가능해야 한다. 이 상황에 대한 판단으로 가장 적절한 것은?

A) 데이터가 적어도 머신러닝이 항상 더 정확하므로 즉시 도입한다  
B) 데이터 부족과 완전한 정확성·설명 요구 때문에 머신러닝이 부적합할 수 있다  
C) 강화학습을 쓰면 데이터 없이도 완벽하게 해결된다  
D) 머신러닝은 설명 가능성이 항상 보장되므로 문제없다  

**정답: B**  
해설: 학습 데이터가 매우 적고, 오차가 허용되지 않으며, 모든 결정을 완전히 설명해야 하는 상황은 확률적이고 때로 블랙박스인 머신러닝에 부적합할 수 있다. 머신러닝이 항상 더 정확하다거나 항상 설명 가능하다는 설명은 옳지 않다.

**문제 4.** 머신러닝 도입이 적합한 문제의 특징으로 보기 어려운 것은?

A) 사람이 규칙을 명시적으로 적기 어려울 만큼 패턴이 복잡하다  
B) 학습에 사용할 충분한 양과 품질의 데이터가 있다  
C) 약간의 예측 오차를 허용할 수 있다  
D) 규칙이 매우 단순하고 변하지 않으며 단순 계산으로 끝난다  

**정답: D**  
해설: 규칙이 단순하고 변하지 않아 단순 계산으로 해결되는 문제는 전통적 프로그래밍이 더 적합하다. 패턴이 복잡하고, 데이터가 충분하며, 어느 정도 오차를 허용할 수 있는 경우가 머신러닝에 적합한 전형적 조건이다.
