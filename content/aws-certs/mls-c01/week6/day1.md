# Day 1 - 알고리즘 선택: 문제 유형별 매핑

## 📌 핵심 정리

- Week 6은 도메인 3(Modeling)의 출발점이다. 시험은 **ML 문제 유형 → 알고리즘 부류 → SageMaker 빌트인** 순으로 좁히도록 출제한다.
- 1차 판별 기준은 딱 둘 — **출력 형태**(범주/수치/그룹/추천/이상/주제)와 **레이블 유무**(지도/비지도).
- 2차 필터는 **데이터 형태**다. "텍스트·이미지·시계열·희소"라는 단어가 보이면 일반 XGBoost는 후보에서 밀린다.
- 불균형 데이터에서 accuracy는 함정이다. 정밀도·재현율·F1·PR-AUC로 갈아탄다.
- 유형이 같아도 **데이터 크기·희소성·해석 가능성·학습 비용**이 최종 후보를 하나로 만든다.

## 비즈니스 문제를 ML 유형으로 번역하기

모델링의 첫 의사결정은 "어떤 알고리즘을 쓸 것인가"이고, 그 앞에 반드시 **ML 문제 유형 번역**이 온다. 시험 지문은 거의 항상 비즈니스 언어로 주어지므로 표준 ML 유형으로 바꾸는 것이 1단계다.

```text
"이탈할 고객을 미리 식별"          → 이진 분류 (churn yes/no)
"이메일을 스팸/정상/홍보로 구분"   → 다중 분류
"내일 매출 금액 예측"              → 회귀
"비슷한 사용자 그룹 자동 발견"      → 군집 (비지도)
"본 적 없는 상품 추천"             → 추천 / 협업 필터링
"평소와 다른 거래 탐지"            → 이상 탐지
"문서 더미에서 주제 발견"          → 토픽 모델링 (비지도)
```

판별 신호는 세 가지다.

- **레이블(정답)이 있나?** 있으면 지도학습, 없으면 비지도.
- **출력이 범주인가 수치인가?** 범주 = 분류, 연속 수치 = 회귀.
- **"그룹/패턴 발견"인가 "예측"인가?** 발견 = 군집/토픽, 예측 = 분류/회귀.

> 💡 **관련 이론**: 지도/비지도/강화의 경계는 "정답 레이블의 존재"로 갈린다. 분류·회귀는 입력-출력 쌍을 학습하는 지도학습이고, 군집·차원축소·토픽모델·이상탐지(대부분)는 레이블 없이 구조를 찾는 비지도학습이다. 추천은 사용자-아이템 상호작용 행렬을 다루며 협업 필터링 관점에선 비지도에 가깝지만, 명시적 평점을 타깃으로 쓰면 지도(회귀)로도 볼 수 있다. 강화학습은 보상 신호로 정책을 학습하는 별도 범주다(SageMaker RL).

### 알고리즘 선택 결정 트리

```
                        [비즈니스 문제 지문]
                                │
                  ┌─────── 레이블이 있는가? ───────┐
                 예(지도)                      아니오(비지도)
                  │                                │
      ┌───── 출력 형태? ─────┐          ┌──── 무엇을 하고 싶은가? ────┐
   범주        수치      순위/선호     그룹 발견   이상 탐지   차원↓   주제 발견
     │           │           │            │          │        │        │
  분류        회귀        추천        K-Means     RCF /     PCA    LDA / NTM
     │           │           │                   IP Insights
  ┌──┴──┐    ┌───┴───┐   Factorization
 표  텍스트  표    시계열   Machines
  │    │      │       │
XGBoost │  XGBoost  DeepAR
Linear  │  Linear
KNN  BlazingText
  │
이미지 → Image Classification
```

## 분류 (Classification)

출력이 **이산 범주**일 때. 이진/다중/다중레이블로 나뉜다.

| 세부 유형 | 예시 | 대표 알고리즘 |
|------|------|------|
| 이진 분류 | 이탈 여부, 사기 여부 | XGBoost, Linear Learner, KNN |
| 다중 분류 | 상품 카테고리 분류 | XGBoost, Linear Learner |
| 다중 레이블 | 한 이미지에 여러 태그 | 신경망, Image Classification |
| 텍스트 분류 | 감성/주제 분류 | BlazingText |

- 정확도만으로 부족할 때가 많다. 불균형 데이터(사기 1%)에서는 정밀도·재현율·F1·AUC를 본다.
- 이진/다중 구분은 `predictor_type`(Linear Learner)이나 `objective`(XGBoost)로 지정한다.

## 회귀 (Regression)

출력이 **연속 수치**일 때. 매출액, 가격, 수요량 예측 등.

- 후보: **XGBoost(objective=reg:squarederror)**, **Linear Learner(predictor_type=regressor)**.
- 시계열 수요 예측처럼 시간축이 핵심이면 회귀로 억지로 풀기보다 **DeepAR**(Day3)나 Amazon Forecast가 적합하다.
- 지표: RMSE, MAE, R². 이상치에 민감하면 MAE를 함께 본다.

## 군집 (Clustering)

레이블 없이 데이터를 자연스러운 그룹으로 묶는다. 고객 세분화, 문서 그룹핑.

- 후보: **K-Means**(SageMaker 빌트인). 클러스터 수 k를 미리 지정한다.
- 평가: 외부 정답이 없으므로 실루엣 계수, 엘보우(WCSS) 등 내부 지표로 k를 고른다.

## 추천 (Recommendation)

사용자-아이템 상호작용으로 선호를 예측한다.

- 후보: **Factorization Machines**(희소 고차원 상호작용에 강함), 신경망 기반 추천.
- 콜드 스타트, 희소성(대부분의 셀이 비어 있음)이 핵심 난점이다.

## 이상 탐지 (Anomaly Detection)

정상에서 벗어난 드문 사건을 찾는다. 레이블이 거의 없는 비지도 문제로 흔히 접근한다.

- 후보: **Random Cut Forest(RCF)**, **IP Insights**(엔티티-IP 이상), 스트리밍은 Kinesis Data Analytics RCF.
- 불균형이 극단적(이상 0.1%)이라 분류로 풀기 어려운 경우가 많다.

> 💡 **관련 이론**: "이상 탐지를 분류로 풀면 안 되나?"라는 함정이 자주 나온다. 이상 사례 레이블이 충분하고 패턴이 안정적이면 지도 분류도 가능하지만, 현실은 이상 사례가 극소수이고 새로운 형태로 끊임없이 변한다. 이때 정상만 학습해 벗어남을 측정하는 비지도 이상탐지(RCF 등)가 더 견고하다. 시험에서 "레이블이 거의 없다 / 새로운 형태의 이상" 단서가 보이면 분류보다 RCF 계열이 정답일 확률이 높다.

## 한눈에 보는 매핑 표

| 문제 유형 | 지도/비지도 | SageMaker 빌트인 후보 | 언제 쓰나 | 언제 쓰면 안 되나 |
|------|------|------|------|------|
| 표 형식 분류/회귀 | 지도 | XGBoost, Linear Learner | 정형 피처, 레이블 있음 | 데이터가 텍스트·이미지 원본일 때 |
| 거리 기반 분류/회귀 | 지도 | KNN | "가장 비슷한 사례"가 곧 답일 때 | 차원이 매우 높거나 추론 지연에 민감할 때 |
| 군집 | 비지도 | K-Means | 레이블 없이 세그먼트 발견 | 예측할 정답 레이블이 이미 있을 때 |
| 추천(희소 상호작용) | 지도/비지도 | Factorization Machines | 원핫으로 폭발한 희소 고차원 | 피처가 조밀한 소규모 정형 데이터 |
| 텍스트 분류/임베딩 | 지도/비지도 | BlazingText | 문서 분류, 단어 벡터 | 수치 정형 데이터 |
| 이미지 분류 | 지도 | Image Classification | 이미지 → 라벨 | 객체 위치까지 필요할 때(Object Detection) |
| 시계열 예측 | 지도 | DeepAR | 관련 시계열 다수, 확률 예측 | 시간축이 무의미한 단순 회귀 |
| 이상 탐지 | 비지도 | Random Cut Forest, IP Insights | 레이블 없는 희귀 사건 | 이상 레이블이 충분하고 패턴이 고정적일 때 |
| 차원 축소 | 비지도 | PCA | 상관된 피처가 수백 개 | 해석 가능한 원본 피처가 꼭 필요할 때 |
| 토픽 모델링 | 비지도 | LDA, NTM | 문서에서 주제 발견 | 이미 카테고리 레이블이 있을 때(분류) |

## 지표 해석표 — 유형이 정해지면 지표도 정해진다

| 지표 | 계산 | 높으면 뜻하는 것 | 우선해야 할 상황 | 함정 |
|---|---|---|---|---|
| Accuracy | (TP+TN)/전체 | 전체적으로 자주 맞힘 | 클래스가 균형일 때만 | 불균형이면 "전부 음성"으로도 99%+ |
| Precision | TP/(TP+FP) | 오탐이 적음 | 오탐 비용이 큼(스팸 차단, 마케팅) | 소수만 양성 예측하면 쉽게 올라감 |
| Recall | TP/(TP+FN) | 미탐이 적음 | 미탐 비용이 큼(사기, 질병) | 전부 양성 예측하면 1.0 |
| F1 | precision·recall 조화평균 | 둘의 균형이 좋음 | 두 비용이 비슷할 때 | 어느 쪽이 문제인지 감춘다 |
| ROC-AUC | TPR-FPR 곡선 면적 | 임계값 무관 분별력 | 임계값 미정, 모델 비교 | 극단 불균형에서 과도하게 낙관적 |
| PR-AUC | precision-recall 곡선 면적 | 소수 클래스 분별력 | 극단 불균형(양성 1% 미만) | 클래스 비율이 바뀌면 값도 바뀜 |
| RMSE | 오차 제곱 평균의 제곱근 | 큰 오차가 적음 | 회귀, 큰 오차를 크게 벌주고 싶을 때 | 이상치에 민감 |
| MAE | 절대오차 평균 | 평균 오차가 작음 | 회귀, 이상치에 강건해야 할 때 | 큰 오차를 관대하게 봄 |

> ⚠️ **함정**: "사기가 전체의 1%"라는 문장이 지문에 있으면 accuracy가 들어간 보기는 거의 항상 오답이다. 전부 정상이라 찍어도 99%가 나오기 때문이다. 이 경우 재현율(놓치면 안 됨)이나 PR-AUC로 답이 이동한다.

## 알고리즘별 전처리 요구

문제 유형이 같아도 전처리 요구가 다르다. 시험은 "스케일링이 필요한가"를 반복해서 묻는다.

| 알고리즘 부류 | 대표 빌트인 | 스케일링 | 범주형 인코딩 | 결측치 |
|---|---|---|---|---|
| 트리 부스팅 | XGBoost | 불필요(스케일 불변) | 숫자화 필요 | 자체 처리 가능 |
| 선형 모델 | Linear Learner | 필요(정규화 옵션 제공) | 필요 | 사전 처리 필요 |
| 거리 기반 | KNN, K-Means | 필수 | 필요 | 사전 처리 필요 |
| 분산 기반 | PCA | 필요(중심화·스케일 권장) | 필요 | 사전 처리 필요 |
| 텍스트 | BlazingText | 해당 없음(토큰 입력) | 해당 없음 | 해당 없음 |

> 💡 **개념**: 트리는 한 피처 안에서 임계값으로 자르는 방식이라 값의 **순서만 유지되면 결과가 같다**(단조 변환 불변). 반면 거리 기반과 선형 모델은 피처 값이 곧 거리·기울기 계산에 들어가므로 스케일 차이가 결과를 직접 왜곡한다. 이 한 줄이 스케일링 문제 전부를 가른다.

## 알고리즘 선택 시 추가 고려사항

선택은 문제 유형만으로 끝나지 않는다.

| 고려 축 | 확인 질문 | 선택에 주는 영향 |
|---|---|---|
| 데이터 형태 | 표/텍스트/이미지/시계열 중 무엇인가 | 알고리즘 부류를 가장 강하게 제약한다 |
| 데이터 크기·희소성 | 수억 행인가, 원핫으로 폭발했는가 | 매우 큰 희소 → Linear Learner/FM, 중간 규모 정형 → XGBoost |
| 해석 가능성 | 규제·심사에 설명이 필요한가 | 선형 모델이 유리(계수 해석) |
| 학습·추론 비용 | GPU·시간 예산이 있는가 | 딥러닝은 비용↑. 단순 문제에 과한 모델은 피한다(KISS) |
| 온라인/실시간 요구 | 스트림에서 즉시 판단해야 하는가 | 실시간 이상 탐지는 Kinesis Data Analytics RCF |
| 콜드 스타트 | 신규 항목·짧은 이력이 있는가 | 관련 시계열을 공유 학습하는 DeepAR가 유리 |

### 빌트인을 직접 쓸 것인가, 관리형 AI 서비스로 갈 것인가

지문에 "ML 전문 인력이 없다", "빠르게 출시", "모델을 직접 학습·관리하고 싶지 않다"가 보이면 빌트인 알고리즘이 아니라 상위 AI 서비스가 정답이다.

| 상황 | SageMaker 빌트인 경로 | 관리형 AI 서비스 경로 |
|---|---|---|
| 문서 감성·개체 추출 | BlazingText로 직접 학습 | Amazon Comprehend |
| 이미지 라벨·얼굴 인식 | Image Classification 학습 | Amazon Rekognition |
| 시계열 수요 예측 | DeepAR 학습·튜닝 | Amazon Forecast |
| 개인화 상품 추천 | Factorization Machines 학습 | Amazon Personalize |
| 커스텀 피처·완전한 제어 필요 | 빌트인 또는 자체 컨테이너 | 부적합(커스터마이즈 한계) |

> ⚠️ **함정**: 반대 방향의 함정도 있다. "우리 도메인 전용 피처를 섞어 정교하게 튜닝해야 한다"는 지문에 관리형 AI 서비스를 고르면 오답이다. **제어 수준 요구**가 두 경로를 가른다.

## 지문 단서 → 정답 매핑표

시험 팁은 "지문 표현 → 후보 알고리즘"의 사전으로 외우는 것이 가장 빠르다.

| 지문 단서 | 밀리는 방향 | 이유 |
|---|---|---|
| "출력이 범주다 / 예/아니오" | 분류(XGBoost, Linear Learner) | 출력 형태가 유형을 결정 |
| "금액·수량을 예측" | 회귀(XGBoost, Linear Learner) | 연속 수치 출력 |
| "레이블이 없다 / 그룹을 발견" | K-Means | 비지도 신호 |
| "주제를 찾는다 / 문서 더미" | LDA, NTM | 토픽 모델링 신호 |
| "시계열 / 미래 값 / 계절성" | DeepAR, Amazon Forecast | 일반 회귀가 아닐 수 있다 |
| "텍스트" | BlazingText | XGBoost가 아니라 텍스트 전용 |
| "이미지" | Image Classification | XGBoost가 아니라 비전 전용 |
| "극히 드문 / 새로운 형태의 비정상" | Random Cut Forest | 레이블 부족 + 패턴 변화 |
| "계정과 IP 조합이 평소와 다르다" | IP Insights | 엔티티-IP 특화 |
| "피처가 너무 많다 / 압축" | PCA | 차원 축소 신호 |
| "사용자-아이템 / 매우 희소" | Factorization Machines | 희소 2차 상호작용 |

> ⚠️ **함정**: 출력 형태를 확정하기 전에 알고리즘 이름부터 고르면 틀린다. "고객 세분화"는 군집처럼 보이지만 지문에 세그먼트 레이블이 이미 존재하면 다중 분류가 정답이다. **레이블 유무가 지도/비지도를 뒤집는다.**

## 시나리오를 푸는 5단계 순서

Specialty 지문은 제약을 여러 개 겹쳐 놓는다. 아래 순서로 읽으면 대부분 하나로 좁혀진다.

1. **출력 형태 확정** — 범주/수치/그룹/추천/이상/주제 중 무엇인가.
2. **레이블 유무 확인** — 없으면 지도학습 보기가 전부 탈락한다.
3. **데이터 형태 확인** — 표/텍스트/이미지/시계열/희소 중 무엇인가. 여기서 빌트인이 거의 하나로 좁혀진다.
4. **제약 대입** — 데이터 크기, 해석 가능성, GPU·비용, 실시간 여부.
5. **전처리·지표 정합성 검사** — 스케일링 요구와 불균형 지표가 보기와 모순되지 않는지 본다.

> ⚠️ **함정**: 제약이 충돌하는 지문에서는 가장 화려한 기술이 아니라 **모든 제약을 동시에 만족하는 선택**이 정답이다. 제약을 하나라도 어기면(예: 레이블이 없는데 지도 분류) 나머지 장점과 무관하게 오답이다.

내일부터는 이 매핑 표의 각 빌트인 알고리즘(XGBoost, Linear Learner, K-Means, KNN)을 하나씩 깊이 파고든다.

## 📖 용어

- **지도학습** : 입력과 정답 레이블 쌍으로 매핑을 배우는 학습. 분류·회귀가 여기 속한다.
- **비지도학습** : 레이블 없이 데이터의 구조만으로 그룹·이상·주제를 찾는 학습.
- **다중 레이블(multi-label)** : 한 샘플에 여러 정답이 동시에 붙는 문제. 사진 한 장에 태그 여러 개.
- **콜드 스타트** : 신규 사용자·상품·매장처럼 이력이 거의 없어 예측이 어려운 상황.
- **희소성(sparsity)** : 행렬 대부분의 칸이 비어 있는 상태. 사용자-아이템 평점 행렬이 전형이다.
- **엘보우(WCSS)** : 군집 수 k를 늘려가며 군집 내 제곱합 감소가 꺾이는 지점을 찾는 k 선택법.
- **실루엣 계수** : 한 점이 자기 군집에 얼마나 잘 붙어 있는지를 -1~1로 나타내는 군집 품질 지표.
- **PR-AUC** : precision-recall 곡선 아래 면적. 양성이 극히 드문 데이터에서 ROC-AUC보다 정직하다.
- **단조 변환 불변** : 값의 크기 순서만 유지되면 결과가 같은 성질. 트리 모델이 여기 해당해 스케일링이 불필요하다.
- **SageMaker 빌트인 알고리즘** : AWS가 컨테이너로 제공해 코드 없이 하이퍼파라미터만으로 학습시킬 수 있는 알고리즘 모음.

## 📝 연습 문제

**문제 1.** 한 통신사가 "다음 달 해지할 가능성이 높은 고객을 미리 식별"하려 한다. 과거 고객의 해지 여부 레이블이 충분히 있다. 이 문제의 ML 유형으로 가장 적절한 것은?

A) 비지도 군집  
B) 이진 분류  
C) 시계열 예측  
D) 토픽 모델링  

**정답: B**  
해설: 출력이 "해지/유지"라는 두 범주이고 레이블이 있으므로 지도학습 이진 분류다. 레이블이 있으므로 비지도 군집(A)·토픽(D)이 아니며, 출력이 연속 수치가 아니므로 시계열 예측(C)도 아니다.

---

**문제 2.** 신용카드 거래에서 사기를 잡으려 한다. 사기 레이블은 거의 없고, 사기 수법은 계속 새로운 형태로 바뀐다. 가장 적합한 접근은?

A) 정상/사기 레이블로 다중 분류 학습  
B) K-Means로 고객을 5개 그룹으로 군집  
C) Random Cut Forest 같은 비지도 이상 탐지  
D) DeepAR로 거래 금액을 예측  

**정답: C**  
해설: 레이블이 거의 없고 패턴이 계속 변하므로, 정상에서 벗어남을 측정하는 비지도 이상 탐지가 견고하다. 레이블이 부족해 지도 분류(A)는 어렵고, 군집(B)은 사기 식별 목적과 맞지 않으며, DeepAR(D)는 시계열 값 예측용이다.

---

**문제 3.** "수천 개 뉴스 기사를 사람이 라벨을 달지 않은 상태에서 자동으로 주제별로 묶고, 각 주제를 구성하는 단어를 알고 싶다." 가장 적절한 알고리즘 부류는?

A) Image Classification  
B) Factorization Machines  
C) Linear Learner 회귀  
D) 토픽 모델링(LDA/NTM)  

**정답: D**  
해설: 레이블 없이 문서에서 주제를 발견하고 주제별 단어 분포를 얻는 것은 토픽 모델링(LDA/NTM)의 전형적 과제다. 이미지(A), 추천(B), 연속값 회귀(C)는 텍스트 주제 발견과 무관하다.

---

**문제 4.** 다음 중 "출력이 연속 수치인 회귀 문제"에 해당하는 것은?

A) 내일의 매장 매출 금액 예측  
B) 이메일을 스팸/정상으로 분류  
C) 고객을 비슷한 군집으로 묶기  
D) 평소와 다른 로그인 패턴 탐지  

**정답: A**  
해설: 매출 "금액"은 연속 수치이므로 회귀다. 스팸/정상(B)은 분류, 군집(C)은 비지도 클러스터링, 비정상 패턴 탐지(D)는 이상 탐지에 해당한다.

**문제 5.** 알고리즘을 좁히는 1차 기준으로 시험에서 가장 먼저 확인해야 할 단서는?

A) 사용할 인스턴스 타입  
B) 팀이 선호하는 프로그래밍 언어  
C) 모델의 출력 형태(범주/수치/그룹/추천/이상)와 레이블 유무  
D) 리전별 서비스 가용성  

**정답: C**  
해설: 출력 형태와 레이블 유무가 ML 문제 유형을 결정하고, 유형이 정해지면 후보 알고리즘이 크게 좁혀진다. 인스턴스 타입(A)·언어(B)·리전(D)은 알고리즘 부류 선택의 1차 기준이 아니다.
