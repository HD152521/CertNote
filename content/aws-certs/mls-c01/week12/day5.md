# Day 5 - D-Day 마무리: 시험 구성·시간 배분·요구사항 번역표·함정 총정리

## 📌 핵심 정리

- 65문항 / 180분 / 750점(1000점 만점) 합격. **도메인별 과락은 없고** 전체 스케일 점수로만 판정한다.
- 1패스는 확실한 문항부터 약 2분 페이스, 헷갈리면 **즉답 + 플래그**. 빈칸은 0점이므로 반드시 채운다.
- 모든 문항의 본질은 "요구사항 문장 → 기법·서비스" 번역이다. **관리 부담 · 데이터 형태 · 비즈니스 비용** 세 축으로 좁힌다.
- 함정의 절반은 **방향 반대**(Sigmoid↔Softmax, Maximize↔Minimize), 절반은 **도메인 혼동**(Monitor↔Debugger↔Clarify)이다.
- 비중이 가장 큰 **도메인 3(36%)**의 정확도가 점수 기대값을 가장 크게 움직인다.

오늘은 새 지식을 넣지 않는다. 시험장에서 그대로 쓸 수 있는 **운영 매뉴얼**만 만든다.

## 헷갈리는 짝 대조표

| 짝 | 갈리는 기준 | 왼쪽을 고를 때 | 오른쪽을 고를 때 |
|---|---|---|---|
| Sigmoid ↔ Softmax | 출력 클래스 수 | 이진 분류 출력 | 다중 클래스 출력(합=1) |
| Maximize ↔ Minimize | 목적 지표의 방향 | 성능 지표(F1·AUC·정확도) | 오차 지표(RMSE·MAE·loss) |
| Streams ↔ Firehose | 관리 부담과 소비 방식 | 밀리초·다중 소비자·재처리 | 완전관리 적재, 버퍼 후 S3 |
| Canary ↔ Shadow | 사용자에게 결과가 가는가 | 일부 사용자에게 실제 응답, 점진 전환 | 트래픽 복제, 응답 미반환(무위험) |
| 정밀도 ↔ 재현율 | 어떤 오류가 비싼가 | FP(오탐)가 비쌈 — 스팸 분류 | FN(미탐)이 비쌈 — 질병 선별 |
| 오버샘플링 ↔ 언더샘플링 | 데이터 총량이 충분한가 | 소수 클래스가 절대적으로 부족 | 다수 클래스가 과하고 데이터 충분 |
| Model Monitor ↔ CloudWatch ↔ CloudTrail | 무엇을 보는가 | 드리프트(입력 분포·모델 품질) | 인프라 지표·로그 / API 호출 감사 |
| Debugger ↔ Clarify | 학습 과정인가 결과 설명인가 | 학습 중 텐서·기울기 이상 | 편향(Disparate Impact)·SHAP 설명 |
| Batch Transform ↔ Async Inference | 일괄인가 요청 단위인가 | 정해진 데이터셋 전량, 엔드포인트 불필요 | 큰 페이로드·긴 처리, 요청별 큐잉 |
| Glue ↔ EMR | 서버리스인가 클러스터 제어인가 | 빠른 ETL·데이터 카탈로그 | Spark/하둡 세밀 튜닝 |
| Athena ↔ Redshift | 애드혹 조회인가 웨어하우스인가 | S3 위 서버리스 SQL, 간헐 탐색 | 대규모 정형 분석, 상시 BI |

## 자주 틀리는 함정 모음

| 함정 | 올바른 판단 |
|------|------|
| 불균형 데이터에 정확도(Accuracy) | F1 / PR-AUC로 (정확도 금지) |
| 트리/XGBoost에 표준화 "필수" | 트리는 스케일 불변, 사실상 불필요 |
| 다중 클래스 출력에 Sigmoid | Softmax가 맞음 |
| 회귀 출력에 Softmax | 선형(활성화 없음)이 맞음 |
| Streams vs Firehose 혼동 | 커스텀/저지연=Streams, 완전관리=Firehose |
| Canary vs Shadow 혼동 | 점진 전환=Canary, 무위험 복제 검증=Shadow |
| Model Monitor vs CloudWatch | 드리프트=Monitor, 인프라 지표=CloudWatch |
| Debugger vs Clarify | 학습 과정=Debugger, 편향·설명=Clarify |
| 대량 오프라인에 Real-time | Batch Transform이 비용 우위 |
| RMSE를 분류에, F1을 회귀에 | 회귀=RMSE/MAE/R², 분류=정밀도/재현율/F1/AUC |
| AMT 목적 지표 방향 | 오차=Minimize, 성능=Maximize |
| 데이터 누수(전처리를 분할 전 전체에) | 학습셋으로 fit, 검증/테스트엔 transform만 |
| 시계열을 랜덤 셔플로 분할 | 시점 기준 분할(과거→미래) |
| 과소적합인데 정규화를 더 강하게 | 반대 — 복잡도를 올리고 더 학습 |
| PCA 전 표준화 생략 | 분산 기반이라 표준화가 선행돼야 함 |
| t-SNE 좌표를 모델 입력으로 | 시각화 전용, 신규 데이터 변환 불가 |
| 배포 후 문제인데 Debugger | 배포 후는 Model Monitor |
| 드리프트 대응으로 CloudTrail | CloudTrail은 API 감사 도구일 뿐 |
| "실시간"만 보고 Real-time Endpoint | 수집의 실시간(Kinesis)과 추론의 실시간은 다른 층위 |
| 장시간 학습 잡을 Lambda로 실행 | SageMaker 학습 잡 / Pipelines |
| 복수 정답 문항에서 개수 무시 | "두 개를 고르시오" 지시를 정확히 셀 것 |

> 💡 **관련 이론**: 함정의 절반은 "방향 반대"이고 절반은 "도메인 혼동"이다. 방향 함정(Sigmoid↔Softmax, Maximize↔Minimize, Streams↔Firehose)은 짝을 외워두면 즉시 걸러진다. 데이터 누수는 특히 교묘한데, 스케일러·인코더를 학습/검증을 합친 전체에 fit하면 검증 정보가 새어 평가가 낙관 편향된다. 반드시 학습셋으로만 fit하고 검증·테스트에는 transform만 적용한다 — 이 한 줄이 자주 보기로 위장해 출제된다.

## D-Day 체크리스트

- 신분증 2종, 시험 시간·장소(또는 온라인 프록터 환경) 사전 확인.
- 온라인 응시면 책상 정리·조명·네트워크·카메라를 전날 점검.
- 시작 전 화장실·물, 180분 집중 컨디션 정비.
- 시작 5분 전에는 새 내용 학습 금지 — 위 60초 리마인더만 훑는다.
- 지문은 끝까지 읽고 **마지막 제약 문장**(비용·운영·규제 조건)을 먼저 표시.
- `MOST` / `BEST` / `LEAST` 같은 최상급 어휘에 표시하며 읽기.
- 1패스: 확실한 것부터, 헷갈리면 즉답 + 플래그.
- 명백한 오답 2개를 먼저 지우고, 남은 2개를 지문의 제약으로 비교.
- 복수 정답 문항은 "몇 개 고르라"는 지시를 정확히 읽기.
- 빈칸 금지 — 시간 부족해도 추정 답 마킹.
- 마지막 10분 마킹 누락·플래그 재확인.

12주를 거쳐 데이터 엔지니어링, EDA, 모델링, 구현·운영의 네 도메인을 모두 통과했다. 그동안 충분히 준비했다 — 합격을 기원한다.

## 📖 용어

- **스케일 점수(scaled score)** : 문항 난이도를 보정해 1000점 만점으로 환산한 점수. 750점 이상이면 합격이다.
- **비채점 문항(unscored item)** : 통계 수집용으로 섞여 있는 15문항. 어느 것인지 표시되지 않으므로 전부 성실히 풀어야 한다.
- **1패스 / 2패스** : 전체를 한 번 훑고(1패스) 플래그한 문항만 다시 보는(2패스) 풀이 전략.
- **플래그(flag)** : 나중에 다시 볼 문항을 시험 화면에서 표시해 두는 기능.
- **요구사항 번역** : 지문의 자연어 조건을 기법·서비스 이름으로 바꾸는 작업. 이 시험의 본질이다.
- **방향 함정** : 짝을 이루는 두 선택지의 방향만 뒤집어 오답을 만드는 출제 방식(Sigmoid↔Softmax, Maximize↔Minimize).
- **도메인 혼동 함정** : 역할이 비슷해 보이는 서비스를 바꿔 넣는 출제 방식(Model Monitor↔Debugger↔Clarify).
- **데이터 누수(data leakage)** : 학습 시점에 알 수 없는 정보가 피처·전처리를 통해 새어 들어가 평가가 낙관 편향되는 것.
- **복수 정답 문항** : "두 개를 고르시오"처럼 정답 개수를 지정하는 유형. 개수 지시를 정확히 읽어야 한다.
- **MOST appropriate** : 여러 보기가 모두 가능할 때, 지문이 강조한 제약에 가장 부합하는 하나를 고르라는 시험 어법.

## 📝 연습 문제

**문제 1.** MLS-C01 시험 구성에 대한 설명으로 옳은 것은?

A) 65문항 중 15문항은 채점되지 않으며 어느 것인지 표시되지 않는다  
B) 65문항을 90분 안에 풀어야 한다  
C) 도메인별 과락 기준이 있어 각 도메인에서 일정 점수를 넘어야 한다  
D) 합격 점수는 1000점 만점에 600점이다  

**정답: A**  
해설: 65문항 중 15문항은 비채점이며 표시되지 않으므로 모든 문항을 성실히 풀어야 한다. 시간은 180분(B 오답), 도메인별 과락은 없고 전체 스케일 점수로 판정하며(C 오답), 합격선은 750점이다(D 오답).

**문제 2.** 시험 시간 배분 전략으로 가장 권장되는 것은?

A) 어려운 문항 하나에 10분 이상 써서 반드시 맞힌다  
B) 확실한 문항을 빠르게 처리하고, 헷갈리면 즉답 후 플래그해 2패스에서 재검토한다  
C) 모르는 문항은 빈칸으로 두고 넘어간다  
D) 모든 문항에 정확히 같은 시간을 강제 배분한다  

**정답: B**  
해설: 쉬운 문항을 빠르게 끝내 어려운 시나리오에 시간을 몰아주고, 헷갈리면 즉답+플래그로 페이스를 지키는 것이 정석이다. 한 문항에 10분(A)은 기대 손실이 크고, 빈칸(C)은 0점이라 반드시 추정 답을 채워야 하며, 시간 균등 강제(D)는 비효율적이다.

**문제 3.** 다음 중 "요구사항 → 서비스" 번역이 잘못된 것은?

A) "운영을 최소화하며 스트림을 S3로 적재" → Kinesis Data Firehose  
B) "배포 후 입력 분포 변화 자동 감지" → Model Monitor  
C) "사용자에게 영향 없이 프로덕션 트래픽으로 신모델 검증" → Canary 배포  
D) "집단 공정성 측정과 SHAP 설명" → SageMaker Clarify  

**정답: C**  
해설: 사용자 영향 없이 트래픽을 복제해 검증하는 것은 Shadow 테스트이며, Canary는 실제 사용자에게 일부 신모델 응답이 가는 점진 전환이다. A·B·D는 모두 올바른 번역이다.

**문제 4.** 다음 중 시험에서 자주 등장하는 함정에 대한 올바른 판단은?

A) 클래스가 95:5로 불균형해도 정확도(Accuracy)만으로 충분히 평가할 수 있다  
B) XGBoost 학습 전에는 모든 수치 피처의 표준화가 반드시 필요하다  
C) 다중 클래스 분류의 출력 활성화 함수로 Sigmoid를 써야 한다  
D) 전처리 스케일러는 학습셋으로만 fit하고 검증·테스트에는 transform만 적용한다  

**정답: D**  
해설: 데이터 누수를 막으려면 스케일러·인코더를 학습셋으로만 fit하고 검증/테스트에는 transform만 적용해야 한다. 불균형에 정확도 단독(A)은 부적절하고, 트리 기반 XGBoost는 스케일 불변이라 표준화가 사실상 불필요하며(B), 다중 클래스 출력은 Softmax가 맞다(C).

**문제 5.** 점수 기대값을 가장 효과적으로 높이는 학습 우선순위로 옳은 것은?

A) 비중이 가장 작은 도메인 1·4만 집중한다  
B) 모든 도메인을 버리고 한 도메인만 100% 만든다  
C) 비중이 가장 큰 도메인 3(모델링, 36%)의 정확도를 끌어올린다  
D) 비채점 문항을 찾아내 그 문항만 건너뛴다  

**정답: C**  
해설: 합격은 전체 스케일 점수로 판정되므로, 비중이 가장 큰 도메인 3(36%)의 정확도를 높이는 것이 기대 점수를 가장 크게 끌어올린다. 작은 도메인만 집중(A)·단일 도메인 올인(B)은 비효율적이고, 비채점 문항은 표시되지 않아 식별·건너뛰기(D)가 불가능하다.
