# Day 3 - 1차 과목③ 종합 모의: 네트워크와 서비스의 활용 약점 정리

셋째 날은 1차 필기의 마지막 과목 **"네트워크와 서비스의 활용"**을 종합한다. 이 과목은 **개념(OSI·TCP/IP·서브넷) + 서비스별 핵심(DNS·Web·Mail·FTP·SSH) + 포트·설정파일 암기**가 뒤섞여 있어 범위가 가장 넓다. 포트 번호 하나, 설정 파일 경로 하나가 정답을 가르므로 **"서비스 = 데몬 = 포트 = 설정파일"의 4종 세트**를 묶어 외우는 것이 핵심 전략이다. 오늘은 네트워크 기초부터 각 서비스, 보안까지 약점을 압축하고 10문항 모의로 마무리한다.

## 약점 정리 1: 네트워크 기초 — OSI와 TCP/IP

OSI 7계층과 TCP/IP 4계층의 대응, 각 계층 장비·프로토콜이 출제된다.

| OSI 계층 | 예시 | 장비 |
|----------|------|------|
| 7 응용 | HTTP, FTP, DNS | - |
| 4 전송 | TCP, UDP | - |
| 3 네트워크 | IP, ICMP | 라우터, L3 스위치 |
| 2 데이터링크 | MAC, 이더넷 | 스위치, 브리지 |
| 1 물리 | 케이블, 비트 | 허브, 리피터 |

서브넷 계산도 단골이다. **/24 = 255.255.255.0 = 256개(사용 254)**. 비트 수만큼 네트워크부, 나머지가 호스트부.

| CIDR | 서브넷 마스크 | 호스트 수(사용) |
|------|---------------|------------------|
| /24 | 255.255.255.0 | 254 |
| /25 | 255.255.255.128 | 126 |
| /26 | 255.255.255.192 | 62 |
| /27 | 255.255.255.224 | 30 |

> 💡 **TCP vs UDP**: TCP는 연결지향·신뢰성(3-way 핸드셰이크), UDP는 비연결·빠름(DNS 조회·스트리밍). 같은 서비스도 둘 다 쓸 수 있다(DNS는 53/UDP·53/TCP).

## 약점 정리 2: 포트 번호 총정리 (최빈출)

포트 암기표는 이 과목의 심장이다. 통째로 외운다.

| 서비스 | 포트 | 프로토콜 |
|--------|------|----------|
| FTP | 20(데이터)/21(제어) | TCP |
| SSH | 22 | TCP |
| Telnet | 23 | TCP |
| SMTP | 25 | TCP |
| DNS | 53 | UDP/TCP |
| DHCP | 67/68 | UDP |
| HTTP | 80 | TCP |
| POP3 | 110 | TCP |
| NTP | 123 | UDP |
| IMAP | 143 | TCP |
| HTTPS | 443 | TCP |
| SMTPS | 465 | TCP |
| Syslog | 514 | UDP |

> ⚠️ **FTP 함정**: 제어는 **21**, 데이터는 **20**(액티브 모드). 패시브 모드에선 데이터 포트가 동적으로 바뀐다. "FTP 포트"만 물으면 21이 정답인 경우가 많다.

## 약점 정리 3: DNS — BIND와 레코드

DNS 서버는 BIND, 설정은 `/etc/named.conf`와 존 파일로 나뉜다.

| 레코드 | 의미 |
|--------|------|
| A | 호스트명 → IPv4 |
| AAAA | 호스트명 → IPv6 |
| MX | 메일 서버(우선순위) |
| CNAME | 별칭(별명 → 정식명) |
| NS | 네임서버 지정 |
| PTR | IP → 호스트명(역방향) |
| SOA | 존 권한 시작·갱신 정보 |

클라이언트 설정 파일: `/etc/resolv.conf`(네임서버 지정), `/etc/hosts`(로컬 정적 매핑), `/etc/nsswitch.conf`(조회 순서).

> 🔍 **조회 도구**: `nslookup`, `dig`(상세), `host`(간단). 역방향은 PTR 레코드, IP→이름 변환에 쓴다.

## 약점 정리 4: Web(Apache)과 Mail

Apache(httpd) 설정 핵심 지시어를 외운다.

| 지시어 | 의미 |
|--------|------|
| `ServerName` | 서버 도메인 |
| `DocumentRoot` | 문서 루트 경로 |
| `Listen` | 수신 포트 |
| `<VirtualHost>` | 가상 호스트 |
| `DirectoryIndex` | 기본 문서(index.html) |

메일은 **전송(SMTP)과 수신(POP3/IMAP)**으로 나뉜다.

| 구분 | 프로토콜 | 역할 |
|------|----------|------|
| MTA | SMTP | 메일 전송(sendmail/postfix) |
| MDA | - | 메일함에 배달(procmail) |
| MUA | POP3/IMAP | 사용자 읽기(클라이언트) |

> 📚 **POP3 vs IMAP**: POP3는 받아서 서버에서 지움(로컬 보관), IMAP은 서버에 두고 동기화(여러 기기). 멀티 디바이스엔 IMAP이 유리.

## 약점 정리 5: FTP와 SSH

FTP는 vsftpd가 대표, 모드 구분이 핵심이다.

| 모드 | 연결 방향 | 특징 |
|------|-----------|------|
| 액티브 | 서버→클라이언트 데이터 | 클라 방화벽 문제 가능 |
| 패시브 | 클라이언트→서버 데이터 | 방화벽 친화적 |

SSH는 보안 원격 접속의 표준이다.

| 항목 | 내용 |
|------|------|
| 포트 | 22 |
| 데몬 | sshd |
| 설정 | `/etc/ssh/sshd_config` |
| 키 인증 | `ssh-keygen`, `authorized_keys` |
| 파일 전송 | `scp`, `sftp` |

> ⚠️ **보안 설정**: `sshd_config`에서 `PermitRootLogin no`(root 직접 로그인 차단), `Port` 변경, 키 인증 권장이 단골. Telnet(23, 평문)은 SSH로 대체해야 한다.

## 약점 정리 6: 네트워크 명령과 보안

진단·설정 명령을 정리한다.

| 명령 | 역할 |
|------|------|
| `ip`/`ifconfig` | 인터페이스 설정·확인 |
| `ping` | 연결 확인(ICMP) |
| `traceroute` | 경로 추적 |
| `netstat`/`ss` | 연결·포트 상태 |
| `nslookup`/`dig` | DNS 조회 |
| `route`/`ip route` | 라우팅 테이블 |
| `arp` | MAC-IP 매핑 |

> 💡 **상태 확인 한 줄**: 열린 포트·LISTEN 상태는 `ss -tlnp`(또는 `netstat -tlnp`)로 본다. 어떤 프로세스가 어느 포트를 쓰는지 한눈에 파악.

## 약점 정리 7: DHCP와 NTP

자동 IP 할당과 시간 동기화도 출제 범위다.

| 서비스 | 포트 | 설정 파일 | 역할 |
|--------|------|-----------|------|
| DHCP | 67(서버)/68(클라) | `/etc/dhcp/dhcpd.conf` | IP 자동 할당 |
| NTP | 123 | `/etc/ntp.conf`(chrony는 chrony.conf) | 시간 동기화 |

DHCP의 IP 임대(lease) 개념과 NTP의 stratum(계층) 구조가 키워드다.

> 🔍 **DHCP 4단계(DORA)**: Discover(탐색)→Offer(제안)→Request(요청)→Ack(확인). 클라이언트가 브로드캐스트로 서버를 찾고 IP를 임대받는 흐름.

## 약점 정리 8: 네트워크 설정 파일과 본딩

RHEL 계열의 인터페이스 설정 파일 구조를 정리한다.

| 파일 | 용도 |
|------|------|
| `ifcfg-eth0` | 인터페이스별 IP·게이트웨이 |
| `/etc/sysconfig/network` | 전역 네트워크 설정 |
| `/etc/hostname` | 호스트명 |
| `/etc/hosts` | 정적 이름 해석 |

핵심 항목: `BOOTPROTO`(static/dhcp), `IPADDR`, `NETMASK`, `GATEWAY`, `ONBOOT`(부팅 시 활성화), `DNS1`.

> ⚠️ **ONBOOT 함정**: `ONBOOT=no`면 부팅 시 인터페이스가 올라오지 않는다. IP를 다 맞춰도 ONBOOT가 no면 네트워크가 안 되는 단골 함정이다.

## 약점 정리 9: 보안 — 침입 차단과 스캔 대응

네트워크 보안 개념도 과목③에 포함된다.

| 개념 | 설명 |
|------|------|
| 방화벽 | iptables/firewalld로 트래픽 통제 |
| TCP Wrapper | `hosts.allow`/`hosts.deny` 접근 제어 |
| 포트 스캔 | nmap 등으로 열린 포트 탐색(공격 정찰) |
| IDS/IPS | 침입 탐지/차단 시스템 |

> 📚 **보안 한 줄**: 평문 프로토콜(Telnet 23, FTP 21)은 암호가 그대로 전송돼 도청에 취약하다. SSH(22)·SFTP·HTTPS(443)로 암호화 대체가 원칙이다.

## 약점 정리 10: IP 주소 체계와 특수 주소

IPv4 클래스와 사설 IP 대역은 단순 암기지만 자주 틀린다.

| 클래스 | 범위(첫 옥텟) | 기본 마스크 | 용도 |
|--------|---------------|-------------|------|
| A | 1~126 | /8 | 대규모 |
| B | 128~191 | /16 | 중규모 |
| C | 192~223 | /24 | 소규모 |
| D | 224~239 | - | 멀티캐스트 |
| E | 240~255 | - | 연구·예약 |

사설 IP 대역도 외운다 — A급 `10.0.0.0/8`, B급 `172.16.0.0/12`, C급 `192.168.0.0/16`.

| 특수 주소 | 의미 |
|-----------|------|
| `127.0.0.1` | 루프백(자기 자신) |
| `0.0.0.0` | 모든 주소·미지정 |
| `255.255.255.255` | 제한 브로드캐스트 |

> ⚠️ **127 vs 126**: A클래스는 1~126이고 127은 루프백 전용으로 빠진다. "A클래스 최대 첫 옥텟은?"의 답은 127이 아니라 **126**.

## 약점 정리 11: IPv6와 라우팅 상식

IPv6는 128비트, 16진수 8그룹(콜론 구분)이다. 연속된 0 그룹은 `::`로 한 번 축약 가능하다.

| 구분 | IPv4 | IPv6 |
|------|------|------|
| 비트 | 32 | 128 |
| 표기 | 점 10진수 | 콜론 16진수 |
| 주소 고갈 | 문제됨 | 사실상 무한 |
| 루프백 | 127.0.0.1 | ::1 |

라우팅은 정적(`route add`/`ip route add`)과 동적(RIP·OSPF·BGP)으로 나뉜다. 기본 게이트웨이는 목적지가 라우팅 테이블에 없을 때 보내는 출구다.

> 🔍 **`::` 규칙**: IPv6에서 `::`(연속 0 축약)은 한 주소에 **딱 한 번만** 쓸 수 있다. 두 번 쓰면 어디까지가 0인지 모호해져 무효다.

## 마무리

네트워크 과목은 **"포트표 + 서비스별 설정파일 + 레코드/지시어"**의 단순 암기 비중이 매우 높다. 포트 번호(22/25/53/80/443), DNS 레코드(A/MX/CNAME/PTR), 메일 프로토콜(SMTP/POP3/IMAP), FTP 모드, SSH 보안 설정 — 이 다섯을 확실히 잡으면 과목③은 안정권이다. 아래 모의로 점검하자.

## 📝 연습 문제

**문제 1.** OSI 7계층 중 라우터가 동작하며 IP·ICMP 프로토콜이 속한 계층은?

A) 2계층(데이터링크)
B) 3계층(네트워크)
C) 4계층(전송)
D) 7계층(응용)

**정답: B**
해설: IP·ICMP는 3계층(네트워크)에 속하며 라우터가 이 계층에서 경로를 결정한다. 스위치는 2계층, TCP/UDP는 4계층이다.

---

**문제 2.** 제어 연결과 데이터 연결을 분리해 사용하며, 제어 포트로 21번을 쓰는 서비스는?

A) SSH
B) FTP
C) Telnet
D) SMTP

**정답: B**
해설: FTP는 제어(21)와 데이터(액티브 20)를 분리하는 특이 구조다. SSH는 22, Telnet은 23, SMTP는 25를 사용한다.

---

**문제 3.** DNS에서 IP 주소를 호스트명으로 변환하는 역방향 조회에 사용되는 레코드는?

A) A
B) MX
C) PTR
D) CNAME

**정답: C**
해설: PTR 레코드는 IP→호스트명 역방향 조회에 쓰인다. A는 정방향(이름→IPv4), MX는 메일 서버, CNAME은 별칭이다.

---

**문제 4.** 메일 서버에서 메일을 다른 서버로 전송하는 역할(MTA)이 사용하는 프로토콜과 포트는?

A) POP3 - 110
B) IMAP - 143
C) SMTP - 25
D) HTTP - 80

**정답: C**
해설: MTA(sendmail/postfix)는 SMTP(25)로 메일을 전송한다. POP3(110)·IMAP(143)은 사용자가 메일을 읽어오는 수신용 프로토콜이다.

---

**문제 5.** 여러 기기에서 동일한 메일함을 동기화해 사용하기에 적합한 수신 프로토콜은?

A) POP3
B) IMAP
C) SMTP
D) NNTP

**정답: B**
해설: IMAP은 서버에 메일을 두고 여러 기기가 동기화해 보기에 적합하다. POP3는 서버에서 내려받아 삭제(로컬 보관)하는 방식이라 멀티 디바이스에 불리하다.

---

**문제 6.** `/24` 서브넷(255.255.255.0)에서 실제 호스트에 할당 가능한 IP 개수는?

A) 256개
B) 254개
C) 128개
D) 62개

**정답: B**
해설: /24는 256개 주소 중 네트워크 주소와 브로드캐스트 주소를 제외해 254개를 호스트에 쓸 수 있다.

---

**문제 7.** SSH 서버 보안을 위해 `/etc/ssh/sshd_config`에서 root의 직접 로그인을 차단하는 설정은?

A) `PermitRootLogin yes`
B) `PermitRootLogin no`
C) `AllowRoot off`
D) `RootLogin deny`

**정답: B**
해설: `PermitRootLogin no`로 설정하면 root 계정의 SSH 직접 로그인이 차단된다. 일반 계정으로 접속 후 su/sudo를 쓰도록 강제하는 보안 관행이다.

---

**문제 8.** DNS 클라이언트가 질의할 네임서버를 지정하는 설정 파일은?

A) `/etc/hosts`
B) `/etc/resolv.conf`
C) `/etc/named.conf`
D) `/etc/nsswitch.conf`

**정답: B**
해설: `/etc/resolv.conf`에 `nameserver` 항목으로 질의할 DNS 서버를 지정한다. `/etc/hosts`는 로컬 정적 매핑, `named.conf`는 BIND 서버 설정이다.

---

**문제 9.** 현재 시스템에서 LISTEN 상태인 포트와 해당 프로세스를 확인하는 명령으로 적절한 것은?

A) `ping -c 4 localhost`
B) `ss -tlnp`
C) `traceroute 8.8.8.8`
D) `arp -a`

**정답: B**
해설: `ss -tlnp`(또는 `netstat -tlnp`)는 TCP·LISTEN·숫자·프로세스 정보를 함께 보여준다. ping은 연결 확인, traceroute는 경로 추적, arp는 MAC 매핑이다.

---

**문제 10.** Apache(httpd) 설정에서 웹 문서의 최상위 디렉터리 경로를 지정하는 지시어는?

A) `ServerName`
B) `Listen`
C) `DocumentRoot`
D) `DirectoryIndex`

**정답: C**
해설: `DocumentRoot`가 웹 콘텐츠의 최상위 경로를 지정한다. `ServerName`은 도메인, `Listen`은 수신 포트, `DirectoryIndex`는 기본 문서를 지정한다.
