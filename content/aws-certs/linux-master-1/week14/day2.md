# Day 2 - 1차 과목② 종합 모의: 리눅스 시스템 관리 약점 정리

둘째 날은 1차 필기에서 배점이 가장 무거운 **"리눅스 시스템 관리"** 과목을 종합한다. 이 과목은 손에 익혀야 점수가 나오는 **실무형 암기**가 핵심이다 — 셸의 종류와 환경 변수, 파일 권한(특히 특수 권한), 디스크 관리(파티션·마운트·쿼터·RAID·LVM), 프로세스와 시그널, 패키지 관리(rpm/yum, dpkg/apt, 소스 컴파일)까지. 명령 옵션 한 글자, 권한 숫자 한 자리가 정답을 가른다. 오늘은 영역별로 자주 틀리는 지점을 표로 압축하고, 10문항 모의고사로 점검한다.

## 약점 정리 1: 셸과 환경 변수

셸은 명령 해석기다. 종류와 설정 파일, 변수 구분이 출제 포인트다.

| 셸 | 특징 |
|----|------|
| bash | 리눅스 기본, sh 호환 + 확장 |
| csh/tcsh | C 문법 유사, 히스토리 |
| ksh | 콘 셸, 상용 유닉스 다수 |
| zsh | 강력한 자동완성·플러그인 |

환경 변수와 셸 변수의 차이가 함정이다. **`export`로 내보내면 환경 변수**(자식 프로세스로 상속), 그냥 대입이면 셸 변수(상속 안 됨).

| 변수 | 의미 |
|------|------|
| `PATH` | 실행 파일 검색 경로 |
| `HOME` | 홈 디렉터리 |
| `PS1` | 기본 프롬프트 문자열 |
| `SHELL` | 로그인 셸 경로 |
| `LANG` | 기본 로케일·언어 |
| `UID` | 사용자 ID |

> 💡 **설정 파일 한 줄**: `/etc/profile`(전역·로그인), `~/.bash_profile`(개인·로그인 시 1회), `~/.bashrc`(개인·셸 열 때마다). alias는 보통 `.bashrc`에 둔다.

## 약점 정리 2: 파일 권한 — 특수 권한이 핵심

기본 권한 rwx(읽기4·쓰기2·실행1)는 기본이고, **특수 권한 3종**이 진짜 시험 포인트다.

| 특수 권한 | 숫자 | 의미 | 표기 |
|-----------|------|------|------|
| SetUID | 4000 | 실행 시 소유자 권한 | `s` (소유자 x 자리) |
| SetGID | 2000 | 실행 시 그룹 권한·디렉터리 그룹 상속 | `s` (그룹 x 자리) |
| Sticky Bit | 1000 | 소유자만 삭제 가능(공유 디렉터리) | `t` (기타 x 자리) |

대표 예: `/usr/bin/passwd`는 SetUID(일반 사용자가 `/etc/shadow` 수정 가능), `/tmp`는 Sticky Bit(누구나 쓰지만 자기 것만 삭제).

> ⚠️ **umask 함정**: umask는 권한을 **빼는** 값. 파일 기본 666, 디렉터리 777에서 umask를 뺀다. umask 022 → 파일 644, 디렉터리 755. 파일에 실행권한은 umask로 안 붙는다.

> 🔍 **대문자 S/T 주의**: 실행 권한(x)이 없는데 SetUID/Sticky가 붙으면 소문자가 아닌 **대문자 S/T**로 표시된다(권한 충돌 표시).

## 약점 정리 3: 디스크 관리 — 마운트·쿼터·RAID·LVM

디스크는 명령과 개념이 뒤섞여 까다롭다.

| 명령 | 역할 |
|------|------|
| `fdisk`/`parted` | 파티션 생성·관리 |
| `mkfs` | 파일시스템 생성(포맷) |
| `mount`/`umount` | 마운트·해제 |
| `df` | 디스크 사용량(파일시스템) |
| `du` | 디렉터리 사용량 |
| `fsck` | 파일시스템 점검·복구 |

`/etc/fstab` 필드 6개 순서: **장치 마운트점 파일시스템 옵션 dump fsck순서**. 부팅 시 자동 마운트 대상이다.

RAID 레벨도 단골이다.

| RAID | 특징 | 최소 디스크 |
|------|------|-------------|
| 0 | 스트라이핑, 속도↑, 무중복 | 2 |
| 1 | 미러링, 안정성↑ | 2 |
| 5 | 분산 패리티 1개 | 3 |
| 6 | 분산 패리티 2개 | 4 |
| 1+0 | 미러+스트라이프 | 4 |

> 📚 **LVM 3층 구조**: 물리볼륨(PV) → 볼륨그룹(VG) → 논리볼륨(LV). `pvcreate → vgcreate → lvcreate` 순. 무중단 용량 확장이 최대 장점.

## 약점 정리 4: 프로세스와 시그널

프로세스 상태·우선순위·시그널은 매년 출제된다.

| 명령 | 역할 |
|------|------|
| `ps` | 프로세스 스냅샷 |
| `top` | 실시간 모니터링 |
| `kill`/`killall` | 시그널 전송 |
| `nice`/`renice` | 우선순위 조정 |
| `jobs`/`fg`/`bg` | 작업 제어 |
| `nohup` | 로그아웃 후에도 유지 |

시그널 번호는 반드시 외운다.

| 번호 | 이름 | 의미 |
|------|------|------|
| 1 | SIGHUP | 재시작·설정 재로드 |
| 2 | SIGINT | 인터럽트(Ctrl+C) |
| 9 | SIGKILL | 강제 종료(무시 불가) |
| 15 | SIGTERM | 정상 종료(기본값) |
| 18/19 | SIGCONT/SIGSTOP | 재개/정지 |

> ⚠️ **nice 값 범위**: `-20`(최우선) ~ `19`(최저). 값이 **작을수록 우선순위 높음**. 음수 지정은 root만 가능.

> 💡 **kill 기본값**: `kill PID`는 기본 **15(SIGTERM)** 전송. 안 죽으면 `kill -9`. 9번은 프로세스가 무시·차단할 수 없다.

## 약점 정리 5: 패키지 관리 — RPM과 DEB

배포판 계열별 패키지 도구를 헷갈리지 말 것.

| 계열 | 저수준 | 고수준(의존성 자동) |
|------|--------|---------------------|
| Red Hat(rpm) | `rpm` | `yum`/`dnf` |
| Debian(deb) | `dpkg` | `apt`/`apt-get` |

| 작업 | rpm | yum |
|------|-----|-----|
| 설치 | `rpm -ivh` | `yum install` |
| 업그레이드 | `rpm -Uvh` | `yum update` |
| 삭제 | `rpm -e` | `yum remove` |
| 조회 | `rpm -qa` | `yum list` |
| 파일 소속 패키지 | `rpm -qf` | - |

> 🔍 **핵심 차이**: `rpm`/`dpkg`는 **의존성을 자동 해결 못 함**(에러만 알림). `yum`/`apt`는 저장소에서 의존 패키지를 자동으로 받아 해결한다.

> 📚 **소스 컴파일 3단계**: `./configure`(환경 점검·Makefile 생성) → `make`(컴파일) → `make install`(설치). configure 옵션 `--prefix`로 설치 경로 지정.

## 약점 정리 6: 사용자·그룹 관리 파일

계정 관리는 명령뿐 아니라 **백엔드 파일**도 출제된다.

| 파일 | 내용 | 권한 |
|------|------|------|
| `/etc/passwd` | 계정 기본 정보(7필드) | 644(공개) |
| `/etc/shadow` | 암호 해시·만료 정책 | 000/400(보호) |
| `/etc/group` | 그룹·구성원 | 644 |
| `/etc/skel` | 신규 계정 홈 템플릿 | - |
| `/etc/login.defs` | 계정 생성 기본값 | - |

passwd의 7필드(사용자명:x:UID:GID:설명:홈:셸)와 shadow의 암호 만료 필드를 묶어 외운다.

> 🔍 **UID 관례**: 0=root, 1~999=시스템 계정, 1000 이상=일반 사용자(배포판에 따라 500부터). UID 0인 계정은 root와 동일 권한이라 보안상 주의.

> ⚠️ **shadow가 보호되는 이유**: 암호 해시가 노출되면 오프라인 크래킹이 가능해 권한을 000/400으로 제한한다. passwd만 보면 비밀번호 자리에 `x`만 보이는 이유.

## 약점 정리 7: 작업 스케줄링 — cron과 at

시스템 관리의 자동화 도구도 이 과목에 속한다.

| 도구 | 용도 | 설정 |
|------|------|------|
| cron | 반복 작업 | `crontab -e`, `/etc/crontab` |
| at | 일회성 예약 | `at 시간` |
| anacron | 부팅 후 누락 작업 보충 | `/etc/anacrontab` |

cron 필드(분·시·일·월·요일)와 권한 제어 파일(`cron.allow`/`cron.deny`)이 함정이다.

> 💡 **allow/deny 우선순위**: `cron.allow`가 존재하면 거기 적힌 사용자만 허용(deny 무시). 없으면 `cron.deny`에 없는 사용자만 허용. allow가 deny보다 강하다.

## 약점 정리 8: 백업과 압축 명령

데이터 보호 명령도 단골이다.

| 명령 | 용도 |
|------|------|
| `tar` | 아카이브 묶기/풀기 |
| `gzip`/`gunzip` | .gz 압축/해제 |
| `bzip2` | .bz2 (높은 압축률) |
| `xz` | .xz (최고 압축률) |
| `dd` | 블록 단위 복사·이미지 |

tar 옵션은 반드시 외운다 — `c`(생성), `x`(해제), `v`(과정 표시), `f`(파일명), `z`(gzip), `j`(bzip2).

> 📚 **tar 한 줄**: 묶기 `tar czvf out.tar.gz dir`, 풀기 `tar xzvf out.tar.gz`. `z`를 `j`로 바꾸면 bzip2. `f`는 항상 파일명 바로 앞에 둔다.

## 약점 정리 9: 디스크 쿼터(quota)

다중 사용자 환경에서 디스크 사용량을 제한하는 쿼터도 시스템 관리에 속한다.

| 단계 | 명령/작업 |
|------|-----------|
| 마운트 옵션 | fstab에 `usrquota,grpquota` 추가 |
| DB 생성 | `quotacheck -cug /파티션` |
| 쿼터 활성화 | `quotaon /파티션` |
| 한도 설정 | `edquota 사용자` |
| 확인 | `quota 사용자`, `repquota` |

쿼터에는 **soft limit(경고·유예기간)**과 **hard limit(절대 한도)**이 있다.

> 🔍 **soft vs hard**: soft는 넘어도 유예기간(grace period) 동안 허용하지만, hard는 즉시 차단한다. 블록(용량)과 inode(파일 개수) 둘 다 제한 가능.

## 약점 정리 10: 모듈과 커널 파라미터

커널 모듈 관리도 시스템 관리의 한 축이다.

| 명령 | 역할 |
|------|------|
| `lsmod` | 적재된 모듈 목록 |
| `modprobe` | 의존성 포함 모듈 적재 |
| `insmod`/`rmmod` | 모듈 적재/제거(의존성 수동) |
| `modinfo` | 모듈 정보 |
| `sysctl` | 커널 파라미터 조회·변경 |

> ⚠️ **insmod vs modprobe**: `insmod`는 의존 모듈을 자동 처리하지 못하지만 `modprobe`는 의존성까지 해결한다(rpm:yum 관계와 동일한 패턴). 영구 커널 파라미터는 `/etc/sysctl.conf`.

> 💡 **시스템 정보 명령 모음**: `free`(메모리), `uptime`(가동 시간·부하), `vmstat`(가상메모리 통계), `iostat`(I/O 통계), `lscpu`(CPU 정보). 성능 진단 시 함께 묶어 출제된다.

## 마무리

시스템 관리 과목은 **"명령 + 옵션 + 숫자"의 정확성**이 전부다. 특수 권한의 숫자(4/2/1), umask 계산, 시그널 번호(9/15), RAID 레벨, LVM 순서, rpm/yum 차이 — 이 다섯이 가장 많이 틀린다. 아래 모의로 마지막 점검을 하자.

## 📝 연습 문제

**문제 1.** SetUID 비트가 설정된 대표적인 명령으로, 일반 사용자가 자신의 비밀번호를 변경할 수 있게 하는 것은?

A) `/bin/ls`
B) `/usr/bin/passwd`
C) `/etc/shadow`
D) `/usr/bin/who`

**정답: B**
해설: `/usr/bin/passwd`는 SetUID가 설정되어 실행 시 소유자(root) 권한으로 동작하므로, 일반 사용자도 root 소유의 `/etc/shadow`를 수정해 비밀번호를 바꿀 수 있다.

**문제 2.** umask 값이 022일 때 새로 생성되는 일반 파일의 기본 권한은?

A) 755
B) 644
C) 666
D) 777

**정답: B**
해설: 파일 기본값 666에서 umask 022를 빼면 644(rw-r--r--)가 된다. 파일에는 실행 권한이 umask로 부여되지 않는다. 디렉터리라면 777-022=755다.

---

**문제 3.** 공유 디렉터리에서 각 사용자가 자신이 만든 파일만 삭제할 수 있도록 제한하는 특수 권한은?

A) SetUID
B) SetGID
C) Sticky Bit
D) umask

**정답: C**
해설: Sticky Bit(1000)는 `/tmp`처럼 모두가 쓸 수 있는 디렉터리에서 파일 소유자(또는 root)만 자신의 파일을 삭제하도록 제한한다.

---

**문제 4.** 프로세스에 전송했을 때 해당 프로세스가 무시하거나 차단할 수 없는 시그널은?

A) SIGTERM(15)
B) SIGHUP(1)
C) SIGINT(2)
D) SIGKILL(9)

**정답: D**
해설: SIGKILL(9)은 프로세스가 가로채거나 무시할 수 없는 강제 종료 시그널이다. SIGTERM(15)·SIGINT(2)·SIGHUP(1)은 핸들러로 처리 가능하다.

---

**문제 5.** 최소 3개의 디스크가 필요하며 분산 패리티를 1개 사용하는 RAID 레벨은?

A) RAID 0
B) RAID 1
C) RAID 5
D) RAID 6

**정답: C**
해설: RAID 5는 최소 3개 디스크에 패리티를 분산 저장하며 디스크 1개 장애를 견딘다. RAID 6은 패리티 2개(최소 4개), RAID 0은 무중복, RAID 1은 미러링이다.

---

**문제 6.** LVM 구성 시 물리볼륨, 볼륨그룹, 논리볼륨을 생성하는 명령 순서로 옳은 것은?

A) `lvcreate → vgcreate → pvcreate`
B) `pvcreate → vgcreate → lvcreate`
C) `vgcreate → pvcreate → lvcreate`
D) `mkfs → pvcreate → lvcreate`

**정답: B**
해설: LVM은 PV→VG→LV의 3계층으로, `pvcreate`로 물리볼륨을 만들고 `vgcreate`로 볼륨그룹에 묶은 뒤 `lvcreate`로 논리볼륨을 만든다.

**문제 7.** RPM 패키지를 의존성까지 자동 해결하며 저장소에서 설치하는 고수준 도구는?

A) `rpm -ivh`
B) `dpkg -i`
C) `yum install`
D) `make install`

**정답: C**
해설: `yum`(또는 dnf)은 저장소에서 의존 패키지를 자동으로 내려받아 해결한다. `rpm -ivh`는 의존성을 자동 해결하지 못하고 누락 시 에러를 낸다.

**문제 8.** `nice` 우선순위 값에 대한 설명으로 옳은 것은?

A) 범위는 0~39이며 값이 클수록 우선순위가 높다
B) 범위는 -20~19이며 값이 작을수록 우선순위가 높다
C) 범위는 -19~20이며 음수는 누구나 지정 가능하다
D) 범위는 1~99이며 root만 변경할 수 있다

**정답: B**
해설: nice 값은 -20(최우선)~19(최저)이며 값이 작을수록 우선순위가 높다. 음수(우선순위 상향) 지정은 root만 가능하다.

**문제 9.** `/etc/fstab`의 필드 구성 순서로 올바른 것은?

A) 마운트점 - 장치 - 파일시스템 - 옵션 - dump - fsck순서
B) 장치 - 마운트점 - 파일시스템 - 옵션 - dump - fsck순서

**문제 10.** 환경 변수와 셸 변수의 차이로 옳은 것은?

A) 셸 변수는 자식 프로세스로 자동 상속된다
B) `export`로 내보낸 환경 변수만 자식 프로세스로 상속된다
C) 둘 다 항상 자식에게 상속된다
D) 환경 변수는 현재 셸에서만 유효하다

**정답: B**
해설: 단순 대입한 셸 변수는 현재 셸에서만 유효하고, `export`로 내보내야 환경 변수가 되어 자식 프로세스로 상속된다.
