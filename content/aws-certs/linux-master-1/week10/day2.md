# Day 2 - 파일 전송 서비스: FTP의 능동·수동 모드와 vsftpd

## 📌 핵심 정리

- FTP는 **제어(21번)와 데이터를 별도 연결로 처리하는 "두 채널 프로토콜"**이다. 이 구조가 모든 함정의 뿌리다.
- **데이터 연결의 방향이 능동/수동을 가른다** — 능동(**PORT**)은 서버가 20번에서 클라이언트로 거꾸로 접속, 수동(**PASV**)은 클라이언트가 서버 고포트로 접속.
- **NAT/방화벽 뒤 클라이언트는 수동 모드가 필요**하다. 그래서 오늘날 수동이 사실상 표준이다.
- vsftpd 보안 핵심: **`chroot_local_user=YES`(홈에 가두기)**, `userlist_deny`(YES=거부·NO=허용만), `/etc/vsftpd/ftpusers`(항상 접속 금지 목록).
- **FTPS ≠ SFTP** — FTPS는 FTP+TLS(두 채널, 990), **SFTP는 SSH 기반 단일 채널 22번**으로 FTP와 무관하다.

## FTP의 두 연결 — 제어 채널과 데이터 채널

- FTP는 다른 프로토콜과 달리 **연결을 두 개** 쓴다.

| 채널 | 포트 | 역할 |
|------|------|------|
| 제어 채널 | 21 | 로그인, 명령(LIST, RETR, STOR) 전달 |
| 데이터 채널 | 20(능동) 또는 임의 고포트(수동) | 실제 파일·디렉터리 목록 전송 |

- 21번 제어 연결은 **세션 내내 유지**되고, 데이터를 옮길 때마다 **별도 데이터 연결이 새로 열린다.**
- 이 데이터 연결을 **누가 시작하느냐**가 능동/수동 모드를 가른다.

> 💡 **개념**: FTP를 "전화로 주문하고 택배로 받는 시스템"으로 그려보라. 21번은 주문 전화선(항상 연결), 데이터 채널은 물건이 오가는 택배 경로(필요할 때마다 새로 개설)다. 능동 모드는 택배 기사가 우리 집으로 직접 오고(서버→클라이언트), 수동 모드는 우리가 물류센터로 찾으러 간다(클라이언트→서버).

## 능동 모드 vs 수동 모드 — 데이터 연결의 방향

- 이 부분이 FTP 문제의 **핵심이자 단골 함정**이다.

| 구분 | 능동(Active) 모드 | 수동(Passive) 모드 |
|------|-------------------|---------------------|
| 데이터 연결 시작 | **서버**가 클라이언트로 연결 | **클라이언트**가 서버로 연결 |
| 서버 데이터 포트 | 20번 (고정) | 임의 고포트(1024 이상) |
| 클라이언트 포트 | 임의 고포트 (서버가 접속) | 임의 고포트 (클라이언트가 접속) |
| 명령 | PORT (클라이언트가 자기 포트 알림) | PASV (서버가 열어둘 포트 알림) |
| 클라이언트 방화벽/NAT | 통과 어려움(서버가 거꾸로 접속) | 통과 쉬움(클라이언트가 능동 접속) |

### 능동 모드 동작 순서

```text
1. 클라이언트 → 서버:21  제어 연결, "PORT 1500" (내 데이터 포트는 1500)
2. 서버:20   → 클라이언트:1500  서버가 거꾸로 데이터 연결을 연다
```

### 수동 모드 동작 순서

```text
1. 클라이언트 → 서버:21  제어 연결, "PASV" (열어둘 포트 알려줘)
2. 서버 → 클라이언트  "포트 50000을 열어뒀다"
3. 클라이언트 → 서버:50000  클라이언트가 데이터 연결을 연다
```

> ⚠️ **함정**: "능동 모드에서 서버의 데이터 포트는 20번"이라는 사실과, "능동 모드는 서버가 클라이언트로 거꾸로 접속한다"는 방향을 정확히 외워야 한다. 시험은 PORT/PASV 명령과 모드를 뒤바꾼 보기를 자주 낸다. PORT=능동, PASV=수동이다.

> 🔍 **핵심 구분**: 왜 수동 모드가 표준이 됐나? 능동 모드는 서버가 클라이언트로 **거꾸로** 연결을 열기 때문에, 클라이언트가 NAT 뒤나 방화벽 안에 있으면 그 연결이 차단된다. 오늘날 대부분의 클라이언트가 NAT/방화벽 뒤에 있으므로, 클라이언트가 직접 연결을 여는 **수동 모드가 사실상 기본**이다. "NAT 뒤 클라이언트 = 수동 모드 필요"가 정답 신호다.

> 📚 **유래/사례**: FTP가 1971년(RFC 114) 설계됐을 때는 방화벽도 NAT도 없던 시대라, 서버가 클라이언트로 데이터를 보내는 능동 모드가 자연스러웠다. 그러나 1990년대 NAT와 방화벽이 보편화되며 능동 모드가 막히기 시작했고, RFC 1579(Firewall-Friendly FTP)가 수동 모드를 권장하면서 오늘날 표준이 됐다.

## vsftpd 설치와 핵심 설정

- 리눅스의 대표 FTP 서버는 **vsftpd(Very Secure FTP Daemon)**로, 이름 그대로 보안을 최우선으로 설계됐다.

```bash
# 설치 및 서비스 기동
dnf install vsftpd          # RHEL 계열 (apt install vsftpd : 데비안 계열)
systemctl enable --now vsftpd
ss -tlnp | grep :21         # 21번 LISTEN 확인
```

### /etc/vsftpd/vsftpd.conf 주요 지시어

```bash
# 익명 접속 관련
anonymous_enable=NO         # 익명 로그인 허용 여부(보안상 보통 NO)
anon_upload_enable=NO       # 익명 사용자 업로드 허용

# 로컬 사용자 관련
local_enable=YES            # 로컬 시스템 계정 로그인 허용
write_enable=YES            # 업로드·삭제 등 쓰기 명령 허용
local_umask=022             # 업로드 파일의 기본 umask

# 디렉터리 제한(보안 핵심)
chroot_local_user=YES       # 사용자를 홈 디렉터리에 가둠(상위 이동 차단)
allow_writeable_chroot=YES  # chroot 홈에 쓰기 권한 있을 때 허용

# 접속 제어
userlist_enable=YES         # /etc/vsftpd/user_list로 접근 통제
userlist_deny=YES           # YES=목록의 사용자 거부, NO=목록만 허용

# 수동 모드 포트 범위(방화벽 개방용)
pasv_enable=YES
pasv_min_port=40000
pasv_max_port=40100
```

> ⚠️ **함정**: `userlist_deny`의 의미가 반대로 헷갈리기 쉽다. `userlist_deny=YES`면 user_list에 적힌 사용자를 **거부**(블랙리스트), `userlist_deny=NO`면 목록의 사용자만 **허용**(화이트리스트)이다. 또 `/etc/vsftpd/ftpusers`는 항상 접속 금지 목록으로, root 등 시스템 계정이 기본 포함된다.

> 🔍 **핵심 구분**: `chroot_local_user=YES`는 사용자를 자기 홈에 **가둬** 상위 디렉터리로 못 나가게 하는 보안 핵심 설정이다. 이때 홈 디렉터리에 쓰기 권한이 있으면 vsftpd가 보안상 거부하므로 `allow_writeable_chroot=YES`를 함께 줘야 한다. "상위 이동 차단 = chroot"를 기억하라.

> 💡 **개념**: vsftpd가 수동 모드를 쓰면 데이터 포트가 임의 고포트라 방화벽이 막아버린다. 그래서 `pasv_min_port`~`pasv_max_port`로 범위를 좁혀 정하고, 그 범위만 방화벽에서 열어준다. 무작정 모든 고포트를 열면 보안이 무너지므로 "범위 지정 → 그 범위만 개방"이 정석이다.

### 직접 쳐보기 — 접속과 전송 테스트

```bash
# FTP 클라이언트로 접속
ftp 192.168.1.10
# Name: ftpuser / Password: ****
ftp> passive          # 수동 모드로 전환
ftp> ls               # 데이터 채널로 목록 받기
ftp> get report.txt   # 다운로드
ftp> put backup.tar   # 업로드
ftp> bye

# 방화벽에 FTP·수동 포트 개방 (firewalld)
firewall-cmd --permanent --add-service=ftp
firewall-cmd --permanent --add-port=40000-40100/tcp
firewall-cmd --reload
```

## 보안 FTP — FTPS와 SFTP의 결정적 차이

- 평문 FTP는 **ID·비밀번호·파일이 모두 그대로** 흐른다. 그래서 암호화 방식이 필요하다.
- 이름이 비슷한 **두 방식을 반드시 구분**해야 한다.

| 구분 | FTPS | SFTP |
|------|------|------|
| 정체 | FTP + SSL/TLS 암호화 | SSH 기반 파일 전송 |
| 기반 프로토콜 | FTP 프로토콜 그대로 + TLS | SSH 프로토콜의 일부 |
| 포트 | 21(명시적 FTPS) 또는 990(암묵적) | **22 (SSH와 동일)** |
| 연결 구조 | 제어+데이터 두 채널(복잡) | 단일 채널(SSH 위) |
| 방화벽 친화성 | 데이터 포트 때문에 까다로움 | 22번 하나라 단순 |
| 서버 | vsftpd 등 FTP 서버 | sshd (별도 FTP 서버 불필요) |

> 🔍 **핵심 구분**: FTPS와 SFTP는 이름만 닮았을 뿐 완전히 다른 기술이다. **FTPS = FTP에 TLS를 씌운 것**(여전히 두 채널, 990 포트), **SFTP = SSH 위에서 도는 파일 전송**(22번 단일 채널, FTP와 무관)이다. "SFTP는 SSH의 일부, 포트 22"가 가장 자주 출제되는 포인트다.

> ⚠️ **함정**: SFTP를 "Secure FTP" 또는 "FTPS와 같은 것"으로 설명하는 보기는 모두 틀렸다. SFTP는 SSH File Transfer Protocol이며 FTP 프로토콜을 전혀 쓰지 않는다. 포트도 990(FTPS)이 아니라 22(SSH)다. 이 둘을 섞은 보기가 함정의 단골이다.

> 📚 **유래/사례**: SFTP가 실무에서 압도적으로 선호되는 이유는 "방화벽 구멍 하나(22번)면 끝"이기 때문이다. FTPS는 제어·데이터 두 채널에 수동 포트 범위까지 열어야 해 NAT 환경에서 골치가 아프다. 이미 SSH가 열려 있으면 추가 설정 없이 SFTP가 따라오므로, 오늘날 안전한 파일 전송의 기본 선택지가 되었다.

## 시험 직전 체크리스트

- 제어 21, 능동 데이터 20, 수동 데이터 고포트
- 능동=서버가 클라이언트로 접속(PORT), 수동=클라이언트가 서버로 접속(PASV)
- NAT 뒤 클라이언트 = 수동 모드 필요
- vsftpd 설정은 `/etc/vsftpd/vsftpd.conf`, 금지 목록은 ftpusers
- chroot_local_user=홈에 가두기, userlist_deny 의미 주의
- FTPS=FTP+TLS(990), SFTP=SSH 기반(22)

## 📖 용어

- **제어 채널 / 데이터 채널** : 로그인과 명령을 주고받는 21번 연결 / 실제 파일과 목록이 오가는 별도 연결.
- **능동(Active) 모드** : 클라이언트가 `PORT`로 자기 포트를 알리면 서버가 20번에서 **거꾸로** 접속하는 방식.
- **수동(Passive) 모드** : 서버가 `PASV`로 열어 둔 고포트를 알려 주고 **클라이언트가** 접속하는 방식.
- **PORT / PASV** : 능동 모드를 여는 명령 / 수동 모드를 요청하는 명령. 모드와 짝지어 외운다.
- **vsftpd** : "Very Secure FTP Daemon". 리눅스 대표 FTP 서버로 설정은 `/etc/vsftpd/vsftpd.conf`.
- **`anonymous_enable`** : 익명 로그인 허용 여부. 보안상 보통 `NO`로 둔다.
- **chroot jail** : 사용자를 자기 홈 아래에 가둬 상위 디렉터리로 못 나가게 하는 격리. `chroot_local_user=YES`.
- **`allow_writeable_chroot`** : chroot한 홈에 쓰기 권한이 있을 때 vsftpd가 거부하지 않도록 허용하는 설정.
- **`userlist_deny`** : `YES`면 user_list의 사용자를 거부(블랙리스트), `NO`면 그 목록만 허용(화이트리스트).
- **`ftpusers`** : 항상 접속을 금지하는 목록. root 등 시스템 계정이 기본으로 들어 있다.
- **`pasv_min_port` / `pasv_max_port`** : 수동 모드 데이터 포트 범위. 이 범위만 방화벽에서 열어 준다.
- **FTPS** : 기존 FTP에 SSL/TLS를 씌운 것. 두 채널 구조를 유지하며 990(암묵적)·21(명시적)을 쓴다.
- **SFTP** : SSH 위에서 도는 파일 전송. **22번 단일 채널**이며 FTP 프로토콜을 전혀 쓰지 않는다.

## 📝 연습 문제

**문제 1.** FTP 능동(Active) 모드에서 데이터 연결이 맺어지는 방향으로 옳은 것은?

A) 클라이언트가 서버의 고포트로 데이터 연결을 연다

B) 서버가 20번 포트에서 클라이언트의 지정 포트로 데이터 연결을 거꾸로 연다

C) 클라이언트와 서버가 모두 21번 포트만 사용한다

D) 서버가 클라이언트의 21번 포트로 데이터 연결을 연다

**정답: B**

해설: 능동 모드에서는 클라이언트가 PORT 명령으로 자기 포트를 알리면, 서버가 20번 데이터 포트에서 클라이언트로 거꾸로 연결을 연다. A는 수동 모드 설명, C는 데이터 채널이 별도라는 사실을 무시했고, D는 21번이 제어 포트라 데이터 연결 대상이 될 수 없다. "능동=서버가 거꾸로 접속"이 핵심이다.

---

**문제 2.** NAT/방화벽 뒤에 있는 클라이언트가 FTP 서버에 접속할 때 일반적으로 권장되는 모드와 그 이유로 옳은 것은?

A) 능동 모드 — 서버가 클라이언트로 접속해 방화벽을 쉽게 통과한다

B) 수동 모드 — 클라이언트가 서버로 직접 데이터 연결을 열어 NAT/방화벽을 통과하기 쉽다

C) 능동 모드 — 데이터 포트가 20번으로 고정되어 NAT가 자동 처리한다

D) 수동 모드 — 서버가 클라이언트의 고포트로 거꾸로 접속한다

**정답: B**

해설: 수동 모드는 클라이언트가 서버로 데이터 연결을 능동적으로 열기 때문에 NAT/방화벽 뒤에서도 통과가 쉽다. A·C의 능동 모드는 서버가 클라이언트로 거꾸로 접속해 NAT 뒤 클라이언트에서 차단되고, D는 수동 모드의 방향을 잘못 설명했다. "NAT 뒤 = 수동 모드"가 정답 신호다.

**문제 3.** vsftpd에서 로컬 사용자를 자신의 홈 디렉터리에 가두어 상위 디렉터리로 이동하지 못하게 하는 설정은?

A) `anonymous_enable=YES`

B) `chroot_local_user=YES`

C) `write_enable=YES`

D) `pasv_enable=YES`

**정답: B**

해설: `chroot_local_user=YES`는 로컬 사용자를 홈 디렉터리에 가두어(chroot jail) 상위 디렉터리 접근을 차단하는 보안 설정이다. A는 익명 접속 허용, C는 쓰기 명령 허용, D는 수동 모드 활성화라 디렉터리 제한과 무관하다. "홈에 가두기 = chroot_local_user"를 기억하라.

**문제 4.** FTP에서 제어(명령) 채널이 사용하는 표준 포트는?

A) 20

B) 21

C) 22

D) 990

**정답: B**

해설: FTP의 제어 채널(로그인·명령 전달)은 21번을 쓴다. A(20)는 능동 모드의 데이터 채널 포트, C(22)는 SSH/SFTP 포트, D(990)는 암묵적 FTPS 포트라 제어 채널 표준 포트가 아니다. "제어 21, 능동 데이터 20"을 짝으로 외워라.

**문제 5.** SFTP에 대한 설명으로 옳은 것은?

A) FTP에 SSL/TLS를 적용한 것으로 990번 포트를 사용한다

B) SSH 프로토콜 기반의 파일 전송으로 22번 포트를 사용하며 단일 채널로 동작한다

C) FTP의 능동 모드를 암호화한 것으로 20번 포트를 사용한다

D) 제어와 데이터 두 채널을 사용하는 FTPS의 다른 이름이다

**정답: B**

해설: SFTP(SSH File Transfer Protocol)는 SSH 위에서 동작하는 파일 전송으로 22번 단일 채널을 쓴다. A는 FTPS 설명, C는 SFTP가 FTP 능동 모드와 무관하므로 틀렸고, D는 SFTP와 FTPS를 같은 것으로 본 대표적 함정이다. "SFTP=SSH 기반·22번"이 핵심이다.

**문제 6.** vsftpd에서 `/etc/vsftpd/ftpusers` 파일의 역할로 옳은 것은?

A) 익명 사용자의 업로드 디렉터리를 지정한다

B) 여기에 등록된 사용자는 FTP 접속이 금지되며 root 등 시스템 계정이 기본 포함된다

C) 수동 모드에서 열 데이터 포트 범위를 정의한다

D) 사용자별 전송 대역폭 제한을 설정한다

**정답: B**

해설: `ftpusers`는 FTP 접속을 금지할 사용자 목록으로, root를 비롯한 시스템 계정이 보안을 위해 기본 등록되어 있다. A는 anon_root 등의 설정, C는 pasv_min/max_port, D는 별도 대역폭 지시어의 역할이라 ftpusers와 무관하다. "ftpusers = 접속 금지 목록"을 기억하라.

**문제 7.** FTPS와 SFTP의 차이로 옳은 것은?

A) FTPS는 SSH 기반이고 SFTP는 FTP에 TLS를 씌운 것이다

B) FTPS는 FTP에 SSL/TLS를 적용한 것이고, SFTP는 SSH 기반으로 22번 포트를 쓴다

C) 둘 다 동일한 프로토콜이며 포트만 다르다

D) FTPS는 22번, SFTP는 990번 포트를 사용한다

**정답: B**

해설: FTPS는 기존 FTP에 SSL/TLS 암호화를 더한 것(여전히 두 채널)이고, SFTP는 SSH 위에서 동작하는 별개의 파일 전송으로 22번을 쓴다. A는 둘을 정반대로 설명했고, C는 둘이 다른 프로토콜임을 무시했으며, D는 포트가 서로 뒤바뀌었다. "FTPS=FTP+TLS, SFTP=SSH"가 핵심이다.
