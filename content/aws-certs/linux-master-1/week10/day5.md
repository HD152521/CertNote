# Day 5 - Week 10 종합 복습: 네트워크 서비스를 포트 한 장으로 꿰기

이번 주는 리눅스 **서버 서비스**의 핵심을 훑었다. Day 1에서 메일(MTA·MDA·MUA와 SMTP·POP3·IMAP)을, Day 2에서 파일 전송(FTP 능동·수동, vsftpd, FTPS/SFTP)을, Day 3에서 원격 접속(SSH·키 인증·포워딩)을, Day 4에서 원격 GUI(VNC·X 윈도)를 다뤘다. 오늘은 이 네 조각을 **포트와 역할**이라는 하나의 좌표계로 묶고, 실기 단골 함정을 복습한 뒤 종합 문제로 점검한다.

핵심 통찰 하나만 가져가자: **모든 네트워크 서비스는 "어떤 포트에서, 어떤 역할의 데몬이, 어떤 방향으로 통신하는가"로 환원된다.** 메일은 발송(SMTP)과 수신(POP3/IMAP)의 비대칭, FTP는 제어와 데이터의 두 채널, SSH는 22번 하나의 다목적 터널, VNC/X는 화면을 누가 가졌는가의 역전 — 이 네 가지 구조만 잡으면 어떤 변형 문제도 풀린다.

## 서비스·포트 총정리 — 한 표로 암기

| 서비스 | 포트 | 암호화 포트 | 역할 |
|--------|------|-------------|------|
| SMTP | 25 | 465·587 | 메일 발송 |
| POP3 | 110 | 995 | 메일 수신(다운로드·삭제) |
| IMAP | 143 | 993 | 메일 수신(서버 보관·동기화) |
| FTP | 21(제어)·20(능동데이터) | 990(FTPS) | 파일 전송 |
| SSH/SFTP | 22 | (자체 암호화) | 원격 접속·파일 전송 |
| Telnet | 23 | 없음(평문) | 원격 접속(레거시) |
| VNC | 5900+N | (SSH 터널 권장) | 원격 데스크톱 |

> 💡 **개념**: 포트 번호는 "이 문은 어떤 서비스 전용인가"의 약속이다. 25는 메일 발송, 110·143은 메일 수신, 21은 FTP 명령, 22는 SSH 다목적, 23은 평문 Telnet. 암호화 포트(465·587·993·995·990)는 평문 포트에 보안을 더한 변종이다. 이 매핑을 즉답할 수 있어야 실기가 풀린다.

> ⚠️ **함정 복습**: 가장 자주 뒤바뀌는 짝 — POP3(110/995)와 IMAP(143/993), SMTPS(465)와 제출(587), FTP 제어(21)와 능동 데이터(20), SSH(22)와 Telnet(23). 이 경계를 바꾼 보기가 시험의 단골이다.

## 메일 서비스 복습 — 발송과 수신의 비대칭

| 구성요소 | 역할 | 대표 |
|----------|------|------|
| MUA | 작성·읽기 클라이언트 | Thunderbird, mutt |
| MTA | 서버 간 전송 | Postfix, Sendmail |
| MDA | 사서함 최종 배달 | Procmail, Dovecot |

> 🔍 **핵심 구분**: MTA(서버 간 전송) ≠ MDA(사서함 배달) ≠ MUA(사용자 클라이언트). 발송은 SMTP 단방향, 수신은 POP3/IMAP. Postfix 설정은 `/etc/postfix/main.cf`이며, mynetworks를 너무 넓게 열면 오픈 릴레이가 된다. POP3=다운로드 후 삭제, IMAP=서버 보관·동기화가 핵심 구분이다.

## FTP 복습 — 두 채널과 능동·수동

```text
능동(Active): 클라이언트가 PORT로 포트 알림 → 서버(20번)가 클라이언트로 거꾸로 접속
수동(Passive): 클라이언트가 PASV 요청 → 서버가 고포트 열어둠 → 클라이언트가 접속
```

> ⚠️ **함정 복습**: 능동은 서버가 클라이언트로 거꾸로 접속(PORT, 20번), 수동은 클라이언트가 서버로 접속(PASV, 고포트). NAT/방화벽 뒤 클라이언트는 수동 모드가 필요하다. vsftpd의 chroot_local_user는 홈에 가두기, ftpusers는 접속 금지 목록이다. FTPS(FTP+TLS, 990)와 SFTP(SSH 기반, 22)는 전혀 다른 기술이다.

## SSH 복습 — 22번의 다목적 보안 채널

```bash
# 보안 설정 핵심(sshd_config)
PermitRootLogin no              # root 직접 로그인 차단
PasswordAuthentication no       # 키 전용(키 등록 후 적용)
MaxAuthTries 3                  # 무차별 대입 방어

# 키 인증: 공개키는 서버 authorized_keys, 개인키는 클라이언트
ssh-keygen -t ed25519
ssh-copy-id user@host

# 포워딩
ssh -L 8080:internal:3306 user@gw   # 로컬: 내 쪽→원격 너머
ssh -R 9090:localhost:80 user@gw    # 원격: 원격 쪽→내 쪽
ssh -D 1080 user@gw                 # 동적: SOCKS 프록시
```

> 🔍 **핵심 구분**: 서버 설정 sshd_config(d가 붙음) vs 클라이언트 설정 ssh_config. 공개키(.pub)는 서버에, 개인키는 클라이언트에. ~/.ssh는 700, 키 파일은 600. scp 포트는 대문자 -P, ssh 포트는 소문자 -p. 포워딩 -L(로컬)·-R(원격)·-D(동적)의 방향 차이를 정확히 구분하라.

## VNC·X 윈도 복습 — 화면을 가진 쪽의 역전

> ⚠️ **함정 복습**: VNC 포트 = 5900 + 디스플레이 번호(:1→5901). X 윈도에서 화면·입력장치를 가진 사용자 앞 기기가 **X 서버**, 그림을 요청하는 응용프로그램이 **X 클라이언트**(역전!). DISPLAY는 그림 보낼 화면 주소, xhost는 호스트 단위·xauth는 쿠키 단위 제어이며, `xhost +`(인자 없음)는 전체 허용으로 위험하다. 안전한 원격 GUI는 `ssh -X`다.

## 진단 흐름 — 서비스 장애를 잡는 순서

```bash
ss -tlnp | grep :포트      # 1. 서비스가 그 포트를 LISTEN 중인가?
systemctl status 서비스     # 2. 데몬이 살아있는가?
telnet host 포트            # 3. 외부에서 포트에 닿는가?(방화벽)
firewall-cmd --list-all     # 4. 방화벽이 포트를 열었나?
journalctl -u 서비스        # 5. 로그에 무슨 오류가?
```

> 📚 **유래/사례**: 서버 서비스 장애의 90%는 이 다섯 단계 안에서 잡힌다 — "데몬이 떴나, 포트를 듣나, 방화벽이 막나, 설정이 맞나, 로그가 뭐라 하나". 메일이 안 가면 mailq, FTP가 막히면 능동/수동·방화벽, SSH가 거부되면 키 권한·PermitRootLogin, GUI가 안 뜨면 DISPLAY·xhost를 본다. 이번 주는 시험을 넘어 실무 서버 운영의 기초다.

**문제 1.** 다음 서비스와 기본 포트의 짝 중 옳지 않은 것은?

A) SMTP — 25

B) IMAP — 143

C) SSH — 22

D) POP3 — 143

**정답: D**

해설: POP3의 기본 포트는 110이고, 143은 IMAP의 포트다. A(SMTP 25), B(IMAP 143), C(SSH 22)는 모두 올바른 짝이다. POP3와 IMAP의 포트를 뒤바꾼 D가 틀린 짝으로, "POP3=110, IMAP=143"의 경계가 단골 함정이다.

**문제 2.** 메일을 서버에 보관하여 여러 기기에서 동기화하기에 적합한 수신 프로토콜과 포트로 옳은 것은?

A) POP3 — 110

B) IMAP — 143

C) SMTP — 25

D) IMAP — 110

**정답: B**

해설: IMAP은 메일을 서버에 보관·동기화하여 여러 기기에서 같은 사서함을 보기에 적합하며 포트는 143이다. A(POP3)는 다운로드 후 삭제라 단일 기기에 적합하고, C(SMTP)는 발송 프로토콜, D는 IMAP에 POP3 포트(110)를 잘못 붙였다. "여러 기기 동기화 = IMAP 143".

**문제 3.** FTP 수동(Passive) 모드의 데이터 연결에 대한 설명으로 옳은 것은?

A) 서버가 20번 포트에서 클라이언트로 거꾸로 연결을 연다

B) 클라이언트가 서버의 고포트로 데이터 연결을 열어 NAT/방화벽 통과에 유리하다

C) 제어와 데이터가 모두 21번 포트만을 사용한다

D) 클라이언트가 PORT 명령으로 자기 포트를 알린다

**정답: B**

해설: 수동 모드는 서버가 고포트를 열어두고 클라이언트가 그곳으로 데이터 연결을 열기 때문에 NAT/방화벽 뒤에서도 통과가 쉽다. A·D는 능동 모드(서버가 거꾸로 접속, PORT 명령) 설명이고, C는 데이터 채널이 별도라는 사실을 무시했다. "수동=클라이언트가 서버로 접속, PASV".

**문제 4.** FTPS와 SFTP에 대한 설명으로 옳은 것은?

A) SFTP는 FTP에 TLS를 적용한 것으로 990번 포트를 사용한다

B) FTPS는 SSH 기반이고 22번 포트를 사용한다

C) SFTP는 SSH 기반 파일 전송으로 22번 포트를 사용하고, FTPS는 FTP에 SSL/TLS를 적용한 것이다

D) 둘은 같은 프로토콜의 다른 이름이다

**정답: C**

해설: SFTP는 SSH 위에서 동작하는 파일 전송으로 22번을 쓰고, FTPS는 기존 FTP에 SSL/TLS를 더한 것이다. A는 SFTP를 FTPS로 잘못 설명했고, B는 FTPS를 SFTP로 뒤바꿨으며, D는 둘이 다른 기술임을 부정한다. "SFTP=SSH·22, FTPS=FTP+TLS·990"이 핵심이다.

**문제 5.** SSH 공개키 인증을 구성할 때 서버와 클라이언트에 두는 키로 옳은 것은?

A) 개인키를 서버 authorized_keys에, 공개키를 클라이언트에 둔다

B) 공개키(.pub)를 서버 authorized_keys에, 개인키를 클라이언트에 둔다

C) 공개키와 개인키를 모두 서버에 둔다

D) 개인키를 서버와 클라이언트 양쪽에 복사한다

**정답: B**

해설: 공개키(.pub)는 서버의 `~/.ssh/authorized_keys`에 등록하고, 개인키는 클라이언트가 비밀로 보관한다. A·C·D처럼 개인키를 서버에 올리면 유출 시 치명적이라 절대 안 된다. "서버엔 공개키, 클라이언트엔 개인키"가 키 인증의 기본 원칙이다.

**문제 6.** SSH 서버에서 root의 직접 로그인을 막는 sshd_config 지시어로 옳은 것은?

A) `PermitRootLogin no`

B) `DenyUsers root`만으로는 불가능하다

C) `PasswordAuthentication no`

D) `AllowRootLogin yes`

**정답: A**

해설: `PermitRootLogin no`가 root의 직접 SSH 로그인을 차단하는 표준 지시어다. C는 비밀번호 인증 전체를 끄는 다른 목적의 설정이고, D는 존재하지 않는(혹은 반대 의미의) 지시어이며, B는 사실과 다른 단정이다. "root 차단 = PermitRootLogin no"를 기억하라.

**문제 7.** VNC 서버를 디스플레이 `:1`로 실행했을 때 기본 포트는?

A) 5900

B) 5901

C) 5911

D) 5910

**정답: B**

해설: VNC 포트는 5900 + 디스플레이 번호이므로 `:1`은 5901이다. A(5900)는 `:0`에 해당하고, C(5911)·D(5910)는 계산 규칙에 맞지 않는다. "5900 + 디스플레이 번호" 공식을 정확히 적용하면 된다.

**문제 8.** X 윈도 시스템에서 사용자 앞의 모니터·키보드·마우스를 관리하는 구성요소는?

A) X 클라이언트

B) X 서버

C) 윈도 매니저

D) 응용프로그램

**정답: B**

해설: X 서버는 화면·키보드·마우스 등 하드웨어를 관리하며 그리기 요청을 받아 실제로 그림을 그리는, 사용자 앞 기기의 구성요소다. A(X 클라이언트)·D(응용프로그램)는 그리기를 요청하는 쪽이고, C(윈도 매니저)는 창 관리를 하는 클라이언트의 일종이다. "화면·입력 관리 = X 서버"라는 역전 개념이 핵심이다.

**문제 9.** Postfix에서 신뢰 네트워크를 너무 넓게 설정해 누구나 메일을 중계할 수 있게 되는 보안 문제와 관련된 지시어는?

A) `inet_interfaces`

B) `mynetworks`

C) `home_mailbox`

D) `myhostname`

**정답: B**

해설: `mynetworks`는 릴레이를 허용할 신뢰 네트워크를 지정하는데, 이를 과도하게 넓히면 오픈 릴레이가 되어 스팸 발송에 악용된다. A는 수신 인터페이스, C는 사서함 형식, D는 호스트명 설정이라 오픈 릴레이와 무관하다. "오픈 릴레이 = mynetworks 과도 개방"을 연결하라.

**문제 10.** 평문으로 통신하여 보안에 취약하므로 SSH로 대체된 원격 접속 프로토콜과 그 포트로 옳은 것은?

A) SSH — 22

B) Telnet — 23

C) FTP — 21

D) Telnet — 22

**정답: B**

해설: Telnet은 ID·비밀번호를 평문으로 전송해 도청에 취약하며 포트 23을 쓰고, 암호화하는 SSH(22)로 대체되었다. A(SSH)는 대체한 쪽이고, C(FTP)는 파일 전송 프로토콜, D는 Telnet에 SSH 포트(22)를 잘못 붙였다. "평문·23번 = Telnet, 암호화·22번 = SSH"가 핵심이다.

**문제 11.** 직접 접근할 수 없는 내부망 서비스를 SSH 게이트웨이를 경유해 내 로컬 포트로 안전하게 잇는 포트 포워딩 옵션은?

A) `-R` (원격 포워딩)

B) `-L` (로컬 포워딩)

C) `-D` (동적 포워딩)

D) `-P` (포트 지정)

**정답: B**

해설: 로컬 포워딩 `-L 로컬포트:대상:대상포트`는 내 로컬 포트로 온 연결을 게이트웨이 너머 내부 서비스로 암호화 터널로 잇는다. A(-R)는 방향이 반대인 원격 포워딩, C(-D)는 SOCKS 프록시, D(-P)는 scp의 포트 옵션이라 포워딩이 아니다. "내부 서비스로 잇기 = 로컬 포워딩 -L".

**문제 12.** 다음 중 보안상 매우 위험하여 권장되지 않는 X 접근 제어 명령은?

A) `xhost -` — 호스트 기반 허용을 끄고 기본 인증으로 복귀

B) `xhost +` — 모든 호스트의 X 서버 접근을 허용

C) `xauth list` — 인증 쿠키 목록 조회

D) `xhost +192.168.1.5` — 특정 호스트만 허용

**정답: B**

해설: 인자 없는 `xhost +`는 모든 호스트의 X 접근을 허용해 화면 캡처·키 입력 탈취가 가능한 매우 위험한 명령이다. A는 오히려 보안을 강화하는 복귀 명령, C는 단순 조회, D는 특정 호스트만 허용해 상대적으로 안전하다. "xhost +(인자 없음) = 전체 허용·위험"을 기억하라.
