# Day 5 - Week 4 종합 복습: 계정·권한 체계를 한 장으로 꿰기

이번 주는 리눅스 보안의 **뼈대**를 다뤘다. Day 1에서 계정이 네 파일의 레코드라는 것을, Day 2에서 그 레코드를 다루는 명령과 권한 상승(su/sudo)을, Day 3에서 권한의 산수(rwx·8진수·umask)를, Day 4에서 그 위에 얹는 특수 권한과 ACL을 배웠다. 오늘은 이 네 조각을 하나의 그림으로 잇고, 실기에서 자주 엮여 나오는 함정을 복습한 뒤 종합 문제로 점검한다.

핵심 통찰 하나만 가져가자: **리눅스의 모든 접근 제어는 "어느 파일의 몇 번째 필드/비트가 무엇인가"로 환원된다.** 계정은 passwd/shadow의 필드, 권한은 9비트+특수 4비트, 세분화는 ACL 항목. 이 좌표계만 잡으면 어떤 변형 문제도 풀린다.

## 계정 파일 4종 — 필드와 권한 복습

| 파일 | 권한 | 필드 수 | 핵심 필드 | 짝 |
|------|------|---------|-----------|-----|
| /etc/passwd | 644 | 7 | UID(3) · GID(4) · 홈(6) · 셸(7) | shadow |
| /etc/shadow | 400/640 | 9 | 해시(2) · LastChange(3) · Min(4) · Max(5) | passwd |
| /etc/group | 644 | 4 | GID(3) · 보조멤버(4) | gshadow |
| /etc/gshadow | 400 | 4 | 그룹암호(2) · 관리자(3) | group |

기억 고정 포인트:
- passwd 7필드, shadow 9필드, group/gshadow 각 4필드
- UID 0 = root(이름 아닌 번호로 판정)
- shadow 날짜 필드 = 1970-01-01부터의 일수
- 기본 그룹은 passwd(GID), 보조 그룹은 group(멤버 목록)

> 💡 **개념**: passwd↔shadow, group↔gshadow는 "공개(644, 신원/소속)와 비밀(400, 해시/정책)"로 분리된 짝이다. 정합성은 `pwck`(passwd/shadow), `grpck`(group/gshadow)로 검사한다.

## 계정 관리 명령 — 옵션과 필드 대응

| 명령 | 핵심 옵션 | 주의 함정 |
|------|-----------|-----------|
| useradd | -u -g -G -d -s -m -c | -g(기본,하나) vs -G(보조,여럿) |
| usermod | -aG(추가) / -G(교체) | -a 빠뜨리면 기존 보조 그룹 소실 |
| userdel | -r(홈까지 삭제) | 옵션 없으면 홈은 남음 |
| passwd | -l(잠금) -u -e(만료) -d(삭제) | -l(차단)과 -d(무암호)는 정반대 |
| chage | -M(Max) -m(Min) -W -E | 대문자 M=Max, 소문자 m=Min |
| gpasswd | -a -d -A | group+gshadow 동시 갱신 |

> ⚠️ **함정 복습**: `usermod -G`(단독)는 기존 보조 그룹을 날리고 교체한다. 반드시 `-aG`. 이건 매주 시험에 나온다고 봐도 된다.

## su vs sudo — 권한 상승 두 모델

| 구분 | su | sudo |
|------|-----|------|
| 요구 암호 | **대상 사용자** 암호 | **자기 자신** 암호 |
| 범위 | 전환 후 그 사람으로 계속 | 단일 명령만 위임 |
| 설정 파일 | 없음 | /etc/sudoers (visudo로 편집) |
| 감사 | 어려움(공유 암호) | 로그에 남음(/var/log/secure) |
| 로그인 셸 | `su -` (환경 완전 적용) | `sudo -i` |

> 💡 **개념**: `su -`의 하이픈 = 로그인 셸(대상 환경 완전 적용). sudoers는 `%`로 그룹 지정(Red Hat=wheel, Ubuntu=sudo). 편집은 항상 `visudo`(문법 검사+잠금).

## 권한 산수 — rwx·8진수·umask

| 변환 | 규칙 |
|------|------|
| 가중치 | r=4, w=2, x=1 |
| 순서 | owner→group→other, 각 r→w→x |
| 644 | rw-r--r-- (일반 파일) |
| 755 | rwxr-xr-x (실행/디렉터리) |
| 600 | rw------- (비밀 파일) |
| umask 파일 | 666 − umask |
| umask 디렉터리 | 777 − umask |

> ⚠️ **함정 복습**: umask 022 → 파일 644, 디렉터리 755. 파일은 666, 디렉터리는 777에서 출발(파일은 x 기본 제외). umask가 클수록 더 제한적.

> 💡 **개념**: 디렉터리에서 x=진입(cd), 파일 삭제는 파일이 아닌 **디렉터리의 w** 권한. chown(소유자 변경)은 root만 가능.

## 특수 권한·ACL — 9비트를 넘어서

| 항목 | 8진수 | 표시 | 효과 |
|------|-------|------|------|
| SetUID | 4 | owner x→s | 소유자 권한 실행(passwd=4755) |
| SetGID | 2 | group x→s | 그룹 실행/디렉터리 그룹 상속 |
| Sticky | 1 | other x→t | 공유 디렉터리 삭제 보호(/tmp=1777) |
| ACL | setfacl -m | ls의 `+` | 개별 사용자/그룹 권한 |

> ⚠️ **함정 복습**: SetUID 셸 스크립트는 커널이 무시(보안). SetUID 탐색=`find / -perm -4000`. ACL 있으면 `ls -l` 권한 끝에 `+`. mask가 named user/group 권한의 상한.

## 자주 엮이는 시나리오 — 통합 사고

**시나리오 A — 새 협업 디렉터리 구축**
```bash
groupadd devteam
usermod -aG devteam alice
usermod -aG devteam bob
mkdir /shared && chgrp devteam /shared
chmod 2775 /shared          # SetGID: 모든 새 파일이 devteam 그룹 상속
```
SetGID(2) + 그룹 쓰기(7의 w)로 팀원이 서로 파일 편집 가능. Day 2(그룹)+Day 3(권한)+Day 4(SetGID) 통합.

**시나리오 B — 신규 직원 계정 + 첫 로그인 강제 변경**
```bash
useradd -m -s /bin/bash -c "New Hire" newbie
passwd newbie               # 초기 암호 설정
chage -d 0 newbie           # 다음 로그인 시 암호 강제 변경
chage -M 90 -W 7 newbie     # 90일마다 변경, 7일 전 경고
```
Day 1(shadow 필드)+Day 2(useradd/passwd/chage) 통합.

**시나리오 C — 보안 점검**
```bash
awk -F: '$3==0{print $1}' /etc/passwd   # UID 0 계정(root만 정상)
find / -perm -4000 -type f 2>/dev/null  # 의심스러운 SetUID
ls -ld /tmp                              # Sticky 확인
```

> 📚 **유래/사례**: 실무 침해 사고 분석의 첫 단계가 정확히 이 세 가지다 — UID 0 백도어 계정, 비정상 SetUID 바이너리, /tmp의 Sticky 누락. 한 줄짜리 명령으로 시스템 보안의 핵심 구멍을 즉시 점검할 수 있다는 점에서, 이번 주 내용은 시험을 넘어 실무 보안의 기초다.

**문제 9.** 보안 점검 중 `awk -F: '$3==0 {print $1}' /etc/passwd`를 실행했더니 `root`와 `backdoor` 두 개가 출력되었다. 이 결과의 의미는?

A) 정상이며 두 계정 모두 시스템 기본 계정이다

**문제 12.** `passwd -l user1`과 `passwd -d user1`의 차이로 옳은 것은?

A) -l은 암호를 삭제하고, -d는 계정을 잠근다

B) -l은 해시 앞에 !를 붙여 로그인을 차단하고, -d는 암호를 삭제해 무암호 상태로 만든다

C) 둘 다 동일하게 계정을 완전히 삭제한다

D) -l은 암호를 만료시키고, -d는 계정 만료일을 설정한다

**정답: B**

해설: `passwd -l`(lock)은 shadow 해시 앞에 `!`를 붙여 로그인을 차단하고, `passwd -d`(delete)는 암호 자체를 삭제해 무암호 로그인이 가능한(위험) 상태로 만든다. 두 효과는 정반대에 가깝다. A는 둘을 뒤바꿨고, C는 계정 삭제(userdel)와 혼동했으며, D는 -e(만료)/-E(계정 만료일)와 혼동한 설명이다.
