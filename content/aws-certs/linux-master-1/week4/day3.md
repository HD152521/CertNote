# Day 3 - 권한의 산수: rwx · 8진수 chmod · 소유권 · umask 계산

리눅스에서 "이 파일에 누가 무엇을 할 수 있는가"는 감(感)이 아니라 **세 자리의 산수**로 정확히 결정된다. 모든 파일과 디렉터리에는 소유자(owner)·그룹(group)·기타(other) 세 부류에 대해 읽기(r)·쓰기(w)·실행(x) 세 권한이 켜지거나 꺼져 있다. 이 9개의 켜짐/꺼짐을 다루는 도구가 `chmod`이고, 새로 만드는 파일의 기본 권한을 결정하는 규칙이 `umask`다.

오늘의 목표는 **권한을 숫자로 자유롭게 변환**하는 것이다. `rwxr-xr--`를 보고 즉시 754라고 말할 수 있고, 644가 무엇을 허용하는지 즉시 풀어낼 수 있어야 한다. 그리고 umask가 권한을 "더하는" 게 아니라 "빼는" 마스크라는 원리를 손으로 계산할 수 있어야 한다. 이 산수가 막히면 Day 4의 특수권한·ACL도 무너진다.

## rwx와 세 부류 — 9비트의 구조

`ls -l`의 맨 앞 10글자가 권한을 나타낸다.

```bash
-rwxr-xr--  1 alice dev  4096 Jun  5 10:00 report.sh
# │└┬┘└┬┘└┬┘
# │ owner group other
# └ 파일 종류(-=파일, d=디렉터리, l=링크)
```

첫 글자는 **종류**(파일 `-`, 디렉터리 `d`, 심볼릭 링크 `l`, 블록장치 `b`, 문자장치 `c`)이고, 나머지 9글자가 세 부류 × 세 권한이다.

| 부류 | 글자 | 의미 |
|------|------|------|
| owner (u) | 1~3 | 파일 소유자 |
| group (g) | 4~6 | 소유 그룹 |
| other (o) | 7~9 | 그 외 모든 사용자 |

각 부류 안의 세 자리는 **r → w → x 순서**로 고정이다. 권한이 있으면 글자, 없으면 `-`.

> 💡 **개념**: 파일과 디렉터리에서 같은 글자라도 의미가 다르다. **파일**에서 r=내용 읽기, w=내용 수정, x=실행. **디렉터리**에서 r=목록 보기(`ls`), w=파일 생성/삭제, **x=그 디렉터리 안으로 진입(`cd`)**이다. 특히 디렉터리의 x가 없으면 r이 있어도 그 안의 파일에 접근할 수 없다(이름은 보여도 들어갈 수 없음). 시험에서 "디렉터리에 x만 있고 r이 없으면?" → 이름은 못 보지만 정확한 파일명을 알면 접근 가능, 같은 함정으로 출제된다.

> 🔍 **더 깊이**: 디렉터리에서 파일을 **삭제**하려면 그 파일에 대한 쓰기 권한이 아니라 **디렉터리에 대한 w 권한**이 필요하다. 파일 자체가 읽기 전용(444)이어도 그 파일이 든 디렉터리에 w가 있으면 삭제된다. 이것이 직관에 어긋나 자주 출제된다. (Sticky bit가 이 동작을 제한하는데, Day 4에서 다룬다.)

## 8진수 변환 — rwx를 숫자로

각 권한에는 가중치가 있다: **r=4, w=2, x=1**. 한 부류의 권한을 더하면 0~7의 숫자가 나온다.

| rwx | 계산 | 8진수 |
|-----|------|-------|
| `---` | 0 | 0 |
| `--x` | 1 | 1 |
| `-w-` | 2 | 2 |
| `-wx` | 2+1 | 3 |
| `r--` | 4 | 4 |
| `r-x` | 4+1 | 5 |
| `rw-` | 4+2 | 6 |
| `rwx` | 4+2+1 | 7 |

세 부류를 각각 계산해 이어 붙이면 세 자리 8진수가 된다.

```
rwxr-xr--
rwx = 7,  r-x = 5,  r-- = 4   →  754
```

> 💡 **개념**: r=4, w=2, x=1은 2진수 비트 가중치(2², 2¹, 2⁰)다. rwx 세 비트를 2진수로 보면 `111`=7, `101`=5, `100`=4가 된다. 그래서 8진수 한 자리(0~7)가 세 비트를 정확히 표현한다. 이 대응을 알면 변환이 암기가 아니라 계산이 된다.

자주 쓰는 권한 숫자는 통째로 외워두면 빠르다.

| 8진수 | rwx | 용도 |
|-------|-----|------|
| **644** | rw-r--r-- | 일반 파일 기본(소유자 읽기/쓰기, 나머지 읽기) |
| **755** | rwxr-xr-x | 실행 파일·디렉터리 기본 |
| **600** | rw------- | 개인 비밀 파일(SSH 키 등) |
| **700** | rwx------ | 개인 디렉터리 |
| **777** | rwxrwxrwx | 모두 전체 권한(보안상 지양) |
| **400** | r-------- | 읽기 전용 비밀 파일 |

> ⚠️ **함정**: 644를 "소유자만 쓸 수 있고 나머지는 읽기"로 정확히 풀어야 한다. 6=rw-(소유자), 4=r--(그룹), 4=r--(기타). 이걸 "모두 읽기/쓰기"로 착각하거나 755(rwxr-xr-x)와 헷갈리는 보기가 단골이다. 또 chmod 숫자를 거꾸로(other부터) 읽는 실수도 흔하다 — **항상 owner-group-other 순**이다.

## chmod — 8진수 방식과 기호 방식

`chmod`로 권한을 바꾸는 방법은 두 가지다.

**8진수(절대) 방식** — 권한 전체를 한 번에 덮어쓴다.

```bash
chmod 755 script.sh          # rwxr-xr-x로 설정(기존 권한 무시하고 덮어씀)
chmod 644 config.txt         # rw-r--r--
chmod 600 ~/.ssh/id_rsa      # rw------- (SSH 키 표준)
chmod -R 755 /var/www        # -R: 하위 전체 재귀 적용
```

**기호(상대) 방식** — 특정 권한만 더하거나 뺀다.

```bash
chmod u+x script.sh          # 소유자(u)에게 실행(x) 추가
chmod g-w file.txt           # 그룹(g)에서 쓰기(w) 제거
chmod o=r file.txt           # 기타(o)를 읽기만으로 설정(나머지 제거)
chmod a+r file.txt           # 모두(a=all)에게 읽기 추가
chmod u+x,g+x,o-r file.txt   # 여러 변경 콤마로 결합
chmod ug=rw,o= file.txt      # u,g는 rw, o는 권한 없음
```

| 대상 | 의미 | 연산자 | 의미 |
|------|------|--------|------|
| u | owner | + | 권한 추가 |
| g | group | - | 권한 제거 |
| o | other | = | 정확히 그 권한으로 설정 |
| a | all(ugo) | | |

> 💡 **개념**: 8진수 방식은 **전체를 덮어쓰기**, 기호 방식은 **부분만 변경**이다. 기존 권한을 모르거나 깡그리 새로 정할 땐 8진수가, "실행 권한만 살짝 추가"처럼 일부만 바꿀 땐 기호 방식이 적합하다. `chmod +x`처럼 대상을 생략하면 umask의 영향을 받아 a(전체)에 적용되되 umask가 막는 비트는 빠진다.

> 🔍 **더 깊이**: `chmod -R`(재귀)을 파일과 디렉터리에 일괄 적용할 때 함정이 있다. 디렉터리는 진입을 위해 x가 필요하지만 일반 파일에는 x가 불필요(보안 위험)하다. `chmod -R 755`를 통째로 걸면 모든 파일에도 실행 권한이 붙는다. 이를 피하려면 `find /path -type d -exec chmod 755 {} \;`와 `find /path -type f -exec chmod 644 {} \;`로 종류별로 나누거나, 기호 방식의 대문자 `X`(`chmod -R a+X`)를 쓴다. **대문자 X는 "디렉터리이거나 이미 누군가에게 x가 있는 파일"에만 x를 추가**한다.

> ⚠️ **함정**: `chmod 777`은 "문제를 빠르게 해결"하는 만능키처럼 보이지만, 누구나 쓰기·실행이 가능해져 심각한 보안 구멍이다. 웹 서버 디렉터리에 777을 거는 것은 공격자가 악성 스크립트를 심을 길을 열어준다. 시험에서 "권한 문제 해결책으로 777" 보기는 항상 오답이다.

```bash
# 직접 쳐보기 — 권한 변환 연습
touch demo.txt && ls -l demo.txt          # 기본 권한 확인
chmod 640 demo.txt && ls -l demo.txt      # rw-r----- 확인
chmod u+x,o-r demo.txt && ls -l demo.txt  # 기호 방식 변화 관찰
stat -c "%a %A %n" demo.txt               # 8진수와 rwx를 동시에
```

## chown / chgrp — 소유권 변경

권한이 "무엇을 할 수 있는가"라면, 소유권은 "누구의 것인가"다. 파일에는 **소유자(user)와 소유 그룹(group)** 두 속성이 있다.

```bash
chown alice file.txt              # 소유자를 alice로
chown alice:dev file.txt          # 소유자 alice, 그룹 dev로 동시 변경
chown :dev file.txt               # 그룹만 dev로(콜론 앞 생략)
chown -R alice:dev /var/www       # 하위 전체 재귀
chgrp dev file.txt                # 그룹만 변경(chown :dev와 동일)
```

> 💡 **개념**: `chown user:group` 형식에서 콜론 앞은 소유자, 뒤는 그룹이다. 콜론 앞을 생략(`chown :group`)하면 그룹만 바뀌어 `chgrp group`과 같다. 소유자만 바꾸려면 콜론을 빼고 `chown user`로 한다.

> ⚠️ **함정**: **`chown`(소유자 변경)은 root만 할 수 있다**. 일반 사용자는 자기 파일이라도 다른 사람에게 소유권을 넘길 수 없다(권한을 넘기면 디스크 쿼터 회피 등 악용 가능). 다만 자기가 속한 그룹으로의 `chgrp`는 일반 사용자도 가능하다. "일반 사용자가 chown으로 소유자 변경 가능?" → 불가능이 정답이다.

> 📚 **유래/사례**: 웹 배포 후 "Permission denied"가 뜨는 전형적 원인은 파일 소유자가 배포한 사람(예: deploy)인데 웹 서버는 `www-data`/`apache` 사용자로 동작하기 때문이다. 해결은 `chown -R www-data:www-data /var/www`로 소유권을 웹 서버 사용자에게 넘기는 것. 이때 777로 권한을 열어 우회하는 건 보안상 최악수다 — **소유권을 맞추는 것이 정답이고 권한을 푸는 것은 오답**이라는 패턴으로 출제된다.

## umask — 기본 권한을 깎는 마스크

새 파일·디렉터리를 만들 때 권한을 매번 chmod로 정하진 않는다. **umask**가 기본 권한을 자동 결정한다. 핵심은 umask가 권한을 **부여**하는 게 아니라 **제거(마스킹)**한다는 것이다.

계산 규칙:
- 파일의 최대 기본 권한: **666**(rw-rw-rw-, 파일엔 x를 기본 부여 안 함)
- 디렉터리의 최대 기본 권한: **777**(rwxrwxrwx)
- 실제 권한 = 최대 권한에서 umask 비트를 **뺀 것**

```
umask 022 일 때:
  파일:      666 - 022 = 644  (rw-r--r--)
  디렉터리:  777 - 022 = 755  (rwxr-xr-x)

umask 077 일 때:
  파일:      666 - 077 = 600  (rw-------)
  디렉터리:  777 - 077 = 700  (rwx------)
```

> 💡 **개념**: 파일이 666에서 시작하는 이유는, 새로 만든 파일에 실행 권한(x)을 자동으로 주면 위험하기 때문이다(스크립트가 의도치 않게 실행될 수 있음). 그래서 파일의 출발점은 x가 빠진 666이고, 디렉터리는 진입에 x가 필수라 777에서 출발한다. 같은 umask라도 파일과 디렉터리의 결과가 다른 건 이 출발점 차이 때문이다.

> 🔍 **더 깊이**: umask 계산은 엄밀히는 "뺄셈"이 아니라 **비트 AND NOT(보수 마스킹)**이다. umask의 각 비트가 1이면 그 권한을 끈다. 022를 2진수로 보면 `000 010 010`이고, 이 비트가 켜진 자리(group의 w, other의 w)를 666에서 끄면 644가 된다. 대부분의 경우 단순 뺄셈으로 같은 답이 나오지만, umask에 홀수(예: 027의 7)가 섞이면 뺄셈 직관이 어긋날 수 있어 비트 마스킹으로 이해하는 게 안전하다. 예: umask 027 → 파일 666 & ~027 = 640, 디렉터리 777 & ~027 = 750.

> ⚠️ **함정**: "umask 022면 새 파일이 755가 된다"는 틀렸다. **755는 디렉터리의 결과**고, 파일은 666-022=**644**다. 파일과 디렉터리의 출발점(666 vs 777)을 혼동시키는 것이 umask 문제의 핵심 함정이다. 또 umask 값이 클수록 권한이 더 많이 깎여 **더 제한적**이 된다(077이 022보다 빡빡함).

```bash
# 직접 쳐보기 — umask 효과 관찰
umask                              # 현재 umask(보통 0022)
umask 077                          # 더 제한적으로 변경
touch secret.txt && ls -l secret.txt   # 600 확인(666-077)
mkdir secretdir && ls -ld secretdir    # 700 확인(777-077)
umask 022                          # 원복
```

> 📚 **유래/사례**: 한 공유 서버에서 사용자들의 umask가 002로 설정돼 있어 새로 만드는 모든 파일이 664(그룹 쓰기 허용)였다. 같은 그룹원끼리 협업하는 환경에선 편리했지만, 한 사용자가 민감한 키 파일을 만들자 같은 그룹의 다른 사용자가 수정할 수 있는 상태가 됐다. 보안팀은 개인 작업용 계정의 기본 umask를 077로 강화하도록 `/etc/profile`과 `~/.bashrc`를 조정했다. 시스템 전역 umask는 `/etc/profile`이나 `/etc/login.defs`에서, 개인은 `~/.bashrc`에서 설정한다.

## 한 장 요약 — 권한 산수 치트시트

| 개념 | 공식/규칙 |
|------|-----------|
| 권한 가중치 | r=4, w=2, x=1 |
| 순서 | owner → group → other, 각 부류 r→w→x |
| 파일 umask 계산 | 666 − umask |
| 디렉터리 umask 계산 | 777 − umask |
| chmod 8진수 | 전체 덮어쓰기 |
| chmod 기호 | u/g/o/a + +/-/= 부분 변경 |
| chown | 소유자 변경(root만), `user:group` |

`rwxr-xr-x = 755`, `rw-r--r-- = 644`를 즉답할 수 있으면 권한 문제의 절반은 끝난 것이다.

## 📝 연습 문제

**문제 1.** 권한 `rwxr-x---`를 8진수로 올바르게 표현한 것은?

A) 740

B) 750

C) 755

D) 705

**정답: B**

해설: rwx=7(4+2+1), r-x=5(4+1), ---=0이므로 750이다. A의 740은 group이 r--(4)일 때, C의 755는 other가 r-x(5)일 때, D의 705는 group이 권한 없고 other가 r-x일 때다. 각 부류를 owner-group-other 순으로 r=4,w=2,x=1로 더해야 한다.

---

**문제 2.** `umask` 값이 022로 설정된 환경에서 새로 생성되는 일반 파일의 권한은?

A) 755 (rwxr-xr-x)

B) 644 (rw-r--r--)

C) 666 (rw-rw-rw-)

D) 600 (rw-------)

**정답: B**

해설: 파일의 기본 최대 권한은 666이고 여기서 umask 022를 빼면 644(rw-r--r--)다. A의 755는 디렉터리(777-022)의 결과이며, C는 umask를 적용하지 않은 출발값, D는 umask 077일 때의 파일 권한이다. 파일은 666, 디렉터리는 777에서 출발한다는 점이 핵심이다.

**문제 3.** 디렉터리에 대해 실행(x) 권한이 갖는 의미로 옳은 것은?

A) 디렉터리 안의 파일 목록을 `ls`로 볼 수 있다

B) 디렉터리 안으로 `cd`하여 진입하고 내부 파일에 접근할 수 있다

C) 디렉터리 안에 새 파일을 생성할 수 있다

D) 디렉터리를 다른 위치로 실행 복사할 수 있다

**정답: B**

해설: 디렉터리에서 x는 그 디렉터리로 진입(`cd`)하고 내부 경로를 통과해 파일에 접근하는 권한이다. A의 목록 보기는 r 권한, C의 파일 생성은 w 권한의 의미다. D는 존재하지 않는 동작이다. 디렉터리는 x가 없으면 r이 있어도 내부 파일에 접근할 수 없다.

**문제 4.** 일반 사용자(root 아님)가 자신이 소유한 파일에 대해 수행할 수 없는 작업은?

A) `chmod`로 권한 변경

B) `chgrp`로 자신이 속한 그룹으로 그룹 변경

C) `chown`으로 다른 사용자에게 소유권 이전

D) `rm`으로 파일 삭제(디렉터리 w 권한 있을 때)

**정답: C**

해설: 소유자를 다른 사용자로 바꾸는 `chown`은 root만 가능하다. 일반 사용자가 소유권을 넘길 수 있으면 디스크 쿼터 회피 등 악용이 가능하기 때문이다. A·B·D는 자기 파일/그룹/디렉터리 권한 범위 내에서 일반 사용자도 수행할 수 있다.

**문제 5.** `chmod g-w,o-r file.txt` 명령의 효과로 옳은 것은?

A) 그룹과 기타 모두에게 쓰기 권한을 추가한다

B) 그룹에서 쓰기를, 기타에서 읽기를 제거한다

C) 그룹에서 읽기를, 기타에서 쓰기를 제거한다

D) 소유자의 모든 권한을 제거한다

**정답: B**

해설: 기호 방식에서 `g-w`는 그룹(g)에서 쓰기(w)를 제거, `o-r`은 기타(o)에서 읽기(r)를 제거한다. 콤마로 두 변경을 결합했다. A는 `+`(추가)의 동작이라 반대이고, C는 대상과 권한 글자가 뒤바뀌었으며, D는 소유자(u)를 건드리지 않으므로 틀렸다.

**문제 6.** `umask` 값이 077일 때 새로 생성되는 디렉터리의 권한은?

A) 700 (rwx------)

B) 755 (rwxr-xr-x)

C) 600 (rw-------)

D) 777 (rwxrwxrwx)

**정답: A**

해설: 디렉터리는 777에서 출발하며 umask 077을 빼면 700(rwx------)이다. B는 umask 022일 때의 디렉터리, C는 umask 077일 때의 파일(666-077) 권한이다. D는 umask를 적용하지 않은 값이다. umask가 클수록 더 많은 권한이 제거되어 제한적이 된다.

**문제 7.** `chmod -R 755 /var/www`를 일반 파일과 디렉터리가 섞인 트리에 적용할 때 발생하는 부작용으로 옳은 것은?

A) 디렉터리에 진입할 수 없게 된다

B) 모든 일반 파일에도 불필요한 실행(x) 권한이 부여된다

C) 모든 파일의 소유자가 변경된다

D) 하위 디렉터리만 변경되고 파일은 영향받지 않는다

**정답: B**

해설: `-R 755`는 디렉터리와 파일을 가리지 않고 모두 rwxr-xr-x로 만들어, 실행이 불필요한 일반 파일에도 x 권한이 붙는 보안 위험을 만든다. 종류별로 나누려면 `find -type f`/`-type d`를 쓰거나 기호의 대문자 `X`를 사용한다. A는 정반대(x가 부여됨), C는 chown의 동작, D는 `-R`이 전체에 적용되므로 틀렸다.
