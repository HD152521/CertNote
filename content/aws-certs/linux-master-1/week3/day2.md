# Day 2 - 흐름을 잇고 비트는 기술: 리다이렉션, 파이프, 메타문자

유닉스 설계 철학을 한 문장으로 요약한 더그 매클로이(Doug McIlroy)의 말이 있다. "한 가지 일을 잘하는 프로그램을 만들어라. 그리고 프로그램들이 협력하도록 만들어라." 이 철학을 현실로 만든 것이 바로 **파이프(pipe)**와 **리다이렉션(redirection)**이다. `ls`는 파일 목록만 뽑고, `grep`은 패턴만 거르고, `wc`는 개수만 센다 — 이 작은 도구들을 파이프로 연결하면 "오늘 수정된 .log 파일이 몇 개인가" 같은 복합 질문에 한 줄로 답할 수 있다.

오늘은 그 연결의 기반이 되는 **파일 디스크립터(file descriptor)** 개념부터 리다이렉션 기호, 파이프와 필터, 그리고 셸이 명령을 해석하기 전에 먼저 처리하는 **메타문자·와일드카드·따옴표**를 깊이 다룬다. 이 영역은 1급 실기와 필기 모두에서 빠지지 않는다.

## 파일 디스크립터: 0, 1, 2가 모든 것의 기준

리다이렉션을 이해하려면 먼저 **파일 디스크립터(FD)**를 알아야 한다. 리눅스에서 모든 프로세스는 시작할 때 세 개의 표준 입출력 통로를 부여받는다.

| FD 번호 | 이름 | 약어 | 기본 연결 대상 |
|---------|------|------|----------------|
| 0 | 표준 입력 | stdin | 키보드 |
| 1 | 표준 출력 | stdout | 화면(터미널) |
| 2 | 표준 에러 | stderr | 화면(터미널) |

핵심은 **stdout(1)과 stderr(2)가 둘 다 기본적으로 화면을 향하지만 별개의 통로**라는 점이다. 정상 결과는 1번으로, 에러 메시지는 2번으로 나간다. 화면에서는 섞여 보이지만 리다이렉션할 때는 따로 다룰 수 있다.

> 💡 **개념**: 리다이렉션이란 이 FD가 가리키는 "연결 대상"을 키보드·화면이 아닌 **파일이나 다른 FD로 바꾸는 것**이다. 그래서 `>`는 "1번(stdout)을 파일로 돌려라"의 줄임이고, `2>`는 "2번(stderr)을 파일로 돌려라"라는 뜻이다.

## 출력 리다이렉션: > 와 >>

명령의 출력을 화면 대신 파일로 보내는 것이 출력 리다이렉션이다.

```bash
ls -l > filelist.txt       # stdout을 파일로 (덮어쓰기)
ls -l >> filelist.txt      # stdout을 파일에 (이어쓰기)
```

- `>` : 파일을 **새로 만들거나 덮어쓴다(overwrite)**. 기존 내용은 사라진다.
- `>>` : 파일 끝에 **이어 붙인다(append)**. 기존 내용은 보존된다.

`>`는 사실 `1>`의 줄임이다. 즉 `ls > out.txt`와 `ls 1> out.txt`는 완전히 같다.

> ⚠️ **함정**: `>`는 **명령 실행 전에 파일을 먼저 비운다(truncate)**. 그래서 `sort file.txt > file.txt`처럼 입력과 출력이 같은 파일이면 sort가 읽기도 전에 파일이 비워져 **내용이 통째로 날아간다**. 같은 파일에 결과를 쓰려면 임시 파일을 거치거나 `sort -o file.txt file.txt`처럼 도구의 자체 옵션을 써야 한다.

## 에러 리다이렉션: 2> 와 stdout/stderr 분리

에러 메시지(stderr, FD 2)는 `2>`로 따로 보낼 수 있다.

```bash
find / -name "*.conf" 2> errors.txt    # 에러(권한 거부 등)만 파일로
find / -name "*.conf" 2> /dev/null     # 에러를 버림 (블랙홀로)
```

`/dev/null`은 **무엇을 써도 사라지는 특수 장치**로, "출력을 버린다"는 의미로 쓴다.

정상 출력과 에러를 **각각 다른 파일**로 분리할 수도 있다.

```bash
make 1> build.log 2> error.log
# stdout → build.log, stderr → error.log
```

### stdout과 stderr를 한 파일로 합치기

둘을 같은 파일로 모으려면 **FD 복제** 표기 `2>&1`을 쓴다. 이는 "2번을 1번이 가리키는 곳과 같게 만들어라"는 뜻이다.

```bash
command > output.txt 2>&1     # stdout과 stderr 모두 output.txt로
command &> output.txt         # 위와 동일 (bash 단축 표기)
command >> output.txt 2>&1    # 이어쓰기로 둘 다
```

> ⚠️ **함정**: `2>&1`의 **위치(순서)**가 결정적이다. `command 2>&1 > out.txt`는 의도와 다르게 동작한다. 셸은 왼쪽부터 처리하므로, 먼저 `2>&1`이 "2번을 현재 1번(화면)과 같게" 만들고, 그 **뒤에** `> out.txt`가 1번만 파일로 바꾼다. 결과적으로 stderr는 화면에 남고 stdout만 파일로 간다. 반드시 `> out.txt 2>&1` 순서로 써서 1번을 먼저 파일로 돌린 뒤 2번을 1번에 합쳐야 한다.

## 입력 리다이렉션: < 와 히어 도큐먼트

`<`는 키보드(stdin) 대신 **파일에서 입력**을 받게 한다.

```bash
sort < names.txt          # names.txt의 내용을 sort의 입력으로
wc -l < access.log        # 파일을 입력으로 줄 수 세기
mail user@host < body.txt # 파일 내용을 메일 본문으로
```

여러 줄을 즉석에서 입력으로 넘기는 **히어 도큐먼트(here document, `<<`)**도 있다.

```bash
cat << END
첫 번째 줄
두 번째 줄
END
# END를 만날 때까지의 텍스트를 cat의 입력으로 전달
```

> 🔍 **더 깊이**: `<<`(히어 도큐먼트)와 비슷한 `<<<`(히어 스트링, here string)도 있다. `<<<`는 한 줄 문자열을 그대로 stdin으로 넘긴다. 예를 들어 `grep "root" <<< "$line"`은 변수 `$line`의 내용을 grep의 입력으로 준다. 임시 파일이나 `echo | grep` 파이프 없이도 문자열을 명령에 먹일 수 있어 스크립트에서 유용하다.

리다이렉션 기호를 한눈에 정리하면 다음과 같다.

| 기호 | 의미 | FD |
|------|------|-----|
| `>` | 출력 덮어쓰기 | 1 |
| `>>` | 출력 이어쓰기 | 1 |
| `<` | 입력 받기 | 0 |
| `2>` | 에러 덮어쓰기 | 2 |
| `2>>` | 에러 이어쓰기 | 2 |
| `&>` | 출력+에러 덮어쓰기 | 1,2 |
| `2>&1` | 에러를 출력 쪽으로 합침 | 2→1 |
| `<<` | 히어 도큐먼트 | 0 |
| `<<<` | 히어 스트링 | 0 |

## 파이프: 한 명령의 출력을 다음 명령의 입력으로

파이프(`|`)는 **앞 명령의 stdout을 뒤 명령의 stdin으로 직접 연결**한다. 리다이렉션이 "FD ↔ 파일"이라면, 파이프는 "FD ↔ FD"(프로세스끼리)다.

```bash
ls -l | grep ".txt"                  # 목록에서 .txt만 추리기
cat access.log | grep "404" | wc -l  # 404 응답 줄 수 세기
ps aux | grep nginx                  # 실행 중 nginx 프로세스 찾기
du -h | sort -rh | head -5           # 용량 큰 항목 상위 5개
```

파이프로 연결된 명령들은 **동시에(병렬로) 실행**되며, 데이터는 커널이 관리하는 파이프 버퍼를 통해 흐른다.

> 💡 **개념**: 파이프는 **stdout만** 다음으로 넘긴다. stderr(2번)는 파이프를 타지 않고 화면에 남는다. stderr까지 파이프로 넘기려면 `command 2>&1 | next` 또는 bash의 `command |& next` 표기를 쓴다.

### 필터: 파이프 사이에 끼어 데이터를 가공하는 명령

**필터(filter)**는 stdin으로 받아 가공한 뒤 stdout으로 내보내는 명령으로, 파이프라인의 중간 단계에 쓰인다. 대표적인 필터를 정리한다.

| 필터 | 역할 |
|------|------|
| `grep` | 패턴에 맞는 줄만 거르기 |
| `sort` | 정렬 (`-r` 역순, `-n` 숫자, `-k` 필드) |
| `uniq` | 인접 중복 줄 제거 (`-c` 개수 세기) |
| `wc` | 줄·단어·바이트 수 세기 (`-l`, `-w`, `-c`) |
| `head` / `tail` | 앞/뒤 N줄 (`tail -f` 실시간) |
| `cut` | 필드·문자 단위 잘라내기 (`-d`, `-f`) |
| `tr` | 문자 치환·삭제 |
| `sed` | 스트림 편집(치환·삭제) |
| `awk` | 필드 기반 텍스트 처리 |
| `tee` | 화면 출력과 파일 저장 동시에 |

`tee`는 특히 유용하다 — 파이프 중간에서 **흐름을 화면과 파일로 동시에 분기**한다.

```bash
ls -l | tee filelist.txt | grep ".sh"
# 전체 목록을 filelist.txt에 저장하면서 동시에 .sh만 화면에 표시
make 2>&1 | tee build.log    # 빌드 로그를 보면서 파일로도 기록
```

> 📚 **유래/사례**: `tee`라는 이름은 배관에서 물길을 둘로 나누는 **T자 관(tee fitting)**에서 왔다. 하나의 입력을 두 갈래(파일·화면)로 흘려보내는 모양이 알파벳 T와 닮았다. 유닉스 명령 이름에는 이처럼 일상 사물에서 따온 작명이 많다.

## 메타문자와 와일드카드: 셸이 먼저 가로채는 특수 기호

명령을 실행하기 전에 셸은 입력 줄에서 **특수한 의미를 가진 문자(메타문자, metacharacter)**를 먼저 처리한다. 그중 파일 이름을 매칭하는 데 쓰는 것을 **와일드카드(wildcard)** 또는 **글로빙(globbing)**이라 한다.

| 와일드카드 | 의미 | 예시 |
|------------|------|------|
| `*` | 0개 이상의 임의 문자 | `*.txt` → 모든 .txt |
| `?` | 정확히 1개의 임의 문자 | `file?.log` → file1.log, fileA.log |
| `[ ]` | 괄호 안 문자 중 하나 | `file[123].txt` |
| `[a-z]` | 범위 안의 한 문자 | `[a-c]*` → a,b,c로 시작 |
| `[!abc]` | 괄호 안 문자를 **제외**한 하나 | `[!0-9]*` → 숫자로 시작 안 함 |
| `{ }` | 중괄호 확장(brace) | `file{1,2,3}.txt` |

```bash
ls *.txt              # 확장자가 .txt인 모든 파일
rm temp?.log          # temp 뒤에 한 글자 + .log
ls [a-c]*             # a, b, c로 시작하는 모든 파일
cp file{1,2,3}.txt /backup/   # file1.txt file2.txt file3.txt 복사
ls *[!0-9]            # 마지막 글자가 숫자가 아닌 파일
```

> 🔍 **더 깊이**: 와일드카드 확장(globbing)을 수행하는 주체는 **명령이 아니라 셸**이다. `ls *.txt`를 입력하면 셸이 먼저 `*.txt`를 실제 파일 이름들(`a.txt b.txt c.txt`)로 바꾼 뒤, 그 결과를 `ls`에게 인자로 넘긴다. 그래서 매칭되는 파일이 하나도 없으면 bash 기본 동작에서는 `*.txt`가 글자 그대로 ls에게 전달된다. 이 "셸이 먼저 확장한다"는 점은 정규표현식과 와일드카드의 결정적 차이로 이어진다.

> ⚠️ **함정**: 와일드카드(글로빙)와 정규표현식(regex)을 혼동하면 안 된다. 둘 다 `*`를 쓰지만 의미가 다르다. 글로빙에서 `*`는 "임의의 0개 이상 문자"지만, 정규표현식에서 `*`는 "**바로 앞 문자**의 0회 이상 반복"이다. 예를 들어 글로빙 `a*`는 a로 시작하는 모든 것이지만, regex `a*`는 a가 0번 이상(즉 빈 문자열 포함)을 뜻한다. `grep`의 패턴은 정규표현식, 파일 이름 매칭은 글로빙이다.

## 따옴표: 셸의 확장을 제어하는 세 가지 인용

메타문자를 **글자 그대로** 쓰고 싶거나 변수 확장을 제어하려면 따옴표를 쓴다. 세 종류의 동작이 모두 다르다.

| 따옴표 | 이름 | 변수($) 확장 | 명령 치환(`` ` ``) | 와일드카드 |
|--------|------|:---:|:---:|:---:|
| `' '` | 작은따옴표(strong) | ❌ | ❌ | ❌ |
| `" "` | 큰따옴표(weak) | ✅ | ✅ | ❌ |
| `` ` ` `` | 역따옴표(backtick) | — | 명령 실행 | — |

```bash
NAME="linux"

echo '$NAME'      # $NAME      (작은따옴표: 전혀 확장 안 함)
echo "$NAME"      # linux      (큰따옴표: 변수만 확장)
echo `date`       # 현재 날짜  (역따옴표: 명령 실행 결과로 치환)
```

- **작은따옴표(`'`)**: 안의 모든 것을 **문자 그대로** 취급한다. `$`, `*`, 공백 모두 글자다.
- **큰따옴표(`"`)**: 변수(`$VAR`)와 명령 치환(`` `cmd` ``)은 확장하되, 와일드카드는 막는다. 공백을 포함한 값을 안전하게 다룰 때 필수다.
- **역따옴표(`` ` ``)**: 안의 명령을 실행해 그 **출력으로 치환**한다(명령 치환). 현대 bash에서는 `$(...)` 표기를 더 권장한다.

```bash
# 명령 치환 — 두 표기는 동일, $() 가 중첩에 안전
echo "오늘은 `date +%Y-%m-%d` 입니다"
echo "오늘은 $(date +%Y-%m-%d) 입니다"

# 변수 값에 공백이 있을 때 큰따옴표의 중요성
FILE="my report.txt"
rm "$FILE"        # 올바름: 'my report.txt' 한 파일 삭제
rm $FILE          # 위험: 'my'와 'report.txt' 두 인자로 분리됨
```

> 💡 **개념**: 큰따옴표로 변수를 감싸야 하는 이유는 **단어 분리(word splitting)** 때문이다. 따옴표 없이 변수를 쓰면 셸이 값 안의 공백을 기준으로 여러 인자로 쪼갠다. 그래서 스크립트에서는 거의 항상 `"$VAR"`처럼 큰따옴표로 감싸는 것이 안전한 관용구다.

> 📚 **유래/사례**: 역따옴표 명령 치환의 가장 큰 약점은 **중첩**이다. `` `cmd1 `cmd2` ` ``처럼 역따옴표를 겹치면 어디서 끝나는지 셸이 헷갈린다. 1990년대 POSIX가 `$(...)` 문법을 도입한 가장 큰 이유가 이 중첩 문제 해결이었다. `$(cmd1 $(cmd2))`처럼 괄호로 명확히 중첩되므로 오늘날 스크립트에서는 `$()`가 표준이다.

### 이스케이프: 백슬래시로 한 글자만 보호하기

따옴표 대신 **백슬래시(`\`)**로 바로 뒤의 한 글자만 특수 의미를 제거할 수도 있다.

```bash
echo \$NAME       # $NAME (달러 기호를 글자로)
echo file\ name   # 'file name' (공백을 글자로)
touch a\*b        # 'a*b'라는 이름의 파일 생성
```

## 마무리

오늘의 핵심은 "셸이 명령을 실행하기 전에 무엇을 먼저 처리하는가"다. 리다이렉션은 파일 디스크립터(0/1/2)의 연결 대상을 바꾸는 일이고, `2>&1`의 순서가 결과를 가른다. 파이프는 stdout을 다음 명령의 stdin으로 잇고, 필터들을 조합해 복합 작업을 한 줄로 만든다. 와일드카드(글로빙)는 셸이 먼저 파일 이름으로 확장하며 정규표현식과는 의미가 다르다. 따옴표는 작은(전부 보호)·큰(변수만 확장)·역(명령 실행)으로 동작이 갈린다. 내일은 alias·history·작업 제어를 다룬다.

## 📝 연습 문제

**문제 1.** 표준 에러(stderr)에 해당하는 파일 디스크립터 번호는?

A) 0
B) 1
C) 2
D) 3

**정답: C**
해설: 표준 입력(stdin)은 0번, 표준 출력(stdout)은 1번, 표준 에러(stderr)는 2번이다. 따라서 에러 메시지만 따로 리다이렉션할 때 `2>`를 쓴다. 3번 이상은 일반적으로 프로그램이 추가로 여는 파일에 할당되며, 표준 입출력에는 포함되지 않는다. 이 0/1/2 번호 체계는 리다이렉션의 모든 기호 해석의 기준이 된다.

**문제 2.** `command > output.txt 2>&1` 의 동작으로 옳은 것은?

A) 표준 출력만 output.txt에 저장하고 에러는 화면에 표시한다
B) 표준 출력과 표준 에러를 모두 output.txt에 저장한다
C) 표준 에러만 output.txt에 저장하고 출력은 화면에 표시한다
D) output.txt의 내용을 command의 입력으로 사용한다

**정답: B**
해설: `> output.txt`가 먼저 stdout(1번)을 파일로 돌리고, 그다음 `2>&1`이 stderr(2번)를 "현재 1번이 가리키는 곳", 즉 output.txt로 합친다. 결과적으로 정상 출력과 에러가 모두 한 파일에 저장된다. 순서가 중요한데, `2>&1`이 `> output.txt`보다 앞에 오면 stderr는 화면에 남게 된다. D는 입력 리다이렉션(`<`)에 대한 설명이라 무관하다.

**문제 3.** 명령의 출력을 화면에 보여주는 동시에 파일에도 저장하는 필터는?

A) `cat`
B) `tee`
C) `split`
D) `dd`

**정답: B**
해설: `tee`는 stdin으로 받은 데이터를 stdout(화면)으로 그대로 내보내면서 동시에 지정한 파일에도 기록한다. 이름처럼 흐름을 T자로 분기한다. `cat`은 파일 내용을 출력만 하고, `split`은 큰 파일을 여러 조각으로 나누며, `dd`는 블록 단위 복사·변환 도구다. 파이프 중간에서 흐름을 화면과 파일로 동시에 보내려면 `command | tee file`을 쓴다.

**문제 4.** 와일드카드 `?`의 의미로 옳은 것은?

A) 0개 이상의 임의 문자
B) 정확히 1개의 임의 문자
C) 괄호 안의 문자 중 하나
D) 앞 문자의 0회 이상 반복

**정답: B**
해설: 글로빙에서 `?`는 **정확히 한 글자**를 의미한다. 예를 들어 `file?.txt`는 file 뒤에 한 글자가 오는 file1.txt, fileA.txt 등에 매칭되지만 file.txt나 file10.txt에는 매칭되지 않는다. "0개 이상의 임의 문자"는 `*`이고, "괄호 안 문자 중 하나"는 `[ ]`이며, "앞 문자의 0회 이상 반복"은 정규표현식의 `*` 의미다. 글로빙과 정규표현식의 `*`를 혼동하지 않도록 주의한다.

**문제 5.** 다음 중 변수 `$NAME`을 확장하지 **않고** 글자 그대로 출력하는 것은?

A) `echo "$NAME"`
B) `echo '$NAME'`
C) `echo $NAME`
D) `echo "${NAME}"`

**정답: B**
해설: 작은따옴표(`' '`)는 안의 모든 내용을 문자 그대로 취급하므로 `$NAME`이 확장되지 않고 `$NAME`이라는 글자가 그대로 출력된다. 큰따옴표(A, D)는 변수를 확장하고, 따옴표 없이 쓴 C도 변수를 확장한다. 큰따옴표는 변수와 명령 치환은 허용하되 와일드카드만 막는 "약한 인용", 작은따옴표는 모든 확장을 막는 "강한 인용"이라는 차이를 기억해야 한다.

**문제 6.** `sort file.txt > file.txt` 를 실행했을 때 발생하는 결과는?

A) file.txt가 정렬되어 저장된다
B) file.txt의 내용이 모두 사라진다
C) 정렬 결과가 화면에 출력된다
D) 에러가 발생하고 파일은 그대로 유지된다

**정답: B**
해설: `>`는 명령 실행 **전에** 출력 대상 파일을 먼저 비운다(truncate). 따라서 sort가 file.txt를 읽으려는 시점에는 이미 파일이 비어 있어, 정렬할 내용이 없고 결과적으로 파일 내용이 통째로 사라진다. 같은 파일에 정렬 결과를 쓰려면 `sort -o file.txt file.txt`처럼 sort 자체 옵션을 쓰거나 임시 파일을 거쳐야 한다. 이는 리다이렉션 처리 순서를 보여주는 대표적 함정이다.

**문제 7.** 명령 치환(command substitution)을 수행하는 표기로 올바르게 짝지어진 것은?

A) `'cmd'` 와 `${cmd}`
B) `` `cmd` `` 와 `$(cmd)`
C) `"cmd"` 와 `<(cmd)`
D) `[cmd]` 와 `{cmd}`

**정답: B**
해설: 명령 치환은 명령을 실행해 그 출력으로 치환하는 기능으로, 역따옴표 `` `cmd` ``와 `$(cmd)` 두 표기가 동일한 역할을 한다. 현대 bash에서는 중첩이 명확하고 가독성이 좋은 `$(cmd)`를 권장한다. 작은따옴표는 확장을 막고, `${...}`는 변수 확장이며, `<(cmd)`는 프로세스 치환으로 명령 치환과는 다르다. `[ ]`와 `{ }`는 각각 글로빙과 중괄호 확장이다.
