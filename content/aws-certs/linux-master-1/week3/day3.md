# Day 3 - 셸을 길들이다: 별칭, 히스토리, 그리고 작업 제어

## 📌 핵심 정리

- `alias`는 명령의 **첫 단어**에만 적용된다. 영구 적용은 `~/.bashrc`, 임시 우회는 `\명령`.
- history 재활용 3종: `!!`(직전) · `!100`(번호) · `!$`(직전 명령의 마지막 인자). 동작은 `HISTSIZE`·`HISTCONTROL`로 조절.
- `Ctrl-Z`는 **일시 중지(SIGSTOP)**, `Ctrl-C`는 **종료(SIGINT)**. 멈춘 작업은 `bg`/`fg`로 되살린다.
- 터미널을 닫으면 **SIGHUP**이 날아가 작업이 죽는다. `nohup ... &`(시작 시) 또는 `disown`(도중)으로 면역시킨다.
- `$( )`는 명령 치환(출력을 값으로), `$(( ))`는 산술 확장(계산 결과). 괄호 하나 차이로 의미가 전혀 다르다.

## alias: 긴 명령을 짧은 단어로

하루에 같은 명령을 수십 번 치는 관리자에게 셸은 단순한 입력기 이상이어야 한다. 그 첫 도구가 별칭이다.

- `alias`는 명령이나 명령 묶음에 **별명**을 붙여, 자주 쓰는 옵션 조합을 외우지 않아도 되게 해준다.

```bash
alias                    # 등록된 모든 별칭 보기
alias ll='ls -alF'       # ll 입력 시 ls -alF 실행
alias rm='rm -i'         # rm을 항상 확인 모드로 (안전장치)
alias ..='cd ..'         # .. 입력으로 상위 디렉터리 이동
alias grep='grep --color=auto'   # grep 결과에 색상

unalias ll               # ll 별칭 제거
unalias -a               # 모든 별칭 제거
```

- 등록 위치가 중요하다. 명령행에서 직접 등록하면 **현재 셸에서만, 로그아웃하면 사라진다**.
- 영구적으로 쓰려면 `~/.bashrc`에 적어 둬야 한다(.bashrc는 셸을 띄울 때마다 읽히므로).

```bash
# ~/.bashrc 에 추가하면 영구 적용
echo "alias ll='ls -alF'" >> ~/.bashrc
source ~/.bashrc         # 즉시 반영
```

> 💡 **개념**: 별칭은 명령의 **맨 앞 단어(명령 이름)**에만 적용된다. `alias ll='ls -l'`을 등록해도 `xll`이나 `echo ll`에서는 확장되지 않는다. 셸은 명령 줄의 첫 단어가 별칭 목록에 있을 때만 치환한다.

> ⚠️ **함정**: 별칭이 원래 명령을 가린 상황에서 **원본 명령**을 그대로 실행하려면 명령 앞에 백슬래시(`\`)를 붙인다. 예를 들어 `alias rm='rm -i'`가 걸려 있을 때 `\rm file`이라고 하면 확인 없이 원래 `rm`이 실행된다. `command rm file`이나 절대 경로 `/bin/rm file`도 같은 효과다. 별칭을 임시로 우회하는 표준 방법이다.

> 📚 **유래/사례**: alias 기능은 1978년 빌 조이(Bill Joy)가 만든 C 셸에서 처음 등장했다. 이전의 본 셸에는 별칭이 없었다. 이 편의성이 큰 인기를 끌어 ksh, bash 등 후속 셸이 모두 채택했다. 그래서 "alias를 처음 도입한 셸은?"이라는 문제의 답은 csh다.

## history: 명령 이력을 기억하고 재실행하기

- `history`는 이전에 입력한 명령들을 번호와 함께 보여준다.
- 명령 이력은 메모리에 유지되다가 로그아웃 시 `~/.bash_history` 파일에 저장된다.

```bash
history                  # 전체 명령 이력
history 10               # 최근 10개
history -c               # 메모리의 이력 삭제(clear)
!!                       # 바로 직전 명령 재실행
!100                     # 100번 명령 재실행
!ls                      # 가장 최근의 ls로 시작한 명령 재실행
!$                       # 직전 명령의 마지막 인자
sudo !!                  # 직전 명령을 sudo 붙여 재실행
```

`!$`(직전 명령의 마지막 인자)는 특히 자주 쓴다.

```bash
mkdir /opt/myapp/config
cd !$              # cd /opt/myapp/config 과 동일
```

히스토리 동작은 환경 변수로 제어한다.

| 변수 | 의미 |
|------|------|
| `HISTSIZE` | 현재 세션 메모리에 보관할 명령 개수 |
| `HISTFILE` | 이력을 저장할 파일 경로 (보통 `~/.bash_history`) |
| `HISTFILESIZE` | 이력 파일에 저장할 최대 줄 수 |
| `HISTCONTROL` | 중복·공백 시작 명령 저장 제어 (`ignoredups`, `ignorespace`) |

```bash
export HISTSIZE=5000
export HISTCONTROL=ignoredups   # 연속 중복 명령은 한 번만 저장
```

> 🔍 **더 깊이**: `HISTCONTROL=ignorespace`를 설정하면 **공백으로 시작하는 명령은 이력에 남지 않는다**. 비밀번호가 포함된 명령을 칠 때 줄 맨 앞에 공백 하나를 두면 history 파일에 기록되지 않아 보안에 유리하다. `ignoreboth`는 ignoredups와 ignorespace를 동시에 적용한다.

> ⚠️ **함정**: `history -c`는 **메모리상의 이력만** 지운다. `~/.bash_history` 파일은 그대로 남아, 다음 로그인 시 다시 불러와진다. 파일까지 비우려면 `history -c && history -w`(메모리 비운 뒤 파일에 덮어쓰기)를 하거나 `> ~/.bash_history`로 파일을 직접 비워야 한다. 또한 여러 터미널을 동시에 쓰면 마지막에 종료된 셸의 이력이 파일을 덮어쓸 수 있다.

## 작업 제어: 포그라운드, 백그라운드, 그리고 job

- 명령을 실행하면 기본적으로 **포그라운드(foreground)**로 동작한다 — 끝날 때까지 셸은 다음 입력을 받지 않는다.
- 시간이 오래 걸리는 작업은 **백그라운드(background)**로 보내 셸을 계속 쓸 수 있다.

### & : 처음부터 백그라운드로 실행

명령 끝에 `&`를 붙이면 백그라운드에서 실행되고 셸은 즉시 프롬프트를 돌려준다.

```bash
sleep 100 &              # 백그라운드 실행
# [1] 12345  → [작업번호] PID 가 출력됨

tar czf backup.tar.gz /data &    # 압축을 백그라운드로
```

- 출력의 `[1]`은 **작업 번호(job number)**, `12345`는 **프로세스 ID(PID)**다.
- 작업 번호는 현재 셸 안에서만 유효한 번호이고, PID는 시스템 전체에서 유일하다.

### Ctrl-Z, jobs, fg, bg

실행 중인 포그라운드 작업을 멈춰 백그라운드로 보내거나, 백그라운드 작업을 관리하는 명령들이다.

| 조작 | 동작 |
|------|------|
| `Ctrl-Z` | 포그라운드 작업을 **일시 중지(stopped)**시킴 |
| `jobs` | 현재 셸의 작업 목록 보기 (`-l` PID 포함) |
| `bg %1` | 1번 작업을 백그라운드에서 **재개(running)** |
| `fg %1` | 1번 작업을 포그라운드로 가져오기 |
| `kill %1` | 1번 작업 종료 |

```bash
# 직접 쳐보기: 멈췄다가 백그라운드로 돌리기
sleep 300              # 포그라운드 실행 (셸이 묶임)
# Ctrl-Z 누름 → [1]+ Stopped  sleep 300
jobs                   # [1]+ Stopped  sleep 300
bg %1                  # [1]+ sleep 300 &  (백그라운드에서 재개)
jobs                   # [1]+ Running  sleep 300 &
fg %1                  # 다시 포그라운드로 가져옴
```

> 💡 **개념**: `Ctrl-Z`는 작업을 **종료가 아니라 일시 중지(SIGSTOP)**한다. 멈춘 작업은 `bg`로 백그라운드에서 다시 굴리거나 `fg`로 포그라운드에 복귀시킬 수 있다. 반면 `Ctrl-C`는 작업에 SIGINT를 보내 **종료**시킨다. 둘을 혼동하지 말 것 — Z는 멈춤(suspend), C는 끝냄(terminate)이다.

- `%`는 작업 번호를 가리키는 기호다. `fg %1`은 1번 작업을, `fg %%` 또는 `fg`는 가장 최근 작업을 뜻한다.

> 🔍 **더 깊이**: 작업 번호 뒤의 `+`와 `-` 기호에도 의미가 있다. `+`는 **현재 작업(current job)** — `fg`나 `bg`를 인자 없이 쓸 때 대상이 되는 작업이고, `-`는 **직전 작업(previous job)**이다. `jobs` 출력에서 `[1]+`, `[2]-`처럼 표시된다.

## nohup과 disown: 터미널을 닫아도 살아남기

- 백그라운드로 돌린 작업이라도 **터미널(셸)을 닫으면 함께 죽는** 경우가 많다.
- 터미널이 닫힐 때 그 안의 작업들에 **SIGHUP(hangup) 신호**가 전달되기 때문이다.
- 장시간 작업을 안전하게 돌리려면 이 신호를 무시하게 해야 한다.

### nohup: 처음부터 SIGHUP을 무시하고 실행

```bash
nohup ./long_job.sh &
# nohup: ignoring input and appending output to 'nohup.out'

nohup ./backup.sh > backup.log 2>&1 &   # 출력을 원하는 파일로
```

- `nohup`(no hangup)은 명령을 SIGHUP에 면역시켜 실행한다.
- 출력 리다이렉션을 지정하지 않으면 stdout/stderr가 자동으로 `nohup.out` 파일에 쌓인다.

### disown: 이미 실행 중인 작업을 셸에서 떼어내기

이미 `&`로 돌린 작업을 뒤늦게 셸과 분리하려면 `disown`을 쓴다.

```bash
./long_job.sh &
disown %1                # 1번 작업을 jobs 목록에서 제거, SIGHUP 면역
disown -h %1             # 작업은 유지하되 SIGHUP만 무시
```

| 방법 | 시점 | 특징 |
|------|------|------|
| `nohup cmd &` | 실행 시작 시 | 출력을 nohup.out에 기록, SIGHUP 무시 |
| `disown %n` | 실행 도중 | 이미 돌아가는 작업을 셸에서 분리 |
| `screen` / `tmux` | 세션 단위 | 터미널 세션 자체를 분리·재접속 (강력) |

> 📚 **유래/사례**: SIGHUP의 'HUP'은 **hang up(전화를 끊다)**에서 왔다. 유닉스 초창기에는 실제 전화 모뎀으로 터미널에 접속했는데, 전화를 끊으면(hang up) 연결된 모든 프로세스에 신호를 보내 정리하도록 한 것이 SIGHUP의 기원이다. 오늘날 SSH 세션이 끊길 때도 같은 신호가 전달되어, 돌리던 작업이 죽는 원인이 된다.

> ⚠️ **함정**: `nohup cmd &`에서 **& 를 빼먹으면** 명령이 포그라운드로 실행되어 셸이 그대로 묶인다. nohup은 "SIGHUP을 무시하라"는 의미일 뿐 "백그라운드로 보내라"는 뜻이 아니다. 백그라운드 실행은 어디까지나 `&`가 담당하므로, 둘을 함께 써야 "터미널 닫아도 백그라운드에서 계속" 동작이 완성된다.

## 명령 치환: 명령의 출력을 값으로 쓰기

**명령 치환(command substitution)**은 명령의 출력 결과를 다른 명령의 인자나 변수 값으로 쓰는 기능이다.

```bash
# $(...) 또는 `...` 두 표기
TODAY=$(date +%Y%m%d)
echo "백업 파일: backup_$TODAY.tar.gz"
# 백업 파일: backup_20260605.tar.gz

# 명령 결과를 바로 다른 명령의 인자로
echo "커널 버전: $(uname -r)"
kill $(pgrep -f myapp)           # myapp 프로세스들을 한 번에 종료
files=$(ls *.log)                # 로그 파일 목록을 변수에
cd $(dirname /opt/app/conf/x.ini)  # /opt/app/conf 로 이동
```

> 💡 **개념**: 명령 치환은 **출력만 값으로** 가져온다. 명령의 종료 코드(성공/실패)가 아니라 stdout에 찍힌 텍스트가 치환된다. 끝의 줄바꿈은 자동으로 제거된다. 그래서 `count=$(ls | wc -l)`처럼 개수를 깔끔한 숫자로 받을 수 있다.

산술 연산에는 비슷하게 생긴 `$(( ... ))`를 쓴다. 명령 치환 `$( )`와 구별해야 한다.

```bash
echo $((3 + 4))          # 7   (산술 확장)
echo $(expr 3 + 4)       # 7   (외부 expr 명령 치환 — 옛 방식)
n=5; echo $((n * 2))     # 10
```

> 🔍 **더 깊이**: `$( )`(명령 치환)와 `$(( ))`(산술 확장)는 괄호 개수만 다르고 의미는 전혀 다르다. 하나짜리는 "명령을 실행해 출력으로 치환", 둘짜리는 "산술식을 계산해 결과로 치환"이다. 옛날에는 산술 연산도 `expr` 명령을 치환해 썼지만(`$(expr ...)`), 외부 프로세스를 띄우므로 느리다. 셸 내장인 `$(( ))`가 더 빠르고 표준이다.

내일은 이 모든 것을 자동화하는 셸 스크립트 기초로 넘어간다.

## 📖 용어

- **alias(별칭)** : 명령에 붙이는 별명. 명령 줄의 **첫 단어**일 때만 확장된다.
- **`\명령`** : 별칭을 무시하고 원본 명령을 실행하는 표기. `command 명령`, 절대 경로도 같은 효과.
- **`~/.bash_history`** : 로그아웃할 때 명령 이력이 저장되는 파일.
- **`!!` / `!n` / `!$`** : 직전 명령 / n번 명령 / 직전 명령의 마지막 인자를 불러오는 히스토리 확장.
- **HISTCONTROL** : 이력 저장 규칙. `ignoredups`(중복 제외), `ignorespace`(공백으로 시작하면 제외).
- **포그라운드 / 백그라운드** : 셸이 끝날 때까지 기다리는 실행과, 프롬프트를 바로 돌려주는 실행(`&`).
- **작업 번호(job number)** : `[1]`처럼 현재 셸 안에서만 통하는 번호. 시스템 전역인 PID와 다르다.
- **`Ctrl-Z` vs `Ctrl-C`** : 일시 중지(SIGSTOP)와 종료(SIGINT). Z는 멈춤, C는 끝냄.
- **`jobs` / `fg` / `bg`** : 작업 목록 보기, 포그라운드로 끌어오기, 백그라운드에서 재개하기.
- **SIGHUP** : 터미널이 닫힐 때 그 안의 프로세스에 날아가는 신호. 이름은 "전화를 끊다(hang up)"에서 왔다.
- **nohup** : SIGHUP을 무시하고 실행하는 명령. 백그라운드로 보내려면 `&`를 함께 써야 한다.
- **disown** : 이미 실행 중인 작업을 셸의 작업 목록에서 떼어내 SIGHUP에서 보호하는 명령.
- **명령 치환 `$( )` vs 산술 확장 `$(( ))`** : 명령의 출력을 값으로 쓰는 것과, 산술식을 계산해 결과를 쓰는 것.

## 📝 연습 문제

**문제 1.** 포그라운드에서 실행 중인 작업을 일시 중지(suspend)시키는 키 조합은?

A) Ctrl-C
B) Ctrl-Z
C) Ctrl-D
D) Ctrl-\

**정답: B**
해설: `Ctrl-Z`는 실행 중인 포그라운드 작업에 SIGSTOP을 보내 일시 중지(stopped) 상태로 만든다. 이후 `bg`로 백그라운드에서 재개하거나 `fg`로 다시 포그라운드로 가져올 수 있다. `Ctrl-C`는 SIGINT로 작업을 종료하고, `Ctrl-D`는 EOF(입력 끝)를 보내며, `Ctrl-\`는 SIGQUIT로 종료하면서 코어 덤프를 남긴다. 멈춤(suspend)과 종료(terminate)를 구분하는 것이 핵심이다.

**문제 2.** 터미널을 닫아도 백그라운드 작업이 종료되지 않도록 SIGHUP을 무시하고 실행하는 명령은?

A) `nohup ./job.sh &`
B) `bg ./job.sh`
C) `disown ./job.sh`
D) `fg ./job.sh &`

**정답: A**
해설: `nohup`(no hangup)은 명령을 SIGHUP 신호에 면역시켜 실행하므로, 터미널이 닫혀도 작업이 살아남는다. 백그라운드 실행을 위해 끝에 `&`도 함께 붙인다. `bg`와 `fg`는 이미 존재하는 작업의 상태를 전환하는 명령이지 새 명령을 실행하지 않는다. `disown`은 이미 실행 중인 작업을 분리할 때 쓰며 명령 인자가 아니라 작업 번호(%n)를 받는다.

**문제 3.** `alias rm='rm -i'`가 설정된 상태에서 확인 없이 원래 rm을 실행하는 방법으로 옳지 않은 것은?

A) `\rm file`
B) `command rm file`
C) `/bin/rm file`
D) `alias rm file`

**정답: D**
해설: `alias rm file`은 별칭을 우회하는 명령이 아니라 alias 등록 문법을 잘못 쓴 것으로, 의도한 삭제가 일어나지 않는다. 별칭을 우회하려면 명령 앞에 백슬래시를 붙이거나(`\rm`), `command` 빌트인을 쓰거나(`command rm`), 절대 경로(`/bin/rm`)로 직접 호출하면 된다. 이 세 가지는 모두 별칭 확장을 건너뛰고 원본 명령을 실행하는 표준 방법이다.

**문제 4.** 바로 직전에 실행한 명령의 **마지막 인자**를 재사용하는 히스토리 표기는?

A) `!!`
B) `!$`
C) `!^`
D) `!*`

**정답: B**
해설: `!$`는 직전 명령의 마지막 인자를 가리킨다. 예를 들어 `mkdir /opt/app` 다음에 `cd !$`를 치면 `cd /opt/app`이 실행된다. `!!`는 직전 명령 전체를 재실행하고, `!^`는 직전 명령의 첫 번째 인자, `!*`는 직전 명령의 모든 인자를 가리킨다. `!$`는 긴 경로를 다시 타이핑하지 않게 해주는 실무에서 매우 자주 쓰이는 표기다.

**문제 5.** 다음 중 명령 치환(command substitution)에 해당하는 것은?

A) `echo $((3 + 4))`
B) `echo $(date)`
C) `echo ${NAME}`
D) `echo $[3 + 4]`

**정답: B**
해설: `$(date)`는 date 명령을 실행해 그 출력으로 치환하는 명령 치환이다. `$(( ))`(괄호 두 개)는 산술 확장으로 수식을 계산하고, `${NAME}`은 변수 확장이며, `$[ ]`는 산술 확장의 옛 표기(deprecated)다. 명령 치환은 명령의 stdout을 값으로 가져오며, 역따옴표 `` `date` ``와 동일한 역할을 한다. 괄호 한 개(`$()`)는 명령, 두 개(`$(())`)는 산술이라는 구분이 핵심이다.

**문제 6.** `jobs` 명령 출력에서 작업 번호 뒤의 `+` 기호가 의미하는 것은?

A) 백그라운드에서 실행 중인 작업
B) 일시 중지된 작업
C) 현재 작업(인자 없는 fg/bg의 대상)
D) 가장 먼저 시작된 작업

**정답: C**
해설: `jobs` 출력에서 `+`는 **현재 작업(current job)**을 표시하며, `fg`나 `bg`를 작업 번호 없이 실행했을 때 대상이 되는 작업이다. `-`는 직전 작업(previous job)을 나타낸다. 실행 상태(Running/Stopped)는 `+`/`-`가 아니라 별도의 상태 텍스트로 표시된다. 작업 시작 순서와도 무관하다. 이 기호는 인자 없는 작업 제어 명령의 기본 대상을 결정한다.

**문제 7.** 명령행에서 등록한 alias를 로그아웃 후에도 계속 사용하려면 어떻게 해야 하는가?

A) `alias -p`로 저장한다
B) `~/.bashrc`에 alias 정의를 추가한다
C) `/etc/passwd`에 등록한다
D) `export`로 alias를 환경 변수화한다

**정답: B**
해설: 명령행에서 직접 등록한 별칭은 현재 셸에서만 유효하고 로그아웃하면 사라진다. 영구적으로 쓰려면 `~/.bashrc`에 alias 정의를 적어 둬야 한다. .bashrc는 새 셸을 띄울 때마다 읽히므로 매번 별칭이 자동 등록된다. `alias -p`는 등록된 별칭을 출력만 할 뿐 저장하지 않고, `/etc/passwd`는 계정 정보 파일이라 무관하며, alias는 변수가 아니므로 export로 상속시킬 수 없다.
