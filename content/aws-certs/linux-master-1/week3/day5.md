# Day 5 - Week 3 종합 복습: 셸과 스크립트의 큰 그림

## 📌 핵심 정리

- 이번 주는 하나의 질문으로 수렴한다 — "손으로 하던 일을 어떻게 셸에게 반복 가능하게 맡기는가".
- 셸 계열은 **본(sh·ksh·bash·zsh)**과 **C(csh·tcsh)**. 표준은 bash, alias·history 도입은 csh.
- 변수는 `export` 여부로 갈리고, 설정 파일은 로그인 셸(`~/.bash_profile`)과 대화형 셸(`~/.bashrc`)이 다르다.
- FD 0·1·2와 `2>&1`의 순서, 글로빙 `*`와 정규식 `*`의 차이, 따옴표 3종이 Day 2의 핵심.
- 스크립트는 shebang → 위치 매개변수 → `[ ]` 조건(문자열 `=`, 숫자 `-eq`, 공백 필수) → if/case/for/while → 함수 순으로 쌓인다.

## Day 1 복습: 셸과 변수, 초기화 파일

- 셸은 커널과 사용자 사이의 명령 해석기다.
- 종류는 본 계열(`sh` → `ksh` → `bash` → `zsh`)과 C 계열(`csh` → `tcsh`)로 나뉘고, **bash가 리눅스 표준 로그인 셸**이다.
- alias와 history를 처음 도입한 건 csh다.
- **셸 변수**는 현재 셸에서만 유효하고 자식에게 상속되지 않으며, `export`로 표시한 **환경 변수**는 자식 프로세스에게 상속된다. 상속은 부모→자식 한 방향뿐이다.

| 명령 | 보여주는 범위 |
|------|--------------|
| `set` | 셸 변수 + 환경 변수 + 함수 (가장 넓음) |
| `env` | 환경 변수만 |
| `export -p` | export된 변수만 |

초기화 파일 읽기 순서는 셸의 종류에 따라 다르다.

- **로그인 셸**: `/etc/profile` → (`~/.bash_profile` → `~/.bash_login` → `~/.profile` 중 첫 번째 하나) → 로그아웃 시 `~/.bash_logout`
- **비로그인 대화형 셸**: `/etc/bashrc` → `~/.bashrc`
- 변경을 즉시 반영하려면 `source` 또는 `.`(점)을 쓴다. `bash file`은 새 자식 셸에서만 적용되므로 효과가 없다.

> 💡 **개념**: 핵심 한 줄 요약 — **`.bash_profile`은 로그인 시 한 번, `.bashrc`는 셸 띄울 때마다.** 그래서 alias·함수는 `.bashrc`에, 환경 변수는 `.bash_profile`에 두는 것이 관례다.

## Day 2 복습: 리다이렉션, 파이프, 메타문자

모든 프로세스는 세 개의 표준 통로를 갖는다 — **stdin(0), stdout(1), stderr(2)**. 리다이렉션은 이 FD의 연결 대상을 바꾼다.

| 기호 | 의미 |
|------|------|
| `>` / `>>` | stdout 덮어쓰기 / 이어쓰기 |
| `2>` | stderr만 리다이렉션 |
| `&>` 또는 `> f 2>&1` | stdout+stderr 함께 |
| `<` | 입력 받기 |
| `<<` / `<<<` | 히어 도큐먼트 / 히어 스트링 |

- `2>&1`의 **순서**가 결과를 가른다. 반드시 `> file 2>&1`(1을 먼저 파일로 돌린 뒤 2를 합침)이어야 둘 다 파일로 간다.
- **파이프(`|`)**는 앞 명령의 stdout을 뒤 명령의 stdin으로 잇는다(stderr는 기본적으로 안 넘어감).
- 필터(grep, sort, uniq, wc, cut, tee 등)를 조합해 복합 작업을 한 줄로 만든다.
- **와일드카드(글로빙)**는 셸이 명령 실행 전에 파일 이름으로 확장한다: `*`(0개 이상), `?`(정확히 1개), `[ ]`(괄호 중 하나). 정규표현식의 `*`(앞 문자 반복)와 의미가 다르다.

**따옴표**의 동작 차이는 단골 출제다.

| 따옴표 | 변수 확장 | 명령 치환 | 와일드카드 |
|--------|:---:|:---:|:---:|
| `' '` 작은 | ❌ | ❌ | ❌ |
| `" "` 큰 | ✅ | ✅ | ❌ |

> ⚠️ **함정**: `sort file > file`은 `>`가 명령 실행 전에 파일을 비우므로 내용이 사라진다. 같은 파일에 쓰려면 도구의 `-o` 옵션이나 임시 파일을 거쳐야 한다.

## Day 3 복습: 별칭, 히스토리, 작업 제어

- **alias**는 긴 명령에 별명을 붙이며, 영구 적용하려면 `~/.bashrc`에 둔다. 임시 우회는 `\명령`, `command 명령`, 절대 경로.
- **history**는 `!!`(직전 전체), `!n`(n번), `!$`(직전 마지막 인자)로 재활용한다. `HISTSIZE`(메모리 개수), `HISTCONTROL`(중복·공백 제어)로 동작을 조절한다.
- **작업 제어**가 이번 주에서 가장 실무적이다.

| 조작 | 동작 |
|------|------|
| `cmd &` | 처음부터 백그라운드 실행 |
| `Ctrl-Z` | 포그라운드 작업 일시 중지(suspend) |
| `Ctrl-C` | 작업 종료(terminate) |
| `jobs` | 작업 목록 |
| `bg %n` / `fg %n` | 백그라운드 재개 / 포그라운드 복귀 |
| `nohup cmd &` | SIGHUP 무시(터미널 닫아도 생존) + 백그라운드 |
| `disown %n` | 실행 중 작업을 셸에서 분리 |

> 💡 **개념**: 터미널이 닫히면 그 안의 작업에 **SIGHUP**이 전달되어 죽는다. `nohup`은 이 신호를 무시하게 하지만, 백그라운드 실행은 어디까지나 `&`가 담당하므로 **둘을 함께** 써야 한다.

## Day 4 복습: 셸 스크립트 기초

- 스크립트 첫 줄의 **shebang**(`#!/bin/bash`)이 인터프리터를 지정한다. `./script.sh`는 자식 셸에서, `source script.sh`는 현재 셸에서 실행된다.
- **위치 매개변수**: `$0`(이름), `$1~$9`(인자), `$#`(개수), `$@`(분리된 전체), `$?`(종료 코드, 0=성공), `$$`(PID).
- **조건 판단(test/[ ])**: 문자열은 `=`·`!=`·`-z`·`-n`, 숫자는 `-eq`·`-ne`·`-gt`·`-lt`, 파일은 `-f`·`-d`·`-e`. 대괄호 안과 연산자 양옆에 **공백 필수**.
- **제어 구조**: `if-elif-else-fi`, `case-esac`(패턴은 `;;`로 끝, `*)`가 기본), `for-do-done`, `while-do-done`, `until`. `break`·`continue`로 반복 제어.
- **함수**: `return`은 0~255 종료 코드만, 데이터는 `echo`+`$(함수)`로 전달. 함수 내부 변수는 `local`로 지역화.

> 🔍 **더 깊이**: if는 `[ ]`뿐 아니라 임의의 명령을 조건으로 받아 그 종료 코드로 분기한다. `if grep -q root /etc/passwd; then ...`처럼. `[ ]`는 그 자체가 `test`라는 명령이기 때문에 if의 조건이 될 수 있다.

## 통합 시나리오: 배운 것이 한 줄로 만나는 곳

이번 주 개념들이 실제 스크립트에서 어떻게 함께 쓰이는지 보자.

```bash
#!/bin/bash
# 로그 디렉터리에서 오늘 .log 파일을 압축하고 결과를 기록

LOG_DIR="/var/log/myapp"
DATE=$(date +%Y%m%d)              # 명령 치환 (Day3)
REPORT="/tmp/compress_$DATE.txt"

if [ ! -d "$LOG_DIR" ]; then      # 파일 검사 + 조건문 (Day4)
    echo "디렉터리 없음: $LOG_DIR" >&2   # stderr 리다이렉션 (Day2)
    exit 1
fi

count=0
for file in "$LOG_DIR"/*.log; do  # 와일드카드 + for (Day2,4)
    [ -f "$file" ] || continue    # 매칭 없을 때 건너뜀
    gzip "$file" 2>> "$REPORT"    # 에러만 이어쓰기 (Day2)
    count=$((count + 1))          # 산술 확장 (Day3)
done

echo "압축 완료: $count개" | tee -a "$REPORT"   # 파이프+tee (Day2)
```

- 이 짧은 스크립트 안에 명령 치환, 조건문, 파일 검사, 리다이렉션, 와일드카드, 반복문, 산술 확장, 파이프, tee가 모두 들어 있다.
- 이번 주에 배운 것이 따로 노는 지식이 아니라 하나의 작업을 자동화하기 위해 맞물리는 부품임을 보여준다.

> 📚 **유래/사례**: 이런 "로그 압축·정리" 스크립트는 실제로 `logrotate`라는 표준 도구가 대신해 준다. 하지만 logrotate 내부 동작과 커스텀 정리 로직은 결국 이런 셸 스크립트의 원리 위에 서 있다. 기본기를 알면 표준 도구가 무엇을 하는지도 이해된다.

## 시험 직전 최종 점검 리스트

- 셸 계열 분류: ksh는 **본 계열**(이름에 속지 말 것), csh가 alias·history 도입
- `$SHELL`은 로그인 기본 셸, **현재 셸은 `echo $0`**
- 셸 변수↔환경 변수 차이는 **export 여부**, 상속은 부모→자식 단방향
- 로그인 셸: `/etc/profile` → `~/.bash_profile`, 대화형: `~/.bashrc`
- FD: stdin 0, stdout 1, stderr 2 / `2>&1`은 **순서**가 중요
- 글로빙 `*`≠정규표현식 `*`
- 작은따옴표=전부 차단, 큰따옴표=변수만 확장
- `Ctrl-Z`=멈춤, `Ctrl-C`=종료 / nohup+`&` 함께
- test: 문자열 `=`, 숫자 `-eq`, **공백 필수**
- `$?`=종료 코드(0=성공), 함수 return은 종료 코드만

## 📖 용어

- **본 계열 / C 계열** : `sh`에서 이어진 bash·ksh·zsh 무리와, `csh`에서 갈라진 tcsh 무리.
- **셸 변수 vs 환경 변수** : `export` 하지 않아 자식에게 안 넘어가는 변수와, 넘어가는 변수.
- **`~/.bash_profile` vs `~/.bashrc`** : 로그인할 때 한 번 읽히는 파일과, 셸을 새로 띄울 때마다 읽히는 파일.
- **`source`(`.`)** : 파일을 현재 셸 안에서 읽어 설정을 즉시 반영하는 명령.
- **FD 0/1/2** : 표준 입력·표준 출력·표준 에러의 번호. 리다이렉션은 이 번호의 연결 대상을 바꾼다.
- **`2>&1`** : 에러를 출력 쪽으로 합치는 표기. `> 파일` 뒤에 써야 둘 다 파일로 간다.
- **글로빙** : 셸이 `*`·`?`·`[]`를 실제 파일명으로 미리 바꾸는 확장. 정규식과 의미가 다르다.
- **SIGHUP** : 터미널이 닫힐 때 그 안의 작업에 전달되는 신호. `nohup`으로 무시시킨다.
- **작업 번호(`%n`)** : 현재 셸 안에서만 통하는 작업 식별 번호. `fg %1`처럼 쓴다.
- **shebang** : 스크립트를 어떤 인터프리터로 실행할지 지정하는 첫 줄.
- **`$?`** : 직전 명령의 종료 코드. 0이 성공이고 조건문이 이 값을 보고 분기한다.
- **`test`/`[ ]`** : 조건을 판단해 종료 코드로 답하는 명령. 문자열은 `=`, 숫자는 `-eq`, 공백 필수.
- **`local`** : 함수 안에서만 살아 있는 지역 변수를 선언하는 키워드.

## 📝 연습 문제

**문제 1.** 다음 셸 중 본(Bourne) 셸 계열이 **아닌** 것은?

A) bash
B) ksh
C) zsh
D) tcsh

**정답: D**
해설: tcsh는 csh(C 셸)의 개선판으로 **C 셸 계열**이다. bash, ksh, zsh는 모두 본 셸 문법을 따르는 본 계열이다. 특히 ksh는 이름의 'k' 때문에 C 계열로 오해하기 쉽지만, 데이비드 콘이 본 셸 호환으로 만든 본 계열 셸이다. C 셸 계열은 csh와 tcsh 둘뿐이며, C 언어와 유사한 문법을 쓰고 history·alias를 처음 도입했다는 특징이 있다.

**문제 2.** 현재 실행 중인 셸의 이름을 확인하는 가장 정확한 방법은?

A) `echo $SHELL`
B) `echo $0`
C) `echo $HOME`
D) `echo $PATH`

**정답: B**
해설: `echo $0`은 현재 실행 중인 셸의 이름을 보여준다. `$SHELL`은 로그인 시 지정된 기본 셸 경로일 뿐, bash로 로그인한 뒤 zsh를 직접 실행해도 여전히 `/bin/bash`를 가리킨다. `$HOME`은 홈 디렉터리, `$PATH`는 명령 검색 경로다. "현재 실행 중인 셸"을 묻는 문제에서 `$SHELL`을 고르면 함정에 빠진다. `ps -p $$`로도 확인할 수 있다.

**문제 3.** `command > out.txt 2>&1` 과 `command 2>&1 > out.txt` 의 차이로 옳은 것은?

A) 두 명령은 완전히 동일하게 동작한다
B) 전자는 둘 다 파일로, 후자는 stdout만 파일로 가고 stderr는 화면에 남는다
C) 전자는 stderr만, 후자는 stdout만 파일로 간다
D) 후자가 더 표준적인 표기다

**정답: B**
해설: 셸은 리다이렉션을 왼쪽부터 처리한다. 전자는 `> out.txt`로 stdout(1)을 먼저 파일로 돌린 뒤 `2>&1`이 stderr를 그 파일로 합쳐 둘 다 파일로 간다. 후자는 `2>&1`이 먼저 "현재 1번(화면)"에 stderr를 합친 뒤 `> out.txt`가 stdout만 파일로 바꾸므로, stderr는 화면에 남는다. 따라서 둘은 동일하지 않으며, 올바른 표기는 전자다.

**문제 4.** 와일드카드(글로빙)에 대한 설명으로 옳은 것은?

A) 파일 이름 확장은 각 명령(ls, cp 등)이 직접 수행한다
B) 글로빙의 `*`는 정규표현식의 `*`와 동일한 의미다
C) 셸이 명령 실행 전에 `*.txt`를 실제 파일 이름으로 확장한다
D) `?`는 0개 이상의 임의 문자를 의미한다

**정답: C**
해설: 와일드카드 확장(글로빙)은 명령이 아니라 **셸**이 명령 실행 전에 수행한다. `ls *.txt`를 입력하면 셸이 먼저 `*.txt`를 실제 파일 목록으로 바꾼 뒤 ls에게 인자로 넘긴다. 글로빙의 `*`(0개 이상 임의 문자)는 정규표현식의 `*`(앞 문자 0회 이상 반복)와 의미가 전혀 다르다. `?`는 0개 이상이 아니라 **정확히 1개**의 임의 문자를 뜻한다.

**문제 5.** 다음 중 변수가 확장되어 출력되는 것은? (`NAME=linux`인 상태)

A) `echo '$NAME'`
B) `echo "$NAME"`
C) `echo \$NAME`
D) `echo '${NAME}'`

**정답: B**
해설: 큰따옴표는 변수 확장을 허용하므로 `"$NAME"`은 `linux`로 출력된다. 작은따옴표(A, D)는 모든 확장을 막아 `$NAME`, `${NAME}`이 글자 그대로 출력되고, 백슬래시(C)는 바로 뒤 `$`의 특수 의미를 제거해 `$NAME`이 그대로 나온다. 큰따옴표는 변수와 명령 치환은 허용하되 와일드카드만 막는 "약한 인용"이라는 점이 핵심이다.

**문제 6.** `Ctrl-Z`로 일시 중지한 작업을 백그라운드에서 다시 실행시키는 명령은?

A) `fg`
B) `bg`
C) `jobs`
D) `kill -CONT`

**정답: B**
해설: `Ctrl-Z`로 멈춘(stopped) 작업을 `bg %n`으로 백그라운드에서 재개할 수 있다. `fg`는 포그라운드로 가져오는 명령이고, `jobs`는 작업 목록을 보여줄 뿐 상태를 바꾸지 않는다. `kill -CONT`도 중지된 프로세스를 재개하긴 하지만 작업 제어의 표준 방법은 `bg`다. 멈춤→백그라운드 재개의 흐름은 `Ctrl-Z` → `bg %n`이 정석이다.

**문제 7.** 터미널을 닫아도 작업이 종료되지 않게 하려고 한다. 가장 적절한 실행 명령은?

A) `./long.sh`
B) `./long.sh &`
C) `nohup ./long.sh &`
D) `nohup ./long.sh`

**정답: C**
해설: 터미널이 닫히면 SIGHUP 신호가 전달되어 작업이 죽는다. `nohup`이 이 신호를 무시하게 하고, `&`가 백그라운드 실행을 담당하므로 **둘을 함께** 써야 "터미널 닫아도 백그라운드에서 생존"이 완성된다. B는 SIGHUP에 여전히 취약하고, D는 `&`가 없어 포그라운드로 실행되어 셸이 묶인다. A는 두 보호 장치가 모두 없다.

**문제 8.** test 명령에서 `/etc/passwd`가 **디렉터리인지** 검사하는 연산자는?

A) `-f`
B) `-d`
C) `-e`
D) `-s`

**정답: B**
해설: `-d`는 대상이 디렉터리일 때 참이 된다. `-f`는 일반 파일, `-e`는 존재 여부(파일·디렉터리 무관), `-s`는 크기가 0보다 큰지(비어있지 않은지)를 검사한다. `/etc/passwd`는 일반 파일이므로 `-d` 검사는 거짓이 된다. 파일 종류를 구분하는 연산자(`-f` 일반 파일, `-d` 디렉터리, `-L` 심볼릭 링크)를 정확히 구별해야 한다.

**문제 9.** `$?` 변수에 대한 설명으로 옳은 것은?

A) 현재 셸의 PID를 담는다
B) 직전 명령의 종료 상태를 담으며 0이 성공이다
C) 마지막 백그라운드 작업의 PID를 담는다
D) 전달된 인자의 개수를 담는다

**정답: B**
해설: `$?`는 직전에 실행된 명령의 종료 상태(exit status)를 담으며, **0이 성공**, 0이 아닌 값이 실패를 의미한다. 조건문은 이 값을 보고 분기한다. 현재 셸의 PID는 `$$`, 마지막 백그라운드 작업의 PID는 `$!`, 인자 개수는 `$#`다. 비슷하게 생긴 특수 변수들을 혼동하지 않도록 각각의 의미를 정확히 구분해야 한다.

**문제 10.** 셸 변수를 자식 프로세스에게 상속시키는 명령과, 변경한 `.bashrc`를 현재 셸에 즉시 반영하는 명령을 올바르게 짝지은 것은?

A) `set` / `bash ~/.bashrc`
B) `export` / `source ~/.bashrc`
C) `env` / `exec ~/.bashrc`
D) `declare` / `run ~/.bashrc`

**정답: B**
해설: 셸 변수를 환경 변수로 승격해 자식에게 상속시키는 명령은 `export`이고, 수정한 `.bashrc`를 현재 셸 프로세스 안에서 즉시 다시 읽는 명령은 `source`(또는 `.`)다. `set`은 변수 출력·옵션 제어용, `env`는 환경 변수 출력·임시 실행용이며, `bash ~/.bashrc`는 새 자식 셸에서만 적용되어 현재 셸에는 효과가 없다. `exec`는 프로세스 교체, `run`은 존재하지 않는 명령이다.

**문제 11.** case 문에서 여러 패턴을 하나의 블록으로 처리하고, 각 블록을 종료하는 기호를 올바르게 짝지은 것은?

A) 패턴 구분 `,` / 블록 종료 `;`
B) 패턴 구분 `|` / 블록 종료 `;;`
C) 패턴 구분 `||` / 블록 종료 `break`
D) 패턴 구분 `;` / 블록 종료 `fi`

**정답: B**
해설: case 문에서 여러 패턴을 한 블록으로 묶을 때는 `|`로 구분하고(`restart|reload)`), 각 패턴 블록은 `;;`로 종료한다. case 전체는 `esac`로 닫는다. if 문이 `fi`로 닫히는 것과 구별해야 한다. `,`나 `||`는 case 패턴 구분에 쓰이지 않고, `break`는 반복문 탈출용이며 case 블록 종료와는 무관하다. 패턴 `|`, 블록 `;;`, 전체 `esac`가 case의 3대 문법 요소다.

**문제 12.** 다음 스크립트의 실행 결과로 옳은 것은?

```bash
#!/bin/bash
count=0
for f in a b c; do
    count=$((count + 1))
done
echo $count
```

A) 0
B) 3
C) a b c
D) 문법 오류

**정답: B**
해설: for 루프가 목록 `a b c`를 세 번 순회하며 매번 `count=$((count + 1))`로 count를 1씩 증가시킨다. `$(( ))`는 산술 확장으로 수식을 계산하므로 count는 0→1→2→3이 되고, 최종적으로 `echo $count`가 3을 출력한다. 변수 f가 아니라 count를 출력하므로 "a b c"가 아니다. 문법도 올바르므로 오류가 아니다. for 순회 횟수와 산술 확장을 함께 이해해야 풀 수 있는 문제다.
