# Day 1 - 셸의 정체: 명령을 해석하는 프로그램과 변수의 세계

1971년 켄 톰슨(Ken Thompson)이 만든 첫 유닉스 셸(Thompson shell)부터, 1977년 스티븐 본(Stephen Bourne)이 만든 본 셸(Bourne shell, `sh`), 그리고 1989년 브라이언 폭스(Brian Fox)가 GNU 프로젝트를 위해 만든 Bash(Bourne-Again SHell)까지 — 셸은 유닉스/리눅스를 쓰는 사람이 가장 먼저, 그리고 가장 자주 마주치는 프로그램이다. 우리가 터미널에 `ls`라고 입력하면 그 글자를 받아 해석하고, `/bin/ls`라는 실행 파일을 찾아 프로세스로 띄우고, 결과를 화면에 돌려주는 모든 과정을 셸이 책임진다.

리눅스마스터 1급에서 셸은 단순한 "명령 입력기"가 아니라 **하나의 인터프리터 언어이자 사용자 환경**으로 다뤄진다. 셸의 종류와 특징, 그리고 변수(환경 변수와 셸 변수)의 동작 원리, 셸 초기화 파일의 읽기 순서까지를 정확히 알아야 한다. 오늘은 그 토대를 깊이 있게 다진다.

## 셸이란 무엇인가: 커널과 사용자 사이의 통역사

리눅스 시스템은 크게 **커널(kernel)**과 **셸(shell)**로 나뉜다. 커널은 하드웨어를 직접 제어하는 핵심이고, 셸은 사용자가 입력한 명령을 커널이 이해할 수 있는 형태로 전달하는 **명령어 해석기(command interpreter)**다. 셸이라는 이름 자체가 "껍데기"라는 뜻인데, 커널을 둘러싸 사용자와 맞닿는 가장 바깥층이기 때문이다.

셸이 명령 한 줄을 처리하는 과정은 대략 이렇다.

```text
1. 프롬프트 출력 → 사용자 입력 대기
2. 입력 라인 읽기 (read)
3. 토큰 분리 + 메타문자/와일드카드 확장 (parsing & expansion)
4. 변수 치환, 명령 치환 수행
5. 빌트인 명령인지 외부 명령인지 판별
6. 외부 명령이면 PATH에서 실행 파일 검색
7. fork() → exec()로 자식 프로세스 생성·실행
8. wait()로 종료 대기 후 종료 코드 회수
9. 다시 프롬프트 출력
```

이 한 사이클(REPL: Read-Eval-Print Loop)을 셸은 로그아웃할 때까지 반복한다.

> 💡 **개념**: 셸은 "대화형 셸(interactive shell)"과 "비대화형 셸(non-interactive shell)"로 나뉜다. 터미널에서 직접 타이핑하면 대화형, 스크립트 파일을 실행하면 비대화형이다. 둘은 읽는 초기화 파일이 다르다 — 이 차이가 오늘 마지막 주제의 핵심이다.

## 셸의 종류와 특징: sh, csh, ksh, bash, zsh

리눅스/유닉스에는 여러 셸이 있고, 시험에서는 각 셸의 **개발자·계열·특징**을 묻는다. 크게 **본 셸 계열(sh → ksh → bash)**과 **C 셸 계열(csh → tcsh)**로 나뉜다.

| 셸 | 이름 | 개발자 | 연도 | 계열 | 특징 |
|----|------|--------|------|------|------|
| `sh` | Bourne Shell | 스티븐 본 | 1977 | 본 계열 | 최초의 표준 셸, 스크립트의 기준 |
| `csh` | C Shell | 빌 조이 | 1978 | C 계열 | C 언어 문법 차용, history·alias 도입 |
| `tcsh` | TENEX C Shell | - | 1983 | C 계열 | csh 개선판, 명령 완성 기능 |
| `ksh` | Korn Shell | 데이비드 콘 | 1983 | 본 계열 | sh 호환 + csh 기능 통합, 연산 기능 |
| `bash` | Bourne-Again Shell | 브라이언 폭스 | 1989 | 본 계열 | GNU 기본 셸, 리눅스 표준 |
| `zsh` | Z Shell | 폴 포크스타드 | 1990 | 본 계열 | 강력한 자동완성·플러그인, macOS 기본 |
| `dash` | Debian Almquist | - | 2002 | 본 계열 | 가볍고 빠른 POSIX sh, 데비안 `/bin/sh` |

핵심 포인트를 정리하면:

- **bash**는 대부분의 리눅스 배포판의 **기본 로그인 셸**이다. 본 셸과 호환되면서 C 셸의 편의 기능(history, alias, job control)을 흡수했다.
- **csh/tcsh**는 C 언어와 유사한 문법을 쓰고, **command history**와 **alias**를 처음 도입한 셸로 자주 출제된다.
- **ksh**는 본 셸 호환성을 유지하면서 **명령행 편집과 산술 연산**을 강화했다.
- **zsh**는 2019년부터 macOS Catalina의 기본 셸이 되어 인지도가 높아졌다.

> 📚 **유래/사례**: Bash의 이름 "Bourne-Again"은 본 셸(Bourne)을 "다시 태어나게 했다(born again)"는 언어유희다. 동시에 종교적 표현 "거듭난(born-again)"과도 발음이 같아, GNU 특유의 위트가 담겨 있다.

### 사용 가능한 셸 확인하기

시스템에 설치된 셸 목록은 `/etc/shells` 파일에, 각 사용자의 기본 로그인 셸은 `/etc/passwd`의 마지막 필드에 기록된다.

```bash
cat /etc/shells          # 설치된 셸 목록
echo $SHELL              # 현재 로그인 셸 경로
echo $0                  # 현재 실행 중인 셸 이름
grep "^$(whoami):" /etc/passwd   # 내 계정의 로그인 셸 확인
chsh -s /bin/zsh         # 기본 로그인 셸을 zsh로 변경 (change shell)
```

> ⚠️ **함정**: `$SHELL`은 "로그인 시 지정된 기본 셸"을 가리키지, "지금 실행 중인 셸"이 아니다. bash로 로그인한 뒤 `zsh`를 직접 실행해도 `$SHELL`은 여전히 `/bin/bash`를 보여준다. 현재 실행 중인 셸은 `echo $0` 또는 `ps -p $$`로 확인해야 한다.

## 셸 변수 vs 환경 변수: 스코프가 모든 것을 결정한다

변수는 셸에서 가장 중요한 개념 중 하나다. 리눅스 변수는 크게 두 종류로 나뉜다.

- **셸 변수(local variable / shell variable)**: 현재 셸 안에서만 유효하다. 자식 프로세스에게 **상속되지 않는다**.
- **환경 변수(environment variable)**: `export`로 표시(mark)되어 **자식 프로세스에게 상속된다**.

```bash
# 셸 변수 선언 — 현재 셸에서만 유효
NAME="linux"
echo $NAME            # linux

# 환경 변수로 승격 — 자식에게 상속됨
export NAME

# 또는 한 줄로 선언과 동시에 export
export PROJECT="cert"
```

이 차이를 직접 확인하는 것이 이해의 핵심이다.

```bash
# 직접 쳐보기: 셸 변수는 자식에게 상속되지 않는다
LOCAL_VAR="only-here"
export GLOBAL_VAR="passed-down"

bash                  # 자식 셸 진입
echo "$LOCAL_VAR"     # (빈 줄) — 상속 안 됨
echo "$GLOBAL_VAR"    # passed-down — 상속됨
exit                  # 부모 셸로 복귀
```

> 💡 **개념**: 변수의 상속은 부모 → 자식 **한 방향**으로만 일어난다. 자식 셸에서 환경 변수를 바꿔도 부모 셸에는 절대 반영되지 않는다. 자식은 부모 환경의 "복사본"을 받아 시작하기 때문이다. 그래서 스크립트 안에서 `export`로 바꾼 변수가 스크립트를 호출한 부모 셸에 남지 않는다.

### set, env, export — 변수를 다루는 세 명령

세 명령이 자주 혼동되므로 정확히 구분해야 한다.

| 명령 | 보여주는 것 | 용도 |
|------|------------|------|
| `set` | **셸 변수 + 환경 변수 + 함수** 전체 | 현재 셸의 모든 변수 출력 |
| `env` | **환경 변수만** | 환경 변수 출력, 임시 환경으로 명령 실행 |
| `export` | export된 변수(환경 변수)만 (`export -p`) | 셸 변수를 환경 변수로 승격 |
| `unset` | - | 변수 또는 함수 삭제 |

```bash
set | head             # 모든 변수(셸+환경+함수) — 가장 많이 나옴
env                    # 환경 변수만
export -p              # export된 변수 목록
unset NAME             # 변수 삭제
declare -p NAME        # 변수 속성과 값 확인 (bash 빌트인)
```

`env`는 출력만이 아니라 **임시로 환경을 바꿔 명령을 실행**하는 데도 쓴다.

```bash
# LANG을 영어로 임시 설정해 date 실행 (현재 셸 환경은 그대로)
env LANG=C date

# 환경 변수를 모두 비우고 깨끗한 환경에서 실행
env -i bash
```

> 🔍 **더 깊이**: `set`은 변수 출력 외에 **셸 옵션**을 켜고 끄는 데도 쓰인다. `set -x`는 실행되는 명령을 추적 출력(디버깅), `set -e`는 에러 발생 시 즉시 중단, `set -u`는 미정의 변수 사용 시 에러를 낸다. 스크립트 상단의 `set -euo pipefail`이 바로 이 옵션 조합으로, 안전한 스크립트의 관용구다.

### 주요 환경 변수

시험에 자주 나오는 환경 변수들을 정리한다.

| 변수 | 의미 |
|------|------|
| `PATH` | 명령 실행 파일을 검색할 디렉터리 목록(`:`로 구분) |
| `HOME` | 사용자 홈 디렉터리 |
| `PWD` | 현재 작업 디렉터리 |
| `SHELL` | 로그인 기본 셸 경로 |
| `USER` / `LOGNAME` | 로그인 사용자 이름 |
| `LANG` | 언어·로케일 설정 |
| `PS1` | 기본 프롬프트 문자열 |
| `TERM` | 터미널 종류 |
| `HISTSIZE` | 메모리에 저장할 history 개수 |
| `MAIL` | 메일함 경로 |

```bash
echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin

# PATH에 디렉터리 추가 (앞에 붙이면 우선 검색됨)
export PATH=/opt/myapp/bin:$PATH
```

> ⚠️ **함정**: `PATH`를 설정할 때 기존 값을 덮어쓰지 말아야 한다. `export PATH=/opt/bin`처럼 쓰면 `ls`, `cat` 같은 기본 명령조차 찾지 못하게 된다. 반드시 `export PATH=/opt/bin:$PATH`처럼 **기존 $PATH를 포함**시켜야 한다. 또한 PATH는 **앞에서부터** 검색하므로, 같은 이름의 명령이 여러 곳에 있으면 먼저 나오는 디렉터리의 것이 실행된다.

## 셸 초기화 파일: 누가, 언제, 어떤 순서로 읽히는가

bash가 시작될 때 어떤 설정 파일을 읽는지는 **(1) 로그인 셸인지 (2) 대화형인지**에 따라 달라진다. 이 부분이 1급 시험의 단골 출제 영역이다.

### 전역 설정 vs 사용자 설정

- **전역(시스템 전체)**: `/etc/profile`, `/etc/profile.d/*.sh`, `/etc/bashrc`(또는 `/etc/bash.bashrc`) — 모든 사용자에게 적용. 관리자(root)만 수정 가능.
- **사용자(개인)**: `~/.bash_profile`, `~/.bash_login`, `~/.profile`, `~/.bashrc`, `~/.bash_logout` — 각 사용자의 홈 디렉터리에 위치.

### 로그인 셸의 읽기 순서

로그인 셸(콘솔 로그인, SSH 접속 등)은 다음 순서로 읽는다.

```text
1. /etc/profile          (전역 — 모든 사용자)
     └─ /etc/profile.d/*.sh  (전역 설정 모음)
2. 사용자 홈에서 다음 중 "처음 발견되는 하나"만 실행:
     ~/.bash_profile  →  ~/.bash_login  →  ~/.profile
3. 로그아웃 시: ~/.bash_logout
```

핵심은 2단계에서 **세 파일을 다 읽는 게 아니라 처음 존재하는 하나만** 읽는다는 점이다. 그래서 대부분의 배포판은 `~/.bash_profile` 안에서 `~/.bashrc`를 명시적으로 불러오도록 작성해 둔다.

```bash
# ~/.bash_profile 의 전형적인 내용
if [ -f ~/.bashrc ]; then
    . ~/.bashrc          # .bashrc를 불러옴 ( . 은 source의 줄임)
fi
```

### 비로그인 대화형 셸의 읽기 순서

터미널 에뮬레이터에서 새 탭을 여는 것처럼 **로그인을 거치지 않는 대화형 셸**은 다음만 읽는다.

```text
1. /etc/bashrc  (또는 /etc/bash.bashrc, 전역)
2. ~/.bashrc    (사용자)
```

> 💡 **개념**: 정리하면 — **`.bash_profile`은 로그인할 때 한 번**, **`.bashrc`는 셸을 새로 띄울 때마다** 읽힌다. 그래서 alias나 함수처럼 "모든 셸에서 매번 필요한 설정"은 `.bashrc`에, 환경 변수처럼 "로그인 시 한 번 설정하면 자식에게 상속되는 설정"은 `.bash_profile`에 두는 것이 관례다.

| 파일 | 범위 | 실행 시점 |
|------|------|-----------|
| `/etc/profile` | 전역 | 로그인 셸 시작 시 (전체 사용자) |
| `/etc/bashrc` | 전역 | 대화형 셸 시작 시 (전체 사용자) |
| `~/.bash_profile` | 개인 | 로그인 셸 시작 시 |
| `~/.bashrc` | 개인 | 대화형 셸 시작 시 |
| `~/.bash_logout` | 개인 | 로그아웃 시 |
| `~/.profile` | 개인 | `.bash_profile` 없을 때 대체 (sh 호환) |

> 🔍 **더 깊이**: `~/.profile`은 본래 bash 전용이 아니라 **본 셸 호환 파일**이다. 데비안/우분투는 전통적으로 `~/.bash_profile` 대신 `~/.profile`을 기본 제공한다. bash는 `.bash_profile`을 먼저 찾고 없으면 `.bash_login`, 그것도 없으면 `.profile`을 읽으므로, 우분투에서는 `.profile`이 실질적인 로그인 스크립트가 된다.

### 설정 변경을 즉시 적용하기: source

설정 파일을 수정한 뒤 로그아웃·재로그인하지 않고 즉시 반영하려면 `source` 또는 `.`(점)을 쓴다.

```bash
source ~/.bashrc       # 현재 셸에 .bashrc 내용을 다시 읽어들임
. ~/.bashrc            # 위와 완전히 동일 ( . 은 source의 단축)
```

> ⚠️ **함정**: `bash ~/.bashrc`처럼 실행하면 안 된다. 이는 **새 자식 셸**을 띄워 그 안에서만 적용한 뒤 끝나버리므로 현재 셸에는 아무 변화가 없다. 반드시 `source`(또는 `.`)를 써서 **현재 셸 프로세스 안**에서 파일을 읽어야 변경이 유지된다. 이것이 바로 셸 변수 상속(부모↔자식)과 직결되는 개념이다.

> 📚 **유래/사례**: `source` 명령은 원래 C 셸에서 처음 등장했고, 본 셸 계열에서는 `.`(점) 하나로 같은 일을 했다. bash는 두 표기를 모두 지원한다. 시험에서 "`. file`과 같은 역할을 하는 명령은?"이라는 문제가 나오면 답은 `source`다.

## 마무리

오늘은 셸의 정체부터 변수의 스코프, 초기화 파일의 읽기 순서까지를 다뤘다. 기억할 핵심은 세 가지다. 첫째, 셸은 종류별로 계열(본 vs C)과 개발자·특징이 정해져 있고 bash가 리눅스 표준이다. 둘째, 변수는 `export` 여부로 셸 변수(상속 안 됨)와 환경 변수(자식에게 상속)로 갈리며, `set`/`env`/`export`가 각각 보여주는 범위가 다르다. 셋째, 초기화 파일은 로그인 셸이면 `/etc/profile → ~/.bash_profile`, 대화형 셸이면 `/etc/bashrc → ~/.bashrc`를 읽으며, 변경 즉시 반영은 `source`로 한다. 이 토대 위에서 내일은 리다이렉션과 파이프를 다룬다.

## 📝 연습 문제

**문제 1.** 다음 중 셸의 계열 분류가 잘못 짝지어진 것은?

A) bash — 본(Bourne) 계열
B) tcsh — C 셸 계열
C) ksh — C 셸 계열
D) zsh — 본(Bourne) 계열

**정답: C**
해설: ksh(Korn Shell)는 데이비드 콘이 본 셸(sh)과의 호환성을 유지하면서 만든 셸로 **본 계열**에 속한다. C 셸 계열은 csh와 그 개선판 tcsh다. bash와 zsh도 본 셸 문법을 따르는 본 계열이다. ksh를 C 셸 계열로 오인하기 쉬운데, 이름에 'k'가 들어가고 산술 연산 등 C 셸의 편의 기능을 흡수했기 때문이다. 그러나 문법 계보는 본 셸이다.

**문제 2.** 셸 변수 `VAR`를 자식 프로세스에게 상속되도록 환경 변수로 만드는 명령으로 옳은 것은?

A) `set VAR`
B) `export VAR`
C) `env VAR`
D) `declare VAR`

**정답: B**
해설: 셸 변수를 환경 변수로 승격(자식에게 상속)시키는 명령은 `export`다. `set`은 셸 옵션 제어와 전체 변수 출력에 쓰이고, `env`는 환경 변수 출력 또는 임시 환경 실행에 쓰이며 변수를 export하지는 않는다. `declare`는 변수 속성을 지정하는 빌트인이지만 자식 상속을 위해서는 `declare -x VAR`처럼 -x 옵션이 필요하다. 단독 `declare VAR`만으로는 export되지 않는다.

**문제 3.** 로그인 셸이 가장 먼저 읽는 전역 설정 파일은?

A) `~/.bashrc`
B) `/etc/bashrc`
C) `/etc/profile`
D) `~/.bash_profile`

**정답: C**
해설: 로그인 셸은 가장 먼저 전역 파일인 `/etc/profile`(그리고 그 안에서 `/etc/profile.d/*.sh`)을 읽고, 그다음 사용자 홈의 `~/.bash_profile`(없으면 `~/.bash_login`, `~/.profile`)을 읽는다. `/etc/bashrc`와 `~/.bashrc`는 비로그인 대화형 셸이 읽는 파일이므로 로그인 셸의 "가장 먼저"에는 해당하지 않는다. `~/.bash_profile`은 전역이 아니라 사용자 개인 파일이다.

---

**문제 4.** 현재 셸에 설정된 **환경 변수만** 출력하는 명령은?

A) `set`
B) `env`
C) `declare`
D) `alias`

**정답: B**
해설: `env`는 환경 변수(export된 변수)만 출력한다. `set`은 셸 변수와 환경 변수, 함수까지 모두 출력하므로 범위가 더 넓다. `declare`는 인자 없이 쓰면 모든 변수와 함수를 보여주고, `alias`는 변수가 아니라 등록된 별칭 목록을 출력한다. "환경 변수만"이라는 조건을 정확히 만족하는 것은 `env`(또는 `export -p`)다.

**문제 5.** `.bashrc` 파일을 수정한 뒤 로그아웃 없이 현재 셸에 즉시 반영하는 올바른 방법은?

A) `bash ~/.bashrc`
B) `exec ~/.bashrc`
C) `source ~/.bashrc`
D) `run ~/.bashrc`

**정답: C**
해설: `source ~/.bashrc`(또는 `. ~/.bashrc`)는 파일 내용을 **현재 셸 프로세스 안에서** 다시 읽어들여 변경을 즉시 반영한다. `bash ~/.bashrc`는 새 자식 셸을 띄워 거기서만 적용한 뒤 종료되므로 현재 셸에는 변화가 없다. `exec`는 현재 프로세스를 다른 프로그램으로 교체하는 명령이라 용도가 다르고, `run`은 존재하지 않는 명령이다.

**문제 6.** 다음 중 `PATH` 환경 변수에 대한 설명으로 옳지 않은 것은?

A) 디렉터리들을 콜론(`:`)으로 구분한 목록이다
B) 같은 이름의 명령이 여러 곳에 있으면 PATH의 뒤쪽 디렉터리가 우선한다
C) 외부 명령을 실행할 때 실행 파일을 검색하는 경로다
D) `export PATH=/opt/bin:$PATH`로 기존 경로 앞에 추가할 수 있다

**정답: B**
해설: PATH는 **앞쪽(왼쪽)부터** 검색하므로, 같은 이름의 명령이 여러 디렉터리에 있으면 **먼저 나오는(앞쪽)** 디렉터리의 것이 실행된다. 따라서 "뒤쪽이 우선한다"는 설명은 틀렸다. 나머지는 모두 옳다. PATH는 콜론으로 구분한 디렉터리 목록이고, 외부 명령 검색에 쓰이며, `$PATH`를 포함시켜 앞에 새 경로를 덧붙이는 방식이 안전한 추가법이다.

**문제 7.** 비로그인 대화형 셸(터미널에서 새 탭 열기)이 읽는 사용자 설정 파일은?

A) `~/.bash_profile`
B) `~/.bash_login`
C) `~/.bashrc`
D) `~/.bash_logout`

**정답: C**
해설: 비로그인 대화형 셸은 전역 `/etc/bashrc` 다음에 사용자의 `~/.bashrc`를 읽는다. `~/.bash_profile`과 `~/.bash_login`은 로그인 셸이 읽는 파일이고, `~/.bash_logout`은 로그아웃할 때 실행되는 파일이다. 그래서 alias나 함수처럼 매 셸마다 필요한 설정은 `~/.bashrc`에 두는 것이 관례이며, 로그인 셸에서도 적용되도록 `.bash_profile`이 `.bashrc`를 source하도록 작성해 둔다.
