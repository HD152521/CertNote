# Day 3 - vi/vim 정밀 정복: 손을 떼지 않고 편집하는 에디터의 미학

리눅스 서버에 접속해 설정 파일을 수정해야 할 때, 거의 항상 마주치는 도구가 `vi`입니다. 그래픽 환경 없는 원격 서버에서도, 최소 설치된 시스템에서도, `vi`는 거의 예외 없이 존재합니다. 그래서 리눅스 관리자에게 `vi`는 선택이 아니라 필수입니다. 처음 `vi`를 만나면 "글자를 입력하려는데 이상한 일이 벌어진다", "어떻게 빠져나가는지조차 모르겠다"는 당혹감을 느끼기 마련입니다. 이것은 `vi`가 **모드(mode)**라는 독특한 개념 위에 설계되었기 때문입니다. 일단 이 모드의 철학을 이해하면, `vi`는 마우스 없이 손을 키보드 홈 포지션에 둔 채 텍스트를 자유자재로 다루는 강력한 도구가 됩니다. 오늘은 `vi`/`vim`을 시험 수준 이상으로 정밀하게 파고들고, `nano`와 `emacs`도 개요로 짚어봅니다.

> 📚 **유래/사례: vi에서 vim으로**
> `vi`(visual editor)는 1976년 빌 조이(Bill Joy)가 만든 에디터입니다. `vim`(Vi IMproved)은 1991년 브람 무레나르(Bram Moolenaar)가 `vi`를 개선해 만든 현대적 버전으로, 구문 강조, 다중 실행 취소, 분할 화면 등을 추가했습니다. 오늘날 대부분의 리눅스에서 `vi`를 입력하면 실제로는 `vim`이 실행됩니다.

## vi의 핵심: 세 가지 모드

`vi`를 이해하는 열쇠는 모드입니다. 같은 키를 눌러도 어떤 모드에 있느냐에 따라 전혀 다르게 동작합니다.

| 모드 | 역할 | 진입 방법 |
|------|------|-----------|
| 명령(Command) 모드 | 커서 이동, 복사/삭제, 명령 실행 | 시작 시 기본, `Esc`로 복귀 |
| 입력(Insert) 모드 | 실제 텍스트 입력 | `i`, `a`, `o` 등 |
| 마지막 행(ex/Last-line) 모드 | 저장, 종료, 검색/치환 | 명령 모드에서 `:` |

핵심 흐름은 이렇습니다. `vi`를 켜면 **명령 모드**에서 시작합니다. 글자를 입력하려면 `i` 등을 눌러 **입력 모드**로 들어가고, 입력이 끝나면 `Esc`로 명령 모드로 돌아옵니다. 저장하거나 종료하려면 명령 모드에서 `:`를 눌러 **마지막 행 모드**로 들어갑니다.

> 💡 **개념: 왜 모드를 나누었을까**
> 일반 에디터는 글자 키가 곧 입력이고, 기능은 Ctrl이나 Alt 조합으로 처리합니다. `vi`는 발상을 뒤집어, 명령 모드에서는 모든 글자 키가 편집 명령으로 작동합니다. 덕분에 `dd`(행 삭제), `yy`(행 복사)처럼 손을 움직이지 않고 한두 타로 강력한 편집을 할 수 있습니다. 이 효율이 수십 년간 `vi`가 사랑받는 이유입니다.

## 입력 모드로 들어가기

같은 입력 모드라도 진입하는 키에 따라 커서 위치가 달라집니다. 시험에 자주 나오는 부분입니다.

| 키 | 동작 |
|----|------|
| `i` | 커서 앞(현재 위치)에서 입력 시작 (insert) |
| `a` | 커서 뒤에서 입력 시작 (append) |
| `I` | 행의 맨 앞에서 입력 시작 |
| `A` | 행의 맨 끝에서 입력 시작 |
| `o` | 현재 행 아래에 새 행을 열고 입력 (open) |
| `O` | 현재 행 위에 새 행을 열고 입력 |

> ⚠️ **함정: i와 a, o와 O의 차이**
> 시험에서 "커서 위치 다음부터 입력하는 키는?"이라고 물으면 답은 `a`(append)이지 `i`(insert)가 아닙니다. 또 `o`는 아래 행, `O`(대문자)는 위 행을 연다는 점, `I`는 행 맨 앞, `A`는 행 맨 끝이라는 점을 정확히 구분해야 합니다. 대소문자 한 글자가 결과를 완전히 바꿉니다.

## 명령 모드에서의 커서 이동

`vi`의 진가는 손을 홈 포지션에 둔 채 이동하는 데 있습니다.

```
h  ←  왼쪽 한 칸
l  →  오른쪽 한 칸
j  ↓  아래 한 행
k  ↑  위 한 행
w     다음 단어의 시작으로
b     이전 단어의 시작으로
e     단어의 끝으로
0     행의 맨 앞(0번 컬럼)으로
^     행의 첫 글자(공백 제외)로
$     행의 맨 끝으로
gg    파일의 첫 행으로
G     파일의 마지막 행으로
5G    5번째 행으로 (또는 :5)
Ctrl+f  한 화면 아래로(forward)
Ctrl+b  한 화면 위로(backward)
```

> 🔍 **더 깊이: hjkl이 화살표가 된 이유**
> `vi`를 만든 빌 조이가 사용하던 ADM-3A 단말기에는 화살표 키가 없었고, h/j/k/l 키에 화살표가 그려져 있었습니다. 그래서 이 네 키가 이동 키가 되었습니다. 오늘날까지 이어진 이 관습 덕분에, vim 사용자는 손을 홈 포지션에서 떼지 않고도 빠르게 이동할 수 있습니다.

## 삭제, 복사, 붙여넣기

명령 모드에서 이루어지는 편집 명령들입니다.

| 명령 | 동작 |
|------|------|
| `x` | 커서 위치의 한 글자 삭제 |
| `dd` | 현재 행 삭제(잘라내기) |
| `3dd` | 현재 행부터 3개 행 삭제 |
| `dw` | 커서부터 단어 끝까지 삭제 |
| `D` | 커서부터 행 끝까지 삭제 |
| `yy` | 현재 행 복사(yank) |
| `3yy` | 3개 행 복사 |
| `p` | 복사/삭제한 내용을 커서 뒤(아래)에 붙여넣기 |
| `P` | 커서 앞(위)에 붙여넣기 |
| `u` | 실행 취소(undo) |
| `Ctrl+r` | 다시 실행(redo) |
| `.` | 직전 명령 반복(repeat) |

> 💡 **개념: vi의 "잘라내기"는 곧 복사다**
> `vi`에는 별도의 클립보드가 없는 대신 레지스터(register)라는 임시 저장 공간이 있습니다. `dd`로 행을 삭제하면 그 내용이 레지스터에 저장되므로, `p`로 다른 곳에 붙여넣을 수 있습니다. 즉 `dd`는 "삭제"이자 동시에 "잘라내기"입니다. 그래서 행 순서를 바꿀 때 `dd` 후 원하는 위치에서 `p`를 누르는 패턴을 자주 씁니다.

## 검색

명령 모드에서 검색은 `/`(아래 방향)와 `?`(위 방향)로 시작합니다.

```
/error      아래 방향으로 error 검색
?error      위 방향으로 error 검색
n           다음 일치로 이동(같은 방향)
N           이전 일치로 이동(반대 방향)
```

검색에는 정규표현식을 쓸 수 있습니다. 예를 들어 `/^root`는 root로 시작하는 행을 찾습니다.

## 마지막 행(ex) 모드: 저장과 종료

명령 모드에서 `:`를 누르면 화면 맨 아래에 명령을 입력하는 ex 모드로 들어갑니다. 가장 많이 쓰는 명령들입니다.

| 명령 | 동작 |
|------|------|
| `:w` | 저장(write) |
| `:w 파일명` | 다른 이름으로 저장 |
| `:q` | 종료(quit) |
| `:q!` | 저장하지 않고 강제 종료 |
| `:wq` | 저장 후 종료 |
| `:x` | 변경된 경우에만 저장 후 종료 |
| `ZZ` | (명령 모드) 저장 후 종료 — :wq와 동등 |
| `:wq!` | 강제로 저장 후 종료 |
| `:5` | 5번째 행으로 이동 |
| `:set nu` | 행 번호 표시(number) |
| `:set nonu` | 행 번호 숨기기 |

> ⚠️ **함정: :wq, :x, ZZ의 미묘한 차이**
> `:wq`는 변경 여부와 관계없이 항상 파일을 다시 씁니다(타임스탬프가 갱신됨). `:x`와 `ZZ`는 **변경된 경우에만** 저장하므로, 내용을 안 바꿨다면 파일을 건드리지 않아 타임스탬프가 보존됩니다. 미세한 차이지만 시험에 출제되고, 빌드 시스템처럼 타임스탬프가 중요한 환경에서는 실무적으로도 의미가 있습니다.

## 치환: ex 모드의 강력한 기능

ex 모드에서 `s`(substitute) 명령으로 텍스트를 치환합니다. 문법은 `sed`와 매우 비슷합니다.

```
:s/old/new/          현재 행의 첫 번째 old를 new로
:s/old/new/g         현재 행의 모든 old를 new로
:%s/old/new/g        파일 전체의 모든 old를 new로
:%s/old/new/gc       파일 전체 치환하되 매번 확인(confirm)
:1,10s/old/new/g     1~10행 범위에서 치환
:%s/old/new/gi       대소문자 무시하고 전체 치환
```

`%`는 "파일 전체 행"을 의미하는 범위 지정자입니다. 그래서 `:%s/.../.../g`는 파일 전체에서 모든 일치를 치환하는 가장 흔한 패턴입니다.

> 🔍 **더 깊이: vi의 치환과 sed의 뿌리**
> `vi`의 ex 모드 치환 `:%s/old/new/g`와 `sed`의 `s/old/new/g`가 닮은 것은 우연이 아닙니다. 둘 다 행 단위 에디터 `ed`에서 비롯된 한 가족이기 때문입니다. `ed` → `ex` → `vi`로 이어지는 계보를 알면, ex 모드 명령들이 왜 이런 문법인지 자연스럽게 이해됩니다.

## 환경 설정: .vimrc

vim의 동작은 홈 디렉터리의 `.vimrc` 파일로 영구 설정할 수 있습니다. ex 모드에서 `:set` 명령으로 임시 설정한 것을 이 파일에 적으면 매번 적용됩니다.

```vim
set number          " 행 번호 표시
set autoindent      " 자동 들여쓰기
set tabstop=4       " 탭 너비 4칸
set expandtab       " 탭을 공백으로 변환
set hlsearch        " 검색 결과 강조(highlight)
set ignorecase      " 검색 시 대소문자 무시
syntax on           " 구문 강조 켜기
```

> 📚 **유래/사례: 점(.) 으로 시작하는 설정 파일**
> `.vimrc`, `.bashrc`처럼 점으로 시작하는 파일은 `ls`에 기본적으로 표시되지 않는 숨김 파일입니다. 끝의 `rc`는 "run commands"의 약자로, 프로그램이 시작할 때 자동으로 실행하는 명령 모음이라는 뜻입니다. 유닉스 초기 CTSS 시스템의 "runcom"에서 유래한 오래된 관습입니다.

## nano 개요: 초보자 친화적 에디터

`nano`는 `vi`와 정반대 철학의 에디터입니다. 모드가 없고, 켜자마자 바로 글자를 입력할 수 있으며, 화면 아래에 단축키 안내가 항상 표시됩니다.

```bash
nano file.txt       # nano로 파일 열기
```

주요 단축키(`^`는 Ctrl 키):

| 단축키 | 동작 |
|--------|------|
| `Ctrl+O` | 저장(write Out) |
| `Ctrl+X` | 종료 |
| `Ctrl+W` | 검색(Where is) |
| `Ctrl+K` | 행 잘라내기 |
| `Ctrl+U` | 붙여넣기 |
| `Ctrl+G` | 도움말 |

`nano`는 간단한 설정 수정에는 편하지만, `vi`처럼 강력한 편집 명령이나 어디서나 보장되는 가용성은 없습니다.

## emacs 개요: 또 하나의 거인

`emacs`는 `vi`와 함께 유닉스 양대 에디터로 꼽힙니다. 리처드 스톨먼이 만들었으며, 사실상 운영체제에 가까울 만큼 확장성이 높습니다. `vi`가 모드 기반이라면, `emacs`는 모든 기능을 Ctrl/Meta(Alt) 조합 키로 호출합니다.

| 단축키 | 동작 |
|--------|------|
| `Ctrl+X Ctrl+S` | 저장 |
| `Ctrl+X Ctrl+C` | 종료 |
| `Ctrl+K` | 행 끝까지 잘라내기 |
| `Ctrl+Y` | 붙여넣기 |
| `Ctrl+S` | 검색 |

> 💡 **개념: vi vs emacs 논쟁**
> 수십 년간 이어진 "에디터 전쟁"에서 `vi`는 가볍고 어디에나 있다는 점, `emacs`는 무한히 확장 가능하다는 점으로 각각의 진영을 형성했습니다. 시험과 실무 관점에서는 어떤 최소 시스템에도 설치되어 있는 `vi`를 다룰 줄 아는 것이 가장 안전한 선택입니다.

## 직접 쳐보기

`vi`는 손으로 익혀야 합니다. 다음을 직접 따라 해 보세요.

```bash
# 1. vi로 새 파일 만들기
vi practice.txt

# vi 안에서 차례대로:
# i 를 눌러 입력 모드 진입
# 아래 내용 입력:
#   Hello Linux
#   This is vi practice
#   Line three
# Esc 를 눌러 명령 모드 복귀

# 2. 커서 이동 연습 (명령 모드에서)
# gg → 첫 행으로, G → 마지막 행으로
# w → 단어 이동, $ → 행 끝, 0 → 행 처음

# 3. 편집 연습
# dd → 한 행 삭제, u → 실행 취소
# yy 후 p → 행 복사 붙여넣기

# 4. 검색과 치환
# /vi 입력 후 Enter → vi 검색, n으로 다음
# :%s/Line/행/g 입력 → Line을 행으로 전체 치환

# 5. 저장하고 종료
# :wq 입력 후 Enter

# 6. 결과 확인
cat practice.txt
rm practice.txt
```

처음에는 모드 전환이 헷갈리지만, "글자가 안 들어가면 일단 Esc 후 i"라는 리듬을 익히면 금세 편해집니다. `dd`, `yy`, `p`, `:wq`만 손에 익혀도 서버 작업의 90%는 해결됩니다.

## 📝 연습 문제

**문제 1.** `vi`에서 현재 커서 위치의 다음(뒤)부터 텍스트를 입력하는 키는?

A) `i`
B) `a`
C) `o`
D) `I`

**정답: B**
해설: `a`(append)는 커서 뒤에서 입력을 시작합니다. `i`(insert)는 커서 앞에서, `o`는 아래 행을 새로 열고, `I`는 행 맨 앞에서 입력을 시작합니다.

---

**문제 2.** `vi`의 명령 모드에서 현재 행을 삭제하는 명령은?

A) `x`
B) `dw`
C) `dd`
D) `yy`

**정답: C**
해설: `dd`는 현재 행 전체를 삭제(잘라내기)합니다. `x`는 한 글자 삭제, `dw`는 단어 삭제, `yy`는 행 복사(삭제가 아님)입니다.

---

**문제 3.** `vi`에서 저장하지 않고 강제로 종료하는 명령은?

A) `:wq`
B) `:q`
C) `:q!`
D) `:x`

**정답: C**
해설: `:q!`는 변경 사항을 버리고 강제 종료합니다. `:wq`는 저장 후 종료, `:q`는 변경이 있으면 종료를 거부, `:x`는 변경된 경우에만 저장 후 종료입니다.

---

**문제 4.** `vi`의 ex 모드에서 파일 전체의 모든 `apple`을 `orange`로 치환하는 명령은?

A) `:s/apple/orange/`
B) `:s/apple/orange/g`
C) `:%s/apple/orange/g`
D) `:1,5s/apple/orange/g`

**정답: C**
해설: `%`는 파일 전체 행을 의미하고 `g`는 행 내 모든 일치를 뜻하므로, `:%s/apple/orange/g`가 파일 전체의 모든 일치를 치환합니다. A는 현재 행 첫 일치만, B는 현재 행 전체만, D는 1~5행만 처리합니다.

**문제 5.** `vi`에서 복사(yank)한 내용을 붙여넣는 명령은?

A) `y`
B) `p`
C) `c`
D) `d`

**정답: B**
해설: `p`(paste/put)는 복사하거나 삭제한 내용을 붙여넣습니다. `y`는 복사(yank), `c`는 변경(change), `d`는 삭제(delete)입니다.

**문제 6.** vim에서 행 번호를 표시하도록 영구 설정하려면 `.vimrc`에 추가할 항목은?

A) `set number`
B) `set autoindent`
C) `syntax on`
D) `set hlsearch`

**정답: A**
해설: `set number`(또는 `set nu`)는 행 번호를 표시합니다. `set autoindent`는 자동 들여쓰기, `syntax on`은 구문 강조, `set hlsearch`는 검색 결과 강조입니다.

**문제 7.** `nano` 에디터에서 파일을 저장(write out)하는 단축키는?

A) `Ctrl+X`
B) `Ctrl+O`
C) `Ctrl+W`
D) `Ctrl+K`

**정답: B**
해설: `nano`에서 `Ctrl+O`(write Out)가 저장입니다. `Ctrl+X`는 종료, `Ctrl+W`는 검색(Where is), `Ctrl+K`는 행 잘라내기입니다.
