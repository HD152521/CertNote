# Day 1 - 파일과 디렉터리 명령: 리눅스 파일 시스템을 손끝으로 다루기

## 📌 핵심 정리

- 경로는 **절대 경로**(`/`부터 시작, 어디서 쳐도 같은 곳)와 **상대 경로**(현재 위치 기준) 두 가지다.
- 디렉터리 처리는 옵션이 갈린다 — `cp`는 `-r` 필수, `mv`는 불필요, `rmdir`은 **빈 것만**, 내용까지 지우려면 `rm -r`.
- `find`는 디스크를 실시간 탐색해 정확하고, `locate`는 DB를 조회해 빠르지만 방금 만든 파일은 못 찾는다.
- `-exec`의 `\;`는 파일마다 명령 1회, `+`는 여러 파일을 묶어 1회 — 대량 처리엔 `+`가 훨씬 빠르다.
- 명령의 정체(내장/별칭/외부)는 `type`이 가장 정확하다. `which`는 PATH 안의 실행 파일만 본다.

> 💡 **개념: 명령어 = 프로그램**
> 우리가 입력하는 `ls`, `cp` 같은 명령어는 사실 `/bin`이나 `/usr/bin`에 존재하는 실행 파일입니다. 셸은 입력된 이름을 `PATH` 환경 변수에 등록된 디렉터리들에서 찾아 실행합니다. 즉 명령어는 마법이 아니라 디스크에 저장된 프로그램일 뿐입니다.

## 경로의 이해: 절대 경로와 상대 경로

- 리눅스 파일 시스템은 최상위 루트 `/`에서 시작하는 거대한 **역트리(inverted tree)** 구조다. 모든 파일·디렉터리는 이 트리 어딘가에 있고, 그 위치 표현이 경로다.
- **절대 경로(absolute path)**: 루트 `/`부터 전체를 명시. `/home/user/docs/report.txt`는 어디에서 입력하든 항상 같은 파일이다.
- **상대 경로(relative path)**: 현재 작업 디렉터리(current working directory)를 기준으로 한다.

| 기호 | 의미 |
|------|------|
| `.` | 현재 디렉터리 |
| `..` | 부모(상위) 디렉터리 |
| `~` | 현재 사용자의 홈 디렉터리 |
| `~user` | 특정 사용자(user)의 홈 디렉터리 |
| `-` | 직전(이전)에 있던 디렉터리 (`cd -`에서 사용) |

- 예: 현재 위치가 `/home/user/docs`일 때 `../photos` → `/home/user/photos`, `./report.txt` → `/home/user/docs/report.txt`.

> 🔍 **더 깊이: `.`과 `..`의 정체**
> `.`과 `..`은 단순한 약속이 아니라 실제로 모든 디렉터리에 존재하는 **하드 링크**입니다. `ls -a` 명령을 실행하면 이 두 항목이 실제 디렉터리 엔트리로 나타납니다. 그래서 빈 디렉터리도 링크 수(link count)가 2입니다. 자기 자신을 가리키는 `.` 하나와, 부모 디렉터리에서 자신을 가리키는 엔트리 하나가 합쳐진 결과입니다.

## 위치 파악: pwd와 cd

- `pwd`(print working directory): 현재 어디에 있는지 출력.
- `cd`(change directory): 위치를 옮긴다.

```bash
pwd                 # 현재 작업 디렉터리의 절대 경로 출력
cd /etc             # /etc 디렉터리로 이동 (절대 경로)
cd ..               # 상위 디렉터리로 이동
cd ~                # 홈 디렉터리로 이동
cd                  # 인자 없이 cd만 입력해도 홈으로 이동
cd -                # 직전에 있던 디렉터리로 토글 이동
```

- `cd -`를 반복하면 두 디렉터리를 토글처럼 왔다 갔다 할 수 있다 — 두 곳을 오가며 작업할 때 유용하다.

> ⚠️ **함정: pwd와 심볼릭 링크**
> `pwd`에는 `-P`(physical)와 `-L`(logical) 옵션이 있습니다. 심볼릭 링크를 통해 디렉터리에 진입한 경우, 기본값인 `-L`은 링크 경로를 그대로 보여주지만 `-P`는 링크가 가리키는 실제 물리적 경로를 보여줍니다. 시험에서 이 둘의 차이를 묻는 문제가 종종 나옵니다.

## 목록 보기: ls

- `ls`(list)는 디렉터리 내용을 나열한다. 가장 많이 쓰는 명령이면서 옵션이 풍부해 시험 단골이다.

```bash
ls              # 현재 디렉터리 내용 (숨김 파일 제외)
ls -a           # 숨김 파일(.으로 시작) 포함 모두 표시
ls -l           # 상세 정보(롱 포맷): 권한, 링크 수, 소유자, 크기, 시간
ls -la          # 상세 정보 + 숨김 파일
ls -lh          # 크기를 사람이 읽기 쉬운 단위(K, M, G)로 표시
ls -lt          # 수정 시간 순으로 정렬 (최신이 위)
ls -ltr         # 수정 시간 역순 (오래된 것이 위, 최신이 아래)
ls -R           # 하위 디렉터리까지 재귀적으로 표시
ls -i           # inode 번호 표시
ls -d */        # 디렉터리 자체만 표시 (내용은 펼치지 않음)
```

`ls -l` 출력 첫 글자 = 파일 유형.

| 첫 글자 | 유형 |
|------|------|
| `-` | 일반 파일 |
| `d` | 디렉터리 |
| `l` | 심볼릭 링크 |
| `c` | 문자 장치 |
| `b` | 블록 장치 |
| `p` | 파이프 |
| `s` | 소켓 |

> 💡 **개념: -h 옵션의 진짜 의미**
> `-h`는 human-readable의 약자입니다. `1048576`처럼 바이트 단위로 출력되던 크기를 `1.0M`처럼 변환합니다. 단, `-l`과 함께 써야 의미가 있습니다. `ls -h`만 단독으로 쓰면 크기 정보 자체가 표시되지 않으므로 효과가 없습니다.

## 디렉터리 만들기와 지우기: mkdir, rmdir

```bash
mkdir project               # project 디렉터리 생성
mkdir -p a/b/c              # 중간 경로(a, b)가 없어도 한 번에 생성
mkdir -m 755 secure         # 권한을 755로 지정하며 생성
rmdir empty_dir             # 빈 디렉터리만 삭제 (내용 있으면 오류)
rmdir -p a/b/c              # c, b, a 순으로 빈 경로 전체 삭제
```

- `mkdir -p`의 `p`는 parents. 깊은 경로를 한 번에 만들 때 필수다.
- `rmdir`은 **빈 디렉터리만** 지운다. 내용이 있는 디렉터리를 통째로 지우려면 뒤에 나오는 `rm -r`를 써야 한다.

> 📚 **유래/사례: 왜 rmdir은 빈 것만 지울까**
> `rmdir`은 시스템 호출 `rmdir(2)`을 그대로 반영한 명령입니다. 이 시스템 호출은 안전성을 위해 의도적으로 빈 디렉터리만 제거하도록 설계되었습니다. 실수로 거대한 디렉터리 트리를 날려버리는 사고를 막기 위한 장치입니다. 강력함과 위험을 분리한 유닉스 철학의 한 단면입니다.

## 파일 생성과 시간 갱신: touch

```bash
touch newfile.txt           # 빈 파일 생성 (이미 있으면 시간만 갱신)
touch a.txt b.txt c.txt     # 여러 파일 동시 생성
touch -t 202601011200 f.txt # 특정 시각(2026-01-01 12:00)으로 타임스탬프 설정
touch -a f.txt              # 접근 시간(atime)만 갱신
touch -m f.txt              # 수정 시간(mtime)만 갱신
```

- 본래 목적은 **타임스탬프 갱신**이지만, 없는 파일을 지정하면 빈 파일을 만들어주므로 빈 파일 생성 용도로 더 자주 쓰인다.

> 🔍 **더 깊이: 리눅스의 세 가지 시간**
> 모든 파일은 세 가지 타임스탬프를 가집니다. **atime**(access time, 마지막 읽은 시각), **mtime**(modify time, 내용이 바뀐 시각), **ctime**(change time, inode 메타데이터가 바뀐 시각)입니다. ctime은 권한이나 소유자가 바뀔 때도 갱신되며, 사용자가 임의로 과거 시각으로 설정할 수 없다는 점에서 atime/mtime과 다릅니다.

## 복사: cp

```bash
cp source.txt dest.txt      # 파일 복사
cp file.txt /backup/        # /backup 디렉터리로 복사
cp -r dir1 dir2             # 디렉터리 재귀 복사 (하위 전체)
cp -i a.txt b.txt           # 덮어쓰기 전에 확인(interactive)
cp -p file.txt copy.txt     # 권한, 소유자, 타임스탬프 보존(preserve)
cp -u src.txt dst.txt       # 원본이 더 최신일 때만 복사(update)
cp -a dir1 dir2             # 아카이브 모드: -dpR과 동등, 모든 속성 보존
```

- 가장 자주 헷갈리는 것이 `-r`(recursive)다. 디렉터리를 복사하려면 반드시 `-r`(또는 `-R`)을 붙여야 하고, 없으면 `omitting directory` 오류가 난다.

> ⚠️ **함정: cp는 기본적으로 덮어쓴다**
> 대부분의 리눅스 배포판에서 `cp`는 대상 파일이 이미 존재해도 경고 없이 덮어씁니다. 데이터를 잃지 않으려면 `-i`(interactive) 옵션으로 확인 프롬프트를 받거나, `-n`(no-clobber)으로 기존 파일을 보호해야 합니다. 실무에서 한 줄의 명령이 중요한 파일을 날려버리는 일이 여기서 시작됩니다.

## 이동과 이름 변경: mv

```bash
mv old.txt new.txt          # 이름 변경 (같은 디렉터리 내)
mv file.txt /tmp/           # 파일을 /tmp로 이동
mv -i a.txt b.txt           # 덮어쓰기 전 확인
mv -f a.txt b.txt           # 강제 덮어쓰기(force, 확인 없이)
mv -u src dst               # 원본이 더 최신일 때만 이동
mv dir1 dir2                # 디렉터리 이동 (cp와 달리 -r 불필요)
```

- 같은 디렉터리 안에서 옮기면 **이름 변경**, 다른 디렉터리로 옮기면 **이동**이 된다.
- 디렉터리를 옮길 때 `cp`와 달리 `-r` 옵션이 필요 없다.

> 🔍 **더 깊이: mv가 빠른 이유**
> 같은 파일 시스템 내에서 `mv`는 실제로 데이터를 복사하지 않습니다. 단지 디렉터리 엔트리(파일 이름과 inode를 연결하는 정보)만 바꿉니다. 그래서 수 기가바이트 파일도 순식간에 이동됩니다. 단, **다른 파일 시스템(다른 파티션, USB 등)으로** 옮길 때는 복사 후 원본 삭제 방식으로 동작하므로 크기에 비례해 시간이 걸립니다.

## 삭제: rm

```bash
rm file.txt                 # 파일 삭제
rm -i file.txt              # 삭제 전 확인
rm -r directory             # 디렉터리와 그 내용 모두 재귀 삭제
rm -f file.txt              # 강제 삭제 (없는 파일이어도 오류 안 냄)
rm -rf directory            # 디렉터리 강제 재귀 삭제 (가장 위험)
```

> ⚠️ **함정: rm -rf의 공포**
> `rm -rf /`는 시스템 전체를 파괴하는 명령으로 악명 높습니다. 특히 변수가 비어 있는 상태에서 `rm -rf $DIR/`처럼 쓰면 `rm -rf /`가 되어버릴 수 있습니다. 리눅스에는 휴지통 개념이 없어 한 번 지우면 복구가 매우 어렵습니다. `rm`을 쓸 때는 경로를 두 번 확인하고, 와일드카드(`*`)를 쓸 때는 특히 신중해야 합니다.

## 파일 찾기: find과 locate

- 파일 찾기는 크게 두 갈래 — 실시간으로 디스크를 탐색하는 `find`, 미리 만들어진 데이터베이스를 조회하는 `locate`.
- `find`는 강력하지만 문법이 독특하다. 기본 형식은 `find [경로] [조건] [동작]`.

```bash
find . -name "*.txt"            # 현재 디렉터리 이하에서 .txt 파일 찾기
find /home -name "report*"      # 이름이 report로 시작하는 파일
find . -iname "readme"          # 대소문자 무시(insensitive)
find . -type f                  # 일반 파일만 (f=file)
find . -type d                  # 디렉터리만 (d=directory)
find . -size +100M              # 100MB보다 큰 파일
find . -size -1k                # 1KB보다 작은 파일
find . -mtime -7                # 7일 이내 수정된 파일
find . -mtime +30               # 30일보다 오래 전 수정된 파일
find . -perm 644                # 권한이 정확히 644인 파일
find . -user alice              # 소유자가 alice인 파일
find . -empty                   # 빈 파일/디렉터리
```

- 진짜 강력함은 `-exec`로 찾은 파일에 명령을 실행하는 데 있다.

```bash
find . -name "*.tmp" -exec rm {} \;        # 찾은 .tmp 파일을 하나씩 삭제
find . -name "*.log" -exec ls -l {} \;     # 찾은 로그 파일 상세 정보 출력
find . -name "*.txt" -exec grep "error" {} \;   # 각 파일에서 error 검색
find . -type f -exec chmod 644 {} +        # 여러 파일을 한 번에 처리(+)
```

- `{}` : 찾은 파일 이름으로 치환되는 자리표시자.
- `\;` : 명령의 끝 표시. 대신 `+`를 쓰면 여러 파일을 한 번의 명령으로 묶어 처리해 효율적이다.

> 🔍 **더 깊이: -exec의 `\;` vs `+`**
> `\;`는 찾은 파일마다 명령을 한 번씩 실행합니다. 파일이 1000개면 명령이 1000번 실행됩니다. 반면 `+`는 가능한 많은 파일을 한 줄의 명령 인자로 묶어 실행합니다. `xargs`와 비슷한 효율을 냅니다. 대량 파일 처리 시 `+`가 훨씬 빠르지만, 명령이 파일을 개별적으로 처리해야 한다면 `\;`를 써야 합니다.

- `locate`는 접근 방식이 완전히 다르다. 시스템이 주기적으로(보통 하루 한 번 cron) 갱신하는 `mlocate.db` 데이터베이스를 조회하므로 매우 빠르다.

```bash
locate report.txt           # 데이터베이스에서 report.txt 검색
locate -i README            # 대소문자 무시
locate -c "*.conf"          # 일치하는 개수만 출력(count)
updatedb                    # locate 데이터베이스 수동 갱신 (root 권한)
```

> ⚠️ **함정: locate는 최신 파일을 못 찾는다**
> `locate`는 데이터베이스에 의존하므로, 방금 만든 파일은 `updatedb`로 DB를 갱신하기 전까지 찾을 수 없습니다. 반대로 이미 삭제된 파일이 결과에 남아 있을 수도 있습니다. "확실한 최신 결과"가 필요하면 느리더라도 실시간 탐색하는 `find`를 써야 합니다.

## 명령어 위치 확인: which, whereis, type

```bash
which ls                    # ls 실행 파일의 경로 (PATH 내에서)
which -a python             # PATH 내 모든 일치 경로 표시
whereis ls                  # 실행 파일 + 매뉴얼 + 소스 위치
type cd                     # 명령의 종류(내장/외부/별칭) 표시
```

- `which` : `PATH`에 등록된 디렉터리에서 실행 파일 위치를 찾는다.
- `whereis` : 바이너리뿐 아니라 매뉴얼 페이지와 소스 코드 위치까지 알려준다.

> 💡 **개념: which와 type의 차이**
> `which`는 외부 명령(디스크의 실행 파일)만 찾습니다. 그래서 `cd`처럼 셸에 내장된 명령에는 `which cd`가 결과를 못 내놓는 경우가 있습니다. 반면 `type cd`는 "cd is a shell builtin"이라고 정확히 알려줍니다. 명령의 정체가 별칭인지, 내장인지, 외부 파일인지 궁금하면 `type`이 가장 정확합니다.

## 직접 쳐보기

다음 실습을 터미널에 직접 입력하며 명령어 흐름을 몸에 익혀보세요.

```bash
# 1. 작업 공간 만들기
mkdir -p ~/practice/week2/day1
cd ~/practice/week2/day1
pwd

# 2. 파일 여러 개 만들고 목록 확인
touch file1.txt file2.txt file3.log
ls -la

# 3. 복사와 이동
cp file1.txt backup.txt
mkdir archive
mv file3.log archive/
ls -R

# 4. 찾기 실습
find . -name "*.txt"
find . -type f -name "*.log"

# 5. 명령어 위치 확인
which ls
type cd

# 6. 정리
cd ~
rm -rf ~/practice
```

- 두세 번 반복하면 파일 시스템을 손끝으로 다루는 감각이 생긴다.
- 특히 `find`의 조건과 `-exec` 조합은 시험뿐 아니라 실무에서도 끝없이 쓰이니 충분히 연습해 둘 것.

## 📖 용어

- **절대 경로** : 루트 `/`부터 다 적는 경로. 어디에서 입력하든 항상 같은 곳을 가리킨다.
- **상대 경로** : 지금 서 있는 디렉터리를 기준으로 적는 경로. `.`, `..`을 쓴다.
- **inode** : 파일의 크기·권한·소유자·시간 같은 메타데이터를 담는 구조체. 파일 이름은 여기 들어 있지 않다.
- **디렉터리 엔트리** : "이 이름은 이 inode다"를 연결해 두는 표. `mv`가 빠른 이유가 여기 있다.
- **하드 링크** : 같은 inode를 가리키는 또 다른 이름. `.`과 `..`이 대표적인 예다.
- **atime / mtime / ctime** : 각각 마지막 읽은 시각, 내용이 바뀐 시각, inode 정보가 바뀐 시각.
- **PATH** : 셸이 명령어 실행 파일을 찾아 뒤지는 디렉터리 목록을 담은 환경 변수.
- **셸 내장 명령(builtin)** : `cd`처럼 별도 실행 파일 없이 셸 안에 들어 있는 명령. `which`로는 잘 안 잡힌다.
- **mlocate.db** : `locate`가 조회하는 파일 목록 데이터베이스. `updatedb`로 갱신한다.
- **재귀(recursive)** : 하위 디렉터리까지 파고들며 처리하는 방식. `cp -r`, `rm -r`의 `r`이 이것이다.

## 📝 연습 문제

**문제 1.** 현재 디렉터리 이하에서 확장자가 `.log`인 일반 파일만 찾으려고 한다. 가장 정확한 명령은?

A) `find . -name "*.log"`
B) `find . -type f -name "*.log"`
C) `find . -type d -name "*.log"`
D) `locate "*.log"`

**정답: B**
해설: `-type f`로 일반 파일만 한정하고 `-name "*.log"`로 확장자를 지정해야 정확합니다. A는 디렉터리까지 포함될 수 있고, C는 디렉터리(`-type d`)만 찾으므로 틀립니다. D의 `locate`는 데이터베이스 기반이라 실시간 정확성이 떨어집니다.

---

**문제 2.** 디렉터리 `dir1`을 그 안의 모든 내용과 함께 `dir2`로 복사하려고 한다. 올바른 명령은?

A) `cp dir1 dir2`
B) `cp -i dir1 dir2`
C) `cp -r dir1 dir2`
D) `mv -r dir1 dir2`

**정답: C**
해설: 디렉터리를 내용까지 복사하려면 재귀 옵션 `-r`이 반드시 필요합니다. A와 B는 `-r`이 없어 "omitting directory" 오류가 납니다. D는 복사가 아니라 이동 명령이며, `mv`는 디렉터리 이동 시 `-r`도 필요 없습니다.

---

**문제 3.** `rmdir` 명령에 대한 설명으로 옳은 것은?

A) 내용이 있는 디렉터리도 강제로 삭제한다
B) 빈 디렉터리만 삭제할 수 있다
C) 파일도 삭제할 수 있다
D) `-r` 옵션으로 재귀 삭제가 가능하다

**정답: B**
해설: `rmdir`은 안전성을 위해 빈 디렉터리만 삭제하도록 설계되었습니다. 내용이 있는 디렉터리는 `rm -r`로 삭제해야 합니다. `rmdir`에는 재귀 삭제 옵션이 없고(`-p`는 빈 상위 경로 삭제), 파일은 삭제할 수 없습니다.

---

**문제 4.** 현재 디렉터리가 `/home/user/docs`일 때, `cd ../photos`를 실행하면 이동하는 위치는?

A) `/home/user/docs/photos`
B) `/home/user/photos`
C) `/home/photos`
D) `/photos`

**정답: B**
해설: `..`은 상위 디렉터리(`/home/user`)를 의미하고, 거기서 `photos`로 들어가므로 `/home/user/photos`가 됩니다. A는 현재 위치 기준(`./photos`), C와 D는 상위로 너무 많이 올라간 잘못된 해석입니다.

---

**문제 5.** `cp` 명령에서 권한, 소유자, 타임스탬프를 그대로 보존하며 복사하는 옵션은?

A) `-r`
B) `-i`
C) `-p`
D) `-u`

**정답: C**
해설: `-p`(preserve)는 원본의 속성(권한, 소유자, 타임스탬프)을 보존합니다. `-r`은 재귀 복사, `-i`는 덮어쓰기 확인, `-u`는 원본이 더 최신일 때만 복사하는 옵션입니다.

---

**문제 6.** 셸 내장 명령인지 외부 명령인지를 가장 정확하게 확인할 수 있는 명령은?

A) `which`
B) `whereis`
C) `locate`
D) `type`

**정답: D**
해설: `type`은 명령이 셸 내장(builtin), 외부 파일, 별칭(alias) 중 무엇인지 정확히 구분해 알려줍니다. `which`는 PATH 내 실행 파일만 찾아 내장 명령을 놓칠 수 있고, `whereis`는 바이너리/매뉴얼/소스 위치를, `locate`는 파일 검색을 담당합니다.

**문제 7.** `find . -name "*.tmp" -exec rm {} \;` 명령에서 `{}`의 역할은?

A) 명령의 끝을 표시한다
B) 찾은 파일의 이름으로 치환되는 자리표시자이다
C) 와일드카드로 모든 파일을 의미한다
D) 현재 디렉터리를 의미한다

**정답: B**
해설: `-exec`에서 `{}`는 `find`가 찾은 각 파일의 이름으로 치환되는 자리표시자입니다. 명령의 끝을 표시하는 것은 `\;`이고, A는 그것에 대한 설명입니다. `{}`는 와일드카드도 현재 디렉터리도 아닙니다.
