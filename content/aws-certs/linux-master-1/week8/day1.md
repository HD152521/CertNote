# Day 1 - 네트워크 기초: OSI 7계층과 IP 주소·서브넷 계산

## 📌 핵심 정리

- 네트워크 문제 해결은 두 질문으로 환원된다 — **"몇 계층에서 막혔는가"(계층 모델)**와 **"어느 네트워크에 속하는가"(서브넷 계산)**.
- 계층별 주소·장비를 묶어 외운다: **2계층 = MAC·스위치, 3계층 = IP·라우터, 4계층 = 포트·TCP/UDP.**
- **TCP는 연결 지향·신뢰성(3-way handshake), UDP는 비연결·고속.** 헤더는 20바이트 vs 8바이트.
- IP 클래스는 첫 옥텟으로 갈린다(A 1~126, B 128~191, C 192~223). **127은 루프백**, **169.254는 APIPA = DHCP 실패 신호**.
- **사용 가능 호스트 수 = 2^(호스트 비트) − 2.** 네트워크 주소는 "블록 크기의 배수 중 그 IP 이하 최댓값", 브로드캐스트는 그 블록의 마지막 주소다.

## OSI 7계층 — 통신을 7개의 책임으로 쪼개기

- 네트워크 통신은 한 덩어리가 아니라 **각자 다른 일을 하는 7개의 층**이 쌓인 구조다.
- **캡슐화** : 송신 측에서 위(7계층)→아래(1계층)로 내려가며 각 계층의 헤더가 붙는다.
- **역캡슐화** : 수신 측에서 아래→위로 올라가며 헤더가 벗겨진다.

| 계층 | 이름 | 핵심 책임 | 데이터 단위(PDU) | 대표 장비/프로토콜 |
|------|------|-----------|------------------|--------------------|
| 7 | 응용(Application) | 사용자 서비스 제공 | 데이터 | HTTP, FTP, SMTP, DNS |
| 6 | 표현(Presentation) | 인코딩·암호화·압축 | 데이터 | SSL/TLS, JPEG, ASCII |
| 5 | 세션(Session) | 연결 설정·유지·종료 | 데이터 | NetBIOS, RPC |
| 4 | 전송(Transport) | 종단 간 신뢰성·포트 | 세그먼트 | TCP, UDP |
| 3 | 네트워크(Network) | 논리 주소·라우팅 | 패킷 | IP, ICMP, 라우터 |
| 2 | 데이터링크(Data Link) | 물리 주소·프레임·오류제어 | 프레임 | 이더넷, MAC, 스위치 |
| 1 | 물리(Physical) | 비트 전기 신호 전송 | 비트 | 케이블, 허브, 리피터 |

> 💡 **개념**: 암기법 "**A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing"(7→1: Application, Presentation, Session, Transport, Network, Data link, Physical). 반대로 1→7은 "**P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way". 시험에서 계층 순서를 묻는 문제가 단골이다.

> 🔍 **핵심 구분**: 계층 번호와 그 계층의 **주소·장비**를 묶어서 외워라. 2계층=MAC 주소·스위치, 3계층=IP 주소·라우터, 4계층=포트 번호·TCP/UDP. "MAC 주소는 몇 계층?" → 2계층, "라우터는 몇 계층?" → 3계층. 이 매핑이 Day 4 장비 문제의 뿌리다.

## TCP/IP 4계층 — 실제 인터넷이 쓰는 모델

- OSI는 **이론적 참조 모델**이고, 실제 인터넷은 더 단순한 **TCP/IP 4계층**으로 동작한다.
- TCP/IP 4계층은 OSI의 여러 계층을 묶은 형태다.

| TCP/IP 계층 | 대응 OSI 계층 | 대표 프로토콜 |
|-------------|---------------|---------------|
| 응용(Application) | 7·6·5 | HTTP, FTP, DNS, SMTP, SSH |
| 전송(Transport) | 4 | TCP, UDP |
| 인터넷(Internet) | 3 | IP, ICMP, ARP |
| 네트워크 접근(Network Access) | 2·1 | 이더넷, ARP |

> 📚 **유래/사례**: TCP/IP는 1970년대 미국 ARPANET에서 실제 구현되며 발전한 "실전 모델"이고, OSI는 1984년 ISO가 표준화한 "이론 모델"이다. 현실 인터넷은 TCP/IP가 장악했지만, 문제 분석의 언어로는 7계층이 더 정밀해 둘 다 쓴다. 시험은 OSI 7계층과 TCP/IP 4계층의 대응 관계를 자주 묻는다.

## TCP vs UDP — 4계층의 두 얼굴

- 전송 계층에는 **성격이 정반대인 두 프로토콜**이 있다.

| 구분 | TCP | UDP |
|------|-----|-----|
| 연결 방식 | 연결 지향(3-way handshake) | 비연결 |
| 신뢰성 | 보장(재전송·순서·흐름제어) | 보장 안 함 |
| 속도 | 상대적으로 느림 | 빠름 |
| 헤더 크기 | 20바이트 | 8바이트 |
| 용도 | 웹, 메일, 파일 전송 | DNS, 스트리밍, VoIP |

> 💡 **개념**: TCP의 **3-way handshake**는 SYN → SYN/ACK → ACK 3단계로 연결을 맺는다. 연결 종료는 4-way(FIN/ACK 두 쌍). UDP는 이런 절차 없이 그냥 보낸다 — 그래서 빠르지만 도착 보장이 없다. "신뢰성=TCP, 속도=UDP"로 기억하라.

## IP 주소 클래스 — 첫 옥텟으로 갈리는 5등급

- IPv4 주소는 **32비트를 8비트씩 4묶음(옥텟)**으로 나눠 점으로 표기한다(예: 192.168.0.1).
- 과거에는 **첫 옥텟 값으로 클래스**를 나눠 네트워크/호스트 부분의 경계를 정했다.

| 클래스 | 첫 옥텟 범위 | 기본 서브넷마스크 | 네트워크/호스트 비트 | 용도 |
|--------|--------------|-------------------|----------------------|------|
| A | 1 ~ 126 | 255.0.0.0 (/8) | 8 / 24 | 대규모 |
| B | 128 ~ 191 | 255.255.0.0 (/16) | 16 / 16 | 중규모 |
| C | 192 ~ 223 | 255.255.255.0 (/24) | 24 / 8 | 소규모 |
| D | 224 ~ 239 | 없음 | — | 멀티캐스트 |
| E | 240 ~ 255 | 없음 | — | 연구·예약 |

> ⚠️ **함정**: 첫 옥텟 **127**(127.0.0.0/8)은 A 클래스 범위에 끼어 보이지만 **루프백(loopback)** 전용이라 일반 호스트에 할당하지 않는다. 그래서 A 클래스 실사용 범위를 1~126으로 적는다. `127.0.0.1`은 자기 자신(localhost)이다.

- **사설 IP 대역**(인터넷에 직접 라우팅되지 않고 내부망에서만 쓰는 주소)도 함께 외운다.

| 클래스 | 사설 IP 범위 |
|--------|--------------|
| A | 10.0.0.0 ~ 10.255.255.255 (10.0.0.0/8) |
| B | 172.16.0.0 ~ 172.31.255.255 (172.16.0.0/12) |
| C | 192.168.0.0 ~ 192.168.255.255 (192.168.0.0/16) |

> 🔍 **핵심 구분**: 169.254.x.x는 사설 IP가 아니라 **APIPA(링크 로컬)** 주소다. DHCP 서버를 못 찾았을 때 호스트가 스스로 부여하는 주소로, "IP는 169.254로 시작하는데 인터넷이 안 된다" = DHCP 실패 신호다. 실무·시험 모두 단골이다.

## 서브넷마스크와 CIDR — 네트워크와 호스트를 가르는 경계선

- 서브넷마스크는 IP 주소에서 **어디까지가 네트워크 부분이고 어디부터가 호스트 부분인지** 알려주는 32비트 값이다.
- **1로 채워진 부분이 네트워크, 0인 부분이 호스트.**

```bash
# 255.255.255.0 을 2진수로 보면
11111111.11111111.11111111.00000000
#  └─────── 네트워크(24비트) ──────┘ └ 호스트(8비트) ┘
```

- **CIDR 표기법**은 이 1의 개수를 슬래시 뒤에 적는 방식이다. `/24` = 마스크 앞쪽 1이 24개 = 255.255.255.0.

| CIDR | 서브넷마스크 | 마지막 옥텟 2진수 | 블록 크기 |
|------|--------------|-------------------|-----------|
| /24 | 255.255.255.0 | 00000000 | 256 |
| /25 | 255.255.255.128 | 10000000 | 128 |
| /26 | 255.255.255.192 | 11000000 | 64 |
| /27 | 255.255.255.224 | 11100000 | 32 |
| /28 | 255.255.255.240 | 11110000 | 16 |
| /29 | 255.255.255.248 | 11111000 | 8 |
| /30 | 255.255.255.252 | 11111100 | 4 |

> 💡 **개념**: 마스크 옥텟 값은 1의 개수만큼 왼쪽부터 채운 결과다. 128=1개, 192=2개, 224=3개, 240=4개, 248=5개, 252=6개. "**128 192 224 240 248 252 254 255**" 이 수열을 외우면 어떤 CIDR도 마스크로 즉시 변환된다.

## 서브넷 계산 — 호스트 수·네트워크 주소·브로드캐스트

- 실기의 핵심이다. 손으로 계산하는 법을 단계로 익히자.

**1) 사용 가능한 호스트 수 = 2^(호스트 비트) − 2**

- **−2를 하는 이유**: **네트워크 주소**(호스트 비트 전부 0)와 **브로드캐스트 주소**(호스트 비트 전부 1) 두 개를 빼기 때문.
- 이 둘은 **호스트에 할당할 수 없다.**

```bash
# /24 → 호스트 비트 8 → 2^8 - 2 = 254 대
# /26 → 호스트 비트 6 → 2^6 - 2 = 62 대
# /30 → 호스트 비트 2 → 2^2 - 2 = 2 대 (라우터 간 연결용)
```

**2) 네트워크 주소·브로드캐스트 주소 구하기 (예: 192.168.1.0/26)**

- /26은 **블록 크기 64**. 마지막 옥텟이 0, 64, 128, 192 단위로 서브넷이 나뉜다.

```bash
# 192.168.1.0/26 의 첫 번째 서브넷
네트워크 주소    : 192.168.1.0      (호스트 비트 전부 0)
첫 사용 가능 주소 : 192.168.1.1
마지막 사용 가능 : 192.168.1.62
브로드캐스트     : 192.168.1.63     (호스트 비트 전부 1)
# 다음 서브넷은 192.168.1.64/26, 그 다음 192.168.1.128/26 ...
```

> 🔍 **핵심 구분**: 어떤 IP가 속한 네트워크 주소는 "블록 크기의 배수 중 그 IP보다 작거나 같은 가장 큰 값"이다. 예: 192.168.1.100/26은 블록 크기 64 → 64의 배수(0,64,128,192) 중 100 이하 최대는 64 → 네트워크 주소 192.168.1.64, 브로드캐스트 192.168.1.127. 이 계산이 실기 단골이다.

**3) 직접 쳐보기 — ipcalc로 검산**

```bash
# ipcalc는 서브넷 계산을 자동으로 보여준다 (없으면 설치)
ipcalc 192.168.1.100/26
# Network:   192.168.1.64/26
# HostMin:   192.168.1.65
# HostMax:   192.168.1.126
# Broadcast: 192.168.1.127
# Hosts/Net: 62
```

- 손으로 먼저 계산하고 `ipcalc`로 **검산**하는 습관을 들이면, 시험장에서 도구 없이도 빠르고 정확하게 풀 수 있다.

> ⚠️ **함정**: "/31"은 호스트 비트가 1개라 2^1−2 = 0이 되어 일반적으로 호스트를 못 담지만, RFC 3021에 따라 라우터 간 점대점 링크에서는 예외적으로 2개 주소를 모두 쓴다. 시험에서는 "/30은 2대, /29는 6대"처럼 −2 공식을 적용하는 문제가 표준이다.

내일(Day 2)부터 배울 `ip addr`, 게이트웨이, 라우팅은 전부 오늘 세운 3계층 위에서 동작한다.

## 📖 용어

- **캡슐화 / 역캡슐화** : 데이터가 아래 계층으로 내려가며 헤더가 붙는 것 / 위로 올라가며 벗겨지는 것.
- **PDU** : 각 계층이 다루는 데이터 단위. 4계층은 세그먼트, 3계층은 패킷, 2계층은 프레임, 1계층은 비트.
- **MAC 주소** : 2계층의 물리 주소. 장비에 새겨진 고유 번호로 같은 네트워크 안에서만 쓰인다.
- **3-way handshake** : TCP가 연결을 맺는 SYN → SYN/ACK → ACK 3단계 절차. 종료는 FIN/ACK 두 쌍(4-way)이다.
- **옥텟(octet)** : IPv4 주소를 이루는 8비트 묶음. 32비트가 네 덩어리로 나뉜다.
- **루프백(127.0.0.1)** : 자기 자신을 가리키는 주소. A 클래스 범위에 있지만 호스트에 할당하지 않는다.
- **사설 IP** : 인터넷으로 라우팅되지 않고 내부망에서만 쓰는 주소(10/8, 172.16~31, 192.168).
- **APIPA(169.254.x.x)** : DHCP 서버를 못 찾은 호스트가 스스로 붙이는 링크 로컬 주소. 인터넷이 안 되는 신호다.
- **서브넷마스크** : IP에서 네트워크 부분과 호스트 부분의 경계를 알려주는 32비트 값. 1은 네트워크, 0은 호스트.
- **CIDR(`/24`)** : 마스크의 1 개수를 슬래시 뒤에 적는 표기. `/24`면 255.255.255.0이다.
- **블록 크기** : 그 CIDR로 서브넷이 나뉘는 간격. /26이면 64씩(0·64·128·192) 끊긴다.
- **네트워크 주소 / 브로드캐스트 주소** : 호스트 비트가 전부 0인 주소 / 전부 1인 주소. 둘 다 호스트에 못 준다.

## 📝 연습 문제

**문제 1.** OSI 7계층 중 IP 주소를 기반으로 패킷의 경로를 결정(라우팅)하는 계층은?

A) 2계층(데이터링크) — MAC 주소로 프레임을 전달

B) 3계층(네트워크) — IP 주소로 패킷을 라우팅

C) 4계층(전송) — 포트 번호로 종단 간 연결

D) 7계층(응용) — 사용자에게 서비스 제공

**정답: B**

해설: IP 주소 기반 라우팅은 3계층(네트워크)의 책임이며 대표 장비가 라우터다. A(2계층)는 MAC 주소로 같은 네트워크 내 프레임을 전달하고, C(4계층)는 포트로 종단 간 신뢰성을, D(7계층)는 응용 서비스를 담당한다. "IP·라우터=3계층, MAC·스위치=2계층"의 구분이 핵심이다.

**문제 2.** 192.168.10.0/26 네트워크에서 사용 가능한(호스트에 할당 가능한) IP 주소의 개수는?

A) 64개

B) 62개

C) 32개

D) 30개

**정답: B**

해설: /26은 호스트 비트가 6개이므로 2^6 − 2 = 62개다. −2는 네트워크 주소(호스트 비트 전부 0)와 브로드캐스트 주소(전부 1)를 제외하기 때문이다. A(64)는 −2를 빼지 않은 전체 블록 크기, C(32)는 /27의 블록 크기, D(30)는 /27의 사용 가능 호스트 수다.

**문제 3.** IP 주소 172.20.5.130/25가 속한 네트워크의 브로드캐스트 주소는?

A) 172.20.5.127

B) 172.20.5.128

C) 172.20.5.255

D) 172.20.5.191

**정답: C**

해설: /25는 블록 크기 128이라 서브넷이 0과 128 단위로 나뉜다. 130은 128~255 범위에 속하므로 네트워크 주소는 172.20.5.128, 브로드캐스트는 그 블록의 마지막인 172.20.5.255다. A(127)는 첫 번째 서브넷(0~127)의 브로드캐스트, B(128)는 두 번째 서브넷의 네트워크 주소, D(191)는 /26 블록의 경계라 틀리다.

**문제 4.** 다음 중 사설 IP 주소가 아닌 것은?

A) 10.50.0.1

B) 172.16.200.5

C) 192.168.1.100

D) 172.32.0.1

**정답: D**

해설: B 클래스 사설 대역은 172.16.0.0 ~ 172.31.255.255이므로 172.32.0.1은 이 범위를 벗어나 공인 IP다. A(10.x)는 A 클래스 사설, C(192.168.x)는 C 클래스 사설, B(172.16.x)는 B 클래스 사설 대역에 정확히 속한다. 172 대역은 16~31까지만 사설이라는 경계가 함정이다.

**문제 5.** TCP와 UDP에 대한 설명으로 옳은 것은?

A) TCP는 비연결형이고 UDP는 3-way handshake로 연결을 맺는다

B) TCP는 신뢰성을 보장하는 연결 지향 프로토콜이고, UDP는 비연결형으로 속도가 빠르다

C) 둘 다 연결을 맺은 뒤 데이터를 전송하며 신뢰성이 동일하다

D) UDP는 재전송과 순서 제어를 수행하고 TCP는 하지 않는다

**정답: B**

해설: TCP는 3-way handshake로 연결을 맺고 재전송·순서·흐름 제어로 신뢰성을 보장하며, UDP는 비연결형이라 그런 절차 없이 빠르게 전송한다. A는 둘을 정반대로 서술했고, C는 신뢰성이 동일하다는 점이 틀렸으며, D는 재전송·순서 제어를 수행하는 쪽이 TCP이므로 뒤바뀌었다.

**문제 6.** CIDR 표기 /28에 해당하는 서브넷마스크로 옳은 것은?

A) 255.255.255.192

B) 255.255.255.224

C) 255.255.255.240

D) 255.255.255.248

**정답: C**

해설: /28은 마지막 옥텟에 1이 4개(11110000)이므로 240이다. 1의 개수에 따른 옥텟 값 수열(128·192·224·240·248·252)에서 4개째가 240이다. A(192)는 /26, B(224)는 /27, D(248)는 /29에 해당한다. "/28 → 240, 호스트 16개 중 사용 14개"로 묶어 기억하면 좋다.

**문제 7.** 호스트의 IP가 169.254.12.34로 자동 설정되고 인터넷이 되지 않는 상황의 가장 가능성 높은 원인은?

A) 정상적인 공인 IP가 할당된 상태다

B) DHCP 서버로부터 주소를 받지 못해 APIPA(링크 로컬) 주소가 자동 부여되었다

C) 루프백 주소가 잘못 설정되었다

D) 서브넷마스크가 /8로 설정되어 있다

**정답: B**

해설: 169.254.0.0/16은 APIPA(링크 로컬) 대역으로, 호스트가 DHCP 서버를 찾지 못했을 때 스스로 부여하는 주소다. 따라서 게이트웨이를 모르므로 인터넷이 되지 않는다. A는 공인 IP가 아니며, C의 루프백은 127.0.0.0/8 대역이고, D의 마스크 문제와는 무관하다. "169.254 = DHCP 실패 신호"로 기억한다.
