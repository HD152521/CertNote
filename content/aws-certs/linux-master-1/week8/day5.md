# Day 5 - Week 8 종합 복습: 네트워크를 계층 한 장으로 꿰기

## 📌 핵심 정리

- 네트워크의 모든 것은 **"몇 계층에서, 어느 주소로, 어느 경로를 거쳐, 어떤 이름으로"** 통신하는가로 환원된다.
- 계층이 곧 진단 내비게이션 — MAC 안 풀리면 `arp`(2), 도달 안 되면 `ping`(3), 포트 안 열리면 `ss`(4), 이름 안 풀리면 `dig`(7).
- 서브넷 3단계: **호스트 수 = 2^(호스트 비트) − 2**, **네트워크 주소 = 블록 크기 배수 중 IP 이하 최댓값**, **브로드캐스트 = 그 블록의 마지막**.
- 경계 함정 두 개: **169.254는 사설 IP가 아니라 APIPA(DHCP 실패)**, **172 사설은 16~31까지만**.
- **임시(`ip`·`ifconfig`·resolv.conf 직접 수정) vs 영구(`ifcfg`·`nmcli con mod`)** 구분이 이번 주 최대 출제 포인트다.

## 계층 모델 — 장비·프로토콜·도구를 한 표로

| 계층 | 주소/단위 | 장비 | 프로토콜 | 진단 도구 |
|------|-----------|------|----------|-----------|
| 7 응용 | 데이터 | L7 스위치 | HTTP, DNS, DHCP, SSH | dig, nslookup |
| 4 전송 | 포트/세그먼트 | L4 스위치 | TCP, UDP | ss, netstat |
| 3 네트워크 | IP/패킷 | 라우터 | IP, ICMP | ping, traceroute |
| 2 데이터링크 | MAC/프레임 | 스위치, 브리지 | ARP, 이더넷 | arp, ip neigh |
| 1 물리 | 비트 | 허브, 리피터 | — | (케이블·링크 확인) |

기억 고정 포인트:

- IP·라우터·ping = 3계층, MAC·스위치·ARP = 2계층, 포트·TCP/UDP·ss = 4계층
- 허브(1)는 신호만, 스위치(2)는 MAC 학습, 라우터(3)는 IP 라우팅·브로드캐스트 분리
- DNS·DHCP는 7계층 응용 프로토콜

> 💡 **개념**: "이건 몇 계층 문제인가"를 먼저 물으면 검사 도구가 자동으로 정해진다. MAC 안 풀리면 arp(2), 도달 안 되면 ping(3), 포트 안 열리면 ss(4), 이름 안 풀리면 dig(7). 계층이 진단의 내비게이션이다.

## IP 클래스·사설 대역·CIDR 복습

| 클래스 | 첫 옥텟 | 기본 마스크 | 사설 대역 |
|--------|---------|-------------|-----------|
| A | 1~126 | /8 (255.0.0.0) | 10.0.0.0/8 |
| B | 128~191 | /16 (255.255.0.0) | 172.16.0.0/12 |
| C | 192~223 | /24 (255.255.255.0) | 192.168.0.0/16 |

기억 고정 포인트:

- 127.x = 루프백(localhost), 169.254.x = APIPA(DHCP 실패 신호)
- 172 사설은 16~31까지만, 192.168은 전체가 사설
- 마스크 옥텟 수열: **128 · 192 · 224 · 240 · 248 · 252 · 254 · 255**

> ⚠️ **함정 복습**: 169.254.x.x는 사설 IP가 아니라 APIPA(링크 로컬)이며 "DHCP 서버를 못 찾았다"는 신호다. 172.32.x.x는 사설 대역(16~31)을 벗어나 공인 IP다. 이 두 경계가 단골 함정이다.

## 서브넷 계산 — 손으로 푸는 3단계

| 계산 | 공식 |
|------|------|
| 사용 가능 호스트 수 | 2^(호스트 비트) − 2 |
| 네트워크 주소 | 블록 크기의 배수 중 IP 이하 최댓값 |
| 브로드캐스트 주소 | 다음 네트워크 주소 − 1 (블록의 마지막) |

```bash
# 예: 192.168.1.200/26 분석
# /26 → 호스트 비트 6 → 2^6 - 2 = 62대, 블록 크기 64
# 64의 배수(0,64,128,192) 중 200 이하 최대 = 192
네트워크 주소    : 192.168.1.192
사용 가능 범위   : 192.168.1.193 ~ 192.168.1.254
브로드캐스트     : 192.168.1.255
```

> 🔍 **핵심 구분**: 호스트 수에서 **−2**는 네트워크 주소(호스트 비트 전부 0)와 브로드캐스트(전부 1)를 호스트에 못 주기 때문이다. /30은 2대(라우터 간 연결), /29는 6대, /28은 14대, /26은 62대. 이 값들을 즉답할 수 있어야 한다.

## 임시 vs 영구 설정 — 명령의 수명 복습

| 작업 | 임시(재부팅 시 소멸) | 영구 |
|------|----------------------|------|
| IP 부여 | `ip addr add` / `ifconfig` | ifcfg-eth0 / `nmcli con mod` |
| 게이트웨이 | `ip route add default` | ifcfg의 GATEWAY |
| DNS | resolv.conf 직접 수정(덮어쓰기 위험) | ifcfg의 DNS1/2 / `nmcli ... ipv4.dns` |

> ⚠️ **함정 복습**: NetworkManager 환경에서 resolv.conf 직접 수정은 재부팅·재시작 시 사라진다. ONBOOT=no면 설정이 맞아도 부팅 후 인터페이스가 안 올라온다. "임시는 ip/ifconfig, 영구는 ifcfg/nmcli"를 항상 구분하라.

## 진단 흐름 — 가까운 곳에서 먼 곳으로

```bash
ping 127.0.0.1     # 1. TCP/IP 스택 정상?
ping 192.168.1.1   # 2. 게이트웨이(L2/L3)?
ping 8.8.8.8       # 3. 외부 IP(라우팅/방화벽)?
ping google.com    # 4. DNS?
ss -tlnp           # 5. 로컬 서비스 포트?
```

> 💡 **개념**: 어느 단계에서 처음 막히느냐가 곧 문제 위치다. 3까지 되고 4가 안 되면 DNS, 2까지 되고 3이 안 되면 게이트웨이 밖 라우팅/방화벽이다. "IP는 되는데 도메인이 안 됨" = DNS의 확정 신호.

## 프로토콜·포트 빠른 복습

| 포트 | 프로토콜 | 포트 | 프로토콜 |
|------|----------|------|----------|
| 22 | SSH(암호화) | 53 | DNS(UDP/TCP) |
| 23 | Telnet(평문) | 67/68 | DHCP |
| 25 | SMTP | 80 | HTTP |
| 21 | FTP | 443 | HTTPS |

> 📚 **유래/사례**: 실무 트러블슈팅의 첫 질문도 정확히 이번 주 내용이다 — "IP는 맞나(Day1·2), 게이트웨이는 닿나(Day2·3), DNS는 풀리나(Day2·3), 어느 계층 장비 문제인가(Day4)". 네트워크 장애의 90%는 이 네 가지 안에서 진단된다. 이번 주는 시험을 넘어 실무 네트워킹의 기초다.

## 📖 용어

- **계층(layer)** : 통신 책임을 나눈 단계. 문제의 위치와 검사 도구를 동시에 결정한다.
- **충돌 도메인 / 브로드캐스트 도메인** : 프레임이 부딪힐 수 있는 범위(스위치가 나눔) / 브로드캐스트가 퍼지는 범위(라우터·VLAN만 나눔).
- **블록 크기** : 그 CIDR로 서브넷이 끊기는 간격. /26이면 64, /27이면 32, /28이면 16이다.
- **−2 규칙** : 호스트 수를 셀 때 네트워크 주소와 브로드캐스트 주소를 빼는 것. 둘 다 호스트에 못 준다.
- **마스크 옥텟 수열** : 128 · 192 · 224 · 240 · 248 · 252 · 254 · 255. 1의 개수만큼 왼쪽부터 채운 값이다.
- **APIPA(169.254.x.x)** : DHCP 실패 시 호스트가 스스로 붙이는 주소. 사설 IP가 아니다.
- **임시 설정 / 영구 설정** : 재부팅하면 사라지는 명령(`ip`·`ifconfig`) / 파일에 남는 설정(`ifcfg`·`nmcli`).
- **`ONBOOT`** : 부팅 시 인터페이스를 자동으로 올릴지 정하는 ifcfg 항목. `no`면 네트워크가 안 붙는다.
- **DORA** : DHCP의 Discover → Offer → Request → Acknowledge 4단계.
- **ARP의 동작 범위** : 같은 L2 네트워크 안에서만. 다른 네트워크로 갈 때는 게이트웨이의 MAC을 쓴다.
- **active-backup / LACP** : 장애 시 넘어가는 이중화 모드 / 여러 링크를 묶어 대역폭을 늘리는 모드.

**문제 1.** OSI 7계층에서 라우터가 동작하는 계층과 그 핵심 기능으로 옳은 것은?

A) 2계층 — MAC 주소로 프레임을 전달한다

B) 3계층 — IP 주소를 기반으로 네트워크 간 경로를 결정한다

C) 4계층 — 포트 번호로 종단 간 연결을 관리한다

D) 1계층 — 신호를 증폭한다

**정답: B**

해설: 라우터는 3계층(네트워크)에서 IP 주소를 보고 다른 네트워크로 패킷을 라우팅하며 브로드캐스트 도메인을 분리한다. A는 2계층 스위치의 기능, C는 4계층 전송의 역할, D는 1계층 리피터의 기능이다. "IP·라우터=3계층"이 핵심이다.

**문제 2.** 192.168.10.0/27 네트워크에서 사용 가능한 호스트 수는?

A) 32개

B) 30개

C) 14개

D) 62개

**정답: B**

해설: /27은 호스트 비트가 5개이므로 2^5 − 2 = 30개다. A(32)는 −2를 빼지 않은 블록 크기, C(14)는 /28의 사용 가능 수, D(62)는 /26의 사용 가능 수다. −2는 네트워크 주소와 브로드캐스트를 제외하기 때문이다.

**문제 3.** IP 주소 10.1.1.100/26이 속한 네트워크의 네트워크 주소와 브로드캐스트 주소로 옳은 것은?

A) 네트워크 10.1.1.64, 브로드캐스트 10.1.1.127

B) 네트워크 10.1.1.96, 브로드캐스트 10.1.1.127

C) 네트워크 10.1.1.64, 브로드캐스트 10.1.1.95

D) 네트워크 10.1.1.0, 브로드캐스트 10.1.1.63

**정답: A**

해설: /26은 블록 크기 64라 서브넷이 0·64·128·192로 나뉜다. 100은 64~127 범위이므로 네트워크 주소는 64의 배수 중 100 이하 최대인 10.1.1.64, 브로드캐스트는 그 블록의 마지막인 10.1.1.127이다. B·C·D는 블록 경계를 잘못 잡았다.

**문제 4.** 다음 중 사설 IP 주소가 아닌 것은?

A) 192.168.50.1

B) 10.255.1.1

C) 172.31.255.254

D) 172.32.1.1

**문제 5.** Red Hat 계열에서 재부팅 후에도 유지되는 정적 IP 설정 방법으로 옳은 것은?

A) `ip addr add 10.0.0.5/24 dev eth0`만 실행한다

B) `ifcfg-eth0` 파일에 IPADDR·NETMASK·ONBOOT=yes를 설정하거나 `nmcli con mod`를 사용한다

C) `/etc/resolv.conf`에 IPADDR을 추가한다

D) `ifconfig eth0 10.0.0.5`만 실행한다

**정답: B**

해설: 영구 설정은 `ifcfg-eth0` 파일 또는 `nmcli con mod`로 해야 한다. A와 D는 임시 설정이라 재부팅 시 사라지고, C의 resolv.conf는 IP가 아니라 DNS 서버를 지정하는 파일이다. "임시(ip/ifconfig) vs 영구(ifcfg/nmcli)" 구분이 핵심이다.

**문제 6.** 현재 LISTEN 중인 TCP 포트와 점유 프로세스를 함께 확인하는 명령은?

A) `ss -tlnp`

B) `ping -c 4 localhost`

C) `dig localhost`

D) `arp -n`

**정답: A**

**문제 7.** `ping 8.8.8.8`은 성공하지만 `ping google.com`은 실패한다. 원인과 확인 도구로 옳은 것은?

A) 게이트웨이 문제이며 `traceroute`로 확인한다

B) DNS 문제이며 `dig` 또는 resolv.conf의 nameserver를 확인한다

C) 인터페이스 다운이며 `ip link`로 확인한다

D) 방화벽 문제이며 `tcpdump`로 확인한다

**정답: B**

해설: IP로는 통신이 되므로 연결·게이트웨이·인터페이스는 정상이고, 도메인만 실패하므로 이름 해석(DNS) 문제다. `dig`로 질의하거나 resolv.conf의 nameserver를 점검한다. A·C·D가 원인이면 IP ping부터 실패했을 것이므로 모두 제외된다.

**문제 8.** 받은 프레임을 모든 포트로 전달하여 충돌 도메인을 공유하는 1계층 장비는?

A) 스위치

B) 라우터

C) 허브

D) 브리지

**정답: C**

해설: 허브는 1계층 장비로 받은 신호를 모든 포트에 뿌려 충돌 도메인을 공유하므로 비효율적이다. A(스위치)는 2계층에서 MAC을 학습해 해당 포트로만 보내고, B(라우터)는 3계층, D(브리지)는 2계층에서 세그먼트를 나눈다. 허브와 스위치의 차이는 단골 출제 포인트다.

**문제 9.** DHCP 주소 할당 과정(DORA)과 사용 포트로 옳은 것은?

A) Discover-Offer-Request-Acknowledge, 서버 UDP 67 / 클라이언트 UDP 68

B) Offer-Discover-Request-Acknowledge, TCP 80

C) Discover-Request-Offer-Acknowledge, UDP 53

D) Request-Acknowledge-Discover-Offer, TCP 67

**정답: A**

해설: DHCP는 Discover-Offer-Request-Acknowledge(DORA) 순으로 동작하며 서버는 UDP 67, 클라이언트는 UDP 68을 쓴다. B는 순서·포트가 모두 틀리고(80은 HTTP), C는 순서가 뒤바뀌고 포트 53은 DNS이며, D는 순서가 잘못되고 DHCP는 TCP가 아닌 UDP를 쓴다.

**문제 10.** 두 개의 NIC을 묶어 평소 하나만 쓰다가 장애 시 다른 NIC으로 자동 전환하는 이중화 본딩 모드는?

A) balance-rr (mode 0)

B) active-backup (mode 1)

C) broadcast (mode 3)

D) 802.3ad/LACP (mode 4)

**정답: B**

해설: active-backup(mode 1)은 한 NIC만 활성으로 쓰다가 장애 시 백업으로 자동 전환하는 이중화 모드다. A·D는 대역폭 증가·부하분산용이고, C(broadcast)는 모든 슬레이브로 동일 프레임을 보내는 특수 용도다. "이중화=active-backup, 대역폭=LACP"로 구분한다.

**문제 11.** 같은 서브넷의 호스트 통신 시 IP에 해당하는 MAC을 알아내는 프로토콜과, 그 동작 범위로 옳은 것은?

A) DNS — 인터넷 전역에서 도메인을 IP로 변환

B) ARP — 같은 로컬 네트워크(L2) 안에서 IP를 MAC으로 변환하며, 다른 네트워크 대상은 게이트웨이의 MAC을 사용

C) ICMP — 전 계층에서 포트를 변환

D) DHCP — IP를 MAC으로 영구 매핑

**정답: B**

해설: ARP는 같은 L2 네트워크 안에서 IP를 MAC으로 변환하고, 다른 네트워크 대상은 상대가 아닌 게이트웨이의 MAC을 알아낸다. A(DNS)는 도메인→IP, C(ICMP)는 도달성·오류 메시지로 포트 변환과 무관하며, D(DHCP)는 IP 자동 할당이라 IP↔MAC 영구 매핑이 아니다.

**문제 12.** CIDR /29 네트워크에 대한 설명으로 옳은 것은?

A) 사용 가능 호스트가 8대이며 서브넷마스크는 255.255.255.240이다

B) 사용 가능 호스트가 6대이며 서브넷마스크는 255.255.255.248이다

C) 사용 가능 호스트가 14대이며 서브넷마스크는 255.255.255.224이다

D) 사용 가능 호스트가 2대이며 서브넷마스크는 255.255.255.252이다

**정답: B**

해설: /29는 호스트 비트가 3개이므로 2^3 − 2 = 6대이며, 마지막 옥텟에 1이 5개(11111000)라 248이다. A(8대)는 −2를 빼지 않은 블록 크기이고 240은 /28, C(14대·224)는 /28 호스트 수와 /27 마스크가 섞였으며, D(2대·252)는 /30의 값이다.
