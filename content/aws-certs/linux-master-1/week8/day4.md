# Day 4 - 네트워크 장비·프로토콜·이중화: 계층으로 꿰는 인프라

## 📌 핵심 정리

- **장비와 프로토콜은 동작 계층이 정해져 있고, 그 계층이 곧 능력과 한계를 결정한다.**
- 허브·리피터(1계층)는 신호만, **스위치(2계층)는 MAC**, **라우터(3계층)는 IP**. **브로드캐스트 도메인은 라우터(또는 VLAN)만 나눈다.**
- 프로토콜 매핑: **ARP**(IP→MAC, 로컬만) · **ICMP**(도달성·경로, 3계층) · **DNS**(이름, **53 UDP+TCP**) · **DHCP**(주소, **67/68 UDP**, DORA 4단계).
- 포트는 TCP/UDP 짝까지 외운다 — 21 FTP · 22 SSH · 23 Telnet(평문) · 25 SMTP · 53 DNS · 80 HTTP · 443 HTTPS · 110/143 POP3/IMAP.
- NIC 묶기: **이중화는 active-backup(mode 1)**, **대역폭 집계는 balance-rr(0)·802.3ad LACP(4)**. **본딩은 커널 모듈, 티밍은 사용자 공간 데몬(teamd)**.

## OSI 계층별 네트워크 장비 — 능력은 계층이 결정한다

| 장비 | 동작 계층 | 핵심 기능 | 한계/특징 |
|------|-----------|-----------|-----------|
| 리피터(Repeater) | 1 (물리) | 약해진 신호 증폭·재생 | 신호만 키움, 구분 능력 없음 |
| 허브(Hub) | 1 (물리) | 여러 포트로 신호 분배 | 받은 신호를 **모든 포트로** 전송(브로드캐스트), 충돌 도메인 공유 |
| 브리지(Bridge) | 2 (데이터링크) | MAC 기반 세그먼트 연결 | 충돌 도메인 분리(소프트웨어 처리, 느림) |
| 스위치(Switch) | 2 (데이터링크) | MAC 주소 학습 후 해당 포트로만 전송 | 포트별 충돌 도메인 분리(하드웨어, 빠름) |
| 라우터(Router) | 3 (네트워크) | IP 기반 네트워크 간 경로 결정 | 브로드캐스트 도메인 분리, 다른 네트워크 연결 |
| L4/L7 스위치 | 4~7 | 포트·애플리케이션 기반 부하분산 | 로드밸런서 역할 |

> 💡 **개념**: 핵심 비교는 **허브 vs 스위치**다. 허브는 받은 프레임을 모든 포트로 뿌려(대역폭 공유·충돌 발생) 비효율적이고, 스위치는 **MAC 주소 테이블**을 학습해 목적지 포트로만 보낸다(충돌 없음·전용 대역폭). "스위치는 MAC을 보고 라우터는 IP를 본다"가 핵심 한 줄이다.

> 🔍 **핵심 구분**: **충돌 도메인 vs 브로드캐스트 도메인.** 스위치는 포트마다 충돌 도메인을 나누지만 브로드캐스트는 모든 포트로 전달한다(브로드캐스트 도메인은 하나). **라우터**가 비로소 브로드캐스트 도메인을 나눈다. 그래서 "브로드캐스트 범위를 줄이려면 라우터(또는 VLAN)"가 답이다.

> 📚 **유래/사례**: 1990년대 초 LAN은 허브가 표준이었지만, 호스트가 늘수록 충돌이 폭증해 성능이 급락했다. 스위치(MAC 학습)가 등장하며 각 포트가 전용 대역폭을 갖게 되어 충돌 문제가 사라졌다. 오늘날 "허브"는 사실상 사라졌고 모든 LAN 스위칭이 스위치 기반이다 — 시험에서는 이 둘의 차이를 개념적으로 묻는다.

## ARP — IP를 MAC으로 바꾸는 다리 (2~3계층 경계)

- 같은 네트워크에서 통신하려면 상대의 IP뿐 아니라 **MAC 주소**를 알아야 한다 — 실제 프레임 전달은 2계층 MAC으로 하기 때문이다.
- ARP가 **"이 IP를 가진 호스트의 MAC이 뭐냐"를 브로드캐스트로 물어** 알아낸다.

```bash
# ARP 동작: "192.168.1.1의 MAC을 아는 사람?" (브로드캐스트)
#          → 해당 호스트가 "내 MAC은 aa:bb:..." (유니캐스트 응답)

arp -n              # ARP 캐시(IP↔MAC) 확인
ip neigh show       # 현대식
```

| 프로토콜 | 방향 | 역할 |
|----------|------|------|
| ARP | IP → MAC | IP를 알 때 MAC을 알아냄 |
| RARP | MAC → IP | MAC을 알 때 IP를 알아냄(과거, DHCP로 대체) |

> ⚠️ **함정**: ARP는 같은 **로컬 네트워크(L2)** 안에서만 직접 동작한다. 다른 네트워크의 호스트와 통신할 때는 상대 IP의 MAC이 아니라 **게이트웨이의 MAC**을 알아낸다. "다른 서브넷 호스트의 MAC이 ARP 테이블에 없다"는 정상이며, 그 트래픽은 게이트웨이를 거쳐 라우팅된다.

## ICMP — 제어·오류 메시지 (3계층)

- ICMP는 데이터를 나르지 않고 **네트워크 상태·오류를 알리는** 3계층 프로토콜이다.
- `ping`과 `traceroute`가 모두 이 프로토콜 위에서 동작한다.

| ICMP 메시지 | 의미 | 관련 도구 |
|-------------|------|-----------|
| Echo Request/Reply | 도달성 확인(ping) | ping |
| Time Exceeded | TTL 0 도달(경로 추적) | traceroute |
| Destination Unreachable | 목적지 도달 불가 | — |
| Redirect | 더 나은 경로 안내 | — |

> 💡 **개념**: `traceroute`가 경로를 그릴 수 있는 건 ICMP **Time Exceeded** 덕분이다. TTL을 1부터 늘리면 각 라우터가 TTL=0이 될 때 "시간 초과" 메시지를 보내고, 그 출처가 곧 해당 홉의 주소다. ICMP는 도달성·경로 진단의 기반 프로토콜이다.

## DNS — 이름을 주소로 (7계층, 포트 53)

- DNS는 사람이 읽는 도메인(google.com)을 **IP로 변환하는 분산 시스템**이다.
- 7계층 응용 프로토콜이며 보통 **UDP 53번** 포트를 쓴다(큰 응답은 TCP).

```bash
# 질의 흐름: 로컬 캐시 → /etc/hosts → resolv.conf의 네임서버 → 루트→TLD→권한 서버
dig google.com +short
host google.com
```

| 레코드 | 역할 |
|--------|------|
| A / AAAA | 도메인 → IPv4 / IPv6 |
| MX | 메일 서버 |
| NS | 권한 네임서버 |
| CNAME | 별칭 |
| PTR | 역방향(IP→도메인) |

> 🔍 **핵심 구분**: DNS는 기본 **UDP 53**을 쓰지만, 응답이 크거나(512바이트 초과) 영역 전송(zone transfer)일 때는 **TCP 53**을 쓴다. "DNS는 UDP만 쓴다"는 흔한 오답이다. 포트 번호 53과 UDP/TCP 둘 다 쓴다는 점을 기억하라.

## DHCP — 주소 자동 분배 (7계층, 포트 67/68)

- DHCP는 호스트에게 **IP·서브넷마스크·게이트웨이·DNS를 자동으로 할당**하는 프로토콜이다.
- 포트는 서버가 **UDP 67**, 클라이언트가 **UDP 68**.

```bash
# DHCP 4단계 (DORA)
# Discover  → 클라이언트: "DHCP 서버 있나요?" (브로드캐스트)
# Offer     → 서버: "이 IP 줄게요"
# Request   → 클라이언트: "그 IP 쓸게요"
# Acknowledge → 서버: "확정"

# 리눅스에서 DHCP로 주소 갱신
dhclient eth0          # 주소 요청
dhclient -r eth0       # 주소 반납(release)
```

> 💡 **개념**: DHCP 4단계는 **DORA**(Discover-Offer-Request-Acknowledge)로 외운다. 이 과정이 실패하면 호스트는 169.254.x.x(APIPA) 주소를 스스로 부여한다(Day 1 참고). "IP가 169.254로 시작" = DHCP의 DORA가 실패했다는 신호다.

> 📚 **유래/사례**: DHCP 이전에는 관리자가 모든 호스트에 IP를 손으로 적었다(정적 할당). 노트북·휴대폰처럼 이동하는 기기가 늘면서 자동 할당이 필수가 되었다. DHCP는 RARP·BOOTP를 발전시킨 것으로, 오늘날 거의 모든 LAN/Wi-Fi가 DHCP로 주소를 나눠준다.

## 주요 프로토콜·포트 한눈에

| 프로토콜 | 포트 | 전송 | 계층 | 용도 |
|----------|------|------|------|------|
| FTP | 20/21 | TCP | 7 | 파일 전송 |
| SSH | 22 | TCP | 7 | 원격 접속(암호화) |
| Telnet | 23 | TCP | 7 | 원격 접속(평문) |
| SMTP | 25 | TCP | 7 | 메일 송신 |
| DNS | 53 | UDP/TCP | 7 | 이름 해석 |
| DHCP | 67/68 | UDP | 7 | 주소 자동 할당 |
| HTTP | 80 | TCP | 7 | 웹 |
| HTTPS | 443 | TCP | 7 | 암호화 웹 |
| POP3 / IMAP | 110 / 143 | TCP | 7 | 메일 수신 |

> ⚠️ **함정**: **SSH(22)와 Telnet(23)** 모두 원격 접속이지만 Telnet은 평문, SSH는 암호화다. 보안상 Telnet은 쓰지 않는다. **DNS만 UDP 기본**, 나머지 위 목록은 대부분 TCP다. 포트 번호와 TCP/UDP 짝을 함께 외워야 한다.

## 본딩(Bonding)·티밍(Teaming) — 인터페이스를 묶어 가용성·대역폭 확보

- 여러 물리 NIC을 **하나의 논리 인터페이스로 묶어** 장애 대비(이중화)나 대역폭 증가를 얻는 기술이다.
- Red Hat 계열의 전통적 방식은 **본딩**, 최신 방식은 **티밍**.

```bash
# 본딩 인터페이스 확인
cat /proc/net/bonding/bond0

# nmcli로 본딩 생성
nmcli con add type bond con-name bond0 ifname bond0 mode active-backup
nmcli con add type bond-slave ifname eth0 master bond0
nmcli con add type bond-slave ifname eth1 master bond0
```

| 본딩 모드 | 번호 | 동작 |
|-----------|------|------|
| balance-rr | 0 | 라운드로빈(부하분산) |
| active-backup | 1 | 하나만 활성, 장애 시 자동 전환(이중화) |
| balance-xor | 2 | 출발지/목적지 기준 분산 |
| broadcast | 3 | 모든 슬레이브로 전송 |
| 802.3ad(LACP) | 4 | 스위치와 협상해 링크 집계 |

| 구분 | 본딩(Bonding) | 티밍(Teaming) |
|------|---------------|---------------|
| 구현 | 커널 모듈(bonding) | 사용자 공간 데몬(teamd) |
| 등장 | 전통적 | 최신(RHEL7+) |
| 설정 | 모드(0~6) | runner(activebackup, loadbalance 등) |

> 💡 **개념**: 가장 자주 쓰는 모드는 **active-backup(mode 1)** — 한 NIC만 쓰다가 죽으면 다른 NIC으로 자동 전환하는 **이중화**다. 대역폭을 늘리려면 **balance-rr(0)**나 **802.3ad(4, LACP)**를 쓴다. "이중화=active-backup, 대역폭 집계=LACP"로 구분한다.

> 🔍 **핵심 구분**: **본딩은 커널 모듈**, **티밍은 사용자 공간 데몬(teamd)**으로 구현된다. 기능은 유사하나 티밍이 더 유연하고 확장적이다. 시험에서 "둘의 차이"를 물으면 구현 위치(커널 vs 유저스페이스)와 등장 시기(전통 vs RHEL7 이후)가 답이다.

## 직접 쳐보기 — 계층별 장비·프로토콜 확인

```bash
# 2계층: MAC 주소와 ARP 테이블
ip link show                  # 인터페이스 MAC 확인
arp -n                        # IP↔MAC 매핑

# 3계층: ICMP 도달성과 경로
ping -c 2 8.8.8.8             # ICMP Echo
traceroute -n 8.8.8.8        # ICMP Time Exceeded로 경로

# 7계층: DNS·DHCP
dig google.com +short        # DNS 질의(UDP 53)
cat /proc/net/bonding/bond0  # 본딩 상태(있을 때)
```

- 각 명령이 **어느 계층의 장비·프로토콜을 건드리는지** 의식하며 실행하면 장비-프로토콜-계층의 삼각 매핑이 손에 익는다.
- 정리하면 하나의 지도가 된다: **1계층(허브·리피터) → 2계층(스위치·브리지·ARP·MAC) → 3계층(라우터·IP·ICMP) → 7계층(DNS·DHCP·HTTP)**, 그 위에 가용성을 더하는 본딩·티밍.

## 📖 용어

- **리피터 / 허브** : 약해진 신호를 증폭하는 1계층 장비 / 받은 신호를 모든 포트로 뿌리는 1계층 장비.
- **스위치** : MAC 주소 테이블을 학습해 목적지 포트로만 프레임을 보내는 2계층 장비.
- **충돌 도메인** : 프레임이 서로 부딪힐 수 있는 범위. 스위치가 포트마다 나눠 준다.
- **브로드캐스트 도메인** : 브로드캐스트가 퍼지는 범위. **라우터(또는 VLAN)만 나눌 수 있다.**
- **L4/L7 스위치** : 포트·애플리케이션 정보까지 보고 트래픽을 나누는 로드밸런서 역할 장비.
- **ARP / RARP** : IP로 MAC을 알아내는 프로토콜 / MAC으로 IP를 알아내던 옛 프로토콜(DHCP가 대체).
- **ICMP Time Exceeded** : TTL이 0이 됐을 때 라우터가 보내는 메시지. traceroute가 경로를 그리는 근거다.
- **영역 전송(zone transfer)** : DNS 서버끼리 도메인 정보를 통째로 주고받는 것. 이때는 UDP가 아니라 TCP 53을 쓴다.
- **DORA** : DHCP의 4단계 — Discover(탐색) → Offer(제안) → Request(요청) → Acknowledge(확정).
- **`dhclient`** : 리눅스에서 DHCP 주소를 요청(`dhclient eth0`)하거나 반납(`-r`)하는 명령.
- **본딩(bonding)** : 여러 NIC을 하나로 묶는 커널 모듈 방식. 모드 번호(0~6)로 동작을 정한다.
- **티밍(teaming)** : 같은 목적을 사용자 공간 데몬 `teamd`로 구현한 최신 방식. runner로 동작을 정한다.
- **active-backup(mode 1)** : 한 NIC만 쓰다가 죽으면 다른 NIC으로 넘어가는 이중화 모드.
- **802.3ad(LACP, mode 4)** : 스위치와 협상해 여러 링크를 하나로 묶어 대역폭을 늘리는 모드.

## 📝 연습 문제

**문제 1.** 받은 프레임을 MAC 주소 테이블을 학습해 목적지 포트로만 전달하는 2계층 장비는?

A) 허브(Hub)

B) 스위치(Switch)

C) 리피터(Repeater)

D) 라우터(Router)

**정답: B**

해설: 스위치는 MAC 주소를 학습해 해당 목적지 포트로만 프레임을 전달하는 2계층 장비다. A(허브)는 1계층으로 모든 포트에 신호를 뿌리고, C(리피터)는 1계층 신호 증폭만 하며, D(라우터)는 3계층에서 IP로 네트워크를 넘는다. "MAC=스위치(2계층), IP=라우터(3계층)"가 핵심이다.

---

**문제 2.** 브로드캐스트 도메인을 분리할 수 있는 장비는?

A) 허브

B) 리피터

C) 라우터

D) 일반 스위치(VLAN 미사용)

**정답: C**

해설: 라우터(3계층)가 비로소 브로드캐스트 도메인을 분리한다. 허브·리피터(1계층)는 충돌 도메인조차 나누지 못하고, 일반 스위치는 충돌 도메인은 포트별로 나누지만 브로드캐스트는 모든 포트로 전달해 브로드캐스트 도메인은 하나다. 브로드캐스트 범위를 줄이려면 라우터 또는 VLAN이 필요하다.

**문제 3.** 같은 네트워크에서 통신할 때 상대 IP에 해당하는 MAC 주소를 알아내는 프로토콜은?

A) ICMP

B) ARP

C) DNS

D) DHCP

**정답: B**

해설: ARP는 IP를 MAC으로 변환하는 프로토콜로, "이 IP의 MAC이 뭐냐"를 브로드캐스트로 물어 알아낸다. A(ICMP)는 도달성·오류 메시지, C(DNS)는 도메인→IP 변환, D(DHCP)는 IP 자동 할당이라 역할이 다르다. ARP는 IP↔MAC 매핑이라는 점이 핵심이다.

**문제 4.** DHCP의 주소 할당 4단계(DORA) 순서로 옳은 것은?

A) Discover → Offer → Request → Acknowledge

B) Request → Offer → Discover → Acknowledge

C) Offer → Discover → Acknowledge → Request

D) Discover → Request → Offer → Acknowledge

**정답: A**

해설: DHCP는 Discover(탐색)-Offer(제안)-Request(요청)-Acknowledge(확정) 순으로 동작하며 머리글자 DORA로 외운다. 클라이언트가 서버를 찾고(Discover), 서버가 IP를 제안하고(Offer), 클라이언트가 그 IP를 요청하고(Request), 서버가 확정(Acknowledge)한다. 나머지 보기는 순서가 뒤바뀌어 틀리다.

**문제 5.** DNS 프로토콜이 사용하는 포트와 전송 프로토콜로 옳은 것은?

A) 80번, TCP만 사용한다

B) 53번, 기본은 UDP를 쓰되 큰 응답·영역 전송에는 TCP도 사용한다

C) 67번, UDP만 사용한다

D) 22번, TCP만 사용한다

**정답: B**

해설: DNS는 53번 포트를 쓰며 일반 질의는 UDP 53, 응답이 크거나(512바이트 초과) 영역 전송(zone transfer) 시에는 TCP 53을 사용한다. A(80)는 HTTP, C(67)는 DHCP 서버, D(22)는 SSH 포트다. "DNS=53, UDP/TCP 둘 다"가 핵심이며 "UDP만"은 흔한 오답이다.

**문제 6.** 두 개의 NIC을 묶어 평소 하나만 사용하다가 장애 발생 시 다른 NIC으로 자동 전환하는 이중화를 구성하려 한다. 적절한 본딩 모드는?

A) balance-rr (mode 0)

B) active-backup (mode 1)

C) broadcast (mode 3)

D) 802.3ad/LACP (mode 4)

**정답: B**

해설: active-backup(mode 1)은 한 NIC만 활성 상태로 쓰다가 장애 시 백업 NIC으로 자동 전환하는 이중화 모드다. A(balance-rr)와 D(LACP)는 대역폭 증가·부하분산용이고, C(broadcast)는 모든 슬레이브로 동일 프레임을 보내 특수 용도다. "이중화=active-backup, 대역폭=LACP"로 구분한다.

**문제 7.** 본딩(Bonding)과 티밍(Teaming)의 차이로 옳은 것은?

A) 본딩은 사용자 공간 데몬, 티밍은 커널 모듈로 구현된다

B) 본딩은 커널 모듈(bonding)로, 티밍은 사용자 공간 데몬(teamd)으로 구현되며 티밍이 더 최신 방식이다

C) 본딩은 3계층, 티밍은 7계층에서 동작한다

D) 둘은 완전히 동일하며 이름만 다르다

**정답: B**

해설: 본딩은 커널 모듈(bonding)로 구현된 전통적 방식이고, 티밍은 사용자 공간 데몬(teamd) 기반의 최신(RHEL7+) 방식으로 더 유연하다. A는 구현 위치를 뒤바꿨고, C는 둘 다 인터페이스 집계로 계층 구분이 부정확하며, D는 구현·등장 시기가 다르므로 틀리다.
