# Day 5 - Week 1 종합 복습: 개념을 꿰뚫는 시간

이번 주는 리눅스라는 거대한 세계로 들어가는 첫 관문이었다. 우리는 운영체제가 무엇인지에서 시작해, 커널과 셸의 구조, 유닉스와 리눅스의 역사, 라이선스가 빚어낸 배포판 생태계, 전원을 켜는 순간부터 로그인까지의 부팅 과정, 그리고 파일시스템의 구조와 파일의 본질인 inode까지 훑었다. 오늘은 이 모든 것을 하나의 흐름으로 다시 엮어보고, 시험에 자주 나오는 비교 포인트를 정리한 뒤, 실전 유형의 연습 문제로 실력을 점검한다. 개별 사실을 암기하는 것을 넘어, "왜 그런가"를 설명할 수 있는지 스스로 확인해보자.

## 흐름으로 다시 보는 Week 1

리눅스를 이해하는 가장 좋은 방법은 "전원을 켜면 무슨 일이 일어나는가"를 따라가는 것이다. 이 한 줄기 이야기 안에 이번 주 모든 개념이 들어있다.

전원을 켜면 **펌웨어(BIOS 또는 UEFI)**가 깨어나 하드웨어를 점검(POST)하고 부팅 장치를 고른다(Day 3). 그 디스크는 **파티션**으로 나뉘어 있고, 파티션 정보는 MBR 또는 GPT 테이블에 담겨 있다(Day 3). 펌웨어는 **부트로더 GRUB2**를 실행하고, GRUB2는 `/boot`에서 **커널(vmlinuz)**을 찾아 메모리에 올린다(Day 3). 커널은 모놀리식 구조로 모든 핵심 기능을 품고 있으며(Day 1), initramfs로 진짜 루트 파일시스템을 마운트한 뒤 첫 프로세스인 **systemd(PID 1)**를 실행한다(Day 3).

systemd는 서비스들을 병렬로 시작해 시스템을 사용 가능하게 만들고, 마침내 **셸**이 로그인한 사용자를 맞이한다(Day 1). 셸은 사용자의 명령을 fork-exec-wait 모델로 실행하며, 그 명령들은 `/bin`, `/sbin`에 있다(Day 1, Day 4). 사용자가 다루는 모든 것은 단일 루트(`/`)에서 뻗는 **FHS** 트리 위의 파일이며(Day 4), 그 파일의 진짜 정체는 이름이 아니라 **inode**다(Day 4).

그리고 이 모든 소프트웨어가 자유롭게 공유될 수 있는 이유는 **GPL 라이선스**의 카피레프트 덕분이고, 그 자유가 우분투·레드햇·SUSE 같은 **배포판** 생태계를 키웠다(Day 2). 이렇게 하나의 이야기로 엮으면 흩어진 개념들이 자기 자리를 찾는다.

> 💡 **개념**: 1급 시험은 단편 지식보다 "개념 간 연결"을 묻는 경향이 강하다. 예를 들어 "왜 /boot를 별도 파티션으로 두는가"는 파티션(Day 3) + 부팅 과정(Day 3) + 파일시스템(Day 4)을 한꺼번에 이해해야 답할 수 있다. 복습할 때 개별 명령어를 외우기보다 이런 연결고리를 정리하자.

## 꼭 기억해야 할 핵심 비교표

이번 주에 등장한 "둘 중 무엇인가"를 묻는 비교들을 한자리에 모았다. 시험 직전 이 표만 봐도 큰 도움이 된다.

| 비교 주제 | A | B | 핵심 차이 |
|----------|---|---|----------|
| 커널 모드 vs 사용자 모드 | 커널(Ring0) | 사용자(Ring3) | 특권 vs 제한, 사이는 시스템 콜 |
| 모놀리식 vs 마이크로커널 | 리눅스(빠름) | Hurd(모듈성) | 단일 공간 vs 분리 서비스 |
| GPL vs BSD/MIT | 카피레프트(공개강제) | 허용적(폐쇄가능) | 파생물 공개 의무 유무 |
| GPL vs LGPL | 전체 공개 | 동적링크 비공개 가능 | 약한 카피레프트 |
| RPM 계열 vs DEB 계열 | rpm/dnf/.rpm | dpkg/apt/.deb | 패키지 형식과 도구 |
| MBR vs GPT | 2TB/4파티션 | 9.4ZB/128 | 디스크·파티션 한계 |
| BIOS vs UEFI | MBR/구식 | ESP/GPT/시큐어부트 | 펌웨어 세대 |
| SysV init vs systemd | 런레벨/직렬 | 타깃/병렬 | 부팅 방식 |
| 하드링크 vs 심볼릭링크 | 같은 inode | 경로 담은 새 inode | 파티션·디렉터리 가능 여부 |
| 블록 vs 문자 장치 | b/디스크/랜덤 | c/키보드/스트림 | I/O 단위 |

> ⚠️ **함정**: 시험에서 가장 헷갈리는 함정 세 가지를 미리 못 박아두자. ① LGPL 라이브러리를 **동적 링크**한 폐쇄 소스 앱은 소스 공개 의무가 **없다**. ② SUSE는 계열은 독립이지만 패키지 형식은 **RPM**이다. ③ 런레벨 0은 종료(poweroff), 6이 재부팅(reboot)이다. 이 셋은 매 회차 변형되어 출제된다.

## 자주 쓰는 명령어 총정리

이번 주에 등장한 명령어를 기능별로 묶어 복습하자. 1급 실기를 위해 직접 쳐보는 것이 중요하다.

```bash
# --- 시스템 정보 ---
uname -r                    # 커널 버전
uname -a                    # 시스템 전체 정보
cat /etc/os-release         # 배포판 정보
echo $SHELL                 # 현재 셸

# --- 패키지 관리(레드햇) ---
rpm -qa                     # 설치된 패키지 전체
dnf install <pkg>           # 의존성 자동 설치
dnf update                  # 전체 업데이트

# --- 패키지 관리(데비안) ---
dpkg -l                     # 설치된 패키지 전체
apt install <pkg>           # 의존성 자동 설치
apt update && apt upgrade   # 목록 갱신 후 업그레이드

# --- 부팅/서비스 ---
systemctl status <svc>      # 서비스 상태
systemctl enable <svc>      # 부팅 시 자동 시작
systemctl get-default       # 기본 타깃 확인
grub2-mkconfig -o /boot/grub2/grub.cfg   # GRUB 재생성

# --- 디스크/파티션 ---
lsblk                       # 블록 장치 트리
fdisk -l                    # 파티션 테이블
blkid                       # UUID와 파일시스템 타입

# --- 파일/링크/inode ---
ls -li                      # inode 번호 포함 목록
stat <file>                 # 상세 메타데이터
ln <src> <link>             # 하드링크
ln -s <src> <link>          # 심볼릭링크
file <file>                 # 파일 종류 판별
```

> 🔍 **더 깊이**: 명령어를 외울 때는 "옵션의 의미"를 함께 익히면 응용이 쉽다. 예를 들어 `rpm -ivh`의 i(install), v(verbose), h(hash 진행표시)를 알면 `rpm -Uvh`(Upgrade)도 자연스럽게 이해된다. `ls -li`의 i가 inode인 것을 알면 `ls -a`(all, 숨김파일)도 함께 떠오른다. 옵션은 대부분 영단어의 첫 글자다.

## 시험 대비 마인드셋

리눅스마스터 1급은 필기와 실기로 나뉜다. 필기는 개념·비교·역사를 묻고, 실기는 실제 명령어를 칠 수 있는지를 본다. 이번 주 내용을 기준으로 대비 전략을 정리하면 다음과 같다.

- **비교 문제**: 위의 비교표가 그대로 출제된다. A와 B의 핵심 차이 한 줄을 말할 수 있어야 한다.
- **명령어 문제**: 명령어와 옵션, 설정 파일 경로를 정확히. `/etc/default/grub`처럼 경로까지 묻는다.
- **순서 문제**: 부팅 4단계, fork-exec-wait 순서처럼 순서를 묻는 문제는 단계를 그림으로 기억한다.

> 📚 **유래/사례**: 리눅스마스터는 한국정보통신진흥협회(KAIT)가 시행하는 국가공인 민간자격이다. 2급은 리눅스 입문자 수준, 1급은 서버 운영과 관리 실무 수준을 검증한다. 1급은 1차 필기 합격 후 2차 실기를 봐야 하므로, 명령어를 눈으로만 외우지 말고 가상머신에 리눅스를 직접 설치해 쳐보는 학습이 합격의 지름길이다.

**문제 1.** 리눅스 부팅 과정에서 각 단계의 역할로 옳지 않은 것은?

A) 펌웨어(BIOS/UEFI)는 POST로 하드웨어를 점검하고 부팅 장치를 선택한다
B) 부트로더(GRUB2)는 커널 이미지를 메모리에 적재하고 제어권을 넘긴다
C) 커널은 initramfs를 이용해 실제 루트 파일시스템을 마운트한다
D) systemd는 커널을 압축 해제하여 MBR의 첫 섹터에 기록한다

**정답: D**

해설: systemd는 PID 1 프로세스로 서비스를 병렬로 시작하는 역할이지, 커널을 압축 해제하거나 MBR에 기록하지 않는다. 따라서 D가 틀렸다. A는 옳다. 펌웨어는 POST와 부팅 장치 선택을 담당한다. B는 옳다. GRUB2는 커널을 메모리에 올린다. C는 옳다. 커널은 initramfs로 루트를 마운트한다.

**문제 2.** 다음 중 카피레프트(GPL)와 허용적 라이선스(BSD/MIT)의 차이를 가장 정확히 설명한 것은?

A) GPL은 파생물의 소스 공개를 강제하지만 BSD/MIT는 폐쇄 소스 배포를 허용한다
B) BSD/MIT는 파생물 소스 공개를 강제하지만 GPL은 그렇지 않다
C) 두 라이선스 모두 어떤 경우에도 상업적 사용을 금지한다
D) GPL과 BSD/MIT는 라이선스 조건이 완전히 동일하여 구분할 필요가 없다

**정답: A**

해설: GPL은 카피레프트로 파생물도 같은 GPL로 공개하도록 강제하지만, BSD/MIT는 허용적 라이선스로 저작권 표시만 유지하면 폐쇄 소스 상업 제품으로 만들 수 있다. B는 정반대다. 공개 강제는 GPL 쪽이다. C는 틀렸다. 두 라이선스 모두 상업적 사용을 허용한다. D는 틀렸다. 파생물 공개 의무 유무라는 핵심 차이가 있다.

**문제 3.** 리눅스 셸이 명령어를 실행하는 fork-exec-wait 모델에서 각 시스템 콜의 역할로 옳은 것은?

A) fork()는 자식 프로세스의 메모리 이미지를 새 프로그램으로 교체한다
B) exec()는 부모 프로세스를 복제하여 동일한 자식을 만든다
C) wait()는 부모가 자식의 종료를 기다려 종료 상태를 회수한다
D) fork()는 부모 프로세스를 즉시 종료시키고 자식만 남긴다

**정답: C**

해설: wait()는 부모(셸)가 자식 프로세스의 종료를 기다렸다가 종료 상태를 회수하는 시스템 콜로, 이를 통해 좀비 프로세스를 방지한다. A는 틀렸다. 이미지 교체는 exec()의 역할이다. B는 틀렸다. 복제는 fork()의 역할이다. D는 틀렸다. fork()는 부모를 종료시키지 않고 자식을 복제할 뿐이다.

**문제 4.** 레드햇 계열과 데비안 계열의 패키지 관리에 대한 설명으로 옳은 것은?

A) 레드햇은 .deb 형식을 쓰고 데비안은 .rpm 형식을 쓴다
B) 레드햇의 고수준 도구는 dnf/yum, 데비안의 고수준 도구는 apt이다
C) 저수준 도구인 rpm과 dpkg는 의존성을 모두 자동으로 해결한다
D) 데비안 계열은 패키지 의존성 개념이 없어 저장소가 필요 없다

**정답: B**

해설: 레드햇 계열은 dnf/yum, 데비안 계열은 apt를 고수준(의존성 자동 해결) 도구로 사용한다. A는 정반대다. 레드햇이 .rpm, 데비안이 .deb를 쓴다. C는 틀렸다. 저수준 도구(rpm, dpkg)는 의존성을 자동 해결하지 못하며, 그래서 고수준 도구가 필요하다. D는 틀렸다. 데비안도 의존성 개념이 있고 저장소(repository)를 사용한다.

**문제 5.** 하드링크와 심볼릭링크에 대한 설명으로 옳은 것은?

A) 하드링크는 다른 파티션과 디렉터리를 가리킬 수 있다
B) 심볼릭링크는 원본과 동일한 inode 번호를 공유한다
C) 하드링크는 원본과 같은 inode를 가리켜 원본 삭제 후에도 데이터가 유지된다
D) 심볼릭링크는 원본을 삭제해도 절대 깨지지 않는다

**정답: C**

해설: 하드링크는 원본과 동일한 inode를 가리키는 또 다른 이름이므로, 원본을 지워도 inode 링크 수만 감소할 뿐 데이터는 유지된다. A는 틀렸다. 파티션·디렉터리를 넘는 것은 심볼릭링크만 가능하다. B는 틀렸다. 심볼릭링크는 자신만의 새 inode를 갖는다. D는 틀렸다. 심볼릭링크는 원본이 사라지면 깨진 링크가 된다.

**문제 6.** 다음 중 SysV init의 런레벨과 systemd 타깃의 대응이 옳은 것은?

A) 런레벨 0은 graphical.target(GUI)에 대응한다
B) 런레벨 3은 multi-user.target(텍스트 다중사용자)에 대응한다
C) 런레벨 5는 poweroff.target(종료)에 대응한다
D) 런레벨 6은 rescue.target(단일사용자)에 대응한다

**정답: B**

해설: 런레벨 3(텍스트 다중사용자 + 네트워크)은 systemd의 multi-user.target에 대응한다. A는 틀렸다. 런레벨 0은 poweroff.target(종료)이다. C는 틀렸다. 런레벨 5는 graphical.target(GUI)이다. D는 틀렸다. 런레벨 6은 reboot.target(재부팅)이고 rescue.target은 런레벨 1에 대응한다.

**문제 7.** 리눅스 파일시스템에서 inode에 대한 설명으로 옳은 것은?

A) inode에는 파일의 이름이 핵심 정보로 저장된다
B) 디스크 용량이 충분하면 inode 고갈은 절대 발생하지 않는다
C) inode는 권한·소유자·크기·데이터 블록 주소 등 메타데이터를 담는다
D) 디렉터리는 inode를 사용하지 않는 특수한 객체이다

**정답: C**

해설: inode는 파일의 권한(rwx), 소유자(UID/GID), 크기, 타임스탬프, 링크 수, 데이터 블록 주소 등 메타데이터를 담는 자료구조다. A는 틀렸다. 파일 이름은 inode가 아니라 디렉터리에 매핑으로 저장된다. B는 틀렸다. inode는 파일시스템 생성 시 개수가 정해지므로 용량이 남아도 고갈될 수 있다. D는 틀렸다. 디렉터리도 inode를 가지는 파일의 한 종류다.

**문제 8.** 리눅스 커널과 운영체제의 기본 개념에 대한 설명으로 옳지 않은 것은?

A) 리눅스 커널은 모놀리식 구조이며 LKM으로 모듈을 동적 적재할 수 있다
B) 사용자 모드 프로그램은 시스템 콜을 통해 커널에 특권 작업을 요청한다
C) "리눅스"는 엄밀히는 커널을 가리키며 우분투 등은 배포판이다
D) 셸은 커널의 일부로서 Ring 0 특권 모드에서 직접 하드웨어를 제어한다

**정답: D**

해설: 셸은 커널의 일부가 아니라 사용자 모드(Ring 3)에서 동작하는 명령어 해석기로, 하드웨어를 직접 제어하지 않고 시스템 콜로 커널에 요청한다. 따라서 D가 틀렸다. A는 옳다. 리눅스는 모놀리식이면서 LKM을 지원한다. B는 옳다. 사용자 프로그램은 시스템 콜로 특권 작업을 요청한다. C는 옳다. 리눅스는 커널이고 우분투는 배포판이다.

**문제 9.** MBR과 GPT, BIOS와 UEFI의 관계에 대한 설명으로 옳은 것은?

A) BIOS는 주로 GPT와, UEFI는 주로 MBR과 함께 쓰인다
B) UEFI는 EFI 시스템 파티션(ESP)에 부트로더를 저장하고 주로 GPT를 사용한다
C) MBR은 9.4ZB 디스크와 128개 파티션을 지원한다
D) GPT는 파티션 테이블을 단일 위치에만 저장하여 MBR보다 손상에 약하다

**정답: B**

해설: UEFI는 FAT으로 포맷된 EFI 시스템 파티션(ESP)에 부트로더를 파일로 저장하며, 주로 GPT 파티션 방식과 함께 사용된다. A는 정반대다. BIOS는 MBR, UEFI는 GPT와 짝을 이룬다. C는 틀렸다. 9.4ZB·128 파티션은 GPT의 특성이다. D는 틀렸다. GPT는 테이블을 디스크 앞뒤로 이중 저장해 MBR보다 손상에 강하다.

A) /dev/sda 같은 장치를 파일처럼 열어 read/write로 다룬다
B) /proc/cpuinfo를 cat으로 읽어 CPU 정보를 텍스트로 확인한다
C) 프로세스 정보를 /proc/<PID> 디렉터리의 파일로 읽을 수 있다
D) 윈도우처럼 C 드라이브와 D 드라이브가 각각 독립된 루트를 갖는다

**정답: D**

**문제 11.** 자유 소프트웨어(FSF)와 오픈소스(OSI) 운동에 대한 설명으로 옳은 것은?

A) 자유 소프트웨어 운동은 1998년 에릭 레이먼드가, 오픈소스는 1985년 스톨먼이 시작했다
B) 자유 소프트웨어의 "Free"는 무료를 뜻하며 절대 유료 판매할 수 없다
C) 자유 소프트웨어는 윤리적 자유를, 오픈소스는 실용적 개발 방법론을 강조한다

**문제 12.** GRUB2 설정을 변경하는 절차와 systemd 서비스 관리에 대한 설명으로 옳은 것은?

A) /boot/grub2/grub.cfg를 직접 편집하면 다음 grub2-mkconfig 실행 시 덮어써진다
B) systemctl enable은 서비스를 즉시 시작하지만 부팅 시 자동 시작은 막는다
C) /etc/default/grub은 자동 생성 파일이므로 직접 편집하면 안 된다
D) systemctl get-default는 서비스의 의존성 목록을 출력한다

**정답: A**

해설: /boot/grub2/grub.cfg는 /etc/default/grub과 /etc/grub.d/를 바탕으로 grub2-mkconfig가 자동 생성하므로, 직접 편집해도 다음 재생성 시 덮어써진다. B는 틀렸다. enable은 부팅 시 자동 시작을 등록하며 즉시 시작은 start가 한다. C는 정반대다. /etc/default/grub은 사용자가 편집하는 파일이고, 자동 생성되는 것은 grub.cfg다. D는 틀렸다. get-default는 기본 타깃(런레벨)을 출력한다.
