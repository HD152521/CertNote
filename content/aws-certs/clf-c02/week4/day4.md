# Day 4 - 데이터 보호의 기본: 암호화, 키 관리, 비밀 보관

어제 "데이터를 어디에 둘지(리전)"를 다뤘다면, 오늘은 "그 데이터를 어떻게 안전하게 보호할지"를 본다. 핵심 기술은 **암호화(Encryption)**다. 데이터를 알아볼 수 없는 형태로 바꿔두면, 설령 누군가 데이터를 훔쳐가도 키가 없으면 무용지물이 된다.

오늘은 암호화의 두 가지 상태(전송 중/저장 시), 암호화 키를 관리하는 서비스(**KMS**와 **CloudHSM**), 그리고 비밀번호·API 키 같은 민감 정보를 안전하게 보관하는 **Secrets Manager**를 개념 수준으로 정리한다. CLF 시험은 알고리즘 같은 깊은 내용이 아니라 "언제 무엇을 쓰는가"를 묻는다.

## 암호화의 두 가지 상태

데이터는 두 가지 상황에서 보호되어야 한다.

**1. 전송 중 암호화 (Encryption in Transit)**: 데이터가 네트워크를 통해 이동하는 동안의 보호. 브라우저와 서버 사이를 오가는 데이터를 가로채도 읽을 수 없게 한다. 대표 기술은 **TLS/SSL**(https://로 시작하는 통신)이다.

**2. 저장 시 암호화 (Encryption at Rest)**: 데이터가 디스크나 스토리지에 저장되어 있는 동안의 보호. 누군가 물리 디스크나 저장된 파일에 접근해도 키 없이는 읽을 수 없다. S3, EBS, RDS 등 대부분의 AWS 스토리지 서비스가 저장 시 암호화를 지원한다.

| 상태 | 보호 대상 | 대표 기술 |
|------|-----------|-----------|
| 전송 중(in transit) | 네트워크 이동 중인 데이터 | TLS/SSL (HTTPS) |
| 저장 시(at rest) | 디스크에 저장된 데이터 | 스토리지 암호화 + KMS 키 |

> 💡 **관련 이론**: "이동 중 가로채기를 막아라" → 전송 중 암호화(TLS). "저장된 데이터를 보호하라" → 저장 시 암호화. 시험에서 두 상태를 구분하는 문제가 자주 나오므로 "in transit vs at rest"를 또렷이 기억하자.

## KMS: 암호화 키를 관리하는 서비스

암호화를 하려면 **키(Key)**가 필요하다. 그런데 키 자체를 어디에 어떻게 안전하게 보관하느냐가 새로운 문제다. 이걸 해결하는 것이 **AWS KMS(Key Management Service)**다.

KMS는 암호화 키를 **생성·저장·관리·교체**해주는 완전 관리형 서비스다. S3, EBS, RDS 등 대부분의 AWS 서비스와 통합되어, 체크박스 하나로 "이 데이터를 KMS 키로 암호화" 설정을 할 수 있다. 키에 대한 접근은 IAM으로 통제하고, 누가 언제 키를 썼는지는 CloudTrail에 기록된다.

KMS의 키 관리 방식:

- **AWS 관리형 키**: AWS가 대신 관리.
- **고객 관리형 키(CMK)**: 고객이 직접 만들고 권한·교체 정책을 통제.

> 💡 **관련 이론**: "AWS 서비스 전반의 암호화 키를 손쉽게 만들고 관리하라"가 보이면 KMS다. 키 관리를 위임하면서도 통합이 간편한 것이 KMS의 핵심 가치다.

## CloudHSM: 전용 하드웨어 키 관리

KMS는 여러 고객이 공유하는 인프라 위에서 동작한다(키는 격리되지만). 그런데 일부 규제 산업은 **"키를 우리 전용 하드웨어에 두고, AWS조차 접근하지 못하게 하라"**고 요구한다. 이때 쓰는 것이 **AWS CloudHSM**이다.

CloudHSM은 고객 **전용 하드웨어 보안 모듈(HSM, Hardware Security Module)**을 제공한다. 키가 검증된 전용 하드웨어 안에서만 다뤄지며, 고객이 키를 완전히 단독 통제한다. 더 엄격한 규정 준수(예: FIPS 140-2 Level 3)나 키에 대한 완전한 단독 통제가 필요할 때 선택한다.

| 항목 | KMS | CloudHSM |
|------|-----|----------|
| 관리 방식 | AWS 관리형, 통합 간편 | 고객 전용 HSM, 단독 통제 |
| 사용 편의 | 매우 쉬움(서비스 통합) | 상대적으로 복잡 |
| 대상 | 일반적인 암호화 요구 | 엄격한 규정/단독 키 통제 |

> 💡 **관련 이론**: "전용 하드웨어에서, AWS도 접근 못 하게, 키를 완전히 단독 통제하라"가 보이면 CloudHSM이다. 그 외 일반적인 키 관리는 통합이 쉬운 KMS가 기본 선택이다.

## Secrets Manager: 비밀 정보의 안전한 보관

데이터베이스 비밀번호, API 키, 토큰 같은 **비밀(Secret)**을 코드에 하드코딩하거나 설정 파일에 평문으로 두는 것은 위험하다. 유출되면 곧바로 침해로 이어진다. **AWS Secrets Manager**는 이런 비밀 정보를 안전하게 저장하고, 애플리케이션이 실행 중에 안전하게 꺼내 쓰도록 해준다.

핵심 특징은 **자동 교체(rotation)**다. 예를 들어 RDS 데이터베이스 비밀번호를 주기적으로 자동 변경하도록 설정하면, 사람이 손대지 않아도 비밀이 정기적으로 갱신된다.

> 💡 **관련 이론**: "DB 비밀번호/API 키를 코드에 박지 않고 안전하게 보관·자동 교체하라"가 보이면 Secrets Manager다. "키(암호화용)"는 KMS, "비밀(자격 증명)"은 Secrets Manager로 구분하면 헷갈리지 않는다.

## 한 줄 정리표

| 서비스/개념 | 한 줄 정체성 |
|-------------|--------------|
| 전송 중 암호화 | 네트워크 이동 중 데이터 보호(TLS) |
| 저장 시 암호화 | 디스크에 저장된 데이터 보호 |
| KMS | 암호화 키 생성·관리(통합 간편) |
| CloudHSM | 전용 하드웨어 기반 단독 키 통제 |
| Secrets Manager | 비밀번호·API 키 보관 및 자동 교체 |

## 정리하며

데이터 보호의 핵심은 암호화이며, 데이터는 전송 중(TLS)과 저장 시 모두 보호되어야 한다. 암호화 키는 KMS로 손쉽게 관리하고, 전용 하드웨어에서 단독 통제가 필요하면 CloudHSM을 쓴다. 비밀번호·API 키 같은 자격 증명은 Secrets Manager로 안전하게 보관·자동 교체한다.

다음 글에서는 Week 4 전체 — 공동 책임 모델·IAM·보안 서비스·규정 준수·데이터 보호 — 를 종합 복습하며, 시험에서 자주 헷갈리는 포인트를 한 번에 정리한다.

## 📝 연습 문제

**문제 1.** 웹 브라우저와 서버 사이를 오가는 데이터를 가로채기로부터 보호하는 것은 어떤 유형의 암호화인가?

A) 저장 시 암호화(at rest)  
B) 전송 중 암호화(in transit)  
C) 디스크 암호화  
D) 키 교체  

**정답: B**  
해설: 네트워크를 통해 이동 중인 데이터를 보호하는 것은 전송 중 암호화이며 TLS/SSL(HTTPS)이 대표 기술이다. 저장 시·디스크 암호화는 저장된 데이터를 보호하고, 키 교체는 암호화 키를 주기적으로 갱신하는 별개의 작업이다.

---

**문제 2.** S3, EBS, RDS 등 여러 AWS 서비스에서 사용하는 암호화 키를 손쉽게 생성하고 중앙에서 관리하려 한다. 가장 적합한 서비스는?

A) AWS Secrets Manager  
B) AWS KMS  
C) Amazon Macie  
D) AWS Artifact  

**정답: B**  
해설: KMS는 AWS 서비스 전반과 통합되어 암호화 키를 생성·저장·관리·교체하는 완전 관리형 서비스다. Secrets Manager는 비밀번호 같은 자격 증명 보관용, Macie는 S3 민감 데이터 탐지, Artifact는 규정 준수 보고서 다운로드 포털이다.

---

**문제 3.** 엄격한 규정 준수 요구에 따라 암호화 키를 고객 전용 하드웨어에서 단독으로 통제해야 한다. 가장 적합한 서비스는?

A) AWS KMS의 AWS 관리형 키  
B) AWS CloudHSM  
C) AWS Secrets Manager  
D) Amazon Inspector  

**정답: B**  
해설: CloudHSM은 고객 전용 하드웨어 보안 모듈(HSM)을 제공해 키를 단독으로 완전히 통제하게 하며, 엄격한 규정 준수 요구에 적합하다. KMS 관리형 키는 AWS가 관리하는 공유 인프라 기반이고, Secrets Manager는 자격 증명 보관용, Inspector는 취약점 점검 도구다.

---

**문제 4.** 데이터베이스 비밀번호와 API 키를 코드에 하드코딩하지 않고 안전하게 보관하며, 주기적으로 자동 교체하려 한다. 가장 적합한 서비스는?

A) AWS KMS  
B) AWS CloudHSM  
C) AWS Secrets Manager  
D) AWS WAF  

**정답: C**  
해설: Secrets Manager는 비밀번호·API 키 같은 자격 증명을 안전하게 저장하고 자동 교체(rotation)를 지원한다. KMS와 CloudHSM은 암호화 "키" 관리에 초점이 있고, WAF는 웹 공격 필터링 서비스다.

**문제 5.** 저장 시 암호화(encryption at rest)에 대한 설명으로 옳은 것은?

A) 네트워크를 통해 전송되는 데이터를 보호한다  
B) 디스크나 스토리지에 저장된 데이터를 키 없이 읽지 못하게 보호한다  
C) HTTPS 통신을 의미한다  
D) 오직 EC2에서만 사용할 수 있다  

**정답: B**  
해설: 저장 시 암호화는 디스크·스토리지에 저장된 데이터를 보호해 키가 없으면 읽을 수 없게 한다. 네트워크 전송 보호와 HTTPS는 전송 중 암호화에 해당하며, 저장 시 암호화는 S3·EBS·RDS 등 다양한 스토리지 서비스에서 지원된다.
