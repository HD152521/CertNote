# Day 3 - 규정 준수: 증명서, 인증 프로그램, 그리고 데이터의 국적

보안 도구로 위협을 막는 것과, "우리가 법과 규정을 지키고 있음을 증명하는 것"은 다른 일이다. 은행, 병원, 정부 기관은 단지 안전한 것으로는 부족하고, **감사관에게 증거를 제출**해야 한다. "당신들이 쓰는 AWS는 ISO 27001 인증을 받았나요?", "환자 데이터(HIPAA)를 다룰 수 있는 환경인가요?" 같은 질문에 답할 수 있어야 한다.

오늘은 규정 준수(Compliance)의 세 축을 본다. 증명서를 받는 도구(**AWS Artifact**), AWS가 따르고 있는 규정 준수 프로그램들, 그리고 데이터가 어느 나라에 저장되는지를 결정하는 **데이터 주권과 리전 선택**이다.

## AWS Artifact: 규정 준수 보고서 다운로드 센터

감사를 받을 때 가장 먼저 필요한 것이 "AWS가 받은 각종 인증·감사 보고서"다. 이걸 받는 곳이 **AWS Artifact**다. AWS Artifact는 AWS의 보안 및 규정 준수 문서를 **셀프 서비스로 다운로드**할 수 있는 포털이다.

여기서 받을 수 있는 대표 문서:

- **SOC 보고서**(SOC 1, 2, 3) — 서비스 조직의 통제 감사 보고서
- **ISO 인증서**(ISO 27001 등)
- **PCI DSS** 규정 준수 증명(신용카드 데이터 취급 관련)
- 각종 규정에 대한 AWS 책임 분담 문서

AWS Artifact는 무료이며, 콘솔에서 바로 보고서를 내려받아 감사관이나 규제 기관에 제출할 수 있다.

> 💡 **관련 이론**: "AWS의 규정 준수 보고서나 인증서(SOC, ISO, PCI DSS 등)를 어디서 받나?"라는 문제가 나오면 답은 **AWS Artifact**다. 인증을 "만드는" 곳이 아니라 이미 받은 인증의 **증빙을 내려받는** 곳이라는 점이 핵심이다.

## 규정 준수 프로그램: AWS가 따르는 표준들

AWS는 전 세계의 수많은 규정·표준에 대해 **인증을 받거나 준수(자율 준수 포함)**하고 있다. 고객은 이 토대 위에서 자신의 워크로드를 구축한다.

| 프로그램 | 대상 영역 |
|----------|-----------|
| HIPAA | 미국 의료 정보 보호 |
| PCI DSS | 신용카드 결제 데이터 |
| ISO 27001 | 정보 보안 관리 체계 |
| SOC 1/2/3 | 서비스 조직 통제 감사 |
| GDPR | EU 개인정보 보호 규정 |
| FedRAMP | 미국 연방 정부 클라우드 보안 |

여기서 다시 한번 **공동 책임 모델**이 등장한다. AWS가 규정 준수 인증을 받았다고 해서 고객의 애플리케이션이 자동으로 규정을 준수하는 것은 **아니다**. AWS는 인프라 측면(of the cloud)의 규정 준수를 책임지고, 고객은 자신의 데이터·애플리케이션·접근 통제(in the cloud)가 규정을 지키도록 설정할 책임이 있다.

> 💡 **관련 이론**: "AWS가 HIPAA/PCI 인증을 받았으니 우리 앱도 자동으로 준수되는가?"의 답은 **아니오**다. 규정 준수도 공동 책임이다. AWS는 기반을, 고객은 그 위에서 자신의 구성을 책임진다.

## 데이터 주권과 리전 선택

"우리 데이터는 절대 EU 밖으로 나가면 안 된다." 이런 요구를 **데이터 주권(Data Sovereignty)** 또는 데이터 레지던시(Data Residency)라고 한다. 어떤 나라·지역의 법은 자국민의 데이터가 자국 영토 안에 저장되어야 한다고 규정한다(예: GDPR).

AWS에서는 **리전(Region)을 선택함으로써 데이터가 물리적으로 어디에 저장될지를 고객이 통제**한다. 예를 들어 데이터를 EU에만 두어야 한다면 프랑크푸르트(eu-central-1)나 아일랜드(eu-west-1) 같은 EU 리전을 선택한다.

중요한 원칙: **고객이 명시적으로 옮기지 않는 한, AWS는 고객 데이터를 선택한 리전 밖으로 이동시키지 않는다.** 즉 어느 리전에 데이터를 둘지는 전적으로 고객의 결정이다.

```
[데이터 주권 요구]   "데이터를 EU 안에만 보관"
        │
        ▼
[리전 선택]         EU 리전(프랑크푸르트/아일랜드 등) 사용
        │
        ▼
[결과]             데이터가 선택한 리전에 물리적으로 저장됨
```

> 💡 **관련 이론**: "특정 국가/지역의 법규 때문에 데이터를 그 안에만 보관해야 한다"가 보이면 답은 **해당 리전을 선택**하는 것이다. 리전 선택은 지연 시간·비용뿐 아니라 **규정 준수(데이터 주권)**를 위한 핵심 결정이다.

## 리전 선택의 4가지 고려 요소(복습)

리전을 고를 때 보통 다음 네 가지를 본다. 규정 준수는 그중 하나로, 보안 영역에서 특히 중요하게 다뤄진다.

| 고려 요소 | 설명 |
|-----------|------|
| 규정 준수/데이터 주권 | 법적으로 데이터를 둘 수 있는 위치인가 |
| 지연 시간 | 사용자와 가까운가 |
| 서비스 가용성 | 그 리전에 필요한 서비스가 있는가 |
| 비용 | 리전마다 가격이 다름 |

## 정리하며

규정 준수의 세 축을 정리했다. 증빙 문서는 **AWS Artifact**에서 셀프 서비스로 받고, AWS는 HIPAA·PCI DSS·ISO 같은 다양한 규정 준수 프로그램을 따른다. 단, 규정 준수도 공동 책임이라 고객 몫이 남는다. 그리고 데이터를 어느 나라에 둘지는 **리전 선택**으로 고객이 직접 통제한다(데이터 주권).

다음 글에서는 규정 준수와 직결되는 **데이터 보호** — 전송 중·저장 시 암호화, KMS와 CloudHSM, Secrets Manager — 를 다룬다. "데이터를 안전하게 보관하라"는 요구를 기술로 풀어내는 방법이다.

## 📝 연습 문제

**문제 1.** 감사를 위해 AWS의 SOC 2, ISO 27001, PCI DSS 규정 준수 보고서를 다운로드하려 한다. 어떤 서비스를 사용해야 하는가?

A) AWS Artifact  
B) AWS Trusted Advisor  
C) Amazon Inspector  
D) AWS Config  

**정답: A**  
해설: AWS Artifact는 SOC, ISO, PCI DSS 등 AWS의 규정 준수 보고서와 인증서를 셀프 서비스로 내려받는 포털이다. Trusted Advisor는 모범 사례 점검, Inspector는 취약점 평가, Config는 리소스 구성 추적 도구로 규정 준수 보고서 다운로드 기능과는 다르다.

---

**문제 2.** 한 EU 회사가 법적 요구에 따라 고객 데이터를 반드시 유럽 내에만 저장해야 한다. AWS에서 이를 보장하는 방법은?

A) 데이터를 모든 리전에 자동 복제한다  
B) 데이터를 저장할 리전으로 EU 내 리전을 선택한다  
C) Amazon Macie를 활성화한다  
D) AWS Shield Advanced를 구독한다  

**정답: B**  
해설: AWS는 고객이 선택한 리전 밖으로 데이터를 임의로 옮기지 않으므로, EU 리전을 선택하면 데이터가 유럽 내에 물리적으로 저장된다(데이터 주권). 전체 리전 복제는 오히려 데이터를 EU 밖으로 내보내고, Macie와 Shield는 데이터 위치를 결정하는 기능이 아니다.

---

**문제 3.** AWS가 PCI DSS 인증을 받았다는 사실에 대한 올바른 이해는?

A) 고객 애플리케이션도 자동으로 PCI DSS를 준수하게 된다  
B) AWS는 인프라 측면의 준수를 책임지고, 고객은 자신의 구성에 대한 준수 책임이 남는다  
C) 고객은 더 이상 어떤 보안 설정도 할 필요가 없다  
D) PCI DSS는 AWS에만 적용되고 고객과 무관하다  

**정답: B**  
해설: 규정 준수도 공동 책임이다. AWS는 클라우드 인프라(of the cloud)의 준수를 책임지지만, 고객은 자신의 데이터·접근 통제·구성(in the cloud)이 규정을 지키도록 설정할 책임이 있다. AWS 인증이 곧 고객 앱의 자동 준수를 의미하지는 않는다.

---

**문제 4.** 데이터 주권(Data Sovereignty) 요구사항을 충족하기 위해 고객이 통제할 수 있는 가장 직접적인 수단은?

A) 인스턴스 유형 선택  
B) IAM 그룹 구성  
C) 데이터를 저장할 AWS 리전 선택  
D) Auto Scaling 설정  

**정답: C**  
해설: 데이터가 물리적으로 어느 지역에 저장될지는 리전 선택으로 결정되며, 이것이 데이터 주권을 충족하는 직접적 수단이다. 인스턴스 유형, IAM 그룹, Auto Scaling은 데이터의 지리적 저장 위치를 결정하지 않는다.

---

**문제 5.** 리전을 선택할 때 고려해야 할 요소로 가장 거리가 먼 것은?

A) 규정 준수 및 데이터 주권 요구사항  
B) 사용자와의 지연 시간  
C) 해당 리전의 서비스 가용성  
D) IAM 사용자의 비밀번호 길이  

**정답: D**  
해설: 리전 선택은 규정 준수·데이터 주권, 지연 시간, 서비스 가용성, 비용을 기준으로 한다. IAM 사용자의 비밀번호 길이는 계정 보안 정책 설정 사항일 뿐 리전 선택과는 무관하다.
