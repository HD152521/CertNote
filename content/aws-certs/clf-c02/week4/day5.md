# Day 5 - Week 4 종합: 보안과 규정 준수 한 번에 정리

이번 주는 시험 비중이 가장 큰 영역(30%)인 **보안 및 규정 준수**를 다뤘다. 오늘은 4일간 배운 내용을 한 줄로 꿰어 복습하고, 시험에서 자주 헷갈리는 비교 포인트를 정리한다. 개별 서비스를 다시 외우기보다는, "어떤 상황엔 무엇"이라는 **매칭 감각**을 다지는 데 집중하자.

## 1) 공동 책임 모델: 모든 답의 출발점

보안 문제를 만나면 항상 먼저 물어야 한다. "이건 AWS 책임인가, 고객 책임인가?"

- **AWS (of the cloud)**: 물리 보안, 하드웨어, 네트워크 인프라, 가상화 계층, 관리형 서비스의 기반.
- **고객 (in the cloud)**: 데이터, 암호화 설정, 접근 권한(IAM), EC2의 OS·앱 패치, 방화벽 규칙.

핵심 원칙 두 가지: ① 관리형 서비스일수록 AWS 책임이 커진다. ② **데이터와 접근 권한은 어떤 경우든 항상 고객 책임**이다.

> 💡 **관련 이론**: 규정 준수에도 같은 원리가 적용된다. AWS가 PCI/HIPAA 인증을 받아도 고객 앱이 자동으로 준수되는 건 아니다. 기반은 AWS, 그 위 구성은 고객.

## 2) IAM: 누가 무엇을 할 수 있는가

| 구성요소 | 한 줄 |
|----------|-------|
| 사용자(User) | 사람·앱 하나의 자격 증명 |
| 그룹(Group) | 사용자 묶음, 권한 일괄 관리 |
| 역할(Role) | 임시 권한 위임(예: EC2 → S3 접근) |
| 정책(Policy) | 권한 규칙을 정의한 JSON |

기억할 모범 사례: 루트 사용자는 일상 사용 금지 + **MFA 필수**, 권한은 **최소 권한 원칙**으로, EC2가 다른 서비스에 접근할 땐 **역할(Role)** 사용(키 하드코딩 금지). IAM은 **무료 글로벌 서비스**다.

> 💡 **관련 이론**: "EC2가 S3에 접근 → 역할", "동일 권한을 여러 명에게 → 그룹", "계정 보안 강화 첫 단계 → 루트 MFA"가 단골 매칭이다.

## 3) 보안 서비스 6종: 무슨 위협을 막는가

| 서비스 | 한 줄 정체성 |
|--------|--------------|
| WAF | 웹 공격(SQL 인젝션·XSS, L7) 필터링 |
| Shield | DDoS(트래픽 폭주) 방어, Standard 무료 |
| GuardDuty | 로그 분석으로 악의적 활동 탐지 |
| Inspector | EC2·컨테이너·Lambda 취약점 점검 |
| Macie | S3 내 민감 데이터(PII) 발견·분류 |
| Security Hub | 보안 결과 통합 대시보드 |

헷갈리기 쉬운 짝:
- **WAF vs Shield**: WAF는 "요청 내용(웹 공격)", Shield는 "트래픽 물량(DDoS)".
- **GuardDuty vs Inspector**: GuardDuty는 "지금 일어나는 악의적 행동", Inspector는 "공격받기 쉬운 약점(취약점)".
- **개별 탐지 vs 통합**: GuardDuty/Inspector/Macie가 탐지하고, Security Hub가 모아서 본다.

> 💡 **관련 이론**: 시험은 "이 시나리오에 맞는 서비스"를 묻는다. 각 서비스의 한 줄 정체성만 또렷하면 대부분 풀린다.

## 4) 규정 준수: 증명과 데이터의 국적

- **AWS Artifact**: SOC·ISO·PCI DSS 등 AWS의 규정 준수 보고서를 셀프 서비스로 **다운로드**하는 포털.
- AWS는 HIPAA·PCI DSS·ISO 27001·SOC·GDPR·FedRAMP 등 다양한 프로그램을 준수.
- **데이터 주권**: 법규상 데이터를 특정 지역에만 둬야 하면 → 해당 **리전을 선택**. AWS는 고객 데이터를 선택한 리전 밖으로 임의 이동시키지 않는다.

> 💡 **관련 이론**: "규정 준수 보고서 어디서? → Artifact", "데이터를 EU에만? → EU 리전 선택"이 핵심 매칭이다.

## 5) 데이터 보호: 암호화·키·비밀

| 서비스/개념 | 한 줄 정체성 |
|-------------|--------------|
| 전송 중 암호화 | 네트워크 이동 중 보호(TLS/HTTPS) |
| 저장 시 암호화 | 디스크에 저장된 데이터 보호 |
| KMS | 암호화 키 관리(통합 간편, 기본 선택) |
| CloudHSM | 전용 하드웨어 단독 키 통제(엄격 규정) |
| Secrets Manager | 비밀번호·API 키 보관·자동 교체 |

헷갈리기 쉬운 짝:
- **in transit vs at rest**: 이동 중 보호 vs 저장 중 보호.
- **KMS vs CloudHSM**: 통합 간편(기본) vs 전용 하드웨어 단독 통제(엄격).
- **KMS vs Secrets Manager**: 암호화 "키" 관리 vs "자격 증명(비밀)" 보관.

## 전체 한 장 흐름도

```
[누가 무엇을?]        IAM (사용자/그룹/역할/정책, MFA, 최소권한)
[누구 책임?]          공동 책임 모델 (AWS=of / 고객=in)
[외부 위협 차단]      WAF(웹) · Shield(DDoS)
[내부 위협 탐지]      GuardDuty · Inspector · Macie → Security Hub
[규정 증명/위치]      Artifact(보고서) · 리전 선택(데이터 주권)
[데이터 보호]         암호화(전송/저장) · KMS/CloudHSM · Secrets Manager
```

## 정리하며

Week 4의 핵심은 "보안은 공동 책임이며, 고객 몫의 도구를 알맞게 고르는 것"이다. 권한은 IAM, 외부 위협은 WAF/Shield, 내부 위협 탐지는 GuardDuty·Inspector·Macie(통합은 Security Hub), 규정 증명은 Artifact, 데이터 보호는 암호화와 KMS/CloudHSM/Secrets Manager. 각 서비스의 한 줄 정체성과 헷갈리는 짝의 차이만 또렷이 잡으면 보안 영역은 충분히 대비된다.

다음 주에는 비용 관리와 지원(요금, 청구, 지원 플랜) 영역으로 넘어가, 클라우드의 "돈 이야기"를 정리한다.

## 📝 연습 문제

**문제 1.** 공동 책임 모델에 따라, EC2 인스턴스에서 실행되는 운영체제의 보안 패치는 누구의 책임인가?

A) AWS  
B) 고객  
C) AWS와 고객이 공동으로 직접 수행  
D) 책임 주체가 없다  

**정답: B**  
해설: EC2(IaaS)에서는 게스트 운영체제와 애플리케이션의 패치가 고객 책임("in the cloud")이다. AWS는 물리 인프라와 가상화 계층 등 "of the cloud"를 책임진다. 관리형 서비스로 갈수록 패치 책임이 AWS로 이동하지만 EC2의 OS는 고객 몫이다.

---

**문제 2.** 대량의 트래픽을 동시에 퍼부어 서비스를 마비시키는 공격(DDoS)을 방어하며, 모든 고객에게 무료로 기본 제공되는 서비스는?

A) AWS WAF  
B) AWS Shield Standard  
C) Amazon GuardDuty  
D) Amazon Macie  

**정답: B**  
해설: Shield Standard는 모든 고객에게 무료로 제공되어 DDoS(트래픽 폭주)를 자동 방어한다. WAF는 웹 공격(SQL 인젝션·XSS) 필터링, GuardDuty는 악의적 활동 탐지, Macie는 S3 민감 데이터 탐지로 DDoS 방어 서비스가 아니다.

---

**문제 3.** 한 회사가 AWS 서비스 전반에서 사용할 암호화 키를 손쉽게 관리하려 한다. 일반적인 요구에 가장 적합한 기본 선택은?

A) AWS CloudHSM  
B) AWS KMS  
C) AWS Secrets Manager  
D) AWS Artifact  

**정답: B**  
해설: KMS는 AWS 서비스와 통합되어 암호화 키를 간편하게 생성·관리하는 기본 선택지다. CloudHSM은 전용 하드웨어에서 단독 키 통제가 필요한 엄격한 경우에 쓰고, Secrets Manager는 자격 증명 보관용, Artifact는 규정 준수 보고서 포털이다.

---

**문제 4.** 감사를 위해 AWS가 받은 ISO 27001 인증서와 SOC 보고서를 받아야 한다. 그리고 별도로, 데이터를 EU 내에만 보관해야 한다. 각각에 대한 올바른 조치 조합은?

A) Artifact에서 보고서 다운로드 / EU 리전 선택  
B) Inspector로 보고서 생성 / 모든 리전에 복제  
C) Trusted Advisor로 보고서 다운로드 / 인스턴스 유형 변경  
D) Security Hub로 인증서 발급 / IAM 그룹 설정  

**정답: A**  
해설: 규정 준수 보고서는 AWS Artifact에서 셀프 서비스로 내려받고, 데이터 주권 요구는 EU 리전을 선택해 충족한다. Inspector·Trusted Advisor·Security Hub는 보고서 발급 포털이 아니며, 전체 리전 복제·인스턴스 유형 변경·IAM 그룹은 데이터 보관 위치 요구와 무관하다.

---

**문제 5.** 데이터베이스 비밀번호를 코드에 하드코딩하지 않고 안전하게 저장하며 주기적으로 자동 교체하려 한다. 가장 적합한 서비스는?

A) AWS Secrets Manager  
B) Amazon Inspector  
C) AWS WAF  
D) Amazon Macie  

**정답: A**  
해설: Secrets Manager는 비밀번호·API 키 같은 자격 증명을 안전하게 보관하고 자동 교체(rotation)를 지원한다. Inspector는 취약점 점검, WAF는 웹 공격 필터링, Macie는 S3 민감 데이터 탐지로 자격 증명 보관·교체 기능과는 다르다.
