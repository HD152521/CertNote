# Day 4 - 자주 틀리는 함정·키워드: "키워드→서비스" 번역표

CLF-C02 문제는 대부분 **상황을 묘사하는 키워드**를 던지고 "가장 적합한 서비스"를 묻습니다. 그래서 시험은 사실상 **키워드를 서비스로 번역하는 게임**입니다. 오늘은 그 번역표를 정리하고, 비슷해서 헷갈리는 서비스 쌍을 비교합니다.

## 핵심 "키워드 → 서비스" 번역표

| 문제 속 키워드 | 정답 서비스 |
|----------------|-------------|
| CDN / 엣지 캐싱 / 콘텐츠 전송 | CloudFront |
| 서버리스 함수 / 이벤트 기반 코드 실행 | Lambda |
| DNS / 도메인 라우팅 | Route 53 |
| 객체 스토리지 / 정적 파일 / 백업 | S3 |
| 장기 아카이브 / 거의 안 꺼냄 / 저렴 | S3 Glacier |
| 관계형 데이터베이스 / 관리형 SQL | RDS |
| NoSQL / 서버리스 / 밀리초 | DynamoDB |
| 데이터 웨어하우스 / 대규모 분석 | Redshift |
| 인메모리 캐시 / 초고속 읽기 | ElastiCache |
| DDoS 방어 | Shield |
| 웹 방화벽 / SQL 인젝션·XSS 차단 | WAF |
| 위협 탐지 / 지능형 모니터링 | GuardDuty |
| API 호출 감사 / 누가 무엇을 했나 | CloudTrail |
| 리소스 구성 추적 / 규정 준수 상태 | Config |
| 지표·로그 모니터링 / 알람 | CloudWatch |
| 전용 네트워크 회선 / 온프레미스 연결 | Direct Connect |
| 비용 견적(사전) | Pricing Calculator |
| 비용 추세 분석(사후) | Cost Explorer |
| 예산 초과 알림 | Budgets |
| 규정 준수 보고서 다운로드 | Artifact |
| 모범 사례 점검(비용·보안·성능) | Trusted Advisor |

> 💡 **관련 이론**: 시험에서 정확한 서비스 이름이 떠오르지 않더라도, 위 키워드 매핑을 거꾸로 추적하면 오답을 빠르게 지울 수 있습니다. 키워드 하나가 정답을 결정하는 "신호어"라고 생각하세요.

## 자주 틀리는 헷갈림 쌍

### CloudTrail vs Config vs CloudWatch

| 서비스 | 답하는 질문 |
|--------|-------------|
| CloudTrail | "누가 언제 무슨 API를 호출했나?" (감사) |
| Config | "리소스 구성이 규칙을 지키나? 어떻게 바뀌었나?" |
| CloudWatch | "성능·지표가 정상인가? 임계치를 넘었나?" (모니터링) |

### S3 vs EBS vs EFS

| 서비스 | 유형 | 신호어 |
|--------|------|--------|
| S3 | 객체 | 정적 파일, 무제한, 웹 |
| EBS | 블록 | EC2에 붙는 디스크(1:1) |
| EFS | 파일 | 여러 EC2 공유 마운트 |

### Shield vs WAF vs GuardDuty

| 서비스 | 막는 것 |
|--------|---------|
| Shield | DDoS(대량 트래픽 공격) |
| WAF | 계층 7 웹 공격(SQL 인젝션, XSS) |
| GuardDuty | 비정상 활동·위협 탐지(예방이 아닌 탐지) |

### IAM 사용자 vs 그룹 vs 역할

| 요소 | 핵심 |
|------|------|
| 사용자 | 사람/앱 1개의 영구 자격 증명 |
| 그룹 | 사용자 묶음에 권한 일괄 부여 |
| 역할 | **임시 권한 위임** (EC2가 S3 접근, 계정 간 접근, 페더레이션) |

> 💡 **관련 이론**: "EC2 인스턴스가 S3에 접근해야 한다"처럼 자격 증명을 코드에 저장하지 않고 서비스에 권한을 주는 상황이면 거의 항상 **IAM 역할**이 정답입니다.

## 함정 표현 주의

- **"비용 효율적인(most cost-effective)"** → 보통 스팟/예약/Glacier/Savings Plans 쪽으로 답이 기운다
- **"운영 부담 최소(least operational overhead)"** → 서버리스(Lambda, Fargate, DynamoDB)나 관리형 서비스가 정답
- **"고가용성"** → 여러 AZ 분산
- **"재해 복구/지역 장애 대비"** → 여러 리전

## 오늘의 마무리

번역표와 헷갈림 쌍은 시험장에서 가장 빠르게 점수로 이어지는 부분입니다. 키워드를 보면 서비스가 반사적으로 떠오를 때까지 표를 반복해서 읽으세요. 내일은 시험 당일 마무리 체크리스트로 마칩니다.

## 📝 연습 문제

**문제 1.** "EC2 인스턴스가 자격 증명을 코드에 저장하지 않고 S3 버킷에 접근하도록 안전하게 권한을 부여"하려면 무엇을 사용해야 하는가?

A) IAM 사용자에 액세스 키 발급  
B) IAM 역할  
C) 루트 사용자 자격 증명  
D) S3 버킷 정책에 비밀번호 저장  

**정답: B**  
해설: IAM 역할은 임시 자격 증명을 통해 서비스에 권한을 위임하므로 액세스 키를 코드에 하드코딩할 필요가 없습니다. IAM 사용자 키 발급은 키 유출 위험이 있고, 루트 사용자는 절대 사용하면 안 되며, 비밀번호를 버킷 정책에 저장하는 것은 보안에 어긋납니다.

---

**문제 2.** "리소스 구성이 내부 규정을 계속 준수하는지 추적하고 변경 이력을 보고 싶다." 가장 적합한 서비스는?

A) AWS CloudTrail  
B) Amazon CloudWatch  
C) AWS Config  
D) AWS WAF  

**정답: C**  
해설: AWS Config는 리소스 구성 상태와 변경 이력을 추적하고 규정 준수 여부를 평가합니다. CloudTrail은 API 호출 감사, CloudWatch는 지표·로그 모니터링, WAF는 웹 방화벽입니다.

---

**문제 3.** "거의 조회하지 않는 데이터를 가장 저렴하게 장기 보관"하려면 어떤 스토리지가 적합한가?

A) Amazon S3 Standard  
B) Amazon EBS  
C) Amazon S3 Glacier  
D) Amazon EFS  

**정답: C**  
해설: S3 Glacier는 검색 지연을 허용하는 대신 매우 저렴한 장기 아카이브 스토리지입니다. S3 Standard는 자주 접근하는 데이터용으로 더 비싸고, EBS는 EC2용 블록 스토리지, EFS는 공유 파일 스토리지로 장기 아카이브 용도가 아닙니다.

---

**문제 4.** "운영 부담을 최소화하면서 이벤트가 발생할 때만 코드를 실행"하고 싶다. 가장 적합한 서비스는?

A) Amazon EC2  
B) AWS Lambda  
C) AWS Elastic Beanstalk  
D) Amazon EC2 Auto Scaling  

**정답: B**  
해설: Lambda는 서버를 관리하지 않고 이벤트 발생 시에만 코드를 실행하는 서버리스 서비스로 운영 부담이 가장 적습니다. EC2와 Auto Scaling은 서버 관리가 필요하고, Elastic Beanstalk도 하부에 EC2를 운영하므로 Lambda보다 부담이 큽니다.

---

**문제 5.** "대량 트래픽을 동원한 DDoS 공격으로부터 애플리케이션을 보호"하려면 어떤 서비스를 사용해야 하는가?

A) AWS WAF  
B) AWS Shield  
C) Amazon GuardDuty  
D) AWS KMS  

**정답: B**  
해설: AWS Shield는 DDoS 공격 방어에 특화된 서비스입니다. WAF는 SQL 인젝션·XSS 같은 계층 7 웹 공격 필터링, GuardDuty는 위협 탐지, KMS는 암호화 키 관리로 DDoS 방어가 주목적이 아닙니다.
