# Day 3 - 전체 모의고사 페이스: 4개 도메인 종합

오늘은 실제 시험처럼 4개 영역을 섞어서 풉니다. 한 문제당 약 1분 안에 답을 고르는 **페이스 감각**을 익히는 것이 목표입니다. 모르는 문제는 표시만 해두고 넘어간 뒤 나중에 돌아오는 습관을 연습하세요. 문제는 평소보다 많은 8개입니다.

## 📌 핵심 정리

- 오늘의 목표는 **지식을 더 넣는 것이 아니라 이미 아는 것을 빨리 꺼내는 것**입니다. 시험장에서 점수를 가르는 것은 지식의 양보다 인출 속도입니다.
- 65문항 / 90분 → 문항당 약 **1분 23초**. 쉬운 문항을 30초에 끝내야 어려운 문항에 2~3분을 쓸 여유가 생깁니다.
- 문제는 **마지막 한 줄부터** 읽습니다. "무엇을 고르라는지"가 거기에 들어 있습니다.
- 보기 4개 중 **명백한 오답 2개를 먼저 지우는 일**이 정답을 곧바로 찾는 것보다 빠르고 안전합니다.
- 모르는 문항은 **표시하고 넘어갑니다.** 한 문항에 3분 이상 머무는 것은 뒤쪽 문항 두세 개를 버리는 것과 같습니다.
- 빈칸은 무조건 0점입니다. 마지막 5분은 반드시 **미응답 채우기**에 씁니다.

## 모의고사 풀이 전략

| 상황 | 행동 |
|------|------|
| 바로 답이 보임 | 즉시 선택하고 다음으로 |
| 헷갈림 | 명백한 오답 2개를 먼저 제거 |
| 전혀 모름 | 표시 후 넘기고 시간 남으면 복귀 |
| "가장 적합한/비용 효율적" 질문 | 핵심 키워드 한 단어로 좁히기 |

> 💡 **관련 이론**: CLF-C02는 65문항을 90분에 풀어야 하므로 평균 약 1분 23초/문항입니다. 쉬운 문제를 빠르게 처리해 어려운 문제에 쓸 시간을 확보하는 것이 합격 페이스의 핵심입니다.

### 1분 23초는 "모든 문항에 1분 23초"라는 뜻이 아닙니다

평균이 1분 23초라는 말을 "모든 문항을 1분 23초씩 풀어야 한다"로 오해하면 오히려 페이스가 무너집니다. 실제 시험지는 난이도가 고르지 않습니다.

| 문항 유형 | 목표 소요 시간 | 설명 |
|-----------|---------------|------|
| 즉답형 (용어 정의, 서비스 이름 매칭) | 20~40초 | "CDN은?" 같은 단답. 여기서 시간을 벌어야 합니다 |
| 표준형 (짧은 상황 + 서비스 고르기) | 1분 내외 | 대부분의 문항이 여기에 속합니다 |
| 시나리오형 (긴 지문, 조건 여러 개) | 2~3분 | 조건이 많은 만큼 오히려 정답이 좁혀집니다 |
| 복수 응답형 (2개 이상 고르기) | 2분 내외 | 보기 하나하나를 O/X로 판정해야 합니다 |

핵심은 **즉답형에서 아낀 시간을 시나리오형에 몰아주는 것**입니다. 즉답형을 40초에 끝내면 문항당 40초씩 남고, 그 여유분이 모여 어려운 문항 몇 개를 살립니다.

> 📚 **사례**: 마라톤 주자는 처음 1km를 전력 질주하지 않습니다. 초반에 힘을 다 쓰면 후반에 걷게 되기 때문입니다. 시험도 같습니다. 1번 문항에서 "완벽하게 확신할 때까지" 5분을 쓰면, 그 5분은 뒤쪽 서너 문항에서 그대로 빠져나갑니다. 앞부분은 **빠르게 통과하고 표시를 남기는 구간**이라고 생각하세요.

### 문제를 읽는 4단계 순서

시험 문제를 처음부터 순서대로 읽으면 지문에 끌려다니게 됩니다. 다음 순서로 읽으면 훨씬 빠릅니다.

1. **마지막 한 줄(질문 문장)을 먼저 읽습니다.** — "무엇을 묻는가"를 먼저 확정합니다. "가장 비용 효율적인 것은?", "누구의 책임인가?", "어떤 서비스를 사용해야 하는가?"
2. **한정어에 표시합니다.** — "가장(MOST)", "최소(LEAST)", "아닌 것(NOT)", "두 개 고르시오(Select TWO)". 이 단어 하나를 놓치면 아는 문제도 틀립니다.
3. **지문에서 신호어만 뽑습니다.** — 지문 전체를 음미할 필요가 없습니다. "밀리초", "장기 보관", "여러 AZ", "운영 부담 최소" 같은 단어가 정답을 결정합니다.
4. **보기를 O / X / △로 표시하며 훑습니다.** — 처음부터 정답을 찾지 말고, 확실한 X부터 지웁니다.

```
   [4단계 읽기]
   질문 문장 → 한정어 → 지문 신호어 → 보기 소거
      ↑                                   │
      └────── 답이 안 좁혀지면 다시 위로 ─┘
```

> ⚠️ **함정**: 가장 많이 틀리는 이유는 몰라서가 아니라 **질문을 반대로 읽어서**입니다. "다음 중 AWS의 책임이 **아닌** 것은?" 같은 부정형 문항에서, 지문을 정독하고도 마지막 "아닌"을 놓쳐 정답 대신 오답을 고르는 일이 매우 흔합니다. 부정형·최상급 단어가 보이면 마음속으로 한 번 더 소리 내어 읽는 습관을 들이세요.

### 보기 소거법 — 지우면서 좁히기

CLF-C02 보기는 대체로 다음 네 가지로 구성됩니다.

| 보기 성격 | 특징 | 대응 |
|-----------|------|------|
| 정답 | 지문의 신호어와 정확히 대응 | 선택 |
| 매력적인 오답 | 같은 카테고리의 다른 서비스(예: WAF 자리에 Shield) | 신호어를 다시 확인 |
| 카테고리 자체가 다른 오답 | 스토리지를 물었는데 DNS 서비스가 등장 | 즉시 소거 |
| 존재하지 않거나 말이 안 되는 보기 | "무제한 무료", "절대 장애 없음" 같은 절대 표현 | 즉시 소거 |

즉, 4개 중 2개는 대체로 **읽자마자 지울 수 있습니다.** 남은 2개 중에서 신호어 하나로 승부를 보면 됩니다.

소거에 쓸 수 있는 빠른 규칙입니다.

- **절대 표현이 들어간 보기는 대체로 오답입니다.** — "항상", "절대", "모든 경우에", "100% 보장", "무제한 무료".
- **카테고리가 어긋난 보기는 지문을 다시 안 봐도 됩니다.** — "데이터베이스를 고르라"는데 보기 중 하나가 네트워크 서비스면 그 자리에서 X입니다.
- **보안 문제에서 "루트 사용자 사용", "액세스 키 하드코딩", "모두에게 관리자 권한"은 항상 오답입니다.** 이 세 표현은 사실상 정답 제외 표시나 마찬가지입니다.
- **비용 문제에서 "더 큰 인스턴스를 미리 사둔다"류는 대체로 오답입니다.** 클라우드의 답은 보통 "수요에 맞춰 조절한다" 쪽입니다.

### 시간을 잡아먹는 세 가지 습관

1. **아는 문제를 두 번 검산합니다.** — 확신이 있는데도 "혹시" 하고 다시 읽는 데 30초씩 쓰면 65문항에서 30분이 사라집니다.
2. **모르는 문제를 붙잡고 기억을 짜냅니다.** — 30초 안에 안 떠오르면 그 뒤 2분을 더 써도 대체로 안 떠오릅니다. 표시하고 넘어가야 합니다.
3. **답을 근거 없이 바꿉니다.** — 새로운 근거를 찾았을 때만 바꾸고, "왠지 불안해서"는 근거가 아닙니다.

## 영역별 단골 키워드 한 줄 복습

- **Domain 1**: 탄력성, 규모의 경제, AZ로 고가용성, IaaS/PaaS/SaaS
- **Domain 2**: 공동 책임, 최소 권한 IAM, CloudTrail(감사)/Config(구성)
- **Domain 3**: EC2/Lambda, S3/EBS/EFS, RDS/DynamoDB/Redshift, CloudFront(CDN)
- **Domain 4**: 온디맨드/RI/스팟, Budgets/Cost Explorer, Support 플랜

### 도메인별 인출 점검 — 눈으로 읽지 말고 먼저 답해보세요

아래 항목은 "읽고 이해하는" 용도가 아니라 **입으로 먼저 답해보고 나서 확인하는** 용도입니다. 답이 3초 안에 안 나오면 그 항목이 오늘 복습할 부분입니다.

**Domain 1 (클라우드 개념, 24%)**

- [ ] 클라우드의 6가지 이점을 순서 상관없이 6개 다 말할 수 있다
- [ ] 확장성과 탄력성의 차이를 한 문장으로 말할 수 있다
- [ ] IaaS / PaaS / SaaS를 예시 서비스와 함께 구분할 수 있다
- [ ] 퍼블릭 / 프라이빗 / 하이브리드 배포 모델을 상황별로 고를 수 있다
- [ ] 리전 / 가용 영역(AZ) / 엣지 로케이션이 각각 무엇을 위한 것인지 말할 수 있다
- [ ] 고가용성과 내결함성, 재해 복구의 차이를 설명할 수 있다

**Domain 2 (보안 및 규정 준수, 30%)**

- [ ] 공동 책임 모델에서 "항상 고객 책임"인 두 가지를 말할 수 있다 (데이터, 접근 권한)
- [ ] IAM 사용자 / 그룹 / 역할 / 정책의 쓰임을 각각 한 줄로 구분할 수 있다
- [ ] 루트 사용자에 대한 권고 세 가지를 말할 수 있다
- [ ] 최소 권한 원칙이 무엇이며 왜 "좁게 시작"하는지 설명할 수 있다
- [ ] Shield / WAF / GuardDuty가 각각 무엇을 다루는지 구분할 수 있다
- [ ] CloudTrail / Config / CloudWatch가 각각 어떤 질문에 답하는지 구분할 수 있다
- [ ] Artifact가 무엇을 제공하는 서비스인지 말할 수 있다

**Domain 3 (클라우드 기술 및 서비스, 34%)**

- [ ] EC2 / Lambda / Elastic Beanstalk / Fargate를 "관리 부담" 순서로 배열할 수 있다
- [ ] S3 / EBS / EFS를 "누가 어떻게 붙여 쓰는지"로 구분할 수 있다
- [ ] RDS / DynamoDB / Redshift / Aurora의 용도를 각각 한 줄로 말할 수 있다
- [ ] VPC / Route 53 / CloudFront / Direct Connect가 각각 무엇을 하는지 말할 수 있다
- [ ] ELB와 Auto Scaling이 하는 일이 어떻게 다른지 설명할 수 있다
- [ ] "글로벌 서비스"에 해당하는 것들을 몇 개 떠올릴 수 있다 (IAM, Route 53, CloudFront 등)

**Domain 4 (청구·요금·지원, 12%)**

- [ ] 온디맨드 / 예약 인스턴스 / Savings Plans / 스팟을 상황별로 고를 수 있다
- [ ] Pricing Calculator와 Cost Explorer의 차이를 "사전 / 사후"로 구분할 수 있다
- [ ] Budgets가 언제 쓰이는 도구인지 말할 수 있다
- [ ] Organizations의 통합 결제가 주는 이점을 말할 수 있다
- [ ] Support 플랜의 큰 갈래(Basic / Developer / Business / Enterprise)를 순서대로 말할 수 있다

> 💡 **개념**: **인출 연습(retrieval practice)**은 "다시 읽기"보다 기억을 훨씬 오래 붙잡아 둡니다. 교재를 한 번 더 읽으면 아는 것 같은 느낌은 강해지지만 실제 시험장에서 꺼내지는 힘은 별로 늘지 않습니다. 반대로 책을 덮고 **먼저 떠올린 다음 확인**하면 그 항목은 훨씬 잘 남습니다. 시험 직전 며칠은 읽기보다 "덮고 떠올리기"에 시간을 쓰세요.

## 상황 묘사를 정답 방향으로 번역하기

CLF-C02의 시나리오형 문항은 결국 **문장 속 한두 단어가 정답 방향을 결정**합니다. 아래는 자주 등장하는 상황 문장과 그때 머릿속에 켜져야 할 방향입니다.

| 지문에 이런 표현이 나오면 | 이 방향으로 생각합니다 |
|---------------------------|----------------------|
| "서버 관리를 하고 싶지 않다", "운영 부담 최소" | 서버리스·관리형 서비스 |
| "가장 비용 효율적으로" | 약정 할인 / 저렴한 스토리지 계층 / 중단 가능 워크로드 |
| "한 대가 죽어도 서비스가 계속되어야 한다" | 여러 가용 영역(AZ)에 분산 |
| "지역 전체가 마비돼도 복구되어야 한다" | 여러 리전 |
| "전 세계 사용자에게 빠르게" | 엣지 로케이션 / CDN |
| "누가 무엇을 했는지 나중에 확인해야 한다" | 감사 로그 |
| "설정이 규칙을 지키는지 계속 확인" | 구성 추적 |
| "임계치를 넘으면 알림" | 지표 모니터링 + 알람 |
| "자격 증명을 코드에 넣지 않고" | IAM 역할 |
| "감사 기관에 제출할 인증 보고서" | 규정 준수 보고서 포털 |
| "밀리초 단위 응답", "키-값" | NoSQL |
| "수년치 데이터를 모아 복잡한 분석" | 데이터 웨어하우스 |
| "거의 꺼내지 않지만 버릴 수는 없다" | 아카이브 스토리지 계층 |
| "온프레미스와 안정적인 전용 연결" | 전용 회선 |

> 📚 **사례**: "회사는 회계 감사에 대비해 지난 1년간 어떤 직원이 어떤 리소스를 변경했는지 확인해야 합니다"라는 상황을 봅시다. 여기서 켜져야 할 단어는 **"누가"** 와 **"확인"** 입니다. 성능 지표도 아니고 구성 규칙 준수도 아니라 "행위 주체와 시각"을 묻고 있으니 감사 로그 쪽입니다. 반대로 같은 문장이 "모든 S3 버킷이 암호화 설정을 유지하고 있는지 계속 확인해야 합니다"로 바뀌면, 이번에는 "누가"가 아니라 **"상태가 규칙을 지키는가"** 이므로 구성 추적 쪽으로 답이 이동합니다. 문장 전체가 아니라 **바뀐 한 단어**가 답을 바꾼다는 점이 핵심입니다.

## 복수 응답 문항 다루는 법

CLF-C02에는 "두 개를 고르시오" 형태의 복수 응답 문항이 섞여 있습니다. 이 유형에서 실수가 많이 나옵니다.

- **몇 개를 고르라는지 먼저 확인합니다.** 두 개를 요구하는데 하나만 고르면 그 문항은 점수가 없습니다.
- **정답을 두 개 찾으려 하지 말고, 보기 각각을 O/X로 판정합니다.** 다섯 개 보기를 하나씩 "이게 맞는 말인가?"로 검사하는 편이 빠릅니다.
- **부분 점수를 기대하지 않습니다.** 요구된 개수를 정확히 맞춰야 합니다.
- **둘 다 확실하지 않으면 확실한 하나를 고정하고, 나머지 하나만 비교합니다.**

> ⚠️ **함정**: 복수 응답 문항에서 "가장 그럴듯한 두 개"를 고르면 틀리기 쉽습니다. 출제자는 보통 **같은 카테고리에서 그럴듯한 오답 두세 개**를 함께 배치합니다. 예를 들어 보안 서비스를 두 개 고르는 문항에 보안 서비스가 네 개 등장하는 식입니다. 이럴 때는 "그럴듯함"이 아니라 **지문이 명시적으로 요구한 조건**에 각 보기를 하나씩 맞춰봐야 합니다.

## 자주 나오는 오답 함정과 그 이유

틀리는 데는 패턴이 있습니다. 아래 목록은 "왜 틀리는가"까지 함께 봐야 다음에 안 틀립니다.

| 함정 | 왜 틀리는가 | 교정 |
|------|-------------|------|
| 고가용성 문제에 "여러 리전"을 고름 | 리전이 더 강력해 보여서 | 한 리전 안에서 장애를 견디는 문제면 여러 **AZ**가 정답입니다 |
| 재해 복구 문제에 "여러 AZ"를 고름 | AZ 답이 익숙해서 | 지역 전체 장애 대비면 여러 **리전**입니다 |
| 감사 로그를 물었는데 모니터링을 고름 | 둘 다 "기록"처럼 보여서 | "누가 무엇을 했나"는 감사, "얼마나 쓰이고 있나"는 모니터링입니다 |
| 사전 견적 도구와 사후 분석 도구를 바꿔 고름 | 이름이 둘 다 비용 관련이라 | 아직 안 쓴 것을 계산하면 견적, 이미 쓴 것을 보면 분석입니다 |
| 스팟을 "항상 가장 저렴하니 정답"으로 고름 | 비용 키워드만 보고 | 스팟은 **중단되어도 되는** 워크로드에만 적합합니다 |
| 서버리스 문제에 EC2 Auto Scaling을 고름 | "자동"이라는 단어 때문에 | Auto Scaling도 결국 서버(EC2)를 운영합니다 |
| 관리형 서비스인데 OS 패치를 고객 책임으로 고름 | "OS 패치=고객"만 외워서 | 관리형 데이터베이스처럼 AWS가 기반 OS를 맡는 경우가 있습니다 |
| "무제한", "항상 무료" 보기를 고름 | 매력적으로 들려서 | 절대 표현은 거의 항상 오답 신호입니다 |
| 서비스 이름은 아는데 카테고리를 헷갈림 | 이름만 암기해서 | 이름 옆에 **"무엇을 위한 것"** 을 항상 붙여서 외웁니다 |

## 한 문장 암기 카드

시험장 직전에 훑을 수 있도록 한 문장씩 정리했습니다. 카드 앞면(왼쪽)을 보고 뒷면(오른쪽)이 떠오르는지 확인하세요.

- **탄력성** — 수요에 맞춰 자동으로 늘었다 줄었다 하는 성질입니다.
- **확장성** — 늘릴 수 있는 능력 자체이며, 자동일 필요는 없습니다.
- **고가용성** — 일부가 고장 나도 서비스가 계속됩니다. 답은 보통 여러 AZ입니다.
- **내결함성** — 고장이 나도 성능 저하 없이 그대로 동작합니다.
- **재해 복구** — 큰 사고 뒤 복구하는 계획이며, 답은 보통 여러 리전입니다.
- **공동 책임 모델** — AWS는 클라우드 "자체", 고객은 클라우드 "안"입니다.
- **항상 고객 책임** — 데이터와 접근 권한입니다.
- **IAM 역할** — 자격 증명 없이 임시 권한을 빌려주는 방법입니다.
- **최소 권한** — 좁게 시작해서 필요할 때 넓힙니다.
- **CDN** — 사용자 가까운 곳에 캐시해 지연 시간을 줄입니다.
- **서버리스** — 서버를 내가 관리하지 않습니다. 운영 부담 최소 문항의 단골 정답입니다.
- **온디맨드** — 약정 없이 쓴 만큼 냅니다. 예측 불가한 워크로드용입니다.
- **약정형 할인** — 오래 꾸준히 쓰는 워크로드에서 유리합니다.
- **스팟** — 중단을 견딜 수 있는 작업에만 씁니다.
- **통합 결제** — 여러 계정을 하나의 청구서로 묶고 사용량을 합산합니다.

## 모의고사를 푼 뒤가 더 중요합니다

문제를 푸는 것보다 **틀린 이유를 분류하는 것**이 점수를 올립니다. 채점 후 틀린 문항을 아래 네 가지로 나눠 보세요.

| 분류 | 증상 | 처방 |
|------|------|------|
| ① 몰랐다 | 서비스 자체를 처음 본다 | 해당 개념 한 줄 요약만 외웁니다 |
| ② 헷갈렸다 | 두 서비스 중에서 잘못 골랐다 | 비교표를 만들어 신호어를 구분합니다 |
| ③ 잘못 읽었다 | 부정형·한정어를 놓쳤다 | 읽기 습관 문제이므로 4단계 읽기를 적용합니다 |
| ④ 시간에 쫓겼다 | 마지막에 급하게 찍었다 | 페이스 문제이므로 앞부분 속도를 올립니다 |

③과 ④는 **지식이 아니라 습관 문제**입니다. 시험이 며칠 남지 않았다면 새 개념을 외우는 것보다 이 둘을 고치는 편이 점수 상승 폭이 큽니다.

> 💡 **개념**: 오답 노트는 "틀린 문제를 다시 적는 것"이 아니라 **틀린 이유를 적는 것**입니다. 문제를 옮겨 적는 데 시간을 쓰지 말고, "부정형을 놓침", "AZ와 리전 혼동" 같은 한 줄만 남기세요. 며칠 뒤 그 목록을 보면 자신의 실수 패턴이 두세 가지로 좁혀지는 것이 보입니다.

## 📖 용어

- **인출 연습** : 책을 덮고 먼저 떠올린 뒤 확인하는 학습법. 다시 읽기보다 기억이 오래갑니다.
- **페이스** : 문항당 쓰는 시간의 리듬. 65문항 90분이면 평균 약 1분 23초입니다.
- **한정어** : "가장", "최소", "아닌", "두 개" 같은 답을 결정짓는 단어.
- **신호어** : "밀리초", "장기 보관", "운영 부담 최소"처럼 정답 서비스를 가리키는 지문 속 단어.
- **소거법** : 정답을 찾기 전에 명백한 오답부터 지워 선택지를 좁히는 방법.
- **복수 응답 문항** : 정답을 두 개 이상 고르라고 요구하는 유형. 개수를 정확히 맞춰야 합니다.
- **평가용 문항** : 65문항 중 채점되지 않는 15문항. 어느 것인지 알 수 없어 모두 성실히 풀어야 합니다.
- **오답 노트** : 틀린 문제가 아니라 **틀린 이유**를 모아 두는 기록.
- **즉답형 문항** : 용어 정의나 서비스 이름을 바로 묻는 짧은 문항. 시간을 버는 구간입니다.
- **시나리오형 문항** : 상황을 길게 묘사하고 최적의 선택을 묻는 문항. 조건이 많을수록 답이 좁혀집니다.
- **절대 표현** : "항상", "무제한", "100% 보장" 등. 보기에 있으면 오답일 가능성이 큽니다.
- **표시(마킹)** : 나중에 다시 볼 문항을 시험 화면에서 체크해 두는 기능.

## 📝 연습 문제

**문제 1.** 트래픽이 급증하면 EC2 인스턴스를 자동으로 늘리고, 줄면 자동으로 줄이는 클라우드의 특성을 무엇이라 하는가?

A) 내구성  
B) 탄력성  
C) 페일오버  
D) 다중 테넌시  

**정답: B**  
해설: 탄력성은 수요 변화에 따라 리소스를 자동으로 늘리고 줄이는 능력으로, Auto Scaling이 대표적입니다. 내구성은 데이터 손실 방지 정도, 페일오버는 장애 시 대체 전환, 다중 테넌시는 여러 고객이 인프라를 공유하는 개념입니다.

---

**문제 2.** 웹 애플리케이션을 SQL 인젝션과 교차 사이트 스크립팅(XSS) 공격으로부터 보호하려면 어떤 서비스를 사용해야 하는가?

A) AWS Shield  
B) Amazon GuardDuty  
C) AWS WAF  
D) AWS KMS  

**정답: C**  
해설: AWS WAF는 웹 애플리케이션 방화벽으로 SQL 인젝션과 XSS 같은 계층 7 공격을 필터링합니다. Shield는 DDoS 방어, GuardDuty는 위협 탐지, KMS는 암호화 키 관리 서비스입니다.

---

**문제 3.** 밀리초 단위의 빠른 응답이 필요한 서버리스 NoSQL 데이터베이스로 가장 적합한 것은?

A) Amazon RDS  
B) Amazon DynamoDB  
C) Amazon Redshift  
D) Amazon Aurora  

**정답: B**  
해설: DynamoDB는 완전관리형 서버리스 NoSQL로 일관된 한 자릿수 밀리초 성능을 제공합니다. RDS와 Aurora는 관계형 데이터베이스, Redshift는 분석용 데이터 웨어하우스로 용도가 다릅니다.

---

**문제 4.** 전 세계 사용자에게 동영상과 이미지를 짧은 지연 시간으로 전달하기 위해 엣지 로케이션에서 콘텐츠를 캐싱하려면 어떤 서비스를 사용해야 하는가?

A) Amazon Route 53  
B) AWS Direct Connect  
C) Amazon CloudFront  
D) Amazon VPC  

**정답: C**  
해설: CloudFront는 콘텐츠 전송 네트워크(CDN)로 엣지 로케이션에 콘텐츠를 캐싱하여 지연 시간을 줄입니다. Route 53은 DNS, Direct Connect는 전용 회선, VPC는 격리된 가상 네트워크입니다.

---

**문제 5.** 여러 AWS 계정의 청구를 하나로 합쳐 볼륨 할인 혜택을 공유하려면 무엇을 사용해야 하는가?

A) AWS Organizations의 통합 결제  
B) AWS Budgets  
C) Savings Plans  
D) AWS Cost Explorer  

**정답: A**  
해설: AWS Organizations의 통합 결제는 여러 계정의 사용량을 합산해 단일 청구서로 만들고 볼륨 기반 할인을 공유합니다. Budgets는 예산 알림, Savings Plans는 사용량 약정 할인, Cost Explorer는 비용 분석 도구입니다.

---

**문제 6.** 코드를 업로드하면 AWS가 용량 프로비저닝, 로드 밸런싱, 확장을 자동으로 처리해 주는 PaaS형 서비스는?

A) Amazon EC2  
B) AWS Lambda  
C) AWS Elastic Beanstalk  
D) Amazon ECS  

**정답: C**  
해설: Elastic Beanstalk는 코드를 업로드하면 인프라 구성과 확장을 자동 처리하는 PaaS 서비스입니다. EC2는 사용자가 직접 관리하는 IaaS, Lambda는 함수 단위 서버리스, ECS는 컨테이너 오케스트레이션입니다.

---

**문제 7.** AWS가 제공하는 규정 준수 보고서(SOC, PCI DSS 등)를 직접 다운로드하려면 어떤 서비스를 사용하는가?

A) AWS Config  
B) AWS Artifact  
C) AWS Trusted Advisor  
D) AWS CloudTrail  

**정답: B**  
해설: AWS Artifact는 SOC, PCI DSS 등 AWS의 규정 준수 보고서를 온디맨드로 제공하는 포털입니다. Config는 리소스 구성 추적, Trusted Advisor는 모범 사례 점검, CloudTrail은 API 감사 로그 서비스입니다.

**문제 8.** 안정적이고 지속적으로 실행되는 워크로드에서 1~3년 약정으로 최대 할인을 받으려는 경우 가장 적합한 EC2 요금 모델은?

A) 온디맨드 인스턴스  
B) 스팟 인스턴스  
C) 예약 인스턴스  
D) 전용 인스턴스  

**정답: C**  
해설: 예약 인스턴스(또는 Savings Plans)는 1~3년 사용을 약정하는 대가로 큰 할인을 제공하여 지속적이고 예측 가능한 워크로드에 적합합니다. 온디맨드는 약정·할인이 없고, 스팟은 중단 가능한 작업용, 전용 인스턴스는 격리 요건용입니다.
