# Day 2 - 도메인 복습 2: 보안 및 규정 준수 + 청구·요금·지원 핵심 총정리

어제는 클라우드 개념과 기술·서비스를 정리했습니다. 오늘은 나머지 두 영역, **Domain 2 (보안 및 규정 준수, 30%)** 와 **Domain 4 (청구·요금·지원, 12%)** 를 총정리합니다. Domain 2는 비중이 두 번째로 큰 만큼 출제가 많고, Domain 4는 작지만 IAM·요금 도구처럼 헷갈리기 쉬운 포인트가 모여 있습니다.

## Domain 2 핵심 — 보안 및 규정 준수

### 공동 책임 모델 (Shared Responsibility Model)

가장 중요한 개념입니다. "클라우드의 보안 vs 클라우드 내부의 보안"으로 구분합니다.

| 책임 주체 | 담당 영역 | 예시 |
|-----------|-----------|------|
| AWS (of the Cloud) | 인프라 보안 | 물리적 시설, 하드웨어, 네트워크, 하이퍼바이저 |
| 고객 (in the Cloud) | 데이터·구성 보안 | 데이터 암호화, IAM 설정, OS 패치, 보안 그룹 |

> 💡 **관련 이론**: "고객 데이터 암호화", "IAM 사용자 관리", "EC2 게스트 OS 패치"는 항상 **고객 책임**입니다. 반대로 "데이터센터 물리 보안", "하드웨어 폐기"는 **AWS 책임**입니다. 단, 관리형 서비스(RDS 등)는 OS 패치를 AWS가 담당하는 점에 주의하세요.

### IAM (Identity and Access Management)

| 요소 | 핵심 |
|------|------|
| 사용자(User) | 개별 사람/애플리케이션 자격 증명 |
| 그룹(Group) | 사용자 묶음, 권한 일괄 부여 |
| 역할(Role) | 임시 권한 위임(서비스 간, 페더레이션) |
| 정책(Policy) | JSON 권한 문서, 최소 권한 원칙 적용 |

- **루트 사용자**: 절대 일상 작업에 쓰지 말고 **MFA 활성화** 후 잠가둔다
- **최소 권한 원칙**: 꼭 필요한 권한만 부여

### 주요 보안 서비스

| 서비스 | 역할 |
|--------|------|
| IAM | 인증·인가 |
| AWS Shield | DDoS 방어 |
| AWS WAF | 웹 애플리케이션 방화벽(SQL 인젝션, XSS 차단) |
| GuardDuty | 위협 탐지(지능형 모니터링) |
| Amazon Inspector | 취약점 자동 평가 |
| KMS | 암호화 키 관리 |
| Secrets Manager | 비밀번호·키 보관 및 자동 교체 |
| AWS Config | 리소스 구성 추적·규정 준수 |
| CloudTrail | API 호출 감사 로그 |

> 💡 **관련 이론**: "누가 무엇을 했는지(API 감사)"는 **CloudTrail**, "리소스가 규정을 지키는지 추적"은 **Config**, "성능/지표 모니터링"은 **CloudWatch**입니다. 이 셋의 구분이 단골 함정입니다.

### 규정 준수 도구

- **AWS Artifact**: 규정 준수 보고서(SOC, PCI DSS 등) 다운로드
- **AWS Compliance Center / Programs**: 인증 프로그램 정보

## Domain 4 핵심 — 청구·요금·지원

### EC2 요금 모델

| 모델 | 특징 | 적합한 경우 |
|------|------|-------------|
| 온디맨드 | 사용한 만큼, 약정 없음 | 단기·예측 불가 워크로드 |
| 예약 인스턴스(RI) | 1~3년 약정, 큰 할인 | 안정적·지속 워크로드 |
| Savings Plans | 사용량 약정 기반 할인 | 유연한 장기 절감 |
| 스팟 인스턴스 | 최대 90% 할인, 중단 가능 | 내결함성 배치 작업 |

### 비용 관리·청구 도구

| 도구 | 용도 |
|------|------|
| AWS Pricing Calculator | 사전 비용 견적 |
| AWS Cost Explorer | 사용·비용 추세 시각화/분석 |
| AWS Budgets | 예산 설정 및 초과 시 알림 |
| Cost and Usage Report (CUR) | 가장 상세한 청구 데이터 |
| Billing Conductor | 사용자 정의 청구 |

> 💡 **관련 이론**: "예산을 넘으면 알림을 받고 싶다"면 **Budgets**, "과거 비용 추세를 분석"하려면 **Cost Explorer**, "아직 만들지 않은 리소스 견적"은 **Pricing Calculator**입니다.

### AWS Organizations & 통합 결제

- **Organizations**: 여러 계정을 묶어 중앙 관리
- **통합 결제(Consolidated Billing)**: 청구를 하나로 합쳐 **볼륨 할인** 공유
- **SCP(서비스 제어 정책)**: 계정별 허용 작업 제한

### 지원 플랜

| 플랜 | 핵심 |
|------|------|
| Basic | 무료, 문서·포럼 |
| Developer | 업무 시간 이메일 지원 |
| Business | 24/7 기술 지원, 전체 Trusted Advisor |
| Enterprise On-Ramp / Enterprise | TAM(전담 기술 계정 관리자), 가장 빠른 응답 |

> 💡 **관련 이론**: **전담 TAM(Technical Account Manager)** 이 필요하면 **Enterprise** 플랜입니다. 24/7 전화 지원이 처음 제공되는 것은 **Business** 플랜부터입니다.

## 오늘의 마무리

이틀에 걸쳐 4개 영역을 모두 압축 정리했습니다. 특히 **공동 책임 모델**, **CloudTrail/Config/CloudWatch 구분**, **요금 모델 4종**은 출제 빈도가 매우 높으니 반드시 손에 익혀두세요. 내일은 4개 영역을 섞은 종합 모의 문제로 페이스를 점검합니다.

## 📝 연습 문제

**문제 1.** 공동 책임 모델에서 다음 중 항상 고객의 책임에 해당하는 것은?

A) 데이터센터의 물리적 보안  
B) 하이퍼바이저 패치  
C) IAM 사용자 및 권한 구성  
D) 하드웨어의 안전한 폐기  

**정답: C**  
해설: IAM 사용자와 권한 설정은 클라우드 "내부"의 구성으로 항상 고객 책임입니다. 물리적 보안, 하이퍼바이저 패치, 하드웨어 폐기는 모두 클라우드 인프라에 해당하므로 AWS 책임입니다.

---

**문제 2.** 계정에서 발생한 모든 API 호출 기록을 감사 목적으로 추적하려면 어떤 서비스를 사용해야 하는가?

A) Amazon CloudWatch  
B) AWS CloudTrail  
C) AWS Config  
D) Amazon Inspector  

**정답: B**  
해설: CloudTrail은 누가 언제 어떤 API를 호출했는지 기록하는 감사 로그 서비스입니다. CloudWatch는 성능 지표·로그 모니터링, Config는 리소스 구성 변경·규정 준수 추적, Inspector는 취약점 평가용입니다.

---

**문제 3.** 중단되어도 무방한 대규모 배치 처리 작업의 비용을 최대 90%까지 절감하려면 가장 적합한 EC2 요금 모델은?

A) 온디맨드 인스턴스  
B) 예약 인스턴스  
C) 스팟 인스턴스  
D) 전용 호스트  

**정답: C**  
해설: 스팟 인스턴스는 여유 용량을 최대 90% 저렴하게 제공하지만 AWS가 회수할 수 있어 중단에 강한(내결함성) 작업에 적합합니다. 온디맨드는 할인이 없고, 예약 인스턴스는 장기 약정 기반, 전용 호스트는 규정 준수·라이선스 목적입니다.

---

**문제 4.** 전담 기술 계정 관리자(TAM)의 지원이 필요한 대규모 기업에 가장 적합한 AWS Support 플랜은?

A) Basic  
B) Developer  
C) Business  
D) Enterprise  

**정답: D**  
해설: 전담 TAM은 Enterprise(및 Enterprise On-Ramp) 플랜에서 제공됩니다. Basic은 무료 기본 지원, Developer는 업무 시간 이메일, Business는 24/7 기술 지원을 제공하지만 전담 TAM은 포함하지 않습니다.

---

**문제 5.** 월별 비용이 설정한 한도를 초과할 경우 알림을 받고 싶다면 어떤 도구를 사용해야 하는가?

A) AWS Pricing Calculator  
B) AWS Budgets  
C) AWS Cost Explorer  
D) AWS Artifact  

**정답: B**  
해설: AWS Budgets는 예산 한도를 설정하고 초과하거나 예측치가 넘으면 알림을 보내는 도구입니다. Pricing Calculator는 사전 견적, Cost Explorer는 과거 비용 분석, Artifact는 규정 준수 보고서 제공 도구입니다.
