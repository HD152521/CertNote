# Day 5 - D-Day 마무리: 시험 구성, 시간 배분, 마지막 점검 체크리스트

드디어 마지막 날입니다. 오늘은 새 지식을 넣기보다 **시험을 어떻게 치를지** 전략을 다집니다. 시험 구성을 정확히 알고, 시간 배분 계획을 세우고, 당일 점검 체크리스트를 손에 쥐면 같은 실력으로도 더 높은 점수를 받을 수 있습니다.

## 📌 핵심 정리

- 오늘은 **새 지식을 넣는 날이 아니라 꺼낼 준비를 하는 날**입니다. 시험 전날의 벼락치기는 대개 점수보다 불안을 키웁니다.
- 65문항 / 90분. 1차 통과 60분, 2차 재검토 25분, 마지막 점검 5분이 기본 골격입니다.
- 합격선은 1,000점 만점에 **700점**입니다. 만점을 노릴 필요가 없습니다.
- 빈칸은 무조건 0점입니다. 마지막 5분은 **미응답 채우기 전용**으로 남겨 두세요.
- 컨디션도 실력의 일부입니다. 잠·식사·이동 시간을 전날 미리 계획해 두세요.

## 시험 구성 (CLF-C02)

| 항목 | 내용 |
|------|------|
| 문항 수 | 65문항 |
| 시간 | 90분 |
| 채점 문항 | 50문항 (15문항은 채점 안 되는 평가용) |
| 문제 유형 | 객관식(보기 1개 정답), 복수 응답(보기 2개 이상) |
| 점수 범위 | 100 ~ 1,000점 |
| 합격선 | 700점 |
| 응시 방식 | 시험장(테스트 센터) 또는 온라인 감독 |
| 결과 | 보통 영업일 기준 며칠 내 합격/불합격 통보 |

> 💡 **관련 이론**: 65문항 중 15문항은 채점되지 않는 평가 문항입니다. 어떤 문항이 평가용인지 알 수 없으므로 **모든 문항을 진지하게** 풀어야 합니다. 합격은 1,000점 만점에 700점 기준입니다.

### 문제 유형별 대응

| 유형 | 어떻게 생겼나 | 대응 |
|------|-------------|------|
| 객관식(정답 1개) | 보기 넷 중 하나를 고름 | 명백한 오답 2개를 먼저 지웁니다 |
| 복수 응답(2개 이상) | "두 개를 고르시오" 형태 | 보기마다 O/X를 매겨 판정합니다 |

복수 응답 문항에서는 **요구된 개수를 정확히 맞춰야** 점수가 됩니다. 하나만 고르거나 세 개를 고르면 그 문항은 살릴 수 없습니다. 문항을 읽자마자 "몇 개를 고르라고 했는가"부터 확인하세요.

### 도메인 비중을 머릿속에 넣고 들어가기

| 영역 | 이름 | 비중 |
|------|------|------|
| Domain 1 | 클라우드 개념 | 24% |
| Domain 2 | 보안 및 규정 준수 | 30% |
| Domain 3 | 클라우드 기술 및 서비스 | 34% |
| Domain 4 | 청구·요금·지원 | 12% |

- Domain 3(34%)과 Domain 2(30%)를 합치면 **전체의 64%**입니다. 시험지 문항 셋 중 둘은 이 두 영역에서 나온다고 보면 됩니다.
- Domain 4는 12%로 가장 작지만, 요금 모델과 비용 도구는 **정답이 딱 떨어지는** 영역이라 투자 대비 회수가 좋습니다. 여기서 흘리는 점수가 아깝습니다.
- 비중은 "무엇을 더 공부할지"가 아니라, 시험장에서 **어느 영역 문제가 많이 나올지 예상하는 용도**로 씁니다. 오늘은 이미 공부를 늘릴 시점이 아닙니다.

> ⚠️ **함정**: "Domain 4는 12%뿐이니 버려도 된다"고 생각하면 곤란합니다. 65문항 기준으로 열 문항 가까이가 여기서 나오고, 합격선까지의 여유가 그리 크지 않습니다. 게다가 요금 모델(온디맨드·약정·스팟)과 비용 도구(사전 견적·사후 분석·예산 알림)는 **외우면 바로 맞는** 유형이라 포기할 이유가 없습니다.

## 시간 배분 전략

- 65문항 / 90분 = 문항당 약 **1분 23초**
- **1차 통과**: 60분 안에 전 문항 1회 통과. 쉬운 건 즉답, 헷갈리면 표시 후 넘김
- **2차 복귀**: 남은 30분에 표시한 문제 재검토
- **마지막 점검**: 모든 문항에 답이 있는지 확인(빈칸은 무조건 오답이므로 추측이라도 채움)

| 구간 | 시간 | 할 일 |
|------|------|-------|
| 0~60분 | 60분 | 전 문항 1차 풀이 + 표시 |
| 60~85분 | 25분 | 표시 문항 재검토 |
| 85~90분 | 5분 | 미응답 확인, 추측 채우기 |

> 💡 **관련 이론**: 빈칸은 0점이지만 추측한 답은 맞을 가능성이 있습니다. 4지선다에서 명백한 오답 2개를 지우면 정답 확률이 50%까지 올라갑니다. 반드시 **모든 문항에 답을 채우세요.**

### 중간 점검 지점을 미리 정해 두세요

시계를 계속 보면 오히려 불안해집니다. **확인 지점 두 곳만** 정해 두고 그때만 보세요.

| 확인 시점 | 여기쯤 와 있어야 정상 | 늦었다면 |
|-----------|---------------------|---------|
| 30분 경과 | 약 22~25문항 | 확신 없는 문항을 더 과감히 표시하고 넘깁니다 |
| 60분 경과 | 65문항 1차 통과 완료 | 남은 문항을 빠르게 훑고 표시만 남깁니다 |

### 페이스가 무너졌을 때의 복구 순서

시험장에서 "시간이 모자란다"고 느끼는 순간이 올 수 있습니다. 그때는 다음 순서로 움직이세요.

1. **남은 시간과 남은 문항 수를 셉니다.** 막연한 불안보다 숫자가 낫습니다.
2. **표시해 둔 문항은 잠시 잊고, 아직 손대지 않은 문항부터 갑니다.** 안 본 문항이 표시 문항보다 맞을 확률이 높습니다.
3. **긴 지문은 마지막 질문 문장만 읽고 판단합니다.** 조건을 다 못 읽어도 카테고리는 잡힙니다.
4. **그래도 시간이 부족하면 남은 문항에 일단 답을 채워 둡니다.** 채운 뒤 시간이 남으면 돌아옵니다.

### 마지막 5분 루틴

- [ ] 응답하지 않은 문항이 하나도 없는지 확인합니다
- [ ] 복수 응답 문항에서 요구 개수를 맞췄는지 확인합니다
- [ ] 근거 없이 바꾸고 싶어지는 답은 그대로 둡니다
- [ ] 남은 시간이 있어도 무리하게 답을 뒤집지 않고 제출합니다

> 📚 **사례**: 시험을 치른 사람들이 가장 많이 후회하는 지점은 "몰라서 틀린 문제"가 아니라 **"마지막에 답을 바꿔서 틀린 문제"** 입니다. 40번 문항에서 A를 골랐다가 마지막 3분에 "아무래도 C 같은데" 하고 바꿨는데 원래 A가 정답이었던 경우입니다. 답을 바꾸는 기준은 딱 하나여야 합니다 — **처음에 못 본 조건을 새로 발견했을 때만** 바꿉니다. "느낌이 이상해서"는 근거가 아닙니다.

## 시험 전 마지막 인출 — 도메인별 한 문장

책을 덮고 아래 질문에 먼저 답해 보세요. 이 단계에서 막히는 항목이 있다면, 그 한 줄만 다시 보고 넘어가면 충분합니다.

**Domain 1 — 클라우드 개념**

- 클라우드의 6가지 이점은? → 선투자→가변비용, 규모의 경제, 용량 추정 불필요, 속도·민첩성, 데이터센터 운영비 절감, 몇 분 만에 전 세계 배포
- 확장성과 탄력성의 차이는? → 늘릴 수 있는 능력 / 수요에 맞춰 자동으로 늘고 줄어드는 성질
- IaaS·PaaS·SaaS는? → 기초 인프라만 / 앱 실행 환경까지 / 완성된 소프트웨어까지
- 고가용성은 무엇으로 얻나? → 여러 가용 영역(AZ) 분산

**Domain 2 — 보안 및 규정 준수**

- 공동 책임 모델 한 줄은? → AWS는 클라우드 "자체", 고객은 클라우드 "안"
- 어떤 서비스를 쓰든 항상 고객 책임인 것은? → 데이터와 접근 권한
- EC2가 S3에 접근해야 할 때 안전한 방법은? → IAM 역할
- 계정 보안의 첫 단계는? → 루트 사용자 MFA 활성화 + 일상 사용 금지
- CloudTrail / Config / CloudWatch는? → 누가 했나 / 규칙을 지키나 / 지표가 정상인가
- Shield / WAF / GuardDuty는? → DDoS 방어 / 웹 공격 차단 / 위협 탐지

**Domain 3 — 클라우드 기술 및 서비스**

- S3 / EBS / EFS는? → 객체 저장 / 한 대에 붙는 디스크 / 여러 대가 공유하는 파일 시스템
- RDS / DynamoDB / Redshift는? → 관계형 / 서버리스 NoSQL / 분석용 데이터 웨어하우스
- EC2 / Lambda의 차이는? → 내가 관리하는 서버 / 이벤트가 있을 때만 실행되는 함수
- ELB와 Auto Scaling은? → 트래픽 나누기 / 서버 대수 늘리고 줄이기
- CloudFront는? → 엣지에 캐시해 전 세계 사용자에게 빠르게 전달

**Domain 4 — 청구·요금·지원**

- 온디맨드 / 약정형 / 스팟은 언제? → 예측 불가·단기 / 장기간 꾸준히 / 중단을 견딜 수 있을 때
- Pricing Calculator / Cost Explorer / Budgets는? → 미래 견적 / 과거 분석 / 현재 알림
- 통합 결제의 이점은? → 여러 계정 청구를 하나로 묶고 사용량을 합산
- Support 플랜의 갈래는? → Basic / Developer / Business / Enterprise

- [ ] 컴퓨팅: EC2 / Lambda / Beanstalk / Fargate
- [ ] 스토리지: S3 / EBS / EFS / Glacier
- [ ] 데이터베이스: RDS / DynamoDB / Redshift / Aurora
- [ ] 네트워킹: VPC / Route 53 / CloudFront / Direct Connect
- [ ] 요금 모델: 온디맨드 / 예약 / Savings Plans / 스팟
- [ ] 비용 도구: Pricing Calculator / Cost Explorer / Budgets
- [ ] Support 플랜 차이(Business=24/7, Enterprise=TAM)

## 헷갈릴 때 쓰는 3초 판별 규칙

시험장에서 두 보기 사이에서 멈췄을 때 꺼내 쓸 짧은 규칙들입니다.

| 상황 | 3초 판별 |
|------|---------|
| AZ인가 리전인가 | 지문에 "지역·지리적" 표현이 있으면 리전, 없으면 AZ |
| 감사인가 모니터링인가 | "누가 했나"면 감사, "얼마나 쓰이나"면 모니터링 |
| 견적인가 분석인가 | 아직 안 썼으면 견적, 이미 썼으면 분석 |
| 스팟을 골라도 되나 | "중단되면 안 된다"는 표현이 있으면 탈락 |
| 서버리스인가 아닌가 | 내가 인스턴스를 세는 순간 서버리스가 아닙니다 |
| 권한을 어떻게 주나 | 사람이면 사용자·그룹, 서비스면 역할 |
| 보기가 매력적인데 확신이 없다 | "항상·무제한·100%"가 있으면 지웁니다 |

> 💡 **개념**: 이런 짧은 규칙을 **휴리스틱(heuristic)** 이라고 합니다. 완벽한 판별법은 아니지만, 시간이 없을 때 **틀릴 확률을 낮추는 지름길** 역할을 합니다. 시험장에서 이론을 처음부터 다시 유도할 시간은 없습니다. 오늘 이 표를 몇 번 읽어 두면, 실제 문항 앞에서 "고민"이 "판별"로 바뀝니다.

## 시험 당일 체크리스트 (실무)

- [ ] 신분증 준비(이름이 등록 정보와 일치하는지)
- [ ] 온라인 감독이면 카메라·마이크·인터넷·조용한 공간 점검
- [ ] 시험 시작 전 충분히 휴식, 과한 벼락치기 금지
- [ ] 시작 30분 전 도착(시험장) 또는 시스템 사전 점검(온라인)
- [ ] 모든 문항 응답 완료 후 제출

### 시험 전날 밤

- [ ] 예약한 **날짜·시각·응시 방식(시험장/온라인)** 을 다시 확인했다
- [ ] 시험장 응시라면 위치와 이동 경로, 예상 소요 시간을 확인했다
- [ ] 온라인 응시라면 응시 안내에 적힌 사전 점검 절차를 미리 한 번 돌려 봤다
- [ ] 신분증을 미리 꺼내 눈에 보이는 곳에 두었다
- [ ] 새 개념을 붙잡지 않고, 핵심 정리와 번역표만 훑었다
- [ ] 평소보다 일찍 잠자리에 들었다

### 시험 당일 아침

- [ ] 평소처럼 식사했다(과식·공복 모두 피함)
- [ ] 카페인은 평소 마시던 양만큼만 마셨다
- [ ] 여유 있게 출발했다 / 온라인이면 장비를 미리 켜 두었다
- [ ] 시작 직전에는 새 문제를 풀지 않고 암기 카드만 훑었다

### 온라인 감독 응시라면 추가로

- [ ] 조용하고 방해받지 않는 공간을 확보했다
- [ ] 책상 위를 비웠다(시험 규정에서 허용하지 않는 물건은 미리 치움)
- [ ] 인터넷 연결이 안정적인지 확인했다

- **재해 복구** — 지역 전체 장애 대비입니다. 답은 여러 리전입니다.
- **공동 책임 모델** — AWS는 클라우드 자체, 고객은 클라우드 안입니다.
- **항상 고객 책임** — 데이터와 접근 권한입니다.
- **IAM 역할** — 자격 증명 없이 임시 권한을 빌려줍니다.
- **최소 권한** — 좁게 시작해 필요할 때 넓힙니다.
- **서버리스** — 운영 부담 최소 문항의 단골 정답입니다.
- **CDN** — 엣지에 캐시해 지연 시간을 줄입니다.
- **스팟** — 중단을 견딜 수 있는 작업에만 씁니다.
- **약정형 할인** — 오래 꾸준히 쓰는 워크로드에 유리합니다.
- **통합 결제** — 여러 계정 청구를 하나로 묶고 사용량을 합산합니다.
- **감사는 CloudTrail, 설정은 Config, 지표는 CloudWatch**입니다.
- **DDoS는 Shield, 웹 공격은 WAF**입니다.
- **빈칸은 0점** — 반드시 모든 문항에 답을 채웁니다.

**문제 3.** 시험 시간 관리에서 빈칸으로 남긴 문항에 대한 가장 올바른 전략은?

A) 확신이 없으면 비워 두어 감점을 피한다  
B) 명백한 오답을 제거한 뒤 추측이라도 반드시 답을 채운다  
C) 어려운 문항은 처음부터 건너뛰고 다시 보지 않는다  
D) 모든 문항의 답을 C로 통일한다  

**정답: B**  
해설: 빈칸은 무조건 0점이지만 추측한 답은 맞을 가능성이 있어 명백한 오답을 지운 뒤 반드시 답을 채워야 합니다. 이 시험에는 오답 감점이 없으므로 비워 두는 것이 불리하며, 어려운 문항을 영영 포기하거나 무작정 한 글자로 통일하는 것도 좋은 전략이 아닙니다.
