# Day 2 - 정규화

## 📌 핵심 정리

- 정규화는 **함수 종속**을 기준으로 엔터티를 쪼개 **중복과 이상현상**을 없애는 과정이다.
- 이상현상은 셋이다. **삽입 이상 · 갱신 이상 · 삭제 이상**.
- 1NF는 **원자값**, 2NF는 **부분 함수 종속 제거**, 3NF는 **이행 함수 종속 제거**, BCNF는 **모든 결정자가 후보키**다.
- 4NF는 다치 종속, 5NF는 조인 종속을 다룬다. 시험 범위에서는 이름과 대상만 구분하면 된다.
- 정규화는 입력·수정·삭제 성능을 높인다. 조회는 조인이 늘어 느려질 수도 있고, 테이블이 작아져 빨라질 수도 있다.

## 함수 종속

정규화의 모든 단계는 한 가지 질문으로 설명된다. "이 속성의 값을 정하는 것은 무엇인가."

- 속성 X의 값이 정해지면 속성 Y의 값이 하나로 정해질 때 **Y는 X에 함수 종속**이라 한다. 표기는 `X → Y`다.
- 이때 X를 **결정자**, Y를 **종속자**라 부른다.

EMP와 DEPT에서 함수 종속을 적어 보면 다음과 같다.

| 함수 종속 | 읽는 법 |
|----------|--------|
| `EMPNO → ENAME, JOB, SAL, DEPTNO` | 사번이 정해지면 이름·직무·급여·부서번호가 하나로 정해진다 |
| `DEPTNO → DNAME, LOC` | 부서번호가 정해지면 부서명·지역이 정해진다 |
| `ENAME → EMPNO` | 성립하지 않는다. 동명이인이 생길 수 있다 |

함수 종속은 세 가지 모양으로 나뉜다. 각 모양이 정규형 하나와 짝을 이룬다.

| 종류 | 모양 | 없애는 정규형 |
|------|------|------------|
| **완전 함수 종속** | 복합키 **전체**에 종속 | (목표 상태) |
| **부분 함수 종속** | 복합키의 **일부**에만 종속 | 2NF |
| **이행 함수 종속** | `X → Y`, `Y → Z`라서 `X → Z`가 되는 종속 | 3NF |

## 이상현상

정규화하지 않은 테이블을 직접 만들어 이상현상을 확인했다. 주문상품 테이블에 상품명까지 함께 넣은 경우다. 주식별자는 `(ORDER_NO, PROD_NO)`이다.

```sql
CREATE TABLE T_ORD_LINE (
  ORDER_NO  NUMBER(4),
  PROD_NO   VARCHAR2(4),
  PROD_NAME VARCHAR2(20),
  QTY       NUMBER(3),
  CONSTRAINT T_ORD_LINE_PK PRIMARY KEY (ORDER_NO, PROD_NO)
);
INSERT INTO T_ORD_LINE VALUES (1001, 'P1', 'PEN', 2);
INSERT INTO T_ORD_LINE VALUES (1002, 'P1', 'PEN', 5);
INSERT INTO T_ORD_LINE VALUES (1002, 'P2', 'NOTE', 1);
SELECT * FROM T_ORD_LINE ORDER BY ORDER_NO, PROD_NO;
```

```text
  ORDER_NO PROD PROD_NAME                   QTY
---------- ---- -------------------- ----------
      1001 P1   PEN                           2
      1002 P1   PEN                           5
      1002 P2   NOTE                          1
```

- `PROD_NAME`은 `PROD_NO`만 알면 정해진다. 주식별자의 일부에만 종속된 **부분 함수 종속**이다.
- 그 결과 `P1`의 이름 `PEN`이 주문 건수만큼 반복 저장된다.

### 갱신 이상

`P1`의 상품명을 바꾸면서 한 행만 고치면 같은 상품에 이름이 두 개 생긴다.

```sql
UPDATE T_ORD_LINE SET PROD_NAME = 'GEL PEN' WHERE ORDER_NO = 1001 AND PROD_NO = 'P1';
SELECT * FROM T_ORD_LINE ORDER BY ORDER_NO, PROD_NO;
SELECT PROD_NO, COUNT(DISTINCT PROD_NAME) AS NAME_CNT FROM T_ORD_LINE GROUP BY PROD_NO ORDER BY PROD_NO;
```

```text
  ORDER_NO PROD PROD_NAME                   QTY
---------- ---- -------------------- ----------
      1001 P1   GEL PEN                       2
      1002 P1   PEN                           5
      1002 P2   NOTE                          1

PROD   NAME_CNT
---- ----------
P1            2
P2            1
```

### 삽입 이상

아직 아무도 주문하지 않은 상품 `P3`를 등록하려 하면 주문번호가 없어 막힌다.

```sql
INSERT INTO T_ORD_LINE (ORDER_NO, PROD_NO, PROD_NAME) VALUES (NULL, 'P3', 'ERASER');
```

```text
ERROR at line 1:
ORA-01400: cannot insert NULL into ("SCOTT"."T_ORD_LINE"."ORDER_NO")
```

### 삭제 이상

`1002`번 주문을 취소해 행을 지우면 `P2`(NOTE)라는 상품이 존재했다는 정보도 함께 사라진다. 상품 정보가 주문 행에 얹혀 있기 때문이다.

실습 후 테이블은 `DROP TABLE T_ORD_LINE PURGE;`로 지웠다.

| 이상현상 | 증상 | 위 예에서 |
|---------|------|----------|
| **삽입 이상** | 원하지 않는 값까지 넣어야 입력된다 | 주문 없이는 상품을 등록할 수 없다 |
| **갱신 이상** | 일부만 고쳐져 데이터가 **불일치**한다 | `P1` 이름이 PEN과 GEL PEN으로 갈렸다 |
| **삭제 이상** | 지우려던 것 외의 정보까지 사라진다 | 주문 삭제로 상품 정보가 없어진다 |

해결은 상품명을 결정자 `PROD_NO`와 함께 **상품 테이블로 분리**하는 것이다. 주문상품에는 `(ORDER_NO, PROD_NO, QTY)`만 남긴다. 이 분리가 2NF다.

## 정규형 단계

| 정규형 | 조건 | 없애는 것 | 분리 예 |
|--------|------|----------|--------|
| **1NF** | 모든 속성이 **원자값**을 가진다 | 다중값 속성, 반복 그룹 | 사원의 "보유자격"에 `정보처리, SQLD`를 한 칸에 넣었다면 행이나 엔터티로 나눈다 |
| **2NF** | 1NF + 모든 일반 속성이 주식별자 **전체**에 종속 | 부분 함수 종속 | 주문상품에서 상품명을 상품으로 분리 |
| **3NF** | 2NF + 일반 속성끼리의 종속이 없다 | 이행 함수 종속 | 사원에 있던 부서명·지역을 부서로 분리 |
| **BCNF** | 3NF + **모든 결정자가 후보키** | 후보키가 아닌 결정자 | 아래 예 참고 |
| 4NF | BCNF + 다치 종속 없음 | 다치 종속 | 서로 독립인 다중값 두 개를 각각 분리 |
| 5NF | 4NF + 조인 종속 없음 | 조인 종속 | 후보키를 통하지 않는 조인 종속을 분리 |

- 2NF 위반은 **복합 주식별자**일 때만 생긴다. 주식별자가 단일 속성이면 "일부에만 종속"될 수 없다.
- 1NF의 원자값은 "더 나눌 필요가 없는 하나의 값"이다. 어디까지가 원자값인지는 업무가 정한다.

### 3NF — EMP와 DEPT가 나뉜 이유

EMP와 DEPT를 하나의 테이블에 합쳐 두었다고 가정한다. 조인 결과가 그 모습이다.

```sql
SELECT E.EMPNO, E.ENAME, E.DEPTNO, D.DNAME, D.LOC
FROM EMP E JOIN DEPT D ON E.DEPTNO = D.DEPTNO
WHERE E.DEPTNO = 20 ORDER BY E.EMPNO;
```

```text
     EMPNO ENAME          DEPTNO DNAME          LOC
---------- ---------- ---------- -------------- -------------
      7369 SMITH              20 RESEARCH       DALLAS
      7566 JONES              20 RESEARCH       DALLAS
      7788 SCOTT              20 RESEARCH       DALLAS
      7876 ADAMS              20 RESEARCH       DALLAS
      7902 FORD               20 RESEARCH       DALLAS
```

- `EMPNO → DEPTNO`, `DEPTNO → DNAME, LOC`이므로 `EMPNO → DNAME`은 **이행 함수 종속**이다.
- 하나로 두면 `RESEARCH, DALLAS`가 사원 수만큼 반복된다. 부서가 이사하면 다섯 행을 모두 고쳐야 한다.
- 결정자 `DEPTNO`와 그 종속자를 DEPT로 떼어 낸 것이 지금의 SCOTT 스키마다. 즉 EMP·DEPT는 3NF를 만족하도록 나뉜 구조다.

### BCNF — 3NF로도 남는 문제

교재에 쓰이는 예는 "수강" 엔터티다.

- 속성: `(학번, 과목, 교수)`. 규칙은 "교수 한 명은 한 과목만 가르친다"와 "학생은 과목마다 교수 한 명에게 듣는다"이다.
- 주식별자는 `(학번, 과목)`이고, 함수 종속은 `(학번, 과목) → 교수`와 `교수 → 과목`이다.
- 일반 속성끼리의 이행 종속은 없으므로 3NF다. 그러나 결정자 `교수`가 후보키가 아니다.
- BCNF로 가려면 `(교수, 과목)`과 `(학번, 교수)`로 분리한다.

> ⚠️ **함정**: 2NF는 "부분", 3NF는 "이행"이다. 둘을 바꿔 놓은 보기가 오답으로 쓰이기 쉽다. BCNF는 "결정자"라는 단어가 보이면 떠올린다.

## 정규화와 성능

| 작업 | 정규화 후 |
|------|----------|
| 입력·수정·삭제 | 중복이 줄어 고칠 곳이 하나다. **성능과 정합성이 좋아진다** |
| 조회 | 조인이 늘어나 느려질 수 있다. 반대로 테이블이 작아지고 인덱스가 정리돼 **빨라질 수도 있다** |

- 그래서 "정규화하면 조회 성능이 반드시 떨어진다"는 서술은 틀린다.
- 조회 성능이 실제로 문제가 될 때 의도적으로 중복을 허용하는 것이 반정규화다. 내일 다룬다.

## 📖 용어

- **함수 종속** : X 값이 정해지면 Y 값이 하나로 정해지는 관계. `X → Y`로 쓴다.
- **결정자** : 함수 종속에서 값을 정하는 쪽 속성. `X → Y`의 X다.
- **부분 함수 종속** : 복합 주식별자의 일부 속성에만 종속된 상태. 2NF에서 없앤다.
- **이행 함수 종속** : `X → Y → Z`처럼 다른 일반 속성을 거쳐 종속된 상태. 3NF에서 없앤다.
- **원자값** : 더 나눌 필요가 없는 하나의 값. 1NF의 조건이다.
- **이상현상** : 중복 때문에 입력·수정·삭제 시 생기는 문제. 삽입·갱신·삭제 이상이 있다.
- **후보키** : 유일성과 최소성을 만족해 주식별자가 될 수 있는 속성 묶음.
- **BCNF** : 모든 결정자가 후보키인 상태. 3NF를 강화한 정규형이다.

## 📝 연습 문제

**문제 1.** 주식별자가 `(주문번호, 상품번호)`인 주문상품 엔터티에 `상품명` 속성이 있다. 상품명은 상품번호만으로 결정된다. 이 엔터티가 위반한 정규형은?

A) 1차 정규형  
B) 2차 정규형  
C) 3차 정규형  
D) 4차 정규형  

**정답: B**  
해설: 상품명이 복합 주식별자의 일부인 상품번호에만 종속되어 있다. 이것은 부분 함수 종속이며 2차 정규형에서 제거한다. 상품명을 상품번호와 함께 상품 엔터티로 분리하면 해결된다.

**문제 2.** 다음 중 이상현상(Anomaly)에 해당하지 않는 것은?

A) 삽입 이상  
B) 갱신 이상  
C) 삭제 이상  
D) 조회 이상  

**정답: D**  
해설: 정규화가 해결하는 이상현상은 삽입 이상, 갱신 이상, 삭제 이상 세 가지다. 조회는 데이터를 바꾸지 않으므로 이상현상의 분류에 들어가지 않는다.

**문제 3.** 사원 엔터티에 `사번 → 부서번호`, `부서번호 → 부서명`의 함수 종속이 있다. 이 구조에 대한 설명으로 가장 알맞은 것은?

A) 사번과 부서명 사이에 이행 함수 종속이 있어 3차 정규형을 위반한다  
B) 부분 함수 종속이 있어 2차 정규형을 위반한다  
C) 부서명이 다중값 속성이라 1차 정규형을 위반한다  
D) 모든 결정자가 후보키이므로 BCNF를 만족한다  

**정답: A**  
해설: 사번이 부서번호를 정하고 부서번호가 부서명을 정하므로 사번 → 부서명은 이행 함수 종속이다. 3차 정규형은 이행 함수 종속을 제거한다. 주식별자가 단일 속성인 사번이므로 부분 함수 종속은 생길 수 없다.

**문제 4.** 정규화에 대한 설명으로 가장 적절하지 않은 것은?

A) 정규화를 하면 데이터 중복이 줄어 입력·수정·삭제 시 정합성을 지키기 쉽다  
B) 1차 정규형은 모든 속성이 원자값을 갖도록 하는 단계다  
C) 정규화를 하면 조인이 늘어나므로 조회 성능은 항상 떨어진다  
D) BCNF는 모든 결정자가 후보키가 되도록 하는 단계다  

**정답: C**  
해설: 정규화 후에는 조인이 늘어 조회가 느려질 수 있지만, 테이블 크기가 줄고 중복이 사라져 오히려 빨라지는 경우도 있다. "항상 떨어진다"는 단정이 틀렸다.

**문제 5.** 아직 주문되지 않은 신상품을 등록하려 했지만, 상품 정보가 주문 테이블에 함께 들어 있어 주문번호 없이는 입력할 수 없었다. 이 현상의 이름은?

A) 갱신 이상  
B) 삭제 이상  
C) 조인 종속  
D) 삽입 이상  

**정답: D**  
해설: 원하지 않는 다른 값(주문번호)까지 있어야 데이터를 넣을 수 있는 현상이 삽입 이상이다. 갱신 이상은 일부만 수정돼 불일치가 생기는 것이고, 삭제 이상은 지우려던 정보 외의 정보까지 사라지는 것이다.
