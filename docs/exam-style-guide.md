# 모의고사 문제 작성 틀 (AWS 11개 자격증)

`content/exams/<slug>.json` 의 문제를 실제 시험 방식으로 쓰기 위한 기준이다. 주차별 연습 문제(`content/aws-certs/**`)는 이 문서의 대상이 아니다. 간단해도 된다.
기계로 확인할 수 있는 항목은 `src/lib/exam/examStyle.test.ts` 가 막는다. 아래 "사람이 확인할 것"은 검수 단계에서 본다.

## 0. 하지 않는 것

- **덤프 사이트(ExamTopics 등)의 문제를 가져오지 않는다.** 응시자가 시험에서 외운 문제는 AWS 응시 약관(NDA)과 사이트 저작권에 걸린다. 문제 모양은 AWS 공식 시험 가이드의 샘플 문항과 이 문서의 규칙을 참고하고, 내용은 전부 새로 쓴다.
- 기존 문제를 문장만 바꿔 다시 쓰지 않는다. 같은 개념을 다루더라도 상황과 제약을 새로 만든다.
- 확신 없는 서비스 동작은 문제로 쓰지 않는다. 쓰기 전에 AWS 공식 문서로 확인하고 `explanation` 에 근거가 드러나게 쓴다.

## 1. 문제 한 개의 구조

실제 시험 문제는 "상황 → 제약 → 질문" 세 덩어리다.

1. **상황 (1~3문장):** 회사·워크로드·현재 구성. 숫자가 있으면 넣는다(인스턴스 40대, 하루 2TB, 리전 2곳, RPO 15분).
2. **제약 (2~3개):** 서로 다른 종류를 섞는다. 비용, 운영 부담, 기존 환경 유지, 가용성·RTO, 보안·규정, 지연 시간, 마이그레이션 기간 중에서 고른다. 제약이 하나뿐이면 정답이 하나로 좁혀져서 연습 문제처럼 느껴진다.
3. **질문 (1문장):** 한정어로 끝난다.
   - 가장 비용 효율적인 / 운영 부담이 가장 적은 / 변경을 최소화하면서 / 가장 안전한 / 가장 확장성 있는
   - 복수 선택은 문장 끝에 "(2개 선택)" 처럼 개수를 쓴다.

한정어는 문제를 푸는 기준이어야 한다. "가장"만 붙이고 기준이 없으면 안 된다. 질문의 한정어와 상황의 제약이 정답을 가르게 쓴다.

## 2. 보기 만들기

- 단일 정답은 보기 4개(A~D), 복수 정답은 보기 5개(A~E).
- **오답 보기도 실제로 쓰는 선택지여야 한다.** 존재하지 않는 기능, 서비스 이름만 봐도 틀린 보기, "아무것도 하지 않는다"는 쓰지 않는다.
- 오답은 보통 이런 이유로 틀리게 만든다(한 문제에 서로 다른 이유 2~3종).
  - 제약 하나를 어긴다: 요구한 RTO 보다 느리다, 비용이 더 든다, 운영 부담이 늘어난다.
  - 비슷한 서비스를 헷갈리게 한다: 적용 범위가 다르다(Compute vs EC2 Instance Savings Plans), 리전·계정 경계가 다르다.
  - 맞는 방향이지만 한 단계가 빠졌다(권한 부여만 있고 암호화 키 정책이 없다).
  - 과하다: 요구보다 큰 서비스를 쓰면서 비용·운영 부담을 키운다.
- 정답이 가장 긴 보기가 되지 않게 한다. 보기 길이를 비슷하게 맞춘다(테스트가 막는다).
- 정답 위치를 고르게 분산한다(테스트가 막는다).
- 금지: "위 모두", "모두 맞다", 오답에만 붙은 "항상·절대·모든 경우" 같은 단서.
- 같은 문제 안에서 보기 서술 형식을 맞춘다(모두 "~한다" 또는 모두 명사구).

## 3. 자격증 수준별 목표

| 수준 | 해당 | 문제 길이(중앙값) | 복수 선택 | 제약 수 |
| --- | --- | --- | --- | --- |
| foundational | CLF-C02, AIF-C01 | 80자 이상 | 5~20% | 1~2개, 개념·서비스 선택 |
| associate | SAA-C03, DVA-C02, SOA-C02, DEA-C01, MLA-C01 | 170자 이상 | 10~22% | 2~3개 |
| specialty | SCS-C03, MLS-C01 | 200자 이상 | 8~22% | 2~3개, 서비스 내부 동작 |
| professional | SAP-C02, DOP-C02 | 250자 이상 | 8~22% | 3개 이상, 멀티 계정·하이브리드·마이그레이션 |

- 한정어 문제 비율은 foundational 40% 이상, 그 외 60% 이상.
- 난이도는 쉬움 25% · 보통 50% · 어려움 25% 로 섞는다. 어려운 문제는 "비슷한 두 선택지 중 제약 하나로 갈리는" 문제다.
- 도메인별 문항 수는 `content/exam-info/<slug>.json` 비중과 맞는다(기존 파일의 도메인별 개수를 그대로 쓴다).

## 4. 해설 쓰기

- 첫 문장에 정답과 핵심 이유를 쓴다. 상황의 어떤 제약이 그 보기를 고르게 했는지 연결한다.
- 오답마다 한 문장으로 "무엇이 맞지 않는지"를 쓴다(제약을 어긴 부분이나 서비스 범위가 다른 부분).
- 헷갈리기 쉬운 비교(범위, 기본값, 한도)는 숫자와 함께 쓴다.
- 길이는 단일 150자 이상, 복수 200자 이상.

## 5. 사실 확인

- 서비스 이름과 기능은 AWS 공식 문서 기준 최신 이름을 쓴다(은퇴·개명 주의: 예) AWS Single Sign-On → IAM Identity Center).
- 한도·기본값·가격처럼 바뀌는 숫자는 문제의 정답을 가르는 근거로 쓰지 않는다. 개념의 차이로 가른다.
- 시험 개정 때 빠지거나 새로 들어온 항목은 `content/exam-info/<slug>.json` 의 `revision` 을 확인한다.

## 6. 작성·검수 절차

1. 작성자가 도메인별로 나눠 쓴다. 주차 노트(`content/aws-certs/<slug>`)로 주제 범위를 확인하고 공식 시험 가이드의 작업 설명(task statement)을 훑는다.
2. 형식 검사: `npx vitest run src/lib/exam` (구조·분포·길이·한정어·복수 선택 형식).
3. **정답 가리고 풀기:** 별도 검수자가 `answer` 와 `explanation` 을 보지 않고 모든 문제를 풀어 정답이 일치하는지 본다. 불일치 문제는 문제를 모호하게 쓴 것이므로 문제를 고친다.
4. 사실 검수: 검수자가 AWS 공식 문서와 해설을 대조한다. 틀리거나 근거를 못 찾은 문장은 고치거나 문제를 바꾼다.
5. `node scripts/build-exam-index.mjs` 로 `src/data/exam-questions.json` 을 다시 만든다.

## 7. JSON 형식

```json
{
  "number": 12,
  "domain": "비용 최적화 설계",
  "prompt": "...",
  "choices": [{ "label": "A", "text": "..." }, { "label": "B", "text": "..." }, { "label": "C", "text": "..." }, { "label": "D", "text": "..." }],
  "answer": "B",
  "explanation": "..."
}
```

- 복수 정답은 `"answer": "B, D"` 형식이고 보기는 A~E 5개, prompt 끝에 `(2개 선택)`.
- `number` 는 1..N 연속, `domain` 은 기존 파일에 쓰인 짧은 이름 그대로(테스트의 `DOMAIN_MAP` 참고).

## 8. 검수에서 실제로 나온 오류 유형 (SAA-C03 시범, 65문항 중 12건)

작성자가 공식 문서를 확인하지 않고 쓰면 이런 오류가 나온다. 쓸 때 먼저 피하고, 검수자는 이 유형을 우선 본다.

1. **정답 보기가 문제 조건을 충족하지 못한다** — "삭제는 7년 뒤에만" 요구에 수명 주기 규칙만 정답으로 둠(삭제 방지가 아님). 정답을 만든 뒤 문제의 모든 요구를 정답 하나하나에 대조한다.
2. **조건이 정답과 충돌한다** — "조회 지연도 허용되지 않는다"고 쓰고 매번 API 를 호출하는 구성을 정답으로 둠. 상황에 쓴 제약이 정답의 동작과 모순되지 않는지 본다.
3. **정답을 가르는 조건이 빠졌다** — "스팟 중단은 영향 없음"만 쓰고 평소 용량이 중단되면 안 된다는 말이 없어 다른 조합도 정답으로 읽힘. 정답 외 보기를 탈락시키는 근거가 문제 본문에 있어야 한다.
4. **과장된 단정** — "수십 배로 치솟아도 스로틀링이 없다"(DynamoDB 온디맨드는 직전 최고치의 2배까지 즉시). "항상·절대·무제한"이 서비스 동작 설명에 들어가면 공식 문서로 다시 확인한다.
5. **소급 불가능한 기능** — CloudTrail 로그 무결성 검증을 지금 켜면서 "최근 3년"을 입증하라고 함. 기능이 켜진 시점 이후에만 적용되는지 확인한다.
6. **문서와 다른 수치** — RTO "1분 안팎"(Aurora 사용 설명서는 수 분), Compute Optimizer 분석 기간(기본 14일). 수치를 문제에 쓰면 공식 문서의 같은 페이지로 확인한다.
7. **해설의 탈락 이유가 틀렸다** — 오답 이유를 "처리량 부족"으로 썼지만 문서상 근거가 없었음. 해설의 탈락 이유도 공식 문서로 확인하거나, 문제 본문의 제약 위반으로 설명한다.
8. **오답 이유가 섞였다** — 두 보기의 탈락 이유를 한 문장에 뭉뚱그려 논리가 어긋남. 보기마다 이유를 따로 쓴다.

작성자는 각 문제의 `sources` 에 확인한 공식 문서 URL 을 1개 이상 적는다(배포 파일에는 들어가지 않는다).

## 9. 2026-11-12 일괄 교체 결과

AWS 11개 자격증 모의고사 735문항(CLF·AIF·DVA·SOA·SAA·SCS·MLS·MLA·DEA 각 65, SAP·DOP 각 75)을 이 틀로 새로 썼다.

- 작성: 자격증마다 도메인을 둘로 나눠 두 작성자가 썼다. 작성자는 `sources` 에 확인한 공식 문서 URL 을 달았다.
- 정답 가리고 풀기: 첫 풀이에서 AIF 를 뺀 10개 자격증이 정답과 일치했다(SOA 64/65, 불일치 1건은 문제 수정). AIF 는 첫 풀이가 신뢰할 수 없어(13건 불일치, 확인해 보니 풀이 쪽 오류) 다시 풀게 했고 65/65 였다.
- 사실 검수: 문제의 약 17%(127문항)가 고쳐지거나 교체됐다. 유형은 8절과 같고 추가로 다음이 나왔다.
  - **신규 고객 제공이 중단된 서비스가 정답**이었다(SageMaker Model Monitor·Clarify·Ground Truth·A2I, Bedrock Agents Classic, CloudTrail Lake, Incident Manager, Audit Manager). 정답에 쓰면 교체하고, 오답 보기에 두는 것은 허용한다.
  - 서비스 이름이 바뀌었다(Application Migration Service → AWS Transform MGN, Security Hub → Security Hub CSPM).
  - Macie·Guardrails 관리형 PII 유형에 한국 주민등록번호가 없다.
  - 정답 보기가 가장 길지 않게 하려고 **오답 보기 끝에 의미 없는 업무 절차 문장**을 붙인 작성자가 있었다("팀 위키에 문서화한다" 등). 오답의 티가 되므로 기술적으로 그럴듯한 부작용 한 구절로 바꿨다.
- 수정·교체된 문항을 정답 가리고 다시 풀게 했고 전부 일치했다.

### 알려진 한계

- 문제 ID(`exam-<slug>-<번호>`)는 그대로지만 내용이 바뀌었다. 예전 풀이 기록은 새 문제와 맞지 않을 수 있다.
- 사실 검수는 공식 문서 기준이며 문서에서 직접 근거를 못 찾은 부수 주장이 일부 남아 있다(각 검수 결과의 `unverified`). 정답을 가르는 주장은 아니다.
- MLS-C01 시험은 공식 시험 페이지상 2026-03-31 에 종료됐다. 문제는 남기되 시험 정보 페이지에 반영할지는 별도로 정한다.
- CLF-C02 의 Support 플랜 문항은 2027-01-01 의 플랜 개편(Developer·Business·Enterprise On-Ramp 종료) 이후 다시 확인한다.
