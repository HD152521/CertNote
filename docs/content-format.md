# 학습 콘텐츠 포맷 규격 (day*.md)

> 근거: 실제 독자 피드백 — "글이 너무 많아서 읽기 힘들어요. 약간 **핵심 정리 노트**마냥 보고 싶어요.
> 그리고 `*단어 : 설명` 이렇게 어려운 것들 있으면 좋겠어요."
>
> 시범 변환(`content/aws-certs/aif-c01/week1/day1~5.md`)으로 형식을 확정했다. **그 5개가 정본 예시다.**

## 목표 구조

```markdown
# Day N - 제목

## 📌 핵심 정리
- 불릿 3~5개. 각 한 줄(길어야 두 줄)
- 결론만. "무엇을 알아야 하는가"

## (본문 섹션들 — 기존 흐름 유지)
불릿·표 위주. 산문 문단은 최소화

## 📖 용어
- **용어** : 한 줄 설명
- **용어** : 한 줄 설명

## 📝 연습 문제
(기존 그대로 — 절대 손대지 않는다)
```

---

## 규칙

### 1. `## 📌 핵심 정리` — 제목 바로 다음에 신설

- 헤딩 문자열은 **정확히 `## 📌 핵심 정리`**. 렌더러가 이 문자열로 뽑아 상단 카드로 띄운다. 틀리면 안 뽑힌다
- 불릿 **3~5개**, 각 한 줄(길어야 두 줄). 결론만 담는다
- **재료**: 기존 요약 섹션이 문서 끝에 **산문 덩어리**로 있다. 그걸 압축해 위로 올린다
- 기존 요약 섹션은 **삭제**한다(위로 옮긴 것이므로 중복)
- 단 거기 있던 **"내일은 ~를 다룬다" 류 예고 문장은 살려서** 문서 끝(용어 앞)에 한 줄로 남긴다

**기존 요약 섹션 이름 사전** (문서마다 다르다 — 전수 조사 결과):

```
## 정리하며            ## 📌 오늘의 요약      ## 마무리
## Summary            ## 한 줄 요약 체크리스트  ## 한 줄 요약
## 핵심 정리           ## 정리                ## 함정 정리
## 오늘의 요약         ## 한 문장 요약 모음     ## 📌 핵심 요약
```
이 외의 변형이 있을 수 있다. **"문서 끝에 있는 마무리/요약 성격의 섹션"이면 대상이다.**

### 2. `## 들어가며` 등 도입부 — 제거

- 📌 핵심 정리가 맨 위에 오면 도입부와 **완전히 중복**된다
- 섹션을 없애고, **유니크한 문장 1줄만** 다음 섹션의 리드 문장으로 흡수한다
- 시험 사실관계는 하나도 빠뜨리지 않는다

### 3. 본문 산문 → 불릿·표

- 3문장 이상 이어지는 설명 문단은 불릿으로 쪼갠다
- 비교·대조는 표로. 이미 표가 있으면 유지
- **정보를 지우지 마라. 압축이지 삭제가 아니다** — 예시·수치·주의점은 남긴다
- **그대로 유지할 것**: ASCII 다이어그램, 코드블록, `> 💡 **관련 이론**` / `> 💡 **개념**` 등 인용 블록

### 4. `## 📖 용어` — 연습 문제 바로 앞에 신설

- 형식은 **반드시 리스트**: `- **용어** : 설명`
  - ⚠️ `*용어 : 설명`(별표 하나)로 쓰면 **연속 줄이 하나의 `<p>`로 뭉쳐 화면에서 줄바꿈 없이 이어진다.**
    실제 파서로 검증한 결과다. 반드시 `- **용어** : 설명` 리스트를 쓸 것
- 개수: **5~10개**. 단 **본문이 3,000자 이하로 짧은 문서는 5개 하한**(안 그러면 배보다 배꼽이 커진다)
- 그 문서에서 처음 나오거나 어려운 용어를 고른다
- 설명은 **독자 눈높이**로. 시험 정의문을 베끼지 말고 쉽게
- 본문의 `> 💡 **관련 이론**` 블록 내용을 재료로 써도 좋다

### 5. 절대 건드리지 말 것

- **`## 📝 연습 문제` 섹션 전체** (문제·보기·정답·해설)
  - ⚠️ 보기 줄 끝의 **두 칸 트레일링 스페이스**는 줄바꿈용이다. 날아가면 보기가 한 줄로 붙는다.
    자동 포매터를 태우지 마라
- 문서 제목(`# Day N - ...`)
- frontmatter가 있으면 그대로
- 사실관계·수치·시험 범위

---

## 검증 (파일마다)

1. `## 📌 핵심 정리`가 **제목 바로 다음**에 있는가
2. `## 📖 용어` 바로 다음이 `## 📝 연습 문제`인가 (예고 문장이 있으면 용어 앞)
3. 용어가 전부 `- **용어** : ` 리스트 형식인가. **별표 하나짜리 `*용어 : 설명` 잔여 줄이 0인가**
   - ⚠️ `^\*` 로 검사하면 **오탐한다.** 연습 문제의 `**문제 N.**` 스템과 본문의 `**굵게**` 리드 문장이 전부 걸린다.
     실제 금지 대상은 **별표가 하나뿐인 줄**이므로 `^\*[^*]` 로 검사하고, 범위도 **연습 문제 앞 본문**으로 한정한다:
     ```bash
     awk '/^## .*연습 문제/{exit} /^\*[^*]/{c++} END{print c+0}' <파일>
     ```
     정본 예시(`aif-c01/week1/day1.md`)도 이 기준으로만 0이 나온다.
4. 연습 문제 섹션이 원본과 **바이트 단위 동일**한가 (`git show HEAD:<경로>`로 대조)

⚠️ **이모지를 정규식 앵커로 쓰지 마라.** `\x{1F4D6}` 같은 지정자가 조용히 0건 매치하고 넘어간 사례가 있다.
스크립트를 쓴다면 **처리 후 반드시 잔여 건수를 세어 검증**하라.

## 압축률 기준

- **줄 수는 성공 지표가 아니다.** 불릿 변환은 줄을 늘린다
- `연습 문제 앞까지의 글자 수 − (📌+📖 블록 글자 수)`로 봐야 실제 압축이 보인다
- 시범 5개 실측: 기존 산문 대비 **-19~29%**. 이 정도가 현실적 목표
