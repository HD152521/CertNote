# SCS-C03 콘텐츠 깊이 보강 계획

> 작성: 2026-07-31 · 근거: 전 자격증 콘텐츠 실측(단어수·파일크기·구조요소 포함률) + 시험 도메인 비중 대조
> 선행 사례: 2026-06-04 SAA/DVA/SOA/SAP/DOP 5종 깊이 보강(완료) — 동일 파이프라인을 SCS에 적용

---

## 1. 진단 — 왜 SCS인가

### 1-1. SCS는 보강 라운드를 거친 적이 없다 (근본 원인)

2026-06-04 깊이 보강 라운드의 대상은 **SAA-C03 / DVA-C02 / SOA-C02 / SAP-C02 / DOP-C02 5종**이었다.
SCS-C03는 그 대상에 없었다. 즉 현재 SCS는 "망가진 콘텐츠"가 아니라 **원본(1세대) 상태 그대로**다.
따라서 이 작업은 신규 설계가 아니라 **검증된 파이프라인의 미적용분 처리**다.

### 1-2. 실측 갭

| 지표 | SCS-C03 (현재) | SAA-C03 (골드 스탠다드) | 갭 |
|------|---------------|------------------------|-----|
| 레슨당 평균 단어 | **713w** | 1,474w | **-52%** |
| 레슨당 평균 파일 | **14KB** | 26KB | -46% |
| 18KB 이상 레슨 | **0 / 60** | 60 / 60 | **-100%p** |
| 🔍 더 깊이 | 78% | 96% | -18%p |
| 📚 실제 사례 | **15%** | 95% | **-80%p** ← 최대 갭 |
| CLI/코드 블록 | 45% | 73% | -28%p |
| ⚠️ 함정 | 88% | 98% | -10%p |
| 🎯 시나리오 | **68%** | 0% | **+68%p (SCS 고유 강점)** |
| 연습문제 포함 | 100% | 100% | 없음 |
| 문제은행 | 308문항 | 384문항 | -20% |

**해석**
- 구조·커버리지·연습문제는 **이미 완비**(12주 60일, 6개 도메인 전부, 전 레슨 문제 O). 무너진 게 아니다.
- 무너진 건 **밀도**다. 특히 `📚 실제 사례`가 15%로, 보안 과목에서 가장 강력한 학습 장치가 비어 있다.
- `🎯 시나리오`(68%)는 SAA에도 없는 SCS만의 강점 — **보존하고 강화**할 것. 제거 금지.

## 2. 완성 기준 (Definition of Done)

레슨 1개가 "완료"로 인정되는 조건. **전부 충족해야 통과.**

### 2-1. 정량
- [ ] 파일 크기 **≥ 18KB** (목표 대역 20~26KB — SAA 평균 26KB)
- [ ] 연습문제 **≥ 5문항** (종합/복습 day는 8~10문항 유지)

### 2-2. 구조 요소 (모두 최소 1회)
- [ ] `🔍 더 깊이` — 표면 설명 너머의 내부 동작·프로토콜·한계
- [ ] `📚 사례` — **실제 침해/운영 사례**(최대 갭, 필수 신설)
- [ ] `⚠️ 함정` — 시험 오답 유발 지점
- [ ] `🎯 시나리오` — 기존 강점, **유지·강화**
- [ ] `💡 관련 이론` — 배경 이론(암호학·네트워크·표준 RFC 등)
- [ ] CLI 또는 **정책 JSON 실물** 블록
- [ ] `## 한 줄 요약` 또는 `## 정리하며`

### 2-3. SCS 특화 요소 (이 과목의 차별점 — 최소 2개 이상)
보안 시험은 "서비스 암기"가 아니라 **"정책을 읽고 로그를 해석하고 대응 순서를 아는 것"** 을 묻는다.

- [ ] **정책 JSON 실물** — SCP / 키 정책 / 버킷 정책 / 신뢰 정책. 조건 키(`aws:PrincipalOrgID`, `kms:ViaService`, `aws:SourceArn` 등) 포함
- [ ] **로그·핀딩 실물 샘플** — GuardDuty finding JSON, CloudTrail 이벤트, VPC Flow Log 행 → "이 로그가 무엇을 말하는가" 해석
- [ ] **서비스 선택 비교표** — 예: GuardDuty vs Inspector vs Macie vs Detective / SSE-S3 vs SSE-KMS vs DSSE-KMS vs SSE-C
- [ ] **대응 플레이북 순서** — IR 계열은 "무엇을 먼저 하는가"의 순서가 곧 정답
- [ ] **실제 침해 사례** — Capital One(SSRF→IMDSv1→S3), 공개 S3 버킷 유출, 액세스 키 GitHub 노출 등 → AWS가 그 뒤 무엇을 바꿨는지(IMDSv2 등)까지 연결

### 2-4. 절대 보존 (회귀 금지)
- [ ] **연습문제 양식 정확 보존** — `src/lib/parseQuiz.ts`가 정규식으로 파싱한다. 깨지면 문제 렌더링이 통째로 사라진다.
  ```
  ## 📝 연습 문제
  **문제 N.** …
  A) …  B) …  C) …  D) …
  **정답: X**
  해설: …
  ---
  ```
- [ ] 기존 `🎯 시나리오` 블록 삭제 금지(SCS 고유 강점)
- [ ] 기존 정답/해설의 사실관계 변경 금지(보강만, 개작 아님)
- [ ] 제목(`# Day N - …`) 변경 금지 — 사이드바·검색·인덱스가 참조

## 4. 작업 방식 (검증된 패턴)

선행 라운드에서 확립된 절차를 그대로 쓴다. **단, 환경 변화 1건 반영.**

### 4-1. 에이전트 운용
- **주차당 에이전트 1개 × 5레슨**, `run_in_background: true`로 병렬
- 각 에이전트는 **서로 다른 주차**만 담당 → 파일 충돌 없음 → **worktree 불필요**
  > (선행 메모의 "worktree 필수"는 구 `webapp/` 하위 구조 시절 제약. 현 레포 루트에서 에이전트 spawn이 정상 동작함을 이번 세션에서 확인)
- **톤 모델**: 같은 자격증의 직전 주차 day1 + **SAA week3/day3**(골드 스탠다드)를 참조로 지정
- 병렬 폭: 3~5 에이전트(주차 단위). 과다 병렬은 소켓 끊김 유발

### 4-2. 사이클 (페이즈마다 반복)
```
1) 진도 확인   stat으로 18KB 미만 파일만 추출 (완료분 재작업 금지)
2) 발주        미달 주차별 에이전트 병렬 spawn
3) 검증        크기(≥18KB) + 구조요소 grep + 퀴즈 양식 정규식 검사
4) 빌드        npm run build (전 페이지 성공)
5) 커밋·푸시   주차 단위 커밋
```

### 4-3. 실패 처리
- 소켓 끊김/타임아웃이 **빈발**한다. 끊겨도 일부 파일은 이미 쓰여 있으므로
  **stat으로 확인 후 미완성분만 재발주**한다. 전체 재작업 금지.

## 5. 검증 (자동화)

각 페이즈 종료 시 실행할 게이트:

```bash
# 1) 크기 미달 파일
find content/aws-certs/scs-c03 -name 'day*.md' -size -18k

# 2) 구조 요소 누락 파일 (📚 사례가 핵심 신설 항목)
for f in $(find content/aws-certs/scs-c03 -name 'day*.md'); do
  grep -q '📚' "$f" || echo "사례 없음: $f"
done

# 3) 퀴즈 양식 무결성 — 파싱 가능 문항 수가 보강 전보다 줄지 않을 것
grep -c '^\*\*문제 [0-9]*\.' content/aws-certs/scs-c03/week*/day*.md

# 4) 빌드
npm run build
```

**최종 통과 기준**: 60/60 레슨이 ≥18KB + 구조요소 충족 + 퀴즈 문항수 보강 전 이상 + 빌드 성공.

## 6.5 R1(퀴즈 파손) 3중 방어 — 구축·검증 완료 (2026-07-31)

"에이전트에게 조심해달라고 부탁하는 것"은 방어가 아니다. 세 겹으로 막되 1층이 핵심이다.

### 파손 메커니즘 (파서 정독으로 확정)
`locateQuizSection()`은 **첫 문제 스템(`**문제 N.`)에 앵커**를 잡고 **그 이후 첫 h2(`## `)에서 끊는다.**
따라서 실제 파손 경로는 셋이다.
1. 문제 사이/뒤에 **h2 삽입** → 그 지점 이후 문제 **전부 소실**
2. 본문에 `**문제 N.` 문구 등장 → 앵커가 앞으로 당겨져 경계 붕괴
3. 보기 2개 미만 파싱 / 정답 마커 변형 → 그 문제만 **조용히 드롭**

### 1층 — 구조적 차단 (핵심): `scripts/restore-quiz.mjs`
퀴즈 바이트를 **에이전트 출력에 아예 포함시키지 않는다.**
보강본에서는 **퀴즈 앞 본문만** 취하고, 퀴즈 제목부터 파일 끝까지는 **git 원본에서 바이트 그대로** 되붙인다.
→ 에이전트가 퀴즈를 어떻게 망가뜨렸든 **결과물의 퀴즈는 항상 원본과 동일**하다.

```bash
node scripts/restore-quiz.mjs content/aws-certs/scs-c03/week5   # 주차 단위
```

**에이전트 작업 규칙(이것만 지키면 됨)**: 모든 보강은 **`## 📝 연습 문제` 앞에서만.**
그 뒤에 쓴 내용은 자동으로 원본으로 덮인다(의도된 동작).

### 2층 — 진짜 파서 게이트: `src/lib/quizContract.test.ts`
정규식을 **재구현하지 않고 프로덕션 `parseQuiz` 를 그대로 호출**해 전 콘텐츠(1,320 파일)를 파싱하고
기준선(`src/data/quiz-baseline.json`)과 대조한다. 재구현하면 "테스트는 통과하는데 화면은 깨지는" 상황이 생긴다.
- 문제 **추가는 허용**(5→7문항 보강), **유실·정답변경·보기수변경은 실패**
- `rawStems`(원문 스템 수) 대비 **조용한 유실이 늘면 실패**

기준선 갱신(의도적 문제 추가 시): `UPDATE_QUIZ_BASELINE=1 npx vitest run src/lib/quizContract.test.ts`

### 3층 — 주차 단위 커밋
페이즈가 아니라 **주차마다 커밋** → 문제 발생 시 롤백 범위가 5레슨으로 제한된다.

| 시나리오 | 결과 |
|---------|------|
| 문제 사이 h2 삽입 + 보기 양식 파손 주입 | 계약 테스트가 **정확히 탐지**(`문제 4 → 2, 2개 유실`) |
| `restore-quiz.mjs` 실행 | 퀴즈 구간 **바이트 단위로 원본과 일치** 복구 |
| 퀴즈 앞 본문 보강 + 정답 마커 파손 동시 주입 | **본문 보강 보존(+203B) + 퀴즈 완전 복구**, 테스트 통과 |

→ R1은 "주의해서 처리"가 아니라 **구조적으로 발생 불가능**한 상태가 됐다.

## 6.6 부수 발견 — 기존 문항 유실 (SCS 무관, 전 자격증)

안전망을 구축하면서 **보강을 시작하기도 전에 라이브의 기존 손실**이 드러났다.

```
전체 day 파일 1,320개 · 현재 렌더되는 문항 8,456개
├ 퀴즈 파싱 0건 파일: 53개
└ 원문에는 있으나 화면에 안 나오는 문항: 97개 (39개 파일)
```

- 대부분 **영어판**(`en/sap-c02` week15·16, `en/soa-c02` week11·12, `en/mla-c01`·`mls-c01` week9·10, `en/dop-c02` week16) — 번역 후반 주차가 통째로 유실
- 한국어판도 일부: `dop-c02/week16/day5`(7문항), `soa-c02/week8/day5`(2), `saa-c03/week3/day1`·`week4/day5`(각 1), `sap-c02/week7/day4`(1), `dva-c02` 3개 파일(각 1)

현재 기준선은 **이 손실을 '기록'** 하고 있어 더 나빠지는 것은 막지만, 손실 자체는 남아 있다.
**SCS 보강과 독립적인 별도 과제**이며, 사용자가 이미 만든 문항이 화면에 안 나오는 것이라
투입 대비 효과가 크다(신규 집필 없이 양식 교정만으로 97문항 복구).
