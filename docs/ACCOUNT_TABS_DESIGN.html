CertNote 마이페이지 탭 기반 개선 설계

구독 정보를 중심으로 한 통합 허브 설계 문서

1. 설계 개요

현재 마이페이지는 선형적 스크롤 레이아웃으로, 프로필·구독·설정 정보가 섞여 있어 사용자가 필요한 정보를 찾기 어렵습니다. 이 설계는:

  • 탭 기반 정보 구조로 각 섹션을 명확히 분리
  • 대시보드 탭을 기본으로 하여 구독 상황을 첫 화면에서 강조
  • 서버/클라이언트 경계를 명확히 하여 성능 최적화
  • 모바일 반응형으로 모든 기기에서 자연스러운 경험 제공

2. 설계 시스템

3. 탭 구조 & 콘텐츠

탭 네비게이션 레이아웃

• 모바일: 스크롤 가능한 가로 탭
• 데스크톱: 고정 너비 컨테이너 내 탭 모두 표시
• 활성 탭: accent 색상의 하단 선 표시

3.1 대시보드 탭 (기본)

첫 로드 시 활성화되는 탭. 사용자가 필요한 모든 핵심 정보를 한눈에 볼 수 있습니다.

구독 상황 카드 (최우선)

크고 눈에 띄는 영역에 구독 상태를 표시합니다. Free 사용자에게는 업그레이드 유도, Pro 사용자에게는 갱신 정보를 강조합니다.

현재 플랜
Pro
갱신일: 2026-08-15
32일 남음
활성

학습 통계 (선택사항)

향후 /api/stats에서 가져올 데이터. 현재는 placeholder로 표시하거나 숨길 수 있습니다.

  • 이번 달 학습 카드 수
  • 복습 연속 달성 일
  • 목표 자격증까지 진행률

최근 활동 요약

마지막 로그인, 최근 학습한 자격증, 마지막 복습 세션 등. 사용자의 참여도를 시각적으로 표시합니다.

3.2 프로필 탭

기존 ProfileSection.tsx를 탭 내부로 이동. 사용자 개인정보와 학습 목표를 편집할 수 있습니다.

포함 필드

  • 이름 (필수)
  • 생년월일 (필수)
  • 목표 자격증 (필수)
  • 직업 (선택)
  • 학습 목적 (선택)
  • 현재 수준/경력 (선택)

각 필드별 input/select 컴포넌트 사용. 저장 버튼 하단 배치. 저장 성공/실패 메시지 표시.

3.3 구독 & 결제 탭

구독과 결제 관련 모든 정보를 한곳에서 관리. SubscriptionCard와 SubscriptionHistory를 통합합니다.

구독 정보 섹션

대시보드와 동일한 구독 상황 카드, 하지만 여기서는 더 상세한 정보 포함:

  • 현재 플랜 (Free/Pro)
  • 구독 시작일
  • 갱신일 및 남은 기간
  • 다음 청구 금액 (Pro만)
  • [결제 정보 변경] 버튼 (Pro만)
  • [구독 취소] 버튼 (Pro만)
  • [Pro 업그레이드] 버튼 (Free만) → /checkout으로 이동

결제 내역 섹션

SubscriptionHistory.tsx 컴포넌트 통합. 과거 청구 및 갱신 기록 표시.

3.4 설정 탭

AccountForms + NotificationSettings를 단일 탭에 통합.

알림 설정 섹션

기존 NotificationSettings.tsx 그대로 이동.

보안 섹션

  • 비밀번호 변경: 현재 비밀번호, 새 비밀번호 입력
  • 로그아웃: 현재 기기에서만 로그아웃

계정 관리 섹션

  • 계정 삭제: 위험도 높음 (danger 색상), 비밀번호 확인 필수

5. 서버/클라이언트 데이터 흐름

Initial Data Load (서버)

Server: page.tsx

1. getCurrentUser() 확인
2. 프로필 데이터 조회 (SELECT name, birthdate, ...)
3. 구독 정보 조회 (plan, current_period_end, days_left)
4. 자격증 목록 조회 (listCerts)

Client: AccountPageClient.tsx

5. Props로 데이터 수신 (userEmail, certs, initial, isPro, periodEnd, daysLeft)
6. 탭 상태(activeTab) 클라이언트 상태로 관리 (useState)

Client: AccountTabs.tsx

7. Props를 각 탭 컴포넌트로 전달
8. 탭 전환 시 새로 로드하지 않음 (클라이언트 상태만 변경)

상호작용 (클라이언트/서버)

프로필 저장 (ProfileTab)

Client: ProfileTab

사용자가 프로필 편집 후 [저장] 클릭

Client: POST /api/account/profile

JSON body로 변경된 필드 전송 (JSON serialization)

Server: PATCH /api/account/profile

1. JWT 토큰에서 userId 추출
2. UPDATE users SET ... WHERE id = userId
3. 성공/실패 응답 반환

Client: ProfileTab

4. 성공 시 router.refresh() → 서버 재평가
5. UI에 "저장되었습니다" 메시지 표시
6. 실패 시 에러 메시지 표시

Client: BillingTab

Free 사용자가 [Pro 업그레이드] 버튼 클릭

Client: Router

useRouter().push('/checkout') 또는 Link href="/checkout"

Client: /checkout

7. 구독 업그레이드 플로우

Flow: Free 사용자가 Pro로 업그레이드

사용자는 마이페이지 내 대시보드 탭 또는 결제 탭에서 [Pro 업그레이드] 버튼을 클릭하여 자연스럽게 /checkout으로 이동합니다.

Step 1: BillingTab (Free 사용자)

구독 상황 카드에 [Pro 업그레이드] 버튼 표시
<a href="/checkout">

Step 2: /checkout 페이지

결제 폼 표시. 사용자가 카드 정보 입력 및 결제
(기존 CheckoutPageClient.tsx 로직 따름)

Step 3: POST /api/checkout

1. 결제 처리 (결제 게이트웨이 호출)
2. 성공 시 users.plan = 'pro', current_period_end 업데이트
3. 응답 반환

Step 4: Redirect to /account

결제 성공 후 /account로 리다이렉트
(또는 /account?tab=billing로 결제 탭 자동 활성화)

Step 5: BillingTab (Pro 사용자)

구독 상황 카드가 Pro 상태로 표시
[결제 정보 변경], [구독 취소] 버튼 노출

URL Parameters (선택사항)

탭 간 네비게이션을 URL에 반영하면 사용자가 링크 공유 가능하고 뒤로가기 시 탭 상태 복구:

// AccountPageClient.tsx에서 useSearchParams 사용 const searchParams = useSearchParams(); const tab = searchParams.get('tab') || 'dashboard'; const [activeTab, setActiveTab] = useState(tab); // 탭 변경 시 URL도 업데이트 function handleTabChange(newTab: string) { setActiveTab(newTab); const params = new URLSearchParams(searchParams); params.set('tab', newTab); router.push(`?${params.toString()}`, { scroll: false }); }

8. 구현 체크리스트

Phase 1: 탭 기본 구조 (1-2 시간)

  • AccountTabs.tsx 생성 (탭 상태 관리)
  • tabs/ 디렉토리 생성 및 4개 탭 컴포넌트 작성
  • 탭 네비게이션 UI 구현 (Tailwind)
  • AccountPageClient에서 AccountTabs로 마이그레이션

Phase 2: 각 탭 콘텐츠 (2-3 시간)

  • DashboardTab: SubscriptionStatus + 통계/활동 섹션
  • ProfileTab: 기존 ProfileSection 통합
  • BillingTab: SubscriptionStatus + SubscriptionHistory
  • SettingsTab: NotificationSettings + 비밀번호/계정 관리

Phase 3: 스타일 & 반응형 (1-2 시간)

  • SubscriptionStatus.tsx 컴포넌트 작성
  • 구독 상황 카드 스타일 (accent 색상 강조)
  • 모바일 탭 네비게이션 (overflow-x-auto)
  • 다크모드 테스트

Phase 4: 기능 통합 (1 시간)

  • 결제 성공 후 /account로 리다이렉트 확인
  • URL parameters로 탭 상태 유지 (선택)
  • API 에러 처리

Phase 5: 테스트 (1 시간)

  • 모든 탭 전환 정상 작동
  • 프로필 저장 성공/실패
  • 구독 업그레이드 플로우
  • 모바일/데스크톱 반응형

9. 향후 개선안

학습 통계 (Stats API)

대시보드 탭에서 /api/stats 엔드포인트로부터 학습 통계를 가져와 표시. 현재는 placeholder로 둠.

로그아웃 로직

설정 탭에서 [로그아웃] 버튼 추가. 현재는 기존 구조에서 로그아웃 버튼이 없으므로, 헤더의 로그아웃 메뉴 사용.

결제 정보 변경 플로우

Pro 사용자가 [결제 정보 변경] 버튼 클릭 시 결제 정보 편집 페이지(/account/billing/edit 등)로 이동. 아직 구현 안 함.

구독 취소 플로우

Pro 사용자가 [구독 취소] 버튼 클릭 시 확인 모달 표시. 취소 사유 선택 후 API 호출. 아직 구현 안 함.

알림 설정 토글 개선

현재 NotificationSettings는 자체적으로 상태 관리. 탭 구조에 맞게 포함시킬 때 UX 개선 고려.

10. 설계 원칙

Good: 정보 계층

  • 대시보드: 핵심 정보 (구독 상황) 최우선
  • 결제 탭: 상세 정보 (갱신 정보, 내역)
  • 설정 탭: 관리 기능 (보안, 계정)

Good: 시각적 강조

  • 구독 상황 카드: 큰 폰트, 테두리, accent 색상
  • Pro 배지: 색상 및 라벨로 구분
  • 액션 버튼: 명확한 CTA

Avoid: 과도한 정보

  • 모든 정보를 대시보드에 노출 (→ 탭으로 분산)
  • 중복된 구독 정보 표시 (→ SubscriptionStatus 재사용)
  • 한 탭에 너무 많은 섹션 (→ 명확한 구분)

Avoid: 의도 불명확한 액션

  • [설정] 같은 모호한 버튼 (→ 구체적인 라벨)
  • 클릭해야 결과를 알 수 있는 버튼 (→ 명확한 라벨)
  • 위험한 액션에 accent 색상 (→ danger 색상 사용)
