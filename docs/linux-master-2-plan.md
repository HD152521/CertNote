# 리눅스마스터 2급 트랙 추가 계획

> 작성 2026-09-01 · 대상 저장소 `CertNote-repo` · 선행 완료: `content/exam-info/linux-master-1.json` (commit c200db6)

## 0. 왜 만드는가

`/linux` 섹션에 트랙이 **하나뿐이고 그게 최상위 난이도**다. `linux-master-1`은 `level: "grade-1"`이고
트랙 README가 대상을 *"리눅스 기본기 보유자"*로, *"1급은 명령어·설정파일 암기 비중이 큼"*이라고 명시한다.
**처음 리눅스를 접하는 사람이 들어올 문이 없다.**

AWS 섹션과 비교하면 비대칭이 분명하다. AWS는 `clf-c02`(foundational, 30일)가 1층 역할을 하고
Associate로 올라가는 퍼널이 있는데, linux는 그 1층이 통째로 비어 있다.

착수 조건도 좋다. `src/lib/levels.ts`에 **자리가 이미 예약돼 있다**:

```ts
linux: ['grade-2', 'grade-1'],
```

즉 정렬·그룹핑·하이라이트 로직은 손댈 필요가 없다. `meta.json`에 `"level": "grade-2"`만 주면
허브가 2급 → 1급 순으로 자동 정렬한다.

### 결론 — 재활용은 "복붙"이 아니라 "구조 재활용 + 난이도 하향 재작성"

- **주제 커버리지는 대부분 이미 존재한다.** 완전 신규 집필이 필요한 영역은 없고, 두 곳만 **부분 보강**이면 된다.
- 그러나 1급 노트는 *기본기 보유자* 대상으로 쓰였다. 처음 접하는 사람에게 그대로 주면 안 된다.
  가장 큰 작업은 새 주제 조사가 아니라 **난이도 하향 재작성**이다.
- **진짜 재활용 자산은 텍스트가 아니라 설계다** — 주제 순서, 용어 선정, 하루치 분량 감각,
  "무엇을 먼저 가르쳐야 하는가"의 판단. 커리큘럼 설계 비용의 큰 몫이 여기 있고 그건 그대로 쓸 수 있다.
- **보강이 필요한 곳은 두 군데뿐**: X 윈도의 데스크톱 환경·디스플레이 매니저, 응용분야의 클러스터링·임베디드·기술동향.
  1급이 실무 심화라 오히려 이런 "개괄" 영역이 얇다.
- 반대로 **덜어내야 할 곳**: w5의 LVM·RAID, w9~w11의 서버 구축 심화(DNS/Apache/Samba/방화벽)는
  2급 범위를 넘는다. 2급 '인터넷 활용'은 서비스 **종류와 개념** 수준이다.

## 4. 추가 절차 (기술)

### 🔴 4-0. 선행 필수 — `sync-content.mjs`의 index.json 파괴 문제

**이걸 먼저 고치지 않으면 2급을 추가해도 한 번의 sync로 통째로 사라진다.**

`scripts/sync-content.mjs:139`가 `content/aws-certs/index.json`을 이렇게 재생성한다:

```js
certs: CERTS.map((c) => ({ slug: c.slug, ... }))
```

그런데 **`CERTS` 배열에 linux 항목이 하나도 없다**(`grep -c linux scripts/sync-content.mjs` → 0).
linux 트랙은 외부 소스 저장소(`~/aws-certs`)에 원본이 없고 이 저장소에서 직접 작성됐기 때문이다.

결과: 누구든 `node scripts/sync-content.mjs`를 실행하면 index.json에서 **linux 항목이 사라진다.**
그러면 `listCerts('linux')`가 빈 배열을 반환하고, `[category]/[slug]`는 `dynamicParams = false`라
**`/linux/*` 전체가 즉시 404**가 된다. 지금 1급도 이미 이 위험에 노출돼 있다.

**해결 선택지**

- (a) `CERTS`에 linux 항목을 추가하되 `sourceRepo`가 없으면 복사를 건너뛰고 index에만 싣는다 — 최소 변경
- (b) index.json 생성을 "기존 항목 병합"으로 바꾼다 — sync 대상이 아닌 트랙을 보존
- (c) linux를 별도 index로 분리 — IA 4섹션 계획과 맞물려 가장 크고, 지금은 과함

**→ (b)로 수정 완료.** 기존 index.json 을 읽어 slug 기준으로 병합한다. CERTS 항목은 동기화된 값으로
갱신하되 `section` 같은 추가 필드를 보존하고, CERTS 에 없는 항목은 손대지 않는다.
회귀 테스트 `src/lib/contentIndex.test.ts` 가 "디스크의 모든 트랙이 인덱스에 있는가 · 모든 항목이
section 을 갖는가"를 검사한다.

### 🔴 4-0b. 검증 중 추가로 드러난 위험 — sync 는 보강된 콘텐츠도 덮어쓴다

index.json 만 문제가 아니었다. `syncCert()` 는 소스의 day.md 를 그대로 `copyFile` 하는데,
**CERTS 의 5개 트랙은 이 저장소에서 콘텐츠 보강을 거쳐 외부 소스보다 내용이 많다.**

2026-09-01 실측(saa-c03 week1):

| | repo | 외부 소스 |
|---|---|---|
| day1 | 25,566 | 25,319 |
| day5 | 36,313 | 30,191 |

전 파일이 repo 쪽이 크고 `diff` 도 다르다. 즉 **지금 sync 를 돌리면 보강분이 사라진다.**

이건 index 병합으로 해결되지 않는다. 스크립트 상단에 실행 금지 경고를 박아뒀고,
"새 트랙을 외부 저장소에서 처음 들여올 때가 아니면 실행하지 말 것"을 명시했다.
근본 해결(소스를 이 저장소로 일원화할지, sync 를 폐기할지)은 별도 결정 사항이다.

### 4-1. 콘텐츠

```
content/aws-certs/linux-master-2/
  meta.json          # slug, code "리눅스마스터 2급", level "grade-2", section "linux",
                     # weeks 10, dayCount 50, accent "#FCC624", order (1급보다 앞)
  README.md          # 1급 README 형식 따라 시험정보 표 포함
  week1..week10/day1..day5.md
```

`content/aws-certs/index.json`에도 항목 추가(4-0 해결 후).

### 4-2. 시험정보 — 이미 스키마가 준비돼 있다

`content/exam-info/linux-master-2.json`. commit c200db6에서 확장한 스키마를 그대로 쓴다:

- `phases[]` — 1차/2차 (문항·시간·형식·응시료·응시자격)
- `passingCriteria` — `"60점 이상 (과목당 40% 미만 과락)"`
- `domains[].weight` — **비워둔다.** 배점 비율이 공식에 없다(§1 참조). 카드는 과목 목록으로 렌더된다
- `validityYears` — 공식 고시에 없으면 생략
- `faq` 5개 · `source` · `syncedAt`

> `domains`에는 공식 3과목(리눅스 일반 · 리눅스 운영 및 관리 · 리눅스 활용)을 넣는다.
> 검정항목 12개까지 넣으면 카드가 길어지므로 과목 단위가 적절하다.

### 4-3. 모의고사 은행

`content/exams/linux-master-2.json` — 배열 형태, `{number, domain, prompt, choices, answer, explanation}`.
`npm run exam:build`가 `src/data/exam-questions.json`으로 인덱싱한다(prebuild에 포함).
자격증 허브의 "트랙 구성" 문항 수가 이 배열 길이에서 나온다.

### 4-4. 레벨 라벨 — 같이 고칠 것

`certLevelLabel('grade-2', 'linux')`가 지금 **`"Grade 2"`**를 반환한다. `src/lib/levels.ts`에
`AWS_LABELS`만 있고 linux 라벨 맵이 없어 title-case 폴백이 걸린다. 한국 국가공인 자격증인데
레벨이 영문으로 표시된다. 1급도 현재 `"Grade 1"`로 나온다.

```ts
const LINUX_LABELS: Record<string, string> = { 'grade-1': '1급', 'grade-2': '2급' };
```

### 4-5. 인덱스 재생성

```
npm run questions:build     # day.md 연습문제 → src/data/questions.json (content/ 전체 스캔, 자동 인식)
npm run exam:build          # content/exams/*.json → src/data/exam-questions.json
npm run content:manifest    # lastmod 매니페스트(sitemap lastModified 근거)
```

sitemap·구조화 데이터는 `listCerts` 기반이라 별도 작업이 없다.

## 5. ⚠️ 콘텐츠 집필 시 필수 안전망

`src/lib/parseQuiz.ts`는 정규식으로 문제를 파싱한다. **양식이 어긋나면 문제가 조용히 사라진다**
(빌드는 성공하고 화면에서만 증발). 1급·SCS 보강 때 실제로 겪은 사고다.

파손 경로: ① 문제 스템 이후 `##` 삽입 → 이후 문제 전부 소실 ② 본문에 `**문제 N.` 등장 → 앵커 이동
③ 보기 2개 미만·정답 마커 변형 → 해당 문제 드롭.

**3중 방어를 반드시 쓸 것**

1. `node scripts/restore-quiz.mjs <디렉터리|파일>` — 퀴즈 앞 본문만 취하고 퀴즈~파일끝은 git 원본 바이트 그대로 복원
2. `npx vitest run src/lib/quizContract.test.ts` — 전 콘텐츠를 프로덕션 파서로 파싱해 기준선 대조.
   유실·정답변경은 실패. 신규 트랙 추가 후 기준선 갱신: `UPDATE_QUIZ_BASELINE=1`
3. **주차 단위 커밋** — 롤백 범위를 5레슨으로 제한

집필 에이전트 프롬프트 필수 문구: *"`## 📝 연습 문제` 앞에서만 작업"*, *"본문에 `**문제 N.` 금지"*,
*"`# Day N -` 제목 변경 금지"*, *"사실 창작 금지(공개 사례만)"*.

## 6. 실행 순서

| # | 작업 | 산출물 | 선행 |
|---|---|---|---|
| 1 | KAIT 공식 출제기준 세부항목 대조 | 커버리지 진단표 | — |
| 2 | `sync-content.mjs` index.json 파괴 문제 수정 | 코드 + 회귀 테스트 | — |
| 3 | 레벨 라벨(`LINUX_LABELS`) 수정 | 코드 + 테스트 | — |
| 4 | `exam-info/linux-master-2.json` 작성 | 시험정보 카드·FAQ·JSON-LD | 1, 4-1 |
| 5 | 커리큘럼 확정(주차·일자별 주제) | 목차 문서 | 1, 2 |
| 6 | 콘텐츠 집필 — 주차 단위 | day.md 50개 | 5 |
| 7 | 모의고사 은행 작성 | `exams/linux-master-2.json` | 6 |
| 8 | 인덱스 재생성 + 빌드 검증 | — | 6, 7 |

**2·3은 콘텐츠와 무관하게 지금 바로 할 수 있고, 2급을 만들지 않기로 해도 손해가 없다.**
2는 현재 1급이 노출된 실제 위험을 제거하고, 3은 1급 페이지의 `"Grade 1"` 표기를 지금 즉시 고친다.

> 초판에서는 4(exam-info)도 "지금 바로" 항목에 넣었는데 틀렸다. `getExamInfo(slug)`는 자격증 허브가
> 자기 slug로 호출하므로, `linux-master-2` 트랙이 없으면 그 JSON은 아무 데서도 읽히지 않는 죽은 데이터다.
> 4는 트랙 뼈대(4-1)와 함께 만들어야 한다.

## 7. 미결 — 착수 전 결정 필요

- **분량**: 10주/50일이 적정한가. 출제기준 세부항목 대조 후 확정
- **1차/2차 분리 여부**: 한 트랙에 1차·2차를 모두 넣을지, 1차 위주로 가고 2차는 뒤쪽 주차에 붙일지
  (2급은 2차도 사지선다라 1급만큼 분리 필요성이 크지 않다)
- **`order` 값**: 허브에서 2급이 1급보다 위에 오도록 배정
- **응용분야 범위**: 검정내용이 '기술동향 · 활용기술'로만 고시돼 범위가 넓다. 기출로 실제 출제 수준 확인 필요
