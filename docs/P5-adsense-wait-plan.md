## 1. day 퀴즈 표시 버그 2건

### 증상 (운영 `/aws/saa-c03/week1/day1`, 2026-10-27 스크린샷)
- **A. 해설에 마크다운 기호 노출** — `**Direct Connect + 본사 데이터센터 유지**`처럼 `**`가 그대로 보인다.
- **B. 보기 왼쪽에 목록 점(•)** — 보기 버튼 A~D 바깥에 불릿이 찍힌다.

### 원인
- A: `src/components/Quiz.tsx:114`가 `question.explanation`을 `<p>` 안에 문자열 그대로 넣는다. 마크다운을 해석하지 않는다.
- B: 퀴즈는 `src/components/Article.tsx`의 `.article` 안에서 렌더되는데, `src/app/globals.css:98-99`의 `.article ul { list-style: disc; padding-left: 1.5rem }`이 `Quiz.tsx:72`의 보기 `<ul>`에도 걸린다.

### 영향 범위 (실측)
- day 마크다운 해설 줄 중 `**` 포함 **590줄**, 백틱(`` ` ``) 포함 **1,801줄**. 백틱도 지금은 기호째 보인다.
- 모의고사 문제은행(`content/exams/*.json`, 785문항)에는 `**`·백틱이 0건이라 `ExamRunner`는 영향 없음.
- 문제 본문·보기 텍스트도 같은 경로라 함께 처리한다.

### 수정 방법
1. 인라인 마크다운만 처리하는 작은 렌더러를 만든다 (`src/components/quiz/InlineMd.tsx`).
   - 지원: `**굵게**`, `` `코드` ``. 그 외는 텍스트 그대로.
   - `dangerouslySetInnerHTML` 쓰지 않는다. 문자열을 토큰으로 나눠 React 요소(`<strong>`, `<code>`)로 만든다. 콘텐츠는 우리 파일이지만 XSS 경로를 새로 열지 않는다.
   - 짝이 안 맞는 `**`는 기호 그대로 둔다(내용 손실 방지).
   - MDX 전체 렌더러를 쓰지 않는 이유: 해설은 클라이언트 컴포넌트 안이라 번들이 커지고, 블록 요소(목록·표)가 섞이면 레이아웃이 깨진다.
2. `Quiz.tsx`의 문제 본문·보기·해설 3곳에 적용한다. `whitespace-pre-wrap`은 유지.
3. 보기 `<ul>`에 `list-none pl-0 my-0`을 준다. 전역 CSS의 `.article ul` 규칙은 본문 목록에 필요하므로 건드리지 않는다.
4. `ExamRunner.tsx:398` 해설에도 같은 렌더러를 걸어 둔다(지금은 0건이지만 문제은행에 기호가 들어오는 순간 같은 버그가 난다).

### 테스트
- `InlineMd` 단위 테스트: 굵게, 코드, 둘 혼합, 짝 없는 `**`, 빈 문자열, 코드 안의 `**`는 굵게 처리 안 함.
- `quizContract.test.ts` 계약 테스트가 깨지지 않는지 확인(퀴즈 파싱은 바꾸지 않는다).
- Playwright: 390px·1440px에서 SAA Day 1 퀴즈를 풀고 해설에 `**` 문자가 없는지, 보기 `ul`의 computed `list-style-type`이 `none`인지 확인.
- 다크 모드에서 `<code>` 배경 대비 확인.

### 완료 기준

## 2. 검색 유입용 콘텐츠 보강

### 원칙 (이전 실측에서 나온 제약)
- **신생 사이트가 이기는 건 팩트성 롱테일**이다(응시료, 재응시 규정, 바우처). "독학", "모의고사", "로드맵"은 블로그·카페가 차지해 노출돼도 클릭이 0이었다.
- **페이지마다 다른 사실만 추가한다.** 11개 허브에 같은 모양의 문단을 얹으면 유사도가 올라 색인에 불리하다(로드맵에 시험 사실을 템플릿으로 붙였다가 유사도 0.66→0.84로 악화된 전례).
- **기출 복원·덤프는 만들지 않는다.** AWS는 실제 시험 문항 공유를 금지하고, 애드센스 심사에서도 저작권 위험이 된다.
- 허브에는 이미 시험 정보 카드(`ExamInfoCard`, 문항 수·시간·응시료·합격 기준·FAQ)가 있다. 같은 사실을 새 페이지로 복제하지 않는다.

### Step 0 — 데이터 먼저 (사용자 작업, 15분)
2026-08 표본(21노출)은 너무 작아 결론이 아니다. 아래 두 화면의 최근 3개월 검색어를 내보내 준다.
- 구글 서치콘솔 → 실적 → 검색어 (노출순 상위 50개)
- 네이버 서치어드바이저 → 유입 검색어

### Step 1 — 후보 (데이터를 보고 1~2개만 고른다)
| 후보 | 왜 | 유지 비용 |
|---|---|---|
| 리눅스마스터 회차별 시험 일정·접수 기간 | 국내 자격이라 영어권 경쟁이 없고, 검색 수요가 회차마다 생긴다 | 연 1회 KAIT 공지 반영. `syncedAt` 표시 필수 |
| 자격증별 "개정 이력" (예: SOA-C02 → CloudOps 개명, SCS-C02 → C03) | 자격증마다 내용이 완전히 달라 중복 위험이 없다 | 개정 때만 |
| 리눅스마스터 1급·2급 차이 비교 | 둘 중 무엇부터 볼지 묻는 검색 | 낮음 |

- 각 후보는 허브 안 섹션으로 넣을지 별도 페이지로 뺄지 Step 0 검색어를 보고 정한다. 검색어가 독립적이면 별도 페이지, 허브 검색어의 변형이면 허브 섹션.
- 출처 URL과 확인 날짜를 페이지에 표시한다(P4 신뢰 장치 원칙).

### 완료 기준
- 새 페이지·섹션이 사이트맵에 들어가고, 기존 허브와 유사도가 0.7 미만.
- 4주 뒤 서치콘솔에서 해당 검색어 노출 여부 확인.

## 3. /en 허브에 자격증 요청 폼

### 배경

### 수정
1. `src/app/en/page.tsx` 하단에 `<CertRequestForm lang="en" />` 추가. 컴포넌트는 이미 `lang` prop과 영어 라벨을 지원한다.
2. 영어 화면에서 서버 오류 메시지가 한국어로 새지 않는지 확인 — `CertRequestForm.tsx:61`이 en일 때는 서버 메시지 대신 고정 문구를 쓰므로 이미 막혀 있다. 후보 자격증 이름(정보처리기사, SQLD 등)의 영어 표기만 확인한다.
3. 화면 전체에 한글이 0자인지 검사한다(구글이 `lang="en"` 페이지의 한글 혼입으로 색인을 뺀 전례).

### 테스트
- Playwright 390px·1440px: /en 하단에 폼이 보이고, 가로 스크롤 없음, 페이지 오류 0.
- /en 렌더 HTML에서 한글 문자 수 0 (후보 목록 포함).
