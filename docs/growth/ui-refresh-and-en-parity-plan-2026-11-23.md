# UI 다듬기 + 영어판 빠진 경로 채우기 계획 (2026-11-23)

사용자 요청(11-23): (1) "AI 티 나는 UI"를 바꾼다. (2) 한국어를 바꾸면 영어도 같이 바꾼다. (3) 영어판에 없는 한국어 경로를 만든다.
근거: 인스타 릴스 "UI 이름 100개"의 용어에 맞춰 홈 화면을 점검한 결과(11-23), `src/app/(ko)` 와 `src/app/(en)/en` 라우트 비교 결과.

## 공통 규칙 (모든 단계에 적용)

- 한국어 화면을 바꾸면 같은 PR 안에서 영어 화면도 바꾼다. 문구는 `src/lib/strings/*` 의 `pick(ko, en)` 구조에 둔다. 영어만 따로 PR 하지 않는다.
- 색인에 영향 주는 것(canonical, hreflang, 사이트맵, noindex, 노트 본문)은 이번 범위에서 건드리지 않는다. 새 공개 페이지를 만들 때만 hreflang 쌍과 사이트맵을 추가한다(`hreflang.test.ts`, `sitemap.test.ts` 통과).
- 로그인·계정 페이지는 색인하지 않는다(noindex, 사이트맵 제외 유지).
- 애드센스 정책: 고정 버튼은 광고 위·옆에서 감추는 기존 로직(`useOverlapsAd`)을 유지한다.
- 움직임은 `prefers-reduced-motion` 을 지키고, 한 화면에 한 가지 효과만 쓴다.
- 단계마다 실행 에이전트와 독립 검수 에이전트를 둔다. 검수 PASS 후에 커밋·PR·머지·운영 확인은 총괄(나)이 한다. 에이전트는 git 과 `.claude/settings.json` 을 건드리지 않는다.
- 단계마다 완료 조건: `npx tsc --noEmit`, `npm run lint`, `npx vitest run`(관련 시험), `npm run build` 통과 + 한국어/영어 × 375·768·1280px × 밝은/어두운 화면 캡처 비교.

## Step 1. 현재 상태 기준선 조사

한국어·영어 홈, 자격증 허브, 노트, 퀴즈, 맛보기(/try) 화면을 캡처하고, 현재 토스트·스켈레톤·카운트업·플로팅 버튼·가입 카드·사이드바 구현 위치를 조사한다. 영어 계정 흐름(login, signup, forgot, reset, verify, welcome, onboarding)이 이미 영어 문구를 가지고 있는지(`src/lib/strings/auth.ts` 등), 언어가 경로(/en)로 정해지는지 쿠키로 정해지는지 확인한다.
Acceptance: 기준 캡처 세트와, 바꿀 파일 목록·영어 경로 방식 결정안이 문서로 남는다. 코드는 바꾸지 않는다.

## Step 2. 영어판 공개 페이지 추가: /en/try, /en/pricing

한국어 `/try`(가입 없이 5문제 맛보기)와 `/pricing` 의 영어판을 `src/app/(en)/en/` 아래에 만든다. 문구는 `pick` 구조로 두고, `GuestPreview` 가 영어 문제 은행을 쓰도록 한다. hreflang 쌍(한국어↔영어), 사이트맵, 메타데이터, JSON-LD, 헤더·푸터 연결을 추가한다.
Acceptance: `/en/try` 에서 영어로 5문제를 풀고 가입 안내가 영어로 나온다. `/en/pricing` 이 200 이다. hreflang·사이트맵 시험 통과. 한글 잔존 0.

## Step 3. 영어판 계정·학습 경로 추가

Step 1 결정에 따라 로그인, 가입, 비밀번호 찾기·재설정, 이메일 인증, 환영, 온보딩, 모의고사(/exam), 복습(/review), 오답노트(/notebook)의 영어 경로를 만든다. 이메일 문구와 오류 메시지도 영어로 한다. 이 경로들은 noindex 이고 사이트맵에 넣지 않는다.
Acceptance: 영어로 가입부터 첫 모의고사 시작까지 막힘 없이 된다. 로그인 후 언어가 유지된다. 한글 잔존 0. 기존 한국어 흐름은 그대로 동작한다.

## Step 4. 홈 개편: 히어로 + 사이드바 중복 제거 (한국어·영어)

홈에서 자격증 카드 14개 앞에 "이어서 공부하기"(최근 본 노트, `ContinueCards` 재사용)나 대표 자격증 하나를 크게 보여 주는 히어로를 만든다. 홈에서는 본문 카드와 같은 목록인 왼쪽 사이드바를 숨기거나 접는다. 카드 위계를 두어(대표 + 나머지) 균일한 격자를 깬다.
Acceptance: 비로그인·로그인 모두 홈 첫 화면에 이어 하기 또는 대표 자격증이 보인다. 정적 프리렌더를 유지한다(홈에서 쿠키·세션·DB 읽기 금지, `page.test.ts` 통과). 한국어·영어 동일 구조.

## Step 5. 피드백 버튼 위치와 알림 통일

모바일에서 플로팅 피드백 버튼을 작은 아이콘이나 푸터 링크로 바꿔 읽는 화면을 덜 가리게 한다(데스크톱 유지 여부는 Step 1 캡처로 판단). 정답·오답·저장 알림을 하나의 토스트 컴포넌트로 통일한다.
Acceptance: 375px 에서 본문 읽기를 가리지 않는다. 피드백 제출 기능과 광고 겹침 감추기가 그대로 동작한다. 알림이 한 가지 방식으로만 나온다. 한국어·영어 동일.

## Step 6. 로딩 스켈레톤

노트·퀴즈·모의고사 로딩 화면(`loading.tsx`)에 스켈레톤을 넣어 빈 화면을 줄인다.
Acceptance: 느린 네트워크 모의 환경에서 레이아웃이 튀지 않는다(CLS 0.1 미만). 한국어·영어 동일.

## Step 7. 작은 움직임과 가입 카드

홈의 숫자(자격증·노트 수)에 카운트업을 한 곳에만 넣고, 카드 등장은 한 번만 가볍게 한다. 가입 카드는 "계속 공부하기"를 기본 버튼으로 두고 가입을 보조로 바꾼다(#93 의 "오늘 하루 보지 않기"는 유지).
Acceptance: `prefers-reduced-motion` 이면 움직임이 없다. 가입 유도 이벤트(PostHog)가 끊기지 않는다. 한국어·영어 동일.

## Step 8. 통합 점검과 운영 확인

전체 화면을 기준선과 비교하고, 새 영어 경로를 포함해 링크 구조(홈에서 닿는지)와 hreflang·사이트맵을 다시 검사한다. 머지 후 Vercel 성공을 확인하고 운영 사이트에서 새 문구와 경로를 확인한다. 11-20 GSC 재검사 결과와 충돌하는 변경(canonical·noindex)이 없는지 확인한다.
Acceptance: 사이트맵 전수 크롤에서 비200·canonical·noindex·hreflang 이상 0건. Core Web Vitals 가 기준선보다 나빠지지 않는다. 성장 기록(`docs/growth`)에 한 줄씩 남긴다.

## 진행 순서와 이유

1 → 2 → 3 → 4 → 5 → 6 → 7 → 8. 영어 경로(2, 3)를 먼저 만들어야 4~7 의 UI 변경이 한국어·영어에 한 번에 적용된다. 4 이후는 서로 독립이라 필요하면 병렬로 돌릴 수 있지만, 같은 파일(홈, 레이아웃)을 건드리므로 PR 은 순서대로 머지한다.
