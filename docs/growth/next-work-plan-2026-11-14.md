# 다음 고도화 계획 (2026-11-14 기준)

영어판 전체(#65~#78)가 끝난 뒤의 남은 개선을 순서대로 적는다. 서치 콘솔 서비스 계정 연결(사용자 작업)은 이 계획에서 제외한다.
공통 규칙: 한국어 동작과 채점은 바꾸지 않는다. 한국어·영어 페이지 URL, canonical, hreflang은 깨지 않는다.

## 순서를 이렇게 잡은 이유

- 작고 독립적인 것(Step 1, 2)을 먼저 끝내 위험을 줄인다.
- `src/app/layout.tsx`를 건드리는 Step 4(`<html lang>`)와 Step 5(푸터 브랜드명)는 같은 파일이라 한 묶음으로 잇는다.
- 페이지 용량(Step 3)은 레이아웃·사이드바 데이터를 바꾸므로 Step 4 뒤에 한다(충돌 방지).
- 영어 가입 안내(Step 6)는 프록시·i18n 라우팅을 건드리므로 Step 4·5 뒤에 한다.
- 로그인이 필요한 확인(Step 7)과 정답 확정(Step 8)은 앞 단계와 파일이 겹치지 않는다.

## Step 1 — `/en/aws`·`/en/linux`·`/en/data` 리다이렉트

영어 주소에는 카테고리가 없어서 `/en/aws` 등이 404다. 세 주소를 `/en`으로 보낸다(308).
인수 기준: 세 주소가 `/en`으로 리다이렉트된다, 사이트맵과 기존 영어 URL(`/en/<자격증>/...`)은 영향 없다, `proxyRouting` 테스트 통과.

## Step 2 — `/en/reviews/*` 14개 정리

한국어 짝이 없고(`/reviews/*`는 404) 사이트맵에도 없는데 링크는 된다. 14개 페이지가 무엇이고 어디서 링크되는지 확인한 뒤 둘 중 하나로 정리한다:
(a) 의도된 페이지면 사이트맵과 hreflang 정책을 정하고, (b) 아니면 링크 제거와 404/리다이렉트 처리.
판단이 애매하면 바꾸지 말고 근거와 함께 보고한다.
인수 기준: 정리 방침이 근거와 함께 문서화되어 있다, 영어 화면의 어떤 링크도 404로 가지 않는다.

**Result (2026-11-14, 방침 b: 의도되지 않은 페이지 → 404 처리 + 영어 링크 제거)**

- 정체: 별도 영어 후기 페이지는 없다. `/en/reviews`와 `/en/reviews/<cert>`(허브 1 + 인증 14)는 `src/app/[category]/reviews/**`가 `category=en`으로 받은 것이다. 이 라우트는 `isSection(category)`가 아니면 `notFound()`를 부르는데(`en`은 섹션이 아님), 루트 `loading.tsx` 스트리밍 때문에 상태코드가 200으로 새어 나갔다. 실측: 수정 전 15개 모두 HTTP 200, 본문은 not-found 화면, `<meta robots=noindex>`, 타이틀은 루트 기본값 → 소프트 404. `contentPathExists`가 `slug==='reviews'`를 category 확인 없이 허용한 것이 원인(`en`이 KNOWN_CATEGORIES에 있음).
- 링크 출처: 영어 섹션 허브 `src/app/[category]/page.tsx`("pass reviews →")와 영어 인증 페이지 `src/app/[category]/[slug]/page.tsx`("Read … pass reviews →"). 사이드바(`SidebarNav.tsx`)는 이미 "en 모드에선 ko 전용이라 생략"으로 영어에선 링크를 숨기고 있었다 → 후기는 한국어 전용이 설계 의도. 후기 DB·색인 정책(`indexPolicy`, 후기 3건 미만 noindex)·사이트맵 제외(`sitemap.ts`: 정적 라우트라 DB 게이팅 불가) 모두 한국어 섹션(`/aws`·`/linux`·`/data`) 기준이다.
- 한국어 짝: 질문의 `/reviews/*`는 존재한 적 없는 경로다. 한국어 후기는 `/{section}/reviews[/{cert}]`이고 정상 동작(200). 영어 hreflang 짝으로 삼을 만한 한국어 후기 페이지 쌍이 없다.
- 변경: (1) `src/lib/contentExists.ts` — 후기 라우트는 섹션 category(`aws`·`linux`·`data`)만 존재로 판정, `en`·`aws-certs`는 false → proxy가 진짜 404로 보낸다. (2) 영어 허브·인증 페이지에서 후기 링크를 `lang === 'ko'`일 때만 렌더. (3) `src/lib/contentExists.test.ts`에 `/en/reviews*` false·`/aws/reviews*` true 시험 추가.
- 검증: vitest(contentExists·proxyRouting) 64건 통과, 수정 후 `/en/reviews` 및 `/en/reviews/<14개>` 전부 404, `/en`·영어 인증 페이지 렌더 HTML에 `/en/reviews` 링크 0건. 후기 hreflang/사이트맵 정책은 기존(한국어 전용·사이트맵 제외·내부 링크로 크롤) 그대로이며 바꾸지 않았다. 영어 후기가 필요해지면 별도 기능으로 `isSection` 가드와 이 시험을 함께 바꿔야 한다.

## Step 3 — 서버가 보내는 `<html lang>`을 경로 기준으로

영어 페이지도 서버 응답이 `<html lang="ko">`이고 hydration 뒤에야 `en`으로 바뀐다. `/en/*` 경로(영어 정보·실습·학습 페이지)는 서버 렌더링 때부터 `lang="en"`이 되게 한다. 라우트 그룹 분리나 요청 헤더 기반 등 변경이 가장 작은 방식을 택한다.
Out of scope: 한국어 페이지의 동작 변경.
인수 기준: `/en/*` 전체 HTML에서 `<html lang="en">`, 한국어 페이지는 `ko` 유지, hydration 경고 없음, 기존 `HtmlLangSync` 동작과 충돌하지 않는다.

## Step 4 — 영어 페이지 푸터 브랜드명

푸터의 "주간랩스"가 영어 페이지에도 한글로 남는다. 영어 경로에서는 영문 표기(예: Jugan Labs)로 바꾼다. 영어 정보 페이지의 운영자 표기와 맞춘다.
인수 기준: 영어 820+18개 페이지의 보이는 텍스트에 한글 0자, 한국어 푸터는 그대로.

## Step 5 — 페이지 HTML 용량 줄이기

학습 페이지 HTML이 한 장에 230~350KB다. 모든 페이지에 실리는 내비·사이드바·카탈로그 데이터와 불필요한 직렬화 데이터가 원인인지 측정한 뒤, 효과가 큰 것부터 줄인다(언어별 카탈로그 분리, 사이드바 데이터를 현재 언어·카테고리 것만 싣기 등). 측정 없이 추측으로 바꾸지 않는다.
인수 기준: 대표 페이지 5개(한국어 허브·day, 영어 허브·day, 실습)의 전송 크기를 전후로 표에 남긴다, 줄어든 만큼 근거가 있다, 전체 테스트·타입 검사 통과, 화면 동작 변화 없음.

## Step 6 — 영어 사용자 가입 흐름

영어 개인정보 페이지의 "Back to sign up"이 한국어 `/signup`으로 간다. 영어 사용자가 한국어 가입 화면으로 넘어가지 않도록 영어 가입·로그인 안내를 보강한다(영어 가입 화면 신설 또는 안내/링크 처리 중 변경이 가장 작은 쪽). 가입 전환을 높이기 위해 영어 노트·실습 화면의 가입 안내 문구도 점검한다. 개인정보·인증 코드는 보안 검토를 받는다.
인수 기준: 영어 페이지에서 한국어 `/signup`·`/login`으로 가는 링크가 의도된 것만 남는다, 인증 흐름 회귀 없음, 관련 테스트 추가.

## Step 7 — 영어 모의고사 풀이 화면 확인

로그인이 필요해 지금까지 실제로 열어 보지 못했다. 테스트 계정이나 로컬 개발 환경의 시드 사용자로 영어 모의고사 시작→풀이→채점 결과를 브라우저에서 확인하고, 화면의 한글 잔존과 깨짐을 찾아 고친다. 계정이 없으면 만들지 말고 필요한 것을 보고한다.
인수 기준: 영어 모의고사 화면 캡처 근거, 한글 0자, 문제 수·정답 처리가 한국어와 같다.

인수 기준: 고친 항목마다 공식 문서 근거, 한국어·영어 문제 수와 정답 일치, `quizContract.test.ts` 통과.
