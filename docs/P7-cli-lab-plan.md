**사용자 확인 완료: 디자인과 동작(2026-10-30).** 노트에는 아직 넣지 않았다. `/lab` 은 noindex 미리보기 페이지다.

### 구조
```

  state.ts      가상 계정 상태(버킷·객체·버전·IAM 사용자). 변경은 새 객체를 돌려준다

### 출력을 만드는 방식 (사용자 질문에 답한 내용)
- 미리 저장한 답을 돌려주지 않는다. 명령이 가상 계정 상태를 바꾸고, 출력은 그 상태를 실제 AWS 응답 모양에 끼워 만든다.
- 값의 출처: ① 사용자가 입력한 값 ② 쌓인 상태 ③ 고정 기준 데이터(리전·AZ, 오류 문구) ④ 이름 해시로 만든 ID, 명령마다 7초씩 흐르는 가상 시계.
- 같은 입력이면 항상 같은 출력이다. 계정 번호·ID·시각이 예시 값이라는 것은 화면에 표시한다.
- 오류 문구와 종료 코드(252·253·254·255)는 AWS CLI v2 를 따르고, 학습용 한국어 해설은 "연습장 안내" 칸으로 실제 출력과 구분한다.
- `--query` 는 `jmespath` 패키지(Apache-2.0, 의존성 없음)를 쓴다.

### 결론: AWS 시험과의 관계
- SAA·DVA·SOA 는 모두 객관식·복수응답형이다(SOA 실습 랩 폐지). **명령어 철자는 시험에 나오지 않는다.**

- 그래서 AWS 연습장은 "명령어 연습"이 아니라 **"손으로 겪는 개념"**으로 내세운다.

## 3. 다음 — 리눅스 셸 연습장 (대표 기능)

### 왜 리눅스인가 — 시험 형식과 직접 맞닿는다
KAIT 공식 페이지(https://www.ihd.or.kr/introducesubject1.do, 2026-10-30 확인):
- **1급 2차**: 필기 40%(단답·서술식 10문항) + **실기 60%(작업식 5~7문항)**, 100분. **실기 환경은 VirtualBox 위 Rocky Linux 8.8.** 필기 출제 기준은 커널 4.x 이상, RHEL/Rocky 8 계열과 Ubuntu 18.04 이상.
- **2급**: 1차(온라인 50문항)·2차(80문항) 모두 사지선다. 범위에 "기본 명령어", "파일 시스템 관련 명령어, 권한 및 그룹 설정", "Shell", "프로세스 관리"가 있다. 명령과 옵션의 결과를 묻는 문항이 많아 직접 쳐 보는 연습이 그대로 점수로 이어진다.
- 1급 출제 범위: 리눅스 실무의 이해 / 시스템 관리(일반 운영, 장치, 보안, 백업) / 네트워크 및 서비스의 활용(서비스, 보안).

### 설계 원칙 (AWS 엔진에서 가져온다)
- 상태를 들고 명령을 해석한다. 출력은 상태에서 계산한다. 같은 입력이면 같은 출력.
- 기준 배포판은 **Rocky Linux 8.8 (GNU coreutils 8.30)** 으로 고정한다. 시험 환경과 같다.
- 출력과 오류 문구는 실제 Rocky 8 컨테이너에서 찍은 값을 **골든 테스트**로 맞춘다. 같은 명령을 실제 셸(podman `rockylinux:8.8`)과 시뮬레이터에 넣어 출력을 비교한다. 추측으로 문구를 쓰지 않는다.
- 지원하지 않는 명령은 지원 목록을 안내한다(AWS 연습장과 같은 "연습장 안내" 칸).

### 상태 모델
- 가상 파일 시스템: inode 번호, 종류(파일·디렉터리·심볼릭 링크), 권한 비트(특수 비트 포함), 소유자·그룹, 크기, 수정 시각, 하드 링크 수, 내용(작은 텍스트).
- 사용자·그룹: `/etc/passwd`, `/etc/group`, `/etc/shadow` 는 상태에서 만들어 보여 준다(파일을 따로 들고 있지 않는다 → 불일치가 생기지 않는다).
- 세션: 현재 사용자(root / 일반 사용자, `su` 로 전환), 현재 디렉터리, umask, 환경 변수 일부.
- 일반 사용자로 바꾸면 권한 검사를 실제처럼 한다(Permission denied). 권한 단원 학습의 핵심.

### 1단계 명령 (2급 범위, 내일 시작)
| 묶음 | 명령 |
|---|---|
| 탐색·파일 | `pwd` `cd` `ls`(-l -a -i -d -h -R) `mkdir`(-p) `touch` `cp`(-r -p) `mv` `rm`(-r -f) `cat` `head` `tail` `wc` `echo`(+ `>` `>>`) |
| 권한 | `chmod`(숫자·기호, setuid·setgid·sticky) `chown` `chgrp` `umask` `stat` |
| 링크 | `ln`(-s) — inode·링크 수 변화를 `ls -li` 로 보여 준다 |
| 사용자 | `useradd`(-m -g -G -s -u) `usermod` `userdel`(-r) `groupadd` `passwd`(-l -u, 비밀번호 입력은 생략) `id` `su` `whoami` |
| 찾기 | `find`(-name -type -perm -user -size -mtime -exec) `grep`(-i -v -n -r -c) |
| 기타 | 파이프 1단(`a | grep`, `a | wc -l`), `tar`(c x t z v f) |

### 2단계 (1급 실기 범위, 1단계 확인 뒤 판단)
- 디스크 쿼터, `crontab`, `systemctl`, `firewall-cmd`, 서비스 설정 파일 편집(httpd·named 등).
- 설정 파일 편집은 vi 를 흉내 내지 않고 **터미널 옆 편집기 패널**로 한다(vi 흉내는 양이 크고, 시험 핵심은 설정 내용이지 편집기 조작이 아니다). 실제 시험은 vi 를 쓰므로 이 차이는 화면에 밝힌다.
- 2단계는 양이 크다. 1단계 사용자 반응을 보고 범위를 정한다.

### 과제 후보 (1단계)
1. 권한 숫자와 기호: `chmod 754`, `u+x,g-w`, umask 022 에서 새 파일·디렉터리 권한
2. 하드 링크 vs 심볼릭 링크: inode 와 링크 수, 원본을 지웠을 때
3. 특수 권한: `/tmp` 의 sticky, setuid 가 붙은 `passwd`
4. 사용자와 그룹: 보조 그룹 추가 → `id` 로 확인 → `userdel -r`
5. find 로 찾기: 권한·소유자·크기 조건, `-exec` 로 일괄 처리

### 골든 테스트
- 시나리오 9개(파일, 권한, 소유자, 링크, 사용자, find·grep, 권한 거부, 경계 사례, 리뷰 회귀) **319단계 전부 실제 출력과 같다.** stdout·stderr·종료 코드를 모두 비교한다.
- 다시 찍기: `docker build -t certnote-rocky88 scripts/shell-lab && node scripts/shell-lab/golden.mjs`
- 실행 환경마다 다른 값만 양쪽에서 같은 자리표시로 바꿔 비교한다: ls·stat 의 시각, stat 의 장치·inode 번호, `ls -li` 의 inode 번호(같은 번호끼리 같은지는 유지), `passwd -S` 의 날짜.
- 다른 사용자 단계는 컨테이너에서 `runuser -u`, 시뮬레이터에서는 세션을 하나 쌓아 실행한다.

### 실제와 일부러 다르게 둔 것
- find·grep -r 은 이름순으로 돈다(실제는 디스크 순서라 매번 다르다). 골든은 정렬해 비교한다.
- root 의 `rm`·`cp`·`mv` 별칭(-i)은 넣지 않았다. 대신 일반 사용자가 쓰기 금지 파일을 지우면 실제처럼 확인 질문을 띄우고 "n" 으로 처리한 뒤 안내한다.
- `ls -l` 권한 뒤의 SELinux 점(`-rw-r--r--.`)은 없다. 컨테이너 기준이다. 실제 시험 VM 은 SELinux 가 켜져 있으면 점이 보인다 — 화면 안내에 넣을지 정해야 한다.
- `ll`(= `ls -l`) 별칭을 넣었다. 실제 Rocky VM 에는 coreutils 의 `/etc/profile.d/colorls.sh` 가 넣어 주지만, 골든을 찍은 최소 컨테이너에는 그 파일이 없다(2026-10-31 사용자가 `ll` 을 쳐서 발견).
- 로케일은 C(영어 메시지, '...' 따옴표). 시험 VM 의 로케일은 아직 확인하지 못했다.
- 비밀번호 입력은 건너뛴다(`passwd` 는 설정된 것으로 처리하고 안내). 일반 사용자에서 `su` 는 막고 `exit` 로 돌아가게 안내한다.
- vi·tar·sort·systemctl 등 실제로 있는 명령은 "command not found" 로 속이지 않고 "아직 지원하지 않음" 안내를 띄운다. tar 는 1단계 표에 있었지만 아카이브 크기·gzip 출력을 정확히 맞추기 어려워 뒤로 미뤘다.

### 확인
- `vitest src/lib/shell-lab` 22개(골든 9 + 셸 동작·자동 완성·과제 13), `src/lib/cli-lab` 21개 그대로 통과.
- 코드 리뷰 에이전트: HIGH 1(`grep -R` 이 심볼릭 링크 고리에서 탭을 멈춤 → 실제처럼 `recursive directory loop` 경고 후 건너뜀), MEDIUM 2(잘못된 와일드카드 `[z-a]` 에서 예외 → 글자 그대로, 빈 변수가 빈 인자로 남음 → 뺌), LOW 2(`constructor` 같은 이름, `mv .`) 모두 고치고 실제 출력으로 회귀 골든을 더했다. 화면에서 예외가 나도 입력이 사라지지 않게 안내를 띄운다.

### 사용자 확인에서 고친 것 (2026-10-31)
- L1 2단계가 `chmod -x` 를 먼저 한 뒤 `u-x,g+w` 를 하면 통과하지 않았다(결과 664 ≠ 674). 정확한 숫자 대신 "기호 모드로 바꿨고, 소유자 x 없음 + 그룹 w 있음" 으로 판정을 바꿨다. 숫자 chmod 로는 여전히 통과하지 않는다.

- `/lab`: 묶음별 카드 목록. 색인 대상(ItemList·Breadcrumb 구조화 데이터). 미리보기 noindex 페이지를 대신한다.
- `/lab/[id]`: 소개 2문단 → 이 실습에서 할 일(단계 제목) → 연습장 → 함께 읽을 노트. 6개 정적 생성.
- `src/lib/labCatalog.ts`: 소개·관련 노트. 사이드바 번들이 시뮬레이터 엔진을 끌어오지 않게 엔진을 import 하지 않고, 코드·제목이 엔진과 같은지는 `labCatalog.test.ts` 가 본다.
- 사이트맵에 `/lab` + 6개. lastModified 는 실습 소스 3개의 커밋 시각(매니페스트에 그 3개만 추가 — 전체 재생성은 무관한 노트 날짜까지 바꿔서 하지 않았다).
- 확인: Playwright 1440px·390px 다크 — 목록·상세·드로어, 페이지 오류 0, 가로 스크롤 없음. `ll -i` 로 inode 단계가 통과하지 않던 것(실행 기록에 별칭 이름이 남음)을 고쳤다.

### 남은 것
1. main 머지(= 운영 배포) 여부 결정.
2. 2단계 범위 결정(tar, sort·cut·파이프 확장, 1급 실기의 crontab·systemctl·쿼터).

### 위험
- **범위 팽창**: 셸은 끝이 없다. 1단계 표의 명령·옵션만 지원하고, 나머지는 "연습장 안내"로 돌린다.
- **틀린 출력이 신뢰를 깎는다**: 실제 출력과 다르면 오히려 역효과다. 골든 테스트 없이 명령을 추가하지 않는다.
- **로케일**: 시험 환경의 언어 설정을 확인하지 못했다. 1단계는 영어(C 로케일) 메시지로 하고, 확인되면 맞춘다.
