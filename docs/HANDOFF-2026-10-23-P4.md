## 1. 배경

- 글·문항 검수 4건(Haiku)과 브랜드 조사(Opus)에서 나온 결론:
  - "신뢰가 안 간다"는 느낌의 주원인은 디자인이 아니다. **확인할 수 없는 주장**(경쟁사 가격표, "한국어 유일", "일회 합격", "555+ 강의")과 **얼굴 없는 운영**(작성자·제작 방식·수정 이력 미공개)이 원인이다.
  - "읽으면 부자연스럽다"는 느낌은 문체가 섞여서다. 존댓말과 평서체가 섞이고, 응원 문구가 들어가고, 이모지 콜아웃이 과하고, 요약 섹션이 겹치고, 용어 표기가 갈린다.
  - 모의고사는 문제를 읽지 않아도 맞힐 수 있었다. 정답 보기가 가장 긴 비율이 최대 100%였고, MLS 정답의 44%가 B였다.
- 로고는 사용자가 직접 만든다. 방향(남색·청록 계열, AWS 주황 `#ff9900` 회피, AWS·Tux·KAIT 마크 미사용, 워드마크 "CertNote")은 대화에서 정했다.

## 4. 작업 방식 메모

- **퀴즈 보호**: day.md는 `## 📝 연습 문제` 앞의 본문만 고친다. 고친 뒤 `node scripts/restore-quiz.mjs <경로>`와 `npx vitest run src/lib/quizContract.test.ts`를 돌린다. `# Day N -` 제목은 바꾸지 않고, 본문에 `**문제 N.`을 쓰지 않는다.
- **모의고사 JSON**을 고친 뒤에는 `node scripts/build-exam-index.mjs`로 `src/data/exam-questions.json`을 다시 만든다.
- **빌드**: worktree에서는 `node_modules`가 junction이라 Turbopack이 `npm run build`를 거부한다. vitest와 tsc는 된다. 빌드 확인은 실제 `node_modules`가 있는 `CertNote-open`에서 한다.
- **CRLF**: Windows 체크아웃에서 `src/data/questions.json`이 줄바꿈만 바뀐 것으로 나오면 `git checkout --`으로 되돌린다. CRLF 체크아웃에서는 `auditStyle.test.ts`가 shebang 뒤 `\r` 때문에 SyntaxError를 낼 수 있다(git 내용은 정상).
- **병렬 실행**: vitest를 여러 개 동시에 돌리면 sitemap·week1Static 테스트가 30초 제한에 걸리거나 DB 테스트가 흔들린다. 단독으로 돌리면 통과한다.
- **문체 일괄 수정 규칙**(`docs/content-style-guide.md`): 따옴표 안 오류 메시지·API 이름·CLI 출력은 용어 치환에서 뺀다. 요약 섹션을 합칠 때 다른 곳에 없는 정보는 지우지 않는다.
